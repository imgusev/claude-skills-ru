# /cs:fullstack-review — Ревью инженерного обеспечения Fullstack { #csfullstack-review--fullstack-engineering-review }

Используйте `cs-fullstack-engineer` агент (который использует `context: fork` чтобы сохранить родительский поток чистым) для обработки этого запроса:

**$ARGUMENTS**

## Библиотека принудительных вопросов { #forcing-question-library }

Канонический источник: `engineering-team/skills/senior-fullstack/references/forcing_questions.md` (7 вопросов, по одному за ход, рекомендация + цитата из канона на каждый вопрос).

1. Размер команды сейчас + численность персонала за 12 месяцев
2. Частота развертывания (per-PR / ежедневно / еженедельно / ежеквартально)
3. Ориентация на клиента / внутренний инструмент / маркетинговый сайт
4. Прогноз трафика p50 + p99 на один год
5. Найм - против обучения - в стек
6. Год-одно ежемесячное облако + потолок бюджета SaaS
7. Три поддающихся проверке критерия успеха с числовыми показателями

## Протокол маршрутизации { #routing-protocol }

1. ** Пройдите по 7 форсирующим вопросам** в `engineering-team/skills/senior-fullstack/references/forcing_questions.md` По одному за ход. Порекомендуйте ответ с цитируемым каноном. Отслеживать в `/tmp/fullstack-grill-<date>.md`.
2. ** Критерии поверхностного удаления ** — если какой-либо вопрос не соответствует одному из них (например, "день микросервисов 1, размер команды 3"), ОСТАНОВИТЕСЬ и решите его, прежде чем продолжить.
3. **Запустите средство выбора детерминированного профиля:**
   ```bash
   python engineering-team/skills/senior-fullstack/scripts/fullstack_decision_engine.py \
     --team-size <N> --team-size-12mo <N12> --cadence <c> \
     --user-facing <true|false> --budget <USD/mo> \
     --traffic-p99-rps <N> --data-sensitivity <tier>
   ```
4. ** Нанесите на поверхность соответствующий профиль + компромисс, занявший второе место** (если в пределах 15%).
5. ** Разделитесь на специалистов** (по одному, сначала в глубину):
   - `api-design-reviewer` для контракта с API
   - `database-designer` для схемы
   - `slo-architect` для достижения цели по надежности
   - `ci-cd-pipeline-builder` для пайплайна
   - `performance-profiler` для базовой линии perf
   - `cs-karpathy-reviewer` перед любым совершением

## Ожидаемый результат (дайджест из ≤ 200 слов) { #output-expectations--200-word-digest }

- Совпадающий профиль + причина
- Три поддающихся проверке критерия успеха с числовыми показателями
- Именованная цепочка утверждающих
- Список вызванных специалистов + пути к артефактам
- Рекомендуемый следующий дополнительный скилл (если таковой имеется)

## Анти-паттерны { #anti-patterns }

- ❌ Связывание форсирующих вопросов — по одному за ход.
- ❌ Пропуск проверки критериев уничтожения.
- ❌ Переосмысление сферы деятельности специалиста. Вилка — не дублируйте.
- ❌ Автоматическое утверждение производственных изменений. Всегда называйте человека, утверждающего.

## Настройка { #customization }

Профили живут по адресу `engineering-team/skills/senior-fullstack/profiles/`. Чтобы настроить для вашей организации:

1. Копия `saas-startup.json` (или в зависимости от того, что лучше всего подходит) для `<your-org>.json`.
2. Редактировать `constraints`, `stack_recommendations`, `success_thresholds`, `named_approver_chain`.
3. Механизм принятия решений автоматически обнаруживает новые JSON-файлы профиля.
