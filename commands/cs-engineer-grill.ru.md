# /cs:engineer-grill — Кросс-ролевое инженерное принуждение-решетка вопросов { #csengineer-grill--cross-role-engineering-forcing-question-grill }

Ознакомьте пользователя с дисциплиной Matt Pocock forcing-question, прежде чем он примет какое-либо инженерное решение. Это шаблон **grill-with-docs** (привязанный к канону, рекомендуемые ответы, критерии исключения), применяемый для трех направлений инженерной деятельности.

**$ARGUMENTS**

## Протокол маршрутизации { #routing-protocol }

1. **Обнаружение сигналов полосы движения ** в промпте пользователя:
   - **Сигналы полного стека:** "каркас", "стек", "Next.js + Postgres", "monorepo", "депло ", "размер команды", "бюджет", "частота"
   - **Интерфейсные сигналы: ** "React", "Next", "Remix", "Vite", "Astro", "bundle", "LCP", "INP", "CLS", "a11y", "WCAG", "Попутный ветер", "система проектирования"
   - **Серверные сигналы: ** "API", "REST", "GraphQL", "база данных", "Postgres", "MongoDB", "схема", "миграция", "QPS", "аренда", "SLO", "Kafka", "очередь", "микросервис", "монолит"

2. **Если `--lane <name>` прилагается: ** пройдите только по 7 вопросам этой полосы.
3. ** Если сигналы полосы движения набирают ≥ 3 попаданий для одной полосы: ** подтвердите это у пользователя, затем ответьте на 7 вопросов по этой полосе.
4. **Если сигналы полосы движения неоднозначны ИЛИ `--lane all`:** спросите пользователя: "Fullstack (7 вопросов о команде / стеке / масштабе), Frontend (7 вопросов об устройстве / рендеринге / пакете / a11y) или Backend (7 вопросов о QPS / tenancy / pattern / SLO)? Или `all` для всех 21."

## Полоса движения: полный штабель { #lane-fullstack }

Вопросы живут в `engineering-team/skills/senior-fullstack/references/forcing_questions.md` Краткое описание:

1. Размер команды на сегодняшний день + численность персонала за 12 месяцев?
2. Частота развертывания для каждого PR, ежедневно, еженедельно, ежеквартально?
3. Ориентированный на клиента, внутренний инструмент или маркетинговый сайт?
4. Прогноз трафика p50 / p99 на один год?
5. Нанимать на работу в соответствии со стеком или обучать команду?
6. Год- одно ежемесячное облако + потолок SaaS?
7. Три поддающихся проверке критерия успеха с числовыми показателями?

## Полоса: интерфейс { #lane-frontend }

Вопросы живут в `engineering-team/skills/senior-frontend/references/forcing_questions.md` Краткое описание:

1. Основное устройство + сеть (мобильная-4G / настольная-оптоволокно / бюджетный Android / корпоративная)?
2. Цель LCP в ms (и INP, CLS)?
3. RSC / SPA / SSR / SSG — выбирать и защищать?
4. Бюджет пакета JS для каждого маршрута в KB-gzip?
5. Зависимый от SEO или защищенный от авторизации?
6. Дизайн-система - источник истины?
7. Цель WCAG + назван владелец a11y?

## Полоса движения: серверная часть { #lane-backend }

Вопросы живут в `engineering-team/skills/senior-backend/references/forcing_questions.md` Краткое описание:

1. Читать/write коэффициент + p99 Прогноз QPS?
2. Модель аренды — одиночная / общая / изолированная?
3. Синхронизация / асинхронность / управляемая событиями — по умолчанию + исключения?
4. Уровень чувствительности данных — PII/ PHI/ PCI?
5. Монолит / модульный монолит / микросервисы — обоснование размера команды?
6. RPO + RTO?
7. SLO + именованная ошибка - бюджетный потребитель?

## Дисциплина (Мэтт Покок, Массачусетский технологический институт, сохранено дословно из `engineering/grill-me`) { #discipline-matt-pocock-mit-preserved-verbatim-from-engineeringgrill-me }

1. ** По одному вопросу за ход. ** Никогда не связывайтесь. Никогда не задавайте вопрос по умолчанию "что вы думаете?".
2. ** Всегда рекомендуйте ответ.** Формат: "Рекомендуется: <ответ>, потому что <обоснование в одном предложении из цитируемого канона>".
3. ** Сначала пройдите по глубине. ** Закончите полосу движения, прежде чем открывать другую.
4. ** Выведите на поверхность критерий уничтожения.** Если ответ пользователя сбивает с толку, остановитесь и решите проблему, прежде чем продолжить.
5. ** Отслеживайте ответы.** Пишите в `/tmp/engineer-grill-<lane>-<date>.md` таким образом, беседа выдерживает сжатие.

## После приготовления на гриле { #after-the-grill }

1. ** Запустите механизм принятия решений по полосе ** с помощью семи ответов:
   - Полный пакет → `python engineering-team/skills/senior-fullstack/scripts/fullstack_decision_engine.py ...`
   - Интерфейс → `python engineering-team/skills/senior-frontend/scripts/frontend_decision_engine.py ...`
   - Серверная часть → `python engineering-team/skills/senior-backend/scripts/backend_decision_engine.py ...`
2. **Отобразите соответствующий профиль + имена утверждающих.**
3. ** Порекомендуйте следующую цепочку вспомогательных скиллы** на основе карты состава.

## Ожидаемые результаты { #output-expectations }

- По одному артефакту на пройденную полосу, записанному на `/tmp/engineer-grill-<lane>-<date>.md`.
- Один итоговый обзор (≤ 250 слов), обобщающий сопоставленный профиль для каждой полосы движения + три следующих действия с наибольшим коэффициентом полезного действия.
- **Никогда** автоматически не утверждайте изменение стека, перенос схемы или выбор архитектуры.
