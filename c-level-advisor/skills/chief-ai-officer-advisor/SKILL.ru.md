# Советник главного специалиста по искусственному интеллекту { #chief-ai-officer-advisor }

Стратегическое лидерство в области искусственного интеллекта для руководителей стартапов и основателей без такового. ** Четыре решения, никакой шумихи вокруг искусственного интеллекта:**

1. ** Должны ли мы использовать API, проводить тонкую настройку или создавать свои собственные?** - модель build—vs-buy с 3-летней общей стоимостью владения
2. ** Является ли этот вариант использования ИИ высокорисковым в соответствии с законодательством и как мы его регулируем?** - Закон ЕС об ИИ + NIST AI RMF + лоскутное одеяло штата США
3. ** Когда мы перейдем с API на автономный хостинг и по какой цене?** - экономика токенов с анализом безубыточности
4. ** На какую роль искусственного интеллекта мы наймем в следующий раз?** — схема от этапа к роли (инженер по искусственному интеллекту ≠ инженер ML ≠ ученый-исследователь)

Этот скилл **не** распространяется на тактическую инженерию искусственного интеллекта/ML. Информацию о внедрении RAG, разработке агента, разработке промптов, инфраструктуре eval, развертывании модели или оптимизации затрат смотрите в разделе `engineering/rag-architect/`, `engineering/agent-designer/`, `engineering/prompt-governance/`, `engineering/self-eval/`, `engineering/llm-cost-optimizer/`.

## Основные обязанности { #core-responsibilities }

### 1. Сборка модели против покупки { #1-model-build-vs-buy }

Решение заключается не в том, "использовать ИИ или нет" — это ** API против точной настройки против собственных ** для каждого варианта использования. Каждый путь имеет разную кривую совокупной стоимости владения, профиль задержки и потолок пропускной способности.

**Путь по умолчанию: API (пограничная модель)**
- Используйте, когда: хорошо обслуживается frontier (Claude, GPT, Gemini), QPS < 100, бюджет задержки > 1 с, стоимость < $50 тыс./month
- Почему: интерфейсы frontier API в 10-100 раз более функциональны, чем те, которые большинство команд могут настроить самостоятельно
- Режим сбоя: ограничения скорости API в масштабе, привязка к поставщику, изменение возможностей между версиями модели

**Точная настройка уменьшенной модели**
- Используйте, когда: поведение, зависящее от домена, к которому невозможно промпт API (медицинское кодирование, юридическое переопределение), большой объем, снижающий стоимость API, бюджет задержки < 500 мс, специфический стиль/format требуемая согласованность
- Подходы: полная точная настройка (редкий случай), LoRa/QLoRA (распространенный), RLHF/DPO (когда имеет значение выравнивание)
- Режим сбоя: отлаженная модель отстает от предельных возможностей в течение 6-12 месяцев; постоянные затраты на переподготовку

** Сборка с нуля / предварительное обучение**
- Используйте, когда: почти никогда. Вы являетесь компанией, основанной по образцу фонда, или у вас есть уникальный массив данных, финансирование в размере более 50 миллионов долларов и терпение более 18 месяцев.
- Режим сбоя: к моменту отправки модели frontier догонят вас, и ваши невозвратные затраты будут невозвратимы

**Запуск** `model_buildvsbuy_calculator.py` для получения рекомендации по конкретному варианту использования с 3-летней общей стоимостью владения. Видишь `references/model_buildvsbuy_strategy.md` для получения полного дерева решений.

### 2. Классификация рисков искусственного интеллекта и управление ими { #2-ai-risk-classification--governance }

Вопрос 2026 года, с которым сталкивается каждый основатель: ** влечет ли этот вариант использования искусственного интеллекта триггеры высокого риска для регулирующих органов?**

**Уровни Закона ЕС об искусственном интеллекте (вступает в силу в 2026 году):**

| Уровень | Примеры | Обязательства |
|---|---|---|
| **Запрещено** | Социальный скоринг, биометрическое наблюдение в режиме реального времени, манипулятивный искусственный интеллект | Не удается деплою развернуться в ЕС |
| **Высокий риск** | Проверка занятости, кредитный рейтинг, доступ к образованию, критически важная инфраструктура, правоохранительные органы, биометрическое удостоверение личности | Оценка соответствия, регистрация, пострыночный мониторинг, прозрачность, человеческий надзор |
| **Ограниченный риск** | Чат-боты, глубокие подделки, распознавание эмоций | Прозрачность: пользователь должен знать, что он взаимодействует с искусственным интеллектом |
| **Минимальный риск** | Рекомендательные системы, спам-фильтры, большинство внутренних компонентов B2B SaaS | Никаких конкретных обязательств |

**Запуск** `ai_risk_classifier.py` чтобы классифицировать вариант использования и получить список требуемых элементов управления.

**Лоскутное одеяло штатов США (неисчерпывающий перечень):**

- NYC LL 144 — Автоматизированные инструменты принятия решений о приеме на работу (AEDTS) требуют ежегодного аудита предвзятости + уведомления кандидата
- Закон штата Колорадо об ИИ / SB 21-169 — ИИ при принятии решений потребителями (кредит, страхование, трудоустройство, жилье)
- Иллинойс HB 53 — AI в интервью/hiring
- Калифорнийский SB 1001 — Раскрытие информации о ботах
- Texas TCPA — Захват биометрических идентификаторов
- Федеральный NIST AI RMF — добровольный; все чаще упоминается в контрактах

**Отраслевые накладки:**

- Здравоохранение: Руководство FDA по ИИ/МЛ (2023), MDR (ЕС) для медицинских устройств с ИИ, путь 510(k) для медицинских устройств с поддержкой ИИ/МЛ
- Финансовые: NYDFS Reg 23, раздел 5 FTC, ECOA для принятия кредитных решений
- Страхование: типовой бюллетень NAIC, правила государственного уполномоченного по страхованию

Видишь `references/ai_risk_governance.md` ознакомьтесь с полным чек-листом нормативно-правовой базы + программы управления.

### 3. Экономия затрат на искусственный интеллект { #3-ai-cost-economics }

** Вопрос о безубыточности: ** при каком ежемесячном объеме токенов самостоятельный вывод превосходит затраты на API?

**Ключевые компоненты:**

- **Стоимость API** — переменная, для каждого токена. Frontier models 2026: Claude Sonnet 4,6 ~$3/$15 за миллион токенов (входные данные/output), GPT-4o ~$2,50/$10, Gemini 2,5 ~$1,25/$5
- ** Стоимость самостоятельного размещения ** — фиксированная (затраты на графический процессор) + переменная (электроэнергия). Спот H100 ~$2-5/hour, Спот A100 ~$1-3/hour. Llama 3.1 70B / Qwen 2.5 72B: ~$0,50-2,00 за миллион выходных токенов при 70% использовании
- ** Скрытые затраты на самостоятельный хостинг ** - оперативные операции по вызову, мониторинг, обновления моделей, накладные расходы на масштабирование, штраф за время простоя
- **Скрытые издержки API** — ограничения скорости, требующие отработки отказа несколькими поставщиками, привязки к поставщику, переключения возможностей между версиями, сохранения данных

**Типичная безубыточность (пограничное качество):** 100 млн–500 млн токенов/month, в зависимости от размера модели и приемлемого соотношения качества. Ниже этого значения выигрывает API. После этого запустите калькулятор.

**Запуск** `ai_cost_economics.py` с характеристиками рабочей нагрузки для достижения точки безубыточности + чувствительность к частоте графического процессора и размеру модели.

Видишь `references/ai_cost_economics.md` для получения полной экономической модели и оперативных соображений.

### 4. Эволюция организации команды искусственного интеллекта { #4-ai-team-org-evolution }

** Неправильный вопрос: ** "Должны ли мы нанять инженера по ML или ученого-исследователя?"
** Правильный вопрос: ** "Какие следующие возможности искусственного интеллекта нам нужно внедрить, и какая роль их открывает?"

Схема перехода от этапа к роли:

| Стадия | Первый наем искусственного интеллекта | Затем | Затем |
|---|---|---|---|
| Предварительная ПМФ | Основатель + 1 МЛ -любопытный инженер, играющий с промпт | — | — |
| Серия A | **Инженер по искусственному интеллекту** (прикладной, полнофункциональный; владеет промптом/evals/deployment) | Второй инженер по искусственному интеллекту для evals/quality | — |
| Серия B | Инженер платформы AI/ML (вывод, оценки, наблюдаемость) | Третий инженер по искусственному интеллекту для обеспечения надежности производства | Специалист по обработке данных, если модель является основным IP |
| Серия C | Менеджер по искусственному интеллекту | Ученый-исследователь ML (только если модель является продуктом) | Безопасность ИИ / красная команда (если ИИ работает с клиентами) |
| Поздняя стадия | Глава AI → CAIO | Множество ученых-исследователей, команда платформы, безопасность/red команда | Объединенные лиды в области искусственного интеллекта для каждой бизнес-единицы |

**Критические различия:**

- **Инженер по искусственному интеллекту** ≠ **Инженер по ML** ≠ ** ученый-исследователь**
  - Инженер по искусственному интеллекту: полный стек + промпты + оценки + развертывание. Большинству стартапов это нужно, а не другим.
  - Инженер ML: развертывание производства, мониторинг, инфраструктура переподготовки кадров. Нанимайте после инженера по обработке данных.
  - Ученый-исследователь: изобретение моделей, новые архитектуры. Только в серии C+, если модель является core IP.

** Централизация против внедрения для ИИ: ** ИИ запускается централизованно (одной командой) и остается там дольше, чем команда обработки данных, потому что площадь поверхности меньше. Встраивайте только тогда, когда искусственный интеллект деплою используется в 4+ поверхностях продукта.
