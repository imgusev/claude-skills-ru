# Главный консультант по работе с клиентами { #chief-customer-officer-advisor }

Стратегическое лидерство в работе с клиентами для руководителей стартапов и основателей без такового. **Четыре решения, без общего опроса CS:**

1. ** Какова наша архитектура удержания — и честно ли соотношение валового удержания и NRR?** — разложение на валовое удержание, сокращение, расширение + таксономия первопричин оттока
2. **Как мы сегментируем клиентов для дифференцированного инвестирования?** — многоуровневый дизайн + оценка соответствия ICP + расчет инвестиций по сегментам
3. ** Какова модель охвата команды CS — и когда мы перейдем к объединению против именованного?** — калькулятор коэффициента охвата + пороговые значения перехода
4. ** Какую роль CS мы наймем следующей?** — схема от этапа к роли (CS ≠ Поддержка ≠ AM ≠ Внедрение)

Этот скилл **не** распространяется на тактическую реализацию CS. Информацию об инструментах для оценки работоспособности, воркфлоу CRM, инфраструктуре опроса NPS или автоматизации онбординга смотрите в разделе `business-growth/customer-success-management/` и смежные тактические скиллы.

## Ключевые вопросы (задайте их в первую очередь) { #key-questions-ask-these-first }

- ** Каков ваш общий уровень удержания?** (Не NRR — NRR скрывает отток за расширением. Сначала спроси Гросса.)
- ** Какова причина ухода клиентов № 1?** (если вы не можете назвать ее, значит, вы не понимаете, что такое отток).
- ** Каково среднее время достижения значения (TTV) по сегментам?** (Длинный TTV на низком уровне = несоответствие; длинный TTV на высоком уровне = онбординг нарушен.)
- ** Какого клиента вы бы уволили сегодня?** (если "нет" — ваша сегментация нарушена; некоторые аккаунты стоят дороже, чем они зарабатывают.)
- ** Каково ваше соотношение ARR на CSM и какова модель — объединенная или именованная? ** (стадия и ACV определяют правильный ответ.)
- ** Входит ли CS в ваш план по сбыту и чем он отличается от плана по продажам?** (CS зависит от удержания; несоответствие - главный показатель неудачи.)

## Основные обязанности { #core-responsibilities }

### 1. Разложение удержания { #1-retention-decomposition }

** Ловушка: ** "Наш NRR составляет 115%, удержание отличное".

Истина: NRR = Общее удержание − Сокращение + расширение. Показатель NRR в 115% при валовом удержании 85% - это дырявое ведро, замаскированное повышенными продажами. NRR 115% при общей сохранности 98% - это полезный продукт.

**Обязательная декомпозиция каждый квартал:**

| Метрика | Что он измеряет | Порог работоспособности (B2B SaaS) |
|---|---|---|
| **Общее удержание (GRR)** | $ от существующих клиентов за вычетом оттока + сокращение | ≥ 90% на стадии роста; ≥ 95% в масштабе |
| **Сохранение логотипа** | % клиентов, которые продлили | ≥ 85% при росте; ≥ 90% при масштабировании |
| **Удержание чистой выручки (NRR)** | GRR + расширение | ≥ 110% при росте; ≥ 120% при масштабировании |
| **Сокращение** | $ от существующих клиентов, сокращающих количество мест/usage | < 5% в год |
| **Расширение** | $ от растущих существующих клиентов | 15-25% ежегодно при здоровом |

**Запуск** `retention_decomposition_analyzer.py` с когортными данными для честной декомпозиции + категоризация первопричин оттока.

Видишь `references/retention_decomposition.md` для таксономии оттока по 7 категориям + плейбук с опережающими показателями.

### 2. Сегментация клиентов { #2-customer-segmentation }

** Ловушка:** "Важен каждый клиент".

Реальность такова: клиенты существуют в диапазоне соответствия ICP × стратегической ценности. Одинаковое обращение с ними приводит к растрате ресурсов CS и игнорированию возможности расширения.

**4-уровневый фреймворк (базовый уровень B2B SaaS):**

| Уровень | Диапазон обр. | Охват | Инвестиции на один счет/yr |
|---|---|---|---|
| **Стратегический** | Лучшие 5%, часто до 100 тысяч долларов+ | Названный исполнительный спонсор CSM + | $20 тыс.-50 тыс. |
| **Предприятие** | Следующие 15-20%, $20 тыс.-100 тыс. | Названный CSM | $5 тыс.-15 тыс. |
| **Среднерыночный** | Следующие 30-40%, $5 тыс.-20 тыс. | Объединенная автоматизация CSM + | $1 тыс.-3 тыс. |
| **Малый и средний бизнес / Длиннохвостый** | Нижние 40-50%, <$5 тыс. | Технология-прикосновение + самообслуживание | $50-500 |

**Запуск** `customer_segmentation_designer.py` для разработки уровней сегментации + дифференциальных инвестиций + оценки соответствия ICP.

Видишь `references/customer_segmentation_strategy.md` для фреймворка ICP fit, триггеров перехода на новый уровень и списка исключений (клиенты ниже минимального уровня инвестиций).

### 3. Модель охвата команды CS { #3-cs-team-coverage-model }

** Ловушка: ** "Нанимайте одного CSM на X клиентов" с единым соотношением во всех сегментах.

Реальность: модель покрытия зависит от сегмента, ACV и сложности. Объединенный CSM работает для low-touch; именованный CSM необходим для стратегических учетных записей.

**Модели покрытия:**

| Модель | Лучше всего подходит для | Соотношение (ARR-на-CSM) | Компромиссы |
|---|---|---|---|
| ** Технологическое прикосновение (без участия человека)** | Малый и средний бизнес, низкий ACV | $5 МЛН-15 млн+ | Затраты на автоматизацию; не удается сохранить сделки с высокими ставками |
| **Объединенный CSM** | Среднерыночный | $2 МЛН-5 млн | Более низкая стоимость; меньшая интимность учетной записи |
| **Именованный CSM** | Предприятие | $500 тыс.-2 млн | Более высокая стоимость; более глубокие отношения |
| **Названный исполнительный спонсор CSM +** | Стратегический | $300 тыс.-1 млн | Самая высокая стоимость; зарезервировано для топовых аккаунтов |

**Запуск** `cs_coverage_calculator.py` с характеристиками книги для расчета требуемой численности персонала CSM и определения пороговых значений перехода.

Видишь `references/cs_coverage_model.md` для коэффициентов, кривых наклона и триггера "когда добавлять менеджера".

### 4. Эволюция организации CS Team { #4-cs-team-org-evolution }

** Неправильный вопрос: ** "Должны ли мы нанять CSM или инженера технической поддержки?"
** Правильный вопрос: ** "Какого следующего результата для клиентов нам не удается достичь, и какая роль способствует этому?"

**Критические различия (основатели путают их):**

| Роль | Владеет | НЕ владеет |
|---|---|---|
| Служба поддержки клиентов | Реактивное разрешение проблемы (очередь заявок) | Обновление, расширение, успешные результаты |
| Менеджер по работе с клиентами | Активная реализация ценностей + обновление + лидерство в расширении | Ежедневные билеты, внедрение |
| Менеджер по работе с клиентами | Коммерческие отношения + завершение расширения | Повседневный успех, техническая глубина |
| Менеджер по внедрению | Онбординг + выход в эфир | Постоянный успех после запуска |
| Операции CS | Инструменты, данные, аналитика, плейбуки | Прямые отношения с клиентами |
| Маркетинг для клиентов | Адвокация, тематические исследования, ссылки | отношения с клиентами 1:1 |

Видишь `references/cs_team_org_evolution.md` для карты от этапа к роли (начальный → поздний этап) + раздельное решение AM-vs-CSM.

## Воркфлоу { #workflows }

### Воркфлоу 1: Ежеквартальный ревью по удержанию персонала (4 часа) { #workflow-1-quarterly-retention-review-4-hours }
** Цель:** Честно распределить удержание + определить топ-3 факторов оттока.

```bash
# 1. Pull cohort data: closed/won by quarter for last 8 quarters
python scripts/retention_decomposition_analyzer.py cohorts.json
# 2. Review GRR / NRR / contraction / expansion separately
# 3. For each cohort showing GRR < 90%: identify churn root cause (7-category taxonomy)
# 4. Cross-check with cs-cro-advisor: does the expansion math add up?
# 5. Cross-check with cs-cpo-advisor: are product gaps driving churn?
# 6. Output: top-3 leakage points + 90-day mitigation plan
```

### Воркфлоу 2: Аудит сегментации клиентов (1 день) { #workflow-2-customer-segmentation-audit-1-day }
**Цель:** Пересегментировать клиентскую базу + сбросить дифференцированные инвестиции.

```bash
# 1. Build customers.json with ARR, tenure, ICP fit signals
python scripts/customer_segmentation_designer.py customers.json
# 2. Identify segment migration (mid-market → enterprise upgrades, downsells)
# 3. Identify kill list (customers below investment floor)
# 4. Output: new tier assignment + investment-per-tier + kill list for sales review
```

### Воркфлоу 3: Определение состава команды CS (1 неделя) { #workflow-3-cs-team-sizing-1-week }
** Цель:** Укомплектовать команду CS в соответствии с моделью "Состав книги + охват".

```bash
# 1. Build book.json with current customer base + planned acquisition
python scripts/cs_coverage_calculator.py book.json
# 2. Calculate required CSM headcount by segment
# 3. Compare to current team; identify gaps
# 4. Cross-check with cs-chro-advisor on comp + leveling
# 5. Cross-check with cs-cfo-advisor on the cost
# 6. Output: 12-month hiring plan + role sequence
```

### Воркфлоу 4: Дорожная карта команды CS (1 неделя) { #workflow-4-cs-team-roadmap-1-week }
** Цель:** Последовательность найма сотрудников CS в течение следующих 18 месяцев в соответствии с результатами работы с клиентами.

1. Перечислите 5 лучших результатов для клиентов, которых компании не удается достичь
2. Сопоставьте каждый результат с ролью, которая его разблокирует (CSM / AM / IM / Support / CS Ops)
3. Последовательность найма; соблюдайте обязательный порядок
4. Перекрестная проверка с помощью cs-chro-advisor
