# Главный юрисконсульт Советник { #general-counsel-advisor }

Стратегические правовые фреймворки для генеральных консультантов стартапов и основателей без таковых. Контрактный риск, стратегия в области интеллектуальной собственности, расшифровка терминов, нормативно-правовая база.

Это ** не юридическая консультация**. Это выявляет правильные вопросы, которые нужно задать квалифицированному внешнему консультанту, и выявляет очевидные ловушки еще до того, как они дойдут до подписи. Относитесь к каждому результату как к отправной точке для разговора с лицензированным адвокатом, а не как к замене такового.

## Ключевые вопросы (задайте их в первую очередь) { #key-questions-ask-these-first }

- ** Кому принадлежит создаваемый или совместно используемый IP-адрес?** (Учредители забывают, что подрядчики не назначают IP автоматически без письменного условия.)
- ** Каков предел ответственности и что из этого следует?** (Стандарт: 12 месяцев сборов, с вычетами за нарушение прав интеллектуальной собственности, утечку данных, умышленное неправомерное поведение.)
- ** Действует ли DPA в случае утечки каких—либо персональных данных?** (GDPR, CCPA, законы штатов - не подлежат обсуждению, если затрагиваются данные ЕС / ЦА.)
- ** Каково право на расторжение, срок уведомления и ловушка автоматического продления? ** (автоматическое продление на 5 лет с уведомлением за 60 дней - распространенная ошибка основателей.)
- **Является ли этот контракт или запуск продукта триггером для нового режима регулирования?** (Здравоохранение → HIPAA. Финтех → BSA/AML. Медицинское оборудование → FDA/MDR.)
- ** Для срочных отчетов: предпочтение при ликвидации, пул опционов до получения денег, защита от разбавления? ** (Три места, где 5% экономики основателя могут незаметно исчезнуть.)

## Основные обязанности { #core-responsibilities }

### 1. Ревью контракта { #1-contract-review }

Стандартные контракты, которые стартап подписывает в течение первых 5 лет своей деятельности:

- **MSA поставщика** — Основное соглашение об обслуживании (облако, инструменты, сервисы)
- **Клиентское соглашение SaaS** — ваш стандартный документ для клиента + красные линии для клиентов
- **NDA** — взаимный + односторонний, с выделением остатков + независимая разработка
- **DPA** — Соглашение об обработке данных (требуется при передаче персональных данных)
- **Трудовое соглашение** — письмо-предложение, передача интеллектуальной собственности, отказ от конкуренции (если это возможно), арбитраж
- **Соглашение с подрядчиком / 1099** — Назначение IP имеет решающее значение; риск неправильной классификации
- **Соглашения о долевом участии** — опционные гранты, соглашения RSU, гранты консультантов (БЫСТРЫЙ шаблон, YC БЕЗОПАСЕН для консультантов)

**Запуск** `contract_risk_scanner.py` по тексту. В нем отмечены 12 наиболее распространенных положений, убивающих основателей.

### 2. Стратегия в области ИС { #2-ip-strategy }

- **Задание на изобретение** — каждый сотрудник и подрядчик подписывает его. Никаких исключений.
- ** Соответствие лицензии с открытым исходным кодом ** — отслеживание лицензии каждой зависимости от OSS; AGPL и GPL триггеры авторского лева.
- ** Коммерческая тайна** — определите, что и как защищено (разработка чистых помещений, контроль доступа, NDA).
- **Патенты** — подача предварительной заявки в течение 12 месяцев с момента раскрытия; PCT для международных.
- **Товарные знаки** — сначала зарегистрируйте словесный знак, затем дизайнерский знак; очистите перед запуском.
- ** Авторское право** — автоматически при создании, но регистрируйтесь для получения предусмотренного законом права на возмещение ущерба.

Видишь `references/ip_and_regulatory.md`.

### 3. Расшифровка таблицы терминов { #3-term-sheet-decoding }

Когда приходит список условий, разница между списком, благоприятствующим основателю, и списком, враждебным основателю, часто скрывается в трех пунктах:

- **Предпочтение при ликвидации** — 1 раз неучастие является стандартным; 1 раз участие или 2 раза враждебность
- ** Пул опционов "До денег" против пула опционов "после денег" ** - Пул опционов "до денег" разбавляет учредителей; пул опционов "после денег" пропорционально разбавляет всех
- **Защита от разбавления** — средневзвешенное значение на широкой основе является стандартным; полный храповик является враждебным

**Запуск** `term_sheet_analyzer.py` чтобы получить оценку дружелюбия основателя от 0 до 100 баллов, используйте флажки.

### 4. Нормативный ландшафт { #4-regulatory-landscape }

Когда следует привлекать стороннего консультанта ** перед совершением**:

| Триггер | Режим | Первый шаг |
|---|---|---|
| Медицинские данные | HIPAA, HITECH, государственные законы о нарушениях | Специализированный консультант по медицинским технологиям |
| Данные о владельце карты | PCI DSS (отраслевой стандарт, не закон, но обязательный по контракту) | QSA + юрисконсульт |
| Движение денег | BSA/AML, государственный денежный переводчик (лоскутное одеяло из 50 штатов) | Специалист по финтеху |
| Претензии к медицинскому устройству | FDA 510 (k) / De Novo / PMA, MDR (ЕС), ISO 13485 | Специалист по медицинскому оборудованию |
| Персональные данные жителей ЕС | GDPR + Закон ЕС об искусственном интеллекте, если искусственный интеллект деплою | Советник ЕС по вопросам конфиденциальности |
| Жители Калифорнии | CCPA / CPRA | Специалист широкого профиля по вопросам конфиденциальности |
| Ценные бумаги (токены, краудфандинг акций) | Правила SEC (Reg D, Reg A+, Reg CF) | Консультант по ценным бумагам |
| Заказчики оборонной и аэрокосмической промышленности | ИТАР, EAR, DFARS, CMMC | Консультант по экспортному контролю |
| Искусственный интеллект в ЕС | Закон ЕС об ИИ (с учетом уровня риска) | Консультант по вопросам конфиденциальности в ЕС + продукт |
| Искусственный интеллект для найма (Нью-Йорк, Колорадо, Иллинойс) | Местные законы о предвзятом отношении к аудиту | Консультант по трудоустройству |

Видишь `references/ip_and_regulatory.md` для упорядочивания.

## Воркфлоу { #workflows }

### Воркфлоу 1: Ревью контракта { #workflow-1-contract-review }
1. Сохраните контракт в виде обычного текста
2. Бежать `contract_risk_scanner.py path/to/contract.txt`
3. Для каждого вывода о ВЫСОКОМ риске подготовьте встречное предложение
4. Доведите "красную линию" + встречные предложения до внешнего консультанта
5. Зарегистрируйте решение с помощью `/cs:decide`

### Воркфлоу 2: Ответ на тестовый лист { #workflow-2-term-sheet-response }
1. Сохраните таблицу терминов в виде файла JSON, соответствующего схеме в `term_sheet_analyzer.py --help`
2. Бежать `python scripts/term_sheet_analyzer.py path/to/term_sheet.json`
3. Ревью оценку дружелюбия основателя и флаги для каждого предложения
4. Обсудите 3 худших условия (не пытайтесь выиграть все 20)
5. Всегда проводите ревью юриста по ценным бумагам/венчурному бизнесу перед подписанием
6. Войдите в систему через `/cs:decide` с `/cs:freeze 30` чтобы предотвратить повторное открытие, вызванное сожалением

### Воркфлоу 3: Аудит гигиены интеллектуальной собственности { #workflow-3-ip-hygiene-audit }
1. Подтвердите, что каждый сотрудник и подрядчик (за последние 12 месяцев) подписали задание на изобретение
2. Запустите инвентаризацию лицензий OSS (`pip-licenses`, `license-checker` для нпм)
3. Сопоставьте зависимости AGPL/GPL и подтвердите соответствие (или удалите)
4. Подача предварительных патентов на новые изобретения (12-месячный срок с момента раскрытия)
5. Зарегистрировать словесные товарные знаки для названия продукта

### Воркфлоу 4: Оценка регулирующих триггеров { #workflow-4-regulatory-trigger-assessment }
1. Перечислите запланированные функции продукта на следующие 12 месяцев
2. Сопоставьте каждый объект с таблицей триггеров в этом документе
3. Для любого триггера HIPAA / FDA / fintech обратитесь к специалисту-консультанту ** перед** созданием
4. Задокументируйте нормативную дорожную карту и бюджет вместе с дорожной картой продукта
5. Соедините с `cs-ciso-advisor` для последовательности ISO 27001/SOC 2
