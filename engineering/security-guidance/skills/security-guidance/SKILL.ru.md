# Крючок для наведения безопасности { #security-guidance-hook }

** Предустановленный хук, который блокирует 12 распространенных анти-шаблонов безопасности до того, как Claude Code их запишет.**

Этот скилл - это **хук**, а не слэш-команда. После установки он запускается автоматически перед каждым `Edit`, `Write`, или `MultiEdit` операция и предупреждает + блокирует, если обнаруживает известную опасную схему.

## Что он улавливает { #what-it-catches }

Крючок сканирует оба:

- **Редактируемый путь к файлу** — помечает файлы воркфлоу GitHub Actions как опасные `${{ }}` узоры
- **Записываемое содержимое** — подстрока соответствует 11 анти-шаблонам

| Узор | Категория | Риск |
|---|---|---|
| Действия GitHub в воркфлоу выражениях | Основанный на пути | Внедрение команды воркфлоу с помощью ненадежных входных данных |
| `child_process.exec`, `exec(`, `execSync(` | Подстрока | Node.js ввод команды |
| `new Function` | Подстрока | Внедрение JS-кода |
| `eval(` | Подстрока | Внедрение JS-кода |
| `dangerouslySetInnerHTML` | Подстрока | Реагировать на XSS |
| `document.write` | Подстрока | DOM XSS |
| `.innerHTML =` | Подстрока | DOM XSS |
| `pickle` | Подстрока | Десериализация Python RCE |
| `os.system`, `from os import system` | Подстрока | Внедрение команды Python |
| `shell=True` (подпроцесс) | Подстрока | Внедрение команды Python |
| f-строка SQL или `.format` SQL | Подстрока | SQL-инъекция |
| `yaml.load(`, `yaml.unsafe_load` | Подстрока | RCE десериализации YAML |

## Как это работает { #how-it-works }

1. Код Клода вот-вот запустится `Edit`, `Write`, или `MultiEdit`
2. Крючок предварительного использования запускается → вызывает `security_reminder_hook.py` с помощью инструмента, вводимого в виде JSON в stdin
3. Хук извлекает file_path + content + проверяет по таблице шаблонов
4. Если шаблон совпадает И это предупреждение не было показано для этого файла+правила в этом сеансе:
   - Напечатайте предупреждение для stderr (Клод его видит)
   - Код выхода 2 → блокирует вызов инструмента
   - Сохраните ключ предупреждения в `~/.claude/security_warnings_state_<session>.json`
5. Если шаблон совпадает, НО предупреждение уже было показано в этом сеансе:
   - Разрешить вызов инструмента (код выхода 0) — Клод уже видел предупреждение один раз
6. Если ни один шаблон не совпадает:
   - Разрешить вызов инструмента (код выхода 0)

## Установка { #installation }

Этот плагин поставляется в виде плагина Claude Code с `hooks.json` электропроводка:

```bash
# In Claude Code:
/plugin marketplace add alirezarezvani/claude-skills
/plugin install security-guidance@claude-code-skills
```

После установки дальнейшая настройка не требуется — крючок запускается автоматически.

## Конфигурация { #configuration }

Отключать для каждого сеанса с помощью переменной окружения:

```bash
ENABLE_SECURITY_REMINDER=0 claude
# Hook is bypassed for this session
```

Используйте экономно — хук наиболее полезен именно тогда, когда у вас возникает соблазн отключить его (потому что у вас поджимают сроки отправки чего-то, что, как вы знаете, является отрывочным).

## Шаблон переопределения для каждого файла { #per-file-override-pattern }

Если конкретный файл законно нуждается `eval()` или `pickle` (например, изолированный REPL, намеренно небезопасный синтаксический анализатор для фаззера), задокументируйте это в файле с комментарием:

```python
# SAFETY: pickle is the required serialization format for this internal tool.
# This file does NOT accept untrusted input. See SECURITY.md for boundary analysis.
import pickle
```

Хук по-прежнему будет предупреждать при первом редактировании за сеанс. После подтверждения разрешены последующие правки в том же сеансе (кэширование состояния сеанса).

## Почему шаблоны основаны на подстроках (А не на AST) { #why-the-patterns-are-substring-based-not-ast-based }

Компромисс: обнаружение на основе AST было бы более точным (никаких ложных срабатываний для строковых литералов, содержащих "eval("). Основанный на подстроке - это:

- **Быстрее** — запускается в ms, не анализирует файл
- ** Межъязыковой ** - тот же хук работает для JS / TS / Python /YAML /etc.
- **Консервативный** — ложноположительные результаты легко устранить (одним нажатием клавиши); ложноотрицательные результаты опасны

Более чем в 90% случаев достаточно определения подстроки. Если вам нужно более строгое обнаружение, используйте соответствующий инструмент SAST (semgrep, CodeQL) в качестве шага CI.

## Государственные файлы { #state-files }

Хук кэширует состояние "показано предупреждение" в `~/.claude/security_warnings_state_<session_id>.json`. Эти файлы:

- Автоматически очищаются через 30 дней (вероятность 10% при каждом вызове хука)
- Ограничены областью действия сеанса (каждая сессия Claude получает свою собственную)
- Содержать список в формате JSON из `<file_path>-<rule_name>` ключи

Вы можете безопасно удалить `~/.claude/security_warnings_state_*.json` файлы в любое время — хук восстанавливает их при следующем запуске.

## Журнал отладки { #debug-log }

Крючок записывает в `~/.claude/security-warnings-log.txt` для отладки ошибок срабатывания крючка:

```bash
tail -f ~/.claude/security-warnings-log.txt
# Shows JSON decode errors, state-file save failures, etc.
```

(Исходная версия, записанная в `/tmp/security-warnings-log.txt` — мы перенесли его в `~/.claude/` для сохранения при перезагрузках.)

## Анти-паттерны { #anti-patterns }

### Отключение перехвата по умолчанию { #disabling-the-hook-by-default }

Разрушает цель. Если `ENABLE_SECURITY_REMINDER=0` становится вашим дефолтом, вы приучили себя игнорировать систему безопасности. Используйте его только для определенных проверенных безопасных операций.

### Изменение списка шаблонов без ревью системы безопасности { #modifying-the-pattern-list-without-security-review }

Любой желающий может добавить шаблон. Удаление одного из них требует ревью безопасности — шаблоны существуют, потому что они сопоставляются с реальными классами CVE.

### Рассмотрение состояния сеанса как неизменяемой политики безопасности { #treating-session-state-as-immutable-security-policy }

Кэш предотвращает назойливый спам, но используется для каждой сессии. Не полагайтесь на "я отклонил это однажды" в качестве долгосрочной политики - вместо этого используйте шаблон документации для каждого файла (комментарий, оправдывающий использование).
