# Кодовый тур { #code-tour }

Создайте файлы **CodeTour** — ориентированные на персону пошаговые инструкции по кодовой базе, которые напрямую ссылаются на файлы и номера строк. Файлы CodeTour хранятся в `.tours/` и работать с [VS Code Расширение CodeTour](https://github.com/microsoft/codetour).

## Обзор { #overview }

Отличный тур — это ** повествование** - история, рассказанная конкретному человеку о том, что важно, почему это важно и что делать дальше. Только создавать `.tour` Файлы в формате JSON. Никогда не изменяйте исходный код.

## Когда использовать этот Скилл { #when-to-use-this-skill }

- Пользователь просит создать экскурсию по коду, онбординг-тур или пошаговое руководство по архитектуре
- Пользователь говорит "тур для этого PR", "объясните, как работает X", "проверка вибрации", "тур RCA".
- Пользователь хочет получить руководство для участников, ревью по безопасности или пошаговое руководство по расследованию ошибок
- Любой запрос на структурированное пошаговое руководство с привязками к файлам/строкам

## Основной воркфлоу { #core-workflow }

### 1. Откройте для себя репозиторий { #1-discover-the-repo }

Прежде чем что-либо спрашивать, изучите кодовую базу:

Параллельно: перечислите корневой каталог, прочитайте README, проверьте конфигурационные файлы.
Затем: определите язык (ы), фреймворк(ы), цель проекта. Структура папок карты глубиной 1-2 уровня. Найдите точки входа — каждый путь в туре должен быть реальным.

Если в репозитории меньше 5 исходных файлов, создайте быстрый углубленный тур независимо от персоны - этого недостаточно, чтобы гарантировать углубленный тур.

### 2. Сделайте вывод о намерении { #2-infer-the-intent }

Одного сообщения должно быть достаточно. Определите персону, глубину и сосредоточьтесь молча.

| Пользователь говорит | Персона | Глубина |
|-----------|---------|-------|
| "тур для этого пиара" | pr-обозреватель | стандартный |
| "почему X сломался" / "RCA" | rca-исследователь | стандартный |
| "Онбординг" / "новый столяр" | новичок-столяр | стандартный |
| "краткий тур" / "проверка атмосферы" | вибродатчик | быстрый |
| "архитектура" | архитектор | глубокий |
| "безопасность" / " ревью авторизации" | специалист по проверке безопасности | стандартный |
| (без уточнения) | новичок-столяр | стандартный |

Когда намерение неоднозначно, по умолчанию используется персона **new-joiner** на *стандартной** глубине — это наиболее полезно в целом.

### 3. Прочитайте фактические файлы { #3-read-actual-files }

**Каждый путь к файлу и номер строки должны быть проверены.** Экскурсия, указывающая на неправильную линию, хуже, чем отсутствие экскурсии.

### 4. Напишите программу тура { #4-write-the-tour }

Сохранить в `.tours/<persona>-<focus>.tour`.

```json
{
  "$schema": "https://aka.ms/codetour-schema",
  "title": "Descriptive Title — Persona / Goal",
  "description": "Who this is for and what they'll understand after.",
  "ref": "<current-branch-or-commit>",
  "steps": []
}
```

### Типы шагов { #step-types }

| Тип | Когда использовать | Пример |
|------|-------------|---------|
| **Содержание** | Только вступление/закрытие (максимум 2) | `{ "title": "Welcome", "description": "..." }` |
| **Каталог** | Ориентация на модуль | `{ "directory": "src/services", "title": "..." }` |
| **Файл + строка** | Рабочая лошадка | `{ "file": "src/auth.ts", "line": 42, "title": "..." }` |
| **Выбор** | Выделите блок кода | `{ "file": "...", "selection": {...}, "title": "..." }` |
| **Узор** | Совпадение регулярных выражений (изменчивые файлы) | `{ "file": "...", "pattern": "class App", "title": "..." }` |
| **URI** | Ссылка на PR, выпуск, документ | `{ "uri": "https://...", "title": "..." }` |

### Количество шагов { #step-count }

| Глубина | Шаги | Использовать для |
|-------|-------|---------|
| Быстрый | 5-8 | Виброкодер, быстрое исследование |
| Стандартный | 9-13 | Большинство персонажей |
| Глубокий | 14-18 | Архитектор, RCA |

### Написание описаний — формула SMIG { #writing-descriptions--smig-formula }

- **S — ситуация**: На что смотрит читатель?
- **M — механизм**: Как работает этот код?
- **Я — подтекст**: Почему это имеет значение для данной персоны?
- **G — Попался**: В чем умный человек мог бы ошибиться?

### 5. Подтвердите { #5-validate }

- [ ] Каждый `file` путь относительно корня репозитория (без ведущего `/` или `./`)
- [ ] Каждый `file` подтверждено существование
- [ ] Каждый `line` проверено путем прочтения файла
- [ ] Первый шаг имеет `file` или `directory` якорь
- [ ] Не более 2 шагов только для содержимого
- [ ] `nextTour` совпадает с другим туром `title` точно, если задано

## Персонажи { #personas }

| Персона | Цель | Должен покрывать |
|---------|------|------------|
| **Вибродатчик** | Быстро проникнись атмосферой | Точка входа, основные модули. Максимум 8 шагов. |
| **Новый столяр** | Структурированный рост | Каталоги, настройка, бизнес-контекст |
| ** Исправление ошибок** | Первопричина быстро | Триггер -> точки неисправности -> тесты |
| **Исследователь RCA** | Почему это не удалось | Цепочка причинно-следственных связей, якоря наблюдаемости |
| ** Пояснитель функций** | Сквозной | Пользовательский интерфейс -> API -> серверная часть -> хранилище |
| **Специалист по связям с общественностью** | Правильно проведите ревью | История изменений, инварианты, рискованные области |
| **Архитектор** | Форма и обоснование | Границы, компромиссы, точки расширения |
| **Специалист по проверке безопасности** | Границы доверия | Поток аутентификации, проверка подлинности, обработка секретов |
| **Рефакторинг** | Безопасная реструктуризация | Швы, скрытые углубления, порядок извлечения |
| **Внешний участник** | Вносите безопасный вклад | Безопасные зоны, конвенции, наземные мины |

## Повествовательная дуга { #narrative-arc }

1. **Ориентация** — `file` или `directory` шаг (никогда не содержит содержимого -только первый шаг — пустой в VS Code)
2. ** Карта высокого уровня** — 1-3 шага создания каталога с указанием основных модулей
3. **Основной путь** — шаги по файлам/строкам, сердце тура
4. **Заключение** — что теперь может сделать читатель, предлагаемые последующие действия

## Анти-паттерны { #anti-patterns }

| Анти-паттерн | Исправить |
|---|---|
| **Список файлов** — "этот файл содержит модели" | Расскажи историю. Каждый шаг зависит от предыдущего. |
| **Общие описания** | Назовите конкретный шаблон, уникальный для этой кодовой базы. |
| ** Угадывание номера строки** | Никогда не пишите строку, которую вы не проверили при чтении. |
| **Слишком много шагов** для быстрой глубины | Фактически вырезал ступеньки. |
| **Галлюцинированные файлы** | Если он не существует, пропустите этот шаг. |
| ** Подведение итогов ** — "мы рассмотрели X, Y, Z" | Расскажите читателю, что он теперь может *сделать*. |
| **Первый шаг только для контента** | Закрепите шаг 1 за файлом или каталогом. |
