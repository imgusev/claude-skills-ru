# /ar:run — Одиночная итерация эксперимента { #arrun--single-experiment-iteration }

Выполните ровно ОДНУ итерацию эксперимента: ревью историю, примите решение об изменении, отредактируйте, зафиксируйте, оцените.

## Использование { #usage }

```
/ar:run engineering/api-speed              # Run one iteration
/ar:run                                     # List experiments, let user pick
```

## Что он делает { #what-it-does }

### Шаг 1: Разрешите эксперимент { #step-1-resolve-experiment }

Если эксперимент не указан, запустите `python {skill_path}/scripts/setup_experiment.py --list` и попросите пользователя выбрать.

### Шаг 2: Загрузите контекст { #step-2-load-context }

```bash
# Read experiment config
cat .autoresearch/{domain}/{name}/config.cfg

# Read strategy and constraints
cat .autoresearch/{domain}/{name}/program.md

# Read experiment history
cat .autoresearch/{domain}/{name}/results.tsv

# Checkout the experiment branch
git checkout autoresearch/{domain}/{name}
```

### Шаг 3: Решите, что попробовать { #step-3-decide-what-to-try }

Результаты ревью.tsv:
- Какие изменения были сохранены? Какой паттерн у них общий?
- Что было отброшено? Избегайте повторения этих подходов.
- Что разбилось? Понимаю почему.
- Сколько пробежек уже было? (Соответствующим образом скорректируйте стратегию эскалации)

**Эскалация стратегии:**
- Этапы 1-5: Низко висящие фрукты (очевидные улучшения)
- Этапы 6-15: Систематическое исследование (изменение одного параметра)
- Прогоны 16-30: Структурные изменения (замена алгоритмов)
- Пробеги 30+: Радикальные эксперименты (совершенно разные подходы)

### Шаг 4: Внесите ОДНО изменение { #step-4-make-one-change }

Редактируйте только целевой файл, указанный в config.cfg. Измени одну вещь. Пусть все будет просто.

### Шаг 5: Фиксация и оценка { #step-5-commit-and-evaluate }

```bash
git add {target}
git commit -m "experiment: {short description of what changed}"

python {skill_path}/scripts/run_experiment.py \
  --experiment {domain}/{name} --single
```

### Шаг 6: Сообщите о результате { #step-6-report-result }

Прочитайте выходные данные скрипта. Сообщите пользователю:
- **ПРОДОЛЖАЙТЕ**: "Улучшение! {metric}: {value} ({delta} из предыдущих лучших)"
- **ОТБРОСИТЬ**: "Улучшений нет. {metric}: {value} против лучших {best}. Возвращено."
- **СБОЙ**: "Ошибка оценки: {reason}. Возвращено."

### Шаг 7: Проверка на самосовершенствование { #step-7-self-improvement-check }

После каждого 10-го эксперимента (проверьте количество строк results.tsv) обновляйте раздел Стратегии в program.md с усвоенными шаблонами.

## Правила { #rules }

- ОДНО изменение за итерацию. Не меняйте 5 вещей сразу.
- НИКОГДА не изменяйте средство оценки (evaluate.py ). Это абсолютная правда.
- Простота побеждает. Равная производительность при более простом коде - это улучшение.
- Никаких новых зависимостей.
