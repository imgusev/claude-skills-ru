# Скриншот всей страницы { #full-page-screenshot }

Сделайте полностраничный снимок экрана любой веб-страницы с помощью протокола Chrome DevTools. Создает единый PNG—файл, который включает в себя все содержимое - даже те части, которые требуют прокрутки. Нулевые внешние зависимости за пределами Node.js 22+ и Chrome с включенной удаленной отладкой.

## Предварительные условия { #prerequisites }

- **Node.js 22+** (использует встроенный `WebSocket`)
- **Chrome/Хромированный** с включенной удаленной отладкой

Проверьте готовность окружающей среды:

```bash
node "${SKILL_DIR}/scripts/full-page-screenshot.mjs" --check
```

Если проверка Chrome завершится неудачей, попросите пользователя открыть `chrome://inspect/#remote-debugging` и включите ** "Разрешить удаленную отладку для этого экземпляра браузера"**.

## Воркфлоу { #workflow }

### Вариант A: Сделайте снимок экрана с уже открытой вкладки (рекомендуется для аутентифицированных страниц) { #option-a-screenshot-an-already-open-tab-recommended-for-authenticated-pages }

1. Список доступных вкладок:

```bash
node "${SKILL_DIR}/scripts/full-page-screenshot.mjs" --list
```

2. Определите цель по названию/URL-адресу, затем захватите:

```bash
node "${SKILL_DIR}/scripts/full-page-screenshot.mjs" <targetId> /tmp/screenshot.png --width 1200 --dpr 1
```

### Вариант B: Скриншот URL-адреса (открывает фоновую вкладку, захватывает, закрывает) { #option-b-screenshot-a-url-opens-a-background-tab-captures-closes }

```bash
node "${SKILL_DIR}/scripts/full-page-screenshot.mjs" --url "https://example.com" /tmp/screenshot.png --width 1200 --dpr 1 --wait 15000
```

> **Примечание:** `--url` режим создает фоновую вкладку. Страницы, требующие аутентификации (SSO, стены входа в систему), должны вместо этого использовать опцию A.

### Параметры { #parameters }

| Параметр | Описание | Значение по умолчанию |
|-----------|-------------|---------|
| `output` | Путь к выходному PNG-файлу | `/tmp/screenshot.png` |
| `--width` | Ширина видового экрана в пикселях CSS (статьи: 1200, дашборды: 1440-1920) | 1200 |
| `--dpr` | Соотношение пикселей устройства (2 = Retina, но размер файла в 4 раза больше) | 1 |
| `--wait` | Время ожидания загрузки страницы в мс (`--url` только режим) | 15000 |
| `--css` | Пользовательский CSS для ввода перед захватом (например, скрытие элементов) | — |

### Проверьте выходные данные { #verify-output }

```bash
# macOS
sips -g pixelWidth -g pixelHeight /tmp/screenshot.png

# Linux
file /tmp/screenshot.png
```

## Основные возможности { #core-capabilities }

1. **Расширение контейнера прокрутки SPA** — Обнаруживает `overflow-y: auto/scroll` контейнеры, прокручивает их, чтобы триггер отложенной загрузки, затем удаляет ограничения переполнения (включая попутный ветер `h-[calc(...)]`) таким образом, весь контент рендерится за один проход.

2. **Определение стабильности DOM** — После `readyState=complete`, отслеживает количество элементов DOM до тех пор, пока оно не стабилизируется. Это гарантирует, что фреймворки SPA завершат рендеринг динамического контента.

3. **Триггер отложенной загрузки ** - Постепенная прокрутка видового экрана для запуска `IntersectionObserver` выполняет обратные вызовы, затем ожидает всех `<img>` элементы для завершения загрузки.

4. **Захват фрагментов для страниц очень высокого размера ** — Страницы размером более 16 000 пикселей захватываются фрагментами размером 8000 пикселей и автоматически сшиваются с помощью Python PIL. Возвращается к сохранению плиток отдельно, если PIL недоступен.

5. **Автоматическое обнаружение Chrome** — Считывает `DevToolsActivePort` файл, чтобы найти порт отладки. Возвращается к проверке портов 9222, 9229, 9333.

6. **Резервный прокси-сервер CDP** — Когда прокси-сервер CDP удерживает веб-сокет браузера, скрипт возвращается к конечным точкам API прокси (`/eval`, `/screenshot`, `/scroll`) для захвата.

## Как это работает { #how-it-works }

```
1. Discover Chrome debugging port
2. Connect via WebSocket (CDP)
3. Attach to target / create background tab
4. Set viewport width via Emulation domain
5. Wait: readyState + DOM stability
6. Detect & expand scroll containers
7. Scroll through page (trigger lazy-load)
8. Wait for images to complete
9. Measure final content height
10. Page.captureScreenshot (or tiled capture)
11. Stitch tiles if needed (PIL)
12. Restore viewport, detach, clean up
```

## Анти-паттерны { #anti-patterns }

| НЕ ДЕЛАЙ ЭТОГО | Делайте вместо этого |
|--------|-----------|
| Использование `--dpr 2` на страницах размером более 10 000 пикселей | Использование `--dpr 1` чтобы избежать проблем с памятью Chrome |
| Использование `--url` для страниц, прошедших проверку подлинности/единого входа | Использование `--list` + TargetID на вкладке, где пользователь вошел в систему |
| Набор `--wait` ниже 5000 для спа-салонов | Спасателям требуется время для извлечения данных и рендеринга; используйте 10000-15000 |
| Захват без проверки `--check` первый | Всегда проверяйте, доступна ли отладка Chrome |
| Жестко заданная ширина видового экрана для всех страниц | Используйте 1200 для статей, 1440+ для дашбордов/таблиц |
| Пропустить проверку выходных данных | Всегда проверяйте с помощью `sips` или `file` команда после захвата |

## Устранение неполадок { #troubleshooting }

| Симптом | Причина | Исправить |
|---------|-------|-----|
| "Не удается найти порт отладки Chrome" | Удаленная отладка не включена | Открытый `chrome://inspect/#remote-debugging`, включите его |
| "Тайм-аут подключения к WebSocket" | Прокси-сервер CDP, поддерживающий соединение | Скрипт автоматически возвращается к прокси-API |
| Пустой/белый скриншот | Страница еще не загружена | Увеличение `--wait` значение |
| Усеченный внизу | Контейнер прокрутки не развернут | Сценарий обрабатывает это автоматически; сообщите о проблеме, если она не устраняется |
| Из памяти | Очень высокая страница + высокий DPR | Уменьшить `--dpr` до 1 и/или уменьшить `--width` |
| "PIL недоступен для сшивания" | Подушка Python не установлена | Установите с помощью `pip3 install Pillow` или принимать отдельные файлы плиток |
