# Генератор рансбуков { #runbook-generator }

**Уровень:** МОЩНЫЙ  
**Категория:** Инженерия  
**Домен:** DevOps / Проектирование надежности сайта

---

## Обзор { #overview }

Быстро создавайте операционные рансбуки из имени службы, затем настраивайте для воркфлоу развертывания, реагирования на инциденты, обслуживания и отката.

## Основные возможности { #core-capabilities }

- Генерация скелета рансбука из командной строки
- Стандартные секции для запуска/stop/health/rollback
- Структурированная эскалация и обработка заполнителей для инцидентов
- Справочные шаблоны для развертывания и плейбуков по инцидентам

---

## Когда использовать { #when-to-use }

- У сервиса нет рансбука, и ему немедленно требуется базовая версия
- Существующие рансбуки несовместимы в разных командах
- Для онбординга по вызову требуется стандартизированная операционная документация
- Вам нужны повторяемые каркасы рансбука для новых сервисов

---

## Быстрый старт { #quick-start }

```bash
# Print runbook to stdout
python3 scripts/runbook_generator.py payments-api

# Write runbook file
python3 scripts/runbook_generator.py payments-api --owner platform --output docs/runbooks/payments-api.md
```

---

## Рекомендуемый воркфлоу { #recommended-workflow }

1. Сгенерируйте исходный скелет с помощью `scripts/runbook_generator.py`.
2. Заполните команды и URL-адреса, относящиеся к конкретной службе.
3. Добавьте проверки подлинности и триггеры отката.
4. Пробный запуск в промежуточном режиме.
5. Храните рансбук в системе управления версиями рядом со служебным кодом.

## Распространенные подводные камни { #common-pitfalls }

- Отсутствующие триггеры отката или команды отката
- Шаги без ожидаемых проверок выходных данных
- Устаревшее право собственности/escalation контакты
- Рансбуки никогда не тестировались вне инцидентов

## Лучшие практики { #best-practices }

1. Сохраняйте возможность копирования и вставки каждой команды.
2. Включайте проверки работоспособности после каждого критического шага.
3. Проверяйте рансбуки с фиксированной частотой ревью.
4. Обновляйте содержимое рансбука после инцидентов и вскрытий.
