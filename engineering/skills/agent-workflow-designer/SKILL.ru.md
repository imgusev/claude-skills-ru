# Дизайнер воркфлоу агента { #agent-workflow-designer }

**Уровень:** МОЩНЫЙ

## Обзор { #overview }

Производство-класс Дизайн Multi-агент рабочие процессы с четким выбором рисунка, хэндофф передачи, обработки сбоев и затрат контексте управления.

## Основные возможности { #core-capabilities }

- Выбор шаблона воркфлоу для многоступенчатых систем агентов
- Генерация скелетной конфигурации для быстрой начальной загрузки воркфлоу
- Контекст и дисциплина затрат в рамках долгосрочных потоков
- Построение стратегии восстановления после ошибок и повторных попыток
- Указатели документации для поиска компромиссов между операционными шаблонами

---

## Когда использовать { #when-to-use }

- Одной промпты недостаточно для определения сложности задачи
- Вам нужны специализированные агенты с четкими границами
- Вам нужна детерминированная структура воркфлоу перед внедрением
- Вам нужны циклы проверки для гейтов качества или безопасности

---

## Быстрый старт { #quick-start }

```bash
# Generate a sequential workflow skeleton
python3 scripts/workflow_scaffolder.py sequential --name content-pipeline

# Generate an orchestrator workflow and save it
python3 scripts/workflow_scaffolder.py orchestrator --name incident-triage --output workflows/incident-triage.json
```

---

## Карта узоров { #pattern-map }

- `sequential`: строгая пошаговая цепочка зависимостей
- `parallel`: разветвление/включение для независимых подзадач
- `router`: отправка по намерению/типу с резервным вариантом
- `orchestrator`: планировщик координирует специалистов с зависимостями
- `evaluator`: генератор + цикл качественного гейта

Подробные шаблоны: `references/workflow-patterns.md`

---

## Рекомендуемый воркфлоу { #recommended-workflow }

1. Выберите шаблон, основанный на форме зависимости и профиле риска.
2. Настройка каркаса с помощью `scripts/workflow_scaffolder.py`.
3. Определите поля контракта хэндоффа для каждого ребра.
4. Добавьте повторные попытки/тайм-ауты и гейты проверки вывода.
5. Пробный запуск с небольшими контекстными бюджетами перед масштабированием.

---

## Распространенные подводные камни { #common-pitfalls }

- Чрезмерно сложные задачи, решаемые с помощью одной хорошо структурированной промпты
- Отсутствующие политики тайм-аута/повторных попыток для вызовов внешней модели
- Передача полного восходящего контекста вместо целевых артефактов
- Игнорирование накопления затрат на каждый шаг

## Лучшие практики { #best-practices }

1. Начните с самого маленького шаблона, который может удовлетворить вашим требованиям.
2. Держите полезные нагрузки хэндоффа явными и ограниченными.
3. Проверьте промежуточные выходные данные перед расширенным синтезом.
4. Соблюдайте ограничения по бюджету и времени ожидания на каждом этапе.
