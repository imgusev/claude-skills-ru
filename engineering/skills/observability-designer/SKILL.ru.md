# Конструктор наблюдаемости (МОЩНЫЙ) { #observability-designer-powerful }

**Категория:** Инженерия  
**Уровень:** МОЩНЫЙ  
**Описание:** Разрабатывайте комплексные стратегии обеспечения наблюдаемости для производственных систем, включая фреймворки SLI/SLO, оптимизацию оповещений и генерацию дашбордов.

## Обзор { #overview }

Observability Designer создает готовые к работе дашборды, конфигурации оповещений и стратегии мониторинга по трем основным направлениям (метрики, журналы, трассировки).

**Когда НЕ следует использовать → slo-architect.** Для проектирования SLO/SLI с математикой бюджета ошибок, пороговыми значениями скорости выгорания в многооконном режиме и гейтами ревью SLO, перейдите к `slo-architect` — это авторитетный скилл для той половины. Этот скилл - это `slo_designer.py` создает только быстрый каркас. Особенность этого скилла: дашборды (`dashboard_generator.py`) и оповещение-шумоподавление (`alert_optimizer.py`).

## Быстрый старт { #quick-start }

```bash
# Dashboard spec (Grafana JSON + docs) for a service
python3 scripts/dashboard_generator.py --service-type api --name payments --criticality critical --role sre --format grafana -o dashboard.json --doc-output dashboard.md

# Analyze an existing alert config for noise, duplicates, and coverage gaps
python3 scripts/alert_optimizer.py --input alerts.json --analyze-only --report alert_report.json
# ...then emit the optimized config once the report is reviewed:
python3 scripts/alert_optimizer.py --input alerts.json --output alerts_optimized.json

# Quick SLO scaffold (hand off to slo-architect for the real error-budget work)
python3 scripts/slo_designer.py --service-type api --criticality high --user-facing true --service-name payments -o slo_scaffold.json
```

** Цикл верификации: ** после деплою оптимизированных оповещений отследите показатели шума в отчете для одной ротации по вызову - если соотношение предупреждений, пригодных для принятия мер, не улучшилось, запустите повторно `--analyze-only` сверьтесь с текущей конфигурацией и выполните итерацию. Импортируйте сгенерированную дашборд в Grafana и подтвердите отображение каждой панели golden-signal данными в реальном времени, прежде чем закрывать задачу.

## Основные компетенции { #core-competencies }

### Проектирование фреймворка SLI/SLO/SLA { #slislosla-framework-design }
- **Индикаторы уровня обслуживания (SLI):** Определяют измеримые сигналы, указывающие на исправность сервиса
- **Цели по уровню обслуживания (SLO):** Установите целевые показатели надежности на основе пользовательского опыта
- **Соглашения об уровне обслуживания (SLA):** Устанавливают обязательства перед клиентами с вытекающими последствиями
- ** Управление бюджетом ошибок:** Расчет и отслеживание расхода бюджета ошибок
- ** Оповещение о частоте выгорания: ** Многооконные оповещения о частоте выгорания для проактивной защиты SLO

### Три столпа наблюдаемости { #three-pillars-of-observability }

#### Показатели { #metrics }
- ** Золотые сигналы:** Мониторинг задержек, трафика, ошибок и насыщенности
- **КРАСНЫЙ метод:** Частота, ошибки и продолжительность для служб, управляемых запросами
- **Метод использования:** Использование, насыщенность и ошибки для мониторинга ресурсов
- ** Бизнес-показатели:** Отслеживание доходов, вовлеченности пользователей и внедрения функций
- **Показатели инфраструктуры:** Показатели процессора, памяти, диска, сети и пользовательских ресурсов

#### Журналы { #logs }
- ** Структурированное ведение журнала: ** Форматы журналов на основе JSON с согласованными полями
- ** Агрегирование журналов: ** Централизованные стратегии сбора журналов и индексации
- ** Уровни журнала:** Надлежащее использование уровней DEBUG, INFO, WARN, ERROR, FATAL
- **Идентификаторы корреляции:** Отслеживание запросов через распределенные системы
- **Выборка журнала:** Управление объемом для систем с высокой пропускной способностью

#### Следы { #traces }
- **Распределенная трассировка:** Сквозная визуализация потока запросов
- **Дизайн диапазона:** Значимые границы диапазона и метаданные
- ** Отслеживание выборки:** Интеллектуальные стратегии отбора проб с точки зрения производительности и затрат
- **Карты служб:** Автоматическое обнаружение зависимостей с помощью трассировок
- **Анализ первопричин:** Воркфлоу отладки на основе трассировки

### Принципы проектирования дашбордов { #dashboard-design-principles }

#### Информационная архитектура { #information-architecture }
- **Иерархия:** Обзор → Служба → Компонент → Пути детализации экземпляра
- **Золотое сечение:** 80% операционных показателей, 20% исследовательских показателей
- **Когнитивная нагрузка: ** Максимум 7±2 панели на экран дашборд
- ** Путешествие пользователя:** Персонажи дашборд на основе ролей (SRE, разработчик, руководитель)

#### Лучшие практики визуализации { #visualization-best-practices }
- ** Выбор диаграммы:** Временные ряды для трендов, тепловые карты для распределений, индикаторы состояния
- ** Теория цвета: ** Красный - критический, желтый - предупреждающий, зеленый - здоровый.
- **Исходные данные:** Целевые показатели SLO, пороговые значения пропускной способности и исторические базовые показатели
- **Временные диапазоны:** По умолчанию установлены значимые окна (4 часа для инцидентов, 7 дней для тенденций)

#### Дизайн панели { #panel-design }
- ** Запросы метрик:** Эффективные запросы Prometheus/InfluxDB с правильной агрегацией
- ** Интеграция оповещений: ** Визуальные индикаторы состояния оповещения на соответствующих панелях
- **Интерактивные элементы:** Переменные шаблона, ссылки с детализацией и наложения аннотаций
- ** Производительность:** Время рендеринга менее секунды за счет оптимизации запросов

### Разработка и оптимизация оповещений { #alert-design-and-optimization }

#### Классификация предупреждений { #alert-classification }
- **Уровни серьезности:** 
  - **Критично:** Сбой в обслуживании, высокая скорость выгорания SLO
  - ** Предупреждение:** Приближение к пороговым значениям, проблемы, с которыми не сталкивается пользователь
  - ** Информация:** Уведомления о развертывании, оповещения о планировании мощностей
- ** Возможность принятия мер: ** Каждое предупреждение должно содержать четкое ответное действие
- **Маршрутизация предупреждений: ** Политики эскалации, основанные на серьезности и принадлежности к команде

#### Предупреждение об усталости { #alert-fatigue-prevention }
- ** Соотношение сигнал/шум: ** Высокая точность (несколько ложных срабатываний) при высокой скорости отзыва
- **Гистерезис:** Различные пороговые значения для срабатывания и разрешения предупреждений
- **Подавление:** Зависимое подавление предупреждений при известных отключениях
- ** Группировка:** Связанные оповещения сгруппированы в отдельные уведомления

#### Разработка правила оповещения { #alert-rule-design }
- **Выбор порогового значения:** Статистические методы определения порогового значения
- **Функции окна:** Соответствующие окна усреднения и вычисления процентилей
- ** Жизненный цикл оповещения:** Четкие условия срабатывания и критерии автоматического разрешения
- ** Тестирование:** Проверка правила оповещения на основе исторических данных

### Генерация рансбука и реагирование на инциденты { #runbook-generation-and-incident-response }

#### Структура Рансбука { #runbook-structure }
- ** Контекст предупреждения:** Что означает предупреждение и почему оно сработало
- **Оценка воздействия: ** Оценка воздействия, ориентированная на пользователя, по сравнению с внутренней оценкой воздействия
- **Этапы расследования:** Упорядоченные процедуры устранения неполадок с оценкой времени
- ** Действия по разрешению:** Общие исправления и процедуры эскалации
- **После инцидента:** Последующие задачи и меры по предотвращению

#### Схемы обнаружения инцидентов { #incident-detection-patterns }
- **Обнаружение аномалий:** Статистические методы обнаружения необычных закономерностей
- ** Составные оповещения: ** Многосигнальные оповещения для сложных режимов отказа
- ** Прогнозирующие оповещения: ** Прогнозные оповещения на основе потенциала и тенденций
- **Мониторинг канареек:** Раннее обнаружение с помощью мониторинга постепенного развертывания

### Фреймворк "Золотые сигналы" { #golden-signals-framework }

#### Мониторинг задержки { #latency-monitoring }
- ** Задержка запроса:** Отслеживание времени отклика P50, P95, P99
- ** Задержка в очереди:** Время, затраченное на ожидание в очередях обработки
- **Задержка в сети:** Задержки при межсервисной связи
- ** Задержка базы данных:** Показатели выполнения запросов и пула подключений

#### Мониторинг дорожного движения { #traffic-monitoring }

#### Мониторинг ошибок { #error-monitoring }

- **Распределение ошибок:** Классификация типов ошибок и определение тенденций

- ** Ограничение скорости:** Регулирование API и отслеживание исчерпания квот

## Обзор скриптов { #scripts-overview }

Этот скилл включает в себя три мощных скрипта на Python для комплексного проектирования наблюдаемости:

### 1. Разработчик SLO (`slo_designer.py`) { #1-slo-designer-slo_designerpy }
Генерирует полные фреймворки SLI/SLO на основе характеристик сервиса:
- **Входные данные:** Описание сервиса в формате JSON (тип, критичность, зависимости)
- ** Выходные данные:** Определения SLI, целевые показатели SLO, бюджеты ошибок, предупреждения о частоте выгорания, рекомендации SLA
- ** Особенности: ** Расчет скорости выгорания в нескольких окнах, бюджетная политика ошибок, генерация правил оповещения

### 2. Оптимизатор оповещений (`alert_optimizer.py`) { #2-alert-optimizer-alert_optimizerpy }
Анализирует и оптимизирует существующие конфигурации оповещений:
- ** Входные данные:** JSON-файл конфигурации оповещения с правилами, пороговыми значениями и маршрутизацией
- ** Результат:** Отчет об оптимизации и улучшенная конфигурация оповещений
- ** Особенности: ** Обнаружение шума, разрывы покрытия, идентификация дубликатов, оптимизация порогового значения

### 3. Генератор дашбордов (`dashboard_generator.py`) { #3-dashboard-generator-dashboard_generatorpy }
Создает исчерпывающие спецификации дашборда:
- **Входные данные:** Сервис/system описание JSON
- **Выходные данные:** JSON и документация, совместимые с дашбордом Grafana
- ** Особенности: ** Покрытие золотыми сигналами, методы RED /USE, пути детализации, представления на основе ролей
