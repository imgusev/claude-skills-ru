## Обзор { #overview }

Навигация, управление и оптимизация монорепозиций. Охватывает рабочие пространства Turborepo, Nx, pnpm и Lerna. Включает анализ влияния между пакетами, выборочные сборки/ тесты только для затронутых пакетов, удаленное кэширование, визуализацию графа зависимостей и структурированные миграции из мульти-репозитория в монорепозиторий. Включает конфигурацию кода Claude для разработки с учетом рабочего пространства.

---

## Основные возможности { #core-capabilities }

- ** Анализ влияния разных пакетов ** - определяет, какие приложения выходят из строя при изменении общего пакета
- **Выборочные команды** — запускайте тесты/сборки только для затронутых пакетов (не для всех)
- ** График зависимостей ** — визуализируйте взаимосвязи пакетов в виде диаграмм Mermaid
- ** Оптимизация сборки** — удаленное кэширование, инкрементные сборки, параллельное выполнение
- **Миграция** — пошаговое мульти-репо → монорепо с нулевой потерей истории
- **Публикация** — наборы изменений для управления версиями, каналы предварительной версии, воркфлоу публикации npm
- **Конфигурация кода Claude** — с учетом рабочего пространства CLAUDE.md с инструкциями по упаковке

## Когда использовать { #when-to-use }

Используйте, когда:
- Несколько пакетов/приложений совместно используют код (компоненты пользовательского интерфейса, утилиты, типы, клиенты API).
- Время сборки медленное, потому что все перестраивается, когда что-то меняется
- Переход из нескольких репозиториев в одно репозиторий
- Необходимо опубликовать пакеты в npm с скоординированным управлением версиями
- Команды работают с несколькими пакетами и нуждаются в унифицированном инструментарии

Пропустить, когда:
- Проект с одним приложением без общих пакетов
- Границы команды /проекта полностью изолированы (polyrepo подойдет)
- Общий код минимален, а затраты на копирование и вставку приемлемы

## Выбор инструмента { #tool-selection }

| Инструмент | Лучше всего подходит для | Ключевая особенность |
|---|---|---|
| **Турбореактивный двигатель** | JS/TS monorepos, простая конфигурация пайплайна | Лучшее в своем классе удаленное кэширование, минимальная конфигурация |
| **Nx** | Крупные предприятия, экосистема плагинов | График проекта, генерация кода, затронутые команды |
| **рабочие пространства pnpm** | Протокол рабочего пространства, эффективность работы диска | `workspace:*` для местных ссылок на пакеты |
| **Лерна** | публикация npm, управление версиями | Пакетная публикация, обычные фиксации |
| **Наборы изменений** | Современная версия (предпочтительнее Lerna) | Формирование списка изменений, каналы предварительного выпуска |

Самые современные настройки: **рабочие области pnpm + Turborepo + Наборы изменений**

## Распространенные подводные камни { #common-pitfalls }

| Ловушка | Исправить |
|---|---|
| Бегущий `turbo run build` без `--filter` на каждом PR | Всегда используйте `--filter=...[origin/main]` в КИ |
| `workspace:*` ссылки приводят к сбоям публикации | Использование `pnpm changeset publish` — он заменяет `workspace:*` с реальными версиями автоматически |
| Все пакеты перестраиваются при изменении несвязанных файлов | Мелодия `inputs` в turbo.json исключить документы, конфигурационные файлы из ключей кэша |
| Общий tsconfig приводит к тому, что один пакет нарушает все проверки типов | Использование `extends` правильно — каждый пакет расширяет root, но переопределяет `rootDir` / `outDir` |
| история git, потерянная во время миграции | Использование `git filter-repo --to-subdirectory-filter` перед объединением — никогда не перемещайте файлы вручную |
| Удаленный кэш не работает в CI | Проверьте переменные TURBO_TOKEN и TURBO_TEAM env; проверьте с помощью `turbo run build --summarize` |
| CLAUDE.md слишком общий — Клод изменяет неправильный пакет | Добавьте явные правила "При работе с X касаться файлов только в приложениях/X" для каждого пакета CLAUDE.md |

## Лучшие практики { #best-practices }

1. **Корень CLAUDE.md определяет карту** — документирует каждый пакет, его назначение и правила зависимостей
2. **В упаковке CLAUDE.md определяет правила** — что разрешено, что запрещено, тестирует команды
3. **Всегда определяйте область действия команд с помощью --filter** — выполнение всего при каждом изменении противоречит цели
4. ** Удаленный кэш необязателен ** — без него monorepo CI работает медленнее, чем CI с несколькими репозиториями
5. ** Наборы изменений вместо ручного управления версиями ** — никогда не редактируйте версии package.json вручную в monorepo
6. **Общие конфигурации в root, расширенные в пакетах** — tsconfig.base.json, .eslintrc.base.js , jest.base.config.js
7. **Анализ влияния перед объединением изменений общего пакета ** — запустите проверку влияния, сообщите радиус поражения
8. ** Сохраняйте пакеты / типы в виде чистого машинописного текста ** — нет кода во время выполнения, нет зависимостей, быстрая сборка и проверка типов
