# Конструктор воркфлоу { #workflow-builder }

Автор запускаемых сценариев воркфлоу для инструмента Claude Code для воркфлоу: детерминированные файлы оркестрации для нескольких агентов (`.js`), которые будут работать с саб-агентами нового контекста в рамках простого потока управления JavaScript. Только лист `agent()` вызовы тратят токены, поэтому основной сеанс остается чистым и весь запуск можно возобновить.

## ВСЕГДА начинайте каждый сеанс с приема пищи (не подлежит обсуждению) { #always-start-every-session-with-intake-non-negotiable }

Прежде чем предлагать или писать какой-либо воркфлоу, запустите прием. Не переходите к коду.

1. ** Спросите, какого рода воркфлоу они хотят.** Используйте этот набор вступительных вопросов:
   - Какую повторяемую, многоэтапную задачу вы хотите автоматизировать?
   - Какую единицу работы выполняет один саб-агент за один раз?
   - Сколько единиц измерения — известный список или обнаружено с помощью цикла?
   - Нужны ли на последующих этапах *все* предыдущие результаты сразу, или каждый элемент может выполняться сам по себе?
   - Требуется ли для какого-либо шага возврат структурированных данных (вердикт, список, оценки)?
   - Примерно сколько токенов / как глубоко это должно быть?

2. ** Если пользователь расплывчат, не затягивайте.** Запустите механизм рекомендаций, чтобы превратить все, что у вас есть, в 1-2 конкретных предложения, затем представьте их * с обоснованием*:
   ```bash
   python scripts/workflow_intake.py --task "their description" \
     --units unknown --stages unknown --needs-all unknown --structured unknown
   ```
   Механизм возвращает рекомендуемую топологию (разветвление / пайплайн / цикл / барьер / судейская коллегия), выбор модели, бюджетную защиту и однострочное обоснование для каждого выбора. Представляйте их как "Вот что я бы создал и почему" — никогда не просите пользователя повторно отвечать на вопросы, на которые он уже ответил наполовину.

3. **Подтвердите форму у пользователя** (топология + фазы + параллельный пайплайн) перед записью файла. Это единственный гейт для получения разрешения.

Видишь [ссылки/decision_and_intake_guide.md](references/decision_and_intake_guide.md) для получения полной информации о фреймворке вопросов, плейбуке с неопределенным вводом и отработанных примерах рекомендаций.

## Решите, является ли воркфлоу вообще подходящим инструментом { #decide-if-a-workflow-is-even-the-right-tool }

| Сценарий | Использование |
|----------|-----|
| Один саб-агент, одна задача | простой инструмент для агента |
| Процедура многократного использования, Клод выбирает шаги динамически | это Скилл |
| Множество саб-агентов в фиксированной топологии, детерминированной + возобновляемой | **Воркфлоу** ✓ |

Воркфлоу окупают свои затраты, когда работа параллельна или многоэтапна, должны быть воспроизводимыми, достаточно продолжительными, чтобы не завершаться на полпути (поэтому важно возобновить), или извлекать выгоду из изоляции каждого шага в отдельном контекстном окне. Для разовых задач просто используйте Claude напрямую.

## Сборка → проверка → запуск цикла { #build--validate--run-loop }

1. **Скаффолд** стартер из подтвержденной топологии:
   ```bash
   python scripts/scaffold_workflow.py --topology pipeline --name pr-triage \
     --description "Triage open PRs" > .claude/workflows/pr-triage.js
   ```
2. **Отредактируйте** файл: `meta` сначала блокируйте (чистый литерал, первый оператор), затем асинхронное тело, используя введенные глобальные значения — `agent()`, `pipeline()`, `parallel()`, `phase()`, `log()`, `budget`, `args`, `workflow()`. Полная поверхность в [ссылки/api_reference.md](references/api_reference.md); копировать-вставлять фигуры в [ссылки/orchestration_patterns.md](references/orchestration_patterns.md).
3. **Проверка** перед запуском — перехватывает синтаксический анализатор - фатальные ошибки:
   ```bash
   python scripts/validate_workflow.py .claude/workflows/pr-triage.js
   ```
4. **Запустите ** это: включите функцию с помощью `export CLAUDE_CODE_WORKFLOWS=1`, сохраните файл в разделе `.claude/workflows/`, затем используйте `/workflows` чтобы запустить и посмотреть его в прямом эфире. Нажмите **P** для приостановки/resume, **X** чтобы пропустить саб-агента. Вышедшие из строя агенты автоматически повторяют попытку.

## Жесткие правила (валидатор обеспечивает их соблюдение) { #hard-rules-validator-enforces-these }

- `meta` является ** чистым литералом** и ** первым оператором** — внутри него нет переменных, расширений, строк шаблона или вызовов функций.
- **Отсутствие недетерминизма:** `Date.now()`, `Math.random()`, без аргументов `new Date()` прервать возобновление — передавать временные метки через `args`.
- **Нет API файловой системы /узла ** (`require`, `fs`, `process`, сеть) в оркестраторе — эта работа принадлежит *внутри* `agent()` промпт.
- `parallel()` берет **грохочет** (`() => agent(...)`), а не голые обещания. По умолчанию используется значение `pipeline()` если только этапу не нужен весь предыдущий результирующий набор.
- **Защитите каждый разомкнутый цикл** счетчиком или `budget.remaining()` проверьте — незащищенные циклы достигают предела в 1000 агентов.
- Пропущенный фильтр/failed агенты: `results.filter(Boolean)`.

## Оснастка { #tooling }

- `scripts/workflow_intake.py` — механизм рекомендаций по приему (топология + модель + бюджет + обоснование на основе неопределенных исходных данных).
- `scripts/validate_workflow.py` — stdlib linter для приведенных выше правил; ПЕРЕДАЧА / ПРЕДУПРЕЖДЕНИЕ / СБОЙ с номерами строк.
- `scripts/scaffold_workflow.py` — сгенерировать стартер `.js` для любой топологии.
- `assets/templates/` — разветвление, пайплайн, цикл до тех пор, пока не начнутся бюджетные проекты. `assets/examples/` — полноценный запускаемый воркфлоу.

Все скрипты запускаются с `--sample` (без аргументов) и `--help`.
