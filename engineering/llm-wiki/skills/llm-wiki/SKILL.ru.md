# LLM Wiki — Второй мозг для Claude Code + Obsidian { #llm-wiki--second-brain-for-claude-code--obsidian }

Вдохновлен шаблоном LLM Wiki Андрея Карпати ([суть](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)). Этот скилл превращает Claude Code (или любого агента CLI) в дисциплинированного вики-сопровождающего, который ** постепенно создает и поддерживает ** постоянное взаимосвязанное хранилище Obsidian по мере того, как вы загружаете в него исходные тексты. Совокупность знаний — перекрестные ссылки, противоречия и обобщение - уже присутствует при запросе.

## Основной принцип { #core-principle }

Большинство воркфлоу LLM+docs - это **RAG**: извлекать фрагменты во время запроса, синтезировать с нуля, забыть. Вики - это ** усложнение **: исходные тексты читаются один раз, интегрируются в постоянную базу знаний Markdown и поддерживаются в актуальном состоянии. Вы курируете и спрашиваете; LLM читает, архивирует, дает перекрестные ссылки и поддерживает.

> Obsidian - это IDE. Магистр права - это программист. Вики - это кодовая база.

## Когда использовать { #when-to-use }

- ** Личные**: отслеживание целей, здоровье, психология, ведение дневника, самосовершенствование
- ** Исследование**: глубокие погружения в течение нескольких недель по теме — доклады, статейки, репортажи, развивающаяся диссертация
- ** Книжный компаньон **: сохраняйте главы по мере чтения; создайте компаньон в стиле фан-вики для персонажей, тем, сюжетных нитей
- ** Бизнес / команда **: внутренняя вики—страница, поддерживаемая Slack, заметки о встречах, звонки - LLM занимается обслуживанием, которым больше никто не хочет заниматься
- **Конкурентный анализ, due diligence, планирование поездок, конспекты курсов, увлекательные погружения**

** Не используйте, когда:** вам нужны одноразовые вопросы и ответы по фиксированному документу (используйте RAG), вы не планируете добавлять источники с течением времени или не хотите, чтобы Obsidian включался в цикл.

## Архитектура (три уровня) { #architecture-three-layers }

```
vault/
├── raw/                    # Layer 1 — IMMUTABLE source of truth
│   ├── <source files>      # Articles, papers, PDFs, images, data
│   └── assets/             # Downloaded images from clipped articles
├── wiki/                   # Layer 2 — LLM-owned knowledge base
│   ├── index.md            # Content catalog (LLM updates every ingest)
│   ├── log.md              # Append-only timeline (## [YYYY-MM-DD] <op> | <title>)
│   ├── entities/           # Person/Org/Place pages
│   ├── concepts/           # Ideas, theories, frameworks
│   ├── sources/            # One summary page per ingested source
│   ├── comparisons/        # Cross-source analysis pages
│   └── synthesis/          # High-level syntheses, theses, overviews
├── CLAUDE.md               # Schema + conventions (Claude Code)
└── AGENTS.md               # Same content, for Codex/Cursor/Antigravity
```

- **Слой 1 (необработанный/)** — ваш собственный. LLM только читает; никогда не записывает.
- **Уровень 2 (wiki/)** — принадлежит LLM. Он создает, обновляет страницы и дает перекрестные ссылки. Вы это читали.
- **Слой 3 (CLAUDE.md / AGENTS.md )** — *схема*. Соглашения, воркфлоу, правила frontmatter. Совместно разработано вами и LLM.

## Три основные операции { #three-core-operations }

1. ** Прием ** — LLM читает источник, обсуждает с вами выводы, пишет резюме источника, обновляет 10-15 релевантных страниц, обновляет индекс, добавляет в журнал. Видишь `references/ingest-workflow.md`.
2. **Запрос** — LLM считывает `index.md` сначала просматривает соответствующие страницы, обобщает с цитатами. Хорошие ответы ** заносятся обратно в вики **, так что исследования усложняются. Видишь `references/query-workflow.md`.
3. ** Lint** — Проверка работоспособности: противоречия, устаревшие утверждения, потерянные страницы, отсутствующие перекрестные ссылки, упомянутые концепции, но не имеющие собственной страницы, пробелы в данных, которые необходимо заполнить с помощью веб-поиска. Видишь `references/lint-workflow.md`.

## Быстрый старт { #quick-start }

```bash
# 1. Initialize a vault (in Obsidian's vault directory)
python scripts/init_vault.py --path ~/vaults/research --topic "LLM interpretability"

# 2. Drop a source into raw/, then ingest
/wiki-ingest ~/vaults/research/raw/anthropic-monosemanticity.pdf

# 3. Ask questions (answers can be re-filed into the wiki)
/wiki-query "how does monosemanticity compare to mechanistic interpretability?"

# 4. Periodic health check
/wiki-lint

# 5. See the timeline
/wiki-log --last 10
```

## Слэш-команды (поставляется этот плагин) { #slash-commands-this-plugin-ships }

| Команда | Цель |
|---|---|
| `/wiki-init` | Загрузите новое хранилище с файлами схемы + стартовая структура |
| `/wiki-ingest <path>` | Читайте источник, обсуждайте, обновляйте wiki, регистрируйте его |
| `/wiki-query <question>` | Поиск в вики, обобщение ответа, предложение отправить обратно |
| `/wiki-lint` | Проведите проверку работоспособности — противоречия, сироты, устаревшие заявления, пробелы |
| `/wiki-log` | Показывать последние записи журнала (использует инструменты unix на `log.md`) |

## Саб-агенты (этот плагин поставляется отдельно) { #sub-agents-this-plugin-ships }

| Агент | При отправке |
|---|---|
| `wiki-ingestor` | Делегированный поток приема — считывает исходный код, предлагает обновления, применяется после вашего одобрения |
| `wiki-linter` | Независимо запускает воркфлоу проверки работоспособности, сообщает о результатах |
| `wiki-librarian` | Отвечает на запросы с использованием поиска по индексу, синтезирует с цитатами |

## Инструменты Python (`scripts/`) { #python-tools-scripts }

Все инструменты являются ** только стандартной библиотекой ** (pip не устанавливается). Бегать с `python scripts/<tool>.py --help`.

| Сценарий | Цель |
|---|---|
| `init_vault.py` | Создать структуру папок + начальное значение CLAUDE.md , AGENTS.md , index.md , log.md |
| `ingest_source.py` | Помощник: извлеките текст/ frontmatter из исходного файла, готового к ревью LLM |
| `update_index.py` | Регенерировать `index.md` с вики-страницы frontmatter (категория, дата, количество источников) |
| `append_log.py` | Добавьте стандартизированную запись в журнале `## [YYYY-MM-DD] <op> \| <title>` |
| `wiki_search.py` | BM25 поиск по вики-страницам (автономный резервный вариант, когда index.md этого недостаточно) |
| `lint_wiki.py` | Найдите сирот (нет входящих ссылок), устаревшие страницы, отсутствующие перекрестные ссылки, неработающие ссылки |
| `graph_analyzer.py` | Вычислить статистику графа связей — концентраторы, сироты, кластеры, отключенные компоненты |
| `export_marp.py` | Визуализируйте вики-страницу (или поддерево) в виде слайд-колоды Marp |

## Совместимость с различными инструментами { #cross-tool-compatibility }

** Схема хранилища** находится в CLAUDE.md (Код Клода) или AGENTS.md (Кодекс/Курсор/Антигравитация/Открытый код). Один и тот же контент работает в обоих случаях. Этот плагин поставляется с обоими шаблонами. Инструкции по настройке каждого инструмента приведены в разделе `references/cross-tool-setup.md`.

```
CLAUDE.md       → Claude Code
AGENTS.md       → Codex CLI, Cursor, Antigravity, OpenCode, Gemini CLI
.cursorrules    → legacy Cursor (pre-AGENTS.md)
```

Скрипты представляют собой чистый Python stdlib → выполняются везде одинаково. Для каждого инструмента изменяется только файл загрузчика.

## Установка Obsidian (рекомендуется) { #obsidian-setup-recommended }

- **Obsidian Web Clipper** — расширение для браузера; преобразует веб-статьи в Markdown и помещает их в `raw/`
- ** Загружайте изображения локально ** — Настройки → Файлы и ссылки → Путь к папке вложений = `raw/assets/`. Настройки → Горячие клавиши → привязать "Загрузить вложения для текущего файла" к `Ctrl+Shift+D`
- ** Просмотр графика ** — просмотр узлов/сирот; необходим для выявления структурных проблем
- ** Плагин Marp** — Колоды слайдов на основе Markdown непосредственно со страниц wiki
- ** Плагин для просмотра данных** — динамические таблицы/ списки поверх заголовка страницы (теги, даты, количество источников)
- **Git** — хранилище представляет собой простое репозиторий Markdown; обновите его

Полное пошаговое руководство по настройке: `references/obsidian-setup.md`

## Почему это работает (по сравнению с обычной ТРЯПКОЙ) { #why-this-works-vs-plain-rag }

| Обычная ТРЯПКА | Вики LLM |
|---|---|
| Заново открывайте знания по каждому запросу | Знания накапливаются |
| Перекрестные ссылки пересчитываются каждый раз заново | Перекрестные ссылки, предварительно написанные и поддерживаемые |
| Противоречия проявляются только в том случае, если вы спрашиваете | Противоречия, выявленные во время приема |
| Исследование исчезает в истории чата | Хорошие ответы повторно представлены в виде новых страниц |
| Масштабируется за счет встраиваемой инфраструктуры | Масштабируется с помощью Markdown + `index.md` + необязательный локальный поиск |

В ~100 источниках / сотнях страниц, `index.md` + поиска по файловой системе достаточно. После этого используйте локальный инструмент поиска, такой как [qmd](https://github.com/tobi/qmd) или использовать `scripts/wiki_search.py`.

## Железное правило { #iron-rule }

**LLM никогда не редактирует файлы в `raw/`.** Никогда. Источники неизменяемы. Все записи LLM отправляются на `wiki/`. Если вам нужно исправить источник, сделайте это в `raw/` самостоятельно — затем повторно проглотите.
