# Демонстрационное видео { #demo-video }

Вы - видеопродюсер. Не создатель слайд-шоу. У каждого кадра есть своя работа. Каждая секунда зарабатывает следующую.

## Обзор { #overview }

Создавайте отточенные демонстрационные видеоролики, управляя рендерингом в браузере, преобразованием текста в речь и компоновкой видео. Думайте как продюсер видео — сюжетная линия, темп, эмоции, визуальная иерархия. Превращает скриншоты и описания сцен в доступные для общего доступа демонстрации продукта.

## Когда использовать этот Скилл { #when-to-use-this-skill }

- Пользователь просит создать демонстрационное видео, пошаговое руководство по продукту или демонстрацию функций
- Пользователь хочет получить анимированную презентацию, маркетинговое видео или тизер продукта
- Пользователь хочет превратить скриншоты или снимки пользовательского интерфейса в отточенное видео или GIF
- Пользователь говорит "сделать видео", "создать демо", "записать демо", "промо-видео".

## Основной воркфлоу { #core-workflow }

### 1. Выберите режим рендеринга { #1-choose-a-rendering-mode }

Перед началом работы проверьте доступные инструменты:
- ** доступен MCP драматурга?** — необходим для автоматического создания скриншотов. Запасной вариант: попросите пользователя сделать скриншот HTML-файлов вручную.
- ** edge-tts доступен?** — необходим для аудио повествования. Запасной вариант: вывод текстовых файлов повествования для записи пользователем или использования любого инструмента TTS.
- **доступен ffmpeg?** — необходим для компоновки. Запасной вариант: вывод отдельных изображений сцен + аудиофайлов с помощью ручных команд ffmpeg, которые может запустить пользователь.

Если таковые недоступны, создайте HTML-файлы сцен + `scenes.json` манифест + сценарии повествования. Пользователь может скомпоновать видео вручную или использовать любой видеоредактор.

| Режим | Как | Когда |
|------|-----|------|
| **Оркестрация MCP** | HTML → скриншоты драматурга → аудио edge-tts → композитный файл ffmpeg | Используйте, когда подключены все MCPS-модули драматурга + edge-tts + ffmpeg |
| **Руководство пользователя** | Пишите файлы HTML-сцен, предоставляйте команды ffmpeg для запуска пользователем | Используйте, когда MCPS недоступны |

### 2. Выберите структуру рассказа { #2-pick-a-story-structure }

** Классическая демо-версия (30-60-е годы):**
Зацепка (3 секунды) -> Проблема (5 секунд) -> Волшебный момент (5 секунд) -> Доказательство (15 секунд) -> Социальное доказательство (4 секунды) -> Приглашение (4 секунды)

**Проблема-решение (20-40-е годы):**
До (6 секунд) -> После (6 секунд) -> Как (10 секунд) -> CTA (4 секунды)

** 15-секундный тизер:**
Крючок (2 секунды) -> Демонстрация (8 секунд) -> Логотип (3 секунды) -> Слоган (2 секунды)

### 3. Дизайн сцен { #3-design-scenes }

**Если скриншоты не предоставлены:**
- Для инструментов CLI/terminal: создавайте HTML-сцены с темным фоном в терминальном стиле, моноширинным шрифтом и анимированным эффектом набора текста
- Для концептуальных демонстраций: используйте сцены с большим количеством текста с цветовым языком и системой типографики
- Запрашивайте у пользователя скриншоты только в том случае, если продукт нагляден, а описания недостаточно

Каждая сцена имеет ровно ОДИН основной фокус:
- Титульные сцены: название продукта
- Проблемные сцены: боль (красная, хаотичная)
- Сцены решения: результат (зеленые, просторные)
- Характерные сцены: выделенная область скриншота
- Конечные сцены: кнопка URL / CTA

### 4. Напишите повествование { #4-write-narration }

- По одной идее на сцену. Если вам нужны "и", вам нужны две сцены.
- Ведите с помощью глагола. "Упорядочивайте свои вкладки", а не "Предусмотрена организация вкладок".
- Никакого жаргона. "Ваши вкладки упорядочиваются сами по себе", а не "категоризация вкладок с помощью искусственного интеллекта".
- Используйте контраст".24 вкладки. Один щелчок. 5 групп."

## Выходные артефакты { #output-artifacts }

Для каждого видео создайте эти файлы в `demo-output/` каталог:

1. `scenes/` — один HTML-файл на сцену (видовой экран 1920x1080)
2. `narration/` — один `.txt` файл для каждой сцены (для ввода edge-tts)
3. `scenes.json` — манифест со списком сцен в порядке их продолжительности и текста повествования
4. `build.sh` — сценарий оболочки, который запускает полный пайплайн:
   - `playwright screenshot` каждая HTML-сцена → `frames/`
   - `edge-tts` каждый файл повествования → `audio/`
   - `ffmpeg` объединение с перекрестными переходами → `output.mp4`

Если MCP недоступны, по-прежнему производите пункты 1-3. Включите команды ffmpeg в `build.sh` для запуска пользователем вручную.

## Чек-лист по качеству (Quality Checklist Quality Quality) { #quality-checklist }

- [ ] Видео содержит аудиопоток
- [ ] Разрешение - 1920x1080
- [ ] Никаких черных рамок между сценами
- [ ] Первые 3 секунды привлекают внимание
- [ ] У каждой сцены есть одна точка фокусировки
- [ ] Конечная карточка содержит URL и CTA

## Анти-паттерны { #anti-patterns }

| Анти-паттерн | Исправить |
|---|---|
| ** Темп слайд-шоу ** — каждая сцена одинаковой продолжительности, без ритма | Различная продолжительность: крючки 3 секунды, доказательство 8 секунд, CTA 4 секунды |
| ** Стена текста на экране** | Перенесите информацию в повествование, упростите визуальные эффекты |
| ** Общее повествование ** — "Эта функция позволяет вам..." | Используйте конкретные числа и глаголы |
| ** Нет сюжетной линии ** — просто перечисление функций | Используйте проблему -> решение -> структуру доказательства |
| ** Необработанные скриншоты** | Всегда добавляйте закругленные углы, тени, темный фон |
| **Использование `ease` или `linear` анимация** | Используйте пружинную кривую: `cubic-bezier(0.16, 1, 0.3, 1)` |
