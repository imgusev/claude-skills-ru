# /cs: исследования-финансирование — Бюджет программы + выгода/взлетно-посадочная полоса + распределение капитальных и эксплуатационных расходов { #csresearch-finance--program-budget--burnrunway--capex-vs-opex-routing }

Запустите `research-finance` скилл на основе этого ввода:

**$АРГУМЕНТЫ**

## Воркфлоу с тремя инструментами { #three-tool-workflow }

1. **`program_budget_planner.py`** — Составьте бюджет на несколько периодов на основе строк пакета работ, примените ставку F & A к подходящей базе в стиле MTDC (исключая капитальное оборудование + дополнительные части свыше 25 тыс. долл.), суммируйте прямые / F & A / полностью загруженные затраты за период с блоком явных допущений. Отраслевая настройка с помощью `--profile`.

2. **`burn_runway_tracker.py`** — Вычислите среднее значение + итоговый расход, взлетно-посадочную полосу в периодах / месяцах и то, достижима ли каждая веха изменения стоимости до того, как закончатся денежные средства. Флаги ускоряющегося горения и взлетно-посадочной полосы ниже порогового значения.

3. **`capex_vs_opex_router.py`** — Оцените каждую статью затрат в соответствии с критериями этапа разработки по МСФО (IAS) 38 (или отметьте ASC 730 "Расходы по мере их возникновения" в соответствии с ОПБУ США). Путь к КАПИТАЛИЗАЦИИ-КАНДИДАТ / РАСХОДЫ / ФИНАНСЫ-ВЛАДЕЛЕЦ - РЕВЬЮ с указанным владельцем. Никогда не записывается на прием.

## Выход { #output }

- Сводный бюджет (прямой / F&A / полностью загруженный) с предположениями
- Взлетно-посадочная полоса + вердикты вех + флаги
- Маршрутизация капитальных/эксплуатационных затрат по каждому элементу с указанием имени владельца
- Топ-3 следующих действия

## Жесткое правило { #hard-rule }

** Каждое число содержит свои допущения; учет-обработка вызывает маршрут к названному финансовому владельцу. ** Этот скилл никогда не регистрирует запись и не определяет обработку.

## Первый запуск + оптимизация { #first-run--optimization }

- **Первым поднялся на борт онбординга:** `python3 skills/research-finance/scripts/onboard.py` (Область исследований и разработок, ставка F & A, порог взлетно—посадочной полосы, стандарт бухгалтерского учета, финансовый владелец) - сохраненная конфигурация предварительно настраивает каждый инструмент. `--show` перечисляет вопросы.
- ** Оптимизация (регистрация):** только если пользователь попросит оптимизировать /расширить взлетно-посадочную полосу, переключитесь на автоматический поиск через `skills/research-finance/scripts/ar_evaluator.py` (`runway_months`, чем выше, тем лучше).

## Отличный от { #distinct-from }

- `finance/financial-analysis` — это корпоративный DCF / закрытие / оценка. Это уровень научно-исследовательской программы.
- `research/grants` — это ** находит финансирование**. Это ** управляет уже выигранными деньгами**.
