# клинические исследования { #clinical-research }

Дизайн проспективного клинического исследования: конечные точки, размер выборки/ мощность и осуществимость фазового гейта. Каждый результат представляет собой ** оценку с заявленными допущениями**, направляемую ** названному владельцу-человеку**. Этот скилл никогда не выдает клинические рекомендации за факт и никогда не заменяет биостатистика или вопросы регулирования.

## Цель { #purpose }

Клинические группы по исследованиям и разработкам, медицинские мониторы и функции биостатистики находятся в данный момент между *у нас-есть-гипотеза* и *у нас-есть-готовый-к-представлению протокол*. Этот скилл формирует три самых сложных дизайнерских решения:

Три детерминированных инструмента:

1. `sample_size_estimator.py` — Мощность закрытой формы / размер выборки для двухплечих ** средних** (d Коэна), ** пропорций** (нормальное приближение) и ** выживаемости** (события Шенфельда). Надувается для отсева. Печатает баннер "ОЦЕНКА — подтвердите с помощью биостатистика".
2. `endpoint_selector.py` — Оценивает конечные точки-кандидаты по 5 взвешенным параметрам (клиническая значимость, измеримость, приемлемость для регулирующих органов, чувствительность к изменениям, нагрузка) и классифицирует каждую из них как ** ПЕРВИЧНУЮ / КЛЮЧЕВУЮ-ВТОРИЧНУЮ / ИССЛЕДОВАТЕЛЬСКУЮ **. Наказывает за неподтвержденные суррогатные конечные точки.
3. `phase_gate_scorer.py` — Оценивает учебный план от 0 до 100 баллов по выполнимости подбора персонала, готовности конечных точек, статистической мощности, сложности эксплуатации и соответствию бюджету; возвращает ** "СОГЛАСЕН" / "СОГЛАСЕН С УСЛОВИЯМИ" / "РЕДИЗАЙН" / "НЕТ" ** плюс названные владельцы, которые должны подписать.

## Когда использовать { #when-to-use }

Используйте этот скилл, когда:

- Вы выбираете основную конечную точку, и вам необходимо защитить ее от проверки суррогатной конечной точкой.
- Вам нужна обоснованная оценка размера первой выборки для краткого описания протокола.
- Учебный план нуждается в технико-экономическом обосновании перед ревью на этапе гейта.
- Вы испытываете давление, проверяя, достижимо ли запланированное зачисление с учетом соответствующего контингента и объектов.

**Не используйте этот скилл для**: подготовки нормативной документации или отчета о клинической оценке (используйте `ra-qm-team`), найдите или разместите грант (используйте `research/grants`), разработайте эксперимент A/B с живым продуктом (используйте `product-team/experiment-designer`), или заменить окончательное обоснование размера выборки биостатистиком.

## Воркфлоу { #workflow }

1. **Набросайте краткий обзор** — Заполните `assets/protocol_synopsis_template.md` (цели, дизайн, совокупность, конечные точки, заполнитель статистического плана, владельцы, которые должны подписать).
2. **Выберите конечную точку** — Запустите `endpoint_selector.py --input endpoints.json --profile {drug|device|biologic|diagnostic|digital-therapeutic}`. Прочитайте классификацию + суррогатные флаги. Если >1 первичный, запланируйте управление множественностью.
3. **Оцените размер выборки** — Запустите `sample_size_estimator.py --design {means|proportions|survival} ...`. Проследите за эффектом/difference/ЧАС на опубликованный или основанный на привязке источник; завышать для отсева.
4. **Оцените осуществимость** — Запустите `phase_gate_scorer.py --input study.json --profile <same> --phase {1|2|3|4}`. Прочитайте вердикт + блокировщики + названные владельцы.
5. **Маршрут для выхода из системы** — Соберите краткий обзор + оценки в пакет гейт. Пакет представляет собой ** рекомендацию**; знак биостатистика, медицинского монитора и владельца, отвечающего нормативным требованиям.

## Сценарии { #scripts }

| Сценарий | Цель | Профили |
|---|---|---|
| `scripts/sample_size_estimator.py` | Мощность / размер выборки для определения средств, пропорций, выживаемости | n/a (ориентированный на дизайн) |
| `scripts/endpoint_selector.py` | оценка конечной точки по 5 измерениям + классификация + суррогатный флаг | лекарственное средство, устройство, биологическое, диагностическое, цифрово-терапевтическое |
| `scripts/phase_gate_scorer.py` | Осуществимость 0-100 + РАЗРЕШЕНА/ВЫПОЛНЯЕТСЯ С УЧЕТОМ УСЛОВИЙ/РЕДИЗАЙН/НЕ РАЗРЕШЕН + владельцы | лекарственное средство, устройство, биологическое, диагностическое, цифрово-терапевтическое |

Все три: только для stdlib, `--help`, `--sample`, `--output {human,json}`.

## Онбординг и кастомизация { #onboarding--customization }

Запустите анкету для онбординга ** один раз перед началом работы ** — в ней указаны ваши настройки по умолчанию и имена владельцев, так что каждый инструмент в этом скилле предварительно настроен. Суть в настройке: ответы на самом деле меняют поведение инструмента.

```bash
python3 scripts/onboard.py            # interactive (also: --defaults, --set key=value, --reset)
python3 scripts/onboard.py --show     # see the questions + current effective config
```

Ответы сохраняются в `~/.config/research-ops/clinical-research.json` (глобальный) или `./.research-ops/clinical-research.json` (`--scope project`) и считываются автоматически `config_loader.py`. Они устанавливают область разработки по умолчанию ** профиль**, по умолчанию ** альфа / мощность / отсев** и имя **биостатист / медицинский монитор / владелец регулирующего органа**, напечатанное на выходных данных. Флаги CLI всегда переопределяют сохраненную конфигурацию; `RESEARCH_OPS_NO_CONFIG=1` полностью игнорирует это.

** Семь вопросов: ** область разработки · альфа · мощность · отсев · биостатист · медицинский монитор · владелец регулирующего органа.

## Оптимизация с помощью автоматического поиска (опция) { #optimize-with-autoresearch-opt-in }

Этот скилл предоставляет ** изолированный, согласованный** мост для `engineering/autoresearch-agent`. Только когда вы просите "оптимизировать" / "запустить цикл", эксперимент с автоматическим поиском итеративно улучшает учебный план по сравнению с собственным показателем осуществимости этого скилла. `scripts/ar_evaluator.py` является основным средством оценки истинности; он печатает `feasibility_composite: <0-100>` (чем выше, тем лучше).

```bash
/ar:setup --domain custom --name trial-feasibility \
  --target study.json \
  --eval "python3 ar_evaluator.py --target study.json" \
  --metric feasibility_composite --direction higher
/ar:loop custom/trial-feasibility
```

Изолированный: нет жесткой зависимости — автоматический поиск выполняется только по запросу, а цикл редактируется `study.json`, никогда не является оценщиком (истина о закрытом грунте).

## Допущения { #assumptions }

- Формулы для определения размера выборки используют обычные приближения со встроенной z-таблицей. Это предварительные оценки; биостатист производит окончательное обоснование (и может использовать моделирование, адаптивные конструкции или точные методы).
- Система оценки конечных точек применяет * обычные* нормативные требования для каждой области разработки с помощью `--profile`. Прецедент, относящийся к конкретной компании или указанию, переопределяет предыдущий.
- Система оценки фазовых гейтов использует профильный показатель затрат на одного пациента; укажите реальный бюджет, чтобы переопределить значение по умолчанию.
- Неподтвержденный суррогат не может привязать ПЕРВИЧНУЮ конечную точку — бомбардир применяет это с помощью штрафа.

## Анти-паттерны { #anti-patterns }

- **Представление оценки мощности как факта.** Каждый результат представляет собой оценку с указанием имени владельца, который должен подписать ее.
- ** Включение для удобства размера эффекта.** Эффект должен быть привязан к опубликованному или основанному на привязке MCID, а не к n, который вы можете себе позволить.
- **Привязка первичного источника к непроверенному суррогатному источнику.** Суррогатным конечным точкам требуются доказательства валидации для указания.
- **Игнорирование множественности.** Для более чем одной первичной конечной точки требуется заранее указанное альфа-распределение.
- ** Пропуск инфляции отсева.** Необработанный n занижает результаты исследования; завышать на 1/ (1 − отсев).


## Библиотека принудительных вопросов (дисциплина Matt Pocock grill) { #forcing-question-library-matt-pocock-grill-discipline }

Проходили по одному мимо `/cs:grill-research-ops` или оркестратор. Рекомендуемый ответ + цитата из канона на каждый вопрос. Никогда не упаковывался.

1. ** "Является ли ваша основная конечная точка клиническим исходом или суррогатной — и если суррогатной, есть ли она в таблице, утвержденной FDA?"**
   Рекомендуется: клинический исход, если суррогатная мать не подтверждена по этому показанию.
   Канон: Таблица суррогатных конечных точек FDA; Глоссарий BEST (Биомаркеры, конечные точки и другие инструменты).

2. ** "На какое минимальное клинически значимое отличие вы рассчитываете — и откуда взялась эта цифра?"**
   Рекомендуется: опубликованный или основанный на привязке MCID, цитируемый; никогда не указывайте размер эффекта удобства.
   Канон: ICH E9; Коэн *Статистический анализ мощности*.

3. ** "Какой процент отсева вы предполагаете, и не завышен ли для этого размер выборки?"**
   Рекомендуется: увеличьте n на 1/ (1 − отсев), используя обоснованную норму.
   Канон: Чоу, Шао и Ван; ИХ E9(R1).

4. ** "Одна основная конечная точка или несколько — и если несколько, то каков контроль множественности?"**
   Рекомендуется: предварительно укажите альфа-распределение (иерархическое / Бонферрони).
   Канон: Руководство FDA по множественным конечным точкам (2022).

5. ** "Кто является названным специалистом по биостатистике /медицинским наблюдателем /владельцем регулирующих органов, подписывающим этот краткий обзор?"**
   Рекомендуется: назовите их сейчас — этот вывод является рекомендацией, а не протоколом.
   Канон: роли и обязанности ICH E6(R2) GCP.

Сначала пройдите вглубь. Зафиксируйте 1-2 перед открытием 3-5. После того, как на все будут даны ответы, вызовите `endpoint_selector.py` → `sample_size_estimator.py` → `phase_gate_scorer.py`.
