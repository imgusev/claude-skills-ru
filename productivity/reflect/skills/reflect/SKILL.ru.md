# Размышление — Переоценка в середине разговора { #reflect--mid-conversation-reassessment }

> ** Переносимость: ** Скилл чистого рассуждения. Никаких внешних инструментов не требуется. Работает в Claude Code CLI + Claude.сеть с искусственным интеллектом изначально. Самый портативный в коллекции v2.

При вызове в середине разговора этот скилл ** приостанавливает выполнение ** и производит откровенную переоценку того, к чему вел разговор. Результатом является ** плавный анализ (без заголовков, разговорный тон) **, охватывающий макроперспективу, анализ пробелов, рефлексивный запрос, проверку предвзятости и контекстуальное согласование. Скилл заканчивается четкой рекомендацией: ** продолжайте, развернитесь или сделайте паузу, чтобы ответить на конкретный вопрос **.

## Триггеры вызова { #invocation-triggers }

**Эксплицитные фразы:**

- "размышлять"
- "сделай шаг назад" / "step back"
- "уменьшить масштаб"
- "мы что-то упускаем"
- "картина в целом"
- "чего нам не хватает"
- "давайте сделаем паузу"
- "проверьте это на вменяемость"
- "мы на верном пути"
- "не слишком ли мы много думаем об этом"
- "лес для деревьев"

**Неявные сигналы (фраза не требуется):**

- Обсуждение деталей внедрения продвинулось более чем на 10 витков без стратегической проверки
- Пользователь проявляет признаки разочарования или зацикленности
- Повторяющиеся тупики или повороты в течение короткого промежутка времени

Когда вы обнаружите неявный триггер, ** не вызывайте его автоматически** - спросите пользователя, хочет ли он отступить. Неявные сигналы - это промпт к размышлению, а не к тому, чтобы проводить его в одностороннем порядке.

## Директива об остановке (перед повторной оценкой) { #stop-directive-before-reassessing }

**Остановите текущий поток.** Не продолжайте выполнение текущей задачи. Размышление - это пауза, а не побочный поиск.

Это важно, потому что:
- Продолжая работать над деталями, "размышляя со стороны", вы не достигнете цели — вы придадите слишком большое значение текущему направлению
- Пользователь ожидает явного перерыва в ритме
- Повторная оценка требует полного внимания к истории разговоров

## Дополнительный осветлитель Grill-Me { #grill-me-optional-clarifier }

Этот скилл намеренно ** малозатратен** - большинство вызовов должны выполнять 5—мерный анализ немедленно, без вопросов. Дисциплина grill-me применяется *только* в том случае, если вызов неоднозначен (например, пользователь вставляет "шаг назад" в начале нового разговора без предварительного контекста для повторной оценки).

### Вопрос 1 (необязательно, задается только тогда, когда контекст слишком разрежен для повторной оценки) { #q1-optional-asked-only-when-context-is-too-thin-to-reassess }

> **Что конкретно я должен пересмотреть? Выбери что-нибудь одно:**
>
> 1. Цель — правильно ли мы решаем проблему?
> 2. Подход — является ли тот путь, по которому мы идем, лучшим?
> 3. Предположения — что мы принимаем как должное?
> 4. Все вышеперечисленное (по умолчанию, если у вас есть время)
>
> *Почему я спрашиваю:* Я вижу ограниченный предыдущий контекст для переоценки, поэтому я хочу сосредоточить внимание на размышлениях, а не на догадках. Если ты предпочитаешь, чтобы я сделал все три, это прекрасно — так и скажи.

Принудительный выбор по умолчанию. ** Задается только тогда, когда контекст действительно скуден; в противном случае пропустите и запустите полный анализ существующего разговора.**

** Условие остановки:** Максимум один вопрос. Если пользователь вызывает в середине разговора в обычном контексте, никаких вопросов не задается - скилл запускается напрямую.

## Фреймворк для анализа в 5 измерениях { #the-5-dimension-analysis-framework }

Перечитайте ** полный текст беседы, начиная с первоначальной цели **, а не только последние повороты. Дисциплина, которая отличает реальное отражение от краткого изложения местного контекста.

### 1. Макроперспектива { #1-macro-perspective }

- ** Первоначальная цель: ** Что пользователь на самом деле начал пытаться сделать?
- ** Обнаружение дрейфа: ** Отклонился ли разговор от поставленной цели? К чему-то лучшему или худшему?
- ** Проверка подключения:** Как текущая работа связана с более масштабной целью?

Ведущий с конкретными доказательствами: "На 3-м ходу целью было X; к 12-му ходу мы работаем над Y. Является ли Y продуктивным сужением X или отдалением?"

### 2. Анализ пробелов { #2-gap-analysis }

- ** Непроверенные предположения** — что мы считаем само собой разумеющимся из того, что мы не проверяли?
- **Отсутствующие стейкхолдеры / аудитории/пользователи** — кому это нужно вне непосредственного контекста?
- **Пропущенные ограничения** — технические, нормативные, ресурсные ограничения не учтены
- **Отклоненные альтернативы** — пути, рассмотренные, но отвергнутые; кратко вернитесь к ним
- **Внешние факторы** — сроки, рынок, зависимости, не входящие в сферу охвата

### 3. Рефлексивное исследование { #3-reflective-inquiry }

- Правильно ли сформулирована проблема?
- Решение правильной проблемы по сравнению с соседний, более простой вариант?
- Более простой путь становится чрезмерно сложным?
- Более трудный, но более ценный путь, которого избегают?
- ** Взгляд свежим взглядом: ** подошел бы кто-нибудь другой к этому по-другому?

### 4. Проверка смещения { #4-bias-check }

Пять предубеждений — распознать каждое из них можно с помощью определенных моделей общения:

| Предвзятость | Сигнал распознавания |
|---|---|
| **Предвзятость подтверждения** | Приведенные доказательства подтверждают только рабочую гипотезу; встречные доказательства отсутствуют или отклоняются |
| **Ошибка с заниженными затратами** | "Мы уже инвестировали X" / "мы продвинулись достаточно далеко, чтобы..." вместо новых затрат/выгод |
| **Закрепление** | Остановился на первом упомянутом варианте; новые варианты сравнивались с ним, а не оценивались независимо |
| **Смещение в сторону сложности** | Добавление функций / шагов / гарантий без конкретного обоснования для каждого |
| **Смещение в сторону новизны** | Перевешивание последних нескольких ходов; игнорируется более старый, но важный контекст |

Для каждого обнаруженного смещения: назовите его, приведите конкретные доказательства, предложите корректирующие действия.

Видишь [`references/cognitive_bias_canon.md`](references/cognitive_bias_canon.md) для полного канона.

### 5. Контекстуальное согласование { #5-contextual-alignment }

- Соответствует ли направление фактическим целям пользователя (как известно из контекста)?
- Игнорируются ли внешние факторы?
- Является ли это наилучшим использованием времени и энергии пользователя прямо сейчас?
- Связь с другими известными проектами или приоритетами?

## Правила тона и формата { #tone-and-format-rules }

Скилл должен создавать:

- ** Плавная проза** — никаких заголовков, никаких маркированных списков, никакого структурированного форматирования отчетов
- ** Сжато, но тщательно** — ни одной строчки, ни целой стены текста
- ** Прямая критика, когда это оправдано** — с конкретными доказательствами из беседы
- ** Проверка, когда это оправдано ** — с конкретным обоснованием того, почему путь является надежным
- ** Никаких туманных заверений** — "выглядит хорошо!" без объяснения причин отвергается
- ** Никаких искусственных проблем ** — когда путь действительно надежен, скажите об этом с конкретными причинами; не выдумывайте проблемы

Видишь [`references/honest_output_discipline.md`](references/honest_output_discipline.md) для создания анти-искусственных проблем.

## Заключительная рекомендация (обязательная) { #closing-recommendation-mandatory }

Каждый прогон заканчивается одной из трех рекомендаций по направлению:

| Рекомендация | Когда | Формат |
|---|---|---|
| **Продолжайте** | Путь твердый | - Продолжай. {specific reasoning for why}." |
| **Поворот к {X}** | Произошел дрейф ИЛИ появилась лучшая траектория | "Повернись к {X}, вдали от {what to drop}. {specific evidence}." |
| **Пауза для {Q}** | Прежде чем продолжить, необходимо ответить на конкретный вопрос | "Сделайте паузу на {Q}. Без ответа на этот вопрос следующий шаг сопряжен с риском {specific cost}." |

Заключение всегда конкретное — никогда не "вам следует больше подумать об этом" или "рассмотрите свои варианты".

## Обработка ошибок { #error-handling }

| Ситуация | Поведение |
|---|---|
| Разговор очень короткий (нет реального контекста для переоценки) | Подтвердите ограничение, спросите пользователя, что он хочет пересмотреть (срабатывает Q1) |
| Текущее направление действительно прочное | Четко сформулируйте это с помощью аргументации; не создавайте проблем |
| Пользователь вызывает промежуточную задачу без четкого вопроса | По умолчанию используется макро-перспектива + проверка смещения; предлагаем копнуть глубже |
| Неявный триггер кажется возможным, но неясным | Не вызывайте проактивно; спросите пользователя, хочет ли он сделать шаг назад |

## Анти-Паттерны для отклонения { #anti-patterns-to-reject }

- Жестко закодированные имена пользователей или ссылки на конкретные домены
- Структурированный вывод отчета (заголовки, маркированные списки), когда требуется прозаический текст
- Выдуманные проблемы, когда на самом деле все в порядке
- Расплывчатое заверение ("выглядит хорошо!") вместо конкретных рассуждений
- Пересматривая только последние повороты вместо полного разговора
- Пропуск заключительной рекомендации по направлению
- Продолжая выполнение текущей задачи, "размышляя со стороны"
