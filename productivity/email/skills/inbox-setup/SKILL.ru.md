# Почтовый ящик-Настройка — Онбординг сортировки электронной почты { #inbox-setup--email-triage-onboarding }

> **В паре с `inbox-triage`.** Этот скилл записывает базу знаний из 7 файлов по адресу `${WORKSPACE}/Email/` это `inbox-triage` считывается при каждом запуске. Файловые контракты (названия, разделы, поля) ДОЛЖНЫ точно соответствовать двум скиллам. Видишь [`references/kb_file_contract.md`](references/kb_file_contract.md).

Запустите один раз (или повторно запустите, когда бизнес/priorities изменение). Опросите пользователя об их шаблонах электронной почты, бизнес-контексте, стиле ответов и приоритетах. Создайте структурированную базу знаний в `${WORKSPACE}/Email/` это захватывает все `inbox-triage` необходимо эффективно обрабатывать входящие сообщения.

## Дисциплина поведения { #conduct-discipline }

** Не создавайте все файлы сразу.** Пройдитесь по 8 разделам по одному за раз. Каждый раздел фиксирует свой файл (ы), прежде чем двигаться дальше. Частичное завершение (например, пользователь прерывает собеседование в середине) по-прежнему создает пригодный для использования частичный КБАЙТ.

Дисциплина "Гриль-ме" применяется во всем:

- ** По одному вопросу за ход. ** Никогда не связывайтесь. Даже за пределами границ участка.
- ** "Почему я спрашиваю" на каждый вопрос ** — чтобы пользователи могли правильно ответить.
- ** Принудительный формат, где это возможно.** Множественный выбор > открытый.
- **Упорядоченный по зависимостям.** Q2 зависит от Q1; нижестоящие разделы зависят от восходящего потока.

Видишь [`references/grill_me_section_walk.md`](references/grill_me_section_walk.md) подробнее о дисциплине, состоящей из 8 разделов.

|---|---|---|
| `email-taxonomy.md` | Система классификации + настройки отчета | **Да** |

## Условие остановки (Полное интервью) { #stop-condition-full-interview }

Всего ~ 25-31 вопрос по 8 разделам (в зависимости от логики пропуска). Жесткий предел: 35 вопросов, включая все дополнительные разъяснения. Раздел 4 (Фреймворк оценки) полностью пропущен, когда в разделе 1 появилась категория "Нет возможности" - электронное письмо, в результате чего общее количество вопросов и картотека оценок уменьшилось на 6. После сообщения раздела 8 "Подтверждение + хэндофф" прием закрыт — ** никогда не открывайте его повторно**. Чтобы изменить настройки позже, пользователь повторно запускает скилл (который обнаруживает существующие файлы и запрашивает для каждого файла: заменить / объединить / пропустить). Правило "задавайте вопросы по одному за раз" действует во всех разделах: не группируйте вопросы даже при переходе от S{n} к S{n+1}.

## Раздел 1: Общая картина { #section-1-the-big-picture }

Шесть вопросов для допроса, по одному за раз:

- **S1.Q1: ** "Чем вы занимаетесь? Расскажите мне о своей роли и бизнесе в 1-2 предложениях. * Почему я спрашиваю: * Контекст определяет, каких шаблонов электронной почты ожидать — почтовый ящик создателя-одиночки совсем не похож на почтовый ящик корпоративного менеджера."
- **S1.Q2: ** "Что доминирует в вашем почтовом ящике? Выберите 1-2 лучших: продажи / работа с клиентами / внутренняя команда / информационные бюллетени / поддержка клиентов / финансы / другое. * Почему я спрашиваю: * Доминирующие категории определяют таксономию."
- **S1.Q3:** "Приблизительное распределение громкости — например, "60% деловых запросов, 20% операций, 20% шума". *Почему я спрашиваю:* Разделение говорит мне, на чем сосредоточить усилия по сортировке".
- **S1.Q4: ** "Какие адреса электронной почты следует использовать для сортировки? *Почему я спрашиваю:* Если их несколько, я настрою таксономии для каждого адреса."
- **S1.Q5: ** "Частота запуска: один раз в день / 2 раза в день / 3 раза в день / только по требованию? * Почему я спрашиваю: * Запускает окно поиска по умолчанию в режиме сортировки (9-часовое перекрытие в 2 раза/day)."
- **S1.Q6: ** "Кто—нибудь помогает управлять электронной почтой — помощник, VA, команда - или соло? *Почему я спрашиваю:* Обработка персон отличается для делегированных почтовых ящиков "Входящие"."

** Действие: ** Постройте мысленную модель. Пока не записывайте файлы. Обратите внимание, относятся ли электронные письма о возможностях к категории (управляет логикой пропуска S4).

## Раздел 2: Категории электронной почты { #section-2-email-categories }

Предложите 5-7 категорий на основе раздела 1 — предварительно рекомендуйте подмножество, а не весь шаблон меню:

- Новые возможности
- Активные разговоры
- Требуемые действия
- Финансовый
- Важный/Личный
- Информационный
- Игнорировать/с низким приоритетом

Затем три форсирующих вопроса, по одному за раз:

- **S2.Q1:** "Вот моя предлагаемая таксономия: [список]. Соответствует ли это реальности вашего почтового ящика — да / в основном / нет? *Почему я спрашиваю:* Если "нет", мне нужно переделать таксономию, прежде чем какой-либо другой раздел обретет смысл."
- **S2.Q2:** "Отсутствующие категории? Перечислите их. (Пропустить, если нет.) * Почему я спрашиваю: * Пропущенные категории приводят к появлению некатегоризированных электронных писем в дальнейшем, что ухудшает качество сортировки."
- **S2.Q3: ** "Какая категория занимает больше всего времени на одно электронное письмо? *Почему я спрашиваю:* Именно на этом нужно больше всего сосредоточить усилия по подготовке черновиков ответов".

**Действие:** Сгенерировать `email-taxonomy.md` с категориями, сигналами (для каждой: фразы-триггеры / шаблоны отправителей / маркеры темы) и действиями по умолчанию для каждой категории.

## Раздел 3: Стиль ответа и голос { #section-3-reply-style--voice }

Шесть вопросов для обсуждения на гриле плюс критический запрос на образец:

- **S3.Q1:** "Регистрация: официальная / повседневная / промежуточная? * Почему я спрашиваю: * Калибрует голос по умолчанию; далее мы уточним его на основе сэмплов."
- **S3.Q2: ** "Три любимые мозоли в общении — фразы, которые вы ненавидите, открытия, которых вы избегаете. *Почему я спрашиваю:* Я отношусь к ним как к запрещенным знакам в черновиках".
- **S3.Q3: ** "Фразы или обозначения, которые вы всегда используете - перечислите столько, сколько придет на ум. *Почему я спрашиваю:* Это отпечатки вашего голоса."
- **S3.Q4: ** "Разные персоны для разных контекстов — например, помощник отвечает как вы? *Почему я спрашиваю:* Контекст персоны изменяет обработку местоимения + подписи."
- **S3.Q5: ** "Типичная длина ответа — однострочный /короткий абзац /длиннее? * Почему я спрашиваю: * Длину голосового сигнала легче всего перепутать."
- **S3.Q6: ** "Жесткие правила — никогда X / всегда Y? (например, никогда не использовать эмодзи, всегда отвечать в течение 24 часов, никогда не принимать звонки без контекста.) * Почему я спрашиваю:* Жесткие правила применяются как не подлежащие обсуждению в каждом проекте".

### S3.ОБРАЗЦЫ (важнейшие исходные данные самого высокого качества) { #s3samples-the-critical-highest-quality-input }

> ** Вставьте 3-5 реальных отправленных писем из вашего почтового ящика.**
>
> * Почему я спрашиваю: * Самоописание голоса ненадежно. Реальные сэмплы — лучший сигнал - я проанализирую их на предмет голосовых паттернов, которые дополняют все вышесказанное. Использование `scripts/voice_sample_analyzer.py` для детерминированного извлечения паттернов.

Если пользователь занимается бизнесом: также спрашивайте о медиа-наборах, оценочных листах, стандартных подачах, повторных ответах.

**Действие:** Сгенерировать `email-patterns.md` с описанием тона (с помощью do/donбез примеров), правила персоны, шаблоны, подписи, жесткие правила. Видишь [`references/voice_calibration.md`](references/voice_calibration.md) для дисциплины "извлечение образцов".

## Раздел 4: Фреймворк оценки (условный) { #section-4-evaluation-framework-conditional }

** Логика пропуска:** запускайте этот раздел только в том случае, если в разделе 1 появились электронные письма о возможностях как значимая категория входящих сообщений. В противном случае переходите сразу к разделу 5.

Шесть вопросов для допроса, по одному за раз:

- **S4.Q1: ** "Первое, что вы проверяете, когда что—то предлагаете, - дайте мне свой внутренний фильтр. *Почему я спрашиваю:* Это вершина дерева решений".
- **S4.Q2: ** "Три мгновенных нарушения условий сделки - вещи, которые заставляют вас немедленно отказаться. *Почему я спрашиваю:* Они становятся сигналами автоматического пропуска."
- **S4.Q3: ** "Три вещи, которые сразу же вызывают у вас интерес. *Почему я спрашиваю:* Это становится сигналом к принятию решения".
- **S4.Q4: ** "Стандартные цены / условия — или "без фиксированной цены", если вы каждый раз ведете переговоры. *Почему я спрашиваю:* Если у вас есть тарифная карта, я ее сгенерирую; если нет, я пропущу".
- **S4.Q5:** "Позиция на переговорах: твердая/гибкая/ зависит от контекста? * Почему я спрашиваю: * Задает черновой тон встречным предложениям."
- **S4.Q6:** "VIP—отправители или организации, которые всегда получают имена или домены из списка участников. * Почему я спрашиваю: * VIP-список обходит обычные фильтры пропуска."

**Действие:** Сгенерировать `evaluation-framework.md` (дерево решений + категории рекомендаций + список VIP-персон) И `rate-card.md` если ценообразование существует.

## Раздел 5: Блок-лист и шаблоны { #section-5-blocklist--patterns }

Три наводящих на размышления вопроса, по одному за раз:

- **S5.Q1:** "Отправителей или домены всегда следует пропускать — перечисляйте их. (Пропустить, если нет.) *Почему я спрашиваю:* Автоматический список блокировок экономит больше всего времени при каждом запуске."
- **S5.Q2: ** "Шаблоны в электронных письмах, которые вы всегда удаляете — например, ссылки "отказаться от подписки" от конкретных маркетологов, холодные обращения рекрутеров, информационные бюллетени? * Почему я спрашиваю: * Шаблоны позволяют сортировать варианты с автоматическим пропуском без обеспечения точного соответствия."
- **S5.Q3:** "Конкретные компании / рекрутеры / информационные бюллетени тратят впустую время — перечислите любые. *Почему я спрашиваю:* Они заполняют блок-лист; сортировка добавит больше по мере того, как вы будете переопределять решения."

**Действие:** Сгенерировать `blocklist.md` (после этого автоматически поддерживается сортировкой).

## Раздел 6: Текущее состояние { #section-6-current-state }

Три наводящих на размышления вопроса, по одному за раз:

- **S6.Q1:** "Активные потоки, которые вы отслеживаете — список с контекстом в одну строку каждый. (Пропустить, если нет.) *Почему я спрашиваю:* Они становятся записями трекера, так что сортировка знает существующий контекст."
- **S6.Q2: ** "Просроченные ответы — есть что-нибудь, на что вы должны были ответить, но не ответили? *Почему я спрашиваю:* Сортировка помечает их как приоритетные при каждом запуске, пока они не будут разрешены."
- **S6.Q3:** "Чувствительные ко времени элементы со сроками выполнения — список с датами. *Почему я спрашиваю:* Трекер следит за соблюдением крайних сроков и в нужное время выявляет их как просроченные."

**Действие:** Сгенерировать `tracker.md` с таблицей активных последующих действий, разделом просроченных действий, разделом разрешенных действий (пусто), журналом обновлений (пусто). Также создайте пустой `triage-log/` каталог.

## Раздел 7: Настройки отчета { #section-7-report-preferences }

Три наводящих на размышления вопроса, по одному за раз:

- **S7.Q1:** "Формат доставки — выберите один: черновик по электронной почте себе / файл в рабочей области / только резюме в чате. *Почему я спрашиваю:* Отчет об сортировке поступает сюда при каждом запуске."
- **S7.Q2:** "Уровень детализации — выберите один: 30-секундное сканирование / подробная разбивка / оба (сначала сканируйте, расширяйте по запросу). *Почему я спрашиваю:* Влияет на длину отчета."
- **S7.Q3: ** "Что—нибудь всегда показывается первым - например, просроченные платежи, VIP-сообщения? * Почему я спрашиваю: * Пользовательские правила "верхней части отчета" раскрывают то, что вас волнует, над стандартными разделами."

**Действие:** Сохраните эти настройки в `email-taxonomy.md` в разделе "Настройки отчета".

## Раздел 8: Подтверждение и Хэндофф { #section-8-confirmation--handoff }

Перечислите каждый созданный файл с кратким изложением в одном предложении. Затем:

> Ваша система сортировки готова. Запустите скилл **Сортировка входящих сообщений**, чтобы обработать свой почтовый ящик. Первые запуски требуют контроля — система учится на ваших правках и переопределениях.

Напоминаю: повторно запускайте эту настройку в любое время./pricing/priorities измениться.

Бежать `scripts/kb_validator.py --workspace ${WORKSPACE}` чтобы подтвердить, что контракт на 7 файлов выполнен до окончательной хэндофф.

## Граница конфиденциальности { #privacy-boundary }

**Никогда не сохраняйте пароли, полные номера учетных записей, SSN или другие конфиденциальные учетные данные в файлах базы знаний. ** Если пользователь добровольно предоставит такую информацию во время собеседования, подтвердите это, но не сохраняйте; соответствующий файл KB будет удален. `[stored separately by user]` на своем месте.

## Поведение при повторном запуске { #re-run-behavior }

Повторный запуск в существующей установке:

1. Обнаруживать `${WORKSPACE}/Email/`
2. Для каждого существующего файла задайте для каждого файла: **заменить / объединить / пропустить**
3. Пройдите только по тем разделам, файлы которых пользователь выбрал для обновления
4. Пропустить разделы, файлы которых сохранил пользователь

## Обработка ошибок { #error-handling }

| Ситуация | Поведение |
|---|---|
| Рабочее пространство недоступно | Остановись. Сообщите пользователю, куда будут отправляться файлы, и запросите разрешение/path |
| Пользователь отказывается делиться образцами | Используйте самоописание; отметьте в файле шаблонов, что для калибровки может потребоваться повторение |
| Пользователь говорит "пропустите это" в середине интервью | Соблюдайте это; отметьте пробел в файле как `[needs follow-up]` |
| Конфиденциальная информация была предоставлена добровольно | Подтвердите, но не сохраняйте; отметьте в файле как `[stored separately by user]` |
| Повторный запуск с существующей установкой | Обнаруживать существующие файлы; запрашивать у пользователя информацию о каждом файле: заменить, объединить, пропустить |
| У пользователя нет ценообразования / возможностей | Полностью пропустите раздел 4; не создавайте пустые файлы |

## Портативность { #portability }

- **Claude Code CLI:** Native — записывает файлы Markdown непосредственно в файловую систему.
- ** Клод.ai web:** Работает с файлами проекта / артефактами. Задокументируйте альтернативный путь: создайте файлы в виде артефактов, попросите пользователя сохранить их в своей рабочей области или используйте подключенную файловую систему, если она доступна.

## Анти-Паттерны для отклонения { #anti-patterns-to-reject }

- Генерирование всех файлов сразу вместо перехода по разделам
- Задавая все вопросы в одном пакете
- Жестко запрограммированные ссылки на провайдера (только для Gmail)
- Сохранение конфиденциальных учетных данных в базе знаний
- Пропуская объяснение "почему этот вопрос имеет значение"
- Пропуск примера - электронные письма запрашивают голосовой ввод (это самый качественный ввод)
- Перезапись существующих файлов без согласия на повторный запуск
- Принудительное создание `rate-card.md` или `evaluation-framework.md` когда они неприменимы
