# Хэндофф { #handoff }

Напишите хэндофф-документ с кратким изложением текущего разговора, чтобы новый агент мог продолжить работу. Сохраните во временном каталоге операционной системы пользователя, а не в текущей рабочей области.

Включите в документ раздел "предлагаемые скиллы", в котором предлагаются скиллы, которые должен использовать агент.

Не дублируйте содержимое, уже захваченное в других артефактах (PRD, планы, ADR, проблемы, фиксации, различия). Вместо этого ссылайтесь на них по пути или URL-адресу.

Отредактируйте любую конфиденциальную информацию, такую как ключи API, пароли или информацию, позволяющую установить личность.

Если пользователь передал аргументы, рассматривайте их как описание того, на чем будет сосредоточен следующий сеанс, и соответствующим образом адаптируйте документ.

## Триггеры вызова { #invocation-triggers }

**Эксплицитные фразы** (любая из):
- "передай это"
- "хэндофф док"
- "подведите итог этому для новой сессии"
- "сократите этот разговор"
- "Я заканчиваю этот сеанс"
- "заберу это позже"
- "отложим это на завтра"
- "сохраните это для следующего сеанса"

**Неявные сигналы** (фразы нет, но намерение безошибочно угадывается):
- Пользователь объявляет, что он переключает компьютеры или останавливается на выполнение дневной задачи в середине дня
- Контекст беседы становится все длиннее без естественной точки остановки
- Пользователь говорит: "Позвольте мне вернуться к этому" или "Я продолжу это позже".

Когда вы обнаружите неявный триггер, предложите хэндофф перед его запуском: * "Хотите, чтобы я написал хэндофф для следующего сеанса?"* — никогда не запускайте его автоматически.

## Настройка при первом запуске { #first-run-setup }

При первом вызове скилл запрашивает, где сохранить хэндоффы, чтобы папка проекта никогда не загромождалась. Настройка предлагается один раз с помощью *"Запустите установку сейчас? (Y/n)"* — при ответе N используются значения OS-temp по умолчанию для этого запуска и никогда не выдается повторных промптов. Пользователь может повторно запустить настройку в любое время с помощью `/cs:handoff-setup`.

Видишь [ссылки/configuration.md](references/configuration.md) для получения полной ссылки на поле конфигурации.

## Выходной путь { #output-path }

Место сохранения считывается из конфигурации пользователя (`~/.config/handoff/config.json`, или проект- локальный `.handoff/config.json` если присутствует). Если конфигурация не существует и пользователь отказался от настройки, вернитесь к:

```bash
mktemp -t handoff-XXXXXX.md
```

Прочитайте файл, прежде чем записывать в него данные.

## Шаблон раздела { #section-template }

Документ "Хэндофф" состоит из пяти разделов. Используйте именно эти заголовки:

- **Цель следующего сеанса** — из аргументов пользователя или выводится из самой последней темы разговора.
- ** Состояние игры ** — что сделано, что в полете, что заблокировано. Ссылайтесь на артефакты, не вставляйте их.
- **Открытые решения** — что должен решить следующий агент, прежде чем продолжить.
- **Скиллы для использования** — конкретный список из 3-5 скилл, которые должны быть задействованы на следующем сеансе, каждый с однострочным объяснением *почему*.
- **Артефакты** — пути/URL-адреса к PRD, планам, ADR, выпускам, филиалам, PR. Не дублируйте их содержимое.

Видишь [ссылки/handoff_structure.md](references/handoff_structure.md) для отработанного примера.

## Работа агента { #the-agents-job }

Заполнение пяти разделов - это работа агента, а не сценария. Следовать [ссылки/handoff_prompt.md](references/handoff_prompt.md) в качестве обязательного чек-листа:

> Для каждой темы, обсуждаемой в беседе, четко решите: *включить в State of play / log как открытое решение / отказаться с обоснованием.*

Свободная подача резюме приводит к радужным отчетам о проделанной работе и снятию блокировок. Чек-лист предотвращает это.

## Анти-паттерны { #anti-patterns }

Дисциплина Мэтта, не допускающая дублирования, стала конкретной:

- **Не вставляйте diff.** Ссылайтесь на ветку или PR.
- **Не вводите PRD повторно.** Ссылка на его путь.
- ** Не суммируйте то, что уже есть в сообщении о фиксации.** Ссылка на хэш фиксации.
- ** Не перечисляйте 20 скилл.** Выберите 3-5, которые действительно нужны для следующего занятия.
- ** Не пересказывайте каждое сообщение в разговоре.** Сжатие до состояния + Решения.

Видишь [ссылки/deduplication_discipline.md](references/deduplication_discipline.md) для получения полного списка.

## Редактирование { #redaction }

Перед сохранением линтер сканирует черновик на наличие секретов и личных данных. В строгом режиме (по умолчанию) он блокирует сохранение результатов; в режиме предупреждения он помечает встроенные и сохраняет в любом случае.

Редактировать:
- Ключи API, токены OAuth, токены JWT
- Пароли и строки подключения к базе данных
- `-----BEGIN ... PRIVATE KEY-----` блоки
- `.env`-стиль `KEY=value` строки, содержащие секреты
- Адреса электронной почты, номера телефонов, имена не связанных между собой третьих лиц
- Внутренние URL-адреса, содержащие токены или идентификаторы сеанса

Видишь [ссылки/redaction_checklist.md](references/redaction_checklist.md) для получения полного списка шаблонов и шагов по ревью вручную на предмет того, что регулярное выражение не может перехватить.

## Автоматическая загрузка при запуске сеанса { #sessionstart-auto-load }

Когда плагин будет установлен, появится `SessionStart` hook сканирует настроенное местоположение сохранения на предмет самой последней хэндофф-передачи (в окне сохранения) и отображает его в новом сеансе как `<handoff_from_previous_session>` данные. Следующий агент считывает это как контекст, а не как инструкции — предлагаемые действия должны быть сверены с текущим состоянием перед выполнением.

Отключать для каждого сеанса с помощью `HANDOFF_SESSIONSTART=0`.

## Напоминание об окончании сеанса { #sessionend-reminder }

Парный `SessionEnd` хук проверяет, существует ли недавняя хэндофф, когда сеанс завершается. Если ничего не происходит (или самое последнее сообщение старше 30 минут), выводится однострочное напоминание, чтобы пользователю было промпт написать его до потери контекста.

Хук не может промпт в интерактивном режиме или заблокировать завершение сеанса — он отображает текст в журнале сеанса.

Отключать для каждого сеанса с помощью `HANDOFF_SESSIONEND=0`.

## Обновление существующего хэндоффа { #refreshing-an-existing-handoff }

Когда работа продолжится по истечении первоначального времени хэндоффа, обновите на месте вместо создания нового файла:

```bash
python3 scripts/handoff_template_generator.py --refresh --goal "<updated goal>"
```

Выводит путь к самому последнему хэндоффу. Агент редактирует его напрямую. Сохраняет местоположение сохранения незагроможденным и гарантирует, что функция SessionStart всегда загружает актуальную версию.

## Инструменты { #tools }

| Инструмент | Цель |
|---|---|
| `setup.py` | Вопросы и ответы при первом запуске - сохранение местоположения, хранение, строгость редактирования, git-контекст, область рекомендаций. |
| `handoff_template_generator.py` | Записывает 5-секционный каркас по настроенному пути. `--refresh` повторно использует самый последний хэндофф вместо создания нового файла. |
| `redaction_linter.py` | Сканирует черновик на наличие секретов/PII перед сохранением. Выйдите 1 при выводах в строгом режиме. |
| `handoff_self_check.py` | Проверка точности — помечает пустую цель, маркеры состояния без артефактов, пропущенные решения, когда git грязный, слишком мало/many Скиллы, встроенное содержимое в артефакты. Бегите перед линтером. |
| `skill_recommender.py` | Предлагает 3-5 скилл для следующего занятия на основе текста цели + сканирования репозитория. |
| `cleanup.py` | Удаляет каркасы, более старые, чем окно сохранения. mtime-guarded — никогда не удаляет хэндофф, отредактированный пользователем. |
| `config_loader.py` | Общий помощник: прочитайте конфигурацию проекта → глобальная конфигурация → значения по умолчанию. |

## Слэш-команды { #slash-commands }

- `/cs:handoff [optional next-session description]` — сгенерируйте хэндофф.
- `/cs:handoff-setup` — перенастройте местоположение сохранения, хранение, редактирование.

## Агент { #agent }

`cs-handoff-author` — Мэтт - персона, озвучивающая скилл. Лаконично, без дублирования, ссылки-не-копии.

## Примеры { #examples }

### Пример 1 — явный вызов с целью { #example-1--explicit-invocation-with-a-goal }

```
User: /cs:handoff "finish wiring the redaction linter and open a draft PR"
```

Пользователь скилла проходит обязательный чек-лист, генерирует каркас из 5 разделов, заполняет его из беседы, запускает средство редактирования и сохраняет в настроенном местоположении. Видишь `assets/example_handoff.md` для полного проработанного примера.

### Пример 2 — неявный триггер { #example-2--implicit-trigger }

```
User: I'm packing up for the day, let me come back to this tomorrow.
```

Обнаружьте неявный сигнал. Предложите перед запуском: * "Хотите, чтобы я написал хэндофф для следующего сеанса?"* — никогда молча. После подтверждения действуйте, как в примере 1, с предполагаемой целью.

### Пример 3 — настройка при первом запуске { #example-3--first-run-setup }

```
User: /cs:handoff "ship the migration"
Skill: Run setup now? (Y/n)
User: Y
[setup walks 5 questions: save location, retention, redaction strictness, git context, recommender scope]
Skill: Config saved to ~/.config/handoff/config.json. Continuing with handoff for: ship the migration.
```

Если пользователь отвечает на N, скилл записывает сообщение sentinel и использует значения по умолчанию (временный каталог операционной системы, 7-дневное хранение, строгое редактирование). Промпта больше никогда не появляется.

### Пример 4 — Автозагрузка при запуске сеанса { #example-4--sessionstart-auto-load }

В следующем сеансе функция SessionStart сканирует настроенное местоположение сохранения, находит самый последний хэндофф и отображает его как `<handoff_from_previous_session>` данные. Следующий агент считывает это как контекст, а не инструкции.

## Использование { #usage }

| Шаг | Команда |
|---|---|
| Настройка при первом запуске | `/cs:handoff-setup` (или сначала ответьте на Y `/cs:handoff`) |
| Сгенерировать хэндофф | `/cs:handoff [goal]` |
| Перенастройте позже | `/cs:handoff-setup --reconfigure` |
| Конфигурация для конкретного проекта | `/cs:handoff-setup --project` |
| Отключить перехватчик запуска сеанса | `HANDOFF_SESSIONSTART=0` (за сеанс) |
