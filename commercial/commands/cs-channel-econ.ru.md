# /cs:channel-econ — Прямая экономика против экономики партнеров { #cschannel-econ--direct-vs-partner-economics }

Запустите `channel-economics` скилл на основе этого ввода:

**$ARGUMENTS**

## Воркфлоу с тремя инструментами { #three-tool-workflow }

1. **`channel_mix_optimizer.py`** — Эффективный LTV для каждого канала, срок окупаемости (CAC / месячная маржа), соотношение эффективности LTV/CAC. Рекомендует смешивать, максимально увеличивая эффективный ARR, с учетом ограничений (min_direct_pct, max_partner_concentration). Таблица чувствительности (что делать, если прямой CAC повысится на 20%?).

2. **`cost_to_serve_calculator.py`** — Полностью загруженная стоимость обслуживания за сделку И за $ обр. Выделяются прямые затраты по сравнению с распределенными накладными расходами. Вычисляет "истинную валовую прибыль" после загрузки конкретного канала. Выявляются скрытые затраты (время на подключение партнеров, инвестиции в сертификацию, накладные расходы на разрешение конфликтов).

3. **`channel_roi_analyzer.py`** — Рентабельность инвестиций на канал с 3 объективами: рентабельность денежных средств за 1 год, рентабельность LTV, предельная рентабельность инвестиций (кривая убывающей доходности). Вердикт: УДВОЕНИЕ / СОХРАНЕНИЕ / ОТМЕНА / ВЫХОД + уменьшение - возвращает точку перегиба.

## Жесткое правило { #hard-rule }

** Рентабельность инвестиций в канал не рассчитывается без разницы в удержании. ** CAC канала сам по себе бессмысленен — у клиентов партнерского канала удержание часто отличается от прямого.

## Отличный от { #distinct-from }

- Родной брат `partnerships-architect` — структура партнерства *** (уровень, GTM, revshare). Экономика канала - это ** математика**.
- `business-growth/revenue-operations` — процесс (маршрутизация лидов, перемещение SDR)
- `c-level-advisor/cro-advisor` — стратегический
- `finance/financial-analysis` — закрыть + отчет (с оглядкой назад); экономика канала - это ** экономика в прямом направлении** для каждого канала
