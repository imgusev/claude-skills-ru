# /cs:partner-tier — Партнерский уровень + совместный GTM + revshare { #cspartner-tier--partner-tier--joint-gtm--revshare }

Запустите `partnerships-architect` скилл на основе этого ввода:

**$ARGUMENTS**

## Воркфлоу с тремя инструментами { #three-tool-workflow }

1. **`partner_tier_classifier.py`** — 5-уровневая детерминированная классификация: РЕФЕРАЛ (неофициальный) / РЕСЕЛЛЕР (транзакционный + маржа) / OEM (white-label + интеграция) / SI/ КОНСАЛТИНГ (сопутствующие услуги) / СТРАТЕГИЧЕСКИЙ (многолетний + совместное инвестирование). Жесткие уровни для каждого уровня (для стратегического требуется наличие ≥5 именованных учетных записей + многолетняя фиксация + выделенные ресурсы). Вердикт уровня + ** критерии уничтожения ** для определения того, когда партнерство должно прекратиться.

2. **`joint_gtm_planner.py`** — 90-дневный совместный план GTM с этапами подготовки к запуску, движением запуска, контрольной точкой в середине квартала, 90-дневными критериями успеха. Подтверждает: невозможно запланировать "управляемый каналом" уровень РЕФЕРАЛОВ.

3. **`revshare_modeler.py`** — Рекомендуемый процентный диапазон revshare, основанный на глубине вклада (РЕФЕРАЛ 5-10%, РЕСЕЛЛЕР 20-35%, OEM 40-55%) + рентабельность инвестиций в партнерскую программу + долгосрочный экономический переход.

## Жесткое правило { #hard-rule }

** Настаивайте на независимых доказательствах, прежде чем классифицировать их как СТРАТЕГИЧЕСКИЕ.** Forrester: сделки по каналам из вашего собственного пайплайна обходятся дороже, чем прямые.

## Отличный от { #distinct-from }

- `business-growth/sales-engineer` — техническая продажа (демонстрации, POCs)
- Родной брат `channel-economics` — расчет затрат на обслуживание + рентабельность инвестиций, а не структура партнерства
- `c-level-advisor/cro-advisor` — стратегический CRO
- `c-level-advisor/ma-playbook` — приобретение, а не партнерство
