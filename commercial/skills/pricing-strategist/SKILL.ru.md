# специалист по ценообразованию-стратег { #pricing-strategist }

## Цель { #purpose }

Помогите коммерческим службам, специалистам по маркетингу продуктов и CMO ответить на три вопроса на этапе ценообразования.:

1. ** Какая модель ценообразования подходит для данного продукта + клиента + рынка?** (на основе места по подписке, на основе использования, на основе ценности, бесплатная, гибридная)
2. ** Что на самом деле платит клиент, прежде чем это покажется ему слишком дорогим?** (PSM Ван Вестендорпа по ответам на опрос WTP)
3. ** Как мы должны распределить это по уровням? ** (Хорошо / лучше / наилучший вариант — с обнаружением анти-шаблона)

Скилл рекомендует ** модель и ассортимент**. Человек выбирает число, владеет компромиссами и управляет GTM.

## Когда использовать { #when-to-use }

- Запуск нового инструмента SaaS / API / AI и выбор первой модели ценообразования
- Пересмотр ценообразования после более чем 18 месяцев использования данных GTM (изменение модели, а не просто повышение цен)
- Разработка или редизайн многоуровневой упаковки (хорошая/улучшенная/наилучший вариант, бронзовая/серебряная/золотая)
- У вас есть данные опроса Van Westendorp, и вам нужен оптимальный ценовой диапазон
- Правление / исполнительный директор спрашивает: "Сколько мы должны взимать?" и вам нужен структурированный ответ
- Вы подозреваете, что в вашей упаковке есть анти-шаблоны (уровень приманки, дамп функций, отсутствие триггера обновления)

**Не используйте для:**
- Утверждение скидки за каждую сделку → `deal-desk`
- Стратегическое позиционирование CMO, создание бренда, категории → `c-level-advisor/cmo-advisor`
- Стратегия получения дохода всей компанией → `c-level-advisor/cro-advisor`
- Техническая поддержка продажи → `business-growth/sales-engineer`

## Воркфлоу { #workflow }

### Шаг 1 — Оцените контекст клиента { #step-1--assess-customer-context }

Заполнять `assets/pricing_brief_template.md` (≈ 20 мин). Обзор: отрасль, средний размер сделки, количество клиентов, факторы ценности, кривая принятия, структура потребления (место / использование / стоимость / гибрид), модели конкурентов.

### Шаг 2 — Выберите модель ценообразования { #step-2--pick-the-pricing-model }

Бежать `scripts/pricing_model_picker.py --input brief.json --profile saas --output markdown`. Выходные данные ранжируют 5 моделей по степени соответствия - оценка 0-100 с учетом компромиссов. Логика принятия решений детерминирована: низкая дисперсия использования + высокая привязка к месту → выигрыши по подписке; использование по степенному закону + переменная ценность для клиентов → выигрыши, основанные на использовании.

### Шаг 3 — Проверка WTP с помощью Van Westendorp PSM { #step-3--validate-wtp-with-van-westendorp-psm }

Если у вас есть данные опроса (≥ 4 вопросов на респондента: слишком дешево / выгодная сделка / становится дороже / слишком дорого обходится), запустите `scripts/wtp_analyzer.py --input survey.json --output markdown`. Выходные данные: 4 точки пересечения (OPP, IDP, PMC, PME) и диапазон приемлемых цен.

PSM указывает ** диапазон **, а не цену. Видишь `references/van_westendorp_methodology.md` для распространенных неправильных толкований.

### Шаг 4 — Дизайн упаковки { #step-4--design-packaging }

Бежать `scripts/packaging_designer.py --input features.json --profile saas --output markdown`. Результат: 3-уровневое назначение "Хорошо"/"Лучше"/"Наилучшее" с флагами анти-шаблона (уровень приманки, дамп функций, триггер без обновления, лидер бронзовых потерь, предприятие без привязки).

### Шаг 5 — Примите решение { #step-5--decide }

Отнесите модель + ассортимент + упаковку в комитет по ценообразованию. Скилл не фиксирует номер — это делаете вы.

## Сценарии { #scripts }

- `scripts/pricing_model_picker.py` — 5-модель fit scorer (подписка / использование / ценность / freemium / гибрид)
- `scripts/wtp_analyzer.py` — Внедрение PSM Ван Вестендорпом
- `scripts/packaging_designer.py` — Хороший / улучшенный / лучший дизайнер уровней с функцией обнаружения анти-шаблонов

Все скрипты: только stdlib. `--help` и `--sample` поработайте над всеми тремя.

## Краткий пример { #quick-example }

```bash
# Emits a scored 5-model pricing-fit recommendation (subscription / usage / value / freemium / hybrid) for the built-in example
cd commercial/skills/pricing-strategist && python3 scripts/pricing_model_picker.py --sample
```

## Допущения { #assumptions }

- Решения о ценообразовании принимаются совместно: коммерческому предприятию принадлежит форма модели + уровень, продукту - характеристики для каждого уровня, финансовому - пакет скидок, юридическому - контракт.
- PSM Ван Вестендорпа - это инструмент **направленного действия**. Минимум N ≥ 30, предпочтительно N ≥ 100. Ниже 30 скрипт выдает предупреждение о размере выборки.
- "Ценообразование, основанное на ценности" требует наличия измеримого фактора потребительской ценности (увеличение выручки, экономия затрат, восстановление времени). Если вы не можете это измерить, не выбирайте на основе ценности.
- Отраслевые профили настраивают значения по умолчанию — они не переопределяют ваши данные.
- Это скилл для поддержки принятия решений, а не предсказание цен. Вывод - это модель + ассортимент, но никогда не номер.

## Анти-паттерны { #anti-patterns }

- ** Рекомендация определенного номера.** Этот скилл определяет модель и ассортимент. Окончательная цена - это коммерческое решение человека, включающее политику отдела заключения сделок, информацию о конкурентах и стратегические намерения, о которых этот скилл не может знать.
- **Используется PSM с N < 30.** Преобладает статистический шум. Сценарий предупреждает; уважайте предупреждение.
- **Трактовка PSM как "цены".** PSM предоставляет диапазон приемлемых цен (RAP) и оптимальную ценовую точку (OPP). Протестируйте ассортимент на рынке, не привязывайтесь к одному перекрестку.
- ** Выбор ценообразования, основанного на ценности, без измеримого показателя ценности. ** Без инструментария, показывающего рентабельность инвестиций клиентов, ценообразование, основанное на ценности, сводится к "тому, что они заплатят", что является просто плохим ценообразованием, основанным на использовании.
- **Проектирование уровней перед выбором модели.** Структура уровней зависит от модели. Сначала запустите pricing_model_picker.
- ** Упаковка "дампов функций" в уровень Best. ** Если у Best в 3 раза больше функций по цене в 2 раза выше, клиенты покупают лучшее и никогда не обновляют. Видишь `packaging_anti_patterns.md`.
- ** Скрытые цены, основанные на использовании, внутри уровней подписки.** "До 100 тыс. вызовов API/mo, тогда $X за 1 тыс.", замаскированный под "профессиональный уровень", - это две модели ценообразования в одной. Клиенты замечают это. Выбери что-нибудь одно.
- ** Путаю этот скилл с deal-desk.** Ценовая стратегия = меню. Deal-desk = утверждение скидок вне меню. Другое решение, другой ритм, другой владелец.

## Отличный от { #distinct-from }

- ** deal-desk** — одобрение скидки за каждую сделку, MEDDIC, оценка сделки. Действует ежедневно по существующим ценам.
- **советник c-уровня/cmo-advisor** — стратегическое позиционирование, бренд, категория. Ценовой стратег использует позиционирование в качестве входных данных, а не генерирует его.
- **советник c-уровня/cro-advisor** — стратегия получения дохода по полной воронке, планы по увеличению, дизайн территории. Специалист по ценовой стратегии - это один из факторов, влияющих на CRO.
- **рост бизнеса/sales-engineer** — техническая продажа, определение объема POC. Механизм продаж работает после установления цены.

## Библиотека принудительных вопросов (дисциплина Matt Pocock grill) { #forcing-question-library-matt-pocock-grill-discipline }

Проходили по одному мимо `/cs:grill-commercial` или оркестратор. Рекомендуемый ответ + цитата из канона на каждый вопрос. Никогда не упаковывался.

1. ** "Платит ли ваш клиент за результаты, места или использование?"**
   Рекомендуется: результаты (основанные на ценности), если вы можете их измерить; использование, если предельные издержки изменчивы; места только в том случае, если использование примерно одинаковое на одного пользователя.
   Канон: Ramanujam 2016 (*Монетизация инноваций*) — Ошибка № 1 из 9: цены на продукты, зависящие от их использования, зависят от количества мест, что составляет ~ 20% от WTP.

2. ** "Есть ли у вас измеримый показатель ценности, или вы только предполагаете?"**
   Рекомендуется: перед выходом на рынок определите показатель стоимости с помощью ценообразования, основанного на стоимости.
   Канон: Патрик Кэмпбелл (Patrick Campbell) / ProfitWell research — ценообразование, основанное на ценности, без использования инструментов, превращается в ценообразование, основанное на плохом использовании.

3. ** "Какова разница в использовании клиентами вашего верхнего дециля по сравнению со средним показателем?"**
   Рекомендуется: дисперсия > 10x → выигрыши, основанные на использовании; дисперсия < 3x → выигрыши по подписке; промежуточный вариант → гибрид с избыточным использованием.
   Канон: Кайл Пойар (* Замедленный рост*) — продукты с высокой дисперсией теряют более 60% выручки по тарифным планам с фиксированной ставкой.

4. ** "Какова ценовая модель вашего конкурента и почему вы выбираете ту же или иную?"**
   Рекомендуется: явно выдвинуть гипотезу дифференциации. Идентичная цена = заявленная идентичная стоимость.
   Канон: Дэвид Скок (*Для предпринимателей*) — ценообразование - это сигнал позиционирования.

5. ** "Какой размер выборки у вас есть для анализа WTP, и сегментирована ли она?"**
   Рекомендуется: N≥30 на сегмент для PSM, N≥100 для conjoint.
   Канон: ван Вестендорп 1976 / Методология программного обеспечения Sawtooth — менее 30 PSM - это статистический шум.

6. ** "Какая единственная функция приводит к повышению уровня?"**
   Рекомендуется: для каждого лучшего уровня требуется один-единственный не подлежащий обсуждению триггер обновления.
   Канон: Рамануджам (*Монетизация инноваций*) — Ошибка № 4: уровни без четких различий заставляют 70% покупателей выбирать самые дешевые.

Сначала пройдите вглубь. Зафиксируйте 1-3 перед открытием 4-6. После того, как будут даны ответы на все 6 вопросов, вызовите `pricing_model_picker.py` → `wtp_analyzer.py` → `packaging_designer.py` в определенной последовательности.
