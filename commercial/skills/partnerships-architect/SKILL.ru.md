# партнерство-архитектор { #partnerships-architect }

## Цель { #purpose }

Помогите руководителю отдела партнерских отношений, руководителю BD и руководителям-основателям ответить на четыре вопроса при появлении
потенциального партнера:

1. ** Является ли это реальным партнером или кто-то ищет льготные условия без самостоятельного запроса?**
2. ** На каком уровне мы должны их подписывать?** (Реферал / реселлер / OEM / SI-Consulting / Стратегический альянс)
3. **Каков 90-дневный совместный план GTM, который доказывает, что партнерство работает?**
4. ** Какой revshare имеет экономический смысл — и в какой момент партнерство превосходит прямые продажи?**

Скилл выдает вердикт уровня + план GTM + группа revshare с четкими критериями уничтожения. Это
**не** подписывает сделку. Человек, выполнив этот скилл, принимает решение.

## Когда использовать { #when-to-use }

- К нам обратился потенциальный партнер и попросил предоставить "стратегические" условия для реселлеров / OEM-производителей
- Вы разрабатываете новую структуру уровней партнерской программы
- Вы проводите ревью существующего партнерства, которое работает неэффективно, и вам необходимо принять решение: изменить уровень, реструктурировать GTM или распустить
- Большой логотип требует "стратегического альянса" — и вам нужно подтвердить, что он реальный, а не навязанный поставщиком.
- Консалтинговая фирма или SI хочет поделиться услугами по вашему продукту
- Поставщик платформы предлагает OEM / white-label, и вам нужно смоделировать математику
- Вы подозреваете, что сделки с "партнерскими источниками" на самом деле являются вашим собственным пайплайном, который обезжиривается для получения маржи

**Не используйте для:**
- Технические демонстрации и POC → `business-growth/sales-engineer`
- Расчет затрат на обслуживание и рентабельности инвестиций на существующем канале → родственном канале `channel-economics`
- Стратегия получения дохода всей компанией → `c-level-advisor/cro-advisor`
- Приобретение компании вместо партнерства → `c-level-advisor/ma-playbook`
- Утверждение скидки за каждую сделку в рамках подписанного партнерского контракта → `deal-desk`

## Воркфлоу { #workflow }

### Шаг 1 — Прием внутрь (≈ 20 мин) { #step-1--intake--20-min }

Заполнять `assets/partnership_intake_template.md`. Фиксируйте: имя_партнера, тип_партнера, доказательства
независимого спроса (названные аккаунты, которые они получили, отношения с конечными клиентами,
размер их отдела продаж), стратегическую ценность (география / продукт / бренд / экономика канала),
обязательства, которые они предложили (совместные маркетинговые расходы, выделенная численность персонала, сертификация,
целевые показатели продаж).

Если шаблон приема не может быть заполнен честно, значит, потенциальный партнер
продемонстрировал недостаточно содержательности для оценки. Остановись. Возвращайся к ним.

### Шаг 2 — Уровневая классификация { #step-2--tier-classify }

Бежать `scripts/partner_tier_classifier.py --input intake.json --profile saas --output markdown`.
Результат ранжирует партнера на 1 из 5 уровней — РЕФЕРАЛ / РЕСЕЛЛЕР / OEM / SI-КОНСАЛТИНГ /
СТРАТЕГИЧЕСКИЙ — с детерминированными этажами. Для СТРАТЕГИЧЕСКОГО требуется named_accounts ≥ 5,
многолетняя фиксация И выделенные ресурсы. Скилл выдает обоснование + критерии убийства.

### Шаг 3 — Совместный план GTM { #step-3--joint-gtm-plan }

Бежать `scripts/joint_gtm_planner.py --input gtm.json --profile saas --output markdown`.
Результат: 90-дневный план с этапами подготовки к запуску (обучение, сертификация, материалы),
ходом запуска (целевые аккаунты, динамика продаж, распределение MDF), контрольной точкой в середине квартала и
критериями успеха за 90 дней. Проверяет: не удается запланировать GTM на основе канала для уровня РЕФЕРАЛОВ; не удается
запланировать white-label для уровня, не относящегося к OEM.

### Шаг 4 — Обновите модель совместного использования { #step-4--revshare-model }

Бежать `scripts/revshare_modeler.py --input revshare.json --output markdown`. Рассчитывает
маржу на сделку напрямую по сравнению с сделкой через партнера, рекомендуемый процентный диапазон revshare, основанный на
глубине вклада партнера (источник > влияние > доставлено), рентабельности инвестиций партнера безубыточности и
долгосрочной экономике - в прогнозируемом масштабе экономика партнера превосходит прямую?

### Шаг 5 — Примите решение { #step-5--decide }

Возьмите tier + GTM plan + revshare band в комитет по партнерству. Скилл не указывает
на партнера — это делаете вы. Задокументируйте критерии уничтожения в контракте, чтобы
при триггере размотка была механической.

## Сценарии { #scripts }

- `scripts/partner_tier_classifier.py` — 5-уровневый классификатор с детерминированными этажами для каждого уровня
- `scripts/joint_gtm_planner.py` — генератор 90-дневного совместного плана GTM с утвержденным уровнем движения
- `scripts/revshare_modeler.py` — диапазон revshare + рентабельность инвестиций безубыточности + долгосрочная экономика

Все скрипты: только stdlib. `--help` и `--sample` поработайте над всеми тремя.

## Краткий пример { #quick-example }

## Допущения { #assumptions }

- Партнер, который не может представить доказательства независимого спроса (именованные счета, конечный клиент
  отношения, собственная команда продаж) охотится за льготными условиями, а не за партнером.
- Отраслевые профили (`--profile`) настройте значения по умолчанию — они не переопределяют ваши данные.
- Диапазоны Revshare % - это рекомендации; переговоры по контракту, политика MDF и
  условия эксклюзивности - это коммерческие решения, принимаемые человеком за пределами этого скилла.
- "Партнерский источник" требует, чтобы партнер представил сделку И владел
  первичная связь. "Под влиянием партнера" оплачивается по более низкой ставке. Атрибуция оплаты
имеет большее значение, чем требования к слайд-деке.
- Этот скилл предназначен для разработки партнерских отношений, а не для подписания -управление партнерскими сделками — один раз
  подписанный коммерческий ревью для каждой сделки направляет `deal-desk`.
- Критерии уничтожения являются обязательными. Партнерство без письменного соглашения о раскручивании триггеров.
  проблема плохого партнера на протяжении многих лет.

## Анти-паттерны { #anti-patterns }

- ** "Партнер = любой, кто спросил". ** Партнер, не имеющий независимого спроса, является охотником за скидками.
  Запустите классификатор уровней — уровень рефералов существует именно для того, чтобы поглощать их
, не отдавая маржу реселлеру.
- **Предоставление условий OEM / white-label без маржи, достаточной для финансирования поддержки.** OEM означает
  вы поддерживаете клиента, который вам не принадлежит. Если revshare не покрывает расходы на поддержку уровня 2,
сделка с OEM-производителем является убыточной.
- ** Выплата revshare на уровне источника только по сделкам, на которые оказано влияние.** Под влиянием ≠ источника. Сделка
  все равно собирался закрываться. Оплатите по действующему тарифу.
- ** Нет критериев уничтожения для неэффективно работающего партнера. ** "Стратегические альянсы" без прекращения действия
  положения становятся постоянными обязательствами после ухода исполнительного спонсора.
- ** Конфликт каналов игнорируется до тех пор, пока представители не уйдут. ** Когда ваш непосредственный представитель и ваш партнер оба
  появляясь в том же аккаунте, вы теряете либо представителя, либо партнера. Определите правила ведения
боя до, а не после.
- ** Исключительная территория, предоставляемая слабому партнеру. ** Это блокирует сильного партнера, который
  был бы на самом деле источником сделок.
- **MDF без отчетности по рентабельности инвестиций.** Фонды развития рынка без именованного пайплайна,
  заявленная рентабельность инвестиций и ежеквартальная корректировка - это субсидии, а не инвестиции.
- ** Отсутствие плана по удалению после окончания партнерства. ** Непрерывность работы с клиентами, обратная передача данных, IP-адрес
  очистка и демонтаж бренда должны быть предварительно согласованы. С ними невозможно вести переговоры после
того, как отношения испортились.

## Отличный от { #distinct-from }

- **бизнес-рост/продажи-инженер** — техническая продажа: демонстрации, POCs, определение области интеграции.
  Действует после принятия решения о партнерстве и заключения сделки.
- **экономика канала ** (родственная) — расчет затрат на обслуживание и рентабельности инвестиций на существующем канале.
  Количественно определяет, является ли подписанный партнер прибыльным. партнерство - архитектор решает
  нужно ли подписываться в первую очередь и на каком уровне.
- **консультант уровня c/cro-advisor** — стратегическое суждение о CRO (когда нанимать вице-президента канала,
  решения о распределении доходов всей компании). партнерства - архитектор работает для каждого партнерства.
- **советник уровня c/плейбук магистра** — когда ответом будет "приобрести их", а не "сотрудничать с
  их". Триггер: у партнера есть независимый ров, который вы не можете воспроизвести, или
партнерство требует справедливости для согласования стимулов. Перенаправьте на ma-плейбук.
- **deal-desk** — утверждение скидки за каждую сделку по подписанным партнерским контрактам.

## Библиотека принудительных вопросов (дисциплина Matt Pocock grill) { #forcing-question-library-matt-pocock-grill-discipline }

Проходили по одному мимо `/cs:grill-commercial` или оркестратор. Рекомендуемый ответ +
цитата из канона на каждый вопрос. Никогда не упаковывался. Зафиксируйте 1-3 перед открытием 4-6.

1. ** "Назовите 5 конечных клиентов, которым этот партнер уже продал товары за последние 12 месяцев — в компаниях, на которые вы бы ориентировались сами".**
   Рекомендуется: если они не могут этого сделать, значит, у них нет независимого спроса. Регистрируйтесь только на уровне РЕФЕРАЛОВ,
если вообще регистрируетесь. Торговые посредники /OEM-производители /стратегические площадки требуют продемонстрированных отношений с конечными потребителями.
   Канон: Джо Хесслинг — анализ сбоев партнерской программы выявил "отсутствие независимого спроса".
   как первопричина № 1 мертвых уровней партнеров.

2. ** "Этот партнер просит о льготных коммерческих условиях или спрашивает, как привлечь к вам клиентов?"**
   Рекомендуется: охотники за скидками лидируют по условиям; реальные партнеры лидируют по аккаунтам. Прослушайте
первые 30 минут первой встречи.
   Канон: Исследование канала Forrester — более 60% "запросов партнеров" на ранних стадиях SaaS
- это поиск скидок, а не инвестиции в канал.

3. ** "Каково общее ценностное предложение в одном предложении и кто является названным конечным потребителем, которого оно обслуживает?"**
   Рекомендуется: если нет совместного предложения ценности, отличного от индивидуального предложения любой из сторон, партнерства
нет — в лучшем случае есть совместный маркетинг.
   Канон: Джеффри Мур (*Пересекая пропасть*) — партнерство по всему продукту существует, когда
ни одна из сторон в одиночку не обеспечивает желаемый результат для клиента.

4. ** "При какой процентной скидке это партнерство превосходит экономику прямых продаж и в каком масштабе?"**
   Рекомендуется: моделировать безубыточный объем пайплайна. Если сделки, заключенные с партнерами, должны превышать
   30% объема канала, чтобы превзойти direct, и партнер может правдоподобно предоставить 5%, у вас есть
   построил проигрышную программу.
   Канон: Прадип Чинтагунта (стенд в Чикаго) об экономике канала — партнерствах с каналами
   без минимального объема работы вы будете безубыточны даже в теории и потеряете деньги на практике.

5. ** "Каковы названные критерии прекращения этого партнерства и указаны ли они в контракте?"**
   Рекомендуется: минимальный этаж пайплайна по кварталам, минимальные сертифицированные ресурсы, минимальный
   совместные сделки закрыты, 90-дневный период лечения. Раскручивание без заранее согласованных критериев становится
   судебная тяжба длилась 2 года.
   Канон: Канал IBM - тематические исследования конфликтов (1990-е годы после отчуждения) — убийство без документов
   критерии превращали плохих партнеров в постоянные обязательства.

6. ** "Если этот партнер продаст товар одному из ВАШИХ прямых аккаунтов, кто выиграет — ваш представитель или они?"**
   Рекомендуется: Правила ведения боя в письменном виде, подписанные перед началом матча. Территория по названию
   учетная запись, по сегментам или по географическому положению. Разрешение конфликтов у названного человека, а не в комитете.
   Канон: Джей Макбейн (Canalys) — конфликт каналов - убийца партнерской программы №1; написан
   ROE, опубликованный до подписания партнером, предотвращает 80% споров.

7. ** "Является ли это партнерством или это должно быть приобретение?"**
   Рекомендуется: если у партнера есть независимый ров, который вы не можете воспроизвести, И
партнерство требует многолетней эксклюзивности, А партнерство требует равного участия
   выравнивание, вы описываете приобретение. Перенаправить на `ma-playbook`.
Канон: Вскрытие каналов HP (частичная интеграция Indigo, EDS) — партнерские отношения
   структурированный как приобретение без участия в капитале, он разрушает больше ценности, чем любой другой путь в чистом виде.

Сначала пройдите вглубь. Заблокируйте 1-3 (это настоящий партнер?) перед открытием 4-7 (
правильная ли структура?). После того, как будут даны ответы на все 7 вопросов, вызовите `partner_tier_classifier.py` →
`joint_gtm_planner.py` → `revshare_modeler.py` в определенной последовательности.
