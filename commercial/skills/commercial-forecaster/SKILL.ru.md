# реклама-прогнозист { #commercial-forecaster }

## Цель { #purpose }

Помогите коммерческим лидерам ответить на три вопроса в прогнозируемый момент:

1. ** Каков номер фиксации / наилучшего варианта / только для канала?** (прогноз 3-уровневых бронирований с раскрытыми допущениями)
2. **Из каких когорт происходит утечка, и скрывает ли сводный NRR утечку?** (прогноз NRR/GRR по каждой когорте за горизонт)
3. **Какие этапы воронки являются надежными, а какие представляют собой статистический шум?** (доверительный интервал коэффициента вариации для каждого этапа)

Скилл рекомендует ** три прогнозных числа + блок явных предположений **. CRO представляет цифру, правление видит допущения, театр умирает.

## Когда использовать { #when-to-use }

- Составление ежеквартального прогноза заказов для правления
- Подготовка прогноза QBR, в котором финансовый директор спросит: "Что такое фиксация, какой наилучший вариант, какой только для канала".
- Прогнозирование ARR на следующие 4-8 кварталов с использованием данных о удержании когорты
- Подозревая, что за сводным числом NRR скрывается утечка информации о недавней когорте
- Охват пайплайна сокращается, и вам нужно знать, какие этапы по-прежнему заслуживают доверия
- Вас просят ввести "единственное число", и вам нужен структурированный ответ, который подтверждает предположение

**Не используйте для:**
- Ретроспективное финансовое закрытие + отчетность → `finance/financial-analysis`
- Стратегическое финансовое планирование (многолетнее, сценарное, сбор средств) → `c-level-advisor/cfo-advisor`
- "Стоит ли нам нанять вице-президента по продажам?" / дизайн территории / составление плана → `c-level-advisor/cro-advisor`
- Установка цен → родственник `pricing-strategist` (доход от проектов *по* уже установленным ценам)
- Одобрение скидки за каждую сделку → родственник `deal-desk`

## Воркфлоу { #workflow }

### Шаг 1 — Пайплайн приема + когорта + исторические данные о преобразовании { #step-1--intake-pipeline--cohort--historical-conversion-data }

Заполнять `assets/forecast_intake_template.md` (≈ 20 мин). Фиксирует: список возможностей со стадией / суммой / датой закрытия / возрастом / последней активностью; историю конверсий от этапа к этапу за последние 4 квартала и последние 12 кварталов; данные о доходах по каждой когорте + данные о удержании за квартал + данные о расширении; названия этапов воронки с историей конверсий за 12 кварталов.

### Шаг 2 — Запустите прогноз бронирований на 3 уровня { #step-2--run-3-tier-bookings-forecast }

```
scripts/bookings_forecaster.py --input intake.json --profile saas --output markdown
```

Выводит три числа — ** фиксация**, ** наилучший вариант**, ** только для канала** - каждое с применяемым коэффициентом преобразования, используемым окном данных (последние 4 квартала против последних 12 кварталов, взвешенных 70/30) и корректировкой вероятности времени до закрытия. Отображает разницу между фиксацией и каналом - только в качестве индикатора риска пайплайна.

**Блок предположений необязателен.** Если вы удалите его, прогноз станет театральным.

### Шаг 3 — ОБР на уровне когорты проекта { #step-3--project-cohort-level-arr }

```
scripts/cohort_arr_projector.py --input intake.json --output markdown
```

Вычисляет NRR + GRR для каждой когорты по горизонту проекции. Помечает любую когорту, у которой NRR снижается по сравнению с среднее значение по конечным когортам - это когорты с утечками, которые сводное число будет скрывать в течение 2-3 кварталов, прежде чем утечка проявится в верхней строке.

Выходные данные включают в себя сводную траекторию NRR/GRR + тепловую карту когорты + выноску с утечкой когорты.

### Шаг 4 — Оценка уверенности воронки на каждом этапе { #step-4--score-per-stage-funnel-confidence }

```
scripts/funnel_confidence_scorer.py --input intake.json --output markdown
```

Для каждого этапа: средний процент конверсии, стандартное отклонение, коэффициент вариации (CoV = StDev / среднее значение), доверительный интервал (ВЫСОКИЙ < 10%, СРЕДНИЙ 10-25%, НИЗКИЙ 25-50%, ОЧЕНЬ НИЗКИЙ > 50%). Рекомендует обработку для каждого этапа: расширение окна данных, обработка как мягкий пол или фиксация качества.

### Шаг 5 — Соберите колоду прогнозов { #step-5--assemble-the-forecast-deck }

Внесите 3-уровневый номер бронирования + тепловую карту когорты + доверие к воронке в колоду QBR / board. ** Блок предположений помещается на слайд с номером.** Если на слайде есть один номер и нет блока предположений, слайд является театральным.

## Сценарии { #scripts }

- `scripts/bookings_forecaster.py` — 3-уровневый прогноз бронирований (фиксированный / наилучший вариант / только для канала) с раскрытым коэффициентом конверсии + окно данных + блок взвешивания
- `scripts/cohort_arr_projector.py` — проекция NRR/GRR для каждой когорты по горизонту с выноской для каждой когорты
- `scripts/funnel_confidence_scorer.py` — доверительные интервалы на основе CoV для каждого этапа с рекомендациями по лечению

Все скрипты: только stdlib. `--help` и `--sample` поработайте над всеми тремя.

## Допущения { #assumptions }

- ** Историческая конверсия является предшествующей, а не истинной.** Последний 4 квартал взвешен на 70%, последний 12 квартал взвешен на 30%. Смесь отражает смену режима (недавнее замедление темпов роста), не привязываясь ни к одному плохому кварталу. Окно + взвешивание отображаются в каждом выводе.
- ** Прогноз без раскрытия блока предположений - это театр. ** Это жесткое правило скилла. CLI отказывается опускать блок допущения.
- ** Декомпозиция по когортам выявляет утечки на 2-3 квартала раньше, чем сводные данные.** Отчетность о NRR без разбивки по когортам скрывает утечку.
- ** CoV (коэффициент вариации) - это правильная дисциплина для определения степени достоверности. ** Стадия со средним значением конверсии 40% и stdev 4% (CoV 10%) - это ВЫСОКАЯ степень достоверности; среднее значение 40%, stdev 20% (CoV 50%) - ОЧЕНЬ НИЗКОЕ. За одним и тем же средним показателем скрывается совершенно разная надежность.
- ** Отраслевой профиль настраивает предварительные данные, а не истину.** Профиль изменяет уровни конверсии по умолчанию в зависимости от отрасли; ваши исторические данные переопределяются.
- ** Скилл выдает три числа и блок предположений. ** CRO выбирает номер фиксации, принимает решение о компромиссе и обходит доску с учетом разницы.

## Анти-паттерны { #anti-patterns }

- **Прогноз на основе одного числа без диапазона достоверности.** Правление запрашивает "число"; дисциплина состоит в том, чтобы представить три с названными предположениями. Видишь `forecast_anti_patterns.md`.
- **Использование преобразования за последние 12 кварталов вслепую.** Скрывает недавнее замедление. Соотношение 70/30 в последнем 4-м квартале по сравнению с последним 12-м кварталом исправляет это.
- **Отчетность о NRR без когортной декомпозиции.** Сводный показатель может быть неизменным, в то время как в недавней когорте утечка составляет 15 п.п.; утечка проявляется в верхней строке через 2-3 квартала. Всегда разлагаются.
- ** Относитесь к наилучшему варианту как к обязательству.** Финансовый директор съест вас. Наилучший вариант включает в себя операции с взвешенной стадией, вероятность закрытия которых составляет < 50%; фиксация включает только этапы с уровнем фиксации.
- **Скрытие блока "Предположение".** Скилл отказывает; если вы удалите его вручную, театр станет вашим.
- ** Нет выноски "дырявая когорта".** Если `cohort_arr_projector.py` помечает когорту, и вы убираете флаг в колоде, утечка становится вашей в следующей четверти.
- **Игнорирование возраста опп на поздней стадии.** "Устная" сделка, которая была устной в течение 180 дней, не является обязательством. Прогнозист бронирований автоматически снижает вес остановленных опп; не увеличивайте их вручную.
- **Нет проверки пайплайна- проверка покрытия.** Отраслевое эмпирическое правило: прогноз > пайплайн ÷ 3 противоречит шаблону. Поверхность инструмента соответствует соотношению; соблюдайте его.

## Отличный от { #distinct-from }

- **`finance/financial-analysis`** — ретроспективный финансовый отчет, отчетность по GAAP/МСФО, разница в сравнении с бюджетом. commercial-forecaster - это перспективная математика пайплайна.
- **`c-level-advisor/cfo-advisor`** — стратегическое многолетнее финансовое планирование, сценарии сбора средств, взлетно-посадочная полоса. специалист по коммерческому прогнозированию - это один из входных данных для финансового директора, а не для разработки стратегии.
- **`c-level-advisor/cro-advisor`** — стратегическое решение CRO: "нанимать ли нам вице-президента по продажам?", дизайн территории, составление плана, когда добавить инженера по продажам. коммерческий прогнозист - это математика, которую использует CRO; cro-советник - это суждение, которое применяет CRO.
- **родной брат `pricing-strategist`** — устанавливает цену (модель + ассортимент). коммерческий прогнозист * прогнозирует выручку по этим ценам*. Ценообразование стоит на первом месте, прогноз - на втором.
- **родной брат `deal-desk`** — оценка за каждую сделку + маршрут утверждения скидки. commercial-forecaster агрегирует пайплайн, с которым deal-desk работает изо дня в день.

## Библиотека принудительных вопросов (дисциплина Matt Pocock grill) { #forcing-question-library-matt-pocock-grill-discipline }

Проходили по одному мимо `/cs:grill-commercial` или оркестратор. Рекомендуемый ответ + цитата из канона на каждый вопрос. Никогда не упаковывался.

1. ** "Какой коэффициент конверсии вы используете, и это последний-4 квартал или последний-12 квартал?"**
   Рекомендуется: смесь 70/30 (в последнем 4-м квартале взвешено 70%, в последнем 12-м квартале взвешено 30%). Только за последним 12 кварталом скрывается недавнее замедление; только за последним 4 кварталом перевыполняется один плохой квартал.
   Канон: Томаш Тунгуз (Theory Ventures) — исследования прогнозирования показывают, что оценки конверсии в режиме "единого окна" не учитывают изменение режима с задержкой ~ в 3 квартала.

2. ** "Каков коэффициент охвата вашего пайплайна и превышает ли ваша фиксация уровень пайплайна ÷ 3?"**
   Рекомендуется: 3-кратный охват - это минимальный уровень для SaaS-индустрии; ниже 3-кратного означает, что ваша фиксация структурно не поддерживается.
   Канон: Опрос Pacific Crest / KeyBanc SaaS — компании, входящие в топ-квартиль SaaS, поддерживают покрытие пайплайна в 3,0-4,5 раза по сравнению с фиксированными заказами.

3. ** "Можете ли вы показать мне NRR по когортам, а не только консолидированный?"**
   Рекомендуется: никогда не сообщайте о сводном NRR без разбивки по когортам. Дырявые когорты прячутся в средних значениях.
   Канон: Патрик Кэмпбелл (ProfitWell) + Дэвид Скок — управляемая когортой декомпозиция удержания приводит к утечке за 2-3 квартала до того, как консолидированный NRR начнет двигаться.

4. ** "Какова разница (CoV) в коэффициенте конверсии каждого этапа за последние 12 кварталов?"**
   Рекомендуется: CoV < 10% → уровень фиксации; 10-25% → умеренный; 25-50% → только мягкий пол; > 50% → не используйте этот этап для прогнозирования.
   Канон: MIT Sloan forecasting research / Hyndman & Athanasopoulos (*Прогнозирование: принципы и практика*) — CoV на основе входных рядов предсказывает точность прогноза более надежно, чем среднее значение.

5. ** "Как долго каждый ОПП на поздней стадии находится на поздней стадии?"**
   Рекомендуется: стадия-возраст > 2-кратная средняя продолжительность стадии → рассматривать как остановленную, исключить из фиксации, сохранить только в конвейере.
   Канон: Дэвид Скок (*Для предпринимателей*) — Идентификация stalled-opp по стадиям и возрасту - это прогнозируемая гигиеническая практика № 1 в пайплайнах SaaS высшего дециля.

6. ** "Находится ли ваш наилучший прогноз в пределах 30% от вашего прогноза только для труб?"**
   Рекомендуется: если в лучшем случае используется < 50% только для труб, ваши предположения о поэтапном преобразовании пессимистичны, и вы занимаетесь "мешками с песком"; если в лучшем случае используется > 80% только для труб, вы придерживаетесь хоккея.
   Канон: исследование McKinsey о предвзятости прогнозов + тесты OpenView SaaS — большинство команд работают в одном из двух режимов сбоя: "мешков с песком" (фиксация << заработка) или "хоккейная клюшка" (фиксация >> заработка).

7. ** "Какой блок предположений сопровождает число на слайде доски?"**
   Рекомендуется: в каждом номере прогноза на слайде доски указывается (а) коэффициент конверсии, (б) окно данных, (в) выбор веса, (г) коэффициент охвата пайплайном. Отсутствие блока предположений = слайд является театральным.
   Канон: Практика коммерческого прогнозирования Bain & Company + пайплайн Forrester - исследование охвата - прогнозы на основе нераскрытых предположений отличаются от фактических данных в 2,3 раза больше, чем прогнозы на основе раскрытых предположений.

Сначала пройдите вглубь. Зафиксируйте 1-3 перед открытием 4-7. После того, как будут даны ответы на все 7 вопросов, вызовите `bookings_forecaster.py` → `cohort_arr_projector.py` → `funnel_confidence_scorer.py` в определенной последовательности.
