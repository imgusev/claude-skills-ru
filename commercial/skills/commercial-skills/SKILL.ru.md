# Оркестратор коммерческого домена { #commercial--domain-orchestrator }

Коммерческая поверхность - это ** экономика каждой сделки и упаковка **: как компания оценивает, упаковывает, утверждает и прогнозирует выручку. Этот оркестратор разветвляет свой контекст, направляет ваш запрос к одному из семи под-скилл, затем возвращает дайджест. Интенсивный прием (PDF-файлы RFP, экспорт по пайплайну, партнерские соглашения) остается в разветвленном контексте.

## Когда вызывать { #when-to-invoke }

| Симптом | Вспомогательный скилл |
|---|---|
| "Мы теряем сделки по цене — должны ли мы снизить цены или переупаковать?" | `pricing-strategist` |
| "Можем ли мы одобрить скидку в размере 40% на эту корпоративную сделку?" | `deal-desk` |
| "Должны ли мы подписать контракт с этим реселлером? Какой у них уровень?" | `partnerships-architect` |
| "Действительно ли наш партнерский канал прибыльный?" | `channel-economics` |
| "Как должна выглядеть наша стандартная матрица скидок?" | `commercial-policy` |
| "Помогите мне ответить на это 60-страничное предложение" | `rfp-responder` |
| "Каков наш прогноз по бронированиям на четвертый квартал при текущей конвертации?" | `commercial-forecaster` |

## Логика маршрутизации (детерминированная) { #routing-logic-deterministic }

Та же пороговая схема с двумя сигналами, что и `business-operations-skills`. Одиночный сигнал → уточняющий вопрос. Смешанные сигналы → сначала наивысшая достоверность, вторая цепочка в последующем повороте.

## Воркфлоу (дисциплина Matt Pocock grill) { #workflow-matt-pocock-grill-discipline }

Взято из книги Мэтта Покока `grill-with-docs` схема: ** исследуйте, затем задавайте, по одному вопросу за ход с рекомендуемым ответом, сначала пройдитесь по дереву решений в глубину, отслеживайте зависимости, закрепляйте каждую проблему в каноне SaaS pricing / deal desk ** (`references/`).

### Шаг 1 — Исследуйте, прежде чем спрашивать { #step-1--explore-before-asking }

Сначала проверьте рабочий каталог пользователя:
- Есть ли уже в рабочей области запись сделки, таблица сопоставления цен, документ запроса предложений или экспорт пайплайна?
- Устраняет ли запрос уже неоднозначность полосы (например, "ревью это 60-страничное предложение" — это `rfp-responder`, вопрос не нужен)?
- Существует ли имя файла артефакта, которое разрешает полосу движения (`pipeline-Q4.csv` → прогноз; `MSA-redline.docx` → сделка)?

Если рабочее пространство разрешает полосу движения, **проложите маршрут автоматически**.

### Шаг 2 — Если все еще неясно, задайте ОДИН форсирующий вопрос с рекомендуемым ответом { #step-2--if-still-ambiguous-one-forcing-question-with-a-recommended-answer }

Правило Мэтта: никогда не связывайся. Всегда рекомендую.

Узор:
```
Q1/1: [precise question naming the two candidate lanes]
Recommended: [Lane X, because <signal-table rationale>]

(Confirm, or override?)
```

### Шаг 3 — Прохождение по дереву принятия решений для многополосных запросов { #step-3--decision-tree-walk-for-multi-lane-inquiries }

Если запрос законно пересекает две полосы (например, "этот заказчик хочет скидку, которую мы обычно не предоставляем" = запрос + СДЕЛКА +, возможно, ПОЛИТИКА), сначала пройдите вглубь:

1. Сначала пройдите полосу наивысшей уверенности → запустите вспомогательный скилл в раздвоенном контексте → дайджест
2. Спросите: "Теперь беги [вторая полоса]? Рекомендуется: да, потому что [зависимость]."
3. Подтвердите перед соединением в цепочку.

Никогда не цепляйтесь молча.

### Шаг 4 — Вызов вспомогательного скилла в раздвоенном контексте { #step-4--invoke-sub-skill-in-forked-context }

Переслать исходный промпт + структурированные входные данные (CSV-файл пайплайна, путь к документу запроса предложений, таблица сопоставления цен, красная строка MSA).

### Шаг 5 — Верните дайджест с цитируемым вызовом по канону { #step-5--return-digest-with-cited-canon-challenge }

≤ 200 слов: проанализировано, 3 лучших результата (привязанных к цитированию по канону), 3 лучших следующих действия (с именем утверждающего, где применимо), путь к артефакту и **одна сложная задача ** для пользователя. Примеры:

- "Ваша система показателей сделки показывает маржу в 38% после скидки. В тесте Skok для предпринимателей говорится, что сделки SaaS с валовой прибылью до скидки менее 70% требуют тщательного изучения. Вы моделировали стоимость выполнения или только винтики?"
- "Ваша упаковка обладает 14 функциями в Better и 16 в Best. Мадхаван Рамануджам (Монетизация инноваций): уровни без четких различий заставляют 70% клиентов выбирать самые дешевые. Какая единственная функция требует обновления?"

## Библиотека принудительных вопросов (шаблон grill-with-docs) { #forcing-question-library-grill-with-docs-pattern }

Проконсультируйте пользователя по поводу решений, определяющих полосу движения, прежде чем использовать вспомогательный скилл. По одному за ход, рекомендуемый ответ, цитата из канона:

- ** ЦЕНОВАЯ политика **: "Прежде чем выбрать модель: платит ли ваш клиент за результаты, места или использование? Рекомендуется: результаты (основанные на ценности), если вы можете их измерить. Анти-паттерн (Ramanujam 2016 * Монетизирующая инновация *): цены на продукт, зависящий от использования, в зависимости от места, ограничивают ваш TAM на 20% от WTP."
- ** Полоса сделок**: "Перед утверждением: какова валовая прибыль при полной скидке ** и** как выглядит пайплайн следующего квартала на тех же условиях? Рекомендуется: моделировать оба варианта. Анти-паттерн (тесты Тунгуза): один 40%-ный прецедент изменяет 3 четверти пайплайна."
- ** Полоса прогнозирования**: "Перед прогнозированием: используете ли вы коэффициенты поэтапной конверсии за последние 4 квартала или за последние 12? Рекомендуется: последние 4 утяжелителя тяжелее. Анти-паттерн (Skok, OpenView): равный вес за 12 месяцев скрывает недавнее замедление."
- **ПАРТНЕРСКАЯ дорожка**: "Перед подписанием: есть ли у партнера ** независимый спрос**, или они перепродают наш пайплайн? Рекомендуется: настаивайте на независимом требовании доказательств. Анти-паттерн (исследование канала Forrester): сделки с использованием вашего собственного пайплайна обходятся дороже, чем прямые."

Никогда не запускайте вспомогательный скилл до тех пор, пока не будет зафиксировано решение об определении полосы движения.

## Допущения { #assumptions }

1. Пользователь обладает коммерческими полномочиями ИЛИ готовит анализ для кого-то, кто это делает.
2. Пользователь хочет ** детерминированной поддержки принятия решений **, а не окончательного ответа — человек одобряет сделку, устанавливает цену, подписывает контракт с партнером.
3. Вводимые данные могут быть частичными — каждый вспомогательный скилл предоставляет шаблонные фиктивные данные, чтобы пользователь мог увидеть форму, прежде чем заполнять свои собственные.

## Нецели { #non-goals }

- Не CRM, система CPQ или хранилище контрактов.
- Автоматически не одобряет сделки. Каждый результат - это ** оценка + рекомендация + маршрутизация между человеком и утверждающим **.
- Не сохраняет историю сделок между сеансами.

## Отличный от { #distinct-from }

- **`business-growth/sales-engineer`** — это ** техническая распродажа** (демоверсии, POCs). Коммерческая - это **экономическая форма** сделки.
- **`business-growth/revenue-operations`** — это ** процесс** (маршрутизация лидов, движение SDR). Коммерция - это **экономика каждой сделки + политика**.
- **`business-growth/contract-and-proposal-writer`** — это *авторская** проза. Реклама - это ** логика принятия решений + структурированный ответ**.
- **`c-level-advisor/cro-advisor`** — это стратегическое суждение CRO ("когда нам нанять вице-президента по продажам?"). Реклама носит тактический характер ("одобрите эту скидку").
- **`finance/financial-analysis`** — это **закрыть + сообщить**. Коммерческий - это ** прогноз + экономика каждой сделки**.

## Анти-паттерны (не делать) { #anti-patterns-do-not }

- ❌ Рекомендовать конкретную цену — рекомендовать **ассортимент + модель**, пользователь выбирает номер
- ❌ Автоматическое утверждение скидок, указанных в политике - каждая скидка >X% направляется указанному лицу, утверждающему ее.
- ❌ Сгенерируйте ответ на запрос без контрольных точек , которые пользователь может проверить
- ❌ Прогнозирование бронирований без явного использования ** предположения о конверсии**
- ❌ Запустите все 7 вспомогательных скилл "для тщательности" - выберите один, переварите, соедините в цепочку, если необходимо
