# :material-sitemap: Оркестрация { #material-sitemap-orchestration }

Облегченный протокол для координации персоналий, скилл-групп и агентов в работе, которая пересекает границы домена. Никакого фреймворка не требуется. Никаких зависимостей. Просто структурированный промпт.

## Основная концепция { #core-concept }

Большая часть реальной работы пересекает границы домена. Запуск продукта требует разработки, маркетинга и стратегии. Ревью архитектуры требует обеспечения безопасности, анализа затрат и оценки команды.

Оркестрация позволяет использовать необходимый опыт на каждом этапе работы:

- **Персонажи** определяют, кто думает (идентичность, суждения, стиль общения)
- **Скиллы** определите, как выполнять (шаги, скрипты, шаблоны, ссылки)
- **Агенты задач** определяют, что делать (ограниченное выполнение в одном домене)

## Узоры { #patterns }

### Одиночный спринт { #solo-sprint }

Один человек, одна цель, множество областей. Меняйте персонажей по мере прохождения этапов.

```
Week 1: startup-cto + engineering skills → Build
Week 2: growth-marketer + marketing skills → Prepare launch
Week 3: solo-founder + business skills → Ship and iterate
```

Лучше всего подходит для: сайд-проектов, MVP, сольных основателей.

### Глубокое погружение в домен { #domain-deep-dive }

Один домен, максимальная глубина. Единая персона, объединяющая множество скиллы.

```
Persona: startup-cto
Skills loaded simultaneously:
  - aws-solution-architect (infrastructure)
  - senior-security (hardening)
  - cto-advisor (tech debt assessment)

Task: Full technical audit of existing system
```

Лучше всего подходит для: ревью архитектуры, аудита соответствия требованиям, технической проверки.

### Мульти-Агент-Хэндофф { #multi-agent-handoff }

Разные персонажи ревью к работам друг друга.

```
Step 1: startup-cto designs the architecture
Step 2: growth-marketer reviews from user/market perspective
Step 3: solo-founder makes the final trade-off decision
```

Лучше всего подходит для: принятия решений с высокими ставками, ревью готовности к запуску, подготовки инвесторов.

### Цепочка скилла { #skill-chain }

Никакая персона не нужна. Последовательно закрепляйте скиллы для процедурной работы.

```
1. content-strategy → Identify topics and angles
2. copywriting → Write the content
3. seo-audit → Optimize for search
4. analytics-tracking → Set up measurement
```

Лучше всего подходит для: повторяемых процессов, пайплайнов контента, чек-листов соответствия требованиям.

## Пример: 6-недельный запуск продукта { #example-6-week-product-launch }

| Фаза | Недели | Персона | Скиллы | Выход |
|-------|-------|---------|--------|--------|
| Строить | 1-2 | технический директор стартапа | aws-архитектор решений, старший специалист по интерфейсу | Документ по архитектуре, деплою MVP |
| Подготовить | 3-4 | рост-маркетолог | стратегия запуска, копирайтинг, seo-аудит | Целевая страница, календарь контента |
| Корабль | 5 | соло-основатель | последовательность рассылки электронной почты, отслеживание аналитики | Запуск, отслеживание подтверждено |
| Повторять | 6 | соло-основатель | форма-cro, копирование-редактирование | Улучшения конверсии, отчет о показателях |

## Правила { #rules }

1. ** По одной персоне за раз.** Переключение - это нормально, но не смешивайте две в одном промпте.
2. ** Скиллы складываются свободно. ** Загружайте столько, сколько необходимо для выполнения задачи.
3. ** Персонажи не обязательны.** Для процедурной работы достаточно одних цепочек скилл.
4. ** Контекст продвигается вперед.** При переключении фаз обобщайте решения и артефакты.
5. **Решает человек.** Переопределите любой выбор фазы, персоны или скилла.
