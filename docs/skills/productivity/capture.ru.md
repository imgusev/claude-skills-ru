Быстрый скилл для преобразования неструктурированных потоков смешанных мыслей, задач и идей в чистую четырехсекционную систему, способную к действию, с нулевой потерей информации.

## Триггеры вызова { #invocation-triggers }

**Эксплицитные фразы** (любая из):
- "свалка мозгов"
- "запечатлей это"
- "позволь мне поделиться кое-какими идеями"
- "У меня есть куча мыслей"
- "вот все, что у меня на уме"
- "свалка идей"
- "дай мне просто выбросить это из головы"
- "Мне нужно привести в порядок свои мысли"
- "вот о чем я думаю"

**Неявные сигналы** (фразы нет, но намерение безошибочно угадывается):
- Пользователь вставляет или диктует длинный неструктурированный блок смешанных идей, задач, планов
- Множество несвязанных мыслей в одном сообщении без упорядоченного обрамления
- Стена размашистого текста, охватывающего более 3-х несвязанных тем

Когда вы обнаружите неявный триггер, запустите скилл. Не спрашивайте сначала "вы хотите, чтобы я это организовал?" — сам дамп и ЕСТЬ запрос.

## Принципы работы (Все пять применяются всегда) { #operating-principles-all-five-apply-always }

1. ** Захватывайте все.** Нулевые потери. Вводятся тривиальные элементы; пользователь удаляет их позже. Никогда молча не отбрасывайте что-либо из-за того, что это "показалось неважным".
2. ** Сохраняйте голос.** Если пользователь сказал "создайте что-нибудь сумасшедшее с помощью искусственного интеллекта", не переформулируйте как "Исследуйте инновационные решения, основанные на ИИ". Сохраняйте энергию и непринужденный тон. Видишь `references/voice_preservation.md` для конкретных анти-паттернов.
3. ** Сопоставьте сложность вывода со сложностью ввода.** Дамп из 5 задач не разбивается принудительно на 4 сложных раздела. Видишь `references/complexity_matching.md` и приведенный ниже сжатый шаблон вывода.
4. ** Будьте честны в отношении двусмысленности.** Если вы не уверены, что что-то означает, отметьте это. Не гадайте молча.
5. **Никаких действий без одобрения.** ЕДИНСТВЕННОЕ немедленное действие - это сама организация. Каждое предложение в разделе 4 ожидает явного выбора пользователем.

## Осветлитель для средней организации Grill-Me { #grill-me-mid-organization-clarifier }

Capture по своей конструкции быстр в исполнении. **Нет предварительного приема.** Свалки достаточно — немедленно приступайте к организации.

Дисциплина grill-me применяется как ** единый уточняющий вопрос для среднего звена организации**, задаваемый ** только тогда, когда** один элемент в дампе действительно неоднозначен между *задачей* и * проектом*, И неправильная классификация существенно изменила бы выходные данные:

> ** Краткое пояснение — один элемент в вашем дампе может пойти в любую сторону. Является [X] одноразовая задача или многоэтапный проект?**
>
> *Почему я спрашиваю:* Если я ошибаюсь в выборе пограничного элемента, я либо закрываю проект как задачу, либо раздуваю задачу до проекта, который не нуждается в структуре. Один вопрос на каждый дамп предотвращает это.

** Условие остановки:** Максимум 1 уточняющий вопрос на каждый дамп. После ответа (или если разъяснений не требовалось) приведите четыре (или сжатые) части.

Если дамп однозначен, полностью пропустите осветлитель.

** Анти-паттерн (не делайте этого):** заранее задайте 3 уточняющих вопроса. Это нарушает поток сброса и упорядочивания, который делает захват полезным.

## Раздел 1: Проекты и идеи { #section-1-projects--ideas }

Объединяйте связанные элементы в тематические проекты, когда существует естественная кластеризация. В этом разделе также содержится:
- Автономные творческие искры
- Наполовину сформировавшиеся концепции
- Мысли "Что, если"
- Встроенные решения (`Decide: X or Y`) и открытые вопросы (`Q: ...`) — хранится В рамках соответствующего проекта, НЕ выделяясь в отдельную категорию верхнего уровня

**Формат для каждого проекта:**

```
### {Project name in user's voice}

- {component / sub-idea}
- {component}
- Q: {open question this project needs answered}
- Decide: {decision this project requires}
```

Используйте слова пользователя для названия проекта. Если пользователь написал "приложение знакомств с искусственным интеллектом для хорьков", не переименовывайте его в "Платформу для домашних животных-компаньонов на базе искусственного интеллекта".

## Раздел 2: Задачи { #section-2-tasks }

Плоский, поддающийся сканированию, ориентированный на действие. Включает в себя:
- Явные задачи
- Решения, сформулированные в виде `Decide: ...`
- Открытые вопросы, сформулированные в виде `Resolve: ...`

Если задача относится к проекту из раздела 1, добавьте `[Project: X]` чтобы связать его — но не повторяйте контекст проекта.

**Формат:**

```
- {task in imperative voice}  [Project: X if related]
- Decide: {decision}  [Project: X if related]
- Resolve: {open question}
- ...
```

## Раздел 3: Соединения { #section-3-connections }

Это то, где скилл зарабатывает себе на жизнь — и где **фальсификация запрещена**.

**Воркфлоу:**

1. ** Инвентаризируйте рабочее пространство** — Glob на предмет соответствия шаблонов имен файлов ключевым словам дампа, Grep на предмет совпадений содержимого, прочитайте структуру каталогов верхнего уровня. Использование `scripts/workspace_inventory.py` делать это детерминистически.
2. **Сопоставьте элементы дампа с существующим содержимым** — файлы / папки, относящиеся к удаленным элементам, предварительное рассмотрение документов, незавершенные проекты с перекрытием.
3. **Поверхностные зависимости внутри дампа** — элементы, которые влияют друг на друга, темы, последствия упорядочивания.
4. ** Будьте честны в отношении недоступности** — если вы не можете проверить рабочее пространство (файловая система недоступна, MCP не подключен), скажите об этом явно. НЕ придумывайте правдоподобно звучащих связей.

** Жесткое правило: ** НИКОГДА не выдумывайте связи. Только поверхностные, которые на самом деле найдены Glob/Grep/Read. Если никаких реальных связей не существует:

> **Подключения:** Подключения не найдены — инвентаризация рабочей области очищена.

Если рабочее пространство недоступно:

> **Подключения:** Отсюда недоступно рабочее пространство. Если вы запускаете это из Claude Code или у вас есть проект с прикрепленными файлами, я могу заполнить это поле. Хотите поделиться, где живет эта работа?

Видишь `references/workspace_detection.md` для каталога тактик обнаружения для каждого контекста.

## Раздел 4: Как я могу помочь { #section-4-how-i-can-help }

**Конкретные предложения, а не абстрактные возможности.** В каждом предложении указывается, что будет произведено И куда оно пойдет.

| ✅ Правильный узор | ❌ Анти-паттерн |
|---|---|
| "Я могу исследовать согласованные модели интеграции MCP и предложить вам 3 варианта. Выход: `docs/consensus-options.md`." | "Возможно, вы захотите изучить интеграционные подходы". |
| "Я могу набросать план запуска на третий квартал в виде 1-пейджерного сообщения. Вывод: ответ в чате, затем `docs/q3-launch.md` если вы хотите, чтобы это было зарегистрировано." | "Может быть, стоит подумать о планировании на третий квартал". |
| "Я могу скомпоновать новый модуль аутентификации с существующим шаблоном из `src/users/`. Вывод: 4 файла в `src/auth/`." | "Мы могли бы изучить варианты аутентификации". |

Заканчиваем директивным вопросом:

> ** Чем из этого мне следует заняться?**

## Сжатый шаблон вывода { #compressed-output-pattern }

Если в дампе содержится **5 или меньше элементов** и элементы ** не связаны между собой** (нет естественной кластеризации), отбросьте формат из 4 разделов и используйте сжатый:

```
## What I heard

- {item}
- {item}
- {item}
- ...

## How I can help

- {concrete offer with what + where}
- {concrete offer with what + where}

Which should I tackle?
```

Триггером является `complexity_estimator.py` рекомендация ИЛИ ваше суждение, когда кластеров не существует. Видишь `references/complexity_matching.md` для проработанных примеров того, когда применяется каждый формат.

## Стратегия обнаружения рабочего пространства { #workspace-detection-strategy }

| Контекст | Способ обнаружения |
|---|---|
| Код Клода CLI | Glob для файлов, соответствующих ключевым словам дампа; Grep для совпадений содержимого; чтение структуры верхнего уровня. Использование `scripts/workspace_inventory.py`. |
| Клод.искусственный интеллект с проектом | Проверьте файлы знаний о проекте на предмет совпадения тем. Перечислите заголовки файлов; поверхностные совпадения по ключевому слову. |
| Подключенные инструменты (концепция, привод и т.д.) | Выполните поиск через MCP, если он доступен. |
| Нет доступного рабочего пространства | Укажите ограничение явно; спросите пользователя об их настройках; не выдумывайте. |

## Гейт для утверждения { #approval-gate }

После доставки четырех (или сжатых) секций:

- ** Дождитесь явного выбора пользователя **, прежде чем делать что-либо еще.
- Если пользователь говорит "перейти", не выбирая конкретное предложение: примите его к сведению, но явно отметьте все пункты, в которых вы не были уверены на 100%, чтобы они могли исправить.
- Сама организация - это единственное автоматическое действие. Каждому предложению по разделу 4 требуется зеленый свет.

## Обработка ошибок { #error-handling }

| Ситуация | Поведение |
|---|---|
| Рабочее пространство недоступно | Укажите это; пропустите раздел 3 или укажите "недоступно рабочее пространство" + спросите о настройке |
| Дамп очень короткий (3-5 позиций) | Используйте сжатый вывод; не форсируйте 4 секции |
| Предметы весьма неоднозначны | Отметьте в выходных данных, запросите до 1 уточняющего элемента (или пропустите уточняющий элемент и устраните двусмысленность при доставке) |
| Дамп содержит конфиденциальную информацию | Подтвердите, но не повторяйте дословно, если пользователь запрашивает организацию без кавычек |
| Конфликтующие элементы в дампе | Явно укажите на конфликт в разделе 1 или 3 (`Conflict: X says A, Y says B`) |
| Пользователь говорит "go" перед утверждением | Соблюдайте это, но явно отмечайте пункты, в которых вы не были уверены |

## Оснастка { #tooling }

| Сценарий | Роль |
|---|---|
| `scripts/workspace_inventory.py` | Помощник Glob+Grep для раздела 3. `python workspace_inventory.py --root . --keywords "k1,k2"` возвращает совпадения по ключевому слову + структура папок. |
| `scripts/dump_classifier.py` | Регулярное выражение - классифицирует каждую строку дампа на `task` / `decision` / `question` / `idea` / `project-component`. Эвристический — переопределение с помощью суждения. |
| `scripts/complexity_estimator.py` | Подсчитывает элементы, обнаруживает сигнал кластеризации, рекомендует `format=full` или `format=compressed`. |

## Анти-Паттерны для отклонения { #anti-patterns-to-reject }

- Создание подключений к рабочей области, которые на самом деле не были проверены с помощью Glob/Grep
- Удаление элементов, считающихся "тривиальными" — фиксируйте все, позволяя пользователю обрезать
- Корпоративный-адаптация повседневного языка пользователя
- Принудительное использование структуры из 4 разделов при небольших вводимых данных (для 5 простых задач это не требуется)
- Действовать в соответствии с предложениями раздела 4 немедленно, без одобрения
- Разделяющие решения/questions в отдельную категорию верхнего уровня вместо того, чтобы встраивать их в соответствующий проект
- Неопределенный раздел-4 предложения ("возможно, вы захотите рассмотреть...")
- Заранее задать 3+ уточняющих вопроса (позволяет быстро перейти к действию)
