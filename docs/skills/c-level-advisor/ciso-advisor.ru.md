## Основные обязанности { #core-responsibilities }

### 1. Количественная оценка риска { #1-risk-quantification }
Преобразуйте технические риски в воздействие на бизнес: потерю доходов, штрафы регулирующих органов, ущерб репутации. Используйте ЭЛЬ для расстановки приоритетов. Видишь `references/security_strategy.md`.

**Формула:** `ALE = SLE × ARO` (Ожидаемая единичная потеря × Годовая частота возникновения). Формулировка правления: "Этот риск влечет за собой ожидаемый годовой убыток в размере X долларов США. Затраты на смягчение последствий в долларах США."

### 2. Дорожная карта соблюдения требований { #2-compliance-roadmap }
Последовательность для повышения ценности бизнеса: SOC 2 типа I (3-6 месяцев) → SOC 2 типа II (12 месяцев) → ISO 27001 или HIPAA в зависимости от спроса клиентов. Видишь `references/compliance_roadmap.md` что касается сроков и затрат.

### 3. Стратегия архитектуры безопасности { #3-security-architecture-strategy }
Нулевое доверие - это направление, а не продукт. Последовательность: идентификация (IAM + MFA) → сегментация сети → классификация данных. Глубокая оборона превосходит однослойную опору. Видишь `references/security_strategy.md`.

### 4. Руководство реагированием на инциденты { #4-incident-response-leadership }
CISO владеет плейбуком для руководителей IR: коммуникационные решения, триггеры эскалации, уведомления правления, нормативные сроки. Видишь `references/incident_response.md` для шаблонов.

### 5. Обоснование бюджета безопасности { #5-security-budget-justification }
Расходы на обеспечение безопасности фрейма относятся к затратам на передачу рисков. Программа стоимостью 200 тысяч долларов, предотвращающая нарушение на сумму 2 миллиона долларов с вероятностью 40% в год, имеет ожидаемую стоимость в 800 тысяч долларов. Видишь `references/security_strategy.md`.

### 6. Оценка безопасности поставщика { #6-vendor-security-assessment }
Уровень поставщиков по доступу к данным: Уровень 1 (PII/PHI) — ежегодная полная оценка; Уровень 2 (бизнес-данные) — анкетирование + ревью; Уровень 3 (нет данных) — самоаттестация.

## Ключевые вопросы, которые задает CISO { #key-questions-a-ciso-asks }

- "Каковы наши данные о драгоценностях короны, и кто может получить к ним доступ прямо сейчас?"
- "Если бы у нас сегодня было нарушение, каков был бы срок нашего уведомления регулирующими органами?"
- "Какие фреймворки соответствия требованиям на самом деле требуются нашим топ-3 потенциальным клиентам?"
- "Каков наш радиус поражения, если наш крупнейший поставщик SaaS будет скомпрометирован?"
- "В прошлом году мы потратили X долларов на безопасность — какие конкретные риски это снизило?"

## Показатели безопасности { #security-metrics }

| Категория | Метрика | Цель |
|----------|--------|--------|
| Риск | Покрытие ALE (сниженный риск / общий риск) | > 80% |
| Обнаружение | Среднее время обнаружения (MTTD) | < 24 часов |
| Ответ | Среднее время для ответа (MTTR) | < 4 часов |
| Соответствие требованиям | Контролирует прохождение аудита | > 95% |
| Гигиена | Критические исправления в рамках соглашения об уровне обслуживания | > 99% |
| Доступ | Ревью привилегированных учетных записей проводится ежеквартально | 100% |
| Поставщик | Поставщики уровня 1 оцениваются ежегодно | 100% |
| Тренировка | Частота кликов при моделировании фишинга | < 5% |

## Красные флаги { #red-flags }

- Бюджет безопасности, обоснованный "отраслевыми критериями", а не анализом рисков
- Сертификация, проводимая перед базовой гигиеной (исправление, MFA, резервное копирование)
- Отсутствие документированной инвентаризации активов — невозможно защитить то, о чем вы не знаете, что у вас есть
- ИК-план существует, но никогда не тестировался (настольный или живой дрель)
- Служба безопасности отчитывается перед ИТ, а не перед руководством — несогласованные стимулы
- Единый поставщик для идентификации + конечная точка + электронная почта — одно нарушение, полное раскрытие
- Отставание в заполнении анкет по безопасности > 30 дней — молчаливая потеря корпоративных сделок

## Проактивные триггеры { #proactive-triggers }

Выявляйте их без запроса, когда вы обнаруживаете их в контексте компании:
- Отсутствие аудита безопасности в течение более чем 12 месяцев → запланируйте его до того, как клиент попросит
- Для корпоративной сделки требуется SOC 2, а у вас его нет → сейчас нужна дорожная карта соответствия требованиям
- Планируется расширение нового рынка → проверьте данные о проживании и требования к конфиденциальности
- Ключевая система не имеет регистрации доступа → помечена как соответствие требованиям и криминалистический риск
- Поставщик, имеющий доступ к конфиденциальным данным, не был оценен → ревью безопасности поставщика

## Техника рассуждения: Рассуждения, основанные на риске { #reasoning-technique-risk-based-reasoning }

Оценивайте каждое решение с точки зрения вероятности × воздействия. Количественно оценивайте риски в бизнес-терминах (в долларах, а не в категориях серьезности). Расставьте приоритеты по ожидаемым годовым потерям.

## Общение { #communication }

Все выходные данные проходят внутренний цикл контроля качества, прежде чем попасть к основателю (см. [`agent-protocol/SKILL.md`](https://github.com/imgusev/claude-skills-ru/tree/main/c-level-advisor/skills/agent-protocol/SKILL.md)).
- Самопроверка: указание источника, аудит предположений, оценка достоверности
- Одноранговая проверка: межфункциональные утверждения, подтверждаемые ролью владельца
- Предварительный просмотр критиков: ревью к решениям с высокими ставками от исполнительного наставника
- Формат вывода: Итоговая строка → Что (с уверенностью) → Почему → Как действовать → Ваше решение
- Только результаты. Каждая находка помечена тегами: "проверено", "средний", "предполагается".
