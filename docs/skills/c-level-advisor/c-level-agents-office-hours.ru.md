**Команда:** `/cs:office-hours <topic>`

Прежде чем давать какие-либо советы, основатель должен ответить на шесть вопросов. По образцу рабочего времени YC: никакого анализа, пока основатель не продумает все до конца. Это функция когнитивного принуждения, которая предотвращает скатывание к поиску решений.

## Когда запускать { #when-to-run }

- Прежде чем приступать к какой-либо крупной инициативе
- Перед сбором средств
- Перед стратегическим поворотом
- Когда основатель взволнован (волнение — это тест на давление)
- Когда ответ "очевиден" (очевидный ответ обычно неверен)

## Шесть вопросов { #the-six-questions }

Основатель должен ответить ** на все шесть вопросов ** в письменной форме, прежде чем будет рассмотрена какая-либо C-роль.

### 1. Проблема { #1-problem }
** Чья это проблема и как они описывают ее своими словами?**
- Не твое обрамление. Их слова.
- Если вы не можете процитировать клиента, значит, у вас нет проблемы, которую стоит решать.

### 2. Клиент { #2-customer }
**Кто такой ICP? Назовите хоть одного реального человека, который купил бы это сегодня.**
- Настоящий человек. Настоящая компания. Настоящее сиденье.
- Если вы не можете назвать ни одного из них, значит, ICP не готов.

### 3. Распределение { #3-distribution }
**Как клиент впервые слышит ваше имя?**
- Канал, намерение, поисковый запрос, друг, конференция — назовите это.
- Если ответ таков: "мы разберемся с маркетингом позже", то ответ отрицательный.

### 4. Обороноспособность { #4-defensibility }
**Если это сработает, что помешает конкуренту скопировать это через 6 месяцев?**
- Сетевые эффекты, затраты на переключение, ров с данными, нормативный ров, бренд — выберите один.
- "Мы выполним лучше" - это не оправдание.

### 5. Капитал { #5-capital }
** Сколько это стоит, когда окупается и каково альтернативное использование денег?**
- Общие затраты, месяцы окупаемости, альтернативные издержки.
- Если вы не знаете, не одобряйте это.

### 6. Соответствие основателю { #6-founder-fit }
** Почему вы тот человек, который подходит для этого, и почему это настолько важно, чтобы потратить на это следующие 3 года?**
- Соответствие основателя рынку - самый сильный показатель выживания.
- Если ответ будет корыстным, то и компания будет такой же.

## Выходной формат { #output-format }

После того, как основатель ответит на все шесть вопросов, эта команда подготовит одностраничное резюме:

```markdown
# Office Hours Brief: <topic>
**Date:** YYYY-MM-DD
**Founder:** <name>

## 1. Problem
> [founder's verbatim answer]

## 2. Customer
> [founder's verbatim answer]

## 3. Distribution
> [founder's verbatim answer]

## 4. Defensibility
> [founder's verbatim answer]

## 5. Capital
> [founder's verbatim answer]

## 6. Founder Fit
> [founder's verbatim answer]

---

**Assessment** (one of):
- 🟢 GREEN — ship the brief to /cs:boardroom
- 🟡 YELLOW — sharpen Q[N] before proceeding
- 🔴 RED — kill or redefine; do not proceed
```

## Маршрутизация { #routing }

После того, как бриф станет ЗЕЛЕНЫМ, перейдите к:
- Вопрос для одной роли → соответствующий `/cs:{role}-review`
- Многоцелевой вопрос → `/cs:brief` затем `/cs:boardroom`

## Почему это работает { #why-this-works }

Большинство плохих решений терпят неудачу не при исполнении — они терпят неудачу при формулировании. Навязывание шести конкретных ответов выявляет слабые места фрейминга до того, как кто-либо потратит время на анализ. Основатель либо заполняет пробелы, либо признает, что вопрос не был готов.

Это и есть YC `office hours` шаблон, адаптированный для кода Claude: запрос - это значение.

## Связанные команды { #related-commands }

- `/cs:brief` — превратите ответы в одностраничное стратегическое резюме
- `/cs:boardroom` — обсуждение с участием многих ролей
- `/cs:founder-mode` — позвольте системе выбрать следующий шаг

## Связанные агенты { #related-agents }

- Все советники cs-* используют краткий вывод
- `cs-chief-of-staff` триггеры `/cs:office-hours` когда прием неясен
