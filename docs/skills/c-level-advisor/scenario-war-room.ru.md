Моделируйте каскадные сценарии "что, если" для всех бизнес-функций. Не стресс-тесты на основе одного предположения — сложные неблагоприятные ситуации, которые показывают, как одна проблема порождает следующую.

## Ключевые слова { #keywords }
сценарное планирование, оперативный штаб, анализ "что, если", моделирование рисков, каскадные эффекты, комплексный риск, планирование неблагоприятных ситуаций, планирование на случай непредвиденных обстоятельств, стресс-тест, кризисное планирование, сценарий с несколькими переменными, предсмертный

## Быстрый старт { #quick-start }

```bash
python scripts/scenario_modeler.py   # Interactive scenario builder with cascade modeling
```

Или опишите сценарий на естественном языке:

> "Что, если мы потеряем нашего главного клиента И пропустим сбор средств в третьем квартале?"
> "Что, если 3 инженера уволятся И нам нужно будет отгрузить товар к третьему кварталу?"
> "Что, если наш рынок сократится на 30%, а конкурент привлечет 50 миллионов долларов?"

## Чем Это не является { #what-this-is-not }

- **Не** стресс-тест на основе одного предположения (это `/em:stress-test`)
- ** Не только финансовое моделирование — моделируется каждая функция
- **Не** Модели только для наихудшего случая 3 уровня серьезности
- **Не** парализует анализом — выводит конкретные преграды и триггеры

## Фреймворк: 6-ступенчатая каскадная модель { #framework-6-step-cascade-model }

### Шаг 1: Определите переменные сценария (максимум 3) { #step-1-define-scenario-variables-max-3 }
Укажите каждую переменную с помощью:
- **Какие изменения** — конкретные, по возможности количественные
- **Вероятность** — ваша наилучшая оценка
- ** Временная шкала** — когда это произойдет

```
Variable A: Top customer (28% ARR) gives 60-day termination notice
  Probability: 15% | Timeline: Within 90 days

Variable B: Series A fundraise delayed 6 months beyond target close
  Probability: 25% | Timeline: Q3

Variable C: Lead engineer resigns
  Probability: 20% | Timeline: Unknown
```

### Шаг 2: Сопоставление влияния домена { #step-2-domain-impact-mapping }

Для каждой переменной влияние каждой соответствующей ролевой модели:

| Домен | Владелец | Модели |
|--------|-------|--------|
| Наличные и взлетно-посадочная полоса | Финансовый директор | Воздействие ожога, смена взлетно-посадочной полосы, варианты моста |
| Доход | КРО | Разрыв ARR, риск каскадного оттока, пайплайн |
| Продукт | Генеральный директор | Влияние дорожной карты, риск PMF |
| Инженерное дело | Технический директор | Воздействие на скорость, риск для ключевого лица |
| Люди | ХРО | Каскад сокращений, последствия замораживания найма |
| Операции | ВОРКУЮЩИЙ | Производительность, влияние OKR, технологический риск |
| Безопасность | CISO | Риск соблюдения сроков |
| Рынок | Исполнительный директор | Влияние CAC, конкурентное воздействие |

### Шаг 3: Отображение каскадного эффекта { #step-3-cascade-effect-mapping }

Это и есть суть. Покажите, как переменная A триггерами приводит к последствиям в областях, которые триггерами приводят к последствиям переменной B:

```
TRIGGER: Customer churn ($560K ARR)
  ↓
CFO: Runway drops 14 → 8 months
  ↓
CHRO: Hiring freeze; retention risk increases (morale hit)
  ↓
CTO: 3 open engineering reqs frozen; roadmap slips
  ↓
CPO: Q4 feature launch delayed → customer retention risk
  ↓
CRO: NRR drops; existing accounts see reduced velocity → more churn risk
  ↓
CFO: [Secondary cascade — potential death spiral if not interrupted]
```

Назовите каскад явно. Покажите, где это может быть прервано.

### Шаг 4: Матрица серьезности { #step-4-severity-matrix }

Смоделируйте три сценария:

| Сценарий | Определение | Восстановление |
|----------|------------|---------|
| **Основание** | Одна переменная попадает в цель, другие - нет | Управляемый с помощью плана |
| **Стресс** | Две переменные воздействуют одновременно | Требует значительного реагирования |
| **Тяжелая** | Попадание по всем переменным; полный каскад | Экзистенциальный; требует вмешательства правления |

Для каждого уровня серьезности:
- Влияние взлетно-посадочной полосы 
- Воздействие ARR
- Влияние на численность персонала
- Временная шкала до неприемлемого состояния (точка триггера)

### Шаг 5: Точки триггера (сигналы раннего предупреждения) { #step-5-trigger-points-early-warning-signals }

Определите измеримый сигнал, который сообщает вам о том, что сценарий разворачивается ** до того, как** он будет подтвержден:

```
Trigger for Customer Churn Risk:
  - Sponsor goes dark for >3 weeks
  - Usage drops >25% MoM
  - No Q1 QBR confirmed by Dec 1

Trigger for Fundraise Delay:
  - <3 term sheets after 60 days of process
  - Lead investor requests >30-day extension on DD
  - Competitor raises at lower valuation (market signal)

Trigger for Engineering Attrition:
  - Glassdoor activity from engineering team
  - 2+ referral interview requests from engineers
  - Above-market offer counter-required in last 3 months
```

### Шаг 6: Стратегии хеджирования { #step-6-hedging-strategies }

Для каждого сценария: действия, которые необходимо предпринять ** сейчас** (до того, как сценарий материализуется), чтобы уменьшить воздействие, если оно произойдет.

| Живая изгородь | Стоимость | Воздействие | Владелец | Крайний срок |
|-------|------|--------|-------|---------|
| Открыть кредитную линию на сумму 500 тысяч долларов | 5 тысяч долларов в год | Покупает на 3 месяца, если произойдет отток | Финансовый директор | 60 дней |
| бонус за удержание на 12 месяцев для 3 ключевых инженеров | 90 ТЫСЯЧ долларов | Привлекает команду благодаря сбору средств | ХРО | 30 дней |
| Диверсификация до концентрации выручки на одного клиента менее 20% | Усилия по продажам | Снижает риск для одного клиента | КРО | 2 четверти |
| Сократите сроки сбора средств, запустите параллельный процесс | Время генерального директора | Закрывается перед слиянием взлетно-посадочных полос | ГЕНЕРАЛЬНЫЙ директор | Немедленный |

## Выходной формат { #output-format }

Каждое заседание в военной комнате приводит к:

```
SCENARIO: [Name]
Variables: [A, B, C]
Most likely path: [which combination actually plays out, with probability]

SEVERITY LEVELS
Base (A only): [runway/ARR impact] — recovery: [X actions]
Stress (A+B): [runway/ARR impact] — recovery: [X actions]
Severe (A+B+C): [runway/ARR impact] — existential risk: [yes/no]

CASCADE MAP
[A → domain impact → B trigger → domain impact → end state]

EARLY WARNING SIGNALS
- [Signal 1 → which scenario it indicates]
- [Signal 2 → which scenario it indicates]
- [Signal 3 → which scenario it indicates]

HEDGES (take these actions now)
1. [Action] — cost: $X — impact: [what it buys] — owner: [role] — deadline: [date]
2. [Action] — cost: $X — impact: [what it buys] — owner: [role] — deadline: [date]
3. [Action] — cost: $X — impact: [what it buys] — owner: [role] — deadline: [date]

RECOMMENDED DECISION
[One paragraph. What to do, in what order, and why.]
```

## Правила проведения хороших занятий в военной комнате { #rules-for-good-war-room-sessions }

** Максимум 3 переменные на сценарий.** Больше 3 — это шум - вы не сможете осмысленно подготовиться к коллапсу с 5 переменными. Смоделируйте 3 проблемы, которые вас действительно беспокоят.

** Количественно или оценочно.** "Снижение выручки" бесполезно. "Риск в размере 420 тысяч долларов в год в течение 60 дней" - это. Используйте диапазоны, если вы не уверены.

** Не останавливайтесь на эффектах первого порядка. ** Урон всегда наносится каскадом, а не при первоначальном попадании.

** Восстановление модели, а не только воздействие. ** У каждого сценария должен быть путь "что мы делаем".

** Отделяйте базовый вариант от чувствительности. ** Не смешивайте "то, что вероятно произойдет" с "тем, что могло бы произойти".

** Не переусердствуйте с моделированием.** 3-4 сценария за цикл планирования - это правильное количество. Большее количество создает паралич анализа.

## Общие сценарии по этапам { #common-scenarios-by-stage }

**Семя:**
- Соучредитель уходит + продукт не запускается
- Финансирование заканчивается + неблагоприятные условия перехода

**Серия А:**
- Цель "Мисс АРР" + сбор средств отложен
- Отток ключевых клиентов + рост числа конкурентов

**Серия B:**
- Сокращение рынка + сжигание нескольких пиков
- Ведущий инвестор хочет pivot + команда сопротивляется

## Интеграция с ролями C-Suite { #integration-with-c-suite-roles }

| Тип сценария | Основные роли | Каскадный переход к |
|--------------|---------------|------------|
| Упущенная выручка | Исполнительный директор, финансовый директор | CMO (пайплайн), исполнительный директор (сокращения), CHRO (увольнения) |
| Отъезд ключевого лица | ХРО, ВОРКУЮЩИЙ | Технический директор (если английский), CRO (если отдел продаж) |
| Провал сбора средств | Финансовый директор, генеральный директор | Исполнительный директор (расширение взлетно-посадочной полосы), CHRO (приостановка найма) |
| Нарушение безопасности | CISO, технический директор | Генеральный директор (связь), финансовый директор (затраты), CRO (влияние на клиентов) |
| Рыночный сдвиг | Генеральный директор, CPO | CMO (изменение местоположения), CRO (новые сегменты) |
| Ход конкурента | Исполнительный директор, CRO | Исполнительный директор (ответ на дорожную карту), генеральный директор (стратегия) |
