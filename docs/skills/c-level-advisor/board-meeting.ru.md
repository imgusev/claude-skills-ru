Структурированное обсуждение с участием нескольких агентов, которое предотвращает групповое мышление, учитывает мнения меньшинства и вырабатывает четкие, действенные решения.

## Ключевые слова { #keywords }
заседание совета директоров, исполнительный рассмотрения, стратегическое решение, с-люкс, мульти-агент, /в CS:зал заседаний, основатель ревью, решение добыча, независимую точку зрения

## Вызывать { #invoke }
`/cs:boardroom [topic]` — например. `/cs:boardroom Should we expand to Spain in Q3?`

## 6-Фазный протокол { #the-6-phase-protocol }

### ФАЗА 1: Сбор контекста { #phase-1-context-gathering }
1. Нагрузка `~/.claude/company-context.md`
2. Загружать решения уровня 2, одобренные от `~/.claude/decisions/approved/` ** (ТОЛЬКО уровень 2 — никогда необработанные транскрипты)**
3. Сброс состояния сеанса — нет утечки из предыдущих разговоров
4. Текущая повестка дня + активированные роли → дождаться подтверждения основателя

**Руководитель аппарата выбирает соответствующие роли** в зависимости от темы (не все 14 каждый раз):
| Тема | Активировать |
|-------|----------|
| Расширение рынка | Генеральный директор, CMO, ФИНАНСОВЫЙ директор, CRO, исполнительный директор |
| Направление продукта | Генеральный директор, CPO, технический директор, CMO |
| Найм/организация | Генеральный директор, CHRO, финансовый директор, главный операционный директор (+ вице-президент по найму в Англии) |
| Ценообразование | CMO, ФИНАНСОВЫЙ директор, CRO, CPO-исполнительный директор |
| Технология | Технический директор, CPO, ФИНАНСОВЫЙ директор, CISO |
| Контракты / временные рамки / юридическая информация | Генеральный директор, CEO, ФИНАНСОВЫЙ директор |
| Стратегия обработки данных / обучение - права на данные | CDO, CAIO, GC, CISO |
| Стратегия искусственного интеллекта / выбор модели / риск искусственного интеллекта | Генеральный директор, технический директор, CDO, ФИНАНСОВЫЙ директор |
| Удержание / отток / успех клиентов | Генеральный директор, CRO, CPO |
| Доставка по России / DORA / структура команды | Вице-президент, технический директор, CHRO, ФИНАНСОВЫЙ директор |

---

### ФАЗА 2: Независимые вклады (ИЗОЛИРОВАННЫЕ) { #phase-2-independent-contributions-isolated }

**Отсутствие перекрестного опыления. Каждый агент запускается до того, как увидит выходные данные других.**

Заказ: Исследование (при необходимости) → CMO → CFO → CEO → Технический директор → COO → CHRO → CRO CRO → CISO → CPO → GC → CDO → CAIO → CCO → VPE (только активированные роли)

** Методы рассуждения:** Генеральный директор: Древо мысли (3 варианта будущего) | Финансовый директор: Цепочка размышлений (покажите математику) | Исполнительный директор: Рекурсия мышления (черновик → критика → доработка) | CPO: Основные принципы | CRO: Цепочка размышлений (математика пайплайна) | Исполнительный директор: Шаг за шагом (карта процесса) | Технический директор: Реагируйте (исследуйте→анализируйте→ действуйте) | CISO: Основанный на риске (P×I) | CHRO: Эмпатия + данные | GC: Основанный на риске (подверженность оговорке) | CDO: Основанный на принятии решений (к какому решению приводят эти данные) | CAIO: требует оценки (нет оценки, нет корабля) | Технический директор: Одержим удержанием персонала (GRR превыше NRR) | VPE: Пропускная способность в первую очередь (математика времени цикла)

** Формат вклада (максимум 5 ключевых моментов, самопроверенных):**
```
## [ROLE] — [DATE]

Key points (max 5):
• [Finding] — [VERIFIED/ASSUMED] — 🟢/🟡/🔴
• [Finding] — [VERIFIED/ASSUMED] — 🟢/🟡/🔴

Recommendation: [clear position]
Confidence: High / Medium / Low
Source: [where the data came from]
What would change my mind: [specific condition]
```

Каждый агент проводит самопроверку, прежде чем вносить свой вклад: указание источника, аудит предположений, оценка достоверности. Никаких немаркированных претензий.

---

### ФАЗА 3: Критический анализ { #phase-3-critic-analysis }
Исполнительный наставник получает ВСЕ результаты этапа 2 одновременно. Роль: состязательный рецензент, а не синтезатор.

Чек-лист:
- Где агенты слишком легко соглашались? (подозрительный консенсус = красный флаг)
- Какие предположения являются общими, но непроверенными?
- Кого не хватает в комнате? (голос клиента? операции на передовой?)
- О каком риске никто не упоминал?
- Какой агент действовал за пределами своего домена?

---

### ФАЗА 4: Синтез { #phase-4-synthesis }
Руководитель аппарата выступает с докладом, используя формат **Итогов заседания Правления** (определенный в [`agent-protocol/SKILL.md`](https://github.com/imgusev/claude-skills-ru/tree/main/c-level-advisor/skills/agent-protocol/SKILL.md)):
- Требуется решение (одно предложение)
- Перспективы (по одной строке на каждую участвующую роль)
- Где они согласны / Где они не согласны
- Взгляд критика (неприятная правда)
- Рекомендуемые пункты решения + действия (владельцы, крайние сроки)
- Ваш звонок (варианты, если основатель не согласен)

---

### ФАЗА 5: Человек в цикле ⏸️ { #phase-5-human-in-the-loop- }

** Полная остановка. Дождитесь основателя.**

```
⏸️ FOUNDER REVIEW — [Paste synthesis]

Options: ✅ Approve | ✏️ Modify | ❌ Reject | ❓ Ask follow-up
```

**Правила:**
- Исправления пользователя ПЕРЕОПРЕДЕЛЯЮТ предложения агента. Никакого отпора. Никаких "но финансовый директор сказал..."
- 30-минутное бездействие → автоматическое закрытие как "ожидающий ревью"
- Повторно открывайте в любое время с помощью `/cs:boardroom resume`

---

### ЭТАП 6: Принятие решения { #phase-6-decision-extraction }
После одобрения учредителем:
- **Уровень 1:** Напишите полную расшифровку → `~/.claude/decisions/raw/YYYY-MM-DD-<slug>.md`
- **Уровень 2:** Запись утвержденного решения → `~/.claude/decisions/approved/YYYY-MM-DD-<slug>.md` и добавить к индексу `~/.claude/decisions/approved/decisions.md`
- Отмечать отклоненные предложения `[DO_NOT_RESURFACE]`
- Подтвердите основателю количество зарегистрированных решений, отслеживаемых действий, добавленных флагов

## Структура памяти { #memory-structure }

Использует каноническую двухуровневую память принятия решений (см. [`agent-protocol/SKILL.md`](https://github.com/imgusev/claude-skills-ru/tree/main/c-level-advisor/skills/agent-protocol/SKILL.md) → "Память принятия решений (каноническая компоновка)"):

```
~/.claude/decisions/
├── raw/YYYY-MM-DD-<slug>.md        # Layer 1 — full transcripts (never auto-loaded)
├── raw/archive/YYYY/               # Raw transcripts after 90 days
├── approved/YYYY-MM-DD-<slug>.md   # Layer 2 — founder-approved records (Phase 1 loads these)
└── approved/decisions.md           # Layer 2 index — append-only
```

** Будущие собрания загружают только уровень 2.** Никогда не загружайте уровень 1. Это предотвращает галлюцинируемый консенсус.

Миграция: наследие `memory/board-meetings/` папка может существовать из более ранних версий; прочитайте ее для истории, но запишите новые стенограммы и решения в `~/.claude/decisions/`.

## Краткий справочник по режиму сбоя { #failure-mode-quick-reference }
| Неудача | Исправить |
|---------|-----|
| Групповое мышление (все согласны) | Повторно запустите изолированную фазу 2; приведите "самый сильный аргумент против". |
| Паралич анализа | Ограничение в 5 баллов; принудительная рекомендация даже при низкой достоверности |
| Катание на велосипеде | Войдите в систему как элемент асинхронного действия; вернитесь к основной повестке дня |
| Распределение ролей (финансовый директор, осуществляющий звонки по продуктам) | Флаги критики; исключить из синтеза |
| Загрязнение слоя | Нагрузки фазы 1 `~/.claude/decisions/approved/` единственное — жесткое правило |
