## Основная философия { #core-philosophy }

Запуск - это импульсная система, а не день. Два фреймворка управляют всем (полное описание в references/launch-фреймворки-и-чек-листы.md):

**Модель канала ORB** — сопоставляет каждое действие запуска с одним из трех типов каналов:
- ** Принадлежащий ** — список адресов электронной почты, блог, встроенное приложение. Вы контролируете досягаемость; активируйте сначала.
- **Арендованные** — социальные платформы, сообщества. Алгоритмический охват; вы играете по их правилам.
- **Заимствовано** — партнерская аудитория, информационные бюллетени, подкасты, поиск товаров. Охват других людей; требуется проработать отношения за несколько недель до дня запуска.

План, охватывающий только один тип канала, является неполным — планка качества соответствует всем трем.

** Фазовая модель** — последовательность запуска вместо того, чтобы делать ставки на один день:
1. ** Предварительный запуск** (через 2-6 недель): список ожидания /ранний доступ, привлечение заемных средств, создание активов.
2. **День запуска**: чек-лист с указанием времени, запуск всех каналов, готовность основателя к взаимодействию
3. ** После запуска** (30 дней): контент momentum — страницы сравнения, тематические исследования, рассылка по электронной почте, ретаргетинг

| Инструмент | Призыв | Выход |
|---|---|---|
| Показатель готовности | `python3 scripts/launch_readiness_scorer.py --checklist launch.json` (нет аргумента = встроенная демонстрация; `--export-template` записывает пустой чек-лист; `--json` для пайплайнов) | оценка готовности от 0 до 100 баллов по категориям с указанием самых слабых категорий |

Гейт дату запуска на нее: результат в чек-лист, когда начинается планирование и опять же одна неделя из запуска ниже проходной балл в ", принадлежащего каналы готов" или "готов активов" категории средства смещать даты, не надеясь.

## Вопросы, относящиеся к конкретной задаче { #task-specific-questions }

1. Что вы запускаете? (Новый продукт, основная функция, незначительное обновление)
2. Каков ваш текущий размер аудитории и вовлеченность?
3. Какие собственные каналы у вас есть? (Размер списка рассылки, посещаемость блога, сообщество)
4. Каковы ваши сроки запуска?
5. Вы уже запускали программу раньше? Что сработало/не сработало?
6. Рассматриваете ли вы возможность поиска продукта? Каков статус вашей подготовки?

## Проактивные триггеры { #proactive-triggers }

Активно предлагайте планирование запуска, когда:

1. ** Указана дата отгрузки ** — Когда обсуждается дата технической поставки, немедленно спросите о плане запуска; отгрузка без маркетингового плана - это упущенная возможность.
2. ** Упомянут список ожидания или ранний доступ ** — Предложение разработать полную поэтапную воронку запуска от альфа-версии до полной GA, а не только целевую страницу.
3. ** Рассмотрение поиска продукта ** — Любое упоминание о поиске продукта должно триггером запускать полный раздел стратегии PH, включая график построения отношений перед запуском.
4. ** Молчание после запуска ** - Если пользователь недавно запустил приложение, но не следил за контентом momentum, заранее предложите маркетинговые действия после запуска (страницы сравнения, электронное письмо с обзором, интерактивная демонстрация).
5. **Планируемое изменение цен** — Обновление цен - это возможность для запуска; предложите создать рекламную кампанию, рассматривая ее как обновление продукта.

## Общение { #communication }

Планы запуска должны быть конкретными, привязанными ко времени и конкретному каналу - никаких расплывчатых рекомендаций "публиковать в социальных сетях". В каждом выводе должно быть указано, кто что делает и когда. Ссылка `marketing-context` чтобы убедиться, что описание запуска соответствует языку ICP и позиционированию, прежде чем составлять какой-либо текст. План качества: план запуска считается завершенным только в том случае, если он охватывает все три типа каналов ORB и включает в себя действия как в день запуска, так и после запуска.

## Связанные скиллы { #related-skills }

- **последовательность рассылки по электронной почте** — ИСПОЛЬЗУЕТСЯ для создания последовательности рассылки объявления о запуске и онбординга после запуска; НЕ заменяет стратегию полного канала.
- ** социальный контент ** - ИСПОЛЬЗУЕТСЯ для составления конкретных постов в социальных сетях и тем для дня запуска; НЕ для стратегии выбора канала.
- ** платная реклама** - ИСПОЛЬЗУЕТСЯ, когда план запуска включает платный компонент усиления; НЕ для стратегий, ориентированных только на органический запуск.
- **контент-стратегия** — ИСПОЛЬЗУЙТЕ, когда запуск требует постоянной программы контента (записи в блоге, тематические исследования) в течение нескольких недель после запуска; НЕ для запуска за один день.
- **ценовая стратегия ** — ИСПОЛЬЗУЕТСЯ, когда запуск связан с изменением цен или введением нового уровня; НЕ для запуска только функциональных возможностей.
- **маркетинг-контекст ** — ИСПОЛЬЗУЙТЕ в качестве основы для согласования сообщений о запуске с ICP и brand voice; всегда загружайте первыми.
