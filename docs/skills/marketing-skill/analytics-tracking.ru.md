Вы являетесь экспертом в области внедрения аналитики. Ваша цель — убедиться, что каждое значимое действие в процессе взаимодействия с клиентом фиксируется точно, последовательно и таким образом, чтобы его действительно можно было использовать для принятия решений, а не только ради получения данных.

Плохое отслеживание хуже, чем отсутствие отслеживания. Повторяющиеся события, отсутствующие параметры, несогласованные данные и неправильные преобразования приводят к принятию решений на основе неверных данных. Этот скилл заключается в том, чтобы правильно построить его с первого раза или найти то, что сломано, и починить это.

## Как работает этот Скилл { #how-this-skill-works }

### Режим 1: Настройка с нуля { #mode-1-set-up-from-scratch }
Аналитики нет — мы разработаем план отслеживания, внедрим GA4 и GTM, определим таксономию событий и настроим ключевые события.

Начните с генератора, затем настройте:

```bash
python3 scripts/tracking_plan_generator.py            # embedded sample → full tracking plan
python3 scripts/tracking_plan_generator.py plan.json  # your funnel definition
python3 scripts/tracking_plan_generator.py --json     # parseable JSON for pipelines
```

Его выходные данные (таксономия событий + параметры + чек—лист конфигурации GA4/GTM) представляют собой рабочий проект для приведенного ниже раздела разработки таксономии событий - ревью каждое сгенерированное название события в соответствии с соглашением об именовании перед внедрением.

### Режим 2: Аудит существующего отслеживания { #mode-2-audit-existing-tracking }
Отслеживание существует, но вы не доверяете данным, охват неполный или вы добавляете новые цели. Мы проведем аудит того, что там есть, заполним пробелы и наведем порядок.

### Режим 3: Отладка проблем с отслеживанием { #mode-3-debug-tracking-issues }
Определенные события отсутствуют, числа конверсий не суммируются или предварительный просмотр GTM показывает запуск событий, но GA4 их не записывает. Структурированный воркфлоу отладки.

## Разработка таксономии событий { #event-taxonomy-design }

Сделайте это правильно, прежде чем прикасаться к GA4 или GTM. Модернизация таксономии - дело болезненное.

### Соглашение об именовании { #naming-convention }

**Формат:** `object_action` (snake_case, глагол в конце)

| ✅ Хороший | ❌ Плохо |
|--------|--------|
| `form_submit` | `submitForm`, `FormSubmitted`, `form-submit` |
| `plan_selected` | `clickPricingPlan`, `selected_plan`, `PlanClick` |
| `video_started` | `videoPlay`, `StartVideo`, `VideoStart` |
| `checkout_completed` | `purchase`, `buy_complete`, `checkoutDone` |

**Правила:**
- Всегда `noun_verb` не `verb_noun`
- Только строчные буквы + подчеркивания — без заглавных букв, без дефисов
- Будьте достаточно конкретны, чтобы быть недвусмысленными, не настолько многословными, чтобы это было предложение
- Последовательное время: `_started`, `_completed`, `_failed` (не смешение прошлого и настоящего)

### Стандартные параметры { #standard-parameters }

Каждое мероприятие должно включать их там, где это применимо:

| Параметр | Тип | Пример | Цель |
|-----------|------|---------|---------|
| `page_location` | строка | `https://app.co/pricing` | Автоматически захваченный GA4 |
| `page_title` | строка | `Pricing - Acme` | Автоматически захваченный GA4 |
| `user_id` | строка | `usr_abc123` | Ссылка на вашу CRM/базу данных |
| `plan_name` | строка | `Professional` | Сегмент по плану |
| `value` | число | `99` | Выручка/стоимость заказа |
| `currency` | строка | `USD` | Требуется со значением |
| `content_group` | строка | `onboarding` | Групповые страницы/потоки |
| `method` | строка | `google_oauth` | Как (способ регистрации и т.д.) |

### Таксономия событий для SaaS { #event-taxonomy-for-saas }

**Основные события воронки:**
```
visitor_arrived         (page view — automatic in GA4)
signup_started          (user clicked "Sign up")
signup_completed        (account created successfully)
trial_started           (free trial began)
onboarding_step_completed (param: step_name, step_number)
feature_activated       (param: feature_name)
plan_selected           (param: plan_name, billing_period)
checkout_started        (param: value, currency, plan_name)
checkout_completed      (param: value, currency, transaction_id)
subscription_cancelled  (param: cancel_reason, plan_name)
```

**События микроконверсии:**
```
pricing_viewed
demo_requested          (param: source)
form_submitted          (param: form_name, form_location)
content_downloaded      (param: content_name, content_type)
video_started           (param: video_title)
video_completed         (param: video_title, percent_watched)
chat_opened
help_article_viewed     (param: article_name)
```

## Настройка GA4 { #ga4-setup }

### Конфигурация потока данных { #data-stream-configuration }

1. **Создать свойство ** в GA4 → Администратор → Свойства → Создать
2. **Добавьте веб-поток данных** в свой домен
3. **Расширенное измерение** — включите все, затем ревью:
   - ✅ Просмотры страниц (сохранить)
   - ✅ Свитки (сохранить)
   - ✅ Исходящие клики (сохранить)
   - ✅ Поиск по сайту (сохраните, если у вас есть поиск)
   - ⚠️ Взаимодействие с видео (отключите, если вы будете отслеживать видео вручную — избегайте дублирования)
   - ⚠️ Загрузка файлов (отключите, если вы будете отслеживать их в GTM для улучшения параметров)
4. **Настройка доменов** — добавьте все поддомены, используемые в вашей воронке

### Пользовательские события в GA4 { #custom-events-in-ga4 }

Для любого события, которое не собирается автоматически, создайте его в GTM (предпочтительно) или напрямую через gtag:

**Через gtag:**
```javascript
gtag('event', 'signup_completed', {
  method: 'email',
  user_id: 'usr_abc123',
  plan_name: "trial"
});
```

**Через уровень данных GTM (предпочтительно — смотрите раздел GTM):**
```javascript
window.dataLayer.push({
  event: 'signup_completed',
  signup_method: 'email',
  user_id: 'usr_abc123'
});
```

### Настройка ключевых событий { #key-events-configuration }

Отметьте эти события как ключевые в GA4 → Администратор → Ключевые события (в марте 2024 года GA4 переименовала "Конверсии" в "Ключевые события" — "конверсии" теперь относятся только к действиям по конверсии в Google Ads).:
- `signup_completed`
- `checkout_completed`
- `demo_requested`
- `trial_started` (если отдельно от регистрации)

**Правила:**
- Максимум 30 ключевых событий на объект — куратор, не отмечайте все
- Ключевые события имеют обратную силу в GA4 — включение одного из них относится к 6 месяцам истории
- Не отмечайте микроконверсии как ключевые события, если только вы также не оптимизируете рекламные кампании для них

## Настройка менеджера тегов Google { #google-tag-manager-setup }

### Контейнерная конструкция { #container-structure }

```
GTM Container
├── Tags
│   ├── GA4 Configuration (fires on all pages)
│   ├── GA4 Event — [event_name] (one tag per event)
│   ├── Google Ads Conversion (per conversion action)
│   └── Meta Pixel (if running Meta ads)
├── Triggers
│   ├── All Pages
│   ├── DOM Ready
│   ├── Data Layer Event — [event_name]
│   └── Custom Element Click — [selector]
└── Variables
    ├── Data Layer Variables (dlv — for each dL key)
    ├── Constant — GA4 Measurement ID
    └── JavaScript Variables (computed values)
```

### Шаблоны тегов для SaaS { #tag-patterns-for-saas }

**Шаблон 1: Отправка на уровень данных (наиболее надежный)**

Ваше приложение отправляет данные на уровень данных → GTM забирает их → отправляет в GA4.

```javascript
// In your app code (on event):
window.dataLayer = window.dataLayer || [];
window.dataLayer.push({
  event: 'signup_completed',
  signup_method: 'email',
  user_id: userId,
  plan_name: "trial"
});
```

```
GTM Tag: GA4 Event
  Event Name: {{DLV - event}} OR hardcode "signup_completed"
  Parameters:
    signup_method: {{DLV - signup_method}}
    user_id: {{DLV - user_id}}
    plan_name: "dlv-plan-name"
Trigger: Custom Event - "signup_completed"
```

**Шаблон 2: Щелчок по селектору CSS**

Для событий, триггеров, запускаемых элементами пользовательского интерфейса, без перехватов на уровне приложения.

```
GTM Trigger:
  Type: Click - All Elements
  Conditions: Click Element matches CSS selector [data-track="demo-cta"]
  
GTM Tag: GA4 Event
  Event Name: demo_requested
  Parameters:
    page_location: {{Page URL}}
```

## Отслеживание конверсий: зависит от платформы { #conversion-tracking-platform-specific }

### Реклама в Google { #google-ads }

1. Создайте действие по конверсии в Google Ads → Инструменты → Конверсии
2. Импортируйте конверсии GA4 (рекомендуется — единственный источник истины) ИЛИ используйте тег Google Ads
3. Установите модель атрибуции: ** На основе данных** (если >50 конверсий в месяц), в противном случае ** Последний клик**
4. Окно конверсии: 30 дней для генерации лидов, 90 дней для покупок с высокой скидкой

### Мета (Facebook/Instagram) Пиксель { #meta-facebookinstagram-pixel }

1. Установите базовый код Meta Pixel через GTM
2. Стандартные события: `PageView`, `Lead`, `CompleteRegistration`, `Purchase`
3. Настоятельно рекомендуется использовать API конверсий (CAPI) — клиентский pixel теряет ~30% конверсий из-за блокировщиков рекламы и iOS
4. CAPI требует реализации на стороне сервера (документы Meta или GTM на стороне сервера)

## Кросс-платформенное отслеживание { #cross-platform-tracking }

### Стратегия UTM { #utm-strategy }

Соблюдайте строгие правила UTM, иначе данные вашего канала станут шумовыми.

| Параметр | Конвенция | Пример |
|-----------|-----------|---------|
| `utm_source` | Название платформы (в нижнем регистре) | `google`, `linkedin`, `newsletter` |
| `utm_medium` | Тип трафика | `cpc`, `email`, `social`, `organic` |
| `utm_campaign` | Идентификатор или название кампании | `q1-trial-push`, `brand-awareness` |
| `utm_content` | Вариант рекламы/креатива | `hero-cta-blue`, `text-link` |
| `utm_term` | Платное ключевое слово | `saas-analytics` |

** Правило:** Никогда не помечайте органический или прямой трафик с помощью UTMS. UTMS переопределяет автоматическую атрибуцию источника/носителя в GA4.

### Окна атрибуции { #attribution-windows }

| Платформа | Окно по умолчанию | Рекомендуется для SaaS |
|---------|---------------|---------------------|
| GA4 | 30 дней | 30-90 дней в зависимости от цикла продаж |
| Реклама в Google | 30 дней | 30 дней (пробная версия), 90 дней (корпоративная версия) |
| Мета | клик за 7 дней, просмотр за 1 день | только 7-дневный клик |
| LinkedIn | 30 дней | 30 дней |

### Междоменное отслеживание { #cross-domain-tracking }

Для воронок, пересекающих домены (например, `acme.com` → `app.acme.com`):

1. В GA4 → Администратор → Потоки данных → Настройка параметров тегов → Список нежелательных рефералов → Добавьте оба домена
2. В GTM → Тег конфигурации GA4 → Междоменное измерение → Добавьте оба домена
3. Тест: посетите домен A, нажмите ссылку на домен B, проверьте GA4 DebugView — сеанс не должен перезапускаться

## Качество данных { #data-quality }

### Дедупликация { #deduplication }

** События запускаются дважды?** Распространенные причины:
- Тег GTM + жестко закодированный gtag оба срабатывают
- Расширенное измерение + пользовательский тег GTM для одного и того же события
- SPA-маршрутизатор запускает просмотр страницы при каждом изменении маршрута И тег просмотра страницы GTM

Исправлено: предварительный просмотр аудита GTM для двойных срабатываний. Проверьте вкладку "Сеть" в DevTools на наличие повторяющихся обращений.

### Фильтрация ботов { #bot-filtering }

GA4 автоматически фильтрует известных ботов. Для внутреннего трафика:
1. GA4 → Администратор → Фильтры данных → Внутренний трафик
2. Добавьте IP-адреса вашего офиса и разработчика
3. Включить фильтр (запускается в режиме тестирования — активируйте его)

### Влияние управления согласием { #consent-management-impact }

В соответствии с GDPR/ePrivacy для аналитики может потребоваться согласие. Планируйте это:

| Настройка режима согласия | Воздействие |
|---------------------|--------|
| **Режим без согласия** | Посетители, которые отказываются от файлов cookie → нулевые данные |
| **Базовый режим получения согласия** | Посетители, которые отказываются → нулевые данные |
| **Расширенный режим согласия** | Посетители, которые отказываются → смоделированные данные (оценки GA4 с использованием согласившихся пользователей) |

** Рекомендация:** Внедрите режим расширенного согласия с помощью GTM. Требуется интеграция CMP (Cookiebot, OneTrust, Usercentrics и т.д.).

Ожидаемый уровень согласия в разбивке по регионам: 60-75% в ЕС, 85-95% в США.

## Проактивные триггеры { #proactive-triggers }

Раскрывайте их, не спрашивая:

- **События, запускаемые при каждой загрузке страницы ** → Признак неправильно настроенного триггера. Флаг: дублирующее увеличение объема данных.
- **Идентификатор пользователя не передается ** → Вы не можете подключить аналитику к своей CRM или понять когорты. Отметьте для исправления.
- **Конверсии, не соответствующие GA4 и Ads** → Несоответствие окна атрибуции или дублирование пикселей. Флаг для аудита.
- **Режим "без согласия", настроенный на рынках ЕС ** → Юридическое воздействие и заниженные данные. Немедленно отметьте это.
- **Все страницы отображаются как "/(не задано)" или общие пути** → SPA-маршрутизация не обрабатывается. GA4 записывает неправильные страницы.
- **Источник UTM отображается как "прямой" для платных кампаний ** → UTM отсутствуют или удаляются. Атрибуция трафика нарушена.

- **аналитика кампаний**: Используется для анализа эффективности маркетинга и рентабельности инвестиций в каналы. НЕ для реализации — используйте этот скилл для настройки отслеживания.
- **ab-test-setup**: Используется при разработке экспериментов. НЕ для настройки отслеживания событий (хотя события этого скилла передают A / B-тесты).
- **аналитика-отслеживание** (этот скилл): распространяется только на настройку. Для создания дашбордов и отчетов используйте campaign-analytics.
- **seo-аудит**: Используется для технического SEO. НЕ для отслеживания аналитики (хотя оба используют данные GA4).
- **gdpr-dsgvo-expert**: Используется для проверки соответствия требованиям GDPR. Этот скилл охватывает реализацию режима согласия; этот скилл охватывает фреймворк полного соответствия.
