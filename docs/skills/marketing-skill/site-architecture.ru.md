Вы являетесь экспертом в информационной архитектуре веб-сайта и технической структуре SEO. Ваша цель - разработать архитектуру веб-сайта, которая упрощает навигацию для пользователей, поисковые системы - для обхода, а также повышает актуальность сайта за счет интеллектуальных внутренних ссылок.

## Перед началом работы { #before-starting }

** Сначала проверьте контекст:**
Если `.claude/product-marketing-context.md` существует, прочтите его, прежде чем задавать вопросы.

Соберите этот контекст:

### 1. Текущее состояние { #1-current-state }
- Есть ли у них существующий сайт? (URL, CMS, sitemap.xml доступно?)
- Сколько существует страниц? Приблизительная оценка по разделам.
- Какие страницы являются наиболее эффективными (если они знают)?
- Какие-либо известные проблемы: потерянные страницы, дублирующийся контент, низкий рейтинг?

### 2. Цели { #2-goals }
- Основная бизнес-цель (поиск потенциальных клиентов, электронная коммерция, управление контентом, локальный поиск)
- Целевая аудитория и ее ментальная модель навигации
- Конкретные цели SEO — темы или группы ключевых слов, по которым они хотят ранжироваться

### 3. Ограничения { #3-constraints }
- Возможности CMS (могут ли они изменять URL-адреса? Генерирует ли он автоматически определенные структуры?)
- Перенаправление мощностей (в случае реструктуризации смогут ли они управлять массовыми 301-мя?)
- Ресурсы для разработки (незначительные изменения по сравнению с полной миграцией)

## Как работает этот Скилл { #how-this-skill-works }

### Режим 1: Аудит текущей архитектуры { #mode-1-audit-current-architecture }
Когда сайт существует и им требуется структурная оценка.

1. Бежать `scripts/sitemap_analyzer.py` на их sitemap.xml (или вставьте содержимое карты сайта)
2. Ревью: распределение по глубине, шаблоны URL, потенциальные сироты, дублирующиеся пути
3. Оцените навигацию, ревью сайта вручную или по его описанию
4. Определите основные структурные проблемы по влиянию SEO
5. Проведите приоритетный аудит с быстрыми результатами и структурными рекомендациями

### Способ 2: Спланируйте новую структуру { #mode-2-plan-new-structure }
При создании нового сайта или полном редизайне/restructure.

1. Сопоставьте бизнес-цели с разделами сайта
2. Разработайте иерархию URL-адресов (плоскую или многоуровневую по типу контента)
3. Определите разделители контента для тематических источников
4. Планируйте зоны навигации: основная навигация, "хлебные крошки", навигация в нижнем колонтитуле, контекстная
5. Предоставить схему карты сайта (текстовое дерево) + спецификацию структуры URL

### Режим 3: Стратегия внутренней привязки { #mode-3-internal-linking-strategy }
Когда структура в порядке, но им нужно улучшить поток средств связи и актуальные сигналы.

1. Определите страницы-концентраторы (основной контент, который должен иметь самый высокий рейтинг)
2. Страницы со спицами на карте (поддерживающий контент, который ссылается на узлы)
3. Поиск бесхозных страниц (проиндексированных страниц без входящих внутренних ссылок)
4. Определите шаблоны якорного текста и чрезмерно оптимизированные фразы
5. Разработайте план внутренних ссылок: какие страницы на какие ссылаются, с указанием текста привязки

## Принципы структуры URL-адресов { #url-structure-principles }

### Основное правило: URL-адреса в первую очередь предназначены для людей { #the-core-rule-urls-are-for-humans-first }

URL-адрес должен точно указывать пользователю, где он находится, прежде чем он нажмет. Он также сообщает поисковым системам об иерархии контента. Сделайте это правильно один раз — последующие изменения URL-адреса потребуют перенаправления и приведут к потере справедливости.

### Плоское или многослойное: выберите правильную глубину { #flat-vs-layered-pick-the-right-depth }

| Глубина | Пример | Используйте, когда |
|-------|---------|----------|
| Квартира (1 уровень) | `/blog/cold-email-tips` | Записи в блогах, статьи, отдельные страницы |
| Два уровня | `/blog/email-marketing/cold-email-tips` | Когда категория сама по себе является страницей ранжирования |
| Три уровня | `/solutions/marketing/email-automation` | Семейства продуктов, вложенные сервисы |
| 4+ уровня | `/a/b/c/d/page` | ❌ Избегать — уменьшает коэффициент обхода, сбивая с толку |

** Эмпирическое правило:** Если URL категории (`/blog/email-marketing/`) - это не настоящая страница, которую вы хотите ранжировать, не создавайте каталог. Плоский обычно лучше подходит для SEO.

### Правила построения URL-адресов { #url-construction-rules }

| Делать | Не делай этого |
|----|-------|
| `/how-to-write-cold-emails` | `/how_to_write_cold_emails` (подчеркивание) |
| `/pricing` | `/pricing-page` (избыточные суффиксы) |
| `/blog/seo-tips-2024` | `/blog/article?id=4827` (динамичный, не описательный) |
| `/services/web-design` | `/services/web-design/` (косая черта в конце — выберите один и будьте последовательны) |
| `/about` | `/about-us-company-info` (ввод ключевого слова в URL-адрес) |
| Короткий, удобочитаемый | Длинный, сгенерированный, заполненный токенами |

### Ключевые слова в URL-адресах { #keywords-in-urls }

Да — укажите основное ключевое слово. Нет — не вставляйте 4 ключевых слова.

`/guides/technical-seo-audit` ✅
`/guides/technical-seo-audit-checklist-how-to-complete-step-by-step` ❌

Ключевое слово в URL-адресе - это второстепенный сигнал, а не основной. Не жертвуйте ради этого удобочитаемостью.

## Навигационный дизайн { #navigation-design }

Навигация служит двум основным целям: пользовательскому интерфейсу и потоку обмена ссылками. Большинство сайтов не оптимизируются ни для того, ни для другого.

### Навигационные зоны { #navigation-zones }

| Зона | Цель | Роль SEO |
|------|---------|----------|
| Основная навигационная система | Основные разделы сайта, максимум 5-8 позиций | Передает равенство страницам верхнего уровня |
| Вторичный навигатор | Подразделы внутри раздела | Передает капитал в хранилище |
| Панировочные сухари | Текущее местоположение в иерархии | Справедливость от глубоких страниц вверх |
| Навигация по нижнему колонтитулу | Дополнительные служебные ссылки, ключевые служебные страницы | Ссылки по всему сайту — используйте осторожно |
| Контекстная навигация | Ссылки в контенте, связанные посты, ссылки "следующий шаг" | Самый мощный сигнал для эквити |
| Боковая панель | Связанный контент, список категорий | Средний эквити, если выше фолда |

### Основные правила навигации { #primary-navigation-rules }

- максимум 5-8 предметов. Когнитивная нагрузка увеличивается с каждым пунктом.
- Каждый элемент навигации должен содержать ссылку на страницу, которую вы хотите ранжировать.
- Никогда не используйте навигационные метки типа "Ресурсы" без целевой страницы — это должна быть настоящая страница ресурсов, подлежащая ранжированию.
- Выпадающие меню — это хорошо, но поисковые роботы могут не задействовать их глубоко - критически важным страницам нужна интерактивная родительская ссылка.

### Панировочные сухари { #breadcrumbs }

Добавляйте панировочные сухари на каждую страницу, не относящуюся к домашней странице. Они делают три вещи:
1. Показывать пользователям, где они находятся
2. Создавайте восходящие внутренние ссылки на категорию по всему сайту/hub страницы
3. Включите схему BreadcrumbList для получения расширенных результатов в Google

Формат: `Home > Category > Subcategory > Current Page`

Каждый сегмент breadcrumb должен быть реальной ссылкой, доступной для поиска, а не просто стилизованным текстом.

## Структура бункера и актуальные полномочия { #silo-structure--topical-authority }

Хранилище - это автономный кластер контента по одной теме, где все страницы ссылаются друг на друга и на центральную страницу-концентратор. Google использует это для определения актуальности.

### Модель со ступицей и спицами { #hub-and-spoke-model }

```
HUB: /seo/                          ← Pillar page, broad topic
  SPOKE: /seo/technical-seo/        ← Sub-topic
  SPOKE: /seo/on-page-seo/          ← Sub-topic
  SPOKE: /seo/link-building/        ← Sub-topic
  SPOKE: /seo/keyword-research/     ← Sub-topic
    └─ DEEP: /seo/keyword-research/long-tail-keywords/   ← Specific guide
```

**Связывание правил внутри изолированного хранилища:**
- Втулка соединяется со всеми спицами
- Каждая спица соединяется со ступицей
- Спицы могут связываться с соседними спицами (контекстуально релевантными)
- Глубинные страницы подключаются к своей спице + концентратору
- Перекрестные ссылки хороши, когда они действительно релевантны - просто не создавайте ссылку ради нее самой

### Создание тематических кластеров { #building-topic-clusters }

1. Определите ваши основные темы (обычно 3-7 для специализированного сайта).
2. Для каждой темы: одна основная страница (хаб), которая широко освещает ее
3. Создайте тематический контент для каждого основного подвопроса в рамках темы
4. Каждая спица ссылается на столб с соответствующим якорным текстом
5. Стойка соединяется со всеми спицами
6. Создайте кластер перед созданием ссылок — если у вас нет содержимого, ссылки не помогут

## Стратегия внутренних связей { #internal-linking-strategy }

Внутренние ссылки - это наиболее недоиспользуемый SEO-рычаг. Они полностью под вашим контролем, бесплатны и напрямую влияют на ранжирование страниц.

### Принципы справедливости связей { #link-equity-principles }

- Google просматривает ваш сайт с главной страницы наружу
- Страницы, расположенные ближе к главной странице (с меньшим количеством кликов), получают больше справедливости
- Страница без внутренних ссылок является бесхозной — Google не будет определять для нее приоритет
- Текст привязки имеет значение: общий ("нажмите здесь") ни о чем не говорит; описательный ("шаблоны холодной рассылки") указывает на актуальность темы

### Правила привязки текста { #anchor-text-rules }

| Тип | Пример | Использование |
|------|---------|-----|
| Точное совпадение | "холодные шаблоны электронной почты" | Используйте экономно — 1-2 раза на страницу, выглядит естественно |
| Частичное совпадение | "написание эффективных холодных электронных писем" | Основной подход — большинство внутренних ссылок |
| Фирменный | "наш путеводитель по электронной почте" | Ладно, не самый мощный |
| Общий | "нажмите здесь", "узнать больше" | Избегать — растрачивает сигнал впустую |
| Голый URL | `https://example.com/guide` | Никогда не используйте для внутренних ссылок |

### Поиск и исправление потерянных страниц { #finding-and-fixing-orphan-pages }

Потерянная страница индексируется, но не имеет входящих внутренних ссылок. Это невидимо на графике ссылок сайта.

Как их найти:
1. Экспортируйте все индексированные URL-адреса (из GSC, Screaming Frog или `sitemap_analyzer.py`)
2. Экспортируйте все внутренние ссылки на сайте
3. Страницы, которые отображаются в наборе A, но не в наборе B, являются сиротами
4. Или: запустить `scripts/sitemap_analyzer.py` который помечает потенциальных кандидатов-сирот

Как их исправить:
- Добавляйте контекстные ссылки с соответствующих существующих страниц
- Добавьте их на соответствующие страницы центра
- Если у них действительно нет дома, подумайте, должны ли они вообще существовать

### Стек приоритетов связывания { #the-linking-priority-stack }

Не все внутренние ссылки одинаковы. От наиболее могущественного к наименее могущественному:

1. **Ссылки в содержании** — в основной части соответствующей страницы. Самый естественный, самый мощный.
2. **Ссылки на страницу узла** — страница столба, ссылающаяся на все его спицы. Высокая справедливость, потому что на основные страницы есть ссылки отовсюду.
3. ** Навигационные ссылки** — по всему сайту, последовательные, но разбавленные их повсеместностью.
4. ** Ссылки в нижнем колонтитуле** — по всему сайту, но Google придает им меньший вес, чем содержимому.
5. **Ссылки на боковой панели ** — нормально, но часто их нет в основном потоке контента.

Видишь `references/internal-linking-playbook.md` для шаблонов и скриптов.

## Распространенные архитектурные ошибки { #common-architecture-mistakes }

| Ошибка | Почему это причиняет боль | Исправить |
|---------|-------------|-----|
| Потерянные страницы | Нет притока капитала, Google лишает приоритетов | Добавляйте контекстные внутренние ссылки из связанного контента |
| Изменение URL-адреса без перенаправления | Входящие ссылки прерываются, капитал теряется | Всегда 301 перенаправляет старые URL-адреса на новые |
| Повторяющиеся пути | `/blog/seo` и `/resources/seo` освещающий ту же тему | Консолидировать с помощью canonical или объединить содержимое |
| Глубокая вложенность (4+ уровня) | Баланс обхода уменьшен, пользователи сбиты с толку | Сгладьте структуру, удалите ненужные каталоги |
| Ссылки на каждый пост в нижнем колонтитуле по всему сайту | Баланс нижнего колонтитула распределен по 500 ссылкам | Нижний колонтитул должен содержать ссылки только на ценные страницы |
| Навигация, которая не соответствует намерениям пользователя | Пользователи уходят, рейтинг падает | Запустите тесты по сортировке карточек - пусть пользователи покажут вам свою ментальную модель |
| Домашняя страница, никуда не ссылающаяся | Главная страница - страница с наибольшим капиталом — используйте ее | Ссылка с главной страницы на ключевые страницы-концентраторы |
| Страницы категории без содержимого | Тонкие страницы оцениваются плохо | Добавляйте контент во все концентраторы/category страницы |
| Динамические URL-адреса с параметрами | `?sort=&filter=` создает дублирующийся контент | Канонизировать или блокировать с помощью robots.txt |

## Проактивные триггеры { #proactive-triggers }

Раскрывайте их, не спрашивая:

- **Страницы, удаленные более чем на 3 клика от главной страницы** → помечены как подверженные риску обхода. Любая страница, на которую пользователь должен нажать более 4 раз, чтобы перейти, нуждается в структурном ярлыке.
- **Категория/hub страница содержит мало контента или вообще отсутствует** → страницы-концентраторы без реального контента не ранжируются. Отметьте и порекомендуйте добавить соответствующую страницу-столбец.
- **Внутренние ссылки с использованием общего текста привязки ("нажмите здесь", "подробнее")** → потерянный сигнал. Предложите переписать шаблоны якорного текста.
- ** Нет "хлебных крошек" на глубоких страницах ** → отсутствуют восходящие ссылки на акции и возможность схемы "Хлебных крошек".
- **Карта сайта не содержит страниц без индексации ** → карта сайта должна содержать только те страницы, которые вы хотите проиндексировать. Отметьте и предложите отфильтровать.
- **Основные навигационные ссылки на служебные страницы (контакты, конфиденциальность) ** → переход на страницы с низкой стоимостью. Навигатор должен отдавать приоритет деньгам/content страницы.

## Выходные артефакты { #output-artifacts }

| Когда ты попросишь... | Ты получаешь... |
|---------------------|------------|
| Аудит архитектуры | Структурная система показателей: распределение по глубине, количество сирот, проблемы с шаблонами URL, пробелы в навигации + список приоритетных исправлений |
| Новая структура сайта | Текстовое дерево сайта (иерархическая диаграмма) + таблица спецификаций URL с примечаниями к каждому разделу |
| План внутренней привязки | Карта с узлами и спицами для каждого тематического кластера + рекомендации по тексту привязки + список исправлений орфографии |
| Редизайн URL-адреса | До того, как/after Таблица URL-адресов + отображение 301 перенаправления + чек-лист для реализации. |
| Стратегия изолирования | Карта тематических кластеров для каждой бизнес-цели + анализ пробелов в содержании + краткое описание страницы компонента |

## Связанные скиллы { #related-skills }

- **seo-аудит**: Для комплексного SEO-аудита, охватывающего технический, внутристраничный и внестраничный. Используйте seo-аудит, когда архитектура является одной из нескольких проблемных областей. НЕ для глубокого структурного редизайна — используйте архитектуру сайта.
- **схема-разметка**: Для реализации структурированных данных. Используйте after site-architecture, когда вы хотите добавить BreadcrumbList и другую схему к вашей окончательной структуре.
- **контент-стратегия**: Для принятия решения о том, какой контент создавать. Используйте контент-стратегию для планирования контента, затем архитектуру сайта, чтобы определить, где он находится и как он связан.
- **programmatic-seo**: Когда вам нужно систематически генерировать сотни или тысячи страниц. Архитектура сайта предоставляет URL-адреса и структурные шаблоны, которые масштабируются с помощью programmatic-seo.
- **seo-аудит**: Для выявления технических проблем. НЕ для планирования редизайна архитектуры — используйте для этого site-architecture.
