## Первоначальная оценка { #initial-assessment }

** Сначала проверьте маркетинговый контекст продукта:**
Если `.claude/product-marketing-context.md` существует, прочтите его, прежде чем задавать вопросы. Используйте этот контекст и запрашивайте только информацию, которая еще не охвачена или не относится конкретно к данной задаче.

Прежде чем приступать к аудиту, поймите:

1. **Контекст сайта**
   - Какой тип сайта? (SaaS, электронная коммерция, блог и т.д.)
   - Какова основная бизнес-цель SEO?
   - Какие ключевые слова/темы являются приоритетными?

2. **Текущее состояние**
   - Какие-либо известные проблемы или озабоченности?
   - Текущий уровень органического трафика?
   - Недавние изменения или миграции?

3. **Сфера применения**
   - Полный аудит сайта или отдельных страниц?
   - Техническая информация + информация на странице или одна область внимания?
   - Доступ к поисковой консоли / аналитике?

## Фреймворк для аудита { #audit-framework }

Аудит проводится на трех уровнях — техническом (сканирование/индексация/скорость), внутристраничном (заголовки, подзаголовки, внутренние ссылки, таргетинг по ключевым словам), содержательном (соответствие намерениям, E-E-A-T, тонкие/дублирующиеся страницы). Полный фреймворк: ссылки/seo-аудит-reference.md.

**Пороговые значения для основных веб-показателей пройдены/не пройдены** (75-й процентиль данных реального пользователя; полная сортировка в references/cwv-thresholds.md):

| Метрика | Хороший | Нуждается в улучшении | Бедный |
|---|---|---|---|
| LCP (самая насыщенная краска) | ≤ 2,5с | 2,5-4,0с | > 4,0с |
| INP (Взаимодействие со следующей краской) | ≤ 200 мс | 200-500мс | > 500 мс |
| CLS (Кумулятивный сдвиг макета) | ≤ 0.1 | 0.1-0.25 | > 0.25 |

## Инструменты { #tools }

| Инструмент | Призыв | Выход |
|---|---|---|
| Средство проверки на странице | `python3 scripts/seo_checker.py --file page.html` (или `--url https://...`; `--json`) | Оценка одной страницы 0-100: заголовок/мета/заголовки/ссылки/изображения |
| Показатель здоровья | `python3 scripts/seo_health_scorer.py --checks checks.json --industry saas` (никаких аргументов = `--demo`; отрасли: saas/электронная коммерция/местные/издательские; `--json`) | Взвешенный показатель работоспособности сайта от 0 до 100 по 7 категориям |

Бежать `seo_checker.py` на ключевых шаблонах/страницах во время внутристраничного слоя и `seo_health_scorer.py` на заполненной контрольной матрице для получения итоговой оценки аудита.

## Выходной формат { #output-format }

### Структура отчета по аудиту { #audit-report-structure }

**Краткое изложение**
- Общая оценка состояния здоровья — руководить с помощью `seo_health_scorer.py` оценка и ее самые слабые категории
- Основные 3-5 приоритетных вопросов
- Выявлены быстрые выигрыши

**Технические результаты SEO**
По каждому вопросу:
- **Проблема**: Что не так
- **Влияние**: Влияние на SEO (высокое/среднее/низкое)
- **Улика**: Как вы ее нашли
- **Исправление**: Конкретная рекомендация
- **Приоритет**: 1-5 или высокий/средний/низкий

**Результаты поисковой оптимизации на странице**
Тот же формат, что и выше

**Выводы по содержанию**
Тот же формат, что и выше

**Приоритетный план действий**
1. Критические исправления (блокирование индексации/ранжирования)
2. Высокоэффективные улучшения
3. Быстрые выигрыши (легкая, немедленная выгода)
4. Долгосрочные рекомендации

## Связанные скиллы { #related-skills }

- **programmatic-seo** — КОГДА: пользователь хочет масштабировать SEO-страницы после того, как аудит выявит пробелы в ключевых словах. ЕСЛИ НЕТ: не используйте для диагностики существующих проблем; оставайтесь в режиме seo-аудита.
- **aeo** — КОГДА: пользователь хочет выполнить оптимизацию для поисковых систем с искусственным интеллектом (SGE, Perplexity, ChatGPT) в дополнение к традиционному поиску. КОГДА НЕТ: не используйте для чисто технических проблем с обходом / индексацией.
- **разметка схемы** - КОГДА: аудит выявляет недостающие возможности для структурированных данных (часто задаваемые вопросы, инструкции, продукт, схемы ревью). КОГДА НЕТ: не используйте в качестве самостоятельного исправления, если нарушено основное техническое SEO.
- **архитектура сайта** — КОГДА: аудит выявляет плохие внутренние ссылки, потерянные страницы или проблемы с глубиной обхода, требующие структурной перестройки. КОГДА НЕТ: не привлекайте, если область аудита ограничена проблемами на странице или контентом.
- **контент-стратегия** — КОГДА: аудит выявляет скудный контент, пробелы в ключевых словах или отсутствие тематической значимости, требующей контент-плана. КОГДА НЕТ: не используйте, если проблема чисто техническая (robots.txt , перенаправления, скорость).
- **маркетинг-контекст** — КОГДА: всегда читайте сначала, если `.claude/product-marketing-context.md` существует для того, чтобы избежать лишних вопросов. ЕСЛИ НЕТ: пропустить, если контекстный файл не существует и пользователь предоставил всю необходимую информацию о продукте напрямую.

## Общение { #communication }

Все результаты аудита соответствуют стандарту качества SEO-аудита ****:
- Ведущий с кратким изложением (максимум 3-5 абзацев)
- Выводы последовательно используйте формат проблемы / воздействия / фактических данных / исправления / приоритета
- Приоритетный план действий - это всегда раздел, посвященный конечным результатам
- Избегайте жаргонных выражений без объяснения причин; пишите для технически осведомленного читателя, но не специалиста по SEO
- Быстрые победы указываются явно и хранятся отдельно от рекомендаций, требующих больших усилий
- Никогда не представляйте рекомендаций без доказательств или обоснования

## Проактивные триггеры { #proactive-triggers }

Автоматически отображать рекомендации по seo-аудиту, когда:

1. ** Упомянуто снижение трафика ** — Пользователь говорит, что органический трафик снизился или рейтинг упал; немедленно определите область аудита.
2. **Миграция или редизайн сайта** — Пользователь упоминает о запланированном или недавнем изменении URL, переключении платформы или редизайне; отметьте необходимость проведения аудита до/после миграции.
3. ** "Почему моя страница не ранжируется?"** — Любое нарушение рейтинга триггером является чек-лист на странице + намерение перед внешними факторами.
4. ** Обсуждение контент—стратегии ** - Когда активен скилл по контент-стратегии и появляются пробелы в ключевых словах, заранее предложите провести SEO-аудит, чтобы подтвердить возможность.
5. **Запуск нового сайта или продукта** — Пользователь готовится к запуску; заранее порекомендуйте технический чек-лист для SEO перед запуском из фреймворка аудита.
