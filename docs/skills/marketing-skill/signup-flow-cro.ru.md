## Первоначальная оценка { #initial-assessment }

** Сначала проверьте маркетинговый контекст продукта:**
Если `.claude/product-marketing-context.md` существует, прочтите его, прежде чем задавать вопросы. Используйте этот контекст и запрашивайте только информацию, которая еще не охвачена или не относится конкретно к данной задаче.

Прежде чем давать рекомендации, разберитесь:

1. **Тип потока**
   - Бесплатная пробная регистрация
   - Создание учетной записи Freemium
   - Создание платной учетной записи
   - Список ожидания/early регистрация доступа
   - B2B против B2C

2. **Текущее состояние**
   - Сколько шагов/screens?
   - Какие поля обязательны для заполнения?
   - Каков текущий уровень завершения работ?
   - Куда уходят пользователи?

3. **Ограничения для бизнеса**
   - Какие данные действительно необходимы при регистрации?
   - Существуют ли требования к соответствию требованиям?
   - Что происходит сразу после регистрации?

## Выходной формат { #output-format }

### Выводы аудита { #audit-findings }
Для каждой найденной проблемы:
- **Проблема**: Что не так

### Рекомендуемые изменения { #recommended-changes }

1. Быстрые победы (исправления в тот же день)
2. Изменения с высокой отдачей (усилия на недельном уровне)
3. Тестовые гипотезы (вещи для A/B-тестирования)

## Общие схемы прохождения регистрации { #common-signup-flow-patterns }

### Пробная версия B2B SaaS { #b2b-saas-trial }
1. Электронная почта + пароль (или авторизация Google)
2. Название + компания (необязательно: роль)
3. → Поток онбординга

### Приложение B2C { #b2c-app }
1. Авторизация Google/Apple ИЛИ электронная почта
2. → Опыт работы с продуктом
3. Заполнение профиля позже

### Список ожидания/Ранний доступ { #waitlistearly-access }
1. Только по электронной почте
2. Необязательно: Роль/use вопрос по делу
3. → Подтверждение списка ожидания

### Учетная запись электронной коммерции { #e-commerce-account }
1. Гостевой выезд по умолчанию
2. Необязательное создание учетной записи после покупки
3. ИЛИ авторизация в социальной сети одним щелчком мыши

## Идеи для экспериментов { #experiment-ideas }

### Эксперименты по проектированию форм { #form-design-experiments }

**Планировка и структура**
- Одноэтапный или многоступенчатый процесс регистрации
- Многоступенчатый режим с индикатором выполнения по сравнению с без него
- расположение полей в 1 столбец по сравнению с расположением полей в 2 столбца
- Форма, встроенная на страницу, по сравнению с отдельной страницей регистрации
- Выравнивание поля по горизонтали и вертикали

**Оптимизация полевых работ**
- Сократите количество полей до минимума (только адрес электронной почты + пароль)
- Добавление или удаление поля с номером телефона
- Единственное поле "Имя" по сравнению с Разделение "Первый/последний"
- Добавление или удаление компании/organization поле
- Требуемый тест и необязательный баланс полей

**Параметры аутентификации**
- Добавить параметры единого входа (Google, Microsoft, GitHub, LinkedIn)
- Выделенный SSO по сравнению с выделенной формой электронной почты
- Проверьте, какие параметры единого входа находят отклик (зависит от аудитории)
- Только для единого входа по сравнению с Единый вход + опция электронной почты

**Визуальный дизайн**
- Протестируйте цвета и размеры кнопок на предмет заметности CTA
- Простой фон в сравнении с визуальными эффектами, связанными с продуктом
- Оформление контейнера тестовой формы (карточный или минимальный)
- Тестирование макета, оптимизированного для мобильных устройств

### Эксперименты с копированием и передачей сообщений { #copy--messaging-experiments }

**Заголовки и CTA**
- Протестируйте варианты заголовков над формой регистрации
- Текст кнопки CTA: "Создать учетную запись" или "Начать бесплатную пробную версию" или "Приступить к работе".
- Внесите ясность в продолжительность судебного разбирательства в CTA
- Акцент на тестовом ценностном предложении в заголовке формы

**Микроскопия**
- Метки полей: минимальные или описательные
- Оптимизация текста-заполнителя
- Четкость и тональность сообщения об ошибке
- Отображение требования к паролю (заранее или при ошибке)

**Элементы доверия**
- Добавьте социальное подтверждение рядом с формой регистрации
- Проверьте значки доверия рядом с формой (безопасность, соответствие требованиям)
- Добавьте сообщение "Кредитная карта не требуется".
- Включите копию гарантии конфиденциальности

### Пробные эксперименты и обязательства { #trial--commitment-experiments }

** Бесплатные пробные версии**
- Требуется кредитная карта или не требуется для пробной версии
- Влияние продолжительности тестирования (7 против 14 против 30 дней)
- Freemium против бесплатной пробной модели
- Пробная версия с ограниченными возможностями по сравнению с полным доступом

**Точки трения**
- Требуется подтверждение электронной почты, а не отложено или удалено
- Влияние тестовой капчи на завершение
- Флажок "Принятие условий" в отличие от неявного принятия
- Проверка телефона для дорогостоящих аккаунтов

### Эксперименты после отправки { #post-submit-experiments }

- Персонализированное приветственное сообщение, основанное на данных регистрации

## Связанные скиллы { #related-skills }

- **онбординг-cro** — КОГДА: сам процесс регистрации завершается успешно, но пользователи не активируются и не достигают своего "ага-момента" после создания учетной записи. КОГДА НЕТ: не переходите к онбордингу-cro, когда пользователи уходят во время самой формы регистрации.
- **форма-cro** — КОГДА: оптимизируемая форма НЕ предназначена для создания учетной записи — вместо форм для поиска потенциальных клиентов, контактов, демонстрационных запросов или опросов требуется форма-cro. ЕСЛИ НЕТ: не используйте form-cro для регистрации/account потоки создания; signup-flow-cro имеет правильный фреймворк для шаблонов аутентификации (SSO, волшебная ссылка, электронная почта + пароль).
- ** page-cro** — КОГДА: целевая страница или маркетинговая страница, ведущая к регистрации, является узким местом — плохой заголовок, слабая ценностная поддержка или несоответствие сообщения. КОГДА НЕТ: не вызывайте page-cro, когда пользователи переходят к форме регистрации, но заходят в нее.
- **ab-test-настройка** — КОГДА: гипотезы из аудита регистрации готовы к тестированию (SSO или электронная почта, одноэтапный или многоступенчатый, требуется кредитная карта или нет). ЕСЛИ НЕТ: не запускайте A/B-тесты в процессе регистрации перед внедрением инструментальной аналитики на уровне полей.
- ** paywall-обновление-cro ** — КОГДА: процесс регистрации - это freemium, и реальная проблема заключается в преобразовании бесплатных пользователей в платных, а не в том, чтобы заставить их зарегистрироваться. КОГДА НЕТ: не смешивайте конверсию пробной версии в платную с оптимизацией потока регистрации.
- **маркетинг-контекст** — КОГДА: проверьте `.claude/product-marketing-context.md` для B2B по сравнению с Контекст B2C, требования соответствия и потребности в квалификационных данных перед разработкой набора полей. ЕСЛИ НЕТ: пропустить, если пользователь предоставил явный контекст продукта и соответствия в разговоре.

## Общение { #communication }

Все выходные данные CRO потока регистрации соответствуют этому стандарту качества:
- Рекомендации всегда организованы следующим образом: ** Быстрые победы → Высокоэффективные → Тестовые гипотезы ** - никогда не бывает плоского списка
- Каждая рекомендация по удалению полей обосновывается вопросом "нужно ли нам это, прежде чем они смогут использовать продукт?". тест
- Параметры единого входа всегда рассматриваются и рекомендуются, когда это уместно — не используйте по умолчанию потоки только для электронной почты
- Опыт после отправки (проверка, состояние успеха, следующие шаги) всегда учитывается — это часть процесса
- Мобильная оптимизация рассматривается как отдельный раздел, а не как запоздалая мысль
- Идеи для экспериментов различают "исправить это" (очевидное) и "протестировать это" (неопределенное) — никогда не рекомендуется тестировать очевидные улучшения

## Проактивные триггеры { #proactive-triggers }

Автоматически всплывающая регистрация-flow-cro, когда:

1. ** "Пользователи регистрируются, но не активируются"** — Низкий уровень активации часто связан с трудностями при регистрации или сбоями в работе после отправки; предварительно проведите аудит полного пути от регистрации до активации.
2. ** "У нас низкая конверсия пробной версии"** — Если соотношение пробной версии к платной низкое, проверьте, не задает ли поток регистрации неправильных ожиданий или не собирает неправильных пользователей.
3. **Бесплатная пробная версия или разрабатываемый продукт freemium ** — При обнаружении продукта или инженерных работ над новым потоком пробной версии заранее предложите ревью для регистрации в потоке cro перед запуском.
4. ** "Должны ли мы требовать кредитную карту?"** — этот вопрос всегда триггером для полного анализа разногласий при регистрации и фреймворка для проведения эксперимента по обязательному тестированию.
5. ** Высокий уровень мобильности при регистрации ** — Когда аналитика или page-cro выявляют пробел в мобильной связи конкретно на странице регистрации, немедленно используйте чек-лист оптимизации мобильной регистрации.
