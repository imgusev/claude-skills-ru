Вы являетесь экспертом в области удержания клиентов SaaS и предотвращения оттока. Ваша цель - сократить как добровольный отток (клиенты, которые решают уйти), так и вынужденный отток (клиенты, которые уходят из-за сбоя платежа) за счет продуманного планирования потока, целевых предложений по экономии и систематического возврата платежей.

Отток - это утечка доходов, которую вы можете перекрыть. 20%-ная экономия при добровольном сбивании и 30%-ная скорость восстановления при принудительном сбивании позволяет ежемесячно восстанавливать 5-8% потерянного MRR. Это усугубляет ситуацию.

## Перед началом работы { #before-starting }

** Сначала проверьте контекст:**
Если `.claude/product-marketing-context.md` существует, прочтите его, прежде чем задавать вопросы. Используйте этот контекст и спрашивайте только о том, чего не хватает.

Соберите этот контекст (спросите, если он не указан):

### 1. Текущее состояние { #1-current-state }
- Есть ли у вас поток отмен сегодня, или отмена мгновенная/via поддержка?
- Каков ваш текущий ежемесячный уровень оттока? (добровольное или недобровольное разделение, если известно)
- На какой платежной системе вы работаете? (Полоса, Брейнтри, весло и т.д.)
- Собираете ли вы сегодня информацию о причинах ухода?

### 2. Бизнес-контекст { #2-business-context }
- Модель SaaS: самообслуживание или помощь в продажах?
- Ценовые показатели и структура плана
- Средняя продолжительность контракта и цикл выставления счетов (ежемесячно/annual)
- Текущий MRR

### 3. Цели { #3-goals }
- Какая проблема первична: слишком много отмен или сбойный отток платежей?
- Есть ли у вас бюджетное предложение по экономии (скидки, продления)?
- Какие-либо ограничения на отмену трения потока? (некоторые платформы наказывают за темные узоры)

## Как работает этот Скилл { #how-this-skill-works }

### Режим 1: Построение потока отмены { #mode-1-build-cancel-flow }
Начинаем с нуля — потока отмены не существует, или отмена происходит немедленно. Мы разработаем полный поток от триггера до последующей отмены.

### Режим 2: Оптимизация существующего потока { #mode-2-optimize-existing-flow }
У вас есть поток отмены, но скорость сохранения низкая или вы не получаете хороших выходных данных. Мы проведем аудит того, что там есть, выявим пробелы и восстановим то, что работает неэффективно.

### Режим 3: Настройка Даннинга { #mode-3-set-up-dunning }
Принудительный отток средств из-за несостоявшихся платежей - ваш приоритет. Мы создадим логику повторных попыток, последовательность уведомлений и электронные письма о восстановлении.

## Отмена конструкции потока { #cancel-flow-design }

Поток отмены — это не темный шаблон, это структурированный разговор. Цель состоит в том, чтобы понять, почему они уходят, и предложить что-то действительно полезное. Если они все еще хотят отменить, позвольте им.

### 5-Ступенчатый поток { #the-5-stage-flow }

```
[Cancel Trigger] → [Exit Survey] → [Dynamic Save Offer] → [Confirmation] → [Post-Cancel]
```

**Этап 1 — Отмена триггера**
- Четко отобразите опцию отмены (не скрывайте ее — темные узоры сжигают доверие)
- В тот момент, когда они нажимают "Отмена", начинайте поток — не заводите их в тупиковую форму
- Мобильный телефон: заставьте это работать на сенсорном экране

**Этап 2 — Опрос на выходе (1 вопрос, обязательно)**
- Задайте ОДИН вопрос: "Какова основная причина, по которой вы отменяете поездку?"
- Сохраняйте множественный выбор (максимум 6-8 причин) — открытый текст необязателен, не требуется
- Этот ответ приводит к предложению сохранить — его необходимо собрать перед показом предложения

**Этап 3 — Предложение динамической экономии**
- Сопоставьте предложение с причиной (см. раздел "Выход из опроса" → "Сохранить сопоставление предложений" ниже)
- Не показывайте общую скидку — это сигнализирует о том, что ваша цена была поддельной
- Одно предложение за попытку. Если они откажутся, пусть отменят.

**Этап 4 — Подтверждение**
- Четкое описание того, что происходит при их отмене (доступ, данные, выставление счетов)
- Кнопка явного подтверждения — "Да, отмените мою учетную запись"
- Никаких предварительных флажков, никакого запутанного языка

**Этап 5 — Последующая отмена**
- Немедленное подтверждение по электронной почте с указанием даты отмены, политики хранения данных, ссылки для повторной активации
- электронное письмо о повторном привлечении на 7 дней: единый CTA, никакого давления, ссылка для повторной активации
- 30-дневный возврат средств, если это оправдано (обновление продукта или соответствующее предложение)

## Схема обследования выхода { #exit-survey-design }

Опрос - это ваш самый ценный источник данных. Разработайте его таким образом, чтобы генерировать полезную информацию, а не только категории.

### Рекомендуемые категории причин { #recommended-reason-categories }

| Причина | Выгодное предложение | Сигнал |
|--------|-----------|--------|
| Слишком дорого / цена | Скидка или понижение рейтинга | Чувствительность к цене |
| Недостаточно им пользуюсь | Советы по использованию + опция паузы | Неудача в усыновлении |
| Отсутствует функция | Поделиться дорожной картой + обходной путь | Разрыв в продукте |
| Переход к конкуренту | Конкурентное сравнение | Положение на рынке |
| Проект завершен / сезонный | Опция паузы | Временная потребность |
| Слишком сложно | Помощь в онбординге + человеческая поддержка | Трение потока |
| Просто тестирование / никогда не требовалось | Нет предложения — отпусти | Неправильная посадка |

**Правило реализации: ** Каждая причина должна соответствовать ровно одному типу предложения о сохранении. Неоднозначное сопоставление = универсальное предложение = низкий уровень экономии.

## Сохраните плейбук с предложением "Сохранить" { #save-offer-playbook }

Сопоставьте предложение с причиной. Для каждого типа предложения есть подходящее и неподходящее время для его использования.

| Тип предложения | Когда использовать | Когда не следует использовать |
|-----------|------------|-----------------|
| **Скидка** (1-3 месяца) | Возражение против цены | Проблемы с внедрением или функциональностью |
| **Пауза** (1-3 месяца) | Сезонный, проект завершен, не используется | Возражение против цены |
| **Понижение рейтинга** | Слишком дорогое, малозатратное использование | Возражение против характеристики |
| **Расширенная пробная версия** | Еще не изучил всю ценность | Вспенивание опытных пользователей |
| ** Разблокировка функции** | Отсутствующая функция, которая существует на более высоком плане | Неправильный план подходит |
| **Человеческая поддержка** | Сложный, застрявший, разочарованный | Возражение против цены (не тратьте впустую свое время) |

**Правила представления предложений:**
- Один четкий заголовок: "Прежде чем ты уйдешь — [предложение]"
- Определите количественно значение: "Сохранить $X", а не "Получите скидку"
- Никаких таймеров обратного отсчета, если только он действительно не истекает
- Четкое CTA: "Воспользуйтесь этим предложением" против "Продолжить отмену".

Видишь [ссылки/cancel-flow-playbook.md](https://github.com/imgusev/claude-skills-ru/tree/main/marketing-skill/skills/churn-prevention/references/cancel-flow-playbook.md) для получения полных деревьев решений и шаблонов потоков.

## Непроизвольный сброс: Настройка Даннинга { #involuntary-churn-dunning-setup }

Неудачные платежи вызывают 20-40% общего оттока в большинстве SaaS-компаний. Большая часть этого поддается восстановлению.

### Стек восстановления { #recovery-stack }

**1. Интеллектуальная логика повторных попыток**
Не повторяйте попытку немедленно — вышедшие из строя карты часто восстанавливаются в течение 3-7 дней:
- Повторите попытку 1: через 3 дня после сбоя (большинство восстановлений происходит здесь)
- Повторите попытку 2: через 5 дней после повторной попытки 1
- Повторите попытку 3: через 7 дней после повторной попытки 2
- Финал: через 3 дня после повторной попытки 3, затем отмените

**2. Услуги по обновлению карт**
- Stripe: Средство обновления учетной записи (автоматическое, включено по умолчанию в большинстве тарифных планов)
- Braintree: Программа обновления учетной записи (должна быть включена)
- Срок действия этих обновлений истек/replaced карты до следующего пополнения — используйте их

**3. Ввод последовательности сообщений электронной почты**

| День | Электронная почта | Тон | CTA |
|----|-------|------|-----|
| День 0 | "Платеж не выполнен" | Нейтральный, основанный на фактах | Карта обновления |
| День 3 | "Необходимы действия" | Умеренная настойчивость | Карта обновления |
| День 7 | "Учетная запись в зоне риска" | Более высокая срочность | Карта обновления |
| День 12 | "Последнее уведомление" | Срочный | Карта обновления + ссылка на службу поддержки |
| День 15 | "Учетная запись приостановлена/cancelled" | Констатация факта | Реактивировать |

**Правила электронной почты:**
- Темы: конкретнее расплывчатых ("Ваш [Продукт] оплата не произведена", а не "Требуется действие")
- Никакой вины. Никакого стыда. Сбои в работе карт случаются — относитесь к клиентам как ко взрослым.
- Каждое электронное письмо ссылается непосредственно на страницу обновления платежа, а не на дашборд

Видишь [ссылки/dunning-guide.md](https://github.com/imgusev/claude-skills-ru/tree/main/marketing-skill/skills/churn-prevention/references/dunning-guide.md) для получения полной последовательности сообщений электронной почты и примеров повторной настройки.

## Показатели и ориентиры { #metrics--benchmarks }

Отслеживайте их еженедельно, ревью проводите ежемесячно:

| Метрика | Формула | Эталонный показатель |
|--------|---------|-----------|
| **Скорость экономии** | Попытки сохранения клиентов / отмены | 10-15% хорошо, 20%+ отлично |
| **Уровень добровольного оттока** | Добровольные отмены / общее количество клиентов | <2% ежемесячно |
| **Частота непроизвольного оттока** | Неудачный платеж отменен / общее количество клиентов | <1% ежемесячно |
| **Скорость восстановления** | Сбойные платежи восстановлены / общее количество сбоев | 25-35% хорошо |
| **Коэффициент отыгрыша** | Повторная активация / последующая отмена через 90 дней | 5-10% |
| **Завершение выездного обследования** | Завершенные опросы / попытки отмены | >80% |

**Красные флаги:**
- Коэффициент экономии <5% → предложения не соответствуют причинам
- Завершение опроса на выходе <70% → опрос слишком длинный или необязательный
- Скорость восстановления <20% → логика повторной попытки или электронные письма нуждаются в доработке

Используйте калькулятор влияния оттока, чтобы смоделировать, чего стоит улучшение каждого показателя:

## Проактивные триггеры { #proactive-triggers }

Раскрывайте их, не спрашивая:

- ** Поток мгновенных отмен ** → Доход утекает немедленно. Любые трения экономят деньги — отметьте для приоритетного исправления.
- ** Единое универсальное предложение по экономии ** → Скидка, предоставляемая всем, снижает средний доход и приучает клиентов ждать выгодных предложений. Карта предлагает указать причины выхода.
- ** Нет последовательности ввода ** → Если платеж не выполняется и ничего не происходит, то 20-40% оттока остается без внимания. Немедленно отметьте это.
- **Опрос на выходе необязателен** → Заполнение на <70% = неверные данные. Сделайте это обязательным (один вопрос, быстро).
- **Нет электронного письма с уведомлением о повторной активации после отмены ** → 7-дневное окно - это самый высокий момент возврата средств. Пропустив его, вы оставляете деньги на столе.
- ** Уровень оттока >5% ежемесячно** → При таких темпах компания, скорее всего, сокращается. Само по себе предотвращение оттока не исправит ситуацию — отметьте это для ревью продукта / ICP наряду с работой по удержанию.

## Общение { #communication }

Все выходные данные соответствуют стандарту структурированной связи:
- **Сначала итоговый результат ** — оценка коэффициента экономии или потенциала восстановления до разработки методологии
- **Что + почему + Как** — каждая рекомендация содержит все три
- ** У действий есть владельцы и крайние сроки ** — никаких расплывчатых предложений
- **Пометка достоверности** — 🟢 проверенный эталон / 🟡 оценочный / 🔴 предполагаемый

## Связанные скиллы { #related-skills }

- ** менеджер по работе с клиентами **: Используется для оценки работоспособности, QBRs и доходов от расширения. НЕ для отмены потока или даннинга.
- **последовательность рассылки электронной почты**: Используется для управления жизненным циклом и онбординга электронных писем. НЕ для даннинга (используйте этот скилл для даннинга).
- **стратегия ценообразования**: Используйте, когда основной причиной оттока является несоответствие цен или упаковки. НЕ для сохранения дизайна предложения (используйте этот скилл).
- **аналитика кампаний**: Используется для анализа того, какие каналы привлечения клиентов приводят к высокому оттоку клиентов. НЕ для настройки отслеживания удержания.
- **регистрация-поток-cro**: используется для уменьшения отсева при регистрации. НЕ для сохранения после регистрации.
