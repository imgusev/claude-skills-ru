> ** Портативность:** Требуется `bash_tool` (для репортерского ПОСТА через curl), Node.js с `docx` пакет и согласованное MCP-соединение. Изначально работает в Claude Code CLI. В Клоде.искусственный интеллект с выполнением кода + согласованный MCP, воркфлоу поддерживается, но медленнее.

> ** Сфера охвата: только для NIH.** Спонсоры, не входящие в NIH (PCORI, DOD CDMRP, VA, фонды), находятся вне сферы охвата и помечаются при приеме.

Для клинического исследователя с исследовательской идеей подготовьте стратегический обзор финансирования NIH в виде редактируемого `.docx`. Выходные данные включают анализ позиционирования исследования, картографирование институтов, поиск целевых грантов и стратегические рекомендации, которые исследователь может редактировать, копировать и делиться ими со своим наставником.

## Правила добросовестности агента (Соглашение об исследовательском пакете) { #agent-integrity-rules-research-pack-convention }

Унаследовано; заблокировано дословно согласно аудиту PR #657.

- **Исполнительская дисциплина.** Шаг не будет завершен до тех пор, пока не будет подтверждено получение результата. Согласованные вызовы **последовательные с паузой более 1 секунды**. Репортер звонит последовательно.
- **Поиск источников данных.** Подсчитывайте только то, какие вызовы инструментов вернули результат в этом сеансе. Никогда не дополняйте учебными знаниями. Учебные знания, помеченные `[Not from Consensus/RePORTER — reference information]` и исключен из подсчетов.
- ** Подсчет и атрибуция.** Отправленные запросы / показанные результаты / процитированные результаты — три отдельных номера, никогда не совпадающих. Каждая цитируемая статья имеет доступный для извлечения URL-адрес с этой сессии.
- **Обработка ошибок.** При сбое → подождите 3 секунды → повторите попытку один раз → войдите в систему. После 3 последовательных сбоев в работе инструментов: остановитесь, предупредите исследователя, объясните, чего не хватает. Никогда молча не пропускайте.
- **Прозрачность.** Раздел журнала аудита в формате DOCX. В сводке чата те же стандарты, что и в документе.

Видишь [`references/reporter_post_patterns.md`](https://github.com/imgusev/claude-skills-ru/tree/main/research/grants/skills/grants/references/reporter_post_patterns.md) для репортера ОПУБЛИКУЙТЕ канон + обнаружение на уровне плана.

## Фаза 1: Прием пищи на гриле (6 форсирующих вопросов, по одному за раз) { #phase-1-grill-me-intake-6-forcing-questions-one-at-a-time }

### Q1 (корень) — Исследовательская идея { #q1-root--research-idea }

> **Опишите идею исследования в 2-3 предложениях. В чем вопрос, что нового и какова клиническая значимость? Расплывчатые ответы ("Искусственный интеллект для здравоохранения", "биомаркеры болезни X") будут отклонены — требуйте конкретики.**
>
> *Почему я спрашиваю:* Пять поисков консенсуса (устоявшиеся / ставки / текущие подходы / смежные методы / пробелы) зависят от точной исследовательской идеи. Расплывчатые идеи порождают расплывчатые цитаты с пробелами и бесполезное повествование о позиционировании.

Откажитесь от каши. Повторите запрос один раз с примерами, если пользователь слишком широк.

### Q2 (зависит от Q1) — Этап карьеры { #q2-depends-on-q1--career-stage }

> ** Этап карьеры — выберите один:**
>
> 1. Докторантура (аспирант, стажер T32)
> 2. Аспирант (F32, кандидат K99)
> 3. Начало карьеры (кандидат на премию K, первый R01)
> 4. Независимый исследователь (несколько R01, созданная лаборатория)
> 5. Старший ИП (R35, серия P, руководство U01)
>
> * Почему я спрашиваю: * Рекомендации по механизму фильтрации этапов карьеры. Серия F - для стажеров, серия K - для начинающих карьеру, серия R - для независимых. Выбор неправильного этапа приводит к неоправданным предложениям по механизму.

Вынуждающий выбор.

### Q3 (зависит от Q2) — Состояние предварительных данных { #q3-depends-on-q2--preliminary-data-status }

> **Предварительные данные — выберите один:**
>
> 1. Нет (проект de novo, пилотных данных пока нет)
> 2. Пилотные данные (ранние выводы, на одном объекте)
> 3. Тщательный предварительный анализ (многоэкспериментальный, готовый к R01-шкале)
> 4. Проверено и готово (для нескольких сайтов, готово к публикации)
>
> *Почему я спрашиваю:* Статус предварительных данных определяет бюджет механизма. Нет данных → Пилотная область R03 / R21. Строгая предварительная оценка → многосайтовая шкала R01 / U01. Несоответствие приводит к неконкурентоспособным приложениям.

### Q4 (зависит от Q2) — Окружающая среда { #q4-depends-on-q2--environment }

> **Исследовательская среда — выберите одну из них:**
>
> 1. R01-приемлемый (научно-исследовательское учреждение с базовым финансированием NIH)
> 2. Средний уровень (региональный академический медицинский центр, скромный портфель NIH)
> 3. Ограниченность ресурсов (небольшое учреждение, минимальная база NIH)
> 4. Отраслевое сотрудничество (академическое + отраслевое партнерство)
>
> * Почему я спрашиваю: * Среда влияет на реалистичность области применения (для многосайтового U01 требуется R01-приемлемый) и на то, какие категории механизмов являются конкурентоспособными (R15 специально нацелен на ограниченные ресурсы).

### Q5 (зависит от Q1) — Поза подчинения { #q5-depends-on-q1--submission-posture }

> ** Поза подчинения — выберите одну:**
>
> 1. Новая заявка (первая подача, предварительных ревью не проводилось)
> 2. Повторная отправка (A1 с необходимыми ответами рецензента)
> 3. Изучение (еще не решили, отправлять ли заявку)
>
> * Почему я спрашиваю: * Для повторных отправок требуется руководство по ответу рецензента в формате DOCX (раздел 7). Новые приложения пропускают это. Исследование смещает акцент на ландшафт, а не на стратегию.

### Q6 (зависит от Q1) — Известные цели института { #q6-depends-on-q1--known-institute-targets }

> **Рассматриваете ли вы уже конкретные институты Национального здравоохранения? Перечислите имена (NCI / NHLBI / NIMH / NINDS / NIDDK / и т.д.) или скажите "нет предпочтений — найдите правильные".**
>
> *Почему я спрашиваю:* Если у вас есть гипотеза института, я проверю ее на основании данных репортеров. Если нет, я назову топ-3 институтов, финансирующих смежные работы, по подсчетам института.

Примите "нет предпочтений" как обычный случай.

** Условие остановки: ** После Q6 зафиксируйте и запустите фазу 2A. Никогда не открывайте впуск после начала фазы 2A.

## Фаза 2А: Позиционирование исследования (5 поисков консенсуса) { #phase-2a-research-positioning-5-consensus-searches }

Запускайте последовательно с частотой 1 q/sec. Каждый поиск соответствует одному аспекту позиционирования:

1. **Установленный** — `"<research idea>" established evidence` — что известно
2. **Ставки** — `"<topic>" mortality OR burden OR cost OR prevalence` — почему это так важно
3. **Современные подходы** — `"<topic>" current treatment OR standard of care OR approach` — по последнему слову техники
4. **Смежные методы** — `"<related technique>" applied to <topic>` — методологические возможности
5. **Пробелы** — `"<topic>" limitations OR unanswered OR future directions OR challenge` — сигналы разрыва

Использование `scripts/citation_tracker.py --action record_consensus_search` для каждого. Уровень плана обнаружен по первому ответу.

** Обобщение: ** для каждого аспекта извлеките 2-3 цитируемых вывода (становится разделом 2 "Пробельные цитаты"). Подготовьте формулировку значимости/инновации, используя шаблон "поле установило X (ссылки), но Y остается без ответа (ссылки)".

## Фаза 2B: Картографирование института + Открытие гранта (СООБЩЕНИЕ репортера) { #phase-2b-institute-mapping--grant-discovery-reporter-post }

Репортер доступен ** только для публикации **. Использование `bash_tool` + `curl` — никогда `web_fetch`.

### Динамическое окно финансового года { #dynamic-fiscal-year-window }

Вычисление во время выполнения с помощью `scripts/fiscal_year_calculator.py`. По умолчанию: текущий финансовый год + 3 предыдущих. Федеральный финансовый год начинается 1 октября, так что:

```bash
python scripts/fiscal_year_calculator.py --output json
# Returns: {"current_fy": 2026, "window": [2023, 2024, 2025, 2026]}
```

### Узкий поиск (И) — находит прямое перекрытие { #narrow-and-search--finds-direct-overlap }

```bash
curl -X POST 'https://api.reporter.nih.gov/v2/projects/search' \
  -H 'Content-Type: application/json' \
  -d '{
    "criteria": {
      "fiscal_years": [2023, 2024, 2025, 2026],
      "include_active_projects": true,
      "advanced_text_search": {
        "operator": "AND",
        "search_field": "all",
        "search_text": "<key term 1> <key term 2>"
      }
    },
    "limit": 50,
    "include_fields": ["project_num", "project_title", "agency_ic_admin", "study_section", "fiscal_year", "principal_investigators", "abstract_text"]
  }'
```

### Широкий (ИЛИ) поиск — находит смежную работу { #broad-or-search--finds-adjacent-work }

```bash
curl -X POST 'https://api.reporter.nih.gov/v2/projects/search' \
  -H 'Content-Type: application/json' \
  -d '{
    "criteria": {
      "fiscal_years": [2023, 2024, 2025, 2026],
      "advanced_text_search": {
        "operator": "OR",
        "search_field": "all",
        "search_text": "<term> <synonym> <related concept>"
      }
    },
    "limit": 50
  }'
```

### Рейтинг института + рейтинг учебной секции { #institute-tally--study-section-ranking }

После ответов репортеров:
- Подсчитать `agency_ic_admin` (код института: NCI, NHLBI, NIMH и т.д.) → топ-3 финансирующих института
- Подсчитать `study_section` → топ-2 учебных раздела (куда отправляются заявки на ревью)

### Открытие NOSI { #nosi-discovery }

Анализ ответов репортеров для `NOT-*` количество возможностей. Для каждого:

```bash
# NOSIs live at predictable URLs:
# https://grants.nih.gov/grants/guide/notice-files/NOT-<INSTITUTE>-<YEAR>-<NUMBER>.html
web_fetch <url>
```

Если выборка завершается неудачей: войдите в систему `[NOSI {number} — fetch failed, not included]`, продолжайте.

## Сопоставление механизмов (с учетом области применения) { #mechanism-matching-scope-aware }

НЕ только карьерный этап. Этап карьеры **+** объем проекта **+** Рекомендация по предварительному накоплению данных.

Использование `scripts/mechanism_matcher.py`:

```bash
python scripts/mechanism_matcher.py \
  --career-stage "early_career" \
  --prelim-data "pilot" \
  --environment "r01_eligible" \
  --scope "single_site" \
  --output json
# Returns mechanism shortlist with rationale
```

Видишь [`references/nih_mechanism_matching.md`](https://github.com/imgusev/claude-skills-ru/tree/main/research/grants/skills/grants/references/nih_mechanism_matching.md) для полной матрицы.

## Фаза 3: Генерация DOCX { #phase-3-docx-generation }

9 секций через Node.js + `docx` библиотека. Видишь [`references/docx_9_sections.md`](https://github.com/imgusev/claude-skills-ru/tree/main/research/grants/skills/grants/references/docx_9_sections.md) для получения полной спецификации.

1. ** Краткое изложение** — должность + этап карьеры + окружение + 3-4 ключевых вывода.
2. ** Позиционирование исследования ** — 3-5 пробельных цитат (выделенных курсивом, встроенных согласованных цитат) + описание позиционирования в 2-3 абзацах + таблица подтверждающих доказательств
3. ** Целевые институты** — таблица ранжирования (институт, количество проектов в окне, % соответствия вашей идее) + интерпретация 2-3 предложений
4. ** Возможности предоставления грантов ** — выделите жирным шрифтом выноску NOSI, если таковая имеется. Таблица топ-3 грантов с гиперссылками на FOA + объем каждого гранта/budget подходящий абзац
5. **Перекрытие финансирования** — таблица топ-5 проектов (PI, номер проекта, IC, год, гиперссылка на RePORTER) + разделительный абзац
6. ** Учебные разделы** — рейтинговая таблица + интерпретация наилучшего соответствия
7. ** Стратегические рекомендации и следующие шаги ** — 3-4 пронумерованных отзыва + ** обязательный отзыв сотрудника программы ** + примечание о сроках подачи + (при повторной подаче Q5=2) руководство рецензента по ответу + заключительный абзац
8. **Ссылки** — пронумерованная библиография с гиперссылкой на Консенсус
9. ** Журнал аудита** — Таблица поиска консенсуса, примечание уровня плана, таблица поиска репортера, таблица выборок NOSI, сводная статистика, примечание об ограничениях инструмента, неудачные шаги

### Укладка { #styling }

Корпус Arial 12pt, темно-синие заголовки (#1a3a5c), светло-голубые заголовки таблиц (#e8f0f8), выноска NOSI желтого цвета. `ExternalHyperlink` узоры:
- Цитаты из статей: `https://consensus.app/papers/...`
- Ссылки на FOA: `https://grants.nih.gov/grants/guide/...`
- Репортерские проекты: `https://reporter.nih.gov/project-details/<id>`

## Обязательная рекомендация сотрудника программы { #mandatory-program-officer-recommendation }

Всегда включайте в раздел 7:

> **Рекомендуемый следующий шаг: свяжитесь с сотрудником программы по адресу {top institute}.** Найдите страницу их сотрудников по адресу https://www.nih.gov/institutes-nih/list-nih-institutes-centers-offices → {institute} → Сотрудники программы. Подготовьте: 1 страницу с конкретными целями + ваше резюме + 3 конкретных вопроса о пригодности. Тема электронного письма: "Запрос перед подачей заявки: <тема>".

Это самый ценный совет для любого соискателя. Никогда не пропускай.

## Этап 4: Доставка { #phase-4-deliver }

- Сохраните DOCX в `<output-dir>/grants_<topic-slug>_<YYYY-MM-DD>.docx`
- Краткое содержание чата: путь к файлу + количество аудитов + уровень плана + вердикт по целям института
- Проверка: проверьте целостность почтового индекса с помощью `python3 -c "import zipfile,sys; zipfile.ZipFile(sys.argv[1]).testzip()" <docx>` (нет выходных данных = не поврежден), затем подтвердите наличие требуемых разделов

## Обработка ошибок { #error-handling }

| Неудача | Поведение |
|---|---|
| Достижение консенсус-лимита по ставке | Подождите 3 секунды, повторите попытку один раз, войдите в систему; если все еще не удается, предупредите исследователя |
| Консенсус возвращает 0 для аспекта | Явно проявляйте себя; никогда не наполняйте учебными знаниями |
| Обнаружен согласованный план- ограничение уровня | Уровень журнала, примечание в аудите, доступ к исследователю |
| СООБЩЕНИЕ репортера возвращает ошибку | Повторите попытку один раз через 3 секунды; если все еще не удается, войдите в систему и продолжайте |
| Репортер возвращает <5 на узком | Документ; широкий ИЛИ должен компенсировать; малое количество поверхностей |
| Не удается выполнить выборку NOSI | Журнал `[NOSI {n} — fetch failed]`, продолжайте |
| 3 последовательных отказа инструмента | Остановитесь, предупредите исследователя о том, чего не хватает |
| Сбой генерации DOCX | Сохраните необработанные данные в виде резервного файла JSON, чтобы исследователь не потерял работу |

## Анти-Паттерны для отклонения { #anti-patterns-to-reject }

- Распараллеливание согласованных вызовов (достигнет предела скорости)
- Используя `web_fetch` для репортера (только для публикации — `web_fetch` это ПОЛУЧИТЬ)
- Жестко заданные значения за финансовый год
- Рекомендации по механизму, основанные только на этапе карьеры (необходимо также учитывать сферу охвата)
- Бесшумное заполнение тонких граней результатов обучающими знаниями
- Пропуск журнала аудита
- Пропуск рекомендации сотрудника программы
- Объединение "найденных документов" с "показанными документами" с "цитируемыми документами"
- Создание сведений о NOSI при сбое выборки
