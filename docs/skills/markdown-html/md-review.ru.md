Конвертер ревью кода из уровня 2 эссе Шихипара ("Ревью кода и PR-записи"). Выполняет запись PR в Markdown с блоками diff + выносками серьезности и создает однофайловый HTML-ревью с переходной навигацией, макетом diff + аннотаций в 2 столбца и нижним колонтитулом с именем рецензента.

Три инструмента stdlib объединяются в пайплайн:

```
diff_parser.py  →  annotation_extractor.py  →  review_html_renderer.py
   (md → diff hunks)   (md → severity-tagged    (hunks + annotations
                        annotations attached     + tokens → 2-col HTML)
                        to nearest hunk)
```

## Когда вызывать { #when-to-invoke }

| Симптом | Действие |
|---|---|
| `markdown-html-orchestrator` маршруты вводятся в качестве РЕВЬЮ | Используйте этот скилл |
| Пользователь запускает `/cs:md-review <path>.md` непосредственно | Используйте этот скилл |
| Входные данные содержат ` ```diff ` огороженные блоки + `> [!MAJOR]`/`> [!BLOCKER]`/etc. выноски | Используйте этот скилл |
| Входные данные - это спецификация / отчет в длинной форме (без блоков diff) | Маршрут к `md-document` вместо этого |
| Входные данные - это слайд-дека | Маршрут к `md-slides` вместо этого |
| Ввод < 100 строк | Отказ (порог Шихипара) |
| Дизайн-система, не онбординг | Мусор; поверхность `/cs:design-system` |

## Пайплайн { #pipeline }

```bash
# 1. Parse markdown → diff hunks JSON
python3 markdown-html/skills/md-review/scripts/diff_parser.py \
    --input <path>.md --output hunks.json

# 2. Extract severity-tagged annotations, attach to nearest preceding hunk
python3 markdown-html/skills/md-review/scripts/annotation_extractor.py \
    --input <path>.md --diff-blocks hunks.json --output annotations.json

# 3. Render 2-col HTML (--reviewer is mandatory — refuses without)
python3 markdown-html/skills/md-review/scripts/review_html_renderer.py \
    --diff-blocks hunks.json --annotations annotations.json \
    --reviewer "Jane Doe" --title "PR #123: Add retry logic" \
    --output review.html
```

## Что визуализируется { #what-gets-rendered }

- ** Верхний переход-навигация ** — каждая аннотация со значком серьезности + предварительный просмотр 80 символов + ссылка для перехода; серьезность указывается в заголовке ("3 БЛОКИРУЮЩИХ · 2 ОСНОВНЫХ · 1 НИЧТОЖЕСТВО")
- **2-столбцовые отдельные строки ** — унифицированное различие слева (старое для каждой строки/new номера строк, знаки +/−, сложение/deletion оттенок фона из маркеров системы дизайна), карточки с аннотациями справа (цвет + значок + aria-метка в соответствии с WCAG 1.4.1)
- **Полоса одобрения** — если `LGTM` присутствуют маркеры и нет аннотаций к степени серьезности, панель "LGTM - результаты не отмечены", окрашенная в цвет успеха
- ** Общие комментарии ** — аннотации, не прикрепленные ни к одному фрагменту рендеринга внизу в их собственном разделе
- **Нижний колонтитул рецензента** — обязательный; отказывается отображать без `--reviewer`
- **Отзывчивый** — 2- столбец сворачивается в стопку на видовых экранах < 900 пикселей

## Жесткие правила { #hard-rules }

1. **`--reviewer` является обязательным.** В ревью кода должен быть указан рецензент-человек. В противном случае отказывает при выходе 3. Отражает дисциплину research-ops "названный владелец".
2. **Отказывается, если нет кусков.** Нет `--- a/file` + `@@ ... @@` блоки означают, что это не ревью кода — отказывается при выходе 4 и рекомендует `md-document`.
3. **Отклоняет ввод < 100 строк.** Markdown выигрывает при значении ниже порогового значения (Shihipar).
4. **Отказывает без онбординга.** Тот же гейт, что и у любого конвертера.
5. ** Строгость никогда не зависит только от цвета.** Каждый значок имеет цвет + иконку + `aria-label` + текст. WCAG 1.4.1 применяется на уровне средства визуализации.
6. ** Вывод в виде одного файла.** Весь встроенный CSS. Единственным внешним является Google Fonts CSS. Нет Prism в md-ревью (разностная раскраска конфликтует с подсветкой синтаксиса).
7. ** Пользовательское соглашение о строгости.** `--severity-convention "critical,important,suggestion,nit"` меняет местами названия уровней; позиция 0 является наиболее серьезной. По умолчанию используется BLOCKER / MAJOR / MINOR / NIT (Руководство разработчика по ревью кода Google).

## Библиотека принудительных вопросов (дисциплина Matt Pocock grill) { #forcing-question-library-matt-pocock-grill-discipline }

1. **Кто является названным рецензентом?** Рекомендуется: пользователь, подписавшийся на ревью. Канон: исследовательский шаблон с именем владельца; * SWE в Google* гл. 9.
2. ** Какое соглашение о строгости применяется — по умолчанию (БЛОКИРУЮЩИЙ /ОСНОВНОЙ/ВТОРОСТЕПЕННЫЙ/ NIT) или пользовательское?** Рекомендуется: по умолчанию, если у вашей команды нет документированной альтернативы. Канон: Google * Руководство разработчика по ревью кода*.
3. ** Привязаны ли аннотации к конкретным фрагментам или это какие-то общие сведения?** Рекомендуется: привязывайте все, что можете; общие сведения переходят в раздел без привязки. Канон: * SWE в Google* глава 9 — "Комментарии должны ссылаться на определенную строку".
4. **Каково название PR-кампании для `<title>` и заголовок?** Рекомендуется: фактический заголовок PR / commit. Канон: документы-как-контекст-для-читателей.
5. **Следует `LGTM` маркеры поставляются в качестве панели одобрения?** Рекомендуется: да, если нет аннотаций к степени серьезности; в противном случае выводы имеют приоритет.

## Отличный от { #distinct-from }

- **`md-document`** — этот конвертер отображает прозу + таблицы + код + выноски. Этот рендерит фрагменты diff + аннотации на полях.
- **`md-slides`** — этот преобразователь разделяется на `---` границы. Это одностраничный артефакт.
- ** PR-комментарии на GitHub ** — это тема. Это артефакт моментального снимка, созданный одним автором.
