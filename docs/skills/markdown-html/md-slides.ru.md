Преобразователь слайд-деки. Считывает таблицу Markdown (границы HR или H1, необязательные примечания докладчика), создает однофайловую HTML-презентацию, которая запускается в любом браузере с навигацией по клавиатуре, режимом презентации и возможностью печати в формате PDF.

Три инструмента stdlib объединяются в пайплайн:

```
slide_splitter.py  →  presenter_notes_parser.py  →  deck_html_renderer.py
   (md → ordered      (extract <!-- notes:         (slides + design-system
    slides with       --> blocks, attach            tokens → single-file
    titles)           per slide)                    HTML with keyboard nav)
```

## Когда вызывать { #when-to-invoke }

| Симптом | Действие |
|---|---|
| `markdown-html-orchestrator` маршруты вводятся в виде слайдов | Используйте этот скилл |
| Пользователь запускает `/cs:md-slides <path>.md` непосредственно | Используйте этот скилл |
| Вход имеет 3+ `---` Строки HR ИЛИ заголовки 5+ H1 с короткими корпусами | Используйте этот скилл |
| Входные данные - это спецификация в длинной форме | Маршрут к `md-document` вместо этого |
| Ввод - это ревью кода | Маршрут к `md-review` вместо этого |
| Ввод не имеет четких границ слайда | Отказаться, направить в `md-document` |
| При вводе будет получен 1 слайд | Отказаться (это плакат) |

## Пайплайн { #pipeline }

```bash
# 1. Split slides on --- or H1 (auto-detect by default)
python3 markdown-html/skills/md-slides/scripts/slide_splitter.py \
    --input <path>.md --output /tmp/slides.json

# 2. Extract <!-- notes: ... --> blocks from each slide
python3 markdown-html/skills/md-slides/scripts/presenter_notes_parser.py \
    --slides /tmp/slides.json --output /tmp/deck.json

# 3. Render single-file HTML deck
python3 markdown-html/skills/md-slides/scripts/deck_html_renderer.py \
    --slides /tmp/deck.json --title "My Talk" --output deck.html
```

## Что поставляется в HTML-коде { #what-ships-in-the-html }

- **Все слайды в виде `<section class="slide">`** — по одному видимому за раз, контролируемому JS
- ** Навигация с клавиатуры** — `→` / `Space` / `PgDn` продвижение; `←` / `PgUp` предыдущий; `Home`/`End` прыжок; `P` режим докладчика; `Esc` выходит ведущий
- **Глубокая привязка URL-хэша** — `#3` переход к слайду 3; переход браузера назад /вперед по слайдам; поделиться `deck.html#5` послать кого-нибудь прямо туда
- ** Индикатор выполнения ** — 3 пикселя вверху, показывающий положение в колоде
- **Счетчик скольжения** — справа внизу ("3/12")
- ** Режим презентатора** (клавиша P) — разбивает окно на части: текущий слайд слева (ширина 60%), панель справа с часами + заметки диктора + предварительный просмотр следующего слайда
- **Таблица стилей печати** — `Cmd+P` создает PDF-файл с одним слайдом на странице
- **`@media (prefers-reduced-motion: reduce)`** удостоенный чести
- **12 пользовательских свойств фирменного CSS** из design-system; design_style влияет на плотность макета
- ** Повторно использует синтаксический анализатор Markdown md-документа ** — тела слайдов отображаются с согласованной обработкой абзаца / списка/ кода / таблицы/выноски

## Жесткие правила { #hard-rules }

1. **Отклоняет ввод при отсутствии четких границ слайда.** Для автоматического режима требуется ≥ 3 строк в час или ≥ 5 заголовков в час 1. В противном случае выйдите из 6 — route to md-document.
2. ** Отказывается от колод с 1 слайдом. ** Это постер, а не колода. Выход 5.
3. **Отклоняет ввод < 100 строк.** Тот же порог Shihipar, что и у всех преобразователей.
4. **Отказывает без онбординга.** Тот же гейт, что и у любого конвертера.
5. **`--strict-notes` отклоняет покрытие примечаниями < 50%.** Колода, на большинстве слайдов которой нет заметок, не настроена для режима презентатора. Выход 7.
6. **Слайды с плавными предупреждениями > 40 исходных строк.** Соотношение сигнал/шум; рендерится в любом случае, но отображает количество.
7. ** Вывод в виде одного файла.** Все встроенные CSS + JS. Единственным внешним является Google Fonts CSS. Prism.js это регистрация через `--syntax`.
8. ** Нет среды выполнения JS фреймворка.** Обработчики событий Vanilla JS + keyboard, нет React / Vue /Svelte.

## Библиотека принудительных вопросов (дисциплина Matt Pocock grill) { #forcing-question-library-matt-pocock-grill-discipline }

1. ** Это на самом деле колода или длинный документ?** Рекомендуется: если вы не можете нарисовать четкие границы слайда, это не колода. Канон: Tufte * Когнитивный стиль PowerPoint*.
2. **Отдел кадров (`---`) или границы H1?** Рекомендуется: HR для типичных колод; H1 для колод, управляемых контуром. Канон: Marp / reveal.js конвергенция pandoc.
3. ** Будет ли он представлен в прямом эфире или распространен для самостоятельного чтения?** Рекомендуется: прямой эфир → нужны заметки докладчика; самостоятельный темп → заметки необязательны. Канон: Вайншенк *100 вещей, которые должен знать каждый ведущий*.
4. ** Есть ли какой-нибудь слайд более чем на 40 строк исходного текста? ** Рекомендуется: разделите его. Канон: NN/g — внимание аудитории падает ниже ~6 пуль / 200 слов.
5. **Является `--syntax` требуется?** Рекомендуется: только для колод с большими блоками кода. По умолчанию выключен. Канон: дисциплина совместного использования отдельных файлов.

## Отличный от { #distinct-from }

- **`md-document`** — это один непрерывный документ. Это N отдельных слайдов.
- **`md-review`** — который отображает различные фрагменты + аннотации. При этом отображаются слайды в прозе.
- **`marketing/landing/`** — это целевая страница, а не колода.
- ** Keynote / PowerPoint** — это инструменты графического дизайна. Это для колод, созданных автором Markdown, проецируемых из браузера.
