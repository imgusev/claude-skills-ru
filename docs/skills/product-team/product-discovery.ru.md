Запустите структурированное обнаружение, чтобы выявить ценные возможности и снизить риски при выборе продукта.

## Когда использовать { #when-to-use }

Используйте этот скилл для:
- Упрощение дерева возможностей и решений
- Сопоставление предположений и планирование тестирования
- Интервью для подтверждения проблемы и обобщение фактических данных
- Проверка решения с помощью прототипов/experiments
- Планирование спринта по обнаружению и результаты

## Основной воркфлоу обнаружения { #core-discovery-workflow }

1. Определите желаемый результат
- Установите один измеримый результат для улучшения.
- Установите исходный уровень и целевой горизонт.

2. Построение дерева возможных решений (OST)
- Результат -> возможности -> идеи для решения -> эксперименты
- Используйте возможности, основанные на свидетельствах пользователей, а не на внутренних мнениях.

3. Предположения о карте
- Определите предположения о желательности, жизнеспособности, осуществимости и удобстве использования.
- Оцените допущения по степени риска и определенности.

Использование:
```bash
python3 scripts/assumption_mapper.py assumptions.csv
```

4. Проверьте проблему
- Проводите собеседования и анализ поведения.
- Подтвердите частоту, серьезность и готовность к решению.
- Рано отвергайте слабые возможности.

5. Проверьте правильность решения
- Прототип перед сборкой.
- Запустите тесты концепции, удобства использования и ценности.
- Измеряйте поведение, а не только заявленные предпочтения.

6. Планируйте спринт по обнаружению
- цикл продолжительностью 1-2 недели с четкими гипотезами
- Ежедневные ревью по фактическим данным
- Завершите принятием решения: продолжить, развернуться или остановиться

## Дерево возможных решений (Тереза Торрес) { #opportunity-solution-tree-teresa-torres }

Структура:
- Результат: показатель, который вы хотите переместить
- Возможности: неудовлетворенные потребности клиентов/pains
- Решения: возможные вмешательства
- Эксперименты: самые быстрые обучающие действия

Проверка качества:
- По крайней мере, 3 различные возможности, прежде чем сходиться.
- По крайней мере, 2 эксперимента на каждую лучшую возможность.
- Привяжите каждую ветвь к источнику доказательств.

## Сопоставление предположений { #assumption-mapping }

Категории допущений:
- Желательность: пользователи хотят этого
- Жизнеспособность: ценность бизнеса существует
- Осуществимость: команда может создать/operate это
- Удобство использования: пользователи могут успешно использовать его

Правило определения приоритетов:
- Сначала проверяются предположения о высоком риске + низкой достоверности.

## Методы проверки проблемы { #problem-validation-techniques }

- Проблемные интервью, сфокусированные на текущем поведении
- Отображение трения в пути
- Синтез запросов в службу поддержки и отдел продаж
- Триангуляция поведенческой аналитики

Примеры пороговых значений доказательности:
- Одна и та же боль повторяется у нескольких целевых пользователей
- Наблюдаемое поведение обходного пути
- Измеримая стоимость текущей боли

## Методы проверки решений { #solution-validation-techniques }

- Концептуальные тесты (понимание ценностного предложения)
- Юзабилити-тесты прототипа (успешное выполнение задачи/time-to-complete)
- Проверка поддельной двери или консьержа (сигнал запроса)
- Ограниченные бета-когорты (удержание/activation сигналы)

## Планирование спринта по обнаружению { #discovery-sprint-planning }

Предлагаемая 10-дневная структура:
- День 1-2: Результат + формирование возможностей
- День 3-4: Сопоставление предположений + разработка теста
- День 5-7: Тесты проблем и решений
- День 8-9: Обобщение фактических данных + варианты принятия решения
- День 10: Ревью решений стейкхолдеров

## Оснастка { #tooling }

### `scripts/assumption_mapper.py` { #scriptsassumption_mapperpy }

Утилита CLI, которая:
- считывает предположения из CSV или встроенного ввода
- оценивает риск/certainty приоритет
- выдает приоритетный план тестирования с предлагаемыми типами тестов

Видишь `references/discovery-frameworks.md` для получения подробной информации о фреймворке.
