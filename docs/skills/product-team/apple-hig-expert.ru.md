Разрабатывайте и аудит приложений в соответствии с рекомендациями Apple по пользовательскому интерфейсу (HIG, [developer.apple.com/design/human-interface-guidelines](https://developer.apple.com/design/human-interface-guidelines)), включая язык дизайна **Жидкое стекло**. Контент HIG меняется с каждым выпуском ОС — если претензия имеет значение, сверьтесь с текущими страницами HIG, указанными в `references/`.

## Перед началом работы { #before-starting }

Если `product-context.md` или `ios-design-context.md` существует, прочтите его, прежде чем задавать вопросы. Затем соберите:

1. ** Целевая платформа **: iOS, macOS, watchOS или visionOS?
2. **Текущее состояние**: новый дизайн или аудит существующего макета/code?
3. ** Категория приложения **: полезность, производительность, игра, социальные сети и т.д.

## Режимы { #modes }

- **Режим 1 — Дизайн с нуля**: сначала выберите парадигму навигации по платформе и примитивы макета (см. `references/platform-specifics.md`), затем примените типографику и семантический цвет (`references/visual-design.md`).
- **Режим 2 — высокий аудит**: заполните `templates/hig-audit-template.md`, беги `scripts/hig_checker.py` по каждому измеряемому элементу и предоставьте отчет с оценкой (смотрите отработанный пример ниже).

## Инструмент обеспечения соответствия { #the-compliance-tool }

`scripts/hig_checker.py` (только для stdlib) имеет три подкоманды:

```bash
# 1. Contrast ratio (WCAG formula; pass >= 4.5:1 for normal text)
python3 scripts/hig_checker.py contrast "#8E8E93" "#FFFFFF"
# -> Contrast Ratio: 3.26 [FAILED]

# 2. Tap-target size (pass >= 44x44 pt per HIG)
python3 scripts/hig_checker.py target 32 32
# -> Tap Target: 32x32 [FAILED]

# 3. Batch audit from JSON -> scorecard (starts at 100, -10 per violation)
python3 scripts/hig_checker.py batch audit.json
```

Форма пакетного ввода:

```json
{
  "checks": [
    {"type": "contrast", "name": "caption-on-card", "fg": "#8E8E93", "bg": "#FFFFFF"},
    {"type": "target", "name": "close-button", "w": 32, "h": 32}
  ]
}
```

** Рубрика системы показателей:** оценка партии начинается со 100 и вычитается 10 за каждую неудачную проверку; нарушения перечисляются по названию элемента. 90-100 = отправка, 70-80 = исправление перед выпуском, ниже 70 = систематическая доработка. Проверки, которые инструмент не может измерить (надписи за кадром, динамическое поведение шрифта, снижение прозрачности), оцениваются вручную с помощью шаблона аудита и помечаются как достоверные.

## Отработанный пример: настройки iOS-аудит экрана { #worked-example-ios-settings-screen-audit }

** Ввод:** макет с основным текстом `#1C1C1E` и подписи `#8E8E93` на белых карточках кнопка закрытия размером 32х32 пт и основной CTA размером 343х50 пт.

**Запуск:**

```bash
python3 scripts/hig_checker.py batch audit.json
```

**Выходные данные (реальные):**

```json
{
  "score": 80,
  "violations": [
    "Contrast 3.26 fails for caption-on-card",
    "Target 32x32 small for close-button"
  ]
}
```

**Выводы → исправления (сначала итоговая строка):**

> ** Высокий балл 80/100 — два исправления перед выпуском.**
> 1. Подписи не отличаются контрастностью (3,26 < 4,5). Использование `.secondaryLabel` (семантический цвет) вместо жестко закодированного `#8E8E93`, или потемнеет до ≥ `#6E6E73` на белом. 🟢 проверено с помощью инструмента.
> 2. Кнопка закрытия имеет размер 32x32 пикселя (минимум < 44x44). Оставьте глиф маленьким, но увеличьте область попадания до 44x44 с помощью отступов/`contentShape`. verified проверено с помощью инструмента.
> 3. Проверка вручную: на карточке поверх фона фотографии используется ультратонкий материал - повторно проверьте контрастность подписи на фоне *наиболее загруженной* нижележащей области и при включенном режиме уменьшения прозрачности. 🟡 требуется тестирование устройства.

## Основные принципы проектирования { #core-design-principles }

1. ** Жидкое стекло** — иерархия полупрозрачных материалов (анонсировано на WWDC25, июнь 2025 г.; выпущено в сентябре 2025 г. для iOS 26, iPadOS 26, macOS Tahoe, watchOS 26, tvOS 26, visionOS 26). В SwiftUI примените его с помощью `glassEffect` модификатор вида; сохраняйте иерархию между содержимым и элементами управления. Видишь `references/visual-design.md`.
2. ** Прежде всего доступность ** — надписи за кадром на каждом элементе, минимальные целевые значения 44x44 пт, контрастность 4,5: 1 для обычного текста (крупный текст 3:1), поддержка динамического ввода. Видишь `references/accessibility.md`.
3. **Эргономика платформы** — панели вкладок/thumb reach на iOS, боковые панели + строка меню + ярлыки на macOS, орнаменты + состояния взгляда на visionOS, вертикальные макеты с возможностью просмотра на watchOS. Видишь `references/platform-specifics.md`.

## Проактивные триггеры { #proactive-triggers }

Наносите их БЕЗ запроса: низкий контраст поверх полупрозрачных слоев; интерактивные элементы размером менее 44 пт; кнопки-значки без надписи "Доступность"; перегрузка по плотности (нет пространства для дыхания между слоями стекла).

## Общение { #communication }

- **Сначала итог ** — статус соответствия перед подробностями.
- **Что + Почему + Как** — "Расширьте область попадания (Что), потому что цели размером 32 pt не соответствуют минимуму HIG (почему); увеличьте до 44x44 с помощью contentShape (Как)".
- ** Пометка достоверности ** — 🟢 проверено инструментом / 🟡 требуется тестирование устройства / 🔴 предполагается.
