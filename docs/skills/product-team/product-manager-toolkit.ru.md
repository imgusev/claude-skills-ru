## Быстрый старт { #quick-start }

### Для определения приоритетов функций { #for-feature-prioritization }
```bash
# Create sample data file
python scripts/rice_prioritizer.py sample

# Run prioritization with team capacity
python scripts/rice_prioritizer.py sample_features.csv --capacity 15
```

### Для анализа интервью { #for-interview-analysis }
```bash
python scripts/customer_interview_analyzer.py interview_transcript.txt
```

### Для создания PRD { #for-prd-creation }
1. Выберите шаблон из `references/prd_templates.md`
2. Заполнять разделы на основе результатов поисковой работы
3. Ревью с инженерами на предмет осуществимости
4. Контроль версий в инструменте управления проектами

## Основные воркфлоу { #core-workflows }

### Процесс определения приоритетов функций { #feature-prioritization-process }

```
Gather → Score → Analyze → Plan → Validate → Execute
```

#### Шаг 1: Сбор запросов на дополнительные функции { #step-1-gather-feature-requests }
- Обратная связь с клиентами (заявки в службу поддержки, интервью)
- Запросы на продажу (блокировщики пайплайна CRM)
- Технический долг (инженерный вклад)
- Стратегические инициативы (цели лидерства)

#### Шаг 2: Посыпьте РИСОМ { #step-2-score-with-rice }
```bash
# Input: CSV with features
python scripts/rice_prioritizer.py features.csv --capacity 20
```

Видишь `references/frameworks.md` для получения рецептуры риса и рекомендаций по подсчету очков.

#### Шаг 3: Проанализируйте портфолио { #step-3-analyze-portfolio }
Ревью выходные данные инструмента для:
- Распределение быстрых выигрышей по сравнению с крупными ставками
- Концентрация усилий (избегайте всех проектов XL)
- Пробелы в стратегическом согласовании

#### Шаг 4: Создайте дорожную карту { #step-4-generate-roadmap }
- Ежеквартальное распределение мощностей
- Идентификация зависимостей
- План коммуникации с стейкхолдерами

#### Шаг 5: Проверка результатов { #step-5-validate-results }
**До завершения разработки дорожной карты:**
- [ ] Сопоставьте главные приоритеты со стратегическими целями
- [ ] Запустите анализ чувствительности (что, если оценки ошибочны в 2 раза?)
- [ ] Ревью с ключевыми стейкхолдерами на предмет "слепых зон"
- [ ] Проверьте, нет ли отсутствующих зависимостей между объектами
- [ ] Подтвердите оценки усилий с помощью инженерных

#### Шаг 6: Выполнение и повторение { #step-6-execute-and-iterate }
- Поделитесь дорожной картой с командой
- Отслеживание фактических и предполагаемых усилий
- Ежеквартально пересматривайте приоритеты
- Обновлять исходные данные по РИСУ на основе полученных знаний

### Процесс поиска клиентов { #customer-discovery-process }

```
Plan → Recruit → Interview → Analyze → Synthesize → Validate
```

#### Шаг 1: Спланируйте исследование { #step-1-plan-research }
- Определите исследовательские вопросы
- Определите целевые сегменты
- Создайте сценарий интервью (см. `references/frameworks.md`)

#### Шаг 2: Набор участников { #step-2-recruit-participants }
- 5-8 интервью в каждом сегменте
- Сочетание опытных пользователей и новичков
- Стимулируйте соответствующим образом

#### Шаг 3: Проведите собеседования { #step-3-conduct-interviews }
- Используйте полуструктурированный формат
- Сосредоточьтесь на проблемах, а не на решениях
- Запись с разрешения
- Делайте минимальные заметки во время собеседования

#### Шаг 4: Проанализируйте информацию { #step-4-analyze-insights }
```bash
python scripts/customer_interview_analyzer.py transcript.txt
```

Выдержки:
- Болевые точки с выраженностью
- Запросы функций с приоритетом
- Задания, которые необходимо выполнить.
- Настроения и ключевые темы
- Известные цитаты

#### Шаг 5: Обобщение полученных результатов { #step-5-synthesize-findings }
- Сгруппируйте похожие болевые точки в ходе интервью
- Выявление закономерностей (3+ упоминания = закономерность)
- Сопоставьте области возможностей с помощью дерева возможных решений
- Определите приоритетность возможностей по частоте и серьезности

#### Шаг 6: Проверка решений { #step-6-validate-solutions }
**Перед строительством:**
- [ ] Создайте гипотезы решения (см. `references/frameworks.md`)
- [ ] Тестирование с использованием прототипов с низкой точностью
- [ ] Измерять фактическое поведение в сравнении с заявленными предпочтениями
- [ ] Повторение на основе обратной связи
- [ ] Документируйте полученные знания для будущих исследований

### Процесс разработки PRD { #prd-development-process }

```
Scope → Draft → Review → Refine → Approve → Track
```

#### Шаг 1: Выберите шаблон { #step-1-choose-template }
Выберите один из `references/prd_templates.md`:

| Шаблон | Вариант использования | Временная шкала |
|----------|----------|----------|
| Стандартный PRD | Сложные функции, кросс-командная работа | 6-8 недель |
| Одностраничный PRD | Простые функции, единая команда | 2-4 недели |
| Краткая характеристика | Фаза исследования | 1 неделя |
| Проворный эпос | Доставка на основе спринта | Продолжающийся |

#### Шаг 2: Набросок содержания { #step-2-draft-content }
- Ведущий с постановкой задачи
- Заранее определите показатели успеха
- Явно укажите элементы, выходящие за рамки
- Включите каркасы или макеты

#### Шаг 3: Цикл ревью { #step-3-review-cycle }
- Проектирование: осуществимость и усилия
- Дизайн: пробелы в пользовательском опыте
- Продажи: подтверждение на рынке
- Поддержка: оперативное воздействие

#### Шаг 4: Уточнение на основе обратной связи { #step-4-refine-based-on-feedback }
- Устранять технические ограничения
- Отрегулируйте область действия в соответствии с временной шкалой
- Документируйте компромиссные решения

#### Шаг 5: Утверждение и начало работы { #step-5-approval-and-kickoff }
- Выход из системы стейкхолдеров
- Интеграция планирования спринта
- Общение с более широкой командой

#### Шаг 6: Отслеживание выполнения { #step-6-track-execution }
**После запуска:**
- [ ] Сравните фактические показатели с целевыми
- [ ] Проводить сеансы обратной связи с пользователями
- [ ] Документируйте, что сработало, а что нет
- [ ] Обновить данные о точности оценки
- [ ] Делитесь знаниями с командой

## Ссылка на инструменты { #tools-reference }

### Определитель приоритетов для РИСА { #rice-prioritizer }

Усовершенствованная реализация фреймворка RICE с анализом портфеля.

**Особенности:**
- Расчет количества риса с настраиваемыми весами
- Анализ баланса портфеля (быстрые выигрыши против крупных ставок)
- Ежеквартальное формирование дорожной карты на основе пропускной способности
- Несколько выходных форматов (текст, JSON, CSV)

**Формат ввода CSV:**
```csv
name,reach,impact,confidence,effort,description
User Dashboard Redesign,5000,high,high,l,Complete redesign
Mobile Push Notifications,10000,massive,medium,m,Add push support
Dark Mode,8000,medium,high,s,Dark theme option
```

**Команды:**
```bash
# Create sample data
python scripts/rice_prioritizer.py sample

# Run with default capacity (10 person-months)
python scripts/rice_prioritizer.py features.csv

# Custom capacity
python scripts/rice_prioritizer.py features.csv --capacity 20

# JSON output for integration
python scripts/rice_prioritizer.py features.csv --output json

# CSV output for spreadsheets
python scripts/rice_prioritizer.py features.csv --output csv
```

### Анализатор интервью с клиентами { #customer-interview-analyzer }

Анализ интервью на основе НЛП для извлечения полезной информации.

**Возможности:**
- Выделение болевой точки с оценкой степени тяжести
- Идентификация и классификация запроса функции
- Распознавание образов, которые необходимо выполнить
- Анализ настроений по разделам
- Извлечение темы и цитаты
- Обнаружение упоминаний конкурентов

**Команды:**
```bash
# Analyze interview transcript
python scripts/customer_interview_analyzer.py interview.txt

# JSON output for aggregation
python scripts/customer_interview_analyzer.py interview.txt json
```

## Распространенные ловушки, которых следует избегать { #common-pitfalls-to-avoid }

| Ловушка | Описание | Предотвращение |
|---------|-------------|------------|
| **Решение - в первую очередь** | Переход к функциям, прежде чем разбираться в проблемах | Начинайте каждый PRD с постановки задачи |
| **Паралич анализа** | Чрезмерное исследование без доставки | Установите временные рамки для этапов исследования |
| ** Фабрика функций** | Особенности транспортировки без измерения воздействия | Определите показатели успеха перед созданием |
| **Игнорирование технического долга** | Не выделяет время для проверки работоспособности платформы | Зарезервируйте 20% мощности для технического обслуживания |
| **Сюрприз для стейкхолдеров** | Не выходит на связь рано и часто | Еженедельные асинхронные обновления, ежемесячные демонстрации |
| **Метрический театр** | Оптимизация показателей тщеславия по сравнению с реальной стоимостью | Привязать показатели к получаемой пользователем ценности |

## Лучшие практики { #best-practices }

**Написание отличных рекламных материалов:**
- Начните с проблемы, а не с решения
- Заранее включите четкие показатели успеха
- Явно укажите, что выходит за рамки
- Используйте визуальные элементы (каркасы, потоки, диаграммы).
- Сохраняйте технические подробности в приложении
- Контроль версий всех изменений

**Эффективная расстановка приоритетов:**
- Сочетайте быстрые выигрыши со стратегическими ставками
- Учитывайте альтернативные издержки задержек
- Учет зависимостей между объектами
- Резерв 20% для непредвиденной работы
- Ежеквартально пересматривайте приоритеты
- Связывать решения с контекстом

**Поиск клиентов:**
- Спросите "почему" пять раз, чтобы найти первопричину
- Сосредоточьтесь на прошлом поведении, а не на будущих намерениях
- Избегайте наводящих вопросов ("Разве тебе не понравилось бы...")
- Интервью в естественной среде пользователя
- Следите за эмоциональными реакциями (боль = возможность)
- Проверка качества с помощью количественных данных
