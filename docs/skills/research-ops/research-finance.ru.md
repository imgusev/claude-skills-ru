Финансовое управление внутренними программами и портфелями НИОКР: составление бюджета по программам с использованием F & A, отслеживание выгод / взлетно-посадочной полосы и распределение капитализации по расходам. Каждое число поставляется со своим блоком ** допущений **, а вызовы для обработки бухгалтерских данных ** направляются к указанному финансовому владельцу ** - этот скилл никогда не регистрирует запись.

## Цель { #purpose }

Партнеры по финансированию исследований и разработок, контролеры программ и руководители операций управляют деньгами, которые уже были выделены или привлечены — ни закрытием корпорации, ни следующим раундом финансирования, ни поиском гранта. Этот скилл формирует три повторяющихся решения:

Три детерминированных инструмента:

1. `program_budget_planner.py` — Строит бюджет на несколько периодов на основе позиций рабочего пакета, применяет ставку F & A (косвенную) к приемлемой базе в стиле MTDC и суммирует прямые / F & A / полностью загруженные затраты за период с блоком явных допущений.
2. `burn_runway_tracker.py` — Вычисляет среднее значение + итоговый расход, взлетно-посадочную полосу в периодах / месяцах и то, достижима ли каждая веха изменения стоимости до того, как закончатся денежные средства. Флаги ускоряющегося горения и взлетно-посадочной полосы ниже порогового значения.
3. `capex_vs_opex_router.py` — Оценивает каждую статью затрат на НИОКР в соответствии с критериями этапа разработки по МСФО (IAS) 38 (или помечает US GAAP ASC 730 "Расходы по мере возникновения") и направляет ее на **КАПИТАЛИЗАЦИЮ-КАНДИДАТ / РАСХОДЫ / ФИНАНСЫ-ВЛАДЕЛЕЦ-РЕВЬЮ** с указанным владельцем. Никогда не принимает автоматического решения.

## Когда использовать { #when-to-use }

Используйте этот скилл, когда:

- Вы разрабатываете или пересматриваете бюджет программы НИОКР, и вам необходимо четко указать распределение прибыли и убытков от продаж.
- Под вопросом взлетно-посадочная полоса программы, и вам нужно ознакомиться с соотношением вех и денежных средств.
- Финансы спрашивают, можно ли капитализировать затраты на разработку, и вам нужен обоснованный первый маршрут.
- Вы готовите ревью портфолио, и вам нужна согласованность записи для каждой программы.

**Не используйте этот скилл для**: запуска корпоративного DCF / оценки / закрытия (используйте `finance/financial-analysis`), обнаруживать или размещать гранты (использовать `research/grants`), или принять окончательное бухгалтерское решение (это вызов контролера + аудитора — этот инструмент выполняет только маршрутизацию).

## Воркфлоу { #workflow }

1. **Выложите программу** — Заполните `assets/rd_program_budget_template.md` со строками рабочего пакета, категориями и суммами за период.
2. **Составьте бюджет** — Запустите `program_budget_planner.py --input program.json --profile {pharma-rd|biotech|medtech|deep-tech|software-rd|university-lab} --fa-rate <negotiated rate>`. Прочитайте прямые / F& A / полностью загруженные сводные данные + предположения.
3. ** Выжигание трассы и взлетно—посадочная полоса ** - Запуск `burn_runway_tracker.py --input ledger.json --threshold-months 6`. Прочитайте взлетно-посадочную полосу + вердикты по вехам + флаги.
4. **Порядок учета маршрута** — Запуск `capex_vs_opex_router.py --input costs.json --standard {ifrs|usgaap}`. Прочитайте маршрутизацию для каждого элемента; отправьте элементы CAPITALIZE-CANDIDATE и FINANCE-OWNER-РЕВЬЮ указанному владельцу.
5. **Соберите ревью** — Объедините в пакет финансирования программы. Каждый номер содержит свои предположения; при вызовах на лечение указывается имя владельца.

## Онбординг и кастомизация { #onboarding--customization }

Запустите анкету для онбординга ** один раз перед началом работы ** — она фиксирует ваши настройки по умолчанию, поэтому каждый инструмент в этом скилле предварительно настроен. Суть в настройке: ответы на самом деле меняют поведение инструмента.

```bash
python3 scripts/onboard.py            # interactive (also: --defaults, --set key=value, --reset)
python3 scripts/onboard.py --show     # see the questions + current effective config
```

Ответы сохраняются в `~/.config/research-ops/research-finance.json` (глобальный) или `./.research-ops/research-finance.json` (`--scope project`) и считываются автоматически `config_loader.py`. Они устанавливают профиль области исследований и разработок ** по умолчанию**, ставку F&A по умолчанию**, порог оповещения о взлетно-посадочной полосе**, **стандарт бухгалтерского учета** и имя ** финансового владельца**, указанное в разделе "Капитализация против расходов". маршрутизация. Флаги CLI всегда переопределяют сохраненную конфигурацию; `RESEARCH_OPS_NO_CONFIG=1` игнорирует это.

## Оптимизация с помощью автоматического поиска (опция) { #optimize-with-autoresearch-opt-in }

Этот скилл предоставляет ** изолированный, согласованный** мост для `engineering/autoresearch-agent`. Только когда вы просите "оптимизировать" / "расширить взлетно-посадочную полосу" / "запустить цикл", эксперимент с автоматическим поиском итеративно улучшает план программы в соответствии с показателем взлетно-посадочной полосы этого скилла. `scripts/ar_evaluator.py` является основным средством оценки истинности; он печатает `runway_months: <float>` (чем выше, тем лучше).

```bash
/ar:setup --domain custom --name extend-runway \
  --target ledger.json \
  --eval "python3 ar_evaluator.py --target ledger.json" \
  --metric runway_months --direction higher
/ar:loop custom/extend-runway
```

Изолированный: нет жесткой зависимости — автоматический поиск выполняется только по требованию, а цикл редактируется `ledger.json`, но никогда не оценщик.

## Допущения { #assumptions }

- Показатель F&A - это наиболее подверженный ошибкам ввод. Планировщик применяет любой тариф, который вы пройдете; он предупреждает вас подтвердить, что это согласованный NICRA, а не предположение.
- Расход/взлетно-посадочная полоса использует итоговый (взвешенный по последнему времени) расход в качестве показателя форвардного пробега и предполагает фиксированные форвардные расходы, если только в вашей бухгалтерской книге не закодирован скачок.
- Маршрутизатор капитальных затрат утверждает критерии на основе ваших данных; утверждение о "технической осуществимости" не делает его истинным — указанный финансовый владелец и аудитор подтверждают это.
- Профили комментируют контекст (например, "большая часть исследований и разработок в области лекарств связана с расходами"), но не изменяют бухгалтерский тест.

## Анти-паттерны { #anti-patterns }

- **Указание бюджетной цифры без связанных с ней предположений.** Ставка F&A, эскалация и база должны указываться вместе с номером.
- ** Автоматическое определение соотношения капитализации и расходов.** Этот инструмент направляет; решение принимает контролер (и аудитор, где требуется).
- ** Для взлетно-посадочной полосы используется средний срок службы. ** Недавний пробег - это честный показатель пробега вперед; средние значения скрывают замедление или скачок.
- **Применение F&A к полной базе.** Капитальное оборудование, большие части вспомогательного оборудования и определенные категории освобождаются от MTDC.
- ** Путаю это с корпоративными финансами.** Оценка, закрытие и сбор средств происходят в `finance/`.


Примерный бюджет исключает секвенсор (капитальное оборудование) и субподряд CRO из базы F&A; маршрутизатор капитальных вложений направляет предварительный отбор на РАСХОДЫ, пилотную линию с полным критерием - на КАПИТАЛИЗАЦИЮ-КАНДИДАТА, а сборку программного обеспечения с частичным критерием - на ревью финансового ВЛАДЕЛЬЦА.

## Библиотека принудительных вопросов (дисциплина Matt Pocock grill) { #forcing-question-library-matt-pocock-grill-discipline }

Проходили по одному мимо `/cs:grill-research-ops` или оркестратор. Рекомендуемый ответ + цитата из канона на каждый вопрос. Никогда не упаковывался.

1. ** "Находятся ли эти затраты на стадии исследования или разработки — и можете ли вы подтвердить техническую осуществимость?"**
   Рекомендуется: исследование = расходы; разработка = капитализация - кандидат только с подтверждением технико-экономического обоснования, направляемым указанному финансовому владельцу.
   Канон: МСФО (IAS) 38.54-57; ASC 730.

2. ** "Какую ставку F &A / косвенную ставку вы применяете, и является ли это согласованной вами ставкой NICRA, минимальной ставкой в 10% или предположением?"**
   Рекомендуется: используйте согласованную ставку; если предполагается, укажите ее явно.
   Канон: 2 CFR 200 (единообразное руководство); Основы NICRA.

3. ** "Какова взлетно-посадочная полоса в месяцах при текущем расходе, и соответствует ли это следующему этапу изменения стоимости?"**
   Рекомендуется: взлетно-посадочная полоса должна закрывать веху плюс буфер; заделайте зазор.
   Канон: Cooper stage-гейт; SaaS/фреймворки для повышения эффективности стартапов (a16z, Bessemer).

4. ** "Является ли рентабельность инвестиций в портфель скорректированной с учетом риска (rNPV / взвешенная вероятность успеха) или сырой NPV?"**
   Рекомендуется: с поправкой на риск; исходный NPV завышает стоимость НИОКР.
   Канон: оценка rNPV при разработке лекарств; литература по реальным опционам.

5. ** "Кто является названным владельцем финансового отдела / контролером, который подписывает порядок учета капитализации по сравнению с расходами?"**
   Рекомендуется: назовите их — этот инструмент рекомендует, он никогда не регистрирует запись.
   Канон: ASC 730 / МСФО (IAS) 38 "Управление"; требования к подписанию аудитором.

Сначала пройдите вглубь. Зафиксируйте 1-2 перед открытием 3-5. После того, как на все будут даны ответы, вызовите `program_budget_planner.py` → `burn_runway_tracker.py` → `capex_vs_opex_router.py`.
