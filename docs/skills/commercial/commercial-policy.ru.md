## Цель { #purpose }

Разработайте ** правила взаимодействия**, которые регулируют дисконтирование от прейскурантной цены — артефакт, в соответствии с которым работают Deal Desk и AEs. Три детерминированных инструмента:

1. `discount_matrix_builder.py` — строит 4-мерную матрицу (диапазон ARR × продолжительность срока × условия оплаты × уровень стратегической ценности), в каждой ячейке которой указан утвержденный диапазон скидок, подкрепленный текущими данными о коэффициенте выигрыша + NRR, плюс уровень утверждающего (AE / менеджер / директор / вице-президент / финансовый директор).
2. `exception_router.py` — когда запрос на скидку попадает за пределы матрицы, направляет его по именованной цепочке утверждающих, присоединяет необходимые компенсирующие обязательства (многолетняя предоплата + именованный путь расширения + справочное обязательство + ужесточение MSA), создает машиночитаемые метаданные отслеживания аудита и помечает риск прецедента, если более 3 аналогичных исключений приземлились в последней четверти.
3. `policy_linter.py` — заполняет матрицу дефектов управления: инверсия утверждающего, инверсия диапазона, нарушение минимального уровня маржи, пробелы в покрытии, края обрыва, неопределенные стратегические уровни, несогласованные минимальные уровни маржи, тонкая база данных.

Результатом является сама политика *** (матрица + поток исключений + отчет о линте), а не ее применение для каждой сделки.

## Когда использовать { #when-to-use }

- Новый руководитель коммерческого отдела или руководитель отдела заключения сделок разрабатывает первую официальную коммерческую политику компании
- Существующая матрица старше 6 месяцев, и в ревью наценок отображается разница в скидках
- Представители ссылаются на "Мария одобрила 28% акций Acme в прошлом квартале" как на прецедент, и вам нужно разорвать цикл прецедентов
- Количество исключений Q-over-Q увеличивается, и вы подозреваете, что матричные диапазоны оценены неправильно
- Финансовый директор ужесточил минимальный уровень маржи, и матрицу необходимо перестроить с учетом новых ограничений
- Правление / исполнительный директор спрашивает: "Почему мы делаем такие большие скидки?", а вам нужна обоснованная политика, основанная на данных

**Не используйте этот скилл для:**
- Одобрить конкретную сделку — это `commercial/skills/deal-desk`
- Установите модель ценообразования + прейскурантную цену — это `commercial/skills/pricing-strategist`
- Автор предложения / SOW / MSA prose — это `business-growth/contract-and-proposal-writer`
- Сделайте стратегический звонок "когда мы наймем вице—президента по продажам" - это `c-level-advisor/cro-advisor`

## Воркфлоу { #workflow }

1. **Аудит текущего распределения скидок.** Извлеките из CRM данные о закрытых выигранных сделках за последние 4 квартала + закрытых проигранных сделках. Заполнять `assets/policy_design_template.md` (~20 минут). Захват: `arr`, `discount_pct`, `term_months`, `payment_terms_days`, `strategic_value`, `win_lost`, `nrr_12mo` за каждую сделку.

2. ** Спроектируйте матрицу с поддержкой данных.** Запустите `scripts/discount_matrix_builder.py --input policy_intake.json --profile {saas|enterprise-software|api|marketplace|services}`. Результатом является 4-мерная матрица с утвержденным диапазоном скидок + уровнем утверждающего + минимальным уровнем маржи + наблюдаемым коэффициентом выигрыша + наблюдаемым NRR на ячейку. Ячейки с `n < 5` наблюдаемые сделки помечаются `THIN`.

3. **Спроектируйте поток исключений.** Запустите `scripts/exception_router.py --sample` чтобы увидеть структуру. Для каждого диапазона серьезности исключения (0-5 пунктов выше, 5-10, 10-20, 20+) маршрутизатор выполняет требуемые компенсационные обязательства. Кодифицируйте поток в вашем документе о политике; маршрутизатор становится операционной реализацией.

4. **Смажьте матрицу.** Запустите `scripts/policy_linter.py --input matrix.json`. Получите ранжированный отчет о результатах — БЛОКИРУЮЩИЙ / ОСНОВНОЙ / ВТОРОСТЕПЕННЫЙ — по 10 правилам lint. Устраните все БЛОКИРОВКИ перед публикацией матрицы в AEs.

5. ** Публикация + ежеквартальный ревью.** Опубликуйте матрицу как версионный артефакт. Повторно запускайте builder и linter каждый квартал в соответствии с новым сводом скользящих сделок на 4 квартала. Ячейки, в которых наблюдается NRR < `target_nrr` помечены для ревью.

## Сценарии { #scripts }

| Сценарий | Цель | Отраслевые профили |
|---|---|---|
| `scripts/discount_matrix_builder.py` | матрица с поддержкой данных 4-dim с уровнями утверждения + минимальными полями полей | saas, корпоративное программное обеспечение, api, маркетплейс, сервисы |
| `scripts/exception_router.py` | Направляет запросы на исключение с компенсирующими обязательствами + журнал аудита | n/a (управляемый матрицей) |
| `scripts/policy_linter.py` | 10-правило прохождения ворса по матрице | n/a (детерминированный для всех профилей) |

Все три: только для stdlib, `--help`, `--sample`, `--input <json>`, `--output {markdown,json}`.

## Допущения { #assumptions }

- Скилл предполагает, что ** модель ценообразования и прейскурантная цена уже существуют** (устанавливаются с помощью `commercial/skills/pricing-strategist`). Коммерческая политика регулирует ** скидки вне списка** — она не устанавливает список.
- Финансовый директор владеет `min_margin_pct` ограничение (минимальный размер маржи). Операционный директор / руководитель отдела сделок владеет `max_discount_pct_without_exception` ограничение (ограничитель полосы). Скилл позволяет разделить эти входные данные по замыслу (в соответствии с Bain * Ценовая власть* — смешение подотчетности является наиболее распространенной причиной смещения политики).
- Промышленные профили выпекаются с *обычной* шириной полос. Компаниям с особенной экономикой следует передавать переопределения через входной JSON.
- Матрица поддерживается данными, но ** не управляется данными**: диапазон задается ограничениями + профилем; наблюдаемые данные - это аннотация, которая сообщает вам, работает ли ячейка. Если наблюдается NRR < цель, это сигнал к **ревью диапазона**, а не к продолжению более глубокого дисконтирования.
- Уровни "стратегической ценности" (`logo`, `expansion`, `lighthouse`) полезны только в том случае, если определены с помощью конкретных тестов. Правило lint L06 обеспечивает соблюдение этого правила.
- Это скилл для разработки политики, а не скилл для одобрения сделки. В нем никогда не говорится "одобрить" — он создает матрицу + поток исключений, который затем применяется **deal-desk**.

## Анти-паттерны { #anti-patterns }

- ** Установка диапазонов скидок без поддержки данных. ** "Вице-президент по продажам высказался за это в теме Slack" не является поддержкой данных. Если вы не можете показать винрейт и NRR для группы, то группа - это риторика. (Пойманный `data_backing` на ячейку + ворсинка L08.)
- ** Позволяем прецеденту определять политику.** "Мария одобрила 28% акций Acme в прошлом квартале" — это не группа, это исключение, которое не нарушило политику. `exception_router.py` помечает 3+ подобных исключения как сигнал о том, что ** матрица неверна**, а не сделка. (Анти-паттерн AP-1.)
- **Утверждение исключений без компенсационных обязательств.** Скидка ни за что - это утечка информации (выигрыш по замыслу). Каждый диапазон серьезности исключений требует обязательств, не подлежащих обсуждению. (`exception_router.COMPENSATING_LIBRARY`.)
- ** При пороговых значениях ARR в круглых числах края обрыва. ** Жесткий порог в 100 тысяч долларов приводит к заключению крупных сделок в течение 2 кварталов (теория агентства MIT Sloan). Сгладьте градиент. (Ворсинка L05.)
- ** "Стратегическая ценность" как неопределенный общий параметр. ** Если "стратегическая" не определена, то в течение квартала 60% сделок будут помечены как стратегические, и матрица будет закрыта. Определите с помощью конкретных тестов. (Ворсинка L06.)
- **Нет ежеквартального ревью.** Рынки меняются; матрицы, не менявшиеся в течение 12 месяцев, оцениваются неправильно. Повторно запускайте конструктор и линтер каждый квартал. (Анти-паттерн AP-8.)
- ** Смешение ответственности финансового директора и CRO.** Финансовому директору принадлежит минимальный уровень маржи; CRO владеет пределом диапазона. Один и тот же подотчетный владелец = предсказуемый переход к тому, за что они получают компенсацию (Bain * Ценовая власть *).
- ** Пропуск пропуска lint перед публикацией.** Результаты блокировки (инверсия утверждающего, нарушение минимального значения полей, перевернутые полосы) делают политику неподписываемой. Линт - это гейт, а не ревью после действия.

## Библиотека принудительных вопросов (дисциплина Matt Pocock grill) { #forcing-question-library-matt-pocock-grill-discipline }

Проходили по одному мимо `/cs:grill-commercial` или коммерческий оркестратор перед запуском скилла. Рекомендуемый ответ + цитата из канона на каждый вопрос. Никогда не упаковывался.

1. ** "Каково наблюдаемое вами распределение скидок за последние 4 квартала — и находится ли медиана внутри или за пределами вашей текущей матрицы?"**
   Рекомендуется: потяните корпус, прежде чем создавать какую-либо ленту. Если наблюдаемая медиана находится за пределами матрицы, то матрица является риторической.
   Канон: Тесты OpenView SaaS; обновляет плейбуки для совместной работы. Анти-паттерн AP-2.

2. ** "Каков коэффициент выигрыша И 12-месячный NRR для сделок в вашем текущем диапазоне "максимальной скидки"?"**
   Рекомендуется: оба, а не один. Группа с высоким коэффициентом выигрыша, но низким NRR покупает логотипы с сохранением "дырявого ведра". Показатели Тунгуза: компании из верхнего квартиля NRR делают скидку на 6 пунктов меньше, чем из нижнего квартиля.
   Канон: Томаш Тунгуз; "Облачное состояние Бессемера".

3. ** "Кто в компании владеет минимальным уровнем маржи И кто владеет предельным диапазоном скидок - это один и тот же человек?"**
   Рекомендуется: Финансовый директор владеет этажом; CRO/руководитель отдела сделок владеет cap. Один и тот же владелец = смещается в сторону того, за что им выплачивается компенсация.
   Канон: Bain *Ценовая власть* — разделение ответственности является структурным решением. Анти-паттерн AP-4.

4. ** "Как определяется "стратегическая ценность" в вашей текущей политике — с помощью конкретных тестов или прилагательных?"**
   Рекомендуется: испытания на бетон. "Топ-20 именованных аккаунтов в целевом списке 2026 года" - это тест; "важный клиент" - нет.
   Канон: СааСтр (Лемкин); Forrester deal-desk research. Правило удаления ворса L06. Анти-паттерн AP-7.

5. ** "Для исключений, превышающих ваш максимальный размер матрицы, какие компенсационные обязательства требуются — и оформляются ли они в письменной форме до подписания утверждающим лицом?"**
   Рекомендуется: минимальная многолетняя предоплата + названный путь расширения; для более серьезных исключений требуется справочное обязательство + ужесточение MSA + исполнительный спонсор.
   Канон: Победа за счет дизайна (Ван дер Коой); исследования ценообразования McKinsey в сфере B2B. Анти-паттерн AP-3.

6. ** "Было ли такое же исключение одобрено более 3 раз за последний квартал — и если да, то неверна ли матрица?"**
   Рекомендуется: более 3 подобных исключений означают, что группа оценена неправильно. Перестройте матрицу заново; не продолжайте утверждать исключения.
   Канон: исследования дрейфа скидок OpenView; `exception_router._precedent_risk`. Анти-паттерн AP-1.

7. ** "Когда вы в последний раз повторно прогоняли матрицу по данным за предыдущие 4 квартала?"**
   Рекомендуется: ежеквартально. Ежегодный ревью проводится слишком медленно; дисциплинированная группа пересматривает его ежеквартально.
   Канон: тесты OpenView; Совместная работа по обновлению. Анти-паттерн AP-8.

8. ** "Для каждого исключения за последний квартал существует ли машиночитаемая запись в журнале аудита - или утверждение осуществляется в Slack и по электронной почте?"**
   Рекомендуется: структурированная запись в CPQ или эквиваленте. Утверждения Slack / по электронной почте не выдерживают переговоров о продлении на 2 года.
   Канон: Лучшие практики Salesforce CPQ; исследование зрелости отдела сделок Forrester. Анти-паттерн AP-5.

Сначала пройдите вглубь. Зафиксируйте 1-4 перед открытием 5-8. После того, как будут даны ответы на все 8 вопросов, вызовите `discount_matrix_builder.py` → `policy_linter.py` → `exception_router.py --sample` в последовательности для создания артефакта политики.

## Краткие примеры { #quick-examples }

```bash
# Design the matrix
python3 scripts/discount_matrix_builder.py --sample
python3 scripts/discount_matrix_builder.py --input policy_intake.json --profile saas --output json > matrix.json

# Lint the matrix
python3 scripts/policy_linter.py --sample
python3 scripts/policy_linter.py --input matrix.json

# Walk the exception flow
python3 scripts/exception_router.py --sample
python3 scripts/exception_router.py --input request.json --output json
```

Матрица выборки приводит к ** СБОЮ ** с 4 блокирующими + 6 основными + 2 второстепенными — по замыслу, для выполнения каждого пути правила. Реальный ввод политики должен быть связан с PASS или PASS_WITH_WARNINGS. Исключение в виде примера (42% при сделке с логотипом стоимостью 320 тыс. долл.) распространяется на AE → Менеджера по продажам → директора → вице-президента по продажам с тремя обязательными компенсационными обязательствами (многолетний контракт на 36 месяцев, предоплата, именованный путь расширения).
