## Обзор { #overview }

Проанализируйте кодовую базу и сгенерируйте документацию по онбордингу для инженеров, технических руководителей и подрядчиков. Этот скилл оптимизирован для быстрого сбора фактов и повторяемых результатов онбординга.

## Основные возможности { #core-capabilities }

- Обнаружение архитектуры и стека по сигналам репозитория
- Список ключевых файлов и конфигураций для новых участников
- Локальная настройка и генерация рекомендаций по общим задачам
- Создание документации, ориентированной на аудиторию
- Чек-лист для отладки и внесения вклада в строительные леса

---

## Когда использовать { #when-to-use }

- Онбординг нового члена команды или подрядчика
- Восстановление устаревших проектных документов после крупных рефакторингов
- Подготовка внутренней документации по хэндоффу
- Создание стандартизированного пакета онбординга для служб

---

## Быстрый старт { #quick-start }

```bash
# 1) Gather codebase facts
python3 scripts/codebase_analyzer.py /path/to/repo

# 2) Export machine-readable output
python3 scripts/codebase_analyzer.py /path/to/repo --json

# 3) Use the template to draft onboarding docs
# See references/onboarding-template.md
```

---

## Рекомендуемый воркфлоу { #recommended-workflow }

1. Бежать `scripts/codebase_analyzer.py` в целевом репозитории.
2. Фиксируйте ключевые сигналы: количество файлов, обнаруженные языки, конфигурационные файлы, структуру верхнего уровня.
3. Заполните шаблон для онбординга в `references/onboarding-template.md`.
4. Адаптируйте глубину вывода в зависимости от аудитории:
   - Младший: установка + защитные барьеры
   - Старший: архитектура + операционные проблемы
   - Подрядчик: ограниченный объем владения + границы интеграции

## Распространенные подводные камни { #common-pitfalls }

- Написание документов без проверки команд установки в чистой среде
- Смешивание архитектуры - глубокое погружение в документы, ориентированные на подрядчика
- Пропуск этапов устранения неполадок и проверки
- Позволяя документам для онбординга отклоняться от текущего состояния репозитория

## Лучшие практики { #best-practices }

1. Сохраняйте инструкции по настройке исполняемыми и ограниченными по времени.
2. Задокументируйте "почему" для ключевых архитектурных решений.
3. Обновляйте документы в том же PR-режиме, что и изменения в поведении.
4. Относитесь к документам по онбордингу как к живому операционному активу, а не как к разовым результатам.
