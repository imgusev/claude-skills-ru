Разрабатывайте полные, надежные пайплайны для извлечения данных с интеллектуальной маршрутизацией, валидацией и отслеживанием бюджета токенов, а не хрупкие одноразовые сценарии.

** Уведомление о зависимостях:** Шаблон BYOK (Принесите свой собственный ключ) для Firecrawl; Ключи API должны загружаться только через переменные окружения. Зависимости для каждого сценария:

| Сценарий | Зависимости | Точный CLI |
|---|---|---|
| `scripts/validate_extraction.py` | только stdlib | `python3 scripts/validate_extraction.py output.json --json` |
| `scripts/firecrawl_example.py` | `firecrawl`, `requests` (шаблон; `--sample` работает в автономном режиме) | `python3 scripts/firecrawl_example.py --sample` |
| `scripts/local_bs4_example.py` | `beautifulsoup4`, `pandas` (шаблон; `--sample` работает в автономном режиме) | `python3 scripts/local_bs4_example.py --sample` |

## Как работает этот Скилл { #how-this-skill-works }

Этот скилл поддерживает 3 режима извлечения, основанные на интеллектуальной маршрутизации:

### Режим 1: Управляемый API (Firecrawl) { #mode-1-api-driven-firecrawl }
Используйте, когда источником является общедоступный URL-адрес, сильно динамичный (JS/SPA), требующий обнаружения с помощью первого поиска или предполагающий массовый обход домена.
### Режим 2: Локальный Python (традиционный) { #mode-2-local-python-traditional }
Используйте при извлечении из локальных файлов (PDF, Excel, CSV), данные являются частными / конфиденциальными, или целью является простая статическая HTML-страница, где Firecrawl является излишним.
### Режим 3: Гибридный пайплайн { #mode-3-hybrid-pipeline }
Используйте, когда Firecrawl обрабатывает обнаружение URL-адресов / веб-извлечение, но для очистки, нормализации и структурирования выходных данных перед сохранением требуется локальный Python (Pandas).

## Пайплайн для извлечения { #the-extraction-pipeline }

При выполнении задачи очистки всегда следуйте этой последовательности:
1. ** Направьте подход:** Явно укажите, используется ли Firecrawl или локальный Python и почему.
2. ** Отслеживание бюджетов:** Оцените квоты Firecrawl API или ограничения контекста токена LLM перед выполнением крупных заданий. 
3. ** Безопасное извлечение:** Внедрите контрольные точки для многостраничных заданий. Изящно обрабатывайте разбиение на страницы и динамические макеты. Начните с редактируемых шаблонов runner — `scripts/firecrawl_example.py` (Режим 1) или `scripts/local_bs4_example.py` (Режим 2); запустите каждый из них с `--sample` сначала нужно увидеть ожидаемую сводную форму без доступа к сети.
4. ** Проверка и очистка:** Запуск `python3 scripts/validate_extraction.py extracted_output.json --json` о каждом результате извлечения перед его отправкой. Он выходит из 0 только при `{"status": "ok"}`; `warning` (пустой вывод) или `error` (искаженный JSON) выход 1 — исправьте и повторно извлеките, никогда не отправляйте непроверенные данные. Помимо этого структурного гейта, перед отправкой также проверьте обязательные поля и дубликаты в соответствии со спецификацией пайплайна.
5. **Формат:** По умолчанию используется CSV для табличных данных, JSON для вложенных структур и Markdown для чистого текста.

## Проактивные триггеры { #proactive-triggers }

Выявляйте эти проблемы, НЕ спрашивая, когда вы замечаете их в контексте:
- **Жестко закодированные ключи API** → Немедленно отметьте и перепишите для использования `os.getenv('FIRECRAWL_API_KEY')`.
- **Утечка личных данных** → Если пользователь просит отправить локальные конфиденциальные файлы во внешний API, отметьте риск конфиденциальности и предложите режим 2 (локальный Python).
- **Отсутствует разбивка на страницы** → Если цель подразумевает сотни записей, но логика разбивки на страницы не запрашивается, отметьте это и добавьте контрольную точку.

## Анти-паттерны { #anti-patterns }
- **Хрупкие селекторы:** Никогда не используйте сильно вложенные CSS-селекторы (например, `div > span > ul > li:nth-child(3)`). Используйте атрибуты данных или надежные структурные привязки.
- ** Игнорирование этикета:** Никогда не скребите, не проверив `robots.txt` или введение разумных ограничений по ставкам.
- ** Без проверки:** Никогда вслепую не записывайте очищенные данные в файл, не проверив, пуст ли массив или отсутствуют критические ключи.
