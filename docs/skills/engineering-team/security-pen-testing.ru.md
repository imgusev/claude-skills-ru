## Обзор { #overview }

### Что делает этот Скилл { #what-this-skill-does }

Этот скилл предоставляет методологию, чек—листы и автоматизацию для **наступательного тестирования безопасности** - активного зондирования систем с целью обнаружения уязвимостей, которые можно использовать. Она охватывает веб-приложения, API-интерфейсы, инфраструктуру и безопасность цепочки поставок.

### Отличие от других Скилл по обеспечению безопасности { #distinction-from-other-security-skills }

| Скилл | Сосредоточься | Подход |
|-------|-------|----------|
| **безопасность-ручное тестирование** (это) | Поиск уязвимостей | Наступление — имитация приемов атакующего |
| старший-secops | Операции по обеспечению безопасности | Защита — мониторинг, реагирование на инциденты, SIEM |
| старший-служба безопасности | Политика безопасности | Управление — политика, фреймворки, реестры рисков |
| скилл-безопасность-аудитор | Гейты CI/CD | Автоматическая проверка безопасности перед объединением |

### Предварительные условия { #prerequisites }

Все описанное здесь тестирование предполагает **письменное разрешение** от владельца системы. Несанкционированное тестирование является незаконным в соответствии с CFAA и аналогичными законами по всему миру. Перед началом работы всегда получайте подписанный документ с описанием объема работ или правил взаимодействия.

## Статический анализ { #static-analysis }

**Рекомендуемые инструменты:** CodeQL (пользовательские запросы для шаблонов, специфичных для проекта), Semgrep (сканирование на основе правил с автоматическим исправлением), плагины безопасности ESLint (`eslint-plugin-security`, `eslint-plugin-no-unsanitized`).

Ключевые шаблоны для обнаружения: SQL-инъекция с помощью конкатенации строк, жестко закодированные секреты JWT, небезопасная десериализация YAML/pickle, отсутствие промежуточного программного обеспечения безопасности (например, Express без шлема).

Видишь [attack_patterns.md](https://github.com/imgusev/claude-skills-ru/tree/main/engineering-team/skills/security-pen-testing/references/attack_patterns.md) для получения шаблонов кода и полезной нагрузки обнаружения в разных типах инъекций.

## Сканирование уязвимостей зависимостей { #dependency-vulnerability-scanning }

**Команды экосистемы:** `npm audit`, `pip audit`, `govulncheck ./...`, `bundle audit check`

**Воркфлоу для сортировки CVE:**
1. **Сбор** — Запуск инструментов аудита экосистемы, обобщение результатов
2. **Дедуплицировать** — Группировать по идентификатору CVE в прямых и транзитивных deps
3. ** Расставить приоритеты** — Критично + пригодно для использования + достижимо = исправить немедленно
4. **Исправлять** — Обновлять, исправлять или смягчать последствия с помощью компенсирующих элементов управления
5. **Проверить** — Повторно запустить аудит для подтверждения исправления, обновления файлов блокировки

```bash
python scripts/dependency_auditor.py --file package.json --severity critical --json
```

## Секретное сканирование { #secret-scanning }

** Инструменты:** TruffleHog (история git + файловая система), Gitleaks (на основе регулярных выражений с пользовательскими правилами).

```bash
# Scan git history for verified secrets
trufflehog git file://. --only-verified --json

# Scan filesystem
trufflehog filesystem . --json
```

**Точки интеграции: ** Перехватчики предварительной фиксации (gitleaks, trufflehog), гейты CI/CD (действия на GitHub с `trufflesecurity/trufflehog@main`). Настройте `.gitleaks.toml` для пользовательских правил (ключи AWS, ключи API, заголовки закрытых ключей) и списков разрешений для тестовых приложений.

## Тестирование безопасности API { #api-security-testing }

### Обход аутентификации { #authentication-bypass }

- **Манипуляция JWT:** Изменение `alg` к `none`, Путаница между RS256 и HS256, изменение формулы изобретения (`role: "admin"`, `exp: 9999999999`)
- ** Фиксация сеанса:** Проверьте, изменяется ли идентификатор сеанса после аутентификации

### Недостатки авторизации { #authorization-flaws }

- **IDOR/BOLA:** Изменяйте идентификаторы ресурсов в каждой конечной точке — тестируйте чтение, обновление, удаление у всех пользователей
- **BFLA:** Обычный пользователь пробует конечные точки администратора (ожидается 403)
- **Массовое назначение:** Добавление привилегированных полей (`role`, `is_admin`) для обновления запросов

### Ограничение скорости и GraphQL { #rate-limiting--graphql }

- ** Ограничение скорости:** Быстрые запросы к конечным точкам аутентификации; ожидайте 429 после порогового значения
- ** GraphQL:** Тестовый самоанализ (должен быть отключен в prod), атаки на глубину запроса, пакетные мутации в обход ограничений скорости

Видишь [attack_patterns.md](https://github.com/imgusev/claude-skills-ru/tree/main/engineering-team/skills/security-pen-testing/references/attack_patterns.md) для получения полной полезной нагрузки по манипулированию JWT, методологии тестирования IDOR, списков конечных точек BFLA, шаблонов самоанализа/ глубины /пакетной атаки GraphQL и методов обхода с ограничением скорости.

## Тестирование веб-уязвимостей { #web-vulnerability-testing }

| Уязвимость | Ключевые тесты |
|--------------|-----------|
| **XSS** | Отраженный (полезная нагрузка script/img/svg), сохраненный (постоянные поля), основанный на DOM (innerHTML + location.hash) |
| **CSRF** | Повтор без токена (ожидайте 403), повтор токена между сеансами, проверьте атрибут cookie того же сайта |
| **SQL-инъекция** | Основанный на ошибках (`' OR 1=1--`), подсчет на основе объединения, слепой подсчет на основе времени (`SLEEP(5)`), слепой на основе логических значений |
| **SSRF** | Внутренние IP-адреса, конечные точки облачных метаданных (AWS/GCP/Azure), обходы IPv6/шестнадцатеричного/десятичного кодирования |
| **Прохождение пути** | [`etc/passwd`](https://github.com/imgusev/claude-skills-ru/tree/main/etc/passwd), Кодировка URL, обход двойного кодирования |

Видишь [attack_patterns.md](https://github.com/imgusev/claude-skills-ru/tree/main/engineering-team/skills/security-pen-testing/references/attack_patterns.md) для полной тестовой полезной нагрузки (обход фильтра XSS, контекстно-зависимый XSS, внедрение SQL для каждого компонента database engine, методы обхода SSRF и пары XSS-источник/приемник на основе DOM).

## Безопасность инфраструктуры { #infrastructure-security }

**Проверка ключей:**
- ** Облачное хранилище:** Общедоступный доступ к корзине S3 (`aws s3 ls s3://bucket --no-sign-request`), групповые политики, списки управления доступом
- **Заголовки безопасности HTTP:** HSTS, CSP (нет `unsafe-inline`/`unsafe-eval`), X-Content-Type-Options, X-Frame-Options, Политика ссылки
- **Конфигурация TLS:** `nmap --script ssl-enum-ciphers -p 443 target.com` или `testssl.sh` — отклонять TLS 1.0/1.1, RC4, 3DES, экспортные шифры
- **Сканирование портов:** `nmap -sV target.com` — помечать опасные открытые порты (FTP/21, Telnet/23, Redis/6379, MongoDB/27017)

## Создание отчета о тестировании пера { #pen-test-report-generation }

Создавайте профессиональные отчеты на основе структурированных результатов:

```bash
# Generate markdown report from findings JSON
python scripts/pentest_report_generator.py --findings findings.json --format md --output report.md

# Generate JSON report
python scripts/pentest_report_generator.py --findings findings.json --format json --output report.json
```

### Результаты в формате JSON { #findings-json-format }

```json
[
  {
    "title": "SQL Injection in Login Endpoint",
    "severity": "critical",
    "cvss_score": 9.8,
    "cvss_vector": "CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H",
    "category": "A03:2021 - Injection",
    "description": "The /api/login endpoint is vulnerable to SQL injection via the email parameter.",
    "evidence": "Request: POST /api/login {\"email\": \"' OR 1=1--\", \"password\": \"x\"}\nResponse: 200 OK with admin session token",
    "impact": "Full database access, authentication bypass, potential remote code execution",
    "remediation": "Use parameterized queries. Replace string concatenation with prepared statements.",
    "references": ["https://cwe.mitre.org/data/definitions/89.html"]
  }
]
```

### Структура отчета { #report-structure }

1. ** Краткое изложение**: Влияние на бизнес, общий уровень риска, топ-3 результатов
2. **Область применения**: Что было протестировано, что было исключено, даты тестирования
3. **Методология**: Используемые инструменты, подход к тестированию (черный/серый/белый прямоугольник)
4. ** Таблица результатов**: Отсортировано по степени тяжести с использованием оценок CVSS
5. ** Подробные выводы**: Каждый с описанием, доказательствами, воздействием, мерами по исправлению
6. **Матрица приоритетов исправления**: Соотношение усилий и воздействия для каждого исправления
7. **Приложение**: Исходные данные инструмента, полные списки полезной нагрузки

## Ответственный воркфлоу по раскрытию информации { #responsible-disclosure-workflow }

Ответственное раскрытие информации является ** обязательным** в отношении любой уязвимости, обнаруженной в ходе авторизованного тестирования. Стандартный график: отчет на 1-й день, последующие действия на 7-й день, обновление статуса на 30-й день, публичное раскрытие на 90-й день.

** Ключевые принципы: ** Никогда не используйте что-либо, выходящее за рамки проверки концепции, шифруйте все сообщения, не получайте доступа к реальным пользовательским данным, документируйте все с помощью временных меток.

Видишь [responsible_disclosure.md](https://github.com/imgusev/claude-skills-ru/tree/main/engineering-team/skills/security-pen-testing/references/responsible_disclosure.md) для получения полной информации о сроках раскрытия (стандартный 90-дневный, ускоренный 30-дневный, расширенный 120-дневный), шаблонах сообщений, юридических соображениях, интеграции программы вознаграждения за ошибки и процессе запроса CVE.

## Воркфлоу { #workflows }

### Воркфлоу 1: Быстрая проверка безопасности (15 минут) { #workflow-1-quick-security-check-15-minutes }

Для ревью перед объединением или быстрой проверки работоспособности:

```bash
# 1. Generate OWASP checklist
python scripts/vulnerability_scanner.py --target web --scope quick

# 2. Scan dependencies
python scripts/dependency_auditor.py --file package.json --severity high

# 3. Check for secrets in recent commits
# (Use gitleaks or trufflehog as described in Secret Scanning section)

# 4. Review HTTP security headers
curl -sI https://target.com | grep -iE "(strict-transport|content-security|x-frame|x-content-type)"
```

**Решение**: При обнаружении каких-либо критических или важных результатов заблокируйте слияние.

### Воркфлоу 2: Полный тест на проникновение (многодневная оценка) { #workflow-2-full-penetration-test-multi-day-assessment }

**День 1 — Разведка:**
1. Сопоставьте поверхность атаки: конечные точки, потоки аутентификации, сторонние интеграции
2. Запустите автоматический чек-лист OWASP (полный объем)
3. Запустите аудит зависимостей во всех манифестах
4. Запустите секретное сканирование по полной истории git

**День 2 — Ручное тестирование:**
1. Тестовая аутентификация и авторизация (IDOR, BOLA, BFLA)
2. Тестовые точки ввода (SQLi, XSS, SSRF, ввод команд)
3. Тестируйте недостатки бизнес-логики
4. Тестирование уязвимостей, специфичных для API (GraphQL, ограничение скорости, массовое назначение)

**День 3 — Инфраструктура и отчетность:**
1. Проверьте разрешения для облачного хранилища
2. Проверьте конфигурацию TLS и заголовки безопасности
3. Проверка портов на наличие ненужных служб
4. Скомпилируйте результаты в структурированный JSON
5. Сгенерировать отчет об испытании пера

```bash
# Generate final report
python scripts/pentest_report_generator.py --findings findings.json --format md --output pentest-report.md
```

### Воркфлоу 3: Гейт безопасности CI/CD { #workflow-3-cicd-security-gate }

Автоматизированная проверка безопасности каждого PR: секретное сканирование (TruffleHog), аудит зависимостей (`npm audit`, `pip audit`), SAST (Semgrep с `p/security-audit`, `p/owasp-top-ten`), и проверка заголовков безопасности на промежуточном этапе.

** Политика гейта**: Блокируйте слияние при критических/высоких результатах. Предупредите на среднем уровне. Низкий уровень журнала/информация.

## Анти-паттерны { #anti-patterns }

1. ** Тестирование в рабочей среде без авторизации ** — Всегда получайте письменное разрешение и по возможности используйте промежуточные/тестовые среды
2. **Игнорирование результатов с низкой степенью серьезности** — Низкие результаты усугубляются; цепочка минимумов может стать критическим путем для эксплойта
3. ** Отказ от ответственного раскрытия информации** — О каждой обнаруженной уязвимости необходимо сообщать по надлежащим каналам
4. ** Полагаясь исключительно на автоматизированные инструменты** — Инструменты упускают недостатки бизнес-логики, цепные эксплойты и новые векторы атак
5. ** Тестирование без определенной области применения** — Нарушение области применения приводит к юридической ответственности; документируйте, что входит в область применения, а что нет.
6. **Отчетность без рекомендаций по устранению неполадок** — Каждое обнаружение должно включать в себя действенные шаги по устранению неполадок
7. ** Небезопасное хранение доказательств ** — Данные ручного тестирования (скриншоты, полезные нагрузки, токены) являются конфиденциальными; шифруйте и ограничивайте доступ
8. ** Одноразовое тестирование** — Тестирование безопасности должно быть непрерывным; интегрируйте в CI/CD и планируйте периодические оценки
