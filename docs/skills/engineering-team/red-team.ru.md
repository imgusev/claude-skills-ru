## Обзор { #overview }

### Что делает этот Скилл { #what-this-skill-does }

Этот скилл предоставляет методологию и инструменты для ** планирования взаимодействия red team** — построения структурированных планов атак на основе выбора техники MITRE ATT&CK, уровня доступа и целей crown jewel. Он оценивает методы по трудозатратам и риску обнаружения, собирает этапы цепочки уничтожения, определяет ограничивающие точки и помечает риски OPSEC.

### Отличие от других Скилл по обеспечению безопасности { #distinction-from-other-security-skills }

| Скилл | Сосредоточься | Подход |
|-------|-------|----------|
| **красная команда** (это) | Имитация противника | Наступление — структурированное планирование и выполнение атаки |
| безопасность-ручное тестирование | Обнаружение уязвимости | Наступление — систематическое использование конкретных слабых мест |
| обнаружение угроз | Обнаружение активности злоумышленника | Проактивное — обнаружение TTP в телеметрии |
| реагирование на инцидент | Активное управление инцидентами | Реагирование — сдерживание и расследование подтвержденных инцидентов |

### Требование к авторизации { #authorization-requirement }

**Все действия red team, описанные здесь, требуют письменного разрешения.** Это включает подписанный документ о правилах взаимодействия (RoE), определенную сферу применения и четкое одобрение руководства. Тот `engagement_planner.py` инструмент не будет генерировать выходные данные без `--authorized` флаг. Несанкционированное использование этих методов является незаконным в соответствии с CFAA, Законом о неправомерном использовании компьютеров и аналогичными законами по всему миру.

## Инструмент для планирования взаимодействия { #engagement-planner-tool }

Тот `engagement_planner.py` инструмент создает оцененный план атаки с упорядоченной цепочкой убийств на основе выбора техники, уровня доступа и целей с драгоценными камнями короны.

```bash
# Basic engagement plan — external access, specific techniques
python3 scripts/engagement_planner.py \
  --techniques T1059,T1078,T1003 \
  --access-level external \
  --authorized --json

# Internal network access with crown jewel targeting
python3 scripts/engagement_planner.py \
  --techniques T1059,T1078,T1021,T1550,T1003 \
  --access-level internal \
  --crown-jewels "Database,Active Directory,Payment Systems" \
  --authorized --json

# Credentialed (assumed breach) scenario with scale
python3 scripts/engagement_planner.py \
  --techniques T1059,T1078,T1021,T1550,T1003,T1486,T1048 \
  --access-level credentialed \
  --crown-jewels "Domain Controller,S3 Data Lake" \
  --target-count 50 \
  --authorized --json

# List all 29 supported MITRE ATT&CK techniques
python3 scripts/engagement_planner.py --list-techniques
```

### Определения уровня доступа { #access-level-definitions }

| Уровень | Исходное положение | Доступные методы |
|-------|------------------|----------------------|
| внешний | Нет внутреннего доступа — только интернет | Только для внешней облицовки (T1190, T1566 и т.д.) |
| внутренний | Точка опоры в сети — нет учетных данных | Внутренняя разведка + подготовка к боковому перемещению |
| аттестованный | Получены действительные учетные данные | Полная цепь отключения, включая priv-esc, боковое перемещение, удар |

### Коды выхода { #exit-codes }

| Код | Значение |
|------|---------|
| 0 | Успешно разработан план взаимодействия |
| 1 | Отсутствует авторизация или неверный метод |
| 2 | Нарушение области действия — метод, выходящий за рамки ограничений уровня доступа |

## Методология этапа уничтожения цепочки { #kill-chain-phase-methodology }

Планировщик взаимодействия распределяет методы по восьми фазам цепочки убийств и соответствующим образом упорядочивает план выполнения.

### Порядок этапов цепочки уничтожения { #kill-chain-phase-order }

| Фаза | Порядок | Тактика МИТРЫ | Примеры |
|-------|-------|--------------|----------|
| Разведка | 1 | TA0043 | T1595, T1596, T1598 |
| Освоение ресурсов | 2 | TA0042 | T1583, T1588 |
| Первоначальный доступ | 3 | TA0001 | T1190, T1566, T1078 |
| Исполнение | 4 | TA0002 | T1059, T1047, T1204 |
| Настойчивость | 5 | TA0003 | T1053, T1543, T1136 |
| Эскалация привилегий | 6 | TA0004 | T1055, T1548, T1134 |
| Доступ с использованием учетных данных | 7 | TA0006 | T1003, T1110, T1558 |
| Боковое перемещение | 8 | TA0008 | T1021, T1550, T1534 |
| Коллекция | 9 | TA0009 | T1074, T1560, T1114 |
| Эксфильтрация | 10 | TA0010 | T1048, T1041, T1567 |
| Воздействие | 11 | TA0040 | T1486, T1491, T1498 |

### Принципы выполнения этапов { #phase-execution-principles }

Каждый этап должен быть завершен до перехода к следующему, если только в рамках задания не указано предполагаемое нарушение (переход к более позднему этапу). Не пропускайте упорство перед попыткой бокового перемещения — упорство обеспечивает непрерывность работы, если обнаружена и удалена единственная точка опоры.

## Оценка техники и расстановка приоритетов { #technique-scoring-and-prioritization }

Методы оцениваются по затраченным усилиям (насколько сложно выполнить их незаметно) и расставляются по приоритетам в плане взаимодействия.

### Формула оценки усилий { #effort-score-formula }

```
effort_score = detection_risk × (len(prerequisites) + 1)
```

Меньший показатель усилий = проще выполнять без обнаружения триггера.

### Ссылка на метод подсчета очков { #technique-scoring-reference }

| Техника | Риск обнаружения | Предварительные условия | Оценка усилий | ИДЕНТИФИКАТОР МИТРЫ |
|-----------|---------------|---------------|-------------|---------|
| Выполнение PowerShell | 0.7 | начальный доступ | 1.4 | T1059.001 |
| Сохранение запланированной задачи | 0.5 | исполнение | 1.0 | T1053.005 |
| Передайте хэш | 0.6 | учетный доступ, внутренняя сеть | 1.8 | T1550.002 |
| Дамп учетных данных LSASS | 0.8 | локальный администратор | 1.6 | T1003.001 |
| Ссылка для подводной охоты | 0.4 | нет | 0.4 | T1566.001 |
| Развертывание программ-вымогателей | 0.9 | настойчивость, боковое движение | 2.7 | T1486 |

## Анализ узких мест { #choke-point-analysis }

Контрольные точки - это методы, необходимые для нескольких путей получения активов crown jewel. Техника обнаружения удушающей точки обнаруживает все пути атаки, которые проходят через нее.

### Идентификация точки дросселирования { #choke-point-identification }

Планировщик взаимодействия определяет труднодоступные места, находя методы в `credential_access` и `privilege_escalation` тактика, которая служит предпосылкой для множества последующих приемов, нацеленных на драгоценности короны.

Уделите приоритетное внимание разработке правил обнаружения и плотности мониторинга вокруг методов "удушающей точки" — усиление "удушающей точки" многократно увеличивает защитную ценность.

### Общие ограничивающие факторы в зависимости от окружающей среды { #common-choke-points-by-environment }

| Тип окружающей среды | Общие точки пересечения | Приоритет обнаружения |
|-----------------|--------------------|--------------------|
| Домен Active Directory | T1003 (дамп учетных данных), T1558 (Kerberoasting) | Самый высокий |
| Среда AWS | T1078.004 (облачная учетная запись), iam:цепочки паролей | Самый высокий |
| Гибридное облако | T1550.002 (PtH), T1021.006 (WinRM) | Высокий |
| Контейнеризированные приложения | T1610 (деплей контейнера), T1611 (эвакуация контейнера) | Высокий |

Полная методология: `references/attack-path-methodology.md`

## Оценка рисков OPSEC { #opsec-risk-assessment }

Элементы риска OPSEC определяют действия, которые могут триггером вызвать обнаружение или оставить постоянные артефакты.

### Категории рисков OPSEC { #opsec-risk-categories }

| Тактика | Основной риск для оперативной безопасности | Смягчение последствий |
|--------|------------------|------------|
| Доступ с использованием учетных данных | Триггеры EDR для доступа к памяти LSASS | Используйте методы без LSASS (DCSync, Kerberoasting) там, где это возможно |
| Исполнение | Ведение журнала команд из командной строки PowerShell | Используйте обход AMSI или альтернативные методы выполнения в области видимости |
| Боковое перемещение | Боковое перемещение NTLM генерирует событие 4624 тип 3 | Используйте Kerberos там, где это возможно; избегайте NTLM по сети |
| Настойчивость | Запланированные задачи генерируют событие 4698 | Используйте менее контролируемые механизмы сохранения в пределах области применения |
| Эксфильтрация | Крупные исходящие переводы триггером DLP | Обработайте данные и используйте медленный вывод, если требуется скрытность |

### Чек-лист OPSEC перед каждым этапом { #opsec-checklist-before-each-phase }

1. Подходит ли данная методика для каждого вида икры?
2. Будет ли он генерировать журналы, которые blue team активно отслеживает?
3. Существует ли менее заметная альтернатива, которая достигает той же цели?
4. Если он будет обнаружен, покажет ли он всю операцию в целом или только текущую точку опоры?
5. Определены ли артефакты очистки для удаления после тренировки?

## Нацеливание на драгоценный камень короны { #crown-jewel-targeting }

Активы Crown jewel - это ценные объекты, которые определяют критерии успеха взаимодействия с red team.

### Классификация драгоценностей короны { #crown-jewel-classification }

| Тип драгоценного камня в короне | Целевые показатели | Пути атаки |
|-----------------|------------------|--------------|
| Контроллер домена | AD DS, NTDS.dit, SYSVOL | Kerberoasting → DCSync → Золотой билет |
| Серверы баз данных | Производственный SQL, NoSQL, хранилище данных | Боковое перемещение → Учетная запись администратора базы данных → упорядочивание данных |
| Платежные системы | Сеть с поддержкой PCI, хранилище данных карты | Сводная сеть → учетная запись службы → эксфильтрация |
| Хранилища исходного кода | Внутренний Git, системы сборки | VPN → внутренний git → ключи для подписи кода |
| Плоскость управления облаком | Консоль управления AWS, администратор IAM | Фишинг → учетные данные → цепочка предположений |

Определение драгоценности короны согласовано в RoE — успех взаимодействия измеряется тем, достигает ли red team определенных драгоценностей короны, а не количеством обнаруженных уязвимостей.

## Методология определения пути атаки { #attack-path-methodology }

Анализ траектории атаки определяет все жизнеспособные маршруты от начального уровня доступа до каждого драгоценного камня короны.

### Оценка траектории { #path-scoring }

Каждый путь оценивается по:
- ** Общая оценка усилий** (сумма оценок усилий по каждой технике)
- **Количество узких мест** (через сколько узких мест проходит путь)
- **Вероятность обнаружения** (произведение рисков обнаружения для каждого метода)

Меньшее усилие + меньшее количество точек удушения = путь наименьшего сопротивления для атакующего.

### Построение графика траектории атаки { #attack-path-graph-construction }

```
external
  └─ T1566.001 (spearphishing) → initial_access
       └─ T1059.001 (PowerShell) → execution
            └─ T1003.001 (LSASS dump) → credential_access [CHOKE POINT]
                 └─ T1550.002 (Pass-the-Hash) → lateral_movement
                      └─ T1078.002 (domain account) → privilege_escalation
                           └─ Crown Jewel: Domain Controller
```

Полный алгоритм подсчета очков, взвешивание точек удушения и матрицу соотношения усилий и отдачи смотрите в разделе `references/attack-path-methodology.md`.

## Воркфлоу { #workflows }

### Воркфлоу 1: Быстрое определение масштабов взаимодействия (30 минут) { #workflow-1-quick-engagement-scoping-30-minutes }

Для определения масштабов целенаправленного упражнения красной команды против конкретной цели:

```bash
# 1. Generate initial technique list from kill-chain coverage gaps
python3 scripts/engagement_planner.py --list-techniques

# 2. Build plan for external assumed-no-access scenario
python3 scripts/engagement_planner.py \
  --techniques T1566,T1190,T1059,T1003,T1021 \
  --access-level external \
  --crown-jewels "Database Server" \
  --authorized --json

# 3. Review choke_points and opsec_risks in output
# 4. Present kill-chain phases to stakeholders for scope approval
```

**Решение**: Если choke_points уже охвачены правилами обнаружения, сосредоточьтесь на пробелах. Если нет, то это самые важные цели упражнений.

### Воркфлоу 2: Полное вовлечение Red Team (многонедельный) { #workflow-2-full-red-team-engagement-multi-week }

**Неделя 1 — Планирование:**
1. Определите драгоценности короны и критерии успеха вместе с стейкхолдерами
2. Подпишите RoE с определенной областью применения, временными рамками и исключениями, выходящими за рамки
3. Составьте план взаимодействия с engagement_planner.py
4. Ревью рисков OPSEC для каждого этапа

**Неделя 2 — Выполнение (Внешняя фаза):**
1. Разведка и профилирование целей
2. Первоначальные попытки доступа (фишинг, использование общедоступных эксплойтов)
3. Документируйте каждый выполненный прием с помощью временных меток
4. Регистрируйте все события обнаружения, чтобы подтвердить охват синей командой

**Неделя 3 — Выполнение (Внутренняя фаза):**
1. Установите постоянство, если получен первоначальный доступ
2. Выполнение методов доступа к учетным данным (контрольные точки)
3. Боковое движение к драгоценностям короны
4. Задокументируйте, когда и как были получены королевские драгоценности

**Неделя 4 — Отчетность:**
1. Обобщение результатов — примененные методы, показатели обнаружения, достигнутые результаты по драгоценностям короны
2. Сопоставьте результаты с пробелами в обнаружении
3. Выработать рекомендации по устранению последствий с учетом приоритетности воздействия в узловой точке
4. Доведите информацию до сведения руководства службы безопасности

### Воркфлоу 3: Предполагаемое нарушение рабочего стола { #workflow-3-assumed-breach-tabletop }

Смоделируйте сценарий со скомпрометированными учетными данными для тестирования быстрого обнаружения:

```bash
# Assumed breach — credentialed access starting position
python3 scripts/engagement_planner.py \
  --techniques T1059,T1078,T1021,T1550,T1003,T1048 \
  --access-level credentialed \
  --crown-jewels "Active Directory,S3 Data Bucket" \
  --target-count 20 \
  --authorized --json | jq '.phases, .choke_points, .opsec_risks'

# Run across multiple access levels to compare path options
for level in external internal credentialed; do
  echo "=== ${level} ==="
  python3 scripts/engagement_planner.py \
    --techniques T1059,T1078,T1003,T1021 \
    --access-level "${level}" \
    --authorized --json | jq '.total_effort_score, .phases | keys'
done
```

## Анти-паттерны { #anti-patterns }

1. ** Работа без письменного разрешения** — Несанкционированные действия red team в отношении любой системы, которой вы не владеете и на тестирование которой у вас нет явного разрешения, являются уголовным преступлением. Тот `--authorized` флаг должен отражать реальный подписанный RoE, а не просто запуск инструмента для обхода проверки. Авторизация должна предшествовать выполнению.
2. ** Пропуск последовательности этапов уничтожения** — Переход непосредственно к боковому перемещению без установления постоянства означает, что однократное обнаружение уничтожает весь плацдарм. Следуйте порядку этапов цепочки убийств — каждый этап создает основу для следующего.
3. ** Не определение драгоценностей короны перед началом ** — Задания без определенных критериев успеха переходят в открытый поиск уязвимостей. Драгоценности короны и условия успеха должны быть согласованы в RoE до выполнения первой техники.
4. **Игнорирование рисков OPSEC в плане** — Упражнения красной команды проверяют обнаружение синей команды. Намеренный отказ от всех методов обнаружения приводит к нереалистичному взаимодействию, которое не подтверждает охват обнаружения. Используйте риски OPSEC, чтобы понять степень подверженности обнаружению, а не для того, чтобы полностью избежать их.
5. ** Невозможность документирования выполненных методов в режиме реального времени** — Ретроактивная документация о том, что было выполнено, ненадежна. Регистрируйте каждый прием, временную метку и результат по мере его выполнения. Отчетность после выполнения задания должна основываться на современных записях.
6. **Не очищать артефакты после выполнения упражнения** — Механизмы сохранения, новые учетные записи, измененные конфигурации и поэтапные данные должны быть удалены после завершения задания. Оставление артефактов red team создает постоянные угрозы безопасности и может быть перепутано с реальной деятельностью злоумышленника.
7. ** Рассматривая путь наименьшего сопротивления как единственный путь** — Атакующие приспосабливаются. Протестируйте несколько путей атаки, включая более трудоемкие маршруты, которые могут ускользнуть от обнаружения. Проверка того, что обнаружен самый простой путь, необходима, но недостаточна.
