## Модель развертывания воркфлоу { #model-deployment-workflow }

Деплей обученную модель в производство с мониторингом:

1. Экспорт модели в стандартизированный формат (ONNX, TorchScript, SavedModel)
2. Модель пакета с зависимостями в контейнере Docker
3. Деплей в промежуточной среде
4. Запустите интеграционные тесты на промежуточном этапе
5. Деплей canary (5% трафика) в рабочую среду
6. Отслеживайте задержку и частоту ошибок в течение 1 часа
7. Переход к полноценному производству, если показатели соответствуют
8. ** Проверка:** задержка p95 < 100 мс, частота ошибок < 0,1%

### Шаблон контейнера { #container-template }

```dockerfile
FROM python:3.11-slim

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY model/ /app/model/
COPY src/ /app/src/

HEALTHCHECK CMD curl -f http://localhost:8080/health || exit 1

EXPOSE 8080
CMD ["uvicorn", "src.server:app", "--host", "0.0.0.0", "--port", "8080"]
```

### Варианты подачи { #serving-options }

| Вариант | Задержка | Пропускная способность | Вариант использования |
|--------|---------|------------|----------|
| FastAPI + Uvicorn | Низкий | Средний | REST API, небольшие модели |
| Сервер логического вывода Triton | Очень низкий | Очень высокий | Вывод на графическом процессоре, пакетная обработка |
| Обслуживание тензорного потока | Низкий | Высокий | Модели тензорного потока |
| Факельный сервиз | Низкий | Высокий | Модели PyTorch |
| Подача луча | Средний | Высокий | Сложные пайплайны, многомодельные |

## Настройка пайплайна MLOps { #mlops-pipeline-setup }

Внедрить автоматизированное обучение и развертывание:

1. Настройка хранилища функций (Feast, Tecton) для обучающих данных
2. Настройка отслеживания экспериментов (MLflow, веса и смещения)
3. Создайте обучающий пайплайн с протоколированием гиперпараметров
4. Зарегистрируйте модель в реестре моделей с метаданными версии
5. Настройка промежуточного развертывания, триггером которого являются события реестра
6. Настройка инфраструктуры A/B тестирования для сравнения моделей
7. Включить мониторинг дрейфа с оповещением
8. **Валидация:** Новые модели автоматически оцениваются по сравнению с базовыми

### Шаблон хранилища функций { #feature-store-pattern }

```python
from feast import Entity, Feature, FeatureView, FileSource

user = Entity(name="user_id", value_type=ValueType.INT64)

user_features = FeatureView(
    name="user_features",
    entities=["user_id"],
    ttl=timedelta(days=1),
    features=[
        Feature(name="purchase_count_30d", dtype=ValueType.INT64),
        Feature(name="avg_order_value", dtype=ValueType.FLOAT),
    ],
    online=True,
    source=FileSource(path="data/user_features.parquet"),
)
```

### Триггеры переподготовки { #retraining-triggers }

| Триггер | Обнаружение | Действие |
|---------|-----------|--------|
| Запланированный | Cron (еженедельно/ежемесячно) | Полная переподготовка |
| Падение производительности | Точность < пороговое значение | Немедленная переподготовка |
| Дрейф данных | Фунт/кв. дюйм > 0,2 | Оценивайте, затем переучивайтесь |
| Новый объем данных | X новых образцов | Постепенное обновление |

## Воркфлоу интеграции с LLM { #llm-integration-workflow }

Интегрировать API LLM в производственные приложения:

1. Создайте уровень абстракции поставщика для обеспечения гибкости поставщика
2. Реализовать логику повторных попыток с экспоненциальным откатом
3. Настройте резервное подключение к дополнительному поставщику
4. Настройте подсчет токенов и усечение контекста
5. Добавьте кэширование ответов для повторяющихся запросов
6. Внедрить отслеживание затрат по каждому запросу
7. Добавьте проверку структурированных выходных данных с помощью Pydantic
8. ** Проверка:** Ответ проанализирован правильно, стоимость в рамках бюджета

### Абстракция поставщика { #provider-abstraction }

```python
from abc import ABC, abstractmethod
from tenacity import retry, stop_after_attempt, wait_exponential

class LLMProvider(ABC):
    @abstractmethod
    def complete(self, prompt: str, **kwargs) -> str:
        pass

@retry(stop=stop_after_attempt(3), wait=wait_exponential(min=1, max=10))
def call_llm_with_retry(provider: LLMProvider, prompt: str) -> str:
    return provider.complete(prompt)
```

## Внедрение системы RAG { #rag-system-implementation }

Построить пайплайн генерации с расширенным поиском:

1. Выберите векторную базу данных (Pinecone, Qdrant, Weaviate)
2. Выберите модель встраивания, основанную на соотношении качества и затрат
3. Внедрить стратегию разбивки документов на части
4. Создайте пайплайн приема с извлечением метаданных
5. Построение поиска с внедрением запроса
6. Добавьте повторный ранжирование для повышения релевантности
7. Отформатируйте контекст и отправьте в LLM
8. ** Проверка:** Ответы ссылаются на извлеченный контекст, галлюцинаций нет

### Выбор векторной базы данных { #vector-database-selection }

| База данных | Хостинг | Масштаб | Задержка | Лучше всего подходит для |
|----------|---------|-------|---------|----------|
| Сосновая шишка | Управляемый | Высокий | Низкий | Производство, управляемое |
| Qdrant | Оба | Высокий | Очень низкий | Критично для производительности |
| Переплетать | Оба | Высокий | Низкий | Гибридный поиск |
| Цветность | Автономный хостинг | Средний | Низкий | Создание прототипов |
| вектор pg | Автономный хостинг | Средний | Средний | Существующие Postgres |

### Стратегии разделения на части { #chunking-strategies }

| Стратегия | Размер куска | Перекрытие | Лучше всего подходит для |
|----------|------------|---------|----------|
| Исправлено | 500-1000 токенов | 50-100 | Общий текст |
| Предложение | 3-5 предложений | 1 предложение | Структурированный текст |
| Семантический | Переменная | Основанный на значении | Исследовательские работы |
| Рекурсивный | Иерархический | Родитель-потомок | Длинные документы |

## Мониторинг модели { #model-monitoring }

Отслеживайте производственные модели на предмет дрейфа и деградации:

1. Настройка отслеживания задержки (p50, p95, p99)
2. Настройка оповещения о частоте ошибок
3. Реализовать обнаружение дрейфа входных данных
4. Отслеживайте сдвиги в распределении прогнозов
5. Регистрируйте достоверность заземления, когда это доступно
6. Сравните версии моделей с показателями A/B
7. Настройка автоматических триггеров переподготовки
8. ** Проверка:** Оповещения срабатывают до видимой пользователем деградации

### Обнаружение дрейфа { #drift-detection }

```python
from scipy.stats import ks_2samp

def detect_drift(reference, current, threshold=0.05):
    statistic, p_value = ks_2samp(reference, current)
    return {
        "drift_detected": p_value < threshold,
        "ks_statistic": statistic,
        "p_value": p_value
    }
```

### Пороговые значения предупреждений { #alert-thresholds }

| Метрика | Предупреждение | Критический |
|--------|---------|----------|
| задержка p95 | > 100 мс | > 200 мс |
| Частота ошибок | > 0.1% | > 1% |
| PSI (дрейф) | > 0.1 | > 0.2 |
| Падение точности | > 2% | > 5% |
