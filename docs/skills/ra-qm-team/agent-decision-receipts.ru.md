## Обзор { #overview }

В журнале записано, что произошло какое-то действие. Квитанция ** защищена от несанкционированного доступа **: в ней записано, кто, что и в соответствии с какой политикой, и она подписана, поэтому любое последующее редактирование нарушает подпись. Этот скилл подготавливает пользователя к последующему действию агента и позже проверяет его только по сертификату: нет базы данных, нет сети, нет доверия к эмитенту.

Криптография не входит в этот скилл. Это примитив квитанции с открытым исходным кодом **OpenAgentOntology** (Apache-2.0), который подписывает каждую квитанцию с помощью Ed25519 ** и** постквантовых элементов ML-DSA-65 (FIPS 204) + SLH-DSA (FIPS 205) при установке постквантовой серверной части. Этот скилл является уровнем принятия решений: когда чеканить, что вставлять, как проверять. Одна установка, никакой криптографии для каждого скилла.

**Три решения, больше ничего:**

1. **Требуется ли для этого действия квитанция?** — побочный эффект + косвенный + позже доказуемый = да.
2. **Отчеканить квитанцию** — создайте манифест действия, подпишите его с помощью примитива OAO.
3. ** Проверьте это ** — повторно вычислите хэш, проверьте каждый сегмент подписи только по сертификату.

Этот скилл ** НЕ является анализом журналов.** Журналы описывают, что произошло, и могут быть отредактированы автоматически. Квитанция чеканится до/во время исполнения и прерывается при редактировании. Используйте журналы для отладки; используйте квитанции в качестве доказательств.

Этот скилл ** НЕ является размещенным нотариусом.** Он отчеканивает местную самоподписанную квитанцию, которую любой желающий может проверить в автономном режиме. Межорганизационная верификация (подтверждение одной организации другой) - это отдельная размещенная служба, которая здесь выходит за рамки.

Этот скилл не является юридическим заключением.** Он предоставляет доказательства, сформированные в поддержку сертификации в стиле FRE 902(13)/(14) и ведения учета в соответствии со статьей 12 Закона ЕС об искусственном интеллекте. Принимается ли данная квитанция к рассмотрению - это вопрос к адвокату.

## Быстрый старт { #quick-start }

```bash
# Install the open-source receipt primitive (Apache-2.0). Add [pq] for the post-quantum legs.
pip install "openagentontology[pq]"

# 1. Build + validate an action manifest (stdlib only, no crypto, no network)
python scripts/build_action_manifest.py --agent my-deploy-agent --operation deploy \
    --target prod/api --policy "EU AI Act Art 12" --out action.json

# 2. Mint the receipt over it (Ed25519 + post-quantum legs)
python -c "import json,openagentontology.receipt as r; \
  print(json.dumps(r.mint_receipt(json.load(open('action.json')), decision='ACTION_GOVERNED')))" > receipt.json

# 3. Verify from the cert alone (no DB, no network)
python -c "import json,openagentontology.receipt as r; \
  print(r.verify_receipt(json.load(open('receipt.json'))))"
# -> {'ok': True, 'sig_ok': True, ... 'reason': 'verified from the cert alone via: ed25519, ml_dsa, slh_dsa'}
```

> ** Примечание о зависимости.** Этот скилл делегирует подписание `openagentontology` (Apache-2.0, регистрация `pip install`). Поставляемый здесь скрипт доступен только для stdlib и не добавляет зависимости от репозитория; пакет устанавливается оператором (шаблон BYO-библиотеки). Если он не установлен, шаг сборки все равно работает — его требуется только для чеканки / проверки.

## Основной воркфлоу { #core-workflow }

Три приведенных ниже решения - это скилл: решите, следует ли получать, отчеканить, затем проверить.

## Решение 1: Требуется ли для этого действия квитанция? { #decision-1-does-this-action-need-a-receipt }

Чеканите чек, когда выполняется действие **всех трех** из:

| Тест | Мятный, если... |
|------|-----------|
| Побочные эффекты | он записывает, отправляет, деплою, удаляет, оплачивает, предоставляет доступ или изменяет внешнее состояние |
| Последовательный | неправильный звонок стоит денег, нарушает соблюдение требований или причиняет вред человеку |
| Позже - доказуемо | кто-то (аудитор, страховщик, регулирующий орган, суд, контрагент) может спросить: "Что сделал агент и почему?" |

Доступные только для чтения, обратимые, тривиальные действия **не** нуждаются в получении. Получите все, и сигнал пропадет; не получите ничего, и единственный звонок, который имел значение, не может быть доказан.

Триггеры с высоким сигналом (mint по умолчанию): `deploy`, `delete`, `pay`/`wire`/`refund`, `grant_access`, `export`/`egress`, `approve`/`deny` претензия, любое типовое решение, которое затрагивает человека в системе искусственного интеллекта с высоким уровнем риска.

## Решение 2: Отчеканить квитанцию { #decision-2-mint-the-receipt }

Манифест действия - это любой ASCII-безопасный dict, описывающий, что сделал агент. Требуются четыре ключа **** — `build_action_manifest.py` отклоняет манифест (выход 2), если какой-либо из них отсутствует. Еще два добавляются автоматически:

| Ключ | Требуется? | Что он несет в себе |
|-----|-----------|-----------------|
| `agent_id` | **требуется** | действующий агент |
| `operation` | **требуется** | глагол (деплою / удалить / оплатить / решить / ...) |
| `target` | **требуется** | на что это подействовало |
| `policy` | **требуется** | правило, которое им управляет (например, "Статья 12 Закона ЕС об ИИ", "внутренний контроль изменений") |
| `inputs_hash` | автоматически добавленный | мешанина из `--inputs`, поэтому полная полезная нагрузка не должна храниться в открытом виде (по умолчанию используется хэш empty , когда `--inputs` опущен) |
| `decision_label` | автоматически добавленный | метка решения о получении (по умолчанию используется `ACTION_GOVERNED`) |

`mint_receipt(manifest, decision=...)` хэширует полный манифест в подтверждение получения, подписывает канонический текст и возвращает квитанцию, содержащую: `evidence_hash`, `signature_b64` (Ed25519), и — когда `[pq]` установлен — `ml_dsa_signature_b64` + `slh_dsa_signature_b64`. Каждая ветвь подписывает одни и те же байты; любая проверка подтверждает подлинность.

> Видишь [ссылки/квитанции-fields.md](https://github.com/imgusev/claude-skills-ru/tree/main/ra-qm-team/skills/agent-decision-receipts/references/receipt-fields.md) для получения полной схемы получения и постквантового обоснования.

## Решение 3: Проверьте это { #decision-3-verify-it }

`verify_receipt(receipt)` пересчитывает `sha256(canonical(evidence))`, сравнивает это с `evidence_hash`, затем проверяет каждый сегмент подписи, для которого у него есть серверная часть. Он возвращается `{ok, hash_ok, sig_ok, legs, reason}`. Один отредактированный байт в любом месте действия прерывает `hash_ok`; поддельная подпись ломает ногу. Для подтверждения требуется только квитанция — никакого обратного звонка отправителю.

Это свойство делает его доказательством: проверяющий, который не доверяет эмитенту, все равно может подтвердить, что квитанция цела и подлинна, полностью в автономном режиме.

## Анти-паттерны { #anti-patterns }

- **Получите журнал регистрации, а не решение.** Чеканка квитанции поверх строки журнала, написанной постфактум, ничего не доказывает. Мята в момент действия, над действием.
- ** Храните ключ подписи рядом с квитанциями.** Если ключ скомпрометирован, подписи ничего не значат. Относитесь к ключу как к любому секрету подписи; никогда не фиксируйте его.
- **Ed25519 - только при наличии постквантовых этапов.** Квитанция является доказательством длительного действия. Подпишите его один раз с помощью постквантовых элементов (ML-DSA-65 + SLH-DSA), чтобы его можно было проверить, если будущий квантовый компьютер сможет взломать Ed25519. Установить `[pq]`.
- ** Внесение необработанных секретных данных или PII в манифест.** Манифест преобразуется в доказательства и может быть восстановлен из квитанции. Переносить хэши (`inputs_hash`), а не открытый текст.
- ** Называя это "допустимым". ** Это доказательство, сформированное для * поддержки* сертификации в стиле FRE 902(13)/(14). Приемлемость - это решение суда, а не претензия инструмента.
- ** Подделка подписи, когда криптография отсутствует.** Примитив выдает явный `unsigned` вместо этого установите флажок. Никогда не предъявляйте неподписанную квитанцию как подписанную.
