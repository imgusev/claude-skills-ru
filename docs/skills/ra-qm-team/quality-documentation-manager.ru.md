## Воркфлоу для управления документооборотом { #document-control-workflow }

Внедрить контроль документов от создания до устаревания:

1. Присвоение номера документу в соответствии с процедурой нумерации
2. Создайте документ с использованием управляемого шаблона
3. Направление ревью требуемым рецензентам
4. Адресуйте комментарии для ревью и документируйте ответы
5. Получите необходимые подписи для утверждения
6. Назначьте дату вступления в силу и распространяйте
7. Обновить основной список документов
8. **Проверка:** Документ доступен в момент использования; устаревшие версии удалены

### Этапы жизненного цикла документа { #document-lifecycle-stages }

| Стадия | Определение | Необходимые действия |
|-------|------------|------------------|
| Черновик | В стадии создания или пересмотра | Авторское редактирование, не для использования |
| Ревью | Распространено для ревью | Рецензенты оставляют отзывы |
| Одобренный | Все подписи получены | Готов к тренировке/distribution |
| Эффективный | Обучение завершено, освобожден | Доступно для использования |
| Вытесненный | Заменен на более новую версию | Вывести из активного использования |
| Устаревший | Больше не применимо | Архив в соответствии с графиком хранения |

### Типы документов и префиксы { #document-types-and-prefixes }

| Префикс | Тип документа | Типичный контент |
|--------|---------------|-----------------|
| QM | Руководство по качеству | Обзор СМК, сфера применения, политика |
| СОП | Стандартная процедура работы | Процедуры на уровне процесса |
| WI | Инструкция по работе | Пошаговое выполнение задач на уровне задач |
| TF | Шаблон/Форма | Контролируемые формы |
| СПЕЦИФИКАЦИЯ | Спецификация | Продукт/process технические характеристики |
| Польский злотый | План | Качество/project планы |

### Требуемые рецензенты в зависимости от типа документа { #required-reviewers-by-document-type }

| Тип документа | Требуемые рецензенты | Требуемые утверждающие лица |
|---------------|-------------------|-------------------|
| СОП | Владелец процесса, QA | Менеджер по контролю качества, владелец процесса |
| WI | Региональный супервайзер, отдел контроля качества | Региональный менеджер |
| СПЕЦИФИКАЦИЯ | Инжиниринг, контроль качества | Технический менеджер, отдел контроля качества |
| TF | Владелец процесса | КОНТРОЛЬ качества |
| Проектная документация | Команда дизайнеров, отдел контроля качества | Орган по контролю за проектированием |

## Система нумерации документов { #document-numbering-system }

Присваивайте согласованные номера документам для идентификации и поиска.

### Формат нумерации { #numbering-format }

Стандартный формат: `PREFIX-CATEGORY-SEQUENCE[-REVISION]`

```
Example: SOP-02-001-A

SOP = Document type (Standard Operating Procedure)
02  = Category code (Document Control)
001 = Sequential number
A   = Revision indicator
```

### Коды категорий { #category-codes }

| Код | Функциональная зона | Описание |
|------|-----------------|-------------|
| 01 | Управление качеством | Процедуры СМК, ревью руководства |
| 02 | Контроль документооборота | Эта область |
| 03 | Человеческие ресурсы | Обучение, компетентность |
| 04 | Дизайн и разработка | Процессы управления проектированием |
| 05 | Покупка | Управление поставщиками |
| 06 | Производство | Производственные процедуры |
| 07 | Контроль качества | Осмотр, тестирование |
| 08 | КАПА | Корректирующий/preventive действия |
| 09 | Управление рисками | Процессы ISO 14971 |
| 10 | Вопросы регулирования | Представления, соблюдение |

### Нумерация Воркфлоу { #numbering-workflow }

1. Автор запрашивает номер документа из системы управления документами
2. Контроль документов проверяет присвоение категории
3. Управление документооборотом присваивает следующий доступный порядковый номер
4. Номер, записанный в Главном списке документов
5. Автор создает документ, используя присвоенный номер
6. ** Проверка:** Формат чисел соответствует стандарту; в главном списке нет дубликатов

### Обозначение пересмотра { #revision-designation }

| Изменить тип | Увеличение ревизии | Пример |
|-------------|-------------------|---------|
| Основной пересмотр | Число приращений | Об/мин 01 → Об/мин 02 |
| Незначительная доработка | Увеличить вложенную редакцию | Rev 01 → Rev 01.1 |
| Административный | Никаких изменений или буквенного суффикса | Rev 01 → Rev 01a |

Видишь `references/document-control-procedures.md` для получения полного руководства по нумерации.

## Процесс утверждения и ревью { #approval-and-review-process }

Получите необходимые ревью и утверждения перед выпуском документа.

### Ревью Воркфлоу { #review-workflow }

1. Автор завершает подготовку проекта документа
2. Автор отправляет заявку на ревью через форму маршрутизации или DMS
3. Рецензенты назначаются в зависимости от типа документа
4. Рецензенты предоставляют комментарии в течение срока ревью (5-10 рабочих дней)
5. Автор обращается к комментариям и документирует ответы
6. Автор повторно отправляет пересмотренный документ
7. Утверждающие подписывают и ставят дату
8. ** Проверка:** Все необходимые проверки завершены; все комментарии рассмотрены с документально подтвержденным решением

### Расположение комментариев { #comment-disposition }

| Расположение | Требуемые действия |
|-------------|-----------------|
| Принять | Включить комментарий в том виде, в каком он написан |
| Принять с изменениями | Включить с изменениями, документально обосновать |
| Отклонить | Не включайте, документируйте обоснование |
| Отложить | Адрес в будущей редакции, документируйте причину |

### Матрица утверждения { #approval-matrix }

```
Document Level 1 (Policy/QM): CEO or delegate + QA Manager
Document Level 2 (SOP): Department Manager + QA Manager
Document Level 3 (WI/TF): Area Supervisor + QA Representative
```

### Требования к подписи { #signature-requirements }

| Элемент | Требование |
|---------|-------------|
| Имя | Печатное имя подписавшего |
| Подпись | Рукописная или электронная подпись |
| Дата | Дата наложения подписи |
| Роль | Функция/role от подписавшего |

## Процесс управления изменениями { #change-control-process }

Систематически управляйте изменениями в документах посредством ревью и утверждения.

### Воркфлоу управления изменениями { #change-control-workflow }

1. Определить необходимость изменения документа
2. Заполните форму запроса на изменение с обоснованием
3. Управление документооборотом присваивает номер изменения и регистрирует запрос
4. Направление к экспертам для оценки воздействия
5. Получение разрешений на основе классификации изменений
6. Автор внедряет утвержденные изменения
7. Обновите номер версии и историю изменений
8. ** Проверка:** Изменения соответствуют утвержденной области применения; история изменений завершена

### Изменить классификацию { #change-classification }

| Класс | Определение | Уровень одобрения | Примеры |
|-------|------------|----------------|----------|
| Административный | Отсутствие влияния на контент | Контроль документооборота | Опечатки, форматирование |
| Второстепенный | Ограниченное изменение контента | Владелец процесса + контроль качества | Разъяснения |
| Майор | Значительное изменение содержания | Полный цикл ревью | Новые требования |
| Чрезвычайная ситуация | Срочная безопасность/compliance | Ускоренная + ретроспектива | Вопросы безопасности |

### Чек-лист для оценки воздействия Assessment Assessment { #impact-assessment-checklist }

| Зона воздействия | Оценочные вопросы |
|-------------|---------------------|
| Тренировка | Требуют ли перемены переподготовки? |
| Оборудование | Влияют ли изменения на оборудование или системы? |
| Проверка подлинности | Требует ли изменение повторной проверки? |
| Регулирующий | Влияют ли изменения на подачу документов в регулирующие органы? |
| Другие документы | Какие соответствующие документы нуждаются в обновлении? |
| Записи | Какие записи затронуты? |

### Документация по истории изменений { #change-history-documentation }

Каждый документ должен содержать историю изменений:

```
| Revision | Date | Description | Author | Approver |
|----------|------|-------------|--------|----------|
| 01 | 2023-01-15 | Initial release | J. Smith | M. Jones |
| 02 | 2024-03-01 | Updated workflow | J. Smith | M. Jones |
```

## Соответствие требованиям 21 CFR, часть 11 { #21-cfr-part-11-compliance }

Внедрите контроль за электронными записями и подписями для обеспечения соответствия требованиям FDA.

### Область применения части 11 { #part-11-scope }

| Применяется к | Не Применяется К |
|------------|-------------------|
| Записи, требуемые правилами FDA | Бумажные записи |
| Записи, представленные в FDA | Внутренние нерегламентированные документы |
| Электронные подписи на требуемых записях | Общее сообщение по электронной почте |

### Электронное управление записью { #electronic-record-controls }

1. Проверка системы на точность и надежность
2. Внедрить безопасный журнал аудита для всех изменений
3. Ограничить доступ к системе авторизованным лицам
4. Создавайте точные копии в удобочитаемом формате
5. Защищайте записи на протяжении всего срока хранения
6. ** Проверка:** Журнал аудита фиксирует, кто, что и когда внес по всем изменениям

### Требования к следам аудита { #audit-trail-requirements }

| Требование | Реализация |
|-------------|----------------|
| Безопасный | Не может быть изменен пользователями |
| Сгенерированный компьютером | Система создает автоматически |
| С отметкой времени | Дата и время каждого действия |
| Исходные значения | Предыдущие значения сохранены |
| Идентификация пользователя | Кто вносил каждое изменение |

### Требования к электронной подписи { #electronic-signature-requirements }

| Требование | Реализация |
|-------------|----------------|
| Уникальный для каждого человека | Не делится между людьми |
| По крайней мере, 2 компонента | Минимальный идентификатор пользователя + пароль |
| Характерное проявление | Имя, дата/time, означающий отображаемый |
| Связанный с записью | Не может быть вырезан или скопирован |

### Проявление подписи { #signature-manifestation }

Каждая электронная подпись должна отображать:

| Элемент | Пример |
|---------|---------|
| Печатное наименование | Джон Смит |
| Дата и время | 2024-03-15 14:32:05 по восточному времени |
| Значение | Одобрено к выпуску |

### Чек-лист системного контроля Controls Controls { #system-controls-checklist }

**Контроль доступа:**
- [ ] Уникальный идентификатор пользователя для каждого пользователя
- [ ] Усилена сложность пароля
- [ ] Блокировка учетной записи после неудачных попыток
- [ ] Тайм-аут сеанса после бездействия

**След аудита:**
- [ ] Все записи, созданные в журнале
- [ ] Все изменения, внесенные со старым/new ценности
- [ ] Идентификация пользователя зафиксирована
- [ ] Дата/time штамп на всех записях

**Безопасность:**
- [ ] Управление доступом на основе ролей
- [ ] Шифрование данных в состоянии покоя и при передаче
- [ ] Регулярное резервное копирование и протестированное восстановление

Видишь `references/21cfr11-compliance-guide.md` для получения подробных требований к соответствию.

| Метрика | Цель | Расчет |
|--------|--------|-------------|
| Время цикла обработки документов | <30 дней | Среднее количество дней от черновика до вступления в силу |

### Управление документами и записями FDA — ISO 13485 §4.2 в соответствии с QMSR (устаревшие разделы QSR, исторические) { #fda-document--record-control--iso-13485-42-under-the-qmsr-legacy-qsr-sections-historical }

> **⚠️ СТАТУС — переход к QMSR (вступает в силу 2026-02-02): ** Окончательное правило Регламента системы менеджмента качества (QMSR) FDA (89 FR 7496) внесло поправки в 21 CFR, часть 820, чтобы ** включить ISO 13485:2016 путем ссылки ** и удалило устаревшую структуру подразделов QSR. Номера разделов в таблице ниже (820.40/.180/.181/.184/.186) ** больше не существуют в CFR**; они сохраняются только в качестве привычного индекса. Текущий документ/record контролирующим органом является **ISO 13485:2016 §4.2** (особенно §4.2.4 контроль документов, §4.2.5 контроль записей), с файлом медицинского устройства в §4.2.3 и дополнениями к записям в сохраненном виде **21 CFR 820.35**. Ссылайтесь на положения стандарта ISO 13485, а не на номера 820.x, в текущей документации по соответствию.

| Унаследованный раздел QSR (исторический, до 2026 года) | Требование | Текущие полномочия в рамках QMSR (устаревший QSR показан для индекса) |
|-------------------------------------------|-------------|------------------------------|
| 820.40 | Управление документами | ISO 13485 §4.2.4 |
| 820.180 | Общие требования к записи | ISO 13485 §4.2.5 + 21 CFR 820.35 (сохранено) |
| 820.181 | Основная запись устройства | ISO 13485 §4.2.3 (файл медицинского устройства) |
| 820.184 | Запись истории устройства | ISO 13485 §4.2.5 + 21 CFR 820.35 (сохранено) |
| 820.186 | Запись системы качества | ISO 13485 §4.2.5 + 21 CFR 820.35 (сохранено) |
