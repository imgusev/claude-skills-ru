## Планирование воркфлоу по управлению рисками { #risk-management-planning-workflow }

Внедрить процесс управления рисками в соответствии с ISO 14971.

### Воркфлоу: Создайте план управления рисками { #workflow-create-risk-management-plan }

1. Определить объем мероприятий по управлению рисками:
   - Идентификация медицинского устройства
   - Охваченные этапы жизненного цикла
   - Применимые стандарты и нормативные акты
2. Установите критерии приемлемости риска:
   - Определите категории вероятности (P1-P5)
   - Определение категорий серьезности (S1-S5)
   - Создайте матрицу рисков с пороговыми значениями приемлемости
3. Распределите обязанности:
   - Руководитель по управлению рисками
   - Эксперты в данной области
   - Органы, выдающие разрешения
4. Определите действия по проверке:
   - Методы проверки контроля
   - Критерии приемлемости
5. Планируйте производственные и постпродакшн-мероприятия:
   - Источники информации
   - Ревью триггеров
   - Процедуры обновления
6. Получить одобрение плана
7. Создать файл управления рисками
8. **Проверка:** План утвержден; определены критерии приемлемости; распределены обязанности; создано досье

### Содержание плана управления рисками { #risk-management-plan-content }

| Раздел | Содержание | Доказательства |
|---------|---------|----------|
| Сфера применения | Охват устройства и жизненного цикла | Заявление о сфере применения |
| Критерии | Матрица приемлемости риска | Документ с матрицей рисков |
| Обязанности | Роли и полномочия | Диаграмма RACI |
| Проверка | Методы и приемлемость | План проверки |
| Производство/постпродакшн | Деятельность по мониторингу | План наблюдения |

### Матрица приемлемости риска (5x5) { #risk-acceptability-matrix-5x5 }

| Вероятность \ Серьезность | Незначительный | Второстепенный | Серьезный | Критический | Катастрофический |
|------------------------|------------|-------|---------|----------|--------------|
| **Частые (P5)** | Средний | Высокий | Высокий | Неприемлемо | Неприемлемо |
| **Вероятный (P4)** | Средний | Средний | Высокий | Высокий | Неприемлемо |
| **Время от времени (P3)** | Низкий | Средний | Средний | Высокий | Высокий |
| **Пульт дистанционного управления (P2)** | Низкий | Низкий | Средний | Средний | Высокий |
| **Маловероятно (P1)** | Низкий | Низкий | Низкий | Средний | Средний |

### Действия на уровне риска { #risk-level-actions }

| Уровень | Приемлемый | Требуемые действия |
|-------|------------|-----------------|
| Низкий | Да | Документируйте и принимайте; по-прежнему сокращайте, насколько это возможно (MDR ЕС) |
| Средний | После сокращения AFAP | Сократите, насколько это возможно; задокументируйте, почему дальнейшее сокращение невозможно |
| Высокий | После сокращения AFAP | Требуемое сокращение; продемонстрируйте, что все дальнейшие варианты исчерпаны |
| Неприемлемо | Нет | Обязательное изменение дизайна |

> **MDR ЕС — AFAP, не ALARP: ** Для устройств с маркировкой CE риски должны быть снижены ** насколько это возможно (AFAP)** без учета экономических соображений (Приложение I к MDR, GSPR 1-4; EN ISO 14971:2019/A11:2021 Отклонение от Z-приложений). ALARP ("настолько низкий, насколько это практически возможно"), который позволяет взвешивать затраты и выгоды при принятии решений о приемлемости, ** не является приемлемым критерием в соответствии с MDR ЕС** - нотифицированный орган отметит это. Сам стандарт ISO 14971:2019 исключил ALARP из нормативного текста. ALARP может сохраняться в некоторых юрисдикциях, не входящих в ЕС (например, британская традиция HSE); если используется за пределами ЕС, явно укажите на отклонение от требований ЕС.

## Воркфлоу анализа рисков { #risk-analysis-workflow }

Систематически выявляйте опасности и оценивайте риски.

### Воркфлоу: Проведение анализа рисков { #workflow-conduct-risk-analysis }

1. Определите предполагаемое использование и разумно предсказуемое неправильное использование:
   - Медицинское показание
   - Популяция пациентов
   - Численность пользователей
   - Среда использования
2. Выберите метод(ы) анализа:
   - FMEA для анализа компонентов/функций
   - FTA для анализа на системном уровне
   - Защита от технологических отклонений
   - Используйте анализ ошибок для взаимодействия с пользователем
3. Определение опасностей по категориям:
   - Энергетические опасности (электрические, механические, термические)
   - Биологические опасности (биологическая нагрузка, биосовместимость)
   - Химические опасности (остатки, выщелачиваемые вещества)
   - Эксплуатационные риски (программное обеспечение, ошибки использования)
4. Определять опасные ситуации:
   - Последовательность событий
   - Предсказуемые сценарии неправильного использования
   - Одиночные неисправности
5. Оцените вероятность причинения вреда (P1-P5)
6. Оценка тяжести вреда (S1-S5)
7. Документ на листе анализа рисков
8. **Валидация:** Рассмотрены все категории опасности; все опасности задокументированы; присвоены вероятность и серьезность

### Чек-лист по категориям опасности (Checklist Categories Categories) { #hazard-categories-checklist }

| Категория | Примеры | Проанализированный |
|----------|----------|----------|
| Электрический | Шок, ожоги, помехи | ☐ |
| Механический | Дробление, резка, захват | ☐ |
| Тепловой | Ожоги, повреждения тканей | ☐ |
| Излучение | Ионизирующий, неионизирующий | ☐ |
| Биологический | Инфекция, биосовместимость | ☐ |
| Химический | Токсичность, раздражение | ☐ |
| Программное обеспечение | Неправильный вывод, синхронизация | ☐ |
| Ошибка использования | Неправильное использование, восприятие, познание | ☐ |
| Окружающая среда | Электромагнитная совместимость, механическое напряжение | ☐ |

### Выбор метода анализа { #analysis-method-selection }

| Ситуация | Рекомендуемый способ |
|-----------|-------------------|
| Неисправности компонентов | FMEA |
| Сбой на системном уровне | Соглашение о свободной торговле |
| Отклонения от процесса | ХАЗОП |
| Взаимодействие с пользователем | Используйте анализ ошибок |
| Поведение программного обеспечения | Программное обеспечение FMEA |
| Ранний этап проектирования | ПХА |

### Критерии вероятности { #probability-criteria }

| Уровень | Имя | Описание | Частота |
|-------|------|-------------|-----------|
| P5 | Частый | Ожидается, что это произойдет | >10⁻³ |
| P4 | Вероятный | Вероятно, это произойдет | от 10-3 до 10⁻⁴ |
| P3 | Случайный | Может произойти | от 10⁻⁴ до 10⁻⁵ |
| P2 | Удаленный | Маловероятно | от 10⁻⁵ до 10⁻⁶ |
| P1 | Невероятный | Очень маловероятно | <10⁻⁶ |

### Критерии серьезности { #severity-criteria }

| Уровень | Имя | Описание | Вред |
|-------|------|-------------|------|
| S5 | Катастрофический | Смерть | Смерть |
| S4 | Критический | Постоянное ухудшение | Необратимая травма |
| S3 | Серьезный | Травма, требующая вмешательства | Обратимая травма |
| S2 | Второстепенный | Временный дискомфорт | Никакого лечения не требуется |
| S1 | Незначительный | Неудобство | Никаких травм |

## Воркфлоу по оценке рисков { #risk-evaluation-workflow }

Оценивайте риски в соответствии с критериями приемлемости.

### Воркфлоу: Оценка выявленных рисков { #workflow-evaluate-identified-risks }

1. Вычислите начальный уровень риска по формуле вероятность × серьезность
2. Сравнение с критериями приемлемости риска
3. Для каждого риска определите:
   - Приемлемо: Задокументировать и принять (MDR ЕС: по-прежнему сокращать, насколько это возможно)
   - Требуемое сокращение (AFAP): Переходите к контролю рисков
   - Неприемлемо: Обязательный контроль рисков
4. Обоснование оценки документа
5. Выявлять риски, требующие анализа соотношения выгод и рисков
6. Полный анализ соотношения выгод и рисков, если применимо
7. Составить резюме оценки рисков
8. **Валидация:** Все риски оценены; определена приемлемость; обоснование задокументировано

### Дерево решений по оценке рисков { #risk-evaluation-decision-tree }

```
Risk Estimated
      │
      ▼
Apply Acceptability Criteria
      │
      ├── Low Risk ──────────► Accept and document
      │
      ├── Medium Risk ───────► Reduce as far as possible (AFAP)
      │   │                    Document why further reduction impossible
      │   ▼
      │   Further reduction possible?
      │   │
      │   Yes──► Implement control
      │   No───► Document AFAP rationale (no economic considerations)
      │
      ├── High Risk ─────────► Risk reduction required
      │   │                    Must demonstrate reduction AFAP
      │   ▼
      │   Implement control
      │   Verify residual risk
      │
      └── Unacceptable ──────► Design change mandatory
                               Cannot proceed without control
```

### Требования к демонстрации AFAP (MDR ЕС) { #afap-demonstration-requirements-eu-mdr }

| Критерий | Требуемые доказательства |
|-----------|-------------------|
| Рассмотрены все варианты управления | Анализ каждого возможного элемента управления в соответствии с иерархией (дизайн, защитные меры, информация) |
| Дальнейшее сокращение невозможно | Доказательства того, что каждый оставшийся вариант технически неосуществим или еще больше не снижает риск |
| Самый современный | Сравнение с аналогичными устройствами и действующими стандартами |
| Вклад стейкхолдеров | Клинические перспективы/перспективы пользователей |

> Экономические соображения (стоимость дальнейшего снижения риска) **не должны** учитываться при принятии решения о приемлемости ЕС (приложение I к MDR GSPR 2; EN ISO 14971:2019/A11:2021). Стоимость может повлиять на бизнес—решения о том, выводить ли устройство на рынок, но никогда не на то, является ли риск приемлемым.

### Триггеры анализа выгод и рисков { #benefit-risk-analysis-triggers }

| Ситуация | Требуемая выгода-риск |
|-----------|----------------------|
| Остаточный риск остается высоким | Да |
| Невозможное снижение риска | Да |
| Новое устройство | Да |
| Неприемлемый риск при клинической пользе | Да |
| Все риски низкие | Нет |

## Воркфлоу по контролю рисков { #risk-control-workflow }

Внедрять и проверять меры по контролю рисков.

### Воркфлоу: Внедрение средств контроля рисков { #workflow-implement-risk-controls }

1. Определите варианты контроля рисков:
   - Безопасность, заложенная в конструкцию (приоритет 1)
   - Защитные меры в устройстве (приоритет 2)
   - Информация для обеспечения безопасности (приоритет 3)
2. Выберите оптимальное управление, следуя иерархии
3. Анализ контроля на предмет появления новых опасностей
4. Контроль документации в соответствии с требованиями к дизайну
5. Внедрить контроль при проектировании
6. Разработать протокол проверки
7. Выполнить проверку и задокументировать результаты
8. Оценка остаточного риска при наличии контроля
9. **Валидация:** Контроль внедрен; верификация пройдена; остаточный риск приемлем; новых нераскрытых опасностей нет

### Иерархия контроля рисков { #risk-control-hierarchy }

| Приоритет | Тип управления | Примеры | Эффективность |
|----------|--------------|----------|---------------|
| 1 | Неотъемлемая безопасность | Исключающая опасность, безотказная конструкция | Самый высокий |
| 2 | Защитные меры | Охранники, сигнализация, автоматическое отключение | Высокий |
| 3 | Информация | Предупреждения, обучение, IFU | Более низкий |

### Оценка остаточного риска { #residual-risk-evaluation }

| После контроля | Действие |
|---------------|--------|
| Приемлемый | Документ, продолжайте |
| Уменьшенный AFAP | Оформите обоснование (никаких экономических соображений), действуйте |
| Все еще неприемлемо | Дополнительный контроль или изменение конструкции |
| Введена новая опасность | Анализируйте и контролируйте новую опасность |

## Управление рисками после производства { #post-production-risk-management }

Контролируйте и обновляйте систему управления рисками на протяжении всего жизненного цикла продукта.

### Воркфлоу: Мониторинг рисков после производства { #workflow-post-production-risk-monitoring }

1. Определить источники информации:
   - Жалобы клиентов
   - Отчеты об обслуживании
   - Бдительность/неблагоприятные явления
   - Мониторинг литературы
   - Клинические исследования
2. Установить процедуры сбора данных
3. Определите триггеры для ревью:
   - Выявлена новая опасность
   - Повышенная частота возникновения известной опасности
   - Серьезный инцидент
   - Обратная связь с регулирующими органами
4. Анализируйте поступающую информацию на предмет соответствия риску
5. Обновляйте файл управления рисками по мере необходимости
6. Сообщать о важных выводах
7. Проводить периодический ревью по управлению рисками
8. ** Проверка:** Отслеживаются источники информации; файл актуален; ревью завершено в соответствии с графиком

### Источники информации { #information-sources }

| Источник | Тип информации | Частота ревью |
|--------|------------------|------------------|
| Жалобы | Проблемы с использованием, сбои | Непрерывный |
| Обслуживание | Поломки в полевых условиях, ремонт | Ежемесячно |
| Бдительность | Серьезные инциденты | Немедленный |
| Литература | Аналогичные проблемы с устройствами | Ежеквартально |
| Регулирующий | Обратная связь с авторитетом | Как получено |
| Клинический | Данные PMCF | По плану |

### Триггеры обновления файла управления рисками { #risk-management-file-update-triggers }

| Триггер | Время отклика | Действие |
|---------|---------------|--------|
| Серьезный инцидент | Немедленный | Полный ревью рисков |
| Выявлена новая опасность | 30 дней | Обновление анализа рисков |
| Тенденция к увеличению | 60 дней | Анализ тенденций |
| Изменение дизайна | Перед внедрением | Оценка воздействия |
| Обновление стандартов | За переходный период | Анализ пробелов |

### Требования к периодическому ревью { #periodic-review-requirements }

| Элемент Ревью | Частота |
|----------------|-----------|
| Полнота файла управления рисками | Ежегодный |
| Эффективность контроля рисков | Ежегодный |
| Анализ пострыночной информации | Ежеквартально |

## Фреймворки для принятия решений { #decision-frameworks }

### Выбор средств контроля рисков { #risk-control-selection }

```
What is the risk level?
        │
        ├── Unacceptable ──► Can hazard be eliminated?
        │                    │
        │                Yes─┴─No
        │                 │     │
        │                 ▼     ▼
        │            Eliminate  Can protective
        │            hazard     measure reduce?
        │                           │
        │                       Yes─┴─No
        │                        │     │
        │                        ▼     ▼
        │                   Add       Add warning
        │                   protection + training
        │
        └── High/Medium ──► Apply hierarchy
                            starting at Level 1
```

### Новый анализ опасности { #new-hazard-analysis }

| Вопрос | Если да | Если нет |
|----------|--------|-------|
| Создает ли контроль новую опасность? | Анализ новой опасности | Продолжайте |
| Является ли новый риск более высоким, чем первоначальный? | Опция управления отклонением | Приемлемый компромисс |
| Можно ли контролировать новую опасность? | Добавить элемент управления | Опция управления отклонением |

### Решение о приемлемости риска { #risk-acceptability-decision }

| Условие | Решение |
|-----------|----------|
| Все риски низкие | Приемлемый |
| Средние риски снижены AFAP | Приемлемый |
| Высокие риски снижены AFAP, документально подтверждены | Приемлемо, если выгоды перевешивают |
| Любой неприемлемый остаток | Неприемлемо - редизайн |
