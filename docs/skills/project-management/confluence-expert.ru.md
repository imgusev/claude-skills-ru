## Интеграция Atlassian MCP { #atlassian-mcp-integration }

**Основной инструмент**: Удаленный MCP-сервер Atlassian (входит в комплект поставки `.mcp.json`, серверный ключ `atlassian`). Инструментами являются camelCase и surface as `mcp__atlassian__<toolName>`. **Канонический список инструментов**: `project-management/references/atlassian-mcp-tools.md`. Никогда не придумывайте названия инструментов — если возможности нет в этом списке, она недоступна через MCP.

**Ключевые операции** (получение `cloudId` один раз через `mcp__atlassian__getAccessibleAtlassianResources`):

```
// List spaces (space CREATION is not available via MCP — see below)
mcp__atlassian__getConfluenceSpaces (cloudId)

// Create a page under a parent — body must be storage-format XHTML or ADF, never wiki markup
mcp__atlassian__createConfluencePage (cloudId, space, title="Sprint 42 Notes", parent page id, body="<p>Meeting notes in storage-format XHTML</p>")

// Update an existing page (fetch current version with getConfluencePage, then supply version + 1)
mcp__atlassian__updateConfluencePage (cloudId, pageId="789012", version=5, body="<p>Updated content</p>")

// Read a page (body + current version)
mcp__atlassian__getConfluencePage (cloudId, pageId="789012")

// Search with CQL
mcp__atlassian__searchConfluenceUsingCql (cloudId, cql='space = "TEAM" AND label = "meeting-notes" ORDER BY lastModified DESC')

// Retrieve child pages for hierarchy inspection
mcp__atlassian__getConfluencePageDescendants (cloudId, pageId="123456")

// Comments
mcp__atlassian__getConfluencePageFooterComments / mcp__atlassian__createConfluenceFooterComment (cloudId, pageId)
```

**Недоступно через MCP — вместо этого используйте веб-интерфейс или REST API:**
- Создавать/delete a **пробел** → Пользовательский интерфейс слияния `Spaces > Create space` или `POST /wiki/api/v2/spaces`
- **Удалить** страницу → Пользовательский интерфейс Confluence или `DELETE /wiki/api/v2/pages/{id}`
- Применить ** ярлыки** → Пользовательский интерфейс слияния или `/wiki/rest/api/content/{id}/label`
- Пространство **разрешения**, шаблоны/blueprints как первоклассные объекты → Пользовательский интерфейс настроек пространства слияния

**Точки интеграции**:
- Создавать документацию для проектов Senior PM
- Поддержите Scrum-мастера с помощью шаблонов церемоний
- Ссылка на вопросы Jira для эксперта Jira
- Предоставьте шаблоны для создателя шаблона

> **Смотрите также**: `references/macro-cheat-sheet.md` для синтаксиса макроса формата хранилища, `references/templates.md` для библиотеки шаблонов, `references/space-architecture-patterns.md` для структуры пространства и шаблонов разрешений.

## Воркфлоу { #workflows }

### Создание пространства { #space-creation }

> Создание пространства ** недоступно через MCP** — создайте пространство в пользовательском интерфейсе Confluence (`Spaces > Create space`) или через REST (`POST /wiki/api/v2/spaces`). Дерево страниц внутри него может быть построено с помощью MCP (`mcp__atlassian__createConfluencePage`).

0. Создайте рекомендуемую иерархию на основе описания команды:
   ```bash
   python3 scripts/space_structure_generator.py team_info.json --format json
   ```
   Ввод: JSON с командой `name`, `size`, `type`, `projects`. Используйте выходные данные: используйте созданное дерево страниц в качестве плана создания для шага 5 — один `mcp__atlassian__createConfluencePage` вызывается для каждого узла, передавая идентификатор родительской страницы дочерним узлам nest.
1. Определите тип пространства (Командное, проектное, База знаний, личное)
2. Создайте пространство с четким названием и описанием (веб-интерфейс / REST)
3. Установите домашнюю страницу space с обзором
4. Настройка разрешений на использование пространства:
   - Просматривать, редактировать, создавать, удалять
   - Права администратора
5. Создайте исходную древовидную структуру страницы
6. Добавьте сочетания клавиш пробела для навигации
7. ** Проверьте**: Перейдите по URL-адресу space и подтвердите загрузку домашней страницы; убедитесь, что тестовый пользователь, не являющийся администратором, видит правильный уровень разрешений
8. **ХЭНДОФФ ДЛЯ**: Команды по наполнению контентом

### Архитектура страницы { #page-architecture }
**Лучшие практики**:
- Используйте иерархию страниц (родительско-дочерние отношения)
- Глубина навигации не более 3 уровней
- Согласованные соглашения об именовании
- Заметки о собраниях с отметкой даты

**Рекомендуемая структура**:
```
Space Home
├── Overview & Getting Started
├── Team Information
│   ├── Team Members & Roles
│   ├── Communication Channels
│   └── Working Agreements
├── Projects
│   ├── Project A
│   │   ├── Overview
│   │   ├── Requirements
│   │   └── Meeting Notes
│   └── Project B
├── Processes & Workflows
├── Meeting Notes (Archive)
└── Resources & References
```

### Создание шаблона { #template-creation }
1. Определить повторяющийся шаблон содержимого
2. Создайте страницу со структурой и заполнителями
3. Добавляйте инструкции в заполнители
4. Форматирование с использованием соответствующих макросов
5. Сохранить как шаблон
6. Поделитесь с космосом или сделайте глобальным
7. **Проверьте **: Создайте тестовую страницу на основе шаблона и убедитесь, что все заполнители отображаются правильно, прежде чем поделиться с командой
8. **ИСПОЛЬЗУЙТЕ**: Ссылки на расширенные шаблоны шаблонов

### Стратегия документирования { #documentation-strategy }
1. **Оценить** текущее состояние документации
2. **Определите** цели документирования и аудиторию
3. ** Систематизировать** таксономию и структуру контента
4. **Создавать** шаблоны и рекомендации
5. **Перенести** существующую документацию
6. **Обучать** команды передовым практикам
7. **Мониторинг** использования и внедрения
8. **ОТЧИТАТЬСЯ ПЕРЕД**: Старшим менеджером по работе с документацией

### Управление базой знаний { #knowledge-base-management }

**Проведите аудит работоспособности контента** перед любой реструктуризацией или ревью управления:
```bash
python3 scripts/content_audit_analyzer.py pages.json --format json
```
Входные данные: список страниц в формате JSON (`title`, `last_modified`, `view_count`, `author`, `labels`, `word_count`) — создайте его, экспортировав метаданные страницы через `mcp__atlassian__getPagesInConfluenceSpace` / `mcp__atlassian__searchConfluenceUsingCql`. Потребляйте выходные данные: устаревший/orphaned/low-engagement результаты становятся архивным списком (метка + перемещение через пользовательский интерфейс, поскольку инструменты для создания меток отсутствуют в MCP) и списком невыполненных работ по приведенным ниже стандартам качества.

**Типы изделий**:
- Практические руководства
- Документы по устранению неполадок
- Часто задаваемые вопросы
- Справочная документация
- Технологическая документация

**Стандарты качества**:
- Четкое название и описание
- Структурированный по заголовкам
- Видна дата обновления
- Идентифицированный владелец
- Ревью проводится ежеквартально

## Основные макросы { #essential-macros }

> **Примечание по синтаксису**: `{macro}` приведенное ниже сокращение - это ** устаревшая нотация вики-разметки**, показанная только для удобства чтения. Облачные страницы Confluence, созданные с помощью MCP (`createConfluencePage` / `updateConfluencePage`) требуется ** формат хранения (XHTML)** — например `{info}` это действительно `<ac:structured-macro ac:name="info"><ac:rich-text-body>...</ac:rich-text-body></ac:structured-macro>`. Синтаксис формата хранения для каждого макроса, перечисленного здесь, смотрите в разделе `references/macro-cheat-sheet.md`; для получения готовых текстов страниц в формате хранилища запустите scaffolder atlassian-шаблоны (`python3 ../atlassian-templates/scripts/template_scaffolder.py meeting-notes`).

### Макросы содержимого { #content-macros }
**Информация, примечание, предупреждение, совет**:
```
{info}
Important information here
{info}
```

**Расширять**:
```
{expand:title=Click to expand}
Hidden content here
{expand}
```

**Оглавление**:
```
{toc:maxLevel=3}
```

** Выдержка и отрывочный материал включают**:
```
{excerpt}
Reusable content
{excerpt}

{excerpt-include:Page Name}
```

### Динамический контент { #dynamic-content }
**Проблемы с Jira**:
```
{jira:JQL=project = PROJ AND status = "In Progress"}
```

**Диаграмма Jira**:
```
{jirachart:type=pie|jql=project = PROJ|statType=statuses}
```

** Недавно обновленный**:
```
{recently-updated:spaces=@all|max=10}
```

**Содержимое по этикетке**:
```
{contentbylabel:label=meeting-notes|maxResults=20}
```

### Макросы совместной работы { #collaboration-macros }
**Статус**:
```
{status:colour=Green|title=Approved}
```

**Список задач**:
```
{tasks}
- [ ] Task 1
- [x] Task 2 completed
{tasks}
```

**Упоминание пользователя**:
```
@username
```

**Дата**:
```
{date:format=dd MMM yyyy}
```

## Макеты и форматирование страниц { #page-layouts--formatting }

## Разрешения на использование пространства { #space-permissions }

> Шаблоны разрешений по типу пробела: смотрите `references/space-architecture-patterns.md`. Примечание: разрешения на пространство настраиваются в пользовательском интерфейсе Confluence (`Space settings > Permissions`) — не через MCP.

### Схемы получения разрешений { #permission-schemes }
**Общественное пространство**:
- Все пользователи: Просмотр
- Члены команды: Редактирование, создание
- Администраторы пространства: Admin

**Командное пространство**:
- Члены команды: Просмотр, редактирование, создание
- Руководители команды: Администратор
- Другие: Нет доступа

**Проектное пространство**:
- Стейкхолдеры: Просмотр
- Команда проекта: Редактирование, создание
- PM: Администратор

## Управление контентом { #content-governance }

**Циклы ревью**:
- Важные документы: Ежемесячно
- Стандартные документы: Ежеквартально
- Архив документов: Ежегодно

**Стратегия архивирования**:
- Переместите устаревший контент в архивное пространство
- Этикетка с надписью "архивировано" и датой
- Сохраняйте в течение 2 лет, затем удалите
- Ведите учет аудита

** Чек-лист качества контента ( Quality Quality**:
- [ ] Четкое, описательное название
- [ ] Владелец/author идентифицированный
- [ ] Видна дата последнего обновления
- [ ] Нанесены соответствующие ярлыки
- [ ] Функциональные ссылки
- [ ] Согласованное форматирование
- [ ] Конфиденциальные данные не разглашаются

## Фреймворк для принятия решений { #decision-framework }

**Когда эскалация до администратора Atlassian**:
- Нужен шаблон для всей организации
- Требуются разрешения на межпространственное использование
- Конфигурация чертежа
- Глобальные правила автоматизации
- Космический экспорт/import

**Когда следует сотрудничать с экспертом Jira**:
- Встраивать запросы и диаграммы Jira
- Страницы ссылок на проблемы Jira
- Создание отчетов на основе Jira
- Синхронизируйте документацию с тикетами

**Когда следует поддерживать Scrum Master**:
- Шаблоны документации по спринту
- Страницы ретроспективы
- Соглашения о командной работе
- Технологическая документация

**Когда следует поддержать старшего премьер-министра**:
- Страницы исполнительного отчета
- Документация по портфолио
- Общение с стейкхолдерами
- Документы по стратегическому планированию
