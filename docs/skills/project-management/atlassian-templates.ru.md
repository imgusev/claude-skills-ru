## Воркфлоу { #workflows }

### Процесс создания шаблона { #template-creation-process }
1. **Откройте для себя**: Опросите стейкхолдеров, чтобы понять потребности
2. **Анализ**: Ревью существующих шаблонов контента
3. **Дизайн**: Создайте структуру шаблона и заполнители
4. **Реализовать**: Создать шаблон с макросами и форматированием
5. ** Тест**: Проверка с использованием выборочных данных — подтвердите правильность отображения шаблона в предварительном просмотре перед публикацией
6. **Документ**: Создание инструкций по использованию
7. **Опубликовать**: Деплою в соответствующем пространстве/проекте с помощью MCP (смотрите операции MCP ниже)
8. **Проверка**: Подтвердите успешное развертывание; при возникновении ошибок выполните откат к предыдущей версии
9. ** Обучать**: Обучать пользователей использованию шаблонов
10. ** Мониторинг**: Отслеживание внедрения и сбор отзывов
11. **Итерация**: Уточнение на основе использования

### Процесс модификации шаблона { #template-modification-process }
1. **Оценка**: Ревью запроса на изменение и влияние
2. **Версия**: Создайте новую версию, оставьте старую доступной
3. **Изменить**: Обновить структуру/содержание шаблона
4. ** Тест **: Проверка изменений, не нарушающих существующее использование; предварительный просмотр обновленного шаблона перед публикацией
5. **Перенести**: Укажите путь переноса для существующего контента
6. **Общаться**: Объявлять пользователям об изменениях
7. **Поддержка**: Помощь пользователям в миграции
8. **Архив**: Отмените старую версию после перехода; подтвердите, что устаревший шаблон отсутствует в списке, а не удален

### Разработка проекта { #blueprint-development }
1. Определите область применения и цель проекта
2. Разработайте многостраничную структуру
3. Создайте шаблоны страниц для каждого раздела
4. Настройка правил создания страниц
5. Добавление динамического контента (запросы Jira, пользовательские данные)
6. Сквозной процесс создания тестовой схемы с использованием пространства для выборки
7. Убедитесь, что все ссылки на макросы разрешены правильно перед развертыванием
8. **ХЭНДОФФ ДЛЯ**: Администратор Atlassian для глобального развертывания

## Библиотека шаблонов слияния { #confluence-templates-library }

Видишь `references/template-design-patterns.md` для шаблонов проектирования шаблонов и `references/governance-framework.md` для модели управления. Для разметки формата хранилища, готового к развертыванию, используйте входящий в комплект scaffolder (см. [Держатель шаблона для строительных лесов](#template-scaffolder-generate-storage-format-markup) ниже). Ниже кратко описаны стандартные типы, которые создает и поддерживает этот скилл.

### Типы шаблонов слияния { #confluence-template-types }
| Шаблон | Цель | Используемые ключевые макросы |
|----------|---------|-----------------|
| **Заметки о встрече** | Структурированные отчеты о собраниях с повесткой дня, решениями и пунктами действий | `{date}`, `{tasks}`, `{panel}`, `{info}`, `{note}` |
| **Устав проекта** | Масштаб проекта на организационном уровне, RACI стейкхолдеров, сроки и бюджет | `{panel}`, `{status}`, `{timeline}`, `{info}` |
| **Ретроспектива спринта** | Гибкий шаблон церемонии с указанием того, что прошло хорошо / не прошло хорошо / Действия | `{panel}`, `{expand}`, `{tasks}`, `{status}` |
| **PRD** | Определение функции с указанием целей, пользовательских историй, функциональных/нефункциональных требований и плана выпуска | `{panel}`, `{status}`, `{jira}`, `{warning}` |
| **Журнал принятия решений** | Структурированный анализ вариантов с матрицей решений и отслеживанием реализации | `{panel}`, `{status}`, `{info}`, `{tasks}` |

**Стандартные разделы** включены во все шаблоны Confluence:
- Панель заголовка с метаданными (владелец, дата, статус)
- Четко обозначенные разделы содержимого со встроенными инструкциями по заполнению
- Элементы действия блокируют использование `{tasks}` макрос
- Ссылки по теме и справочные материалы

### Полный пример: шаблон заметок о встрече { #complete-example-meeting-notes-template }

> **Предупреждение о формате**: Приведенный ниже пример **устаревшая вики-разметка** (`{panel}`, `h2.`, `{tasks}`), показанный для удобства чтения человеком. Вики-разметка не является форматом хранения Confluence и ** будет отклонена** `mcp__atlassian__createConfluencePage` / `updateConfluencePage`, которые ожидают формат хранения (XHTML, `<ac:structured-macro>` элементы) или ADF. Чтобы получить готовый к развертыванию эквивалент формата хранилища, запустите scaffolder: `python3 scripts/template_scaffolder.py meeting-notes` (см. [Держатель шаблона для строительных лесов](#template-scaffolder-generate-storage-format-markup)).

```
{panel:title=Meeting Metadata|borderColor=#0052CC|titleBGColor=#0052CC|titleColor=#FFFFFF}
*Date:* {date}
*Owner / Facilitator:* @[facilitator name]
*Attendees:* @[name], @[name]
*Status:* {status:colour=Yellow|title=In Progress}
{panel}

h2. Agenda
# [Agenda item 1]
# [Agenda item 2]
# [Agenda item 3]

h2. Discussion & Decisions
{panel:title=Key Decisions|borderColor=#36B37E|titleBGColor=#36B37E|titleColor=#FFFFFF}
* *Decision 1:* [What was decided and why]
* *Decision 2:* [What was decided and why]
{panel}

{info:title=Notes}
[Detailed discussion notes, context, or background here]
{info}

h2. Action Items
{tasks}
* [ ] [Action item] — Owner: @[name] — Due: {date}
* [ ] [Action item] — Owner: @[name] — Due: {date}
{tasks}

h2. Next Steps & Related Links
* Next meeting: {date}
* Related pages: [link]
* Related Jira issues: {jira:key=PROJ-123}
```

> Примеры форматов хранения для других встроенных типов (журнал принятия решений, рансбук, начало проекта) взяты из `python3 scripts/template_scaffolder.py --list`; шаблоны проектирования для остальных типов (Устав проекта, ретроспектива Спринта, PRD) находятся в `references/template-design-patterns.md`.

## Библиотека шаблонов Jira { #jira-templates-library }

### Типы шаблонов Jira { #jira-template-types }
| Шаблон | Цель | Ключевые разделы |
|----------|---------|--------------|
| **История пользователя** | Запросы функций в формате / I want / So that | Критерии приемлемости (даны/Когда/Затем), ссылки на дизайн, Технические примечания, Определение выполненного |
| **Отчет об ошибке** | Фиксация дефектов с этапами воспроизведения | Среда, шаги для воспроизведения, Ожидаемое и фактическое поведение, серьезность, обходной путь |
| ** Эпический** | Сфера охвата инициативы высокого уровня | Видение, цели, Показатели успеха, Разбивка истории, зависимости, временная шкала |

**Стандартные разделы** включены во все шаблоны Jira:
- Четкая итоговая строка
- Критерии принятия или успеха в качестве флажков
- Блок связанных проблем и зависимостей
- Определение "Сделано" (для историй)

## Рекомендации по использованию макросов { #macro-usage-guidelines }

** Динамический контент**: Используйте макросы для автоматического обновления контента (даты, упоминания пользователей, запросы Jira).
**Визуальная иерархия**: Используйте `{panel}`, `{info}`, и `{note}` для создания визуального различия
**Интерактивность**: Используйте `{expand}` для разборных секций в длинных шаблонах
** Интеграция**: Встраивание диаграмм и таблиц Jira с помощью `{jira}` макрос для оперативных данных

## Каркас шаблона — генерирует разметку формата хранилища { #template-scaffolder--generate-storage-format-markup }

Входящий в комплект scaffolder выдает **Confluence storage-формат XHTML** — точный формат тела `createConfluencePage`/`updateConfluencePage` прими это. Это канонический путь развертывания для этого скилла:

```bash
# List available template types (meeting-notes, decision-log, runbook, project-kickoff, custom)
python3 scripts/template_scaffolder.py --list

# Generate a template body (storage-format XHTML)
python3 scripts/template_scaffolder.py meeting-notes

# Custom template with chosen sections and macros, JSON output for programmatic use
python3 scripts/template_scaffolder.py custom --sections "Overview,Goals,Action Items" --macros "toc,status,info" --format json
```

Потребляйте выходные данные: используйте `CONFLUENCE STORAGE FORMAT MARKUP` блок (текстовый режим) или поле разметки (режим JSON) и передайте его дословно как `body` из `mcp__atlassian__createConfluencePage`. Затем примените предложенные метки через пользовательский интерфейс Confluence (инструменты для создания меток отсутствуют в MCP).

## Интеграция Atlassian MCP { #atlassian-mcp-integration }

**Основной инструмент**: Удаленный MCP-сервер Atlassian (входит в комплект поставки `.mcp.json`, серверный ключ `atlassian`). Поверхность инструментов как `mcp__atlassian__<toolName>` (Верблюжий футляр). **Канонический список инструментов**: `project-management/references/atlassian-mcp-tools.md`. Никогда не придумывайте названия инструментов — если возможности нет в этом списке, она недоступна через MCP; перейдите к веб-интерфейсу или REST API.

### Операции с шаблонами через MCP { #template-operations-via-mcp }

Получить `cloudId` один раз через `mcp__atlassian__getAccessibleAtlassianResources`. Замените заполнители угловых скобок реальными значениями; узнайте точные названия параметров из схемы каждого инструмента во время вызова.

**Создайте страницу шаблона слияния** (основная часть из приведенного выше шаблона scaffolder):
```
mcp__atlassian__createConfluencePage (cloudId, space, title="Template: Meeting Notes",
  body=<storage-format XHTML from template_scaffolder.py>, parent page id optional)
```
Этикетки (`template`, `meeting-notes`) должен быть применен в пользовательском интерфейсе Confluence — здесь нет инструмента MCP label.

**Обновите существующую страницу шаблона** (сначала прочтите, чтобы получить текущую версию):
```
mcp__atlassian__getConfluencePage (cloudId, pageId=<existing page id>)
mcp__atlassian__updateConfluencePage (cloudId, pageId=<id>, version=<current + 1>,
  body=<updated storage-format content>)
```

**Шаблоны описания проблемы Jira**: отсутствует ** инструмент MCP для настройки полей ** (`default_value` в поле описания, экранах, контекстах полей). Настройте значения описания по умолчанию в пользовательском интерфейсе администратора Jira (`Settings > Issues > Field configurations`) или через REST (`/rest/api/3/fieldconfiguration`). Что МОЖЕТ сделать MCP: создавать вопросы, предварительно заполненные текстом шаблона, с помощью `mcp__atlassian__createJiraIssue` (передайте текст шаблона в качестве описания) и проверьте обязательные поля для каждого типа проблемы с помощью `mcp__atlassian__getJiraIssueTypeMetaWithFields`.

**Первоклассные шаблоны/чертежи слияния** также ** не могут быть созданы с помощью MCP** — `createConfluencePage` создает обычные страницы, которые служат в качестве шаблонов для копирования. Чтобы зарегистрировать шаблон реального пространства, используйте `Space settings > Templates` в пользовательском интерфейсе.

**Деплей страницы шаблона в нескольких пространствах (пакетное):**
```
# Repeat per target space:
mcp__atlassian__createConfluencePage (cloudId, space=<target>, title="Template: Meeting Notes", body=<storage-format content>)
# Verify each create before proceeding:
mcp__atlassian__getConfluencePage (cloudId, pageId=<id returned by create>)
# Assert the returned body is non-empty and contains the expected <ac:structured-macro> elements
```

**Контрольная точка проверки после развертывания:**
- Извлеките созданную/обновленную страницу с помощью `mcp__atlassian__getConfluencePage` и утверждайте, что он рендерится без ошибок макроса
- Убедитесь, что Jira-macro внедряет resolve в целевой проект Jira
- Подтвердите, что блоки задач являются интерактивными в опубликованном представлении
- Если какая-либо проверка завершится неудачей: вернитесь с помощью `mcp__atlassian__updateConfluencePage` с `version: <current + 1>` и тело предыдущей версии

## Лучшие практики и управление { #best-practices--governance }

**Стандарты, специфичные для организации:**
- Отслеживайте версии шаблонов с примечаниями к версиям в заголовке страницы
- Отметьте устаревшие шаблоны с помощью `{warning}` баннер перед архивацией; заархивировать (не удалять)
- Поддерживайте руководства по использованию, связанные с каждым шаблоном
- Собирайте отзывы о ежеквартальном цикле ревью; включайте показатели использования, прежде чем отказаться от использования

**Гейты качества (применяются перед каждым развертыванием):**
- Пример содержимого, представленного для каждого раздела
- Протестировано с использованием выборочных данных в режиме предварительного просмотра
- Комментарий к версии добавлен в журнал изменений
- Внедрен механизм обратной связи (включены комментарии или связанный опрос)

**Процесс управления**:
1. Запрос и обоснование
2. Разработка и ревью
3. Тестирование с пилотными пользователями
4. Документация
5. Одобрение
6. Развертывание (с помощью MCP или вручную)
7. Тренировка
8. Мониторинг

## Протоколы Хэндоффа { #handoff-protocols }

Краткое изложение Хэндоффа (контекст управления в `references/governance-framework.md`):

| Партнер | Получает ОТ | Отправляет В |
|---------|--------------|---------|
| **Старший премьер-министр** | Требования к шаблонам, шаблоны отчетности, исполнительные форматы | Готовые шаблоны, аналитика использования, предложения по оптимизации |
| **Scrum-мастер** | Потребности в церемонии спринта, пожелания конкретной команды, предпочтения в ретро формате | Готовые к спринту шаблоны, гибкие структуры церемоний, шаблоны отслеживания скорости |
| **Эксперт Jira** | Требования к шаблону выпуска, требования к отображению пользовательских полей | Шаблоны описания проблемы, шаблоны конфигурации полей, шаблоны запросов JQL |
| **Эксперт по слияниям** | Потребности, связанные с конкретным пространством, запросы на глобальный шаблон, требования к чертежам | Настроенные шаблоны страниц, структуры чертежей, планы развертывания |
| **Администратор Atlassian** | Стандарты для всей организации, глобальные требования к развертыванию, шаблоны соответствия | Глобальные шаблоны для утверждения, отчетов об использовании, статуса соответствия |
