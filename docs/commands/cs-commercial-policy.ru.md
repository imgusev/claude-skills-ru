Запустите `commercial-policy` скилл на основе этого ввода:

**$ARGUMENTS**

## Воркфлоу с тремя инструментами { #three-tool-workflow }

1. **`discount_matrix_builder.py`** — Диапазоны скидок, подкрепленные данными (по диапазону ARR × продолжительности срока × условиям оплаты × стратегической ценности). Выводит матрицу + уровень утверждающего для каждой ячейки. Отраслевая настройка `--profile {saas,enterprise-software,api,marketplace,services}`.

2. **`exception_router.py`** — Поток исключений: когда в сделке запрашиваются условия, выходящие за рамки матрицы, кто утверждает и какие компенсационные обязательства требуются (многолетний контракт + предоплата + именованный путь расширения).

3. **`policy_linter.py`** — Проверка согласованности по всей матрице: нет противоречий (например, "Менеджер одобряет до 25%", но "вице-президент одобряет до 20%"), нет пробелов (диапазон сделок без определенного утверждающего), нет очевидной игровой поверхности (обрыв 99% против 100%).

## Жесткое правило { #hard-rule }

** Нет диапазона скидок без резервной копии данных.** Проверьте коэффициент выигрыша и NRR по текущему диапазону, прежде чем рекомендовать изменения.

## Отличный от { #distinct-from }

- Родной брат `commercial/skills/deal-desk` — ** политика применяется** к индивидуальным сделкам. Коммерческая политика **разрабатывает** политику.
- Родной брат `commercial/skills/pricing-strategist` — устанавливает модель ценообразования ** + прайс-лист уровня **. Коммерческая политика регулирует ** скидки вне списка**.
- `c-level-advisor/cro-advisor` — стратегический
- `c-level-advisor/cfo-advisor` — финансовые защитные барьеры (минимальный уровень маржи); коммерческая политика вводит их в действие
