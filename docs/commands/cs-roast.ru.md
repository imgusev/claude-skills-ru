# /cs-roast

<span class="meta-badge">:material-console: Слэш-команда</span>
<span class="meta-badge">:material-github: <a href="https://github.com/imgusev/claude-skills-ru/tree/main/productivity/roast/commands/cs-roast.md">Источник</a></span>

**Команда:** `/cs:roast [the idea]`

Клод по умолчанию соглашается с вами. `/roast` все наоборот. Он собирает пять независимых
рецензентов, которые разбирают идею на части и рассматривают ее со всех сторон, а затем выступают в роли судьи, выносящего
один честный вердикт. Запустите его, прежде чем тратить время и деньги на создание чего-то неправильного.

## Когда запускать { #when-to-run }

- "Обжаривание / испытание давлением / стресс-тест этой идеи"
- "Утвердить эту бизнес-идею" / "созвать дискуссионную группу"
- "Выскажи мне жестокое второе мнение, прежде чем я построю это"
- Вы хотите по—настоящему принять решение - и вы можете ответить "нет".

## Когда не следует бегать { #when-not-to-run }

- Вам нужна поддержка или мягкий мозговой штурм. Это существует для того, чтобы сказать вам, что идея мертва, когда она есть.
- Кросс-функциональное корпоративное решение, требующее полного использования C-suite → `/cs:boardroom`.
- Чисто фактический поиск без какого-либо прилагаемого решения.

## Что Вы получаете { #what-you-get }

1. ** Один общий бриф** — собран из идей / воз / денег / преимуществ / ограничений (`brief_builder.py`).
2. ** Параллельно работают пять рецензентов**, каждый из которых оценивает свой собственный показатель от 1 до 10:
   - Критик ("Что убивает это?"), Чемпион ("10-кратный рост?"), Аналитик ("соответствует ли логика
     удерживать?", нет интернета), Исследователь ("что говорит рынок?", Интернет), Клиент ("буду ли я платить?").
3. **Один вердикт** — `GO / RESHAPE / KILL` + уверенность, полученная от взвешенного синтезатора (не среднее значение;
   требование /фатальный недостаток/логические гейты могут наложить вето на ХОД), при этом реальная напряженность названа и устранена.
4. ** Считывание денег ** + ** самый дешевый 48-часовой тест ** с явными сигналами о прохождении / неудаче.

## Фразы-триггеры (автоматический вызов без /cs:) { #trigger-phrases-auto-invoke-without-cs }

- "поджарь эту идею" / "поджарь мою идею"
- "испытайте это давлением" / "стресс-тестируйте эту идею"
- "утвердить эту бизнес-идею" / "созвать дискуссионную группу"
- "жестокое повторное мнение, прежде чем я начну строить"

## Дисциплина { #discipline }

- ** Одинаковое резюме для всех пятерых** — они должны судить об одном и том же.
- **Параллельный, а не последовательный** — пять `Task` звонки в одном сообщении, чтобы они думали независимо.
- **Никогда не усредняйте** — запустите синтезатор, устраните напряжение.
- ** Гейты накладывают вето на ПЕРЕХОД ** — отсутствие покупателя, обнаруженный фатальный недостаток или нарушенная логика ограничивают доступ к заявке ниже.
- ** Завершение фальсифицируемого теста ** — назовите его, укажите стоимость, установите временные рамки, укажите "пройдено"/"не пройдено".

## Воркфлоу { #workflow }

```bash
# 1. Assemble the shared brief
python ../skills/roast/scripts/brief_builder.py \
  --idea "..." --who "..." --money "..." --edge "..." --constraints "..."

# 2. Fire all five reviewers in parallel (one Task each, subagent_type: general-purpose),
#    pasting the same brief into each. Collect five 1-10 scores.

# 3. Synthesize the call (weighting + veto gates + tension, NOT an average)
python ../skills/roast/scripts/verdict_synthesizer.py \
  --critic 4 --champion 8 --analyst 7 --investigator 5 --customer 6

# 4. Design the cheapest test from the riskiest assumption
python ../skills/roast/scripts/cheapest_test_designer.py --risk price --price 99
```

## Условия остановки { #stop-conditions }

- Вынесен вердикт (ПЕРЕЙТИ/ИЗМЕНИТЬ ФОРМУ /УБИТЬ) + уверенность + самый дешевый тест → выполнено.
- Пользователь вводит новые данные → повторно обжаривает измененное измерение. В противном случае удерживайте вызов.
- Пользователь говорит "стоп" → отбросьте это.
