Создайте краткий, обоснованный гейт-документ с требованиями к продукту для `$ARGUMENTS`.

## Использование { #usage }

```bash
/prd <feature-or-problem>
```

`$ARGUMENTS` это особенность, инициатива или постановка проблемы. Если пусто, попросите об этом, прежде чем делать что-либо еще.

## Фаза 1 — Форсированные вопросы (перед любым составлением проекта) { #phase-1--forcing-questions-before-any-drafting }

Пройдите по ним по одному за раз. Не смешивайте их в пакеты. Каждый ответ содержит необходимый раздел PRD.

1. ** Проблема** — Какую проблему пользователя это решает, и откуда вы знаете, что она существует? (Доказательства: заявки в службу поддержки, цитаты из интервью, данные воронки — "генеральный директор хочет этого" не являются доказательствами.)
2. **Пользователь** — У кого конкретно возникла эта проблема? (Сегмент, роль, частота возникновения боли. "Все" - это не ответ.)
3. ** Метрика** — Какое отдельное число перемещается, если это работает, на сколько, где измеряется?
4. ** Альтернативы** — Что эти пользователи делают сегодня вместо этого? Почему этого недостаточно?
5. **Нецелевые** — Какие смежные запросы явно выходят за рамки версии 1?

## Составление гейта (жесткий отказ) { #drafting-gate-hard-refusal }

** Откажитесь от составления PRD, если ответ на вопрос 1 (проблема), 2 (пользователь) или 3 (показатель) неизвестен, является циклическим или "мы разберемся с этим позже".** Вместо этого выведите открытые вопросы и самый дешевый способ ответить на каждый (например, 5 интервью с клиентами, воронкообразный запрос, тест на фальшивую дверь). PRD без проблем, пользователя и метрики - это пожелание к функции, а не документ с требованиями.

## Этап 2 — Черновик (чек-лист обязательных разделов) { #phase-2--draft-required-sections-checklist }

Каждый PRD должен содержать все эти разделы — приведите чек-лист в конце и отметьте каждый из них:

- [ ] Постановка задачи (с доказательствами из Q1)
- [ ] Целевой пользователь и сегмент (со второго квартала)
- [ ] Цели и явно выраженные нецелевые задачи (из 5-го квартала)
- [ ] Истории пользователей с критериями приемлемости
- [ ] Показатель успеха + порог + источник измерения (из 3-го квартала)
- [ ] Рассмотренные альтернативы / базовый уровень "ничего не делать" (с 4 квартала)
- [ ] Область применения, зависимости и допущения о сроках
- [ ] Открытые вопросы и риски

Сократите его до ~ 2 страниц. Используйте шаблон репозитория в качестве каркаса.

## Фаза 3 — Крючок для определения приоритетов (необязательно) { #phase-3--prioritization-hook-optional }

Если у пользователя есть несколько функций-кандидатов, предложите предварительно оценить их перед выполнением PRD:

```bash

```
