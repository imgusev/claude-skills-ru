**Команда:** `/cs:research <research question>`

Тот `cs-research` персона - это ** точка входа по умолчанию для любого запроса на исследование**. Направляет к специалисту или запускает резервный вариант. Всегда прозрачно принимайте решение о маршруте.

## Отличный от `engineering/autoresearch-agent` { #distinct-from-engineeringautoresearch-agent }

Они используют одно и то же слово "исследование", но служат для ** разных вариантов использования**:
- **`/cs:research`** (эта команда) — исследование-маршрутизация запросов + резервный воркфлоу
- **`engineering/autoresearch-agent`** — цикл автономного эксперимента по оптимизации файлов (шаблон Карпатии)

Никакого перекрытия. Не путайте их.

## Когда запускать { #when-to-run }

- По умолчанию для ЛЮБОГО запроса на исследование — позвольте маршрутизатору выбрать правильный инструмент
- Вы не уверены, к какому специалисту обратиться
- Вам нужен запасной вариант, если ни один специалист не подойдет
- Вам нужна единая точка входа для исследовательской работы

## Когда не следует бегать { #when-not-to-run }

- Вы уже знаете, к какому специалисту обращаетесь — обратитесь к нему напрямую (`/cs:litreview`, `/cs:grants`, и т.д.) и пропустите шаг маршрутизации
- Вы хотите провести эксперименты по оптимизации файлов - используйте `engineering/autoresearch-agent`

## 6 Целей маршрутизации { #the-6-routing-targets }

| Специалист | Маршруты, когда в вопросе упоминается |
|---|---|
| `pulse` | reddit / hn / x / buzz / настроения / тренд / "пульс включен" |
| `grants` | NIH / грант / R01 / K-премия / Репортер / "Гранты для" |
| `litreview` | ревью литературы / PICO / SPIDER / систематический ревью |
| `syllabus` | прилагаемая учебная программа / план курса / список литературы |
| `patent` | уровень техники / FTO / свобода эксплуатации / патент / новизна |
| `dossier` | "досье на" / due diligence / проверка биографических данных / "подготовьте меня к" |

## Минимальный прием (2-4 вопроса) { #minimal-intake-2-4-questions }

| Вопрос | Спрашивает | Когда |
|---|---|---|
| Вопрос 1 | Исследовательский вопрос (1-2 предложения, конкретные) | Всегда |
| Q2 | Вывод: краткое описание быстрого чата ИЛИ автономный файл .docx | Всегда |
| Вопрос 3 | Устранение неоднозначности в домене (список выбора из 7 вариантов с рекомендуемым ответом при совпадении одного сигнала) | Когда классификация неоднозначна ИЛИ совпадает один сигнал с простым существительным |
| Q4 | Временной интервал для общего исследования (быстрое 5 против тщательного 15) | Только тогда, когда был необходим Q3 И пользователь выбрал "ничего из вышеперечисленного". |

Большинство вызовов завершаются в Q2.

## Прозрачность маршрутизации (обязательная) { #routing-transparency-mandatory }

После классификации скилл ** всегда**:

1. Излагает решение в одном предложении: "Маршрутизация в `litreview` потому что вы упомянули PICO и систематический ревью (2 сигнала)."
2. Предлагает переопределить: "Если вам нужны общие исследования вместо этого или другой специалист, так и скажите".
3. Продолжает следовать рекомендуемому маршруту, если пользователь не возражает (без таймеров).
4. Если пользователь переопределяет → принимает, перенаправляет, регистрирует переопределение.

**Никогда не делегируйте молча.** Это свойство, укрепляющее доверие, которое заставляет работать гибридный шаблон.

## Что Вы получаете { #what-you-get }

**Если делегировано специалисту:** полный вывод специалиста (Markdown briefing ИЛИ .docx, в зависимости от специалиста). Помеченный `[Delegated to: research → {specialist}]`.

**Если есть запасной вариант:** скилл запускает свой собственный 8-шаговый воркфлоу-процесс и производит:

```
# [Research Question] — Briefing
*Generated: [DATE] | Routed: fallback*

## TL;DR
[2-3 sentences]

## Findings
### [Sub-question 1]
[2-4 paragraphs with inline citations]
### [Sub-question 2]
...

## Cross-Cutting Patterns
[1-2 paragraphs]

## Sources
[Numbered + hyperlinked + reliability tier per source]

## Audit
[Three counts + per-source tier + failures]
```

Версия DOCX использует ту же структуру, что и стиль research-pack.

## Дисциплина { #discipline }

- **Детерминированная классификация** (НЕ обоснованная LLM) - сопоставление сигналов по ключевым словам с помощью `classifier.py`
- **Обязательная прозрачность маршрутизации ** — никогда не отключается
- **Делегирование специалистов является сквозным ** - не отвечайте предварительно на вопросы специалистов
- ** Резервный вариант после третьего квартала ** если ни один специалист не подходит
- **Отказаться от общего "исследования [тема]"** специалисту без парного существительного "специалист"
- **Отслеживание по трем счетам ** в резервном режиме
- **Дисциплина источника** — цитировать только это-сеансовые вызовы инструмента

## Воркфлоу { #workflow }

```bash
# Phase 1 intake (Q1 + Q2 minimum)

# Phase 2 classification
python ../skills/research/scripts/classifier.py --question "<Q1>"
# Returns: {route_to: "litreview", confidence: "high (2 signals)", matched: [...]}

# Phase 3a delegation (if specialist matched at ≥2 signals)
python ../skills/research/scripts/routing_transparency_logger.py \
  --action record_delegation --session NAME --target litreview --signals "..."
# Pass question to /cs:litreview verbatim; let it run its own intake

# Phase 3b fallback (if no specialist matched)
python ../skills/research/scripts/fallback_decomposer.py --question "<Q1>"
# Returns 3-5 sub-questions
# Run 8-step fallback workflow: source-select → search → read+extract → synthesize → cross-cut → output → audit
```

## Условия остановки { #stop-conditions }

- Специалист делегирован → применяется условие остановки специалиста
- Резервное копирование завершено → доставлена сводка по Markdown или DOCX
- Выбран Q3, но нет четкого специалиста → спросите Q4 (временной горизонт), затем запустите резервный вариант
- Пользователь говорит "стоп" → выдает частичный результат с использованием того, что было собрано

## Фразы-триггеры { #trigger-phrases }

- "исследование [тема]"
- "загляни в [тема]"
- "что мы знаем о [тема]"
- "расследовать [тема]"
- "найди мне информацию о [тема]"
- "проведи некоторое исследование по [тема]"
- "Мне нужно понять [тема]"
- Плюс: любой запрос на исследование, который явно не соответствует более узкому специалисту

## Отклоненные анти-паттерны { #anti-patterns-rejected }

- Обоснованная LLM классификация (должно быть детерминированное соответствие ключевым словам)
- Тихое делегирование (всегда поверхностное решение о маршрутизации)
- Отказ в направлении к специалисту при совпадении ≥2 сигналов
- Бесшумная маршрутизация по одному сигналу, состоящему из одного существительного (например, "финансирование", "управление по санитарному надзору за качеством пищевых продуктов и медикаментов") — вместо этого задайте вопрос 3 с рекомендуемым ответом
- Предварительно ответив на запрос специалиста о приготовлении блюд на гриле
- Прибегать к запасному варианту, когда специалист явно справился бы лучше
- Создание резервных источников при ограниченном поиске
- Пропуск журнала аудита в резервном режиме
- Рассматривающее "досье на [компания]" в качестве запасного варианта, когда `dossier` это правильный специалист
- Рассматривая вопрос "что люди говорят о X" как запасной вариант, когда `pulse` совпадения
- Универсальное исследование с автоматической маршрутизацией " [тема]" без парного существительного "специалист" (вместо этого задайте вопрос 3)
