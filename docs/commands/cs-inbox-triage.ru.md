**Команда:** `/cs:inbox-triage`

Тот `cs-inbox-triage` персона обрабатывает ваш почтовый ящик, используя базу знаний, созданную `/cs:inbox-setup`. Предназначен для повторяющихся запусков (1-3 раза в день) с небольшим потреблением - большинство вызовов пропускают вопросы и выполняются с настройками KB по умолчанию.

## Когда запускать { #when-to-run }

- ** Повторяющаяся частота ** — 1-3 раза в день, в зависимости от вашего `email-taxonomy.md` частота выполнения
- **По требованию** — вне каденции (после длительного перерыва, перед встречей и т.д.)
- ** Предварительная сортировка ** - быстрая проверка только просроченных товаров трекера

** Не запускайте, если** KB еще не существует — Скилл остановится и направит вас к `/cs:inbox-setup` первый.

## ТОЛЬКО ЧЕРНОВИКИ — обсуждению не подлежат { #drafts-only--non-negotiable }

> **Этот скилл создает черновики. Он НИКОГДА не отправляется.**

Это свойство безопасности, которое делает автоматический запуск скилла безопасным. Тот `draft_safety_validator.py` применяет его после запуска. Любой вызов инструмента в форме отправки в журнале действий не проходит проверку.

Если вы хотите, чтобы за вами прислали скилл: не делайте этого. Ревью черновики в вашем почтовом клиенте и отправляйте их самостоятельно. Это сделано специально.

## Потребление света (Максимум 2 дополнительных вопроса) { #light-intake-max-2-optional-questions }

В большинстве случаев оба вопроса полностью пропускаются.

| Вопрос | Спросили, когда | Значение по умолчанию, если пропущено |
|---|---|---|
| Q1 — Переопределить 9-часовое окно по умолчанию? | Запуск по требованию вне нормальной частоты | используйте частоту вращения по умолчанию |
| Q2 — Пропустить категории в этом прогоне? | Пользовательский вызов включает в себя skip-intent ("пропускать информационные бюллетени"). | запустить все категории |

## Что происходит (10 шагов) { #what-happens-10-steps }

После прочтения КБ:

1. **Определите окно поиска ** — частота + сейчас → window_start (по умолчанию 9 часов для 2 раз в день; перекрытие предотвращает пропущенные электронные письма)
2. ** Поиск поставщика электронной почты ** — первичный (входящие + отправлено после window_start) + вторичный (помечено как непрочитанное)
3. **Классифицировать** — применять таксономию; пропускать темы с самым низким приоритетом (информационные бюллетени/автоматизация), не читая
4. ** Поиск новых отправителей ** — веб-поиск потенциальных отправителей, отсутствующих в трекере / блок-листе
5. **Генерировать рекомендации** — применять `evaluation-framework.md` если существует; классифицировать, ПРИНЯТЬ К СВЕДЕНИЮ / СТОИТ РАССМОТРЕТЬ / ПЕРЕДАТЬ / ПОМЕТИТЬ ДЛЯ РЕВЬЮ
6. **Черновики ответов** — сопоставление голоса с `email-patterns.md`. НИКОГДА НЕ ОТПРАВЛЯЙТЕ.
7. **Доставить отчет** — честь `email-taxonomy.md` настройки отчета (электронная почта / файл / чат)
8. **Обновить KB** — добавить новые отклонения к `blocklist.md`; обновить `tracker.md` с новыми/решенными последующими действиями
9. **Внутренний журнал** — запись `triage-log/<YYYY-MM-DD>-<run-label>.md`
10. **Обработка пустых входящих сообщений** — по-прежнему выдает минимальный отчет; помечает просроченные элементы отслеживания

## Воркфлоу { #workflow }

```bash
# 1. Pre-flight — read + validate KB (fail-fast if missing)
python ../skills/inbox-triage/scripts/kb_reader.py --workspace ${WORKSPACE}

# 2. Compute search window
python ../skills/inbox-triage/scripts/search_window_calculator.py \
  --cadence 2x-daily --now $(date -u +%Y-%m-%dT%H:%M)

# 3. Execute Steps 2-10 (described in SKILL.md). For each step, log to:
#    ${WORKSPACE}/Email/triage-log/<date>-<label>.md

# 4. Post-flight — verify NEVER-SEND held
python ../skills/inbox-triage/scripts/draft_safety_validator.py \
  --action-log ${WORKSPACE}/Email/triage-log/$(date +%Y-%m-%d)-*.md
# Failure here is critical — halt + alert user immediately
```

## Условия остановки { #stop-conditions }

- Все 10 шагов выполнены → отчет доставлен + обновлен кбайт + записан журнал
- Отсутствуют файлы размером в КБ → остановить; перейти к `/cs:inbox-setup`
- Инструмент электронной почты недоступен → остановить; сообщить пользователю, какой инструмент необходим
- более 100 новых электронных писем → отмечать объем; предлагать сосредоточиться только на приоритетных категориях
- Пользователь говорит "стоп" → создать частичный отчет из того, что было обработано; отметить остальное

## Важнейшие правила { #critical-rules }

1. ** ТОЛЬКО ЧЕРНОВИКИ — НИКОГДА НЕ ОТПРАВЛЯЙТЕ.** Не подлежит обсуждению.
2. ** Быстрый сбой при отсутствующем КБАЙТ.** Чистая остановка; переход к настройке.
3. ** Уважайте KB.** Задокументированные предпочтения являются источником истины; не переоценивайте их с помощью суждений.
4. ** Конфиденциальность.** Нет учетных данных в KB; ссылайтесь на потоки по идентификатору для конфиденциального контента.
5. ** Прозрачность.** Отмечайте каждое изменение в КБАЙТ в журнале сортировки.
6. ** Первые запуски требуют контроля.** Документировано — система учится на ваших правках и переопределениях.

## Категории принятия решений по сортировке { #triage-decision-categories }

| Категория | Когда | Выход |
|---|---|---|
| ** ВОЗЬМИ ЭТО** | Соответствует критериям из `evaluation-framework.md` | Рекомендую принять участие; черновик ответа |
| **СТОИТ РАССМОТРЕТЬ** | Обладает потенциалом, нуждается в оценке пользователя | Контекст поверхностного ключа; черновик ответа для редактирования пользователем |
| **ПРОЙТИ** | Не соответствует критериям | Краткое "почему"; черновик вежливого отказа |
| **ОТМЕТЬТЕ ДЛЯ РЕВЬЮ** | Необычно; требуется прямое решение пользователя | Поверхность полностью обработана; осадка отсутствует (пользователь определяет форму отклика) |

## Отклоненные анти-паттерны { #anti-patterns-rejected }

- **Отправка электронных писем** — только черновики, обсуждению не подлежат
- Работа без файлов базы знаний
- Хранение паролей / учетных данных в КБАЙТ
- Пропуск цикла обучения (обновления KB) в конце выполнения
- Переопределение задокументированных предпочтений пользователя собственным суждением
- Чтение потоков с самым низким приоритетом (пустая трата контекста)
- Включение предварительного просмотра чернового текста в отчет (черновики уже есть в почтовом клиенте)
- Блокировка провайдера без шаблона адаптера
- Молчаливый сбой из-за отсутствующих инструментов
