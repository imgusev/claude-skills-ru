**Команда:** `/cs:inbox-setup`

Тот `cs-inbox-setup` персона проведет собеседование из 8 разделов, чтобы создать свою персонализированную базу знаний по сортировке электронной почты в `${WORKSPACE}/Email/`.

## Когда запускать { #when-to-run }

- **Первый раз ** настройка сортировки электронной почты
- ** Изменения в бизнесе** — новая роль, новые предложения, новый состав клиентов
- ** Изменения в ценах** — необходимо обновить вашу тарифную карту
- ** Смена почтового ящика ** — значительно различающийся объем электронной почты или сочетание категорий

НЕ запускайте, если ваш существующий KB по-прежнему соответствует действительности. Повторный запуск обходится дорого (~20 минут интервью). Если требуется обновить только один параметр, отредактируйте файл KB напрямую.

## Эта пара { #the-pair }

Это одна половина пары:

- `/cs:inbox-setup` (эта команда) — **записывает** КБАЙТ (выполняется один раз)
- `/cs:inbox-triage` — ** считывает + добавляет** КБАЙТ (выполняется повторно)

Оба имеют строгий контракт на 7 файлов. Видишь [`kb_file_contract.md`](https://github.com/imgusev/claude-skills-ru/tree/main/productivity/email/skills/inbox-setup/references/kb_file_contract.md) для спецификации.

## Что ты получишь { #what-youll-get }

После ~25-31 вопроса по 8 разделам (около 15-20 минут) скилл-мастер создает эти файлы в `${WORKSPACE}/Email/`:

| Файл | Всегда создавался? | Содержание |
|---|---|---|
| `email-taxonomy.md` | ✓ | Категории + сигналы + действия по умолчанию + настройки отчета |
| `email-patterns.md` | ✓ | Регистрация голоса + выход из системы + персона + жесткие правила + шаблоны |
| `evaluation-framework.md` | Только в том случае, если у пользователя есть возможности | Дерево решений + сигналы "ПРИНИМАЙ" + сигналы "ПРОПУСКАТЬ" + список VIP-персон |
| `rate-card.md` | Только в том случае, если у пользователя есть цена | Стандартное ценообразование + условия + позиция на переговорах |
| `blocklist.md` | ✓ (посеянный) | Автоматический пропуск отправителей + шаблоны отклонения; увеличивается с течением времени при сортировке |
| `tracker.md` | ✓ (посеянный) | Активные последующие действия + просрочка + крайние сроки |
| `triage-log/` | ✓ (пустой каталог) | Журналы сортировки для каждого запуска (заполняются с помощью сортировки входящих сообщений) |

## Дисциплина "Гриль-я" { #grill-me-discipline }

- ** По одному вопросу за ход. ** Никогда не связывайтесь. Даже через границы участка.
- ** Принудительный формат там, где это возможно.** Множественный выбор > открытый для принятия решений с высоким коэффициентом использования.
- ** "Почему я спрашиваю" на каждый вопрос ** — чтобы вы могли хорошо ответить.
- **Упорядоченный по зависимостям.** Q2 зависит от Q1; нижестоящие разделы зависят от восходящего потока.
- **Фиксация для каждого раздела.** Каждый раздел записывает свои файлы в конце. Если вы откажетесь от участия в середине собеседования, частичный KB все еще можно использовать.
- ** Пропустить-логика.** Раздел 4 (Фреймворк оценки) полностью пропущен, если в разделе 1 не появилось возможности - категория электронной почты.
- ** Конфиденциальность.** Никогда не сохраняйте пароли, номера учетных записей, SSN, учетные данные в файлах KB.
- ** Повторный запуск в безопасном режиме.** Для существующих файлов появляется промпта о согласии для каждого файла: заменить / объединить / пропустить.

## 8 разделов { #the-8-sections }

1. ** Общая картина** — роль, доминирующие категории входящих сообщений, распределение объема, адреса, частота выполнения, делегирование (6 вопросов)
2. **Категории электронной почты** — предложите таксономию из S1, подтвердите, уточните (3 вопроса) → пишет `email-taxonomy.md`
3. ** Стиль ответа и голос ** — регистрация, любимые раздражители, выход из системы, персона, длина, жесткие правила + ** вставьте 3-5 реальных отправленных электронных писем ** (7 вопросов + примеры) → записи `email-patterns.md`
4. **Фреймворк оценки** (условный) — внутренний фильтр, нарушители сделок, аттракторы, ценообразование, переговоры, список VIP-персон (6 вопросов) → записи `evaluation-framework.md` + `rate-card.md`
5. **Список блокировок и шаблоны** — пропуск отправителей, шаблоны отклонения, потери времени (3 вопроса) → записи `blocklist.md`
6. **Текущее состояние** — активные темы, просроченные ответы, крайние сроки (3 вопроса) → записи `tracker.md` + создает `triage-log/`
7. **Настройки отчета** — формат доставки, уровень детализации, основные приоритеты отчета (3 вопроса) → добавляется к `email-taxonomy.md`
8. **Подтверждение и Хэндофф** — инвентаризация файлов + сообщение о хэндоффе → направляет вас к `/cs:inbox-triage`

** Условие остановки: ** всего ~ 25-31 вопрос (S4 пропускает ~ 6). Жесткий потолок 35. Никогда не открывайте повторно после S8 — повторно запустите скилл, чтобы изменить настройки.

## Воркфлоу { #workflow }

```bash
# 1. Detect workspace + check for existing KB
ls ${WORKSPACE}/Email/

# 2. If exists → re-run mode (per-file replace/merge/skip).
#    If fresh → start session:
python ../skills/inbox-setup/scripts/section_progress_tracker.py \
  --action start --session "inbox-setup-$(date +%Y%m%d)" --user "<who>"

# 3. Walk S1 → S2 → ... → S8 (one Q per turn).

# 4. At S3.SAMPLES, analyze pasted emails:
python ../skills/inbox-setup/scripts/voice_sample_analyzer.py --samples-file /tmp/samples.txt

# 5. At end of each section, write its file(s) + record:
python ../skills/inbox-setup/scripts/section_progress_tracker.py \
  --action record_section_done --session NAME --section N --files "..."

# 6. At S8, validate final state + close session:
python ../skills/inbox-setup/scripts/kb_validator.py --workspace ${WORKSPACE}
python ../skills/inbox-setup/scripts/section_progress_tracker.py --action close --session NAME
```

## Условия остановки { #stop-conditions }

- Все 8 разделов завершены (или S4 пропущен) → сообщение о хэндоффе + готово
- Пользователь говорит "стоп" в середине интервью → сохранить часть КБ; отметьте в `[needs follow-up]`; предложение возобновить позже
- Рабочее пространство недоступно → остановить; сообщить пользователю, куда будут отправляться файлы; запросить разрешение/путь

## Отклоненные анти-паттерны { #anti-patterns-rejected }

- Генерирование всех файлов сразу вместо пошаговых разделов
- Групповые вопросы
- Жестко запрограммированные ссылки на провайдера (только для Gmail)
- Сохранение конфиденциальных учетных данных в КБ
- Пропуская объяснение "почему этот вопрос имеет значение"
- Пропуск примера -запрос по электронной почте в S3 (это голосовой сигнал самого высокого качества)
- Перезапись существующих файлов без согласия на повторный запуск
- Принудительное создание `rate-card.md` или `evaluation-framework.md` когда они неприменимы
