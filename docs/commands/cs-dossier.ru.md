**Команда:** `/cs:dossier <entity>`

Тот `cs-dossier` Персона создает проверенное гипотезами исследовательское досье на конкретную компанию, человека, некоммерческую или правительственную организацию, а не общий профиль.

## Когда запускать { #when-to-run }

- Встреча по продажам / предложение о партнерстве (нужны зацепки для разговора, привязанные к специфике)
- Тщательная проверка инвестиций / приобретений
- Журналистика / личная проверка (за исключением случаев, связанных с конфиденциальностью)
- Подготовка к собеседованию при приеме на работу
- Конкурентная разведка

## Когда не следует бегать { #when-not-to-run }

- Обычное любопытство ("чем занимается эта компания?") → самостоятельно поищите в Интернете
- Быстрый поиск → быстрее, чем просто в Google
- Нет гипотезы для проверки → скилл отказывается работать по замыслу

## Не является универсальным по дизайну { #non-generic-by-design }

Скилл отказывается быть кратким изложением в Википедии. Вопрос 4 (ваша гипотеза) является ** обязательным** — без него досье подтверждает то, что вы уже думаете, и бесполезно для принятия решений.

## Принудительный прием пищи (6 вопросов, по одному за раз) { #forcing-intake-6-questions-one-at-a-time }

| Вопрос | Спрашивает | Примечания |
|---|---|---|
| Вопрос 1 | Идентификация субъекта (имя + идентификатор, устраняющий неоднозначность) | отказывается от двусмысленных имен |
| Q2 | Тип темы: физическое лицо / компания / некоммерческая организация / государственная организация / другое | принудительный выбор — управляет исходной матрицей |
| Вопрос 3 | Цель: продажи / инвестиции / приобретение / журналистика / интервью / конкурс / проверка / другое | выбор форсировки — угол наклона приводов + чувствительность |
| Q4 | **Гипотеза (ОБЯЗАТЕЛЬНАЯ)** — то, во что вы уже верите + хотите проверить/опровергнуть | не пропускается; при отказе возвращается один раз |
| Q5 | Глубина: 5-минутное краткое или 15-минутное досье для принятия решения | вынуждающий выбор |
| Q6 | Чувствительность, которую необходимо исключить | условный — только в том случае, если Q3 ∈ {journalism, personal vetting} |

Условие остановки: после Q6 (или ранее с пропусками) зафиксируйте и запустите фазу 2. Никогда не открывайте повторно.

## Что Вы получаете { #what-you-get }

После завершения всех этапов:

```
dossier_<entity-slug>_<YYYY-MM-DD>.docx

9 sections:
1. Executive Summary (verdict: SUPPORTED/PARTIALLY/DISPROVEN/INCONCLUSIVE + 3 must-know)
2. Identity Facts Table (founded/born, location, size, role, affiliations; sourced + tiered)
3. Hypothesis Test (verbatim hypothesis + supporting evidence + disconfirming evidence + verdict)
4. 12-Month Activity Timeline (news, hires, departures, products, controversies)
5. Network Signals (collaborators / investors / customers / advisors)
6. Reputation Signals (sentiment, Glassdoor, peer mentions)
7. Red Flags + Hidden Patterns (litigation, departures, financials, tiered)
8. Conversation Hooks (3-5 finding-tied hooks with framing)
9. Source Provenance + Audit Log (per-source tier + search summary + counts)
```

## Дисциплина проверки гипотез { #hypothesis-testing-discipline }

**≥30% поискового бюджета выделяется на неподтверждающие запросы.** Это не подлежащее обсуждению отличие от общего профиля.

Пример для гипотезы "Microsoft консолидирует расходы на ИИ в литейном производстве":

| Тип запроса | Пример |
|---|---|
| **Поддерживаю** (хотел бы подтвердить) | "Внедрение Microsoft Foundry в 2026 году" |
| **Поддерживающий** | "Консолидация инфраструктуры искусственного интеллекта Microsoft" |
| **Не подтверждающий** (хотел бы опровергнуть) | "Пересмотр условий сделки Microsoft OpenAI" |
| **Опровержение** | "Диверсификация поставщиков искусственного интеллекта Microsoft" |
| **Опровержение** | "Модель партнерства Microsoft со сторонними разработчиками 2026" |

`skills/dossier/scripts/disconfirming_evidence_balance.py` обеспечивает соблюдение этого соотношения. Останавливается на уровне <30% и промпт дополнительных неподтверждающих запросов.

## Уровень надежности источника { #source-reliability-tiering }

Каждый факт в DOCX помечен уровнем (первичный / вторичный / третичный):

| Уровень | Примеры |
|---|---|
| **Первичный** | Заявки SEC EDGAR, судебные протоколы, официальные сайты правительства, официальный сайт компании |
| **Вторичный** | Основные новости (NYT, WSJ, Reuters), отраслевая пресса (TechCrunch, The Information) |
| **Третичный** | Блоги, форумы (Reddit, HN), Glassdoor, социальные сети |

`skills/dossier/scripts/source_tier_classifier.py` делает это с помощью URL.

## Дисциплина (Соглашение об исследовательском пакете) { #discipline-research-pack-convention }

- **Один прием Q за оборот.** Никогда не связывайте.
- ** Вопрос 4 обязателен.** Отойдите назад один раз; вернитесь к неявной гипотезе "самое удивительное открытие" с флагом.
- **опровержение на ≥30%.** Применяется с помощью инструмента.
- ** Последовательный поиск.** Последовательный веб-поиск + веб-выборка, этикет 1 вопрос/сек.
- **Дисциплина источника.** Приводите только результаты сеанса. Учебные знания, помеченные `[Background — verify before quoting]`, исключенный из подсчетов.
- ** Три подсчета + уровень.** Отправлено / получено / процитировано + разбивка по уровням.
- ** Устранение неоднозначности темы перед этапом 3.** Откажитесь от двусмысленных имен.
- ** Учтены исключения из-за чувствительности.** Если в Q6 исключена "история болезни", не всплывайте, даже если ее найдут.
- ** Поиск зацепок для разговоров - привязан.** Общие зацепки ("спросите об их дорожной карте") отклонены.
- **BYOK MCP помечен в аудите.** Обнаружилось использование Crunchbase / Pitchbook.

- "исследование [компания]"

- "усердие инвестора [компания]"
- "подготовка к собеседованию для [компания]"

## Отклоненные анти-паттерны { #anti-patterns-rejected }

- Создание досье без выдвижения гипотезы Q4
- <30% неподтверждающего бюджета поиска (предвзятость подтверждения)
- Вопросы о дозированном приеме
- Прием неоднозначных имен объектов
- Общие зацепки для разговора ("спросите об их дорожной карте")
- Сенсационные красные флажки (расставляйте их в ряд, не редактируйте)
- Пропуск уровня надежности источника для флагов
- Создание репортажа, когда LinkedIn заблокирован
- Использование BYOK MCP без пометки в аудите
- Включая конфиденциальные темы, исключенные пользователем (Q6)
- Подтверждение -предвзятый вердикт ("ПОДДЕРЖАННЫЙ" без привлечения опровергающих доказательств)
