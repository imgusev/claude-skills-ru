**$ARGUMENTS**

## Пять правил (сохранено от Мэтта Покока, Массачусетский технологический институт) { #five-rules-preserved-from-matt-pocock-mit }

1. ** По одному вопросу за ход. ** Никогда не связывайтесь.
2. ** Рекомендуйте ответ на каждый вопрос.**
3. ** Изучите рабочее пространство, прежде чем задавать вопросы ** — проверьте наличие записей о сделках, ценовых предложений, документов RFP, красных линий MSA.
4. ** Сначала пройдите по глубине.**
5. ** Отслеживание зависимостей** — ценообразование → упаковка → сделка → прогноз.

## Дерево коммерческих решений (сначала в глубину) { #the-commercial-decision-tree-depth-first }

### Ответвление 1 — Какая полоса движения? { #branch-1--which-lane }

- ЦЕНООБРАЗОВАНИЕ / СДЕЛКА / ПАРТНЕРСТВО / CHANNEL_ECON / ПОЛИТИКА / ЗАПРОС ПРЕДЛОЖЕНИЙ / ПРОГНОЗ

### Ветвь 2 — Форсирующий вопрос для каждой полосы { #branch-2--the-forcing-question-per-lane }

** ЦЕНООБРАЗОВАНИЕ: ** "Платит ли ваш клиент за результаты, места или использование?"
Рекомендуется: результаты (основанные на ценности), если вы можете их измерить; использование, если предельные издержки изменчивы; места только в том случае, если использование примерно одинаковое на одного пользователя.
Канон: Рамануджам 2016 * Монетизация инноваций* (список из 9 ошибок). Анти-шаблон: сиденье, основанное на продукте, изменяющемся в зависимости от использования, ограничивает TAM на ~20% от WTP.

** СДЕЛКА:** "Какова валовая прибыль при полной скидке И как выглядит пайплайн следующего квартала на тех же условиях?"
Рекомендуется: моделировать оба варианта. Отказывайте в одобрении до тех пор, пока представители не смогут четко сформулировать прецедентный риск.
Канон: Skok (для предпринимателей — математика скидок), Tunguz benchmarks. Анти-паттерн: один 40%-ный прецедент изменяет форму 3 четвертей пайплайна.

**ПАРТНЕРСТВО:** "Есть ли у партнера независимый спрос, или они перепродают наш пайплайн?"
Рекомендуется: настаивайте на доказательствах по независимому запросу (названные аккаунты, полученные партнером, а не совместно проданные).
Канон: исследование канала Forrester. Анти-паттерн: сделки по каналам из вашего собственного пайплайна обходятся дороже, чем прямые.

** CHANNEL_ECON:** "Какова ваша полная стоимость обслуживания напрямую по сравнению с партнером?"
Рекомендуется: моделировать оба варианта с выделенными накладными расходами.
Канон: Бессемеровские тесты состояния облачного канала.

** ПОЛИТИКА: ** "Основана ли ваша текущая матрица скидок на данных или на прецеденте?"
Рекомендуется: данные — диапазон скидок по сравнению с коэффициент выигрыша по сравнению с NRR.
Канон: исследования скидок OpenView.

** Запрос предложения: ** "Есть ли у вас подтверждающие баллы по каждому требованию, или вы пишете желательные заявки?"
Рекомендуется: только пробные баллы. Отказывайтесь выдумывать претензии.
Канон: APMP (Ассоциация профессионалов в области управления предложениями).

** ПРОГНОЗ: ** "Вы используете поэтапное преобразование за последние 4 квартала или за последние 12?"
Рекомендуется: последние 4, взвешенные по отношению к самому последнему.
Канон: Скок, OpenView. Анти-паттерн: 12-месячный равновес скрывает недавнее замедление.

### Ветвь 3 — Проверка обратимости { #branch-3--reversibility-check }

"Если это коммерческое решение будет принято, и мы захотим отменить его через 90 дней, сколько это будет стоить?"
Трудно поддающийся отмене + неожиданный + реальный компромисс → ADR в соответствии с критериями Matt's grill-with-docs.

### Ветвь 4 — Цепочка утверждения { #branch-4--approval-chain }

"Кто является человеком, утверждающим выходные данные?"
Рекомендуется: названная роль + названный человек, а не "команда".

### Ветвь 5 — Теперь вызываем дополнительный скилл { #branch-5--now-invoke-the-sub-skill }

Только после того, как ветви 1-4 будут заблокированы, вызовите `/cs:commercial` с помощью синтезированного запроса.

## Формат вывода за оборот { #output-format-per-turn }

```
Q[i]/[total]: [precise question]
Recommended: [answer + canon-cited rationale]

(Confirm, or override?)
```

## Условия остановки { #stop-conditions }

- Все ветви разрешены → вызвать `/cs:commercial <synthesized>`
- Пользователь говорит "прекратите гриль, просто запустите его" → вызвать с тем, что решено, пометить неразрешенные ветви в дайджесте
- Пользователь отказывается → нет вспомогательной скиллы, сохраните частичный гриль для `commercial-grill-{timestamp}.md`

## Отличный от { #distinct-from }

- `engineering/grill-me` (Мэтт Покок) — универсальный
- `engineering/grill-with-docs` (Мэтт Покок) — кодовая база + ADR-привязка для разработки. Это ** Проверка коммерческого домена ** в соответствии с каноном ценообразования SaaS.
- `/cs:commercial` — **выполняет** маршрутизацию. Это ** сначала опрашивает**.
