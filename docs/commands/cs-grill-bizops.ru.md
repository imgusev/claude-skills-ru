**$АРГУМЕНТЫ**

## Пять правил (сохранено от Мэтта Покока, Массачусетский технологический институт) { #five-rules-preserved-from-matt-pocock-mit }

1. ** По одному вопросу за ход. ** Никогда не связывайтесь.
2. ** Рекомендуйте ответ на каждый вопрос.** По умолчанию задавать вопрос "что вы думаете?" - это лень.
3. ** Изучите рабочее пространство, прежде чем задавать вопросы.** Если `Glob`/`Read`/`Grep` чтобы решить эту проблему, сделайте это в первую очередь.
4. ** Сначала пройдитесь по дереву решений в глубину.** Завершите ветку, прежде чем открывать другую.
5. ** Отслеживание зависимостей.** Разрешите A перед B, если B зависит от A.

## Дерево решений BizOps (сначала в глубину) { #the-bizops-decision-tree-depth-first }

Пройдитесь по этим ветвям по порядку. Пропускайте ветвь только в том случае, если рабочая область уже разрешила ее.

### Ответвление 1 — Какая полоса движения? { #branch-1--which-lane }

- ПРОЦЕСС / ПОСТАВЩИК / ПОТЕНЦИАЛ / СВЯЗЬ / ЗНАНИЯ / ЗАКУПКИ
- Источник канона: таблица сигналов этого скилла + `references/` на полосу движения

### Ветвь 2 — Состояние измерения { #branch-2--measurement-state }

Для ПРОЦЕССА: "Есть ли у вас измеренное время цикла для каждого этапа или приблизительные оценки?" — Рекомендуется: настаивайте на измерении для трех самых длинных этапов. Анти-паттерн (Голдратт, 1984): сопоставление оценок → оптимизация неправильного ограничения.

Для ПОСТАВЩИКА: "Порог уровня 1 - затраты или операционная зависимость?" — Рекомендуется: операционная зависимость. Анти-шаблон (Target/нарушение системы кондиционирования воздуха, Verkada): при распределении уровней только по расходам не учитываются критически важные поставщики с низкими расходами.

Для ЕМКОСТИ: "Планируйте использование или пропускную способность?" — Рекомендуется: пропускная способность (закон Литтла). Анти-шаблон (DORA): планирование использования более чем на 80% снижает пропускную способность.

Для связи: "Нажимать или тянуть связь?" — Рекомендуется: зависит от величины изменения. Модель ADKAR (Хайатт, 2006): для изменения с высокой степенью неопределенности требуется толчок + 7+ точек соприкосновения.

Для ОЗНАКОМЛЕНИЯ: "SOP или рансбук?" — Рекомендуется: SOP, если люди, рансбук, если автоматизация на 50%. Различие между Atlassian и Google SRE.

Для ЗАКУПОК: "Расходы или цель консолидации поставщиков?" — Рекомендуется: консолидация, если по Парето 20% лучших поставщиков = 80% расходов. В противном случае проведите категоризацию.

### Филиал 3 — Владелец + подотчетность { #branch-3--owner--accountability }

"Кому это принадлежит, когда появится рекомендация?" — Рекомендовано: названный человек, а не команда. Анти-паттерн: "это принадлежит оперативной команде" = это не принадлежит никому.

### Ветвь 4 — Обратимость { #branch-4--reversibility }

"Является ли это решение обратимым через < 30 дней при стоимости < X долларов?" Если нет, предложите ДОПОГ (в соответствии с критериями ДОПОГ Matt's grill-with-docs: трудно отменить + неожиданно-без-контекста + реальный компромисс).

### Ветвь 5 — Теперь вызываем дополнительный скилл { #branch-5--now-invoke-the-sub-skill }

Только после того, как ветви 1-4 будут разрешены, вызовите `/cs:bizops` чтобы перейти к нужному под-скиллу.

## Формат вывода за оборот { #output-format-per-turn }

```
Q[i]/[total resolved branches]: [precise question]
Recommended: [answer + 1-sentence canon-cited rationale]

(Confirm, or override?)
```

## Условия остановки { #stop-conditions }

- Все ветви разрешены → вызвать `/cs:bizops <synthesized inquiry>`
- Пользователь говорит: "прекратите готовить на гриле, просто запустите его" → вызвать `/cs:bizops` после того, как все будет решено, отметьте неразрешенные ветви в дайджесте
- Пользователь отказывается → нет вызова вспомогательного скилла, сохраните частичный гриль в `bizops-grill-{timestamp}.md`

## Отличный от { #distinct-from }

- `engineering/grill-me` (Мэтт Покок) — общий план приготовления на гриле, без доменного канона
- `engineering/grill-with-docs` (Мэтт Покок) — кодовая база + привязанный к ADR гриль для проектирования. Это **Приготовление на гриле домена BizOps**.
- `/cs:bizops` — который ** выполняет** маршрутизацию. Это **запрашивает** перед выполнением.
