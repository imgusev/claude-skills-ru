## Воркфлоу { #workflows }

### Воркфлоу 1: Создание персоны пользователя { #workflow-1-generate-user-persona }

** Ситуация:** У вас есть пользовательские данные (аналитика, опросы, интервью), и вам необходимо создать персону, основанную на исследованиях.

**Шаги:**

1. **Подготовка пользовательских данных**

   Требуемый формат (JSON):
   ```json
   [
     {
       "user_id": "user_1",
       "age": 32,
       "usage_frequency": "daily",
       "features_used": ["dashboard", "reports", "export"],
       "primary_device": "desktop",
       "usage_context": "work",
       "tech_proficiency": 7,
       "pain_points": ["slow loading", "confusing UI"]
     }
   ]
   ```

2. **Запустите генератор персон**
   ```bash
   # Human-readable output
   python scripts/persona_generator.py

   # JSON output for integration
   python scripts/persona_generator.py json
   ```

3. **Ревью сгенерированных компонентов**

   | Компонент | Что нужно проверить |
   |-----------|---------------|
   | Архетип | Соответствует ли это шаблонам данных? |
   | Демография | Получены ли они на основе фактических данных? |
   | Цели | Являются ли они конкретными и выполнимыми? |
   | Разочарования | Включают ли они в себя подсчет частот? |
   | Последствия для дизайна | Могут ли дизайнеры действовать в соответствии с этим? |

4. **Подтверждение персоны**

   - Покажите 3-5 реальным пользователям: "Это похоже на вас?"
   - Перепроверьте заявки в службу поддержки
   - Сверить с данными аналитики

5. **Ссылка:** Смотрите `references/persona-methodology.md` для критериев достоверности

### Воркфлоу 2: Создайте карту путешествия { #workflow-2-create-journey-map }

** Ситуация:** Вам нужно визуализировать сквозной пользовательский интерфейс для достижения конкретной цели.

**Шаги:**

1. **Определить область применения**

   | Элемент | Описание |
   |---------|-------------|
   | Персона | Какой тип пользователя |
   | Цель | Чего они пытаются достичь |
   | Начать | Триггер, с которого начинается путешествие |
   | Конец | Критерии успеха |
   | Временные рамки | Часы/дни/недели |

2. **Сбор данных о путешествии**

   Источники:
   - Интервью с пользователями (попросите "рассказать мне о...")
   - Записи сеансов
   - Аналитика (воронка, отсев)
   - Заявки в службу поддержки

3. **Составьте карту этапов**

   Типичные этапы B2B SaaS:
   ```
   Awareness → Evaluation → Onboarding → Adoption → Advocacy
   ```

4. **Заполните слои для каждого этапа**

   ```
   Stage: [Name]
   ├── Actions: What does user do?
   ├── Touchpoints: Where do they interact?
   ├── Emotions: How do they feel? (1-5)
   ├── Pain Points: What frustrates them?
   └── Opportunities: Where can we improve?
   ```

5. **Выявлять возможности**

   Оценка приоритета = Частота × Серьезность × Разрешимость

6. **Ссылка:** Смотрите `references/journey-mapping-guide.md` для шаблонов

### Воркфлоу 3: Спланируйте юзабилити-тест { #workflow-3-plan-usability-test }

** Ситуация:** Вам нужно проверить дизайн с реальными пользователями.

**Шаги:**

1. **Определите исследовательские вопросы**

   Преобразуйте расплывчатые цели в проверяемые вопросы:

   | Расплывчатый | Поддающийся тестированию |
   |-------|----------|
   | "Прост ли он в использовании?" | "Могут ли пользователи завершить оформление заказа менее чем за 3 минуты?" |
   | "Нравится ли это пользователям?" | "Выберут ли пользователи дизайн A или B?" |
   | "Есть ли в этом смысл?" | "Могут ли пользователи находить настройки без подсказок?" |

2. **Выберите метод**

   | Способ | Участники | Продолжительность | Лучше всего подходит для |
   |--------|--------------|----------|----------|
   | Удаленный модератор | 5-8 | 45-60 мин | Глубокие прозрения |
   | Немодерируемый удаленный | 10-20 | 15-20 мин | Быстрая проверка |
   | Партизанский | 3-5 | 5-10 мин | Быстрая обратная связь |

3. **Задачи проектирования**

   Хороший формат задания:
   ```
   SCENARIO: "Imagine you're planning a trip to Paris..."
   GOAL: "Book a hotel for 3 nights in your budget."
   SUCCESS: "You see the confirmation page."
   ```

   Выполнение задания: Разминка → Основное → Второстепенное → Пограничный случай → Свободное исследование

4. **Определение показателей успеха**

   | Метрика | Цель |
   |--------|--------|
   | Показатель завершенности | >80% |
   | Время выполнения задания | <2× ожидаемый |
   | Частота ошибок | <15% |
   | Удовлетворение | >4/5 |

5. **Подготовить руководство для модератора**

   - Инструкции для размышлений вслух
   - Промпты, не являющиеся ведущими
   - Вопросы после выполнения задания

6. **Ссылка:** Смотрите `references/usability-testing-frameworks.md` для получения полного руководства

### Воркфлоу 4: Обобщение результатов исследований { #workflow-4-synthesize-research }

** Ситуация:** У вас есть необработанные исследовательские данные (интервью, опросы, наблюдения), и вам нужна практическая информация.

**Шаги:**

1. **Закодируйте данные**

   Пометьте каждую точку данных тегом:
   - `[GOAL]` - Чего они хотят достичь
   - `[PAIN]` - Что их расстраивает
   - `[BEHAVIOR]` - Что они на самом деле делают
   - `[CONTEXT]` - Когда / где они используют продукт
   - `[QUOTE]` - Прямые пользовательские слова

2. **Сгруппировать похожие паттерны**

   ```
   User A: Uses daily, advanced features, shortcuts
   User B: Uses daily, complex workflows, automation
   User C: Uses weekly, basic needs, occasional

   Cluster 1: A, B (Power Users)
   Cluster 2: C (Casual User)
   ```

3. **Рассчитать размеры сегментов**

   | Кластер | Пользователи | % | Жизнеспособность |
   |---------|-------|---|-----------|
   | Опытные пользователи | 18 | 36% | Основная персона |
   | Бизнес-пользователи | 15 | 30% | Основная персона |
   | Обычные пользователи | 12 | 24% | Второстепенная персона |

4. **Извлечение ключевых выводов**

   Для каждой темы:
   - Вывод заявления
   - Подтверждающие доказательства (цитаты, данные)
   - Частота (X/Y участников)
   - Влияние на бизнес
   - Рекомендация

5. **Расставлять приоритеты в отношении возможностей**

   | Фактор | Счет 1-5 |
   |--------|-----------|
   | Частота | Как часто это происходит? |
   | Серьезность | Насколько это больно? |
   | Ширина | Сколько пользователей пострадало? |
   | Разрешимость | Можем ли мы это исправить? |

6. **Ссылка:** Смотрите `references/persona-methodology.md` для анализа фреймворка

## Ссылка на инструмент { #tool-reference }

### persona_generator.py { #persona_generatorpy }

Генерирует персонажей, управляемых данными, на основе данных исследований пользователей.

| Аргумент | Ценности | Значение по умолчанию | Описание |
|----------|--------|---------|-------------|
| формат | (нет), json | (нет) | Выходной формат |

**Выборочный вывод:**

```
============================================================
PERSONA: Alex the Power User
============================================================

📝 A daily user who primarily uses the product for work purposes

Archetype: Power User
Quote: "I need tools that can keep up with my workflow"

👤 Demographics:
  • Age Range: 25-34
  • Location Type: Urban
  • Tech Proficiency: Advanced

🎯 Goals & Needs:
  • Complete tasks efficiently
  • Automate workflows
  • Access advanced features

😤 Frustrations:
  • Slow loading times (14/20 users)
  • No keyboard shortcuts
  • Limited API access

💡 Design Implications:
  → Optimize for speed and efficiency
  → Provide keyboard shortcuts and power features
  → Expose API and automation capabilities

📈 Data: Based on 45 users
    Confidence: High
```

**Сгенерированные архетипы:**

| Архетип | Сигналы | Фокус на дизайне |
|-----------|---------|--------------|
| пользователь power_user | Ежедневное использование, более 10 функций | Эффективность, индивидуализация |
| случайный_пользователь | Еженедельное использование, 3-5 функций | Простота, руководство |
| бизнес_пользователь | Рабочий контекст, командное использование | Сотрудничество, отчетность |
| мобильный_первый | Мобильный первичный | Касание, автономный режим, скорость |

**Выходные компоненты:**

| Компонент | Описание |
|-----------|-------------|
| демография | Возрастной диапазон, местоположение, профессия, технический уровень |
| психография | Мотивации, ценности, установки, образ жизни |
| поведение | Модели использования, предпочтения функций |
| потребности и цели | Первичный, вторичный, функциональный, эмоциональный |
| разочарования | Болевые точки с доказательствами |
| сценарии | Истории контекстуального использования |
| конструктивные применения | Практические рекомендации |
| точки данных | Размер выборки, уровень достоверности |

## Краткие справочные таблицы { #quick-reference-tables }

### Выбор метода исследования { #research-method-selection }

| Тип вопроса | Наилучший метод | Размер выборки |
|---------------|-------------|-------------|
| "Что делают пользователи?" | Аналитика, наблюдение | более 100 событий |
| "Почему они это делают?" | Интервью | 8-15 пользователей |
| "Насколько хорошо они могут это делать?" | Юзабилити-тест | 5-8 пользователей |
| - А что они предпочитают? | Опрос, A/B тест | более 50 пользователей |
| "Что они чувствуют?" | Изучение дневника, интервью | 10-15 пользователей |

### Уровни доверия к персоне { #persona-confidence-levels }

| Размер выборки | Уверенность | Вариант использования |
|-------------|------------|----------|
| 5-10 пользователей | Низкий | Исследовательский |
| 11-30 пользователей | Средний | Направленный |
| 31+ пользователь | Высокий | Производство |

### Серьезность проблемы с удобством использования { #usability-issue-severity }

| Серьезность | Определение | Действие |
|----------|------------|--------|
| 4 - Критический | Препятствует завершению задачи | Исправьте немедленно |
| 3 - Основные | Значительная трудность | Исправление перед выпуском |
| 2 - Второстепенный | Вызывает колебания | Исправляйте, когда это возможно |
| 1 - Косметический | Замечено, но не вызывает проблем | Низкий приоритет |

### Типы вопросов для интервью { #interview-question-types }

| Тип | Пример | Использовать для |
|------|---------|---------|
| Контекст | "Расскажи мне о своем обычном дне" | Понимание окружающей среды |
| Поведение | "Покажи мне, как ты делаешь X" | Наблюдение за реальными действиями |
| Цели | "Чего ты пытаешься достичь?" | Раскрытие мотиваций |
| Боль | - Что самое трудное? - спросил я. | Выявление разочарований |
| Отражение | "Что бы ты изменил?" | Генерирование идей |

## Чек-лист для проверки подлинности (#) { #validation-checklist }

### Качество персоны { #persona-quality }
- [ ] На основе более 20 пользователей (минимум)
- [ ] По крайней мере, 2 источника данных (количество + квалификация)
- [ ] Конкретные, выполнимые цели
- [ ] Разочарования включают в себя подсчет частоты
- [ ] Последствия для проектирования специфичны
- [ ] Заявленный уровень достоверности

### Качество карты путешествия { #journey-map-quality }
- [ ] Четко определенная сфера деятельности (персона, цель, временные рамки)
- [ ] Основано на реальных пользовательских данных, а не на предположениях
- [ ] Заполнены все слои (действия, точки соприкосновения, эмоции)
- [ ] Болевые точки, выявленные на каждом этапе
- [ ] Приоритетные возможности

### Качество юзабилити-теста { #usability-test-quality }
- [ ] Исследовательские вопросы поддаются проверке
- [ ] Задачи - это реалистичные сценарии, а не инструкции
- [ ] более 5 участников на каждый дизайн
- [ ] Определены показатели успеха
- [ ] Результаты включают оценки степени тяжести

### Качество синтеза исследований { #research-synthesis-quality }
- [ ] Данные, закодированные последовательно
- [ ] Шаблоны, основанные на более чем 3 точках данных
- [ ] Выводы включают доказательства
- [ ] Рекомендации выполнимы
- [ ] Приоритеты оправданы
