# Коммуникатор дорожной карты { #roadmap-communicator }

Создайте четкие коммуникационные артефакты дорожной карты для внутренних и внешних стейкхолдеров.

## Когда использовать { #when-to-use }

Используйте этот скилл для:
- Создание презентаций дорожной карты в различных форматах
- Написание обновлений для стейкхолдеров (совет директоров, инженеры, клиенты)
- Подготовка примечаний к выпуску (пользовательских и внутренних)
- Генерация списков изменений из истории git
- Структурирование анонсов функций

## Форматы дорожных карт { #roadmap-formats }

1. Сейчас / Следующий / Позже
- Лучше всего подходит для неопределенности и стратегической гибкости.
- Сообщайте направление без ложной точности.

2. Временная шкала дорожная карта
- Лучше всего подходит для обязательств с фиксированной датой и координации запуска.
- Требует активного управления рисками и зависимостями.

3. Тематическая дорожная карта
- Лучше всего подходит для планирования, ориентированного на конечный результат, и межкомандной координации.
- Группирует инициативы по проблемному пространству или стратегической цели.

Видишь `references/roadmap-templates.md` для шаблонов.

## Схемы обновления стейкхолдерами { #stakeholder-update-patterns }

### Правление / Исполнительный директор { #board--executive }
- Ориентированный на результат и риск
- Сосредоточьтесь на прогрессе в достижении стратегических целей
- Выделите компромиссы и необходимые решения

### Инженерное дело { #engineering }
- Область применения, зависимости и ясность последовательности
- Статус, блокирующие факторы и последствия для ресурсов

### Клиенты { #customers }
- Описание ценности и временное окно
- Что доступно сейчас по сравнению с предстоящим
- Четкая установка ожиданий

Видишь `references/communication-templates.md` для многоразовых шаблонов.

## Руководство по примечаниям к выпуску { #release-notes-guidance }

### Примечания к выпуску, ориентированные на пользователя { #user-facing-release-notes }
- Ориентируйтесь на пользовательскую ценность, а не на детали внутренней реализации.
- Группируйте по воркфлоу или пользовательским заданиям.
- Явно включите миграцию/изменения в поведении.

### Примечания к внутреннему выпуску { #internal-release-notes }
- Укажите технические подробности, влияние на эксплуатацию и известные проблемы.
- Фиксируйте план раскатки, критерии отката и заметки о мониторинге.

## Генерация журнала изменений { #changelog-generation }

Использование:
```bash
python3 scripts/changelog_generator.py --from v1.0.0 --to HEAD
```

Особенности:
- Считывает диапазон журнала git
- Анализирует обычные префиксы фиксации
- Группирует записи по типу (`feat`, `fix`, `chore` и т.д.)
- Выводит Markdown или обычный текст

## Фреймворк для анонса функций { #feature-announcement-framework }

1. Контекст проблемы
2. Что изменилось
3. Почему это важно
4. Кто получает наибольшую выгоду
5. Как начать работу
6. Призыв к действию и канал обратной связи

## Чек-лист для проверки качества связи (#) { #communication-quality-checklist }

- [ ] Фрейминг, ориентированный на конкретную аудиторию, является явным.
- [ ] Результаты и компромиссы очевидны.
- [ ] Терминология согласована во всех артефактах.
- [ ] Риски и зависимости не скрыты.
- [ ] Указаны следующие действия и владельцы.
