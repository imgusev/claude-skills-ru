# Конкурентный срыв { #competitive-teardown }

**Уровень:** МОЩНЫЙ  
**Категория:** Команда разработчиков  
**Предметная область:** Конкурентная разведка, Стратегия продукта, Анализ рынка

---

## Когда использовать { #when-to-use }

- Перед сессией по разработке стратегии продукта или дорожной карты
- Когда конкурент запускает важную функцию или меняет цены
- Ежеквартальный конкурентный ревью
- Перед рекламным выступлением, где вам нужны данные боевой карты
- При выходе на новый сегмент рынка

---

## Демонтажный воркфлоу { #teardown-workflow }

Выполните следующие шаги последовательно, чтобы произвести полный демонтаж:

1. **Определите конкурентов** — Перечислите 2-4 конкурента для анализа. Подтвердите, что является основным фокусом.
2. **Сбор данных** — Использование `references/data-collection-guide.md` собирать необработанные сигналы как минимум из 3 источников для каждого конкурента (веб-сайт, ревью, объявления о вакансиях, SEO, социальные сети).  
   _ Контрольная точка подтверждения: Прежде чем продолжить, подтвердите, что у вас есть данные о ценах, не менее 20 ревью и количество размещенных вакансий для каждого конкурента._
3. ** Оценка с использованием рубрики ** — Примените приведенную ниже 12-мерную рубрику, чтобы создать числовую систему показателей для каждого конкурента и вашего собственного продукта.  
   _ Контрольная точка проверки: Каждое измерение должно иметь оценку и, по крайней мере, одно подтверждающее примечание._
4. **Генерировать выходные данные** — Заполнять шаблоны в `references/analysis-templates.md` (Матрица характеристик, ценовой анализ, SWOT, карта позиционирования, аудит UX).
5. ** Составьте план действий** — Переведите полученные результаты в шаблон пунктов действий (быстрые победы / среднесрочные / стратегические).
6. **Пакет для стейкхолдеров** — Составьте презентацию для стейкхолдеров, используя результаты шагов 3-5.

## Руководство по сбору данных { #data-collection-guide }

> Полные исполняемые скрипты для каждого источника находятся в `references/data-collection-guide.md` Краткое описание того, что нужно запечатлеть, приведено ниже.

### 1. Анализ веб-сайта { #1-website-analysis }

Ключевые моменты, которые нужно зафиксировать:
- Уровни ценообразования и ценовые точки
- Списки функций для каждого уровня
- Первичный CTA и обмен сообщениями
- Тематические исследования / логотипы клиентов (signals ICP)
- Интеграционные логотипы
- Сигналы доверия (сертификаты, значки соответствия)

### 2. Ревью в App Store { #2-app-store-reviews }

Ревью категории настроений:
- ** Хвалите ** → то, что нравится пользователям (защищайте / укрепляйте это)
- **Запросы функций** → неудовлетворенные потребности (пробелы в возможностях)
- **Ошибки** → сигналы о качестве
- ** Жалобы на UX ** → точки трения, по которым вы можете их обойти

**Пример запроса в App Store (iTunes Search API):**
```
GET https://itunes.apple.com/search?term=<competitor_name>&entity=software&limit=1
# Extract trackId, then:
GET https://itunes.apple.com/rss/customerreviews/id=<trackId>/sortBy=mostRecent/json?l=en&limit=50
```
Разобрать `entry[].content.label` для получения текста ревью и `entry[].im:rating.label` для получения звездного рейтинга.

### 3. Объявления о вакансиях (данные о размере команды и техническом стеке) { #3-job-postings-team-size--tech-stack-signals }

Сигналы из объявлений о вакансиях:
- **Объем проектирования** → масштабирование по сравнению с консолидацией
- ** Упоминания о конкретных технологиях ** → стек (React/Vue, Postgres/Mongo, AWS/GCP)
- **Соотношение продаж к CS** → движение, ориентированное на продукт, и движение, ориентированное на продажи
- **Роли в Data/ML** → предстоящие функции искусственного интеллекта
- **Функции по соблюдению требований** → расширение регулирования

### 4. SEO-анализ { #4-seo-analysis }

SEO-сигналы для захвата:
- Топ-20 органических ключевых слов (цель: информационная / навигационная / коммерческая)
- Авторитет домена / количество обратных ссылок
- Частота публикации в блоге и темы
- Какие страницы ранжируются (страницы товаров, блоги, документы)

### 5. Настроения в социальных сетях { #5-social-media-sentiment }

Фиксируйте последние упоминания с помощью Twitter /X API v2, Reddit или LinkedIn. Ищите повторяющиеся похвалы, жалобы и запросы на новые функции. Видишь `references/data-collection-guide.md` для примеров запросов API.

## Рубрика подсчета очков (12 измерений, 1-5) { #scoring-rubric-12-dimensions-1-5 }

| # | Измерение | 1 (Слабый) | 3 (Среднее значение) | 5 (Лучший в своем классе) |
|---|-----------|----------|-------------|-------------------|
| 1 | **Особенности** | Только ядро, много пробелов | Сплошное покрытие | Всеобъемлющий + уникальный |
| 2 | **Ценообразование** | Сбивающий с толку / завышенный по цене | Рыночный курс, чистый | Прозрачный, гибкий, справедливый |
| 3 | **ПОТОК** | Сбивающее с толку, высокое трение | Функциональный | Восхитительное, минимальное трение |
| 4 | **Производительность** | Медленный, ненадежный | Приемлемый | Быстрое и высокое время безотказной работы |
| 5 | **Документы** | Разреженный, устаревший | Достойный охват | Всеобъемлющий, доступный для поиска |
| 6 | **Поддержка** | Только электронная почта, медленно | Чат + электронная почта | 24/7, отличный отклик |
| 7 | **Интеграция** | 0-5 интеграций | 6-25 | 26+ или глубокая экосистема |
| 8 | **Безопасность** | Никаких упоминаний | Заявленный SOC2 | SOC2 Тип II, ISO 27001 |
| 9 | **Масштабируемость** | Нет корпоративного уровня | Готовый продукт для среднего рынка | Корпоративный уровень |
| 10 | **Бренд** | Общий, незапоминающийся | Достойное позиционирование | Сильный, дифференцированный |
| 11 | **Сообщество** | Нет | Форум / Slack | Активное, динамично развивающееся сообщество |
| 12 | **Инновации** | Нет последних выпусков | Ежеквартально | Частый, значимый |

**Пример заполненной строки** (Конкурент: Acme Corp, измерение 3 – UX):

| Измерение | Оценка Acme Corp | Доказательства |
|-----------|----------------|---------|
| ПОТОК | 2 | В ревью App Store упоминается "запутанная навигация" (38 упоминаний); для онбординга требуется 7 шагов перед TTFV; мастера онбординга нет; при регистрации требуется CC. |

Примените этот шаблон ко всем 12 измерениям для каждого участника.

## Шаблоны { #templates }

> Полный шаблон Markdown находится в `references/analysis-templates.md`. Сокращенная ссылка ниже.

### Матрица сравнения признаков { #feature-comparison-matrix }

Строки: основные функции, уровни ценообразования, возможности платформы (Web, iOS, Android, API).  
Столбцы: ваш продукт + до 3 конкурентов.  
Оцените каждую ячейку от 1 до 5 баллов. Суммируйте, чтобы получить общее количество из 60.  
** Условные обозначения результатов:** 5 = Лучший в классе, 4= Сильный, 3= Средний, 2= Ниже среднего, 1= Слабый/отсутствующий

### Анализ ценообразования { #pricing-analysis }

Количество участников: тип модели (за место / на основе использования / фиксированная ставка / freemium), начальные / средние / корпоративные цены, продолжительность бесплатной пробной версии.  
Подведите итог: лидер по цене, лидер по ценности, премиальное позиционирование, ваша позиция и 2-3 маркера ценовых возможностей.

### SWOT-анализ { #swot-analysis }

Для каждого участника: по 3-5 баллов в каждом квадранте (Сильные и слабые стороны, возможности для нас, угрозы для нас). Привязывайте каждый маркер к сигналу данных (предложение для ревью, количество размещенных вакансий, страница с ценами и т.д.).

### Карта позиционирования { #positioning-map }

оси 2x2 (например, Простое ↔ сложное / низкое значение ↔ Высокое значение). Разместите каждого конкурента и свой продукт. Размер пузыря = доля рынка или финансирование. Видишь `references/analysis-templates.md` для ASCII и редактируемых версий.

### УБ аудит чек-лист { #ux-audit-checklist }

Онбординг: TTFV (минуты), шаги для активации, требуется CC, качество мастера онбординга.  
Ключевые воркфлоу: этапы, точки соприкосновения, сравнительный балл (ваш и их).  
Мобильные устройства: рейтинги iOS / Android, соотношение функций, лучшие жалобы и похвалы.  
Навигация: глобальный поиск, сочетания клавиш, справка в приложении.

### Элементы действия { #action-items }

| Горизонт | Усилие | Примеры |
|---------|--------|---------|
| Быстрые победы (0-4 раза в неделю) | Низкий | Добавьте значки для ревью, опубликуйте целевую страницу сравнения |
| Среднесрочный (1-3 месяца) | Умеренный | Запустите бесплатный уровень, улучшите онбординг TTFV, добавьте наиболее востребованную интеграцию |
| Стратегический (3-12 месяцев) | Высокий | Выход на новый рынок, создание API версии 2, достижение SOC2 Type II |

### Презентация стейкхолдеров (7 слайдов) { #stakeholder-presentation-7-slides }

1. ** Краткое описание** — Уровень угрозы (НИЗКИЙ/СРЕДНИЙ/ВЫСОКИЙ/КРИТИЧЕСКИЙ), максимальная сила, наилучшие возможности, рекомендуемые действия
2. **Положение на рынке** — карта позиционирования 2x2
3. **Система показателей характеристик** — 12- измерительный радар или таблица, общее количество баллов
4. ** Анализ ценообразования** — Сравнительная таблица + ключевая информация
5. ** Основные моменты UX ** — Что у них получается лучше (3 балла) по сравнению с тем, где мы выигрываем (3 балла)
6. ** Голос клиента** — Топ-3 жалоб на ревью (цитируется или перефразируется)
7. ** Наш план действий** — Быстрые победы, среднесрочные, стратегические приоритеты; Приложение с исходными данными
