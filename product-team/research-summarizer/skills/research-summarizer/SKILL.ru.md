# Составитель резюме исследования { #research-summarizer }

> Читайте меньше. Поймите больше. Цитируйте правильно.

Структурированный воркфлоу-процесс обобщения результатов исследований, который превращает плотный исходный материал в полезные краткие сведения. Создан для менеджеров по продуктам, аналитиков, основателей и всех, кто читает больше, чем следовало бы.

Не универсальное "обобщение этого" — повторяемый фреймворк, который извлекает то, что важно, сравнивает разные источники и правильно форматирует цитаты.

---

## Область применения — Отличается от исследования/предметной области { #scope--distinct-from-the-research-domain }

Этот скилл обобщает ** документы, которые уже есть у пользователя** (документы, статьи, отчеты, вставленные или прикрепленные). Он не выполняет веб-поиск и не нуждается в MCP-сервере. Это НЕ ТАК:

- `research/litreview` — академическая литература * поиск* и ревью-генерация руководств (поиск статей с помощью консенсусных / академических API)
- `research/dossier` — due-diligence организации, проведенный на основе живого веб-исследования
- `research/notebooklm` — управляет пользовательским интерфейсом продукта Google NotebookLM
- `research/research` — маршрутизатор для открытого "исследования [тема]" запросы, требующие поиска

Если пользователь попросит вас * найти* источники, а не переварить предоставленные, вместо этого перейдите к исследованию / домену.

## Когда активируется этот Скилл { #when-this-skill-activates }

Распознать эти шаблоны у пользователя:

- "Подведите итог этому документу / статье/отчету"
- "Каковы ключевые выводы, содержащиеся в этом документе?"
- "Сравните эти источники"
- "Извлеките цитаты из этого PDF-файла"
- "Дайте мне краткое описание исследования по [тема]"
- "Разберите этот технический документ"
- Любой запрос, включающий: обобщение, краткое содержание исследования, ревью литературы, цитирование, сравнение источников

Если у пользователя есть документ и он хочет получить структурированное представление → применяется этот скилл.

## Воркфлоу { #workflow }

### Воркфлоу 1 — Сводка из одного источника { #workflow-1--single-source-summary }

1. **Определить тип источника**
   - Научная статья → использовать структуру IMRAD (Введение, методы, результаты, анализ, обсуждение)
   - Веб-статья → использовать структуру "утверждение-доказательство-вывод".
   - Технический отчет → использовать структуру резюме
   - Документация → использовать сводную структуру ссылок

2. **Сформулируйте краткое содержание** — `python3 scripts/format_summary.py --template academic` (или `article`/`report`/`executive` для каждого типа источника), затем заполните каждый раздел из источника:
   ```
   Title: [exact title]
   Author(s): [names]
   Date: [publication date]
   Source Type: [paper | article | report | documentation]

   ## Key Thesis
   [1-2 sentences: the central argument or finding]

   ## Key Findings
   1. [Finding with supporting evidence]
   2. [Finding with supporting evidence]
   3. [Finding with supporting evidence]

   ## Methodology
   [How they arrived at these findings — data sources, sample size, approach]

   ## Limitations
   - [What the source doesn't cover or gets wrong]

   ## Actionable Takeaways
   - [What to do with this information]

   ## Notable Quotes
   > "[Direct quote]" (p. X)
   ```

3. **Оценка качества**
   - Достоверность источника (ревью, авторитетное издание, первичный или вторичный)
   - Убедительность доказательств (подкрепленных данными, эпизодических, теоретических)
   - Недавность (когда опубликовано, все еще актуально?)
   - Индикаторы предвзятости (источник финансирования, принадлежность к авторам, пробелы в методологии)

### Воркфлоу 2 — Сравнение из нескольких источников { #workflow-2--multi-source-comparison }

1. **Сбор источников** (2-5 документов)
2. ** Обобщите каждый **, используя приведенный выше воркфлоу с одним источником
3. **Построение матрицы сравнения**

   ```
   | Dimension        | Source A        | Source B        | Source C        |
   |------------------|-----------------|-----------------|-----------------|
   | Central Thesis   | ...             | ...             | ...             |
   | Methodology      | ...             | ...             | ...             |
   | Key Finding      | ...             | ...             | ...             |
   | Sample/Scope     | ...             | ...             | ...             |
   | Credibility      | High/Med/Low    | High/Med/Low    | High/Med/Low    |
   ```

4. **Синтезировать**
   - В чем источники сходятся во мнениях? (сходящиеся результаты = более сильный сигнал)
   - В чем они расходятся во мнениях? (расходящиеся выводы = требуется расследование)
   - Какие пробелы существуют во всех источниках?
   - Каков вес доказательств по каждой позиции?

5. **Подготовить краткое обобщение**
   ```
   ## Consensus Findings
   [What most sources agree on]

   ## Contested Points
   [Where sources disagree, with strongest evidence for each side]

   ## Gaps
   [What none of the sources address]

   ## Recommendation
   [Based on weight of evidence, what should the reader believe/do?]
   ```

### Воркфлоу 3 — Извлечение цитат { #workflow-3--citation-extraction }

1. **Запустите экстрактор** — `python3 scripts/extract_citations.py document.txt --output json` обнаруживает DOI/URL/авторский год/пронумерованные ссылки и дедуплицирует их
2. **Ревью и форматирование** извлеченного списка в запрошенном стиле (по умолчанию APA 7); вручную перехватывать цитаты, пропущенные регулярным выражением
3. **Классифицировать цитаты** по типу:
   - Первоисточники (оригинальные исследования, данные)
   - Вторичные источники (ревью, мета-анализы, комментарии)
   - Третичные источники (учебники, энциклопедии)
4. **Вывод ** отсортированная библиография с классификационными тегами

Поддерживаемые форматы цитирования:
- **APA 7** (по умолчанию) — социальные науки, бизнес
- **IEEE** — инженерия, информатика
- **Чикаго** — гуманитарные науки, история
- ** Гарвард** — общий академический
- **MLA 9** — искусство, гуманитарные науки

## Оснастка { #tooling }

### `scripts/extract_citations.py` { #scriptsextract_citationspy }

Утилита CLI для извлечения и форматирования цитат из текста.

**Особенности:**
- Определение цитирования на основе регулярных выражений (DOI, URL, автор-год, пронумерованные ссылки)
- Несколько выходных форматов (APA, IEEE, Chicago, Harvard, MLA)
- Экспорт JSON для интеграции с менеджерами ссылок
- Дедупликация повторяющихся цитат

**Использование:**
```bash
# Extract citations from a file (APA format, default)
python3 scripts/extract_citations.py document.txt

# Specify format
python3 scripts/extract_citations.py document.txt --format ieee

# JSON output
python3 scripts/extract_citations.py document.txt --format apa --output json

# From stdin
cat paper.txt | python3 scripts/extract_citations.py --stdin
```

### `scripts/format_summary.py` { #scriptsformat_summarypy }

Утилита CLI, которая генерирует **пустые структурированные сводные таблицы** — вы (модель) заполняете их из исходного кода. Он не анализирует сам контент.

**Особенности:**
- 6 шаблонов: академический, статья, отчет, исполнительный, сравнение, литература
- Настраиваемая глубина лесов (краткая, стандартная, подробная)
- Вывод текста и JSON-файлов для последующей обработки

**Использование:**
```bash
# Generate structured summary template
python3 scripts/format_summary.py --template academic

# Brief executive summary format
python3 scripts/format_summary.py --template executive --length brief

# All templates listed
python3 scripts/format_summary.py --list-templates

# JSON output
python3 scripts/format_summary.py --template article --output json
```

## Фреймворк для оценки качества { #quality-assessment-framework }

Оцените каждый источник по четырем параметрам:

| Измерение | Высокий | Средний | Низкий |
|-----------|------|--------|-----|
| **Доверие** | Ревью, прошедший экспертную оценку, признанный автор | Авторитетное издание, известный автор | Блог, неизвестный автор, без ревью |
| **Доказательства** | Большая выборка, строгий метод | Умеренные данные, разумный подход | Анекдотично, нет данных, мнение |
| **Недавность** | Опубликовано в течение 2-х лет | 2-5 лет | более 5 лет, возможно, устарел |
| **Объективность** | Отсутствие конфликтов, сбалансированный взгляд | Раскрыты незначительные связи | Финансируемый заинтересованной стороной, односторонний |

**Общая оценка:**
- 4 Максимума = сильный источник — цитируйте с уверенностью
- 2+ носителя = Адекватный источник — цитируйте с оговорками
- 2+ Минимумы = Слабый источник — проверьте самостоятельно, прежде чем цитировать

## Проактивные триггеры { #proactive-triggers }

Отмечайте их, не спрашивая:

- **Источник не имеет даты ** → Обратите на это внимание. Недатированные источники теряют очки достоверности.
- **Источник противоречит другим источникам** → Явно выделите противоречие. Не замалчивайте разногласия.
- ** Источник находится за платным доступом ** → Обратите внимание на ограниченный доступ. Предложите альтернативы, если они известны.
- **Пользователь предоставляет только один источник для сравнения ** → Запросите еще хотя бы один. Для сравнения требуется 2+.
- **Цитаты неполные** → Отметьте отсутствующие поля (год, автор, название). Не изобретайте метаданные.
- **Источнику более 5 лет в быстро развивающейся области ** → Предупреждаем о возможном устаревании.

## Цикл проверки { #verification-loop }

Перед предоставлением какого-либо резюме проверьте:

1. Каждая ключевая находка ссылается на местоположение в источнике (раздел, страница или цитата) — никаких неподтвержденных утверждений.
2. `python3 scripts/extract_citations.py <file> --output json` выходит из 0 и его `total` соответствует количеству библиографий в ваших выходных данных (исследуйте любые пробелы).
3. Каждый источник имеет оценку качества по 4 параметрам (таблица выше); слабые источники помечаются, а не включаются автоматически.
4. Для сравнения: матрица содержит по одной строке на измерение и по одному столбцу на источник — ни один источник не пропущен.
5. Ничего не было придумано: отсутствующие метаданные помечены как "не указано" и никогда не заполнялись.

## Связанные скиллы { #related-skills }

- **продуктовая аналитика** — Количественный анализ. Дополняющий — используйте research-summarizer для качественных источников, product-analytics для показателей.
- **конкурентный срыв** — Конкурентное исследование. Дополнительные исследования — обобщающий инструмент для анализа отдельных источников, конкурентный анализ рыночного ландшафта.
- **контент-продакшн** — написание контента. Исследование-сумматор подает контент-производство — сначала суммируйте источники, затем пишите.
- **обнаружение продукта** — фреймворки обнаружения. Комплементарное исследование—обобщающий инструмент для кабинетных исследований, открытие продукта для исследований пользователей.
