# Скилл инженера по продажам { #sales-engineer-skill }

## 5-Фазный воркфлоу { #5-phase-workflow }

### Фаза 1: Открытие и исследование { #phase-1-discovery--research }

**Цель:** Понять требования клиентов, техническую среду и движущие силы бизнеса.

**Чек-лист:**
- [ ] Проводить технические консультации с стейкхолдерами
- [ ] Составьте карту текущей архитектуры клиента и болевых точек
- [ ] Определить требования и ограничения к интеграции
- [ ] Требования к безопасности документов и их соответствию
- [ ] Оцените конкурентную среду для этой возможности

**Инструменты:** Запустить `rfp_response_analyzer.py` чтобы оценить соответствие первоначальных требований.

```bash
python scripts/rfp_response_analyzer.py assets/sample_rfp_data.json --format json > phase1_rfp_results.json
```

**Выходные данные:** Документ о техническом открытии, карта требований, первоначальная оценка охвата.

**Контрольная точка проверки: ** Показатель охвата должен составлять >50%, а обязательные пробелы - ≤3, прежде чем переходить ко второму этапу. Проконсультируйтесь с:
```bash
python scripts/rfp_response_analyzer.py assets/sample_rfp_data.json --format json | python -c "import sys,json; r=json.load(sys.stdin); print('PROCEED' if r['coverage_score']>50 and r['must_have_gaps']<=3 else 'REVIEW')"
```

---

### Этап 2: Разработка решения { #phase-2-solution-design }

**Цель:** Разработать архитектуру решения, отвечающую требованиям заказчика.

**Чек-лист:**
- [ ] Сопоставьте возможности продукта с требованиями заказчика
- [ ] Архитектура интеграции дизайна
- [ ] Определение потребностей в кастомизации и усилий по разработке
- [ ] Выстраивать стратегию конкурентной дифференциации
- [ ] Создание диаграмм архитектуры решения

**Инструменты:** Запустить `competitive_matrix_builder.py` использование данных этапа 1 для выявления отличительных черт и уязвимостей.

```bash
python scripts/competitive_matrix_builder.py competitive_data.json --format json > phase2_competitive.json

python -c "import json; d=json.load(open('phase2_competitive.json')); print('Differentiators:', d['differentiators']); print('Vulnerabilities:', d['vulnerabilities'])"
```

**Результат:** Архитектура решения, конкурентное позиционирование, стратегия технической дифференциации.

**Контрольная точка проверки: ** Убедитесь, что существует по крайней мере один сильный отличительный признак для каждого приоритета клиента, прежде чем переходить к этапу 3. Если отличительные признаки не найдены, выполните эскалацию до команды разработчиков (см. Пункты интеграции).

---

### Этап 3: Подготовка и доставка демонстрационной версии { #phase-3-demo-preparation--delivery }

**Цель:** Проведение убедительных технических демонстраций с учетом приоритетов стейкхолдеров.

**Чек-лист:**
- [ ] Создайте демонстрационную среду, соответствующую варианту использования клиента
- [ ] Создайте демонстрационный сценарий с тезисами для каждой роли стейкхолдера
- [ ] Подготовьте ответы на возражения
- [ ] Отрепетируйте сценарии сбоев и пути восстановления
- [ ] Сбор отзывов и корректировка подхода

**Шаблоны:** Используйте `assets/demo_script_template.md` для структурированной подготовки демонстрации.

** Результат: ** Настроенная демонстрация, темы для обсуждения с учетом специфики стейкхолдеров, сбор отзывов.

** Контрольная точка проверки:** Демонстрационный сценарий должен соответствовать всем обязательным требованиям, отмеченным в `phase1_rfp_results.json` перед доставкой. Перекрестная ссылка с:
```bash
python -c "import json; rfp=json.load(open('phase1_rfp_results.json')); [print('UNCOVERED:', r) for r in rfp['must_have_requirements'] if r['coverage']=='Gap']"
```

### Фаза 4: POC и оценка { #phase-4-poc--evaluation }

**Цель:** Выполнить структурированное доказательство концепции, подтверждающее правильность решения.

**Чек-лист:**
- [ ] Определите область применения POC, критерии успеха и временные рамки
- [ ] Распределять ресурсы и создавать среду
- [ ] Выполнить поэтапное тестирование (базовый, расширенный, пограничный варианты)
- [ ] Отслеживать прогресс в соответствии с критериями успеха
- [ ] Создать систему показателей оценки

**Инструменты:** Запустить `poc_planner.py` чтобы сгенерировать полный план POC.

```bash
python scripts/poc_planner.py poc_data.json --format json > phase4_poc_plan.json

python -c "import json; p=json.load(open('phase4_poc_plan.json')); print('Go/No-Go:', p['recommendation'])"
```

**Шаблоны:** Используйте `assets/poc_scorecard_template.md` для отслеживания оценки.

**Результат:** План POC, система показателей оценки, go/no-go рекомендация.

** Контрольная точка проверки: ** Для преобразования POC требуется оценка в системе показателей >60% по всем параметрам оценки (функциональность, производительность, интеграция, удобство использования, поддержка). Если оценка <60%, задокументируйте пробелы и вернитесь к циклу 2 для перепроектирования решения.

### Этап 5: Предложение и закрытие { #phase-5-proposal--closing }

**Цель:** Подготовить техническое предложение, которое будет способствовать закрытию коммерческой деятельности.

**Чек-лист:**
- [ ] Составление результатов POC и показателей успеха
- [ ] Создать техническое предложение с планом реализации
- [ ] Рассмотреть нерешенные возражения с использованием доказательств
- [ ] Поддержка обсуждения ценообразования и упаковки
- [ ] Одержать победу/loss анализ после принятия решения

**Шаблоны:** Используйте `assets/technical_proposal_template.md` для документа с предложением.

**Результат:** Техническое предложение, сроки реализации, план снижения рисков.

## Инструменты автоматизации на Python { #python-automation-tools }

### 1. Анализатор ответа на запрос RFP { #1-rfp-response-analyzer }

**Сценарий:** `scripts/rfp_response_analyzer.py`

** Цель:** Проанализировать требования к RFP/RFI, оценить охват, выявить пробелы и сгенерировать заявку/no-bid рекомендации.

** Категории охвата:** Полный (100%), частичный (50%), запланированный (25%), промежуточный (0%).  
** Взвешивание приоритетов: ** Обязательно иметь 3×, должно быть 2×, Приятно иметь 1×.

**Логика предложения/отказа от предложения:**
- **Ставка:** Охват >70% И обязательные пробелы ≤3
- **Условная ставка:** Покрытие 50-70% ИЛИ обязательные промежутки 2-3
- **Без участия в торгах:** Охват <50% ИЛИ обязательные пробелы >3

**Использование:**
```bash
python scripts/rfp_response_analyzer.py assets/sample_rfp_data.json            # human-readable
python scripts/rfp_response_analyzer.py assets/sample_rfp_data.json --format json  # JSON output
python scripts/rfp_response_analyzer.py --help
```

**Формат ввода:** Смотрите `assets/sample_rfp_data.json` для получения полной схемы.

### 2. Построение конкурентной матрицы { #2-competitive-matrix-builder }

**Сценарий:** `scripts/competitive_matrix_builder.py`

** Цель:** Создание матриц сравнения характеристик, расчет конкурентных баллов, выявление отличительных черт и уязвимостей.

** Оценка характеристик: ** Полная (3), частичная (2), ограниченная (1), Нет (0).

**Использование:**
```bash
python scripts/competitive_matrix_builder.py competitive_data.json              # human-readable
python scripts/competitive_matrix_builder.py competitive_data.json --format json  # JSON output
```

** Выходные данные включают: ** Матрицу сравнения характеристик, взвешенные конкурентные оценки, отличительные признаки, уязвимости и темы выигрыша.

---

### 3. Планировщик POC { #3-poc-planner }

**Сценарий:** `scripts/poc_planner.py`

**Цель:** Создание структурированных планов POC с указанием сроков, распределения ресурсов, критериев успеха и оценочных карточек.

**Разбивка по фазам по умолчанию:**
- **Неделя 1:** Настройка — подготовка среды, перенос данных, настройка
- **Недели 2-3:** Базовое тестирование — основные варианты использования, интеграционное тестирование
- ** Неделя 4:** Расширенное тестирование — передовые кейсы, производительность, безопасность
- **Неделя 5:** Оценка — заполнение системы показателей, ревью стейкхолдеров, переход/no-go

**Использование:**
```bash
python scripts/poc_planner.py poc_data.json              # human-readable
python scripts/poc_planner.py poc_data.json --format json  # JSON output
```

** Выходные данные включают:** Поэтапный план POC, распределение ресурсов, критерии успеха, систему показателей оценки, реестр рисков и go/no-go рекомендательный фреймворк.
