# Доходные операции { #revenue-operations }

Анализ пайплайна, отслеживание точности прогнозов и измерение эффективности GTM для отделов по доходам SaaS.

> **Выходные форматы:** Поддерживаются все скрипты `--format text` (удобочитаемый) и `--format json` (дашборды/интеграции).

```bash
# Analyze pipeline health and coverage

```

## Обзор инструментов { #tools-overview }

### 1. Анализатор пайплайна { #1-pipeline-analyzer }

Анализирует состояние пайплайна продаж, включая коэффициенты охвата, коэффициенты конверсии этапов, скорость заключения сделок, риски старения и риски концентрации.

** Входные данные:** JSON-файл со сделками, квотой и конфигурацией этапа
** Выходные данные:** Коэффициенты охвата, коэффициенты конверсии, показатели скорости, признаки старения, оценка рисков

**Использование:**

```bash
python scripts/pipeline_analyzer.py --input pipeline.json --format text
```

**Рассчитанные ключевые показатели:**
- **Коэффициент охвата пайплайном** -- Общее значение пайплайна/ целевая квота (работоспособно: 3-4 раза)
- **Коэффициенты пересчета стадий** -- Коэффициенты перехода от стадии к стадии
- ** Скорость продаж** -- (Возможности x Средний размер сделки x Процент выигрышей) / Средний цикл продаж
- **Устаревание сделок** -- Помечает сделки, среднее время цикла которых превышает 2 раза на каждом этапе
- **Риск концентрации** - Предупреждает, когда >40% пайплайна приходится на одну сделку
- **Анализ пробелов в охвате** - Выявляет кварталы с недостаточным количеством пайплайнов

**Схема ввода:**

```json
{
  "quota": 500000,
  "stages": ["Discovery", "Qualification", "Proposal", "Negotiation", "Closed Won"],
  "average_cycle_days": 45,
  "deals": [
    {
      "id": "D001",
      "name": "Acme Corp",
      "stage": "Proposal",
      "value": 85000,
      "age_days": 32,
      "close_date": "2025-03-15",
      "owner": "rep_1"
    }
  ]
}
```

### 2. Отслеживание точности прогноза { #2-forecast-accuracy-tracker }

Отслеживает точность прогноза с течением времени с помощью MAPE, обнаруживает систематические отклонения, анализирует тенденции и предоставляет разбивку по категориям.

** Входные данные:** JSON-файл с прогнозируемыми периодами и необязательной разбивкой по категориям
** Выходные данные:** Оценка MAPE, анализ смещений, тенденции, разбивка по категориям, оценка точности

**Использование:**

```bash
python scripts/forecast_accuracy_tracker.py forecast_data.json --format text
```

**Рассчитанные ключевые показатели:**
- **МЭЙП** -- имею в виду(|фактический - прогноз| / |фактический|) х 100
- **Предвзятость прогноза** - Тенденция к завышению прогноза (положительная) и занижению прогноза (отрицательная).
- **Взвешенная точность** -- MAPE, взвешенный по стоимости сделки для определения существенности
- **Тенденции периода ** - Повышение, стабильность или снижение точности с течением времени
- ** Разбивка по категориям** - Точность по представителю, продукту, сегменту или любому пользовательскому измерению

**Оценки точности:**
| Рейтинг | Диапазон отображения | Интерпретация |
|--------|-----------|----------------|
| Превосходно | <10% | Высоко предсказуемый процесс, основанный на данных |
| Хороший | 10-15% | Надежное прогнозирование с незначительной дисперсией |
| Справедливый | 15-25% | Нуждается в совершенствовании процесса |
| Бедный | >25% | Значительные пробелы в методологии прогнозирования |

**Схема ввода:**

```json
{
  "forecast_periods": [
    {"period": "2025-Q1", "forecast": 480000, "actual": 520000},
    {"period": "2025-Q2", "forecast": 550000, "actual": 510000}
  ],
  "category_breakdowns": {
    "by_rep": [
      {"category": "Rep A", "forecast": 200000, "actual": 210000},
      {"category": "Rep B", "forecast": 280000, "actual": 310000}
    ]
  }
}
```

### 3. Калькулятор эффективности GTM { #3-gtm-efficiency-calculator }

Рассчитывает основные показатели эффективности SaaS GTM с использованием отраслевого бенчмаркинга, рейтингов и рекомендаций по улучшению.

** Входные данные:** JSON-файл с показателями доходов, затрат и клиентов
** Выходные данные:** Магическое число, LTV: CAC, окупаемость CAC, Кратность записи, Правило 40, NDR с рейтингами

**Использование:**

```bash
python scripts/gtm_efficiency_calculator.py gtm_data.json --format text
```

**Рассчитанные ключевые показатели:**

| Метрика | Формула | Цель |
|--------|---------|--------|
| Магическое число | Чистые расходы на НИОКР за новый год / предыдущий период | >0.75 |
| LTV:CAC | (ARPA x Валовая прибыль / коэффициент оттока) / CAC | >3:1 |
| Окупаемость CAC | CAC / (ARPA x валовая прибыль) месяцы | <18 месяцев |
| Записать несколько | Чистый ожог / Чистый новый обход | <2 раза |
| Правило 40 | Рост выручки % + маржа FCF % | >40% |
| Чистое удержание доллара | (Начать ОБХОД + Расширение - сжатие - отток) / Начать обход | >110% |

**Схема ввода:**

```json
{
  "revenue": {
    "current_arr": 5000000,
    "prior_arr": 3800000,
    "net_new_arr": 1200000,
    "arpa_monthly": 2500,
    "revenue_growth_pct": 31.6
  },
  "costs": {
    "sales_marketing_spend": 1800000,
    "cac": 18000,
    "gross_margin_pct": 78,
    "total_operating_expense": 6500000,
    "net_burn": 1500000,
    "fcf_margin_pct": 8.4
  },
  "customers": {
    "beginning_arr": 3800000,
    "expansion_arr": 600000,
    "contraction_arr": 100000,
    "churned_arr": 300000,
    "annual_churn_rate_pct": 8
  }
}
```

## Воркфлоу операций по получению доходов { #revenue-operations-workflows }

### Еженедельный ревью по пайплайну { #weekly-pipeline-review }

Используйте этот воркфлоу для еженедельной проверки пайплайна.

1. **Проверьте входные данные:** Подтвердите, что экспорт пайплайна является текущим и все обязательные поля (стадия, значение, дата закрытия, владелец) заполнены, прежде чем продолжить.

2. **Сгенерировать отчет о пайплайне:**
   ```bash
   python scripts/pipeline_analyzer.py --input current_pipeline.json --format text
   ```

3. ** Перепроверьте итоговые данные** с исходной системой вашей CRM, чтобы подтвердить целостность данных.

4. **Ревью ключевых показателей:**
   - Коэффициент покрытия пайплайна (превышает ли он квоту в 3 раза?)
   - Сделки, возраст которых превышает пороговый уровень (какие сделки нуждаются во вмешательстве?)
   - Риск концентрации (не слишком ли мы зависим от нескольких крупных сделок?)
   - Распределение по стадиям (есть ли правильная форма воронки?)

5. **Документ с использованием шаблона:** Используйте `assets/pipeline_review_template.md`

6. ** Пункты действий:** Решение проблем со стареющими сделками, перераспределение концентрации пайплайна, заполнение пробелов в охвате

### Ревью точности прогноза { #forecast-accuracy-review }

Используйте ежемесячно или ежеквартально для оценки и улучшения дисциплины прогнозирования.

1. ** Проверьте входные данные:** Перед запуском убедитесь, что все прогнозные периоды имеют соответствующие фактические значения и ни один период не пропущен.

2. **Создание отчета о точности:**
   ```bash
   python scripts/forecast_accuracy_tracker.py forecast_history.json --format text
   ```

3. ** Перепроверьте фактические данные ** с записями о закрытых выигрышах в вашей CRM, прежде чем делать выводы.

4. **Анализировать закономерности:**
   - Имеет ли MAPE тенденцию к снижению (улучшению)?
   - В каких повторениях или сегментах наблюдается самый высокий процент ошибок?
   - Существует ли систематическое завышение или занижение прогнозов?

5. **Документ с использованием шаблона:** Используйте `assets/forecast_report_template.md`

6. ** Действия по улучшению:** Тренируйте представителей с высокой предвзятостью, корректируйте методологию, улучшайте гигиену данных

### Аудит эффективности GTM { #gtm-efficiency-audit }

Используйте ежеквартально или во время подготовки совета директоров для оценки эффективности выхода на рынок.

1. ** Проверьте входные данные:** Перед запуском подтвердите сверку показателей выручки, затрат и клиентов с финансовыми записями.

2. **Расчет показателей эффективности:**
   ```bash
   python scripts/gtm_efficiency_calculator.py quarterly_data.json --format text
   ```

3. ** Перепроверьте рассчитанные суммы доходов и расходов ** с вашей финансовой системой, прежде чем делиться результатами.

4. **Сопоставление с целевыми показателями:**
   - Магическое число (>0,75)
   - LTV:CAC (>3:1)
   - Окупаемость CAC (<18 месяцев)
   - Правило 40 (>40%)

5. **Документ с использованием шаблона:** Используйте `assets/gtm_dashboard_template.md`

6. **Стратегические решения:** Корректировка распределения расходов, оптимизация каналов, улучшение удержания

### Ежеквартальный ревью бизнеса { #quarterly-business-review }

Объедините все три инструмента для всестороннего анализа QBR.

1. Запустите анализатор пайплайна для прогнозного охвата
2. Запустите отслеживатель прогнозов для обеспечения точности прогнозирования в обратном направлении
3. Запустите калькулятор GTM для определения показателей эффективности
4. Перекрестные ссылки на работоспособность пайплайна с точностью прогноза
5. Приведение показателей эффективности GTM в соответствие с целями роста
