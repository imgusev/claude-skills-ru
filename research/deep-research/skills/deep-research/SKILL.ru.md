# Глубокое исследование — Дисциплинированное метаисследование { #deep-research--disciplined-meta-research }

Превратите "исследование этой темы" в проверяемое, многократно используемое исследование вместо одноразовой стены текста. Результатом является папка, к которой вы можете вернуться через месяц: каждая заявка прослеживается до определенного исходного файла, план документирует, почему был сделан каждый выбор, а протокол обновления позволяет вам обновить его позже, не запуская все заново.

** Это тяжелая, методичная часть исследования.** Это не быстрый обзор — это воркфлоу, к которому вы обращаетесь, когда получаете ответ *неправильно*, который стоит дороже, чем токены, потраченные на то, чтобы получить правильный ответ.

## Чем он отличается от маршрутизатора быстрого поиска { #how-it-differs-from-a-quick-research-router }

Исследовательский скилл в стиле маршрутизатора (классификация по ключевым словам → делегирование → краткий последовательный поиск → краткое описание Markdown) оптимален, когда вам нужен быстрый ответ и риск принятия решения невелик. `deep-research` это противоположная профессия: она оплачивает строгость. Используйте его, когда ответ подкрепляет стратегию, необратимое решение, опубликованный артефакт или гипотезу, которую вам необходимо на самом деле проверить, — ситуации, когда незначительный запасной вариант был бы помехой.

Конкретно, `deep-research` добавляет то, чего нет в кратком обзоре: заранее поддающиеся фальсификации гипотезы, параллельный саб-агент, распространяющийся по множеству каналов, триангуляция с явным разнообразием типов источников, обязательный состязательный проход, файлы для каждого источника с дословными цитатами и `refresh_targets.md` для дельта-обновлений позже.

## Пайплайн (9 этапов) { #the-pipeline-9-phases }

Глубина масштабируется в соответствии с задачей — `shallow` запускает основные фазы в режиме реального времени; `medium`/`deep` добавьте цели обнаружения возможностей, проверки и обновления.

| # | Фаза | Что он делает |
|---|-------|--------------|
| 1 | **Переосмысление** | Перепишите вопрос, исправьте лежащее в его основе решение, сформулируйте 2-4 *фальсифицируемые* гипотезы |
| 2 | ** Жанр и блоки** | Выберите жанр отчета (qa / пояснение / решение / ландшафт / проверка / пользовательский) и его составные части |
| 3 | **План** | Писать `plan.md`: объем, структура, стратегия поиска поставщиков, запросы возражений, реестр рисков, критерии остановки |
| 3.5 | **Обнаружение возможностей** | Аудит доступных ключей API/channels в среде; сопоставьте подтемы с исходными текстами; при необходимости вернитесь к HTML |
| 4 | **Поиск** (цикл) | Отправка источников → параллельный запуск саб-агентов → выборка и дедупликация → сохранение каждого в `sources/NN.md`; повторная оценка между раундами |
| 5 | ** Оценка и триангуляция** | Оцените каждый источник на предмет достоверности / новизны / предвзятости; для каждой диссертации требуется ≥3 независимых источников разного типа |
| 6 | **Синтезировать + состязательный** | Соберите отчет из блоков, задайте 4 вопроса для самокритики, добавьте контраргументы, подготовленные из стали |
| 6.5 | **Проверить** | Облегченная проверка цитирования перед закрытием |
| 7 | **Обновить целевые показатели** | Извлекать сущности / числа / гипотезы в `refresh_targets.md` — точка входа для будущих обновлений |

## Основные механизмы { #core-mechanisms }

Это то, что отличает документированное расследование от уверенной догадки:

- **Триангуляция.** Каждый тезис должен быть подкреплен ≥3 независимыми источниками * разных типов* (первичными / академическими / отраслевыми / дискуссионными). Утверждение с меньшим количеством доказательств помечается как "недостаточное", а не как факт.
- **Источник-заземление.** Каждый источник становится своим собственным `sources/NN_slug.md` с метаданными, дословными цитатами и оценками. Никаких висячих утверждений — каждое утверждение ссылается на определенный файл. Пустая выборка приводит к пустому утверждению, а не к сфабрикованной цитате.
- ** Состязательный проход.** На этапе 6 всегда используются самые сильные из доступных аргументов: 4 вопроса для самокритики плюс активный поиск контраргументов и опровергающих доказательств.
- **Фальсифицируемые гипотезы.** На этапе 1 выдвигаются 2-4 гипотезы; на этапах 5-6 явно подтверждается или опровергается каждая из них на основании имеющихся доказательств или отмечается, что она недостаточно определена.
- ** Параллельные саб-агенты.** Фаза 4 запускает поисковые саб-агенты одновременно (дешевые модели для широкого охвата сети, более мощные - для подтем с большим количеством рассуждений) — никогда по одному.
- **Протокол обновления.** Фаза 7 испускает `refresh_targets.md`; ан `update <slug>` запуск выдает дельту (новые участники, изменения сущности, обновленные номера, состязательные триггеры) вместо воспроизведения всего расследования.
- ** Атомарные выводы.** Тезисы, которые можно использовать повторно в `findings/FN.md` плюс еще `sources.csv` индекс — исследуйте соединения по всем вопросам вместо того, чтобы каждый раз начинать с нуля.

## Структура выходных данных { #output-structure }

```
<root>/<slug>/
├── plan.md                  # scope, sourcing strategy, risk register, changelog
├── sources.csv              # index of every source with scores
├── sources/
│   ├── 01_<slug>.md         # one file = one source (metadata + verbatim quotes)
│   └── ...
├── findings/                # atomic, reusable theses (larger investigations)
│   └── F1_<short>.md
├── refresh_targets.md       # what to watch on update (medium/deep)
├── diffs/
│   └── YYYY-MM-DD_delta.md   # delta from an `update <slug>` run
└── YYYY-MM-DD_<genre>.md     # final report
```

## Когда использовать { #when-to-use }

- Некачественный ответ обходится дорого: стратегия, бизнес-план, отчет или основа для статьи.
- Сравнивая N институтов, продуктов, методологий или рынков, вы нуждаетесь в обоснованных аргументах.
- Проверка гипотезы или решения на основе внешних данных.
- Мета-исследование: "понять, как работает X", "составить карту ландшафта Y", отвечая на ряд связанных вопросов.

## Анти-паттерны { #anti-patterns }

- ** Не пропускайте проверку существующей работы.** Перед поиском проверьте, есть ли ответ уже в проекте или в папке с предыдущими исследованиями — вы рискуете повторно исследовать то, что у вас уже есть.
- ** Не пропускайте переформулировку**, даже если запрос "кажется ясным". Решение, лежащее в основе вопроса, обычно изменяет поиск.
- ** Не выводите данные только в чат.** Всегда сохраняйте источники и отчет в файлах — значение повторного использования находится в папке, а не в расшифровке.
- ** Не выдумывайте цитаты.** Если выборка ничего не возвращает, утверждение пусто — никогда не придумывайте правдоподобный URL. Привяжите каждое утверждение к сохраненной дословной цитате.
- ** Не стройте выводов на скудном материале.** Слишком мало источников или все источники одного типа означают, что триангуляция не проводилась — скажите об этом, а не преувеличивайте уверенность.
- ** Не пропускайте состязательный проход ** на среднем/deep расследования. Исследование только для подтверждения - это режим сбоя, для предотвращения которого существует этот скилл.
- ** Не запускайте саб-агенты последовательно.** Параллельное разветвление; последовательный поиск лишает преимущества настенных часов.
- ** Не падайте в обморок `sources/` в один файл.** Файлы для каждого источника - это то, что делает результаты доступными для поиска и повторного использования в ходе различных расследований.
- ** Не выбирайте самую тяжелую модель для всего.** Соответствие модели подзадаче — дешево для широких подсечек, эффективно для синтеза и состязательного прохода.

## Перекрестные ссылки { #cross-references }

- ** исследовательский маршрутизатор ** — для быстрого просмотра тем, где риск принятия решения невелик; `deep-research` это альтернатива для тяжеловесов, когда строгость важнее скорости.
- **конкурентный разбор** - для сравнения N конкурентов по структурированной 12-мерной матрице.
- **обзор литературы / досье / патент** — специалисты в предметной области, когда исследование носит узко академический характер, человек/company-focused, или ориентированный на патенты.
