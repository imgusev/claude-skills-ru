# NotebookLM — Автоматизация браузера { #notebooklm--browser-automation }

> ** Требуется:** Среда автоматизации браузера (Claude Code CLI с возможностью использования на компьютере, расширение Claude Chrome или эквивалент). **Скилл корректно завершит работу в контекстах, не связанных с автоматизацией, с четким сообщением "не поддерживается".**

> ** Важно:** Этот скилл - единственный скилл для автоматизации браузера в коллекции версии 2. Это не соответствует соглашению о правилах целостности агента research-pack. Применяются различные ограничения (динамика пользовательского интерфейса, асинхронная генерация, стены входа в систему).

## Шаг 0: Настройка контекста браузера (обязательно) { #step-0-browser-context-setup-mandatory }

Прежде чем выполнять какие-либо другие действия, убедитесь, что доступна автоматизация браузера:

1. Проверьте, загружены ли в жгут инструменты управления браузером (скриншот, щелчок, поиск элемента, навигация).
2. Если недоступно → ** остановка с четким сообщением:** "Этот скилл требует автоматизации браузера. В настоящее время в {context}. Не удается продолжить. Используйте Claude Code CLI с помощью computer-use, расширения Claude Chrome или аналогичного."
3. Если доступно → сделайте первоначальный снимок экрана, перейдите к https://notebooklm.google.com
4. ** Обнаружьте стену входа в систему с помощью скриншота.** Если обнаружен экран входа в систему: остановитесь с надписью "Пожалуйста, войдите в NotebookLM в браузере, затем повторно задействуйте этот скилл". **Никогда не пытайтесь выполнить автоматический вход в систему.**

## Фаза 0: Приготовление на гриле (Маршрут действий) { #phase-0-grill-me-intake-action-routing }

До 4 форсирующих вопросов, по одному за раз, в порядке зависимости. Большинство вызовов заканчиваются на Q3.

### Q1 (корень) — Действие { #q1-root--action }

> ** Что ты хочешь, чтобы я сделал? Выбери что-нибудь одно:**
>
> 1. **Прочитать / извлечь** — задать вопрос о существующей записной книжке
> 2. ** Добавьте источник ** — вставьте содержимое (URL, текст, файл, Google Doc или синтезированный контент) в записную книжку
> 3. ** Создайте выходные данные студии ** — Аудио / видео обзор, ментальную карту, отчет (документ для брифинга, учебное пособие, часто задаваемые вопросы, временная шкала), Карточки, викторину, инфографику или слайды — точный набор предоставляется с панели live Studio
> 4. **Создайте новую записную книжку** — инициализируйте заголовком + исходные тексты
>
> *Почему я спрашиваю:* Каждое действие выполняется по-разному в пользовательском интерфейсе и требует разных параметров. Предварительное обозначение действия предотвращает потерю скриншотов и позволяет мне задавать только те дополнительные вопросы, которые применимы.

** Принуждение к выбору.** Если пользователь говорит "открыть NotebookLM" без указания действия, **откажитесь от запуска** и повторно задайте вопрос Q1.

### Q2 (зависит от Q1) — Идентификатор записной книжки { #q2-depends-on-q1--notebook-identity }

> ** Какой блокнот?** * (запрашивается для действий 1, 2, 3 — не для "создать новый")*
>
> *Почему я спрашиваю:* Если вы назовете мне имя, я проведу поиск по домашней странице; если вы дадите мне URL-адрес, я перейду напрямую. Неоднозначные имена получат промпту для устранения неоднозначности со скриншотами.

Для действия 4 (создать новый): замените на "Как называется новый блокнот?"

### Q3 (зависит от Q1) — параметр, зависящий от конкретного действия { #q3-depends-on-q1--action-specific-parameter }

**Действие 1 (чтение/извлечение):**
> - Какой вопрос нужно задать записной книжке? Используйте естественные формулировки — чат notebook справляется с этим лучше всего."

**Действие 2 (добавить источник):**
> "Какой тип источника? Выбери что-нибудь одно:
> 1. URL / веб-сайт / ссылка на YouTube
> 2. Скопированный текст (вставьте сюда или укажите на содержимое)
> 3. Загрузите файл (укажите абсолютный путь)
> 4. Google Doc (ссылка)
> 5. Синтезированный контент (я предварительно обработаю и добавлю как "Скопированный текст")
>
> *Почему я спрашиваю:* Каждый тип источника проходит через отдельный подпоток в диалоговом окне "Добавить источник". Оплата авансом экономит один шаг."

**Действие 3 (студийный выход):**
> "Какой студийный результат? Начиная с 2026-06 гг. панель Studio предлагает аудио—обзор, видео-обзор, ментальную карту, отчеты (Документ для брифинга / Учебное пособие / Часто задаваемые вопросы / Временная шкала / пользовательские), карточки, викторину, инфографику и слайды - я сделаю скриншот живой панели и подтвержду, что на самом деле показывает ваш аккаунт, прежде чем нажимать. И: какое-нибудь пользовательское направление для промптов? ** Промпты по умолчанию выдают посредственный результат — я всегда открываю меню настройки и пишу подробный промпт.** Укажите мне ракурс или аудиторию.
>
> *Почему я спрашиваю:* Тип вывода устанавливает кнопку пользовательского интерфейса для поиска. Пользовательская промпта обязательна для обеспечения качества."

**Действие 4 (создать новое):**
> - Первоначальные источники? Укажите URL-адреса, пути к файлам или "Я добавлю позже"."

### Q4 (зависит от Q1 = действие 3) — Подробная информация о пользовательском промпте Studio { #q4-depends-on-q1--action-3--studio-custom-prompt-detail }

> ** Сообщите мне ракурс, аудиторию и продолжительность студийного выхода. Примеры:**
>
> - ** Аудиообзор:** "Беседа с двумя ведущими для нетехнического руководителя, 8-10 минут, сосредоточьтесь на бизнес-последствиях, а не на технической глубине"
> - ** Инфографика:** "Стиль дерева решений, ориентированный на действия, максимум 6 панелей, монохромный темно-синий"
> - ** Учебное пособие:** "Уровень бакалавра, определения + 3 практических вопроса по каждой концепции"
>
> *Почему я спрашиваю:* Это становится пользовательской промпт. **По умолчанию промпты Studio выдают посредственный результат — в определенном направлении выводится четкий результат.**

**Запрашивается только для генерации выходных данных студии (Q1=3). В противном случае пропустите.**

**Условие остановки:** После Q4 (или ранее с пропусками зависимостей) зафиксируйте и запустите последовательность действий.

Видишь [`references/studio_output_custom_prompts.md`](references/studio_output_custom_prompts.md) для канона.

## Обнаружение записной книжки { #notebook-discovery }

Для действий 1-3 (требуется существующий блокнот):

1. Перейдите на главную страницу → скриншот
2. Если пользователь указал **URL** → перейти напрямую
3. Если пользователь указал **имя**:
   - Используйте семантический поиск(), чтобы найти карточку блокнота по видимому тексту заголовка
   - Если совпадений несколько → скриншот домашней страницы, список опций, попросите пользователя указать
   - Если совпадения нет → попросите пользователя указать URL-адрес или подтвердить правописание

Для действия 4 (создать новое):
1. Найдите кнопку "Создать блокнот" на главной странице
2. Нажмите → установить заголовок из Q2
3. Добавление исходных источников за 3 квартал

## Действие 1: Чтение / извлечение { #action-1-read--extract }

1. Откройте записную книжку (открытие записной книжки выше)
2. Найдите входные данные чата (семантический поиск или координаты скриншота)
3. Введите вопрос (используйте естественную формулировку пользователя из Q3)
4. Отправить (кнопка ввода или отправки)
5. **Подождите 3-5 секунд**
6. Сделайте снимок экрана с областью ответа
7. Извлеките и представьте в ** чистом формате** (не в необработанном дампе чата)

## Действие 2: Добавьте источники { #action-2-add-sources }

Подпотоки для каждого типа источника:

| Тип | Поток пользовательского интерфейса |
|---|---|
| URL / Веб-сайт / YouTube | Добавить источник → Ссылку → вставить URL |
| Скопированный текст | Добавить источник → Скопированный текст → вставить содержимое |
| Загрузка файла | Используйте инструмент загрузки файлов с абсолютным путем + введите ref (никогда не нажимайте на собственный инструмент выбора файлов). |
| Google Doc | Добавить источник → Документы Google → Средство выбора диска |
| Синтезированный контент | Предварительно обработайте содержимое в другом месте, затем добавьте в виде скопированного текста |

** После каждого добавления: ** дождитесь проглатывания spinner, сделайте снимок экрана, чтобы подтвердить успех.

** Синтезированный шаблон содержимого (мощный): ** вместо того, чтобы просить NotebookLM загружать необработанный URL-адрес с потенциально зашумленным содержимым, предварительно обработайте содержимое (извлеките основную статью, удалите навигацию / объявления / комментарии), затем добавьте как "Скопированный текст". Обеспечивает значительно лучшее обобщение.

## Действие 3: Студийные материалы { #action-3-studio-outputs }

** Обнаруживайте, а не предполагайте.** Инвентарь студии NotebookLM меняется в зависимости от раскатки и уровней аккаунтов. На момент последней проверки (2026-06) панель предлагает: ** Аудио-обзор, видео-обзор, Ментальную карту, отчеты** (Документ для брифинга, учебное пособие, Часто задаваемые вопросы, Временная шкала, пользовательские форматы отчетов), ** Карточки, викторину, инфографику, слайды**. Относитесь к этому списку как к подсказке, а не как к абсолютной истине — скриншот панели live Studio является авторитетным источником. Пользовательский интерфейс NotebookLM быстро развивается; сверяйте с текущим продуктом и обновляйте этот раздел, когда он будет обновляться (последняя проверка инвентаря Studio 2026-06).

**Обязательный воркфлоу:**

1. Найдите панель Studio (справа; возможно, потребуется переключить) и ** сделайте снимок экрана — плитки, которые вы видите, являются реальными типами вывода для этой учетной записи**
2. Найдите конкретную кнопку вывода для запрашиваемого типа (если она не видна, установите флажок "Узнать больше"/переполнение, прежде чем объявлять ее недоступной).
3. ** Откройте меню настройки ** (шеврон/стрелка рядом с кнопкой) — ** НЕ главная кнопка**
4. **Напишите подробный пользовательский промпт** (из Q4)
5. Подтвердите и отправьте
6. **НЕ дожидаться завершения** — подтвердить начало генерации, уведомить пользователя, вернуть

### Примеры пользовательских промптов (4 типа вывода) { #custom-prompt-examples-4-output-types }

** Обзор аудио:**
> "Беседа двух ведущих между исследователем и опытным практиком. Аудитория: нетехнический руководитель, принимающий бюджетное решение. Продолжительность: 8-10 минут. Сосредоточьтесь на бизнес-последствиях, а не на технической глубине. Приведите по одному конкретному примеру на каждый важный момент. Кратко подтвердите контраргументы."

**Инфографика:**
> "Стиль дерева решений. Ориентированный на конкретные действия (каждая дискуссия заканчивается решением или действием). макс. 6 панелей. Монохромный темно-синий цвет с янтарной подсветкой. Каждая панель содержит: заголовок (4-6 слов), основную часть из 1-2 предложений, линию принятия решения/действия. Никаких наполнительных панелей."

**Учебное пособие:**
> "Уровень бакалавриата (дайте определение каждому техническому термину). Структура: 6 концепций по 4 элемента в каждой (определение / почему это важно / один отработанный пример / 3 практических вопроса). Практикуйте вопросы более высокого порядка (применяйте / анализируйте), а не вспоминайте."

**Слайды (слайд-дека):**
> "12 слайдов, максимум по 1-2 предложения на каждый основной слайд. Ведущий отмечает на каждом слайде: один конкретный пример + одно вероятное возражение аудитории + как на него отреагировать. Никаких маркеров в текстах слайдов — только проза. Завершите призывом к действию из одного слайда."

Видишь [`references/studio_output_custom_prompts.md`](references/studio_output_custom_prompts.md) для большего.

## Действие 4: Создайте новую записную книжку { #action-4-create-new-notebook }

1. Перейдите на главную страницу
2. Нажмите "Создать записную книжку".
3. Установите заголовок из Q2
4. Добавьте исходные источники из Q3 (используйте подпотоки действия 2 для каждого типа источника)
5. **Дождитесь автоматической генерации итоговой информации ** (эта генерация является синхронной — обычно завершается менее чем за 30 секунд)
6. Конечное состояние скриншота

## Критическое асинхронное поведение { #critical-async-behavior }

> **Правило асинхронного вывода: ** Для студийных генераций (особенно ** Обзор аудио** — 5-10 мин) НЕ ждите завершения. Время ожидания сеанса пользователя истечет.
>
> Воркфлоу: Нажмите Сгенерировать → подтвердите запуск генерации с помощью скриншота → сообщите пользователю "Генерация продолжается — NotebookLM уведомит вас, когда будет готово" → ** завершите задачу.**

Это шаблон "запускай и уведомляй". Отличается от add-source и auto-summary (которые достаточно быстры, чтобы ждать).

Использование `scripts/async_action_classifier.py` чтобы определить время ожидания или уведомления для каждого действия:

| Действие | Ждать? |
|---|---|
| Добавить источник (URL/текст/файл) | Да — дождитесь приема спиннера (~5-30 секунд) |
| Чтение/извлечение (чат) | Да — подождите ответа 3-5 секунд |
| Студия: Аудио-обзор | **Нет** — открыть огонь и уведомить (5-10 мин) |
| Студия: Видеообзор | **Нет** — открыть огонь и уведомить об этом (5-15 мин) |
| Студия: Инфографика / Слайды / Ментальная карта | **Нет** — выстрелить и уведомить (2-5 мин) |
| Студия: Учебное пособие / Документ для инструктажа / Часто задаваемые вопросы / Карточки / Викторина | Да — подождите ~30-60 секунд |
| Создайте новую записную книжку | Да — дождитесь автоматического подведения итогов (<30 секунд) |

```bash
# Verdict + paste-ready notify message for any action
python3 scripts/async_action_classifier.py --action "video overview"
# -> Verdict: FIRE_AND_NOTIFY, estimated 5-15 minutes, with the exact
#    "NOT waiting in this session" message to relay to the user
```

## Скриншот-Первая дисциплина { #screenshot-first-discipline }

NotebookLM - это ** динамический SPA **, где пользовательский интерфейс меняется в зависимости от:
- Уровень учетной записи (бесплатный по сравнению с плюсовым по сравнению с корпоративным)
- Раскатка функций (некоторые типы студий пока доступны не всем пользователям)
- Последние изменения пользовательского интерфейса (Google часто повторяет продукт)

** Каждому действию пользовательского интерфейса должен предшествовать снимок экрана.** Причины:

1. Убедитесь, что пользовательский интерфейс соответствует ожиданиям, прежде чем действовать
2. Поймайте стены входа в систему пораньше
3. Обнаруживать неожиданные изменения макета
4. Журнал аудита для отладки

Использование `screenshot()` (или эквивалент в вашем средстве автоматизации браузера) перед каждым значимым взаимодействием с пользовательским интерфейсом.

Видишь [`references/browser_automation_canon.md`](references/browser_automation_canon.md) для поддержания дисциплины.

## найти()-Перед-щелчком { #find-before-click }

Используйте ** средства поиска семантических элементов** перед координатами пикселей везде, где это возможно:

- ✅ `find(text="Audio Overview")` → возвращает элемент независимо от положения
- ❌ `click(x=420, y=380)` → прерывается при перестановке пользовательского интерфейса

Семантические поисковики выдерживают незначительные изменения пользовательского интерфейса. Пиксельные координаты - нет.

Возвращайтесь к координатам только тогда, когда:
- Семантический поиск() ничего не возвращает
- Элемент не имеет стабильного text/aria-label/data-атрибута
- Визуальное положение - единственный надежный сигнал

## Сохранение выходных данных в рабочей области { #saving-outputs-to-workspace }

Для действий по чтению/извлечению полезной информации:

1. Чистое извлечение ответа из чата (удаление пользовательского интерфейса chrome)
2. Удобный для чтения формат (абзацы, списки, блоки кода по мере необходимости)
3. Если пользователь запросил → сохранить в файл (`${WORKSPACE}/notebooklm/<notebook-slug>-<action>-<date>.md`)
4. В противном случае → вернуться в чат в качестве окончательного резюме

Для студийных выходов:
1. В NotebookLM размещаются выходные данные (аудиообзор доступен в приложении, инфографика доступна для загрузки и т.д.).
2. Сообщите пользователю местоположение (URL-адрес или путь навигации в приложении)
3. Не пытайтесь загружать / сохранять выходные данные студии в локальное рабочее пространство — это работа NotebookLM

## Формат обратной связи { #reporting-back-format }

После завершения любого действия:

1. Сделайте окончательный снимок экрана, если он визуально уместен
2. Дайте ** чистую сводку** (не необработанный дамп чата):
   - Использованный блокнот (название)
   - Принятые меры (конкретные)
   - Результат (1-2 предложения)
   - Для сгенерированных выходных данных: что было создано + где оно находится + когда готово
3. Для действий с запуском и уведомлением: явно указано "NotebookLM уведомит вас, когда будет готово".

## Обработка ошибок { #error-handling }

| Неудача | Поведение |
|---|---|
| Автоматизация браузера недоступна | Быстрый сбой с сообщением "для этого скилла требуется автоматизация браузера" (шаг 0 остановка) |
| Обнаружена стена входа в систему | Остановись. Попросите пользователя войти в систему. Не пытайтесь автоматически войти в систему. |
| Название нескольких записных книжек совпадает | Скриншот домашней страницы, список опций, просьба пользователя указать |
| Источник проглатывания спиннер застрял > 60-х годов | Обратите внимание на тайм-аут, спросите пользователя, хочет ли он повторить попытку |
| Кнопка Studio не найдена на панели | Прокрутите вниз или найдите "Узнать больше"; если по-прежнему отсутствует, функция "Примечание" может быть не включена для этой учетной записи |
| Ответ в чате не появляется в течение 10 секунд | Снимок экрана, проверьте состояние ошибки, повторите попытку один раз |
| Макет страницы неожиданно изменился | Сделайте снимок экрана, опишите, что видно, попросите пользователя дать рекомендации |

## Анти-Паттерны для отклонения { #anti-patterns-to-reject }

- Названия инструментов, специфичные для конкретного инструмента, без абстракции (например, жесткое кодирование "Claude Chrome Extension")
- Синхронное ожидание в студийных поколениях (особенно обзор аудио)
- Пропуск скриншотов между действиями
- Использование пиксельных координат, когда доступна функция семантического поиска()
- Попытка автоматически обрабатывать потоки входа в систему
- Создание студийных выходных данных без открытия меню настройки
- Использование промптов Studio по умолчанию (всегда пишите пользовательские)
