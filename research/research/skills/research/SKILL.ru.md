# Исследование — Гибридный маршрутизатор + запасной вариант { #research--hybrid-router--fallback }

**Оркестратор среды выполнения для предметной области исследования.** Архитектура C: детерминированная классификация → делегирование специалисту ИЛИ собственный воркфлоу "Планирование-декомпозиция-поиск-синтез-цитирование".

## Портативность { #portability }

Требует `WebSearch` + `WebFetch` для резервного воркфлоу; скиллы специалиста (`pulse`, `grants`, `litreview`, `syllabus`, `patent`, `dossier`) должен присутствовать для того, чтобы делегирование работало. Node.js с `docx` пакет требуется, если Q2 = режим документа. Изначально работает в Claude Code CLI. В Клоде.поддерживается искусственный интеллект с веб-инструментами + выполнение кода, воркфлоу.

## Отличный от `engineering/autoresearch-agent` { #distinct-from-engineeringautoresearch-agent }

Эти два скилла объединяются словом "исследование", но служат ** совершенно разным вариантам использования**:

- **`research/research/`** (этот скилл) — маршрутизатор запросов к исследованию + резервный воркфлоу ("Исследование X")
- **`engineering/autoresearch-agent/`** — Цикл автономного эксперимента по оптимизации файлов Karpathy ("Сделайте этот код быстрее")

Никакого перекрытия. Они сосуществуют.

## Гибридная архитектура (C) { #hybrid-architecture-c }

Каждый вызов приводит к одному из трех результатов:

1. **Делегирование** — Классифицируется как специализированная область. Маршруты там есть. Пользователь видит результаты работы специалиста.
2. **Резервное выполнение** — Классифицируется как общее исследование. Запускает собственный план → поиск → синтез воркфлоу.
3. **Запрос на разъяснение** — Классификация неоднозначна ИЛИ сопоставлен сигнал с одним существительным. Задает один форсирующий вопрос (с рекомендуемым ответом) для устранения неоднозначности, затем направляет.

Скилл ** никогда молча не запускает свой запасной вариант**, когда специалист справился бы лучше. **Прозрачность маршрутизации** - это то, что делает гибридную архитектуру надежной.

## Специализированный реестр { #specialist-registry }

| Специалист | Маршрутизирующие сигналы | Домен |
|---|---|---|
| `pulse` | reddit / hn / x / buzz / настроения / тренды / "что говорят люди" / "пульс включен" / "следи за пульсом" / "текущий разговор" | Исследование последних событий из нескольких источников |
| `grants` | NIH / грант / R01 / K-премия / Репортер / NOSI / "гранты для" / FDA / "исследовательский отдел" / "главный исследователь" | Информация о грантовом финансировании NIH |
| `litreview` | ревью литературы / PICO / SPIDER / систематический ревью / "ревью статей по" / метаанализ | Ориентация на академическую литературу |
| `syllabus` | программа / план курса / учебный план / "список для чтения" / "для моего класса" / "для моих учеников" | Дополнительное чтение курса |
| `patent` | уровень техники / FTO / свобода действий / патент / "патентный ландшафт" / изобретение / поиск новизны / "ландшафт интеллектуальной собственности" | Патент на предшествующий уровень техники + ландшафт |
| `dossier` | "досье на" / "due diligence" / "проверка биографических данных" / "подготовьте меня к" / "исследование конкурентов" / "проверка инвестора" / "подготовка к собеседованию" / "предыстория" | Исследование объектов на уровне принятия решений |

**Эскалация → `deep-research`:** когда неправильный ответ обходится дорого (стратегия, сравнение N вариантов, проверка гипотезы, отображение поля) и строгость важнее скорости, эскалация до `deep-research` скилл вместо быстрого резервного воркфлоу — он запускает триангулированное, многоэтапное, состязательное расследование и сохраняет доступную для проверки, многоразовую папку исследований. Этот маршрутизатор - самый быстрый путь; `deep-research` это тот, что в тяжелом весе.

## Правила добросовестности агента { #agent-integrity-rules }

Этот скилл соответствует правилам исследовательского набора:

- **Дисциплина выполнения (только резервный вариант)**: Последовательный поиск. ограничение скорости 1 q/сек. Подтвердите полученный ответ перед следующим вызовом.
- **Дисциплина источников**: Цитируйте только источники, возвращаемые вызовами инструментов этого сеанса. Учебные знания, помеченные `[Background — not from search]` и исключен из подсчетов.
- ** Отслеживание по трем счетам (только резервный вариант)**: Отправленные запросы / полученные источники / цитируемые источники.
- **Политика повторных попыток **: При сбое → подождите 3 секунды → повторите попытку один раз → войдите в систему. После 3 последовательных сбоев: остановитесь, предупредите пользователя.
- **Дисциплина маршрутизации**: Никогда не делегируйте молча. Всегда указывайте решение + принимайте переопределение.

## Фаза 1: Прием пищи на гриле (2-4 вопроса) { #phase-1-grill-me-intake-24-questions }

Потребление намеренно минимально — цель состоит в том, чтобы быстро проложить маршрут, а не допрашивать. По одному вопросу за ход.

### Q1 (всегда) — Исследовательский вопрос { #q1-always--research-question }

> ** Каков вопрос исследования? Изложите это в 1-2 предложениях. Конкретное лучше, чем широкое — "ИИ для здравоохранения" дает вам расплывчатый опрос; "Как системы здравоохранения интегрируют поддержку принятия клинических решений на основе LLM?" дает вам полезный ответ.**

** Откажитесь от каши. ** Если пользователь говорит "исследуйте ИИ", ответьте один раз: "А что конкретно с ИИ — внедрение, безопасность, возможности, финансирование, регулирование, сравнение? Выбери ракурс."

### Q2 (всегда) — Предпочтение вывода { #q2-always--output-preference }

> ** Какой результат вы хотите получить? Выбери что-нибудь одно:**
> 1. Краткий инструктаж в чате (5-минутное чтение, Markdown в чате)
> 2. Отдельный документ (.docx с цитатами, доступный для общего доступа)

Вынуждающий выбор. Режим работы с документами триггерами более глубокого поиска и полными журналами аудита.

### Вопрос 3 (задается только при возврате классификации `ask` или `fallback` без сигналов) — Устранение неоднозначности домена { #q3-asked-only-when-classification-returns-ask-or-fallback-with-no-signals--domain-disambiguation }

> ** Краткое пояснение — выберите наиболее близкое совпадение ** * (рекомендуется: {N} — ваш вопрос соответствовал `{specialist}` сигнал)*:
> 1. Научная литература (статьи, прошедшие ревью)
> 2. Отрасль / тенденции (что за шумиха, новости, настроения)
> 3. Конкретная организация (компания, физическое лицо, организация)
> 4. Технология / патенты (уровень техники, структура интеллектуальной собственности)
> 5. Грантовое финансирование (NIH, фонды)
> 6. Материалы курса (учебная программа)
> 7. Ни одно из вышеперечисленных исследований общего характера не проводится.

Когда классификатор вернулся `ask` (сигнал с одним существительным), предварительно отметьте рекомендуемый вариант. **Пропустить, если классификация привела к обходу маршрута без ответа (≥2 сигналов ИЛИ одна сильная фраза из нескольких слов).**

### Q4 (спрашивается только, нужен ли Q3, И пользователь выбрал "ничего из вышеперечисленного") — Общие сведения - область исследования { #q4-asked-only-if-q3-was-needed-and-user-picked-none-of-the-above--general-research-scope }

> ** Что касается общего исследования, каков ваш временной горизонт — быстрое сканирование (5 поисковых запросов) или тщательное (15 поисковых запросов)?**

Пропустите, если за дело взялся специалист.

** Условие остановки: ** После Q4 (или раньше, если применены пропуски зависимостей) зафиксируйте и запустите фазу 2. ** Большинство вызовов завершают прием после Q1 + Q2.**

## Фаза 2: Детерминированная классификация { #phase-2-deterministic-classification }

Это ** детерминировано, а не обосновано LLM** — для скорости, отлаживаемости и согласованности.

```python
SIGNALS = {
  pulse:    ["reddit", "hn", "hacker news", "x.com", "twitter", "buzz",
             "sentiment", "trending", "what are people saying",
             "what's happening", "the conversation around",
             "pulse on", "take the pulse", "current conversation"],
  grants:   ["nih", "grant", "grants for", "r01", "r21", "k-award", "reporter",
             "nosi", "funding", "fda", "study section", "principal investigator"],
  litreview:["literature review", "lit review", "litreview", "pico", "spider",
             "systematic review", "review papers on", "research papers on",
             "papers about", "meta-analysis"],
  syllabus: ["syllabus", "course outline", "curriculum", "reading list",
             "for my class", "for my students", "course material"],
  patent:   ["prior art", "fto", "freedom to operate", "patent",
             "patent landscape", "invention", "novelty search",
             "patent search", "ip landscape"],
  dossier:  ["dossier on", "due diligence", "background check",
             "prep me for", "competitor research", "investor diligence",
             "interview prep", "research my competitor", "background on"]
}

# Signals are case-insensitive literal phrases (multi-word substring match).
# Bracketed placeholders (e.g., "research [company]") are intentionally NOT
# signals — they over-trigger on generic "research X" queries that should
# fall back to general research, not auto-route to dossier.
# STRONG signal = multi-word phrase (contains a space): pairs verb with noun
# ("dossier on", "prior art") and routes reliably.
# BARE-NOUN signal = single word ("funding", "fda", "patent", "grant"):
# too weak to silent-route on alone — it must trigger Q3 with a
# recommended answer instead.

For each specialist S:
  score[S] = count of SIGNALS[S] phrases matched in question (case-insensitive substring)

if max(score) >= 2:
  route_to = argmax(score)                  # high confidence — silent route
elif max(score) == 1 and only one specialist has score 1:
  if the matched phrase is multi-word (contains a space):
    route_to = that specialist              # strong phrase — silent route
  else:
    route_to = "ask"                        # bare noun — ask Q3, recommend that specialist
else:
  route_to = "fallback"                     # ambiguous or no match — ask Q3 / run fallback
```

**Внедрение:** `scripts/classifier.py --question "..."` возвращает решение о маршрутизации + согласованные сигналы + баллы для каждого специалиста + (для `ask`) рекомендованный специалист. Используйте его; не внедряйте повторно. Приведенная выше карта СИГНАЛОВ и правила сохраняются фраза за фразой в синхронизации со скриптом - дрейф = ошибка.

## Фаза 3а: Делегирование полномочий специалисту (≥2 сигналов ИЛИ одна сильная фраза из нескольких слов) { #phase-3a-specialist-delegation-2-signals-or-one-strong-multi-word-phrase }

При делегировании:

1. Передайте вопрос пользователя ** дословно** плюс настройки вывода (Q2)
2. **Позвольте специалисту самостоятельно приготовить блюда на гриле** — не отвечайте предварительно на вопросы специалиста
3. Возвращает вывод специалиста в виде видимого пользователем результата
4. Пометьте результат с помощью `[Delegated to: research → {specialist}]` в выводе чата, чтобы пользователь знал, какой скилл его создал
5. Пометьте журнал аудита с помощью `scripts/routing_transparency_logger.py --action record_delegation`

## Фаза 3b: Собственный резервный воркфлоу { #phase-3b-own-fallback-workflow }

Если маршрутизация не привела к совпадению специалистов (и Q3 подтвердил результаты общего исследования), выполните 8-шаговый резервный вариант:

1. **Разложить** — разбейте вопрос на 3-5 подвопросов (что / почему / как / кто / что дальше). Покажите разложение перед поиском. `scripts/fallback_decomposer.py --question "..."` дает детерминированную отправную точку.
2. ** Выбор источника ** — для каждого подвопроса: недавность → веб-поиск + веб-выборка (+ Reddit /HN по сигналу); технические / документы → веб-поиск + веб-выборка; академический → Согласованный MCP, если подключен, иначе веб-поиск с `scholar.google.com` фильтр сайта; данные/номера → веб-выборка первичных документов; уровень объекта → предложение `dossier` измените маршрут.
3. ** Поиск ** — последовательный по каждому подвопросу, 1 вопрос в секунду, 2-4 запроса на источник, от широкого к узкому.
4. **Чтение + извлечение ** — Веб-выборка результатов с высоким уровнем сигнала; обратите внимание на каждый URL-адрес источника.
5. ** Обобщить** — 2-4 абзаца на каждый подвопрос со встроенными цитатами; поверхностное несогласие, когда источники расходятся во мнениях.
6. ** Сквозные шаблоны** — 1-2 абзаца по подвопросам: консенсус, противоречия, пробелы.
7. **Вывод** — краткое описание Markdown по умолчанию; DOCX, если пользователь выбрал режим документа.
8. ** Журнал аудита** — три подсчета (отправлено / получено / процитировано) + уровень надежности для каждого источника (первичный / вторичный / третичный).

## Протокол прозрачности маршрутизации (обязательный) { #routing-transparency-protocol-mandatory }

После классификации скилл ** всегда**:

1. **Излагает решение** в одном предложении: "Маршрутизация в `litreview` потому что вы упомянули ПИКО и мета-анализ (2 сигнала)."
2. ** Предлагает переопределить **: "Если вам нужны общие исследования вместо этого ИЛИ другой специалист, скажите об этом сейчас".
3. ** Продолжает следовать рекомендуемому маршруту, если пользователь не возражает ** — никаких таймеров, никаких обратных отсчетов.
4. **Если пользователь переопределяет** → принять, перенаправить, зарегистрировать переопределение с помощью `routing_transparency_logger.py --action record_override`.

**Никогда не делегируйте молча.** Это свойство, укрепляющее доверие, которое заставляет работать гибридный шаблон.

## Выходной формат { #output-format }

**Краткое описание Markdown** (Q2 = краткий обзор в чате): название + `*Generated: [DATE] | Routed: [specialist | fallback]*`, затем ** TL;DR** (2-3 предложения) → ** Выводы** (по одному H3 на подвопрос, встроенные цитаты) → ** Сквозные шаблоны** → ** Источники** (пронумерованные, с гиперссылками, уровень надежности каждого) → ** Аудит** (три подсчета + неудачи).

**DOCX** (Q2 = отдельный документ): стандартные шаблоны DOCX для исследовательского пакета - Arial 12pt, темно—синие заголовки, синие заголовки таблиц, источники с гиперссылками, раздел журнала обязательного аудита. Ссылайтесь на `docx` скилл для настройки.

### Блок журнала аудита (резервный режим) { #audit-log-block-fallback-mode }

```
Queries sent: N | Sources received: M | Sources cited: K
Failures: F (3-consecutive-failures triggered: yes/no)
Per-source tier: [URL — primary | secondary | tertiary]
Routing decision: fallback (no specialist matched)
Sub-questions: [list]
```

Все решения о маршрутизации + переопределения также регистрируются в `~/.research_sessions/<session>.json` через `routing_transparency_logger.py`.

## Режимы отказа { #failure-modes }

| Неудача | Поведение |
|---|---|
| Одиночный сигнал без существительного (например, "финансирование", "Управление по санитарному надзору за качеством пищевых продуктов и медикаментов") | Задайте вопрос 3, предварительно указав подходящего специалиста в качестве рекомендуемого ответа. Никогда не бесшумный маршрут. |
| Классификация неоднозначна (несколько совпадений с 1 сигналом или ни одного) | Спросите Q3 (устранение неоднозначности домена). |
| Делегирование специалистов терпит неудачу | Заметка в чате. Предложите повторить попытку или вернуться к общему исследованию. |
| Пользователь переопределяет маршрутизацию | Прими это. Измените маршрут. Зарегистрируйте переопределение. |
| Резервный поиск возвращает скудные результаты | Поверхность явно. Предположите, что вопрос может быть слишком узкоспециализированным или слишком новым. Не выдумывайте. |
| 3 последовательных отказа инструмента в резервном режиме | Остановите, предупредите пользователя, поделитесь тем, что было собрано. |
| Вопрос не является исследовательским (например, "напиши мне код"). | Вежливо откажитесь. Предложите соответствующий скилл. |
| На дополнительный вопрос невозможно ответить | Отметьте как "ограниченный общественный сигнал по этому поводу"; не пропускайте молча. |
| Несоответствие выходного формата | Honor Q2; если недоступен, вернитесь к Markdown с примечанием. |
| Специализированный скилл, отсутствующий в окружающей среде | Пропустите это при подсчете очков в классификации; перейдите к запасному варианту или следующему лучшему специалисту. |

## Отклоненные анти-паттерны { #anti-patterns-rejected }

- LLM-обоснованная классификация (должно быть детерминированное ключевое слово + соответствие намерениям)
- Тихое делегирование (всегда поверхностное решение о маршрутизации)
- Отказ в направлении к специалисту при совпадении ≥2 сигналов
- Бесшумная маршрутизация по единственному сигналу без имени существительного (необходимо задать вопрос "исследование тенденций одобрения FDA", а не автоматический маршрут к грантам)
- Доступность настенных часов ("автоматический переход после Ns") - модель не может ждать; следуйте рекомендуемому маршруту, если пользователь не возражает
- Предварительно ответьте на запрос специалиста по приготовлению гриля (пусть он работает сам по себе)
- Создание резервных источников при ограниченном поиске
- Пропуск журнала аудита в резервном режиме
- Рассматривающее "досье на [компания]" в качестве запасного варианта, когда `dossier` является подходящим специалистом (словосочетание в паре глагол-существительное используется; общая форма "исследование X" - нет)
- Универсальное исследование с автоматической маршрутизацией " [тема]" запросы к специалисту ("исследование Microsoft" само по себе неоднозначно — может быть досье или общее; спросите Q3 вместо того, чтобы гадать)

## Оснастка { #tooling }

- **`scripts/classifier.py`** — Детерминированное согласование СИГНАЛОВ → решение о маршруте (`specialist` / `ask` + рекомендуется / `fallback`) + оценка по каждому специалисту + совпадающие фразы. `--question "..." --output json`.
- **`scripts/routing_transparency_logger.py`** — Журнал аудита с поддержкой JSON по адресу `~/.research_sessions/<session>.json`. Записывает каждое решение о маршрутизации, переопределении и хэндоффе делегирования.
- **`scripts/fallback_decomposer.py`** — Эвристический вопрос → 3-5 подвопросов (что / почему / как / кто / что дальше).

### Справочные материалы (каждый ссылается на более чем 7 авторитетных источников) { #reference-docs-each-cites-7-authoritative-sources }

## Зависимости { #dependencies }

- **`WebSearch`** + **`WebFetch`** — Требуется для резервного воркфлоу
- **Специальные скиллы** — Требуются для делегирования полномочий: `pulse`, `grants`, `litreview`, `syllabus`, `patent`, `dossier`. Если специалист отсутствует, маршрутизатор пропускает его и вместо этого перенаправляет на резервный вариант.
- **Node.js `docx` библиотека** — Требуется, если пользователь выбирает вывод документа (Q2 = автономный)
- **Согласованный MCP** — необязательно; используется в качестве запасного варианта, если возникают академические подвопросы
