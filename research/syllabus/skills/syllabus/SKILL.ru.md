# Программа — Список дополнительного чтения по курсу { #syllabus--course-supplementary-reading-list }

> ** Переносимость:** Требуется согласованное подключение MCP, Node.js с `docx` пакет и возможность чтения файлов для учебной программы. Изначально работает в Claude Code CLI. В Клоде.искусственный интеллект с согласованным MCP + выполнением кода + загрузкой файла поддерживает воркфлоу.

Для преподавателя или студента, изучающего программу курса, подготовьте профессиональный список дополнительного чтения в качестве `.docx` содержащий недавние статьи, прошедшие ревью рецензентов по каждому разделу курса.

## Архитектурный шаблон: Связанный сценарий { #architectural-pattern-bundled-script }

В этом скилле используется ** встроенный вспомогательный скрипт JavaScript ** для генерации DOCX, а не встраивание более 300 строк кода макета:

- Логика генерации DOCX является многоразовой + сложной
- Лучшее разделение задач: скилл = оркестрация + интеллект; сценарий = механическая сборка документа
- Эффективность использования токенов: скилл не создает макет заново при каждом запуске
- Более простой в обслуживании и версии

Прилагаемый скрипт находится по адресу `scripts/generate_reading_list.js`. Скилл организует пайплайн + вызывает скрипт с вводом JSON.

## Правила добросовестности агента (Соглашение об исследовательском пакете) { #agent-integrity-rules-research-pack-convention }

Заблокирован дословно в соответствии с аудитом PR #657.

- ** Используйте только то, что возвращает консенсус.** Название каждой статьи, автор, журнал, год выпуска, URL-адрес должны быть получены из вызовов инструментов этого сеанса. Учебные документы с пометкой "Знания" `[Not from Consensus — model knowledge]` и исключен.
- ** Подтвердите, прежде чем двигаться дальше.** Поиск не будет завершен до тех пор, пока не будет получен и проверен ответ.
- ** Отследите три отсчета.** Отправленные запросы / полученные статьи / цитируемые статьи. Появится в сводке по аудиту.
- ** Пробелы на поверхности, не заполняйте их.** Раздел с одним листом бумаги + примечание об ограниченных результатах > раздел, дополненный выдумками.

## Фаза 0: Приготовление на гриле (3 форсирующих вопроса) { #phase-0-grill-me-intake-3-forcing-questions }

### Q1 (root) — Ввод учебной программы { #q1-root--syllabus-input }

> **Предоставьте учебную программу — выберите одну из них:**
>
> 1. Путь к файлу (PDF, DOCX, текст) — я его прочитаю
> 2. Вставленное содержимое — вставьте ниже
> 3. Изображение печатной учебной программы — прикрепите изображение
>
> *Почему я спрашиваю:* Для каждого формата требуется свой ридер (PDF / DOCX parser / vision). Получение информации заранее предотвращает напрасные попытки.

Вынуждающий выбор. Отказывайтесь начинать без учебной программы.

### Q2 (зависит от Q1) — Аудитория курса { #q2-depends-on-q1--course-audience }

> **Аудитория курса — выберите одну:**
>
> 1. Бакалавриат (вводный уровень)
> 2. Бакалавриат (продвинутый / высший дивизион)
> 3. Выпускник (магистр / ранний кандидат наук)
> 4. Выпускник (докторантура / продвинутый уровень)
> 5. Профессиональное / непрерывное образование
> 6. Смешанный
>
> *Почему я спрашиваю:* Аудитория диктует уровень общего жаргона и сложность вопросов для обсуждения. Резюме для старшекурсников определяют каждый термин; резюме для выпускников предполагают свободное владение техникой. Дискуссионные вопросы для анализа тестов старшекурсников; для критики и расширения тестов выпускников.

Видишь [`references/audience_calibration.md`](references/audience_calibration.md) для канона.

### Q3 (зависит от Q1) — Диапазон лет { #q3-depends-on-q1--year-range }

> **Диапазон лет выпуска документов — выберите один:**
>
> 1. Последний 1 год (только самый последний)
> 2. Последние 2 года (по умолчанию — последние + год контекста)
> 3. Последние 5 лет (шире, включает фундаментальную недавнюю работу)
>
> *Почему я спрашиваю:* Списки для чтения быстро устаревают. фильтры, рассчитанные на 1 год, сохраняют свежесть продуктов; фильтры, рассчитанные на 5 лет, основаны на новейших разработках, которые уже стали стандартом. Задает параметр year_min при каждом поиске консенсуса.

Принудительный выбор по умолчанию (последние 2 года).

** Условие остановки:** максимум 3 вопроса перед этапом 1. Контрольно-пропускной пункт после 2-й фазы группирования и подтверждения - это сам по себе момент "поджаривания".

## Этап 1: Разбор учебной программы { #phase-1-parse-the-syllabus }

В соответствии с форматом ввода Q1:

- **PDF**: используйте программу чтения PDF-файлов; извлеките текст
- **DOCX**: используйте синтаксический анализатор pandoc или DOCX; извлеките текст
- **Текст/вставлено**: читать непосредственно
- **Изображение**: используйте vision; извлеките текст

Из извлеченного текста:
1. Название курса + преподаватель + срок обучения
2. Список тем (названия лекций, разбивка по неделям и т.д.)
3. Результаты обучения (если они явные; если отсутствуют, укажите 3-5 из описания)

Отметьте предполагаемые результаты обучения как `[inferred]` в формате DOCX.

## Этап 2: Группирование тем + Подтверждение с пользователем { #phase-2-group-topics--confirm-with-user }

### Группа через topic_grouper.py { #group-via-topic_grouperpy }

Использование `scripts/topic_grouper.py` сгруппировать связанные темы в 6-12 разделов. Эвристика: тесно связанные темы объединяются; сквозные темы получают свой собственный раздел.

### Контрольная точка группирования и подтверждения (принудительные опции) { #group-and-confirm-checkpoint-forcing-options }

После группировки представьте:

> **Предлагаемые разделы: [список с количеством элементов]. Выбери что-нибудь одно:**
>
> 1. "Выглядит хорошо — переходите к этим разделам"
> 2. "Объединить разделы [X] и [Y]"
> 3. "Разделенная секция [X] на две части"
> 4. "Добавьте раздел для [тема]"
> 5. "Удалить раздел [X]"
>
> * Почему я спрашиваю: * Группировка определяет распределение поиска. Неправильная группировка приводит к растрате бюджета поиска на плохие кластеры. Это ** последний дешевый момент ** скорректировать курс, прежде чем поисковые запросы потребуют согласованных запросов.

**Отказаться от запуска фазы 3 без явного выбора пользователя.**

## Этап 3: Поиск консенсуса по каждому разделу { #phase-3-search-consensus-per-section }

Последовательный, 1 вопрос в секунду. 1-2 запроса на раздел.

### Плетение в прикладной области (критическое) { #applied-domain-weaving-critical }

Не просто выполняйте поиск по теме — **выполняйте поиск по теме + применяемому домену**:

| ❌ Универсальный | ✅ Прикладная область |
|---|---|
| "кинетика ферментов" | "применение кинетики ферментов в пищевой промышленности" |
| "машинное обучение" | "поддержка принятия клинических решений с помощью машинного обучения" |
| "термодинамика" | "термодинамика систем возобновляемой энергетики" |
| "анализ социальных сетей" | "анализ социальных сетей и мероприятия в области общественного здравоохранения" |

Значительно повышает актуальность статьи. Видишь [`references/applied_domain_weaving.md`](references/applied_domain_weaving.md) для канона.

### Схема для каждого сечения { #per-section-pattern }

```
For each section:
  1. Construct query: "{topic-keywords} {applied-domain-angle}" + year_min from Q3
  2. Submit to Consensus (sequential, 1 q/sec gap enforced by citation_tracker)
  3. Receive results
  4. (If thin) submit one fallback query without applied-domain angle
  5. Select 1-3 papers per section (15-25 total across all sections)
```

### Приоритеты выбора { #selection-priorities }

1. **Актуальность** — статья непосредственно посвящена теме раздела
2. **Ревью / метаанализ** - обобщение информации в данной области
3. **Количество цитирований** — устоявшаяся работа
4. **Связь с прикладной областью ** — привязана к предметной области курса (например, инженерия против теории)

## Этап 4: Составление резюме + Вопросы для обсуждения { #phase-4-write-summaries--discussion-questions }

### Написание резюме { #summary-writing }

На бумагу:
- Простой язык (откалиброван для аудитории со второго квартала)
- 2-3 предложения
- Определите жаргон, если аудитория бакалавриата; предполагайте свободное владение, если выпускник

### Качественные слитки { #quality-bars }

| ✅ Хорошее резюме | ❌ Плохое резюме |
|---|---|
| "В этом ревью показано, как различные диеты — средиземноморская, скандинавская, вегетарианская — изменяют типы молекул жира, циркулирующих в вашей крови, что влияет на риск сердечных заболеваний". | "В этой статье проводится ревью липидомных профилей при различных диетических вмешательствах и их кардиометаболических последствиях". |

### Написание вопросов для обсуждения { #discussion-question-writing }

На бумагу:
- Цветение ** более высокого порядка** (применять / анализировать / оценивать)
- Привязан к конкретному результату изучения курса
- Способствует обсуждению, а не просто воспоминанию

| ✅ Хороший вопрос | ❌ Плохой вопрос |
|---|---|
| "Если качество пищевых жиров может изменить липидный состав вашего липопротеина, что это говорит о биохимической основе рекомендаций по питанию, рекомендующих преобладание ненасыщенных жиров над насыщенными?" | "Что же обнаружили авторы?" (Просто напомню) |

Использование `scripts/discussion_question_validator.py` чтобы отметить вопросы, доступные только для отзыва.

## Этап 5: Сгенерируйте файл .docx с помощью встроенного скрипта { #phase-5-generate-docx-via-bundled-script }

```bash
node scripts/generate_reading_list.js \
  --input /tmp/syllabus_data.json \
  --output /path/to/reading_list_<course>_<date>.docx
```

Скрипт принимает JSON с этой схемой:

```json
{
  "courseTitle": "string",
  "courseSubtitle": "string",
  "generatedDate": "string",
  "yearRange": "string",
  "introText": "string",
  "learningOutcomes": ["string", ...],
  "sections": [
    {
      "heading": "string",
      "papers": [
        {
          "title": "string",
          "authors": "string",
          "journal": "string",
          "year": number,
          "url": "string",
          "summary": "string",
          "question": "string"
        }
      ]
    }
  ],
  "auditLog": {
    "totalQueriesSent": number,
    "totalPapersReceived": number,
    "totalPapersCited": number,
    "toolConstraints": "string",
    "searchDetails": [
      {
        "section": "string",
        "query": "string",
        "papersReturned": number,
        "papersSelected": number,
        "status": "string"
      }
    ],
    "failures": []
  }
}
```

Скрипт обрабатывает:
- `docx` требуется пакет с резервным вариантом для нескольких местоположений
- Титульный лист, введение со ссылкой на консенсус, поле результатов обучения, пронумерованные статьи по разделам
- `ExternalHyperlink` с полными согласованными URL-адресами (никогда не усекаемыми)
- `LevelFormat.BULLET` для списков (не маркеров в юникоде)
- Нижний колонтитул с метаданными генерации
- Проверка ввода (пропущенные поля → корректная ошибка)

Видишь [`references/bundled_script_pattern.md`](references/bundled_script_pattern.md) за то, почему в комплекте против встроенного.

## Этап 6: Доставка { #phase-6-deliver }

- Путь к файлу
- Сводка аудита в чате: "Сохранено {file}. {N} секции × {M} документы / {K} цитируется. Уровень плана: {tier}."
- Проверка: проверьте целостность почтового индекса с помощью `python3 -c "import zipfile,sys; zipfile.ZipFile(sys.argv[1]).testzip()" <docx>` (нет выходных данных = не поврежден), затем подтвердите наличие требуемых разделов

## Обработка ошибок { #error-handling }

| Неудача | Поведение |
|---|---|
| Достижение консенсус-лимита по ставке | Подождите 3 секунды, повторите попытку один раз, войдите в систему |
| Поиск возвращает 0 для раздела | Обратите внимание на раздел "ограниченные результаты — рассмотрите возможность применения добавок вручную". |
| 3 последовательных сбоя | Остановите, предупредите пользователя, поделитесь собранным к настоящему времени |
| `docx` пакет не установлен | Попытки написания сценария `npm install`; если все еще не удается, завершите работу с четким сообщением |
| Ошибка проверки DOCX | Распакуйте XML, зарегистрируйте проблему, попросите пользователя повторить попытку |
| Формат учебного плана не поддерживается | Перечислите поддерживаемые форматы, попросите пользователя преобразовать |
| Результаты обучения не могут быть извлечены | Сделайте вывод 3-5 из описания курса; отметьте, как указано в документе |

## Анти-Паттерны для отклонения { #anti-patterns-to-reject }

- Распараллеливание согласованных вызовов (ограничение скорости)
- Поиск по темам без учета прикладной области (низкая релевантность)
- Заполнение разделов сфабрикованными записями, когда консенсус возвращается тонким
- Общие вопросы для обсуждения ("Что обнаружили авторы?")
- Насыщенные жаргоном резюме, неподходящие для уровня аудитории курса
- Пропуск шага группирования и подтверждения (напрасный поиск)
- Усечение согласованных URL-адресов в гиперссылках
- Встраивание 300 строк JavaScript-кода, генерируемого docx, в тело скилла (используйте встроенный скрипт)
