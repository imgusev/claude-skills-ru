# Патент — уровень техники + Ландшафтный анализ { #patent--prior-art--landscape-intelligence }

> ** Портативность:** Требуется `web_fetch` (Google Patents, Espacenet, USPTO), `WebSearch` (смежное академическое искусство), Node.js с `docx` упаковка и опционально Lens.org API-ключ для сигналов citation-graph. Изначально работает в Claude Code CLI. В Клоде.искусственный интеллект с веб-инструментами + Выполнение кода + BYOK Lens.org , поддерживается воркфлоу.

> **Выходит за рамки:** товарный знак, авторское право, коммерческая тайна. Они помечаются при приеме. Используйте другой скилл или квалифицированного консультанта.

> ** Правовая оговорка: ** Этот скилл выдает поисковый сигнал, а не юридическую консультацию. Вердикты - это технические оценки. **Всегда консультируйтесь с патентным поверенным перед подачей заявки или принятием решения о лицензировании.**

## Нестандартное обрамление — Отличительный признак { #non-generic-framing--the-differentiator }

Этот скилл - ** уровень техники + ландшафтный интеллект**. Это ** отказывается быть ведром**. Каждый вызов привязывается к одному из пяти вариантов использования с помощью grill-me перед запуском любого поиска. Выбранный вариант использования определяет всю стратегию поиска, эвристику ранжирования и акцент на DOCX.

| Вспомогательный вариант использования | Стратегия поиска | Акцент в DOCX |
|---|---|---|
| **Поиск новинок** | Узкие + претензии - ориентированы на текст; дата предварительной подачи не имеет значения | Самое близкое искусство + претензия-дифференциация |
| **Свобода в эксплуатации** | Только широкие + активные патенты; фильтрация по юрисдикции | Флаги FTO + риск по каждой претензии |
| **Конкурентный ландшафт** | Ширина + количество заявок + тенденции цен за клик | Карта файлов + горячие точки для инвестиций |
| **Тщательность при приобретении** | Конкретный правопреемник + объем портфолио + цепочка назначений | Таблица портфолио + подтверждение права собственности |
| **Предшествующий уровень судебного разбирательства** | Конкретный целевой патент + смежный уровень техники до даты приоритета | Выбывающие кандидаты, ранжированные по значимости |

Видишь [`references/sub_use_case_routing.md`](references/sub_use_case_routing.md) для канона.

## Правила добросовестности агента (Соглашение об исследовательском пакете) { #agent-integrity-rules-research-pack-convention }

Заблокирован дословно в соответствии с аудитом PR #657.

- ** Дисциплина выполнения.** Только вызовы последовательного поиска. ** ограничение скорости 1 запрос в секунду.** Подтвердите полученный ответ перед следующим вызовом.
- **Дисциплина источника.** Цитируйте только патенты, возвращенные вызовами инструментов этого сеанса. Учебные знания, помеченные `[Not from search — reference information]` и исключен из подсчетов.
- ** Отслеживание по трем счетам.** Отправленные запросы / полученные патенты (показаны) / процитированные патенты. Всплыло в журнале аудита.
- **Политика повторных попыток.** При сбое → подождите 3 секунды → повторите попытку один раз → войдите в систему. После 3 последовательных сбоев в работе инструментов: остановите, предупредите пользователя, объясните, чего не хватает.
- **Обнаружение на уровне плана.** Lens.org бесплатный уровень = 1000 запросов в месяц. В Google Patents нет авторизации, но есть ограничения по скорости для каждого IP-адреса. Обнаруживайте и извлекайте колпачки на поверхность.

## Фаза 1: Прием пищи на гриле (6 форсирующих вопросов, по одному за раз) { #phase-1-grill-me-intake-6-forcing-questions-one-at-a-time }

### Q1 (корень) — Описание изобретения { #q1-root--invention-description }

> **Опишите изобретение в 2-3 предложениях. Что он делает и что в нем нового?**
>
> * Почему я спрашиваю: * Определение концепции и ключевых слов полностью зависит от точного описания. Расплывчатые описания ("Искусственный интеллект для здравоохранения", "улучшенный виджет") будут отклонены — отойдите назад и попросите пользователя указать, что делает изобретение и чем оно отличается от существующих подходов.

** Откажитесь от каши. ** Если ответ общий, спросите еще раз: "Что она делает такого, чего не делают существующие системы?" Затем зафиксируйте (с оговоркой в DOCX).

### Q2 (зависит от Q1) — Обязательство по дополнительному варианту использования { #q2-depends-on-q1--sub-use-case-commitment }

> ** Какова цель этого поиска? Выбери что-нибудь одно:**
>
> 1. Поиск новизны (достаточно ли я нова для подачи заявки)
> 2. Свобода действий (подадут ли на меня в суд, если я отправлю товар)
> 3. Конкурентная среда (кто еще здесь играет)
> 4. Тщательность при приобретении (действительно ли target владеет X)
> 5. Судебный процесс по поиску предшествующего уровня техники (уничтожение конкретного патента)
>
> *Почему я спрашиваю:* Каждый путь использует принципиально иную стратегию поиска. Я ** откажусь начинать, пока ты не выберешь что-нибудь одно**.

Принудительный формат. Если пользователь говорит "все из них", нажмите для основной цели — второстепенные цели могут выполняться в качестве последующего поиска.

### Q3 (спрашивается только в том случае, если Q2 ∈ {FTO, landscape, diligence}) — Юрисдикции { #q3-asked-only-if-q2--fto-landscape-diligence--jurisdictions }

> **Какие юрисдикции имеют значение? Выберите все, что применимо: US / EP / CN / JP / KR / PCT / worldwide.**
>
> * Почему я спрашиваю: * Важно только то, где вы будете продавать. Ландшафт радикально меняется в зависимости от региона. Тщательность требует проверки всех юрисдикций, в которых осуществляет свою деятельность цель.

Пропустите новизну (дата приоритета переносима с точки зрения юрисдикции) и судебный процесс (юрисдикция определяется целевым патентом).

### Q4 (зависит от Q1) — Известный уровень техники { #q4-depends-on-q1--known-prior-art }

> ** Вы уже сталкивались с известным уровнем техники, близким к этому? Укажите номер патента или статьи.**
>
> *Почему я спрашиваю:* Если вы знаете одно произведение искусства, я могу поискать рядом с ним — гораздо точнее, чем начинать с нуля. Если вы этого не сделаете, все в порядке — просто подтвердите.

Закрепление на якоре. Примите "нет", но спросите, видел ли пользователь *какую-либо* связанную с этим работу, даже неофициально.

### Q5 (зависит от Q2) — Толерантность к риску { #q5-depends-on-q2--risk-tolerance }

> ** Допустимый риск для этого поиска: строгий (одно близкое попадание означает отказ от пути) или сбор сигналов (вы хотите получить информацию о местности в любом случае)?**
>
> *Почему я спрашиваю:* Строгий режим агрессивно ранжирует и позволяет получать вердиктные хиты; сигнальный режим отдает приоритет широте и визуализации.

Просили о новизне и FTO; пропустили из-за чистого ландшафта (по определению, всегда собирающий сигнал).

### Q6 (спрашивается только в том случае, если Q2 ∈ {novelty, FTO}) — Статус адвоката { #q6-asked-only-if-q2--novelty-fto--attorney-status }

> ** Разговаривали ли вы с патентным поверенным? Этот скилл дает поисковый сигнал, а не юридическую консультацию. Подтвердите, что вы понимаете, что это только для технической оценки.**
>
> *Почему я спрашиваю:* Новизна и FTO имеют юридические последствия. Вердикт скилл - оценочный; юридические позиции требуют квалифицированного адвоката.

** Триггеры нижнего колонтитула с юридическим отказом от ответственности в DOCX.** Пропущено из-за ландшафта и тщательности (меньший юридический риск).

** Условие остановки:** После Q6 (или ранее, если применены пропуски зависимостей) зафиксируйте и запустите фазу 2. Никогда не открывайте прием после начала фазы 2.

## Этап 2: Выбор стратегии поиска { #phase-2-search-strategy-selection }

Детерминированный на основе полученных ответов. Использование `scripts/sub_use_case_router.py`:

```bash
python scripts/sub_use_case_router.py \
  --sub-use-case novelty \
  --jurisdictions "" \
  --risk strict \
  --known-art "US10000000B2"
```

Возвращает: план запроса (5-8 запросов) + эвристика ранжирования + флаги выделения в DOCX.

## Фаза 3: Поиск по нескольким источникам (последовательный) { #phase-3-multi-source-search-sequential }

### Приоритет источника { #source-priority }

1. **Патенты Google** (https://patents.google.com) — рабочая лошадка, авторизация не требуется, широкий охват
2. **Espacenet** (https://worldwide.espacenet.com) — глобальный охват, подходит для искусства за пределами США
3. **PPS USPTO** (https://ppubs.uspto.gov) — Глубокое погружение в США
4. **Lens.org ** (https://www.lens.org) — график цитирования, требуется ключ API BYOK

### Шаблоны запросов для каждого варианта использования { #per-sub-use-case-query-patterns }

**Новизна:**
- 3 узких запроса по терминологии, относящейся к конкретным изобретениям (Google Patents)
- 2 общих концептуальных запроса с синонимами (Google Patents + Espacenet)
- 1 Запрос с ограничением по классу CPC, если класс идентифицирован по первоначальным обращениям

**FTO:**
- Юрисдикция-отфильтрована: только активные патенты (не просроченные, не отмененные)
- Фильтр по дате: приоритет < сегодня
- Активный-извлечение текста заявки для каждого попадания

**Конкурентный ландшафт:**
- Более широкие запросы в области технологий
- Идентификация класса CPC → подсчитать лучшие файлы в этом классе
- тенденция подачи заявок за 10 лет по годам в расчете на одного из топ-5 заявителей

**Тщательность при приобретении:**
- Поиск конкретных правопреемников (целевая компания + дочерние компании + названные изобретатели)
- Проверка цепочки назначений (регистрация назначений USPTO)
- Разрешение семейства для дедупликации

**Предшествующий уровень судебного разбирательства:**
- Требуемый ввод целевого патента (количество)
- Извлечение даты приоритета
- Поиск произведений искусства до даты приоритета в тех же классах CPC
- Поиск по смежным заявкам на языке

### Последовательная дисциплина { #sequential-discipline }

1 q/сек по ВСЕМ источникам вместе взятым. Отслеживается с помощью `scripts/citation_tracker.py` с пробелом, обусловленным временной меткой.

## Этап 4: Извлечение заявки + Оценка релевантности { #phase-4-claim-extraction--relevance-scoring }

За каждый самый близкий арт-хит:
- Вытягивание ** независимая претензия 1** (самая широкая претензия — основное средство предвосхищения/очевидности)
- Извлекать ** ключевые зависимые формулы изобретения** (формулы, которые добавляют изобретательский уровень)
- Оценка релевантности по сравнению с описанием изобретения (совпадение формулировки формулы изобретения с терминологией Q1)

Ранжируйте по баллам. Вердикт по каждому варианту использования (НОВЫЙ / ПОТЕНЦИАЛЬНО НОВЫЙ / НЕ НОВЫЙ для новизны; ЯВНЫЙ / ПОМЕЧЕННЫЙ / ВЫСОКИЙ РИСК в зависимости от юрисдикции для FTO).

## Этап 5: График цитирования + Разрешение семейства { #phase-5-citation-graph--family-resolution }

### График цитирования (Lens.org БЕК) { #citation-graph-lensorg-byok }

Если пользователь предоставляет Lens.org Ключ API:
- Идентификация основополагающего патента (количество цитируемых > пороговое значение, обычно 50+)
- Недавние сигналы с высоким процентом цитирования (количество цитирований за последние 24 месяца в качестве показателя текущей активности)
- Прямые ссылки на целевой патент (предшествующий уровень техники для судебного разбирательства) или на ближайший уровень техники (новинка)

Если нет Lens.org ключ: пропустить; отметить в журнале аудита; рекомендовать ревью цитирования вручную в Google Patents.

### Разрешение семейных проблем { #family-resolution }

Одно и то же изобретение часто подается в нескольких юрисдикциях (US + EP + JP + CN). Сгруппируйте по семейному идентификатору или номеру приоритета, чтобы избежать двойного подсчета. Использование `scripts/family_resolver.py`:

```bash
python scripts/family_resolver.py --hits-file hits.json
# Returns: deduplicated family list + family-member jurisdictions
```

## Осведомленность о классификации CPC/IPC { #cpcipc-classification-awareness }

** Критично:** поиск по ключевым словам сам по себе пропускает смежные произведения искусства. После первоначального поиска извлеките классы CPC/IPC из 5 лучших обращений и запустите ** один запрос с ограничением по классу**. Это постоянно выводит на поверхность произведения искусства, которые упускаются при поиске по ключевым словам.

Видишь [`references/cpc_classification_canon.md`](references/cpc_classification_canon.md) для канона.

## Этап 6: Генерация DOCX (8 разделов) { #phase-6-docx-generation-8-sections }

Акцент, зависящий от варианта использования. Через Node.js + `docx` библиотека.

1. ** Краткое изложение + вердикт ** — Баннер с описанием варианта использования + вердикт в одну строку (НОВЫЙ / ПОМЕЧЕННЫЙ / и т.д.) + 3-4 ключевых вывода + нижний колонтитул с юридическим отказом от ответственности.
2. **Ближайший уровень техники** — 5-10 патентов в ранжированном порядке. За попадание: название с гиперссылкой + правопреемник + даты подачи/приоритета + текст независимой заявки 1 (выделен курсивом) + оценка релевантности + обоснование релевантности (1-2 предложения)
3. ** Патентный ландшафт** — Таблица лучших заявителей (топ-10 по количеству) + описание тенденции подачи заявок за 10 лет + таблица распределения классов CPC. Только для ландшафта и усердия; сокращенно иначе.
4. ** Сигналы графика цитирования ** — Основополагающие патенты (если включена функция Lens) + недавняя активность с высоким процентом цитирования. Если объектив недоступен, обратите внимание на "рекомендуется провести ревью вручную" и пропустите таблицу.
5. ** Географический охват** — Заявки по юрисдикциям для топ-10 обращений. Только для FTO, ландшафта, усердия; пропущено из-за новизны и судебных разбирательств.
6. **Флаги FTO** (только для FTO) — активные патенты, представляющие риск нарушения. Для каждого флага: патент с гиперссылкой + юрисдикция + соответствующие претензии + уровень риска (ВЫСОКИЙ/СРЕДНИЙ/НИЗКИЙ) + примечание по смягчению последствий.
7. **Стратегия + рекомендации** — для конкретного случая использования:
   - Новизна → предложения по дифференциации требований
   - FTO → подсказки по дизайну + стратегия юрисдикции
   - Пейзаж → список тех, за кем нужно следить
   - Усердие → красные флажки в портфолио
   - Судебный процесс → ранжированные кандидаты на выбывание
   - ** Обязательное заявление об отказе от ответственности для консультации с патентным поверенным ** при принятии любого решения о подаче заявки / лицензировании.
8. ** Журнал аудита** — Таблица поиска (#, запрос, источник, результаты, статус), подсчеты (отправлено / показано / процитировано), ограничения инструмента (примечания уровня плана), невыполненные шаги, напоминание о консультации с адвокатом

### Укладка { #styling }

Текст Arial 12pt, темно-синие заголовки (#1a3a5c), светло-синие заголовки таблиц (#e8f0f8), красная выноска флага FTO. `ExternalHyperlink` узоры:
- Патенты Google: `https://patents.google.com/patent/[number]`
- Эспасенет: `https://worldwide.espacenet.com/patent/...`
- USPTO: `https://patents.uspto.gov/patent/...`

## Дисциплина свиданий { #date-discipline }

Различать при каждом попадании:
- **Дата подачи заявки** — когда заявка была впервые подана
- **Дата приоритета** — самое раннее требование о приоритете (часто до подачи заявки)
- **Дата публикации** — когда заявка стала общедоступной (обычно через 18 месяцев после получения приоритета)
- **Дата выдачи** — когда был выдан патент (позднее публикации)

Укажите **юридически значимую дату** для каждого варианта использования:
- Новизна → дата приоритета (в сравнении с предполагаемой датой подачи заявки на изобретение)
- FTO → дата предоставления + статус (активен или истек)
- Ландшафт → дата публикации (когда началось обнародование)
- Проверка → дата предоставления + дата назначения
- Судебный процесс → дата приоритета целевого патента (устанавливает предельный уровень техники)

## Этап 7: Доставка { #phase-7-deliver }

- Сохранить: `<output-dir>/patent_<invention-slug>_<sub-use-case>_<YYYY-MM-DD>.docx`
- Краткое описание чата: путь к файлу + вариант дополнительного использования + вердикт + количество аудитов + уровень плана
- Проверка: проверьте целостность почтового индекса с помощью `python3 -c "import zipfile,sys; zipfile.ZipFile(sys.argv[1]).testzip()" <docx>` (нет выходных данных = не поврежден), затем подтвердите наличие требуемых разделов
- Напоминание: "Проконсультируйтесь с патентным поверенным перед подачей заявки /лицензированием".

## Обработка ошибок { #error-handling }

| Неудача | Поведение |
|---|---|
| Пользователь отказывается переходить к дополнительному варианту использования | Отказываюсь продолжать. Повторно задайте вопрос 2 с примерами. |
| Описание изобретения является общим | Отклонить ответ. Повторно задайте вопрос 1: "Что он делает такого, чего не делают существующие системы?" |
| Ограничения по ставкам патентов Google | Подождите 3 секунды, повторите попытку один раз. Вернитесь к Espacenet для этого запроса. Войдите в систему аудита. |
| Lens.org ключ пропал | Пропустите раздел "График цитирования", обратите внимание на "рекомендуется провести ревью вручную" в DOCX. |
| Не удается извлечь текст заявки | Вернитесь к абстрактному; отметьте как "только для абстрактного" в обосновании релевантности. |
| Неполное разрешение семейных проблем | Примечание при аудите; могут появиться дубликаты одного и того же изобретения; рекомендуется выполнить дедупликацию вручную. |
| Все запросы возвращают <3 совпадений | Выставляйте явно как "либо нишевое искусство, либо подлинный пробел"; никогда не выдумывайте. |
| 3 последовательных отказа инструмента | Остановите, предупредите пользователя, объясните, чего не хватает. |
| Сбой генерации DOCX | Сохраните необработанные данные в виде резервного файла JSON, чтобы пользователь не потерял работу. |
| Номер целевого патента недействителен (судебный процесс) | Проверьте формат перед поиском; попросите пользователя подтвердить. |

## Анти-Паттерны для отклонения { #anti-patterns-to-reject }

- Запуск любого поиска до того, как пользователь перейдет к дополнительному варианту использования (отказывается от общей "справки по патенту")
- Группирование всех вопросов о приеме вместо того, чтобы задавать их по одному за раз
- Принятие расплывчатых описаний изобретений ("Искусственный интеллект для здравоохранения")
- Поиск только по ключевым словам без отслеживания класса CPC/IPC
- Обработка членов семьи как отдельных обращений (должна быть дедуплицирована)
- Путают дату подачи заявки с датой приоритета и датой публикации
- Пропуск юридического заявления об отказе от ответственности, когда дополнительный вариант использования имеет юридические последствия
- Сообщение о вердикте без претензий-текстовые доказательства
- Изготовление Lens.org данные о цитировании при отсутствии ключа
- Предложение обходных путей без подтверждения необходимости ревью адвоката
- Пропуск журнала аудита
