# Досье — Исследование объектов на уровне принятия решений { #dossier--decision-grade-entity-research }

> ** Портативность:** Требуется `WebSearch` + `WebFetch`, Node.js с `docx` упаковка и опционально `bash_tool` + `curl` для бесплатных API (SEC EDGAR, GitHub, ProPublica). BYOK MCPS (LinkedIn, Crunchbase, Apollo, Pitchbook, SimilarWeb) являются дополнительными улучшениями. Изначально работает в Claude Code CLI.

## Нестандартное обрамление — Отличительный признак { #non-generic-framing--the-differentiator }

Этот скилл заключается в ** исследовании сущностей на уровне принятия решений с проверкой гипотез**. Это ** отказывается** быть "расскажите мне о Microsoft". Каждый вызов вынуждает пользователя заранее раскрывать свою гипотезу (Q4), поэтому досье скорее * проверяет* ее, чем подтверждает.

Форма варианта использования:

> "Во вторник я выступаю с презентацией Microsoft. Моя гипотеза заключается в том, что они консолидируют расходы на искусственный интеллект на своей собственной платформе Foundry. Подтвердите или опровергните и дайте мне три зацепки для разговора, привязанные к тому, что вы найдете".

**НЕ:**

> - Расскажи мне о "Майкрософт".

Вынуждающий Q4 — вопрос о гипотезе — является неродовым якорем. Пропустите это, и скилл выдаст краткое описание из Википедии.

Видишь [`references/hypothesis_testing_discipline.md`](references/hypothesis_testing_discipline.md) для канона.

## Правила добросовестности агента (Соглашение об исследовательском пакете) { #agent-integrity-rules-research-pack-convention }

Заблокирован дословно в соответствии с аудитом PR #657.

- ** Дисциплина выполнения.** Последовательные поисковые вызовы. WebSearch + WebFetch имеют более низкие ограничения по ставкам, чем консенсус, но по-прежнему применяются 1 q/sec этикет. Подтвердите полученный ответ перед следующим вызовом.
- **Дисциплина источника.** Цитируйте только источники, возвращаемые вызовами инструментов этого сеанса. Википедия / учебные знания с пометкой `[Background — verify before quoting]` и исключен из подсчета первичных результатов.
- ** Отслеживание по трем счетам.** Отправленные запросы / полученные источники / цитируемые источники. Плюс ** разбивка по уровням** (первичный / вторичный / третичный), уникальная для досье. Всплыло в журнале аудита.
- **Политика повторных попыток.** При сбое → подождите 3 секунды → повторите попытку один раз → войдите в систему. После 3 последовательных сбоев: остановитесь, предупредите пользователя.
- ** Уровень надежности источника.** Каждая цитата помечена как первичная (официальная, SEC, судебные протоколы) / вторичная (основные новости, отраслевая пресса) / третичная (блоги, форумы). DOCX отображает уровень на каждом флаге.

## Фаза 1: Прием пищи на гриле (6 форсирующих вопросов, по одному за раз) { #phase-1-grill-me-intake-6-forcing-questions-one-at-a-time }

### Q1 (root) — Идентификатор субъекта { #q1-root--subject-identity }

> ** Кто является объектом исследования? Дайте мне точное название и, если это компания, веб-сайт или URL-адрес LinkedIn. Если это человек, укажите его URL-адрес в LinkedIn или уникальный идентификатор (принадлежность к компании + роль).**
>
> * Почему я спрашиваю: * Устранение неоднозначности. Всего насчитывается 47 Джонов Смитов. Есть три компании под названием "Атлас". Мне нужна конкретная сущность для исследования.

Если пользователь вводит только имя, введите второй идентификатор. **Отказывайтесь использовать двусмысленные имена.**

### Q2 (зависит от Q1) — Тип темы { #q2-depends-on-q1--subject-type }

> ** Что это за предмет такой? Выберите что-нибудь одно: физическое лицо / компания / некоммерческая организация / правительственная организация / другое.**
>
> *Почему я спрашиваю:* Применяются различные исходные матрицы. Для людей я проверяю LinkedIn, GitHub, Scholar, news; для компаний я проверяю SEC EDGAR (если общедоступный), Crunchbase, news, GitHub для технических организаций; для некоммерческих организаций я проверяю форму 990s на ProPublica.

Вынуждающий выбор. "Другое" требует однострочного описания.

### Q3 (зависит от Q2) — Назначение { #q3-depends-on-q2--purpose }

> ** К чему вы готовитесь? Выбери что-нибудь одно:**
>
> 1. Встреча по продажам / предложение о партнерстве
> 2. Инвестиционная осмотрительность
> 3. Тщательность при приобретении
> 4. Журналистика / должная осмотрительность
> 5. Подготовка к собеседованию при приеме на работу
> 6. Конкурентная разведка
> 7. Личная проверка (дата, наем, деловой партнер)
> 8. Другое (указать)
>
> *Почему я спрашиваю:* Цель диктует угол обзора, глубину и чувствительность "красного флажка". Для подготовки к продажам нужны зацепки для разговора. Инвестиционная осмотрительность нуждается в сигналах тяги. Личная проверка требует четких границ чувствительности.

### Q4 (зависит от Q3) — **Гипотеза — ОБЯЗАТЕЛЬНА** { #q4-depends-on-q3--hypothesis--mandatory }

> ** В чем заключается ваша гипотеза? Во что вы уже верите по этому поводу, и что вы хотите проверить или опровергнуть?**
>
> *Почему я спрашиваю:* Это важнейший вопрос. Досье, которое просто подтверждает то, что вы уже считаете бесполезным. Изложив вашу гипотезу заранее, я могу найти доказательства, которые могли бы ее *опровергнуть*, а также доказательства, подтверждающие ее, — и вынести вам вердикт, который вы действительно можете использовать.
>
> Примеры:
> - "Я полагаю, что Microsoft консолидирует расходы на искусственный интеллект в литейном производстве первой партии. Подтвердите или опровергните."
> - "Я думаю, что генеральный директор не в себе — слишком много болтовни, никакой тяги. Проверь это."
> - "Я считаю, что соотношение накладных расходов этой некоммерческой организации является приблизительным. Проверь 990-е годы."
> - "Я думаю, что этот человек достаточно техничен, чтобы справиться с ролью технического директора. Проверьте."

** ОБЯЗАТЕЛЬНО.** Если пользователь говорит "У меня его нет", нажмите "Назад" ** один раз **: "Тогда угадайте. Зафиксируйте позицию, которую вы сможете обновить позже. Досье нуждается в проверке гипотезы, в противном случае это общий профиль, который не поможет вам принять решение."

Если все еще отказывают: вернитесь к имплицитной гипотезе "что самое удивительное, что я смог найти?" и ** отметьте резервный вариант в журнале аудита**.

Этот вопрос является ** неродовым якорем **. Пропустите это, и скилл станет кратким описанием в Википедии.

### Q5 (зависит от Q3) — Глубина { #q5-depends-on-q3--depth }

> **Временной интервал: 5-минутное краткое изложение или 15-минутное досье для принятия решения?**
>
> * Почему я спрашиваю: * Краткий режим ограничивает ~ 10 поисков и пропускает пропуски сети + репутации. Оценка принятия решения углубляется в каждом разделе. Выбирайте в зависимости от того, сколько кожи у вас есть в этом решении.

Вынуждающий выбор.

### Q6 (спрашивается только в том случае, если Q3 ∈ {journalism, personal vetting}) — Чувствительность { #q6-asked-only-if-q3--journalism-personal-vetting--sensitivities }

> ** Что-нибудь конфиденциальное, что следует исключить? Например, личные медицинские данные, семейные подробности, политическая история или конкретные темы, которые запрещены к обсуждению?**
>
> * Почему я спрашиваю: * В некоторых исследовательских контекстах существуют этические ограничения. Я предпочел бы знать заранее, чем раскрывать то, чем ты никогда не поделишься.

Пропустить распродажи/investment/acquisition/competitive информация (низкая чувствительность); спросите о журналистике/personal проверка (высокая чувствительность).

** Условие остановки:** После Q6 (или ранее с пропусками зависимостей) зафиксируйте и запустите фазу 2. Никогда повторно не открывайте прием после начала фазы 2.

## Этап 2: Устранение неоднозначности темы { #phase-2-subject-disambiguation }

Перед этапом 3 передайте вопрос конкретному объекту:

- Для людей: подтвердите URL LinkedIn ИЛИ (работодатель + должность + город)
- Для компаний: подтвердите домен ИЛИ (юридическое название + юрисдикция регистрации)

Если после отката Q1 все еще остается неоднозначность: ** остановитесь и повторно задайте Q1** с идентификаторами, устраняющими неоднозначность. Отказываюсь продолжать.

## Фаза 4: Поиск на основе гипотез { #phase-4-hypothesis-driven-search }

Каждый поиск на этапе 4 ДОЛЖЕН быть классифицирован как либо:

- **Подтверждающие доказательства** (подтверждают гипотезу), ИЛИ
- **Неподтверждающие доказательства** (опровергли бы гипотезу)

**≥30% поискового бюджета выделяется на неподтверждающие запросы.** Принудительный с помощью `scripts/disconfirming_evidence_balance.py`.

Пример для гипотезы "Microsoft консолидирует расходы на ИИ в литейном производстве":

- **Поддержка:** "Внедрение Microsoft Foundry 2026", "Консолидация инфраструктуры искусственного интеллекта Microsoft"
- ** Опровержение:** "Пересмотр условий сделки Microsoft OpenAI", "Диверсификация поставщиков искусственного интеллекта Microsoft", "Модель партнерства сторонних разработчиков Microsoft 2026"

Это то, что делает досье ** ориентированным на принятие решения**, а не на подтверждение.

Для каждого поиска:
- Запись через `citation_tracker.py` с классификацией (подтверждающей/опровергающий)
- Применить исходный уровень из `source_tier_classifier.py` к каждому результирующему URL-адресу

## Этап 5: График мероприятий на 12 месяцев { #phase-5-12-month-activity-timeline }

12-месячное окно по умолчанию для временной шкалы активности; более глубокое для основополагающей идентичности.

Категории:
- Новости (приобретения, наем сотрудников, увольнения, запуск продуктов)
- Раунды финансирования / финансовые мероприятия
- Споры / юридические события
- Публичные заявления / изменения в стратегии

Обратная хронология. Каждая запись снабжена гиперссылками + многоуровневая.

## Фаза 6: Сеть + сигналы репутации { #phase-6-network--reputation-signals }

### Сеть { #network }

- **Компании:** инвесторы (в/out), клиенты (названные), партнеры
- **Люди:** соучредители, консультанты, наставники, работодатели, роли в совете директоров
- **Некоммерческие организации:** спонсоры, правление, руководство

5-10 записей, ранжированных по ** значимости для гипотезы**.

### Репутация { #reputation }

- Настроения на основе новостей (за последние 12 месяцев)
- Стеклянная дверь для компаний (общий рейтинг + 3 типичных ревью)
- Упоминания коллег для людей
- Предостережение: данные о репутации зашумлены; уровень соответственно

## Фаза 7: Пропуск с красным флагом { #phase-7-red-flag-pass }

Всплывайте, но не делайте сенсаций:

- Судебный процесс (судебные протоколы → первичный уровень)
- Регулирующие действия (SEC, Министерство юстиции, действия агентства → первичные)
- Необычные увольнения (увольнения ключевого персонала в течение 90 дней)
- Финансовые сигналы (примечания о продолжающейся деятельности в 10-Ks → первичные)
- Ухудшение репутации (устойчивое негативное освещение → вторичное)

** Каждый флаг многоуровневый.** Уровень отображается рядом с каждым флагом в DOCX.

## Фаза 8: Генерация зацепки для разговора { #phase-8-conversation-hook-generation }

3-5 конкретных зацепок, привязанных к ** фактическим выводам **, а не к общим тезисам.

Видишь [`references/conversation_hook_quality.md`](references/conversation_hook_quality.md) для канона.

| ❌ Универсальный | ✅ Поиск-связанный |
|---|---|
| "Спросите об их дорожной карте" | "Упомяните об их недавнем приобретении [X] — это сигнализирует о том, что они инвестируют в вертикаль Y. Предлагаемое обрамление: "Увидел [X] объявление — как это изменит вашу дорожную карту на Y?" |
| "Спросите о приеме на работу" | "Их вице-президент по инженерным вопросам уволился 3 недели назад (LinkedIn). Предлагаемое обрамление: "Я заметил [имя] двинулись дальше — каков план руководства eng?" |
| "Расскажите об их ценностях" | "На прошлой неделе они обновили свою страницу с ценами (их официальный сайт). Предлагаемая формулировка: "Увидел обновление цен — что послужило причиной этого?"" |

Каждый крючок:
- **Крючок** (одно предложение)
- ** Поиск, к которому он привязан** (с гиперссылкой + уровень)
- ** Предлагаемое обрамление ** (пользователь может адаптировать дословную формулировку)

## Этап 9: Генерация DOCX (9 разделов) { #phase-9-docx-generation-9-sections }

Через Node.js + `docx` библиотека.

1. ** Краткое содержание ** — один абзац: кто они такие + почему они важны + ** вердикт по гипотезе ** (ПОДДЕРЖИВАЕТСЯ / ЧАСТИЧНО ПОДДЕРЖИВАЕТСЯ / ОПРОВЕРГНУТО / НЕУБЕДИТЕЛЬНО) + 3 пункта, которые вам следует знать.
2. **Таблица идентификационных данных** — основана/born, местоположение, размер/stage, текущая роль, ключевые связи. Все ячейки получены из источника; наведение курсора - текстовый уровень.
3. **Проверка гипотезы** — гипотеза пользователя, изложенная дословно. Подтверждающие доказательства (3-5 абзацев с цитатами с гиперссылками). Опровергающие доказательства (3-5 абзацев с цитатами с гиперссылками). Абзац вердикта (2-3 предложения с объяснением веса).
4. ** График деятельности за 12 месяцев ** — Новости, финансирование, наем сотрудников, увольнения, запуск продуктов, споры. Обратная хронология. Каждая запись снабжена гиперссылкой.
5. **Сетевые сигналы** — Сотрудники / инвесторы / партнеры. 5-10 записей, ранжированных по степени соответствия гипотезе.
6. ** Сигналы репутации ** — Настроения из новостей, Glassdoor для компаний, упоминания среди коллег для людей. Предостережение: данные о репутации зашумлены.
7. ** Красные флажки + Скрытые закономерности** — Судебные разбирательства, действия регулирующих органов, необычные отклонения, финансовые сигналы, ухудшение репутации. Многоуровневый.
8. ** Зацепки для разговора ** — 3-5 конкретных зацепок, привязанных к выводам. Каждый: крючок + поиск + предлагаемое обрамление.
9. ** Источник происхождения + журнал аудита** — Список источников с указанием уровня. Сводная таблица поиска (#, запрос, классификация, возвращаемые источники, цитируемые источники). Три подсчета + подсчет по уровням. Неудачные поиски. Флаг использования BYOK-MCP.

## Обработка ошибок { #error-handling }

| Неудача | Поведение |
|---|---|
| Неоднозначное название темы | Отказываюсь продолжать. Повторно задайте вопрос Q1 с идентификатором, устраняющим неоднозначность. |
| Пользователь отказывается излагать гипотезу | Оттолкнись один раз. Если вам все еще отказывают, вернитесь к вопросу: "Что самое удивительное, что я смог найти?" неявная гипотеза. Отметьте в аудите. |
| Тема не имеет никакого общественного влияния | Поверхность явно. Предложите другое название или раннюю стадию. Не выдумывай. |
| LinkedIn scrape заблокирован | Обратите внимание в аудите; вернитесь к веб-поиску; предложите пользователю выполнить проверку вручную. |
| СЕК ЭДГАР терпит неудачу | Повторите попытку один раз. Если по-прежнему не удается, отметьте "общедоступные заявки не получены" и продолжайте. |
| Данные о настроениях скудны | Отметьте раздел репутации как "ограниченный публичный сигнал"; не делайте выводов на основе обучения. |
| Чувствительные тематические поверхности (исключение Q6) | Исключить из DOCX. Отметьте в чате (не в DOCX), чтобы пользователь знал, что исключение было выполнено. |
| 3 последовательных отказа инструмента | Остановите, предупредите пользователя, поделитесь собранным к настоящему времени. |
| Сбой генерации DOCX | Сохраните необработанные данные в виде резервного файла JSON. |

## Анти-Паттерны для отклонения { #anti-patterns-to-reject }

- Создание досье без выдвижения гипотезы Q4
- Выделение <30% бюджета поиска на неподтверждающие доказательства
- Вопросы о дозированном приеме
- Прием неоднозначных имен объектов
- Общие зацепки для разговора ("спросите об их дорожной карте")
- Сенсационные красные флажки (расставляйте их в ряд, не редактируйте)
- Пропуск уровня надежности источника для флагов
- Создание покрытия, когда LinkedIn или scraping заблокированы
- Использование данных BYOK-MCP без пометки в журнале аудита
- Включая конфиденциальные темы, исключенные пользователем в 6 квартале
- Подтверждение -предвзятый вердикт ("ПОДДЕРЖАННЫЙ" без привлечения опровергающих доказательств)
