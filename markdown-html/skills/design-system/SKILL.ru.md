# Система проектирования — Онбординг + Общие токены бренда { #design-system--onboarding--shared-brand-tokens }

Скилл системы проектирования является **общим владельцем бренда** для плагина Markdown-HTML. Запустите его онбординг один раз. Каждый конвертер (`md-document`, `md-review`, `md-slides`) считывает результирующую конфигурацию с помощью `config_loader.py` и применяет те же 12 пользовательских свойств CSS к своим выводам. Без этого преобразования отображаются с использованием значений по умолчанию для заполнителей — технически функциональных, но не брендированных.

Этот скилл включает в себя ровно три инструмента Python:

1. **`onboard.py`** — интерактивный (или `--defaults` / `--set` / `--show` / `--reset`) волшебник.
2. **`config_loader.py`** — импортируемый загрузчик настроек с приоритетом project > global > defaults и `MARKDOWN_HTML_NO_CONFIG=1` обход.
3. **`brand_palette_validator.py`** — Средство проверки контрастности WCAG-AA + средство получения палитры HSL.

Все три доступны только для stdlib и не содержат вызовов LLM (детерминированы для каждой дисциплины Path-B).

## Когда вызывать { #when-to-invoke }

| Симптом | Действие |
|---|---|
| Пользователь говорит "преобразовать этот Markdown в HTML" впервые в этой рабочей области | Бежать `python3 markdown-html/skills/design-system/scripts/onboard.py` |
| `~/.config/markdown-html/design-system.json` не существует ИЛИ `setup_completed_at` равно нулю | Переработка отходов, поверхностный онбординг |
| Пользователь хочет переопределить бренд для каждого репозитория | `python3 .../onboard.py --scope project` |
| Пользователь хочет изменить одно поле неинтерактивно | `python3 .../onboard.py --set brand.primary=#FF6B35` |
| Пользователь хочет сбросить и повторно включить онбординг | `python3 .../onboard.py --reset` затем запустите повторно |
| Пользователь хочет использовать настройки по умолчанию с нулевым касанием (CI, эфемерный сеанс) | `python3 .../onboard.py --defaults` |
| Запуск без головы / в контейнере, который должен игнорировать сохраненную конфигурацию | `MARKDOWN_HTML_NO_CONFIG=1 ...` |

## Набор вопросов для онбординга (10 вопросов) { #onboarding-question-set-10-questions }

| # | Ключ | Выбор / Валидатор | Значение по умолчанию |
|---|---|---|---|
| 1 | `default_output_dir` | путь; `os.access(parent, os.W_OK)` | `./markdown-html-out/` |
| 2 | `brand.primary` | ШЕСТИГРАННИК `^#?[0-9a-fA-F]{6}$` | `#0A1628` |
| 3 | `brand.accent` | Шестнадцатеричный или пустой (автоматическое получение) | производный от первичного |
| 4 | `typography.heading_font` | Название шрифта Google (12 безопасных значений по умолчанию) | `Inter` |
| 5 | `typography.body_font` | Название шрифта Google | `Inter` |
| 6 | `design_style` | `editorial / technical / minimal / playful` | `technical` |
| 7 | `code_theme` | `light / dark / auto` | `auto` |
| 8 | `toc.behavior` | `sticky-sidebar / collapsible-top / inline / none` | `sticky-sidebar` |
| 9 | `company_name` | строка (может быть пустой) | `""` |
| 10 | `logo_url` | URL-адрес или пустой (base64-встроен при рендеринге) | `""` |

## Жесткие правила { #hard-rules }

1. **Должен соблюдаться контраст основного текста WCAG AA.** `brand_palette_validator.validate()` запускается после каждого изменения. Основной текст в bg должен составлять 4,5:1; ссылка в bg должна составлять 4,5:1. Если ни один из них не сработает, `onboard.py` отказывается сохранять (код выхода 4) и предлагает пользователю выбрать более темный основной, пустой `brand.bg`/`brand.text` чтобы позволить деривации выбрать безопасную пару или переопределить `brand.text` напрямую. Канон: WCAG 2.2 §1.4.3.
2. **Выходной каталог должен быть доступен для записи.** `onboard.py` проходит по пути, чтобы найти существующего предка, и проверяет `os.W_OK`. Пустой или недоступный для записи путь → код выхода 3. Работа оркестратора `output_path_resolver.py` соблюдает одно и то же правило при каждом преобразовании.
3. ** Кастомизация должна изменять поведение, а не служить украшением.** Каждый пользователь (md-документ, md-ревью, md-слайды) должен прочитать конфигурацию и выполнить рендеринг по-другому при изменении пользователем `design_style`, `brand.primary`, `code_theme`, или `toc.behavior`. Поля, предназначенные только для оформления, не соответствуют требованиям к дизайну.
4. **Приоритет исправлен.** Проект > глобальный > значения по умолчанию. Глубокое слияние сохраняет вложенные ключи (например, вы можете переопределить `brand.primary` в конфигурации проекта без потери `typography.heading_font` из глобального).
5. **Обходной env существует не просто так.** `MARKDOWN_HTML_NO_CONFIG=1` предназначен для безголового CI, эфемерных тестовых контейнеров и циклов вычислителя в стиле автоматического поиска. Никогда не устанавливайте его автоматически для интерактивного пользователя.

## Производная палитра из 12 токенов { #derived-12-token-palette }

Как только бренд пользователя будет захвачен, `brand_palette_validator.derive_palette()` создает 12 пользовательских свойств CSS, хранящихся в `derived_palette` в том же конфигурационном файле. Каждый конвертер встраивает их в свой `<style>` блок.

| Токен | Цель | Вывод |
|---|---|---|
| `--md-bg` | Справочная информация о документе | Основной, если темный, почти нейтральный, если яркий |
| `--md-surface` | Фон карточки / выноски/ блок-цитаты | Яркость Bg ± 4-6% |
| `--md-border` | Разделители по линии роста волос, границы стола | Яркость Bg ± 8-12% |
| `--md-text` | Основной текст | Не совсем белый на темном фоне, почти черный на светлом |
| `--md-text-muted` | Подписи, метаданные, нижние колонтитулы | `rgba(text, 0.68)` |
| `--md-accent` | Основной CTA, заголовки выносок, выделение ссылок | Основной, если яркий, со смещением оттенка, более светлый, если темный |
| `--md-accent-soft` | Акцентные фоны, состояния наведения курсора | `rgba(accent, 0.14)` |
| `--md-code-bg` | Встроенный код, огороженный блок bg | Яркость Bg ± 4-5% |
| `--md-link` | Гиперссылки | Итеративно прошелся, чтобы достичь контраста 4,5:1 на bg |
| `--md-link-hover` | Состояние зависания | Яркость связи ± 6-8% |
| `--md-success` | ОК / одобрено / принято | Закрепленный зеленый цвет, подобранный по яркости |
| `--md-warn` | Осторожно / nit / TODO | Закрепленный янтарь, подобранный по яркости |

## Библиотека принудительных вопросов (шаблон Matt Pocock grill-with-docs) { #forcing-question-library-matt-pocock-grill-with-docs-pattern }

Один вопрос за ход, рекомендуемый ответ, цитата из канона.

1. ** Какой основной цвет вашего бренда? ** Рекомендуется: шестнадцатеричный, который вы уже используете в своем продукте или документации, а не обычный синий. Канон: Аарон Уолтер, *Дизайн для эмоций* (цвет несет в себе влияние бренда).
2. ** Следует ли выводить акцент или устанавливать его?** Рекомендуется: выводить при первом запуске (hue-shift + lighten создает согласованный компаньон); устанавливать явно, только если он указан в вашем фирменном наборе. Канон: Adobe Spectrum, *Цветовая основа*.
3. ** Редакционный, технический, минимальный или игривый? ** Рекомендуется: `technical` для получения технических спецификаций/отчетов, `editorial` для давно прочитанных рассказов, `minimal` для получения скудных справочных материалов, `playful` для маркетингового/целевого контента. Канон: Эллен Лэптон, *Мышление с помощью типа* (стиль служит риторической цели).
4. ** Всплывающее окно на боковой панели или встроенное? ** Рекомендуется: `sticky-sidebar` для документов объемом более 800 слов, `inline` для краткого чтения. Канон: Нильсен-Норман, *Оглавление "Лучшие практики"* (2023).
5. ** Сохранить как глобальное или для каждого проекта?** Рекомендуется: глобальное по умолчанию (согласованно для всей вашей работы); используйте `--scope project` только в том случае, если у этого репозитория другой бренд. Канон: схема онбординга между исследованиями и операциями, `research-ops/CLAUDE.md` §8.

## Настройка в процессе использования (отработанный пример) { #customization-in-use-worked-example }

```bash
# First-run onboarding (interactive, walks all 10 questions)
python3 markdown-html/skills/design-system/scripts/onboard.py

# Zero-touch defaults for CI / first-test
python3 .../onboard.py --defaults

# Change just the primary color and design style
python3 .../onboard.py --set brand.primary=#FF6B35 --set design_style=editorial

# Per-repo override
python3 .../onboard.py --scope project --set design_style=minimal

# Reset and re-onboard
python3 .../onboard.py --reset
python3 .../onboard.py

# Inspect the effective config (project > global > defaults)
python3 .../config_loader.py --show
python3 .../config_loader.py --status

# Bypass saved config (returns DEFAULTS only)
MARKDOWN_HTML_NO_CONFIG=1 python3 .../config_loader.py --show

# Spot-check WCAG contrast before committing to a brand
python3 .../brand_palette_validator.py --primary "#FF6B35" --accent "#00D4AA"
```

## Допущения { #assumptions }

1. У пользователя есть по крайней мере один шестнадцатеричный код бренда, который он хочет использовать в своих HTML-преобразованиях.
2. Пользователь соглашается на одноразовую настройку продолжительностью 1-2 минуты.
3. Пользователь согласен с Google Fonts в качестве источника типографики (CDN, локальный хостинг шрифтов отсутствует).
4. WCAG 2.2 AA - это уровень доступности (4,5:1 корпус, 3:1 большой /пользовательский интерфейс). AAA (7:1) выходит за рамки.

## Нецели { #non-goals }

- Не полноценная система маркеров дизайна (Словарь стилей, Theo). Двенадцать жетонов, а не сотня.
- Это не решение для размещения пользовательских шрифтов. Только шрифты Google.
- В преобразователях нет переключателя темного / светлого режимов. `code_theme: auto` обрабатывает вариант предпочтительной цветовой схемы для подсветки синтаксиса; палитра макета является однорежимной для каждого онбординга.
- Не пакет аудита доступности (для этого используйте axe-core / pa11y). Мы применяем только контраст.
- Не преобразует существующий CSS — производная палитра вводится в только что сгенерированный HTML.

## Выходной артефакт { #output-artifact }

`~/.config/markdown-html/design-system.json` (глобальный) или `./.markdown-html/design-system.json` (проект). Схема JSON находится по адресу `assets/design_system_schema.json`.

## Анти-паттерны (не делать) { #anti-patterns-do-not }

- ❌ Пропустите онбординг и запустите конвертер с параметрами—заполнителями по умолчанию - выходные данные выглядят без маркировки.
- ❌ Выберите яркий основной бренд в качестве `brand.bg` напрямую (низкий контраст текста). Вместо этого используйте его в качестве акцента.
- ❌ Набора `MARKDOWN_HTML_NO_CONFIG=1` незаметно для интерактивного пользователя — он задастся вопросом, почему исчезли его токены.
- ❌ Закодируйте семантику бренда в `derived_palette` за пределами таксономии из 12 токенов. Добавляйте новый токен только с заранее заданным именем + назначением + правилом вывода.
