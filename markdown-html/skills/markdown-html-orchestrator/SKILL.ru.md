# Markdown → HTML — оркестратор домена { #markdown--html--domain-orchestrator }

Аргумент Тарика Шихипара (эссе о выводе HTML-кода Claude, Medium 2026): ** Markdown сворачивается после 100 строк для артефактов, сгенерированных агентом.** Длинные спецификации, ревью кода и пояснения к архитектуре теряют плотность, иерархию и упрощенное взаимодействие в тот момент, когда они превышают экран текста. HTML восстанавливает все три — однофайловые, встроенные в браузер, доступные для общего доступа.

Этот оркестратор разветвляет контекст, детерминированно классифицирует входные данные Markdown, направляет к нужному под-скиллу конвертера и возвращает дайджест с выходным путем. Интенсивное потребление (полные тела Markdown, различия, слайд-деки) остается в раздвоенном контексте.

**Статус домена (завершен):** все пять скилл доступны в режиме реального времени — оркестратор + `design-system` (онбординг + общие токены бренда) + три вспомогательных скилла для конвертации (`md-document`, `md-review`, `md-slides`). Всегда направляйте преобразования в скрипты поставляемого конвертера; никогда не выполняйте встроенный HTML вручную.

## Когда вызывать { #when-to-invoke }

| Симптом | Вспомогательный скилл |
|---|---|
| "Преобразуйте этот RFC / спецификацию / отчет / пояснение в HTML" — документ в расширенной форме | `md-document` |
| "Превратите эту PR-запись / ревью кода в HTML" — Markdown с блоками diff | `md-review` |
| "Сделайте слайд-колоду из этого Markdown" — `---` границы или частота H1 | `md-slides` |

## Предполетные гейты (жесткие отказы) { #pre-flight-gates-hard-refusals }

1. **Ниже порогового значения в 100 строк.** Markdown выигрывает менее чем на 100 линиях (Shihipar). Классификатор печатает `below_min_lines: true` и `route_explainer.py` отказывается. Скажите пользователю, чтобы он сохранил свои вводимые данные в виде Markdown.
2. **Дизайн-система не онбординг.** Если `~/.config/markdown-html/design-system.json` не существует (или его `setup_completed_at` равно null), отказать. Укажите пользователю на `python3 markdown-html/skills/design-system/scripts/onboard.py` (или `--defaults` для запуска с нулевым касанием).
3. ** Недоступное для записи местоположение сохранения.** `output_path_resolver.py` отказывает, если настроенный `default_output_dir` (или `--out` переопределить) недоступен для записи.

## Логика маршрутизации (детерминированная) { #routing-logic-deterministic }

Двухсигнальный пороговый паттерн, снятый с `research-ops/skills/research-ops-skills/SKILL.md` Подсказка по имени файла = 2 балла; каждый сигнал содержимого = 1 балл. Бесшумный маршрут разрешен, если победитель ≥ 3 И (занявший второе место = 0 ИЛИ победитель ≥ 2× занявший второе место). Ниже порогового значения → один уточняющий вопрос с рекомендуемым ответом.

### Таблица сигналов { #signal-table }

| Класс сигнала | Подсказки по имени файла | Сигналы о содержании | Вспомогательный скилл |
|---|---|---|---|
| ДОКУМЕНТ | `report.md`, `*-doc.md`, `spec.md`, `rfc-*.md`, `*-analysis.md`, `*-explainer.md` | `## Table of Contents` (2), `^# `, `^## `, строки таблицы Markdown, `> [!NOTE]/[!TIP]/[!IMPORTANT]` выноски | `md-document` |
| РЕВЬЮ | `review.md`, `*-pr-*.md`, `*.diff.md`, `code-review*.md` | ` ```diff ` (2), `^[-+]{3} ` (2), `^@@` (2), `> [!BLOCKER]/[!MAJOR]/[!MINOR]/[!NIT]` (2), `LGTM`/`nit:`/`blocker:` | `md-review` |
| СЛАЙДЫ | `deck.md`, `slides.md`, `*-talk.md`, `presentation*.md` | `^---$` ≥ 3 (2 + на границе), `<!-- notes:` (2), количество H1 ≥ 5 при среднем промежутке ≤ 12 строк (2) | `md-slides` |

Пайплайн:

```bash
python3 markdown-html/skills/markdown-html-orchestrator/scripts/doctype_classifier.py \
    --input <path>.md --output json \
  | python3 markdown-html/skills/markdown-html-orchestrator/scripts/route_explainer.py
```

`route_explainer.py` проверяет состояние системы проектирования, применяет отказ < 100 строк и печатает один из: `ROUTE_SILENTLY -> md-<type>`, `ASK_USER one question: ...`, или `REFUSE — fix the issues above`.

## Воркфлоу { #workflow }

### Шаг 1 — Подтвердите онбординг { #step-1--confirm-onboarding }

Если пользователь никогда не запускал онбординг, запустите одноразовую настройку:

```bash
python3 markdown-html/skills/design-system/scripts/onboard.py
```

Десять вопросов, 1-2 минуты. Отражает суть бренда + акцент + заголовок/body Шрифты Google + стиль оформления (редакционный/technical/minimal/playful) + каталог вывода по умолчанию + тема синтаксиса + поведение TOC + дополнительный логотип/company. Хранится в `~/.config/markdown-html/design-system.json`. Возможность повторного запуска с помощью `--scope project` для переопределений для каждого репозитория.

### Шаг 2 — Классифицируйте входные данные { #step-2--classify-the-input }

Бежать `doctype_classifier.py` на Markdown. Ознакомьтесь с вердиктом.

### Шаг 3 — Проложите маршрут или спросите { #step-3--route-or-ask }

Распределите классификацию по `route_explainer.py`. Если там написано `ROUTE_SILENTLY`, перенаправьте исходный Markdown + конфигурацию системы проектирования в средство визуализации именованного суб-скилла в разветвленном контексте. Если там написано `ASK_USER`, задайте ОДИН вопрос с рекомендуемым ответом.

### Шаг 4 — Определите выходной путь { #step-4--resolve-the-output-path }

```bash
python3 markdown-html/skills/markdown-html-orchestrator/scripts/output_path_resolver.py \
    --input <path>.md --doctype <document|review|slides>
```

Обработка столкновений по умолчанию имеет значение `-2 / -3 / ...` суффикс; `--on-collision timestamp` для имен с печатью.

### Шаг 5 — Переход к дополнительному скиллу { #step-5--hand-off-to-the-sub-skill }

Средство визуализации под-скилла маршрутизируемого конвертера (`md-document/scripts/`, `md-review/scripts/`, или `md-slides/scripts/`) принимает входные данные Markdown, конфигурацию системы проектирования и разрешенный путь вывода и записывает один автономный HTML-файл. Оркестратор возвращает дайджест из ≤ 100 слов: строки ввода, путь вывода, применяемый стиль оформления, 3 основные используемые функции (оглавление, поиск, копирование кода и т.д.) и один форсирующий вопрос для пользователя. Никогда не рендерьте HTML вручную — рендерингом владеют скрипты конвертера.

## Библиотека принудительных вопросов (шаблон Matt Pocock grill-with-docs) { #forcing-question-library-matt-pocock-grill-with-docs-pattern }

Пройдите их по одному за раз, с рекомендуемым ответом на каждый вопрос, ссылаясь на канон. Поднимите этот список в `/cs:grill-markdown-html` для проведения планового допроса.

1. ** К какому решению приводит этот HTML—код - читатель просматривает, принимает решение или представляет?**
   Рекомендуется: сначала назовите его; плотность зависит от назначения. Канон: Shihipar — "соответствие формата вывода контексту потребления"; Tufte — *Визуальное отображение количественной информации*, гл. 1.
2. **Markdown ввода составляет ≥ 100 строк?**
   Рекомендуется: да — ниже этого сохраните его как Markdown. Канон: Shihipar — Markdown по-прежнему выигрывает менее чем на 100 линиях.
3. ** Внедрена ли онбординг в систему проектирования?**
   Рекомендуется: да, во всем мире (`~/.config/markdown-html/design-system.json`). Канон: схема онбординга исследовательских операций (`research-ops/CLAUDE.md` §8); WCAG 2.2 §1.4.3 (контраст текста 4.5:1).
4. **Где сохраняются выходные данные и будет ли при этом что-либо перезаписано?**
   Рекомендуется: настроенный `default_output_dir` с `--on-collision suffix`. Канон: Мэтт Покок `handoff` скилл — никогда не перезаписывайте рабочий артефакт автоматически.
5. **Тип документа конфиденциальный — молчаливый-маршрут или один вопрос?**
   Рекомендуется: бесшумный маршрут только в том случае, если вердикт классификатора является одним из `document/review/slides` И `silent_route_allowed: true`. В противном случае спросите. Канон: двухсигнальный порог для исследовательских операций (`research-ops/skills/research-ops-skills/SKILL.md` § "Логика маршрутизации").

Никогда не запускайте вспомогательный скилл до того, как дорожка будет заблокирована.

## Допущения { #assumptions }

1. У пользователя есть файл Markdown объемом более 100 строк, который он хочет преобразовать.
2. Пользователь запустил онбординг один раз (`~/.config/markdown-html/design-system.json` существует с `setup_completed_at` населенный пункт).
3. Допускается вывод HTML-кода в виде одного файла (нет многофайлового сайта, нет встроенного сервера, нет этапа сборки).
4. Внешние возможности ограничены Google Fonts CSS + Prism.js CDN (jsdelivr / cdnjs).

## Нецели { #non-goals }

- Не генератор целевых страниц (используйте `marketing/landing/`).
- Не интерактивная игровая площадка для настройки промптов (используйте официальный сайт Anthropic `playground` плагин).
- Не генератор статических сайтов (нет мультифайлового вывода, нет индекса сайта).
- Не генератор PDF (слайды используют `@media print`; пользователь печатает из браузера).
- Не пайплайн для просмотра / перезагрузки в реальном времени (преобразование выполняется одним выстрелом).

## Отличный от { #distinct-from }

- **Плагин для антропной игровой площадки ** (`/playground`) — создает интерактивные элементы управления (ползунки, ручки, перетаскивание) для настройки промпта с циклом копирования-промпта-возврата. Этот плагин преобразует существующие документы Markdown в HTML. Разные инструменты для разных работ.
- **`marketing/landing/`** — генерирует целевые страницы с нуля (фаза-0 вход → 3 раздела → фирменный TSX/HTML). Этот плагин преобразует существующий файл Markdown, который у вас уже есть.
- **`engineering/handoff/` + `productivity/handoff/`** — сохраняйте непрерывность сеанса между разговорами с Клодом. Другой тип артефакта (хэндофф-бриф или преобразование документа).

|---|---|---|

## Анти-паттерны (не делать) { #anti-patterns-do-not }

- ❌ Преобразовать Markdown < 100 строк — Markdown по-прежнему выигрывает. Откажитесь и сообщите об этом пользователю.
- ❌ Запустите оркестратор до онбординга системы проектирования. Выходные данные выглядят разбитыми без токенов.
- ❌ Молча соедините два вспомогательных скилла (например, "конвертируйте документ И создавайте из него слайды"). Выберите один, закончите, спросите, прежде чем связывать в цепочку.
- ❌ Используйте внешние JS-фреймворки (React/Vue/Svelte). Только Vanilla JS + IntersectionObserver. Prism.js CDN является единственным исключением.
- ❌ Вывод нескольких файлов (извлеченный CSS, каталоги ресурсов). Один файл или ничего — в этом весь смысл.
- ❌ Перезаписать существующий выходной файл по умолчанию. Суффиксы средства определения пути `-2`, `-3`, …; `--on-collision overwrite` это только для регистрации.
