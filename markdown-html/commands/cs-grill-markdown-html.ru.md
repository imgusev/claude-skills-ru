# /cs:grill-Markdown-HTML — Гриль для предварительной конвертации { #csgrill-markdown-html--pre-conversion-grill }

Ознакомьте пользователя с 5 форсирующими вопросами, прежде чем перейти к конвертеру. ** Один вопрос за ход**, с рекомендуемым ответом и цитатой из канона. Пользователь должен ответить на вопрос Q1 до того, как будет задан вопрос Q2. Никогда не связывайтесь.

**$АРГУМЕНТЫ**

## 5 вопросов (шаблон Matt Pocock grill-with-docs) { #the-5-questions-matt-pocock-grill-with-docs-pattern }

### Q1/5 — Назначение { #q15--purpose }

> ** К какому решению приводит этот HTML—код - читатель просматривает, принимает решение или представляет?**
>
> Рекомендуется: сначала назовите его; плотность зависит от назначения.
>
> Канон: Shihipar (эссе Клода Коде в HTML—формате) - "соответствие формата вывода контексту потребления"; Tufte, *Визуальное отображение количественной информации*, гл. 1.

Если пользователь пожмет плечами, спросите один раз: "Беглый просмотр → минимальный макет. Принятие решения → sticky TOC + поиск. Презентация → колода слайдов."

### Q2/5 — Порог количества строк { #q25--line-count-threshold }

> **Markdown ввода составляет ≥ 100 строк?**
>
> Рекомендуется: да — ниже этого сохраните его как Markdown. Бежать `wc -l <file>.md` для подтверждения.
>
> Канон: Shihipar — Markdown по-прежнему выигрывает менее чем за 100 строк.

Если меньше 100 строк, откажитесь от преобразования. НЕ продолжайте.

### Q3/5 — Онбординг системы проектирования? { #q35--design-system-onboarded }

> **Была ли онбординг проведена в системе проектирования?**
>
> Рекомендуется: да, во всем мире. Бежать `python3 markdown-html/skills/design-system/scripts/onboard.py` (или `--defaults` для нулевого касания), если нет.
>
> Канон: схема онбординга между исследованиями и операциями (`research-ops/CLAUDE.md` §8); WCAG 2.2 §1.4.3.

Проверьте через:

```bash
python3 markdown-html/skills/design-system/scripts/config_loader.py --status
```

Если `setup_completed: false`, поверхностный онбординг. НЕ продолжайте без этого.

### Q4/5 — Выходной канал { #q45--output-path }

> **Где сохраняются выходные данные и будет ли при этом что-либо перезаписано?**
>
> Рекомендуется: настроенный `default_output_dir` с `--on-collision suffix` (значение по умолчанию, которое генерирует `-2`, `-3`, ... вместо перезаписи).
>
> Канон: Мэтт Покок `handoff` скилл — никогда не перезаписывайте рабочий артефакт автоматически.

Разрешить с помощью:

```bash
python3 markdown-html/skills/markdown-html-orchestrator/scripts/output_path_resolver.py \
    --input "$ARGUMENTS" --doctype <verdict>
```

### Q5/5 — Уверенность в типе документа { #q55--doctype-confidence }

> **Тип документа конфиденциальный — молчаливый-маршрут или один уточняющий вопрос?**
>
> Рекомендуется: бесшумный маршрут только тогда, когда `silent_route_allowed: true` в выходных данных классификатора. В противном случае задайте один уточняющий вопрос и порекомендуйте победителя.
>
> Канон: двухсигнальный порог для исследовательских операций (`research-ops/skills/research-ops-skills/SKILL.md` § "Логика маршрутизации").

Классифицировать с помощью:

```bash
python3 markdown-html/skills/markdown-html-orchestrator/scripts/doctype_classifier.py \
    --input "$ARGUMENTS" --output human
```

## Дисциплина { #discipline }

- ** По одному вопросу за ход. ** Не объединяйте Q1 + Q2 в одном сообщении. Ждите ответа.
- ** Всегда рекомендуйте ответ.** Никогда не задавайте открытый вопрос.
- ** Всегда ссылайтесь на канон.** В рекомендации должна быть ссылка на источник.
- **Отклонить, не переопределять.** Если Q2 или Q3 завершаются неудачей, преобразование не выполняется. Решетка защищает от бесшумного выхода из строя.
- ** Сначала пройдите по глубине.** Ответьте на все 5 вопросов для этого преобразования, прежде чем приступать к другому.

После 5-го квартала передайте `/cs:markdown-html <path>` чтобы действительно выполнить преобразование с подтвержденными ответами на руках.
