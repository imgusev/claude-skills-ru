# Аналитика кампаний { #campaign-analytics }

Анализ эффективности кампании производственного уровня с помощью моделирования атрибуции в несколько касаний, анализа конверсии по воронке и расчета рентабельности инвестиций. Три инструмента Python CLI обеспечивают детерминированную, воспроизводимую аналитику, используя только стандартную библиотеку - никаких внешних зависимостей, никаких вызовов API, никаких моделей ML.

---

Все скрипты принимают файл JSON в качестве позиционного входного аргумента. Видишь `assets/sample_campaign_data.json` для получения полных примеров.

### Проверка входных данных { #input-validation }

Перед запуском скриптов убедитесь, что ваш JSON действителен и соответствует ожидаемой схеме. Распространенные ошибки:

- **Отсутствуют необходимые ключи** (например,, `journeys`, `funnel.stages`, `campaigns`) → сценарий завершает работу с описательным `KeyError`
- **Несоответствующие длины массива** в данных воронки (`stages` и `counts` должна быть одинаковой длины) → поднимает `ValueError`
- **Нечисловые денежные значения** в данных об рентабельности инвестиций → повышает `TypeError`

Использование `python -m json.tool your_file.json` для проверки синтаксиса JSON перед передачей его в любой скрипт.

Все скрипты поддерживают два выходных формата через `--format` флаг:

- `--format text` (по умолчанию): Удобочитаемые таблицы и резюме для ревью

## Типичный воркфлоу-процесс анализа { #typical-analysis-workflow }

Для полного ревью кампании последовательно запустите три сценария:

```bash
# Step 1 — Attribution: understand which channels drive conversions
python scripts/attribution_analyzer.py campaign_data.json --model time-decay

# Step 2 — Funnel: identify where prospects drop off on the path to conversion
python scripts/funnel_analyzer.py funnel_data.json

# Step 3 — ROI: calculate profitability and benchmark against industry standards
python scripts/campaign_roi_calculator.py campaign_data.json
```

Используйте результаты атрибуции для определения наиболее эффективных каналов, затем сосредоточьте анализ воронки на сегментах этих каналов и, наконец, проверьте показатели рентабельности инвестиций, чтобы определить приоритеты перераспределения бюджета.

### Анализ атрибуции { #attribution-analysis }

```bash
# Run all 5 attribution models
```

## Сценарии { #scripts }

### 1. attribution_analyzer.py { #1-attribution_analyzerpy }

Реализует пять стандартных отраслевых моделей атрибуции для распределения конверсионных баллов по маркетинговым каналам:

| Модель | Описание | Лучше всего подходит для |
|-------|-------------|----------|
| Первое касание | 100% заслуга первого взаимодействия | Кампании по повышению осведомленности о бренде |
| Последнее прикосновение | 100% скидка на последнее взаимодействие | Кампании прямого реагирования |
| Линейный | Равный кредит всем точкам соприкосновения | Сбалансированная многоканальная оценка |
| Затухание во времени | Больше внимания уделяется недавним точкам соприкосновения | Короткие циклы продаж |
| Основанный на положении | разделение на 40/20/40 (первое/среднее/последнее) | Маркетинг с полной воронкой |

### 2. funnel_analyzer.py { #2-funnel_analyzerpy }

Анализирует воронки конверсий для выявления узких мест и возможностей оптимизации:

- Коэффициенты конверсии от этапа к этапу и процент отсева
- Автоматическое определение узких мест (наибольшие абсолютные и относительные перепады)
- Общий коэффициент конверсии воронки
- Сравнение сегментов при наличии нескольких сегментов

### 3. campaign_roi_calculator.py { #3-campaign_roi_calculatorpy }

Рассчитывает комплексные показатели рентабельности инвестиций с помощью отраслевого бенчмаркинга:

- **Рентабельность инвестиций**: Процент возврата инвестиций
- **ROAS**: Коэффициент рентабельности расходов на рекламу
- **CPA**: Стоимость одного приобретения
- **CPL**: Стоимость за лид
- **CAC**: Стоимость привлечения клиентов
- **CTR**: Показатель кликабельности
- **CVR**: коэффициент конверсии (количество потенциальных клиентов)
- Выявляет неэффективные кампании по сравнению с отраслевыми показателями

## Лучшие практики { #best-practices }

1. ** Используйте несколько моделей атрибуции ** - Сравните по крайней мере 3 модели для триангуляции значения канала; ни одна модель не раскрывает всю историю целиком.
2. ** Установите соответствующие окна обратной связи ** - Сопоставьте период полураспада с вашей средней продолжительностью цикла продаж.
3. ** Сегментируйте свои воронки ** - Сравните сегменты (канал, когорту, географию), чтобы определить факторы, влияющие на производительность.
4. ** Сначала сравните с вашей собственной историей ** - Отраслевые тесты обеспечивают контекст, но наиболее релевантным сравнением являются исторические данные.
5. ** Регулярно проводите анализ рентабельности инвестиций** - еженедельно для активных кампаний, ежемесячно для стратегического ревью.
6. ** Включите все затраты ** - Учитывайте затраты на креативность, оборудование и рабочую силу наряду с расходами на МЕДИА для получения точной рентабельности инвестиций.
7. ** Тщательно документируйте A/B тесты** - Используйте предоставленный шаблон для обеспечения статистической достоверности и четких критериев принятия решения.

## Ограничения { #limitations }

- **Нет проверки статистической значимости** -- Скрипты предоставляют только описательные показатели; для вычисления p-значения требуются внешние инструменты.
- ** Только стандартная библиотека** - Никаких расширенных статистических библиотек. Подходит для большинства размеров кампаний, но не оптимизирован для наборов данных, превышающих 100 тыс. поездок.
- ** Автономный анализ ** -- Скрипты анализируют статические снимки JSON; никаких подключений к данным в реальном времени или интеграции API.
- **Единая валюта** - Предполагается, что все денежные значения выражены в одной валюте; поддержка конвертации валют отсутствует.
- ** Упрощенный временной спад ** - Экспоненциальный спад, основанный на настраиваемом периоде полураспада; не учитывает дни недели / выходные или сезонные закономерности.
- ** Нет отслеживания между устройствами ** -- Атрибуция выполняется на основе предоставленных данных о путешествии как есть; разрешение идентификации между устройствами должно обрабатываться выше по потоку.
