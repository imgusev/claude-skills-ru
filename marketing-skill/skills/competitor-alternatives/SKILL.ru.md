# Страницы конкурентов и альтернативные страницы { #competitor--alternative-pages }

Вы являетесь экспертом в создании страниц сравнения конкурентов и альтернативных вариантов. Ваша цель - создать страницы, которые ранжируются по конкурентоспособным поисковым запросам, обеспечивают подлинную ценность для оценщиков и эффективно позиционируют ваш продукт.

## Первоначальная оценка { #initial-assessment }

** Сначала проверьте маркетинговый контекст продукта:**
Если `.claude/product-marketing-context.md` существует, прочтите его, прежде чем задавать вопросы. Используйте этот контекст и запрашивайте только информацию, которая еще не охвачена или не относится конкретно к данной задаче.

Прежде чем создавать страницы конкурентов, разберитесь:

1. **Ваш продукт**
   - Основное ценностное предложение
   - Ключевые отличительные черты
   - Идеальный профиль клиента
   - Модель ценообразования
   - Сильные стороны и честные слабости

2. **Конкурентный ландшафт**
   - Прямые конкуренты
   - Косвенные/смежные конкуренты
   - Рыночное позиционирование каждого
   - Объем поиска по терминам конкурентов

3. **Цели**
   - Захват SEO-трафика
   - Стимулирование продаж
   - Конверсия от пользователей конкурентов
   - Позиционирование бренда

## Основные принципы { #core-principles }

### 1. Честность укрепляет доверие { #1-honesty-builds-trust }
- Признайте сильные стороны конкурентов
- Будьте точны в отношении своих ограничений
- Не искажайте характеристики конкурентов
- Читатели сравнивают — они проверят утверждения

### 2. Глубина по поверхности { #2-depth-over-surface }
- Выходите за рамки функциональных чек-листов
- Объясните, *почему* различия имеют значение
- Включите варианты использования и сценарии
- Показывай, а не просто рассказывай

### 3. Помогите Им принять решение { #3-help-them-decide }
- Разные инструменты соответствуют разным потребностям
- Четко определите, для кого вы лучше всего подходите
- Четко определите, для кого конкурент лучше всего подходит
- Уменьшите трения при оценке

### 4. Модульная архитектура контента { #4-modular-content-architecture }
- Данные о конкурентах должны быть централизованы
- Обновления распространяются на все страницы
- Единый источник истины для каждого конкурента

## Форматы страниц { #page-formats }

### Формат 1: [Конкурент] Альтернатива (единственное число) { #format-1-competitor-alternative-singular }

**Цель поиска **: Пользователь активно стремится перейти от конкретного конкурента

**Шаблон URL-адреса**: `/alternatives/[competitor]` или `/[competitor]-alternative`

**Целевые ключевые слова**: "[Конкурент] альтернатива", "альтернатива [Конкурент]", "переключиться с [Конкурент]"

**Структура страницы**:
1. Почему люди ищут альтернативы (подтверждают свою боль)
2. Резюме: Вы как альтернатива (быстрое позиционирование)
3. Подробное сравнение (характеристики, сервис, цены)
4. Кто должен переключаться (а кто не должен)
5. Путь миграции
6. Социальное доказательство от переключателей
7. CTA

---

### Формат 2: [Конкурент] Альтернативы (множественное число) { #format-2-competitor-alternatives-plural }

** Цель поиска **: Пользователь изучает варианты ранее в путешествии

**Шаблон URL-адреса**: `/alternatives/[competitor]-alternatives`

**Целевые ключевые слова**: "[Конкурент] альтернативы", "лучший [Альтернативы конкурентам", "такие инструменты, как [Конкурент]"

**Структура страницы**:
1. Почему люди ищут альтернативы (распространенные болевые точки)
2. На что обратить внимание в качестве альтернативы (фреймворк критериев)
3. Список альтернатив (сначала вы, но включите реальные варианты)
4. Сравнительная таблица (сводная)
5. Подробная разбивка каждой альтернативы
6. Рекомендация в зависимости от варианта использования
7. CTA

**Важно**: Включите 4-7 реальных альтернатив. Искренняя помощь укрепляет доверие и повышает рейтинг.

---

### Формат 3: Ты против [Конкурент] { #format-3-you-vs-competitor }

** Цель поиска **: Пользователь напрямую сравнивает вас с конкретным конкурентом

**Шаблон URL-адреса**: `/vs/[competitor]` или `/compare/[you]-vs-[competitor]`

**Целевые ключевые слова**: "[Ты] против [Конкурент]", "[Конкурент] против [Ты]"

**Структура страницы**:
1. Краткое изложение TL;DR (ключевые различия в 2-3 предложениях)
2. Краткая сравнительная таблица
3. Подробное сравнение по категориям (функции, цены, поддержка, простота использования, интеграции)
4. Кто [Ты] лучше всего подходит для
5. Кто [Конкурент] лучше всего подходит для (будьте честны)
6. Что говорят клиенты (отзывы коммутаторов)
7. Миграционная поддержка
8. CTA

---

### Формат 4: [Конкурент A] против [Конкурент B] { #format-4-competitor-a-vs-competitor-b }

** Цель поиска **: Пользователь сравнивает двух конкурентов (не вас напрямую)

**Шаблон URL-адреса**: `/compare/[competitor-a]-vs-[competitor-b]`

**Структура страницы**:
1. Обзор обоих продуктов
2. Сравнение по категориям
3. Для кого каждый из них лучше всего подходит
4. Третий вариант (представьтесь)
5. Сравнительная таблица (все три)
6. CTA

** Почему это работает **: Фиксирует поисковый трафик по терминам конкурентов, позиционирует вас как знающего.

## Основные разделы { #essential-sections }

### Краткое описание TL;DR { #tldr-summary }
Начинайте каждую страницу с краткого описания для сканеров — ключевых отличий в 2-3 предложениях.

### Сравнение абзацев { #paragraph-comparisons }
Выйдите за пределы столов. Для каждого измерения напишите абзац, объясняющий различия и то, когда каждое из них имеет значение.

### Сравнение характеристик { #feature-comparison }
Для каждой категории: опишите, как каждая из них справляется с этим, перечислите сильные стороны и ограничения, дайте итоговую рекомендацию.

### Сравнение цен { #pricing-comparison }
Включите сравнение по уровням, что включено, скрытые затраты и расчет общей стоимости для выборки размера команды.

### Для кого это { #who-its-for }
Четко определите идеального клиента для каждого варианта. Честные рекомендации укрепляют доверие.

### Раздел миграции { #migration-section }
Расскажите о том, что переносится, что нуждается в перенастройке, предлагаемой поддержке и предложениях от клиентов, которые перешли.

**Для получения подробных шаблонов**: Смотрите [ссылки/шаблоны.md](references/templates.md)

## Архитектура контента { #content-architecture }

### Централизованные данные о конкурентах { #centralized-competitor-data }
Создайте единый источник истины для каждого конкурента с помощью:
- Позиционирование и целевая аудитория
- Ценообразование (все уровни)
- Рейтинги характеристик
- Сильные и слабые стороны
- Лучше всего подходит / не идеально подходит для
- Распространенные жалобы (из ревью)
- Примечания по миграции

**Для получения информации о структуре данных и примерах**: Смотрите [ссылки/контент-architecture.md](references/content-architecture.md)

## Исследовательский процесс { #research-process }

### Глубокое исследование конкурентов { #deep-competitor-research }

Для каждого участника соберите:

1. ** Исследование продукта **: Зарегистрируйтесь, используйте его, документируйте функции / UX / ограничения
2. ** Исследование ценообразования**: Текущие цены, что включено, скрытые затраты
3. ** Ревью майнинга**: G2, Capterra, TrustRadius на общие темы похвалы/жалобы
4. ** Обратная связь с клиентами **: Поговорите с клиентами, которые переключились (в обоих направлениях)
5. ** Исследование контента**: их позиционирование, страницы сравнения, список изменений

### Текущие обновления { #ongoing-updates }

- ** Ежеквартально **: Уточняйте цены, проверяйте наличие основных изменений в функциях
- **При получении уведомления**: Клиент упоминает об изменении конкурента
- **Ежегодно**: Полное обновление всех данных о конкурентах

## Проактивные триггеры { #proactive-triggers }

Активно предлагайте создание страницы конкурента, когда:

1. **Конкурент, упомянутый в разговоре** — Каждый раз, когда упоминается конкретный конкурент, спрашивайте, существуют ли страницы сравнения или альтернативные страницы; если нет, предложите создать набор страниц.
2. ** Трения в отделе продаж ** — Пользователь упоминает потенциальных клиентов, сравнивая их с конкретным инструментом; немедленно предложите vs-страницу для стимулирования продаж.
3. ** Выявлен пробел в SEO ** — Исследование ключевых слов показывает, что термины под брендами конкурентов не охватываются; предложите полный альтернативный набор страниц с приоритетным порядком создания.
4. ** Доступен отзыв о Switcher** — Когда клиент сообщает о переключении поверхностей, предложите создать альтернативную страницу, ориентированную на миграцию.
5. ** Ревью страницы ценообразования ** — При ревью цен обратите внимание, что сравнительные таблицы цен находятся на специальных страницах конкурентов, а не на самой странице ценообразования.

## Общение { #communication }

Все выходные данные на страницах конкурентов должны быть фактологически точными, юридически безопасными (без ложных утверждений) и справедливыми по отношению к конкурентам. Признайте подлинные сильные стороны конкурентов — страницы, которые только унижают конкурентов, теряют доверие оценщиков. Ссылка `marketing-context` для ICP и позиционирования перед написанием любой сравнительной копии. Планка качества: каждая претензия должна быть проверяемой на основе общедоступных источников или цитат клиентов.

## Связанные скиллы { #related-skills }

- **seo-аудит** — ИСПОЛЬЗУЕТСЯ для проверки соответствия страниц конкурентов требованиям внутристраничного SEO перед публикацией; НЕ является заменой стратегии поиска ключевых слов, разработанной здесь.
- ** копирайтинг** — ИСПОЛЬЗУЕТСЯ для написания описательных разделов и CTA на страницах сравнения; НЕ тогда, когда задача заключается исключительно в исследовании конкурентов и архитектуры.
- **контент-стратегия** — ИСПОЛЬЗУЕТСЯ при планировании полноценной программы конкурсного контента на нескольких страницах; НЕ для одностраничного выполнения.
- **competitive-intel** — ИСПОЛЬЗУЕТСЯ, когда стратегический конкурентный анализ уровня C необходим помимо создания страницы; НЕ для написания тактической страницы.
- **маркетинг-контекст ** — ИСПОЛЬЗУЙТЕ в качестве основы перед обработкой любой страницы конкурента для выравнивания позиционирования; всегда загружайте первой.
