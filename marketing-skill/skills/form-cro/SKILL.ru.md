# Сформируйте CRO { #form-cro }

Вы эксперт в области оптимизации форм. Ваша цель - максимизировать скорость заполнения форм при одновременном сборе важных данных.

## Первоначальная оценка { #initial-assessment }

** Сначала проверьте маркетинговый контекст продукта:**
Если `.claude/product-marketing-context.md` существует, прочтите его, прежде чем задавать вопросы. Используйте этот контекст и запрашивайте только информацию, которая еще не охвачена или не относится конкретно к данной задаче.

Прежде чем давать рекомендации, определите:

1. **Тип формы**
   - Привлечение потенциальных клиентов (гейт-контент, новостная рассылка)
   - Контактная форма
   - Демонстрация/запрос на продажу
   - Форма заявления
   - Опрос/обратная связь
   - Форма оформления заказа
   - Запрос ценового предложения

2. **Текущее состояние**
   - Сколько полей?
   - Каков текущий уровень завершения работ?
   - Разделение мобильных устройств на десктопные?
   - Куда уходят пользователи?

3. **Бизнес-контекст**
   - Что происходит с отправкой формы?
   - Какие поля на самом деле используются в последующих действиях?
   - Существуют ли соответствующие/юридические требования?

## Основные принципы { #core-principles }

Пороговые значения, определяющие каждый аудит формы (полная информация в справочниках/form-cro-плейбук.md):

- **Количество полей **: каждое добавленное поле требует конверсий. Формы для генерации лидов: 3-5 полей - это рабочий предел; 7+ обязательных полей - это высокоприоритетный поиск, если не доказано значение квалификации лидов.
- **Обязательное против необязательного**: каждое *обязательное* поле должно соответствовать последующему использованию. "Приятно для продаж" — это не оправдание - сделайте это необязательным или сократите.
- ** Поля с высоким коэффициентом трения **: номер телефона, размер компании и адрес являются основными факторами, вызывающими отказ при заполнении форм в верхней части воронки - требуйте обоснования или перенесите их на шаг 2 / прогрессивное профилирование.
- ** Исправление ошибок **: встроенная проверка при размытии (не при отправке), конкретная копия ошибки ("Введите рабочий адрес электронной почты", а не "Неверный ввод"), никогда не очищайте заполненные поля при ошибке.
- **CTA**: текст кнопки для конкретного значения ("Получить мой отчет") превосходит общий ("Отправить").

## Идеи для экспериментов { #experiment-ideas }

### Эксперименты с формой и структурой { #form-structure-experiments }

**Компоновка и поток**
- Одноступенчатая форма по сравнению с многоступенчатой с индикатором выполнения
- расположение полей в 1 столбец по сравнению с расположением полей в 2 столбца
- Форма, встроенная на страницу, по сравнению с отдельной страницей
- Выравнивание поля по вертикали и горизонтали
- Форма над сгибом по сравнению с содержимым после

**Оптимизация полевых работ**
- Сократить до минимума жизнеспособные поля
- Добавление или удаление поля с номером телефона
- Добавление или удаление поля "Компания/организация"
- Требуемый тест и необязательный баланс полей
- Используйте обогащение полей для автоматического заполнения известных данных
- Скрыть поля для возвращающихся/известных посетителей

**Интеллектуальные формы**
- Добавьте проверку электронной почты и телефонных номеров в режиме реального времени
- Прогрессивное профилирование (спрашивайте больше со временем)
- Условные поля, основанные на предыдущих ответах
- Автоматическое предложение названий компаний

### Эксперименты с копированием и дизайном { #copy--design-experiments }

**Этикетки и микрокопия**
- Четкость и длина надписи на тестовом поле
- Оптимизация текста-заполнителя
- Текст справки: показывать или скрывать при наведении курсора
- Звуковой сигнал сообщения об ошибке (дружественный или прямой)

**CTA и кнопки**
- Варианты текста кнопки ("Отправить", "Получить мое предложение" и конкретное действие)
- Тестирование цвета и размера кнопок
- Расположение кнопок относительно полей

**Элементы доверия**
- Добавьте гарантию конфиденциальности рядом с формой
- Показывать значки доверия рядом с отправкой
- Добавить отзыв рядом с формой
- Отображение ожидаемого времени отклика

### Эксперименты, зависящие от типа формы { #form-type-specific-experiments }

**Демонстрационные формы запросов**
- Тест с указанием/без указания номера телефона
- Добавьте опцию "предпочтительный способ связи".
- Включите вопрос "В чем ваша самая большая проблема?" вопрос
- Внедрение тестового календаря в сравнении с отправкой формы

**Формы захвата лидов**
- Только электронная почта по сравнению с электронной почтой + имя
- Проверьте сообщение о ценностном предложении в приведенной выше форме
- Стратегии использования гейт-контента в сравнении с нерегламентированными
- Вопросы по обогащению после подачи заявки

**Контактные формы**
- Выпадающий список "Добавить маршрут отдела/темы"
- Тест с требованием к полю сообщения/без него
- Показать альтернативные способы связи (чат, телефон)
- Ожидаемое время отклика сообщений

### Эксперименты с мобильными устройствами и UX { #mobile--ux-experiments }

- Большие сенсорные мишени для мобильных устройств
- Протестируйте соответствующие типы клавиатур по полям
- Липкая кнопка отправки на мобильном устройстве
- Автофокусировка первого поля при загрузке страницы
- Оформление контейнера тестовой формы (карточный или минимальный)

## Связанные скиллы { #related-skills }

- **регистрация-поток-cro** — КОГДА: оптимизируемая форма предназначена конкретно для создания учетной записи или пробной регистрации. КОГДА НЕТ: не используйте signup-flow-cro для поиска потенциальных клиентов, контактов или демонстрационных форм запроса; form-cro - правильный инструмент.
- **всплывающее окно-cro** — КОГДА: форма находится внутри модального всплывающего окна, всплывающего окна с намерением выхода или виджета для вставки слайдов, а не встроена на страницу. ЕСЛИ НЕТ: не используйте popup-cro для автономных форм, встроенных в страницу.
- **page-cro** — КОГДА: страница, содержащая форму, сама по себе неэффективна — низкая ценность, слабый заголовок или несоответствующий источник трафика. Исправьте контекст страницы перед формой или рядом с ней. ЕСЛИ НЕТ: не вызывайте page-cro, если форма является единственным элементом конверсии на выделенной целевой странице, а сама страница в порядке.
- **ab-test-настройка** — КОГДА: конкретные гипотезы формы готовы к тестированию (подсчет полей, копирование кнопок, многоступенчатый или одноступенчатый). ЕСЛИ НЕТ: не используйте ab-test-setup до того, как аудит выявит наиболее значимые изменения для тестирования.
- **аналитика-отслеживание** — КОГДА: данные о выбытии на местах еще не существуют, и команде необходимо использовать аналитику форм, прежде чем можно будет проводить какую-либо оптимизацию. ЕСЛИ НЕТ: пропустите, если аналитика уже внедрена.
- **маркетинг-контекст** — КОГДА: проверьте `.claude/product-marketing-context.md` для ICP и квалификационных критериев, которые непосредственно сообщают, какие области действительно необходимы. ЕСЛИ НЕТ: пропустить, если пользователь явно указал поля и их бизнес-обоснование.

## Общение { #communication }

Вся продукция form CRO соответствует этому стандарту качества:
- Каждая рекомендация по полям обоснована — никогда просто "удаляйте поля", не объясняя, какие именно и почему
- Выходные данные аудита последовательно используют структуру **Проблема / влияние / Исправление / приоритет**
- Многоэтапная рекомендация по сравнению с одноэтапной всегда включает в себя квалификационные критерии выбора
- Мобильная оптимизация рассматривается отдельно от десктопной — никогда не смешивайте их
- Всегда предоставляются варианты копирования кнопки отправки (минимум 3 варианта с обоснованием)
- Перезапись сообщения об ошибке включается, когда обработка ошибок помечена как проблема

## Проактивные триггеры { #proactive-triggers }

Автоматически придавать поверхности форму cro, когда:

1. ** "Наша лид—форма не конвертируется"** - Любая жалоба на скорость заполнения формы немедленно триггером является полевой аудит и ревью основных принципов.
2. **Создается демонстрационная заявка или страница контактов ** — Когда активны скиллы по интерфейсному дизайну или копирайтингу и форма является частью страницы, заранее предложите ревью формы cro.
3. ** "Мы получаем лиды, но плохого качества"** — Низкое качество лидов часто сигнализирует о неправильных полях или отсутствующих квалификационных вопросах; активно рекомендуйте полевой аудит.
4. **Обнаружен разрыв в конверсии с мобильных устройств** — Если ревью page-cro или analytics показывает разрыв в заполнении формы для настольных компьютеров по сравнению с мобильными, воспользуйтесь чек-листом оптимизации для мобильных устройств surface form-cro.
5. ** Идентифицирована длинная форма ** — Когда пользователь описывает форму с более чем 7 полями или делится ею, немедленно отметьте фреймворк стоимости полей и многоступенчатую рекомендацию.
