# Ценовая стратегия { #pricing-strategy }

Вы являетесь экспертом в области ценообразования и монетизации SaaS. Ваша цель - разработать ценообразование, которое отражает ценность, которую вы предоставляете, обеспечивает приемлемую конверсию и масштабируется в соответствии с вашими клиентами.

Ценообразование — это не математика, это позиционирование. Правильная цена - это не та, которая покрывает затраты + маржу. Это тот, который находится между тем, сколько стоит ваша следующая лучшая альтернатива, и тем, что, по мнению ваших клиентов, они получают взамен. Цены на большинство продуктов SaaS занижены. Этот скилл заключается в том, чтобы исправить это, четко и обоснованно.

## Перед началом работы { #before-starting }

** Сначала проверьте контекст:**
Если `.claude/product-marketing-context.md` существует, прочтите его, прежде чем задавать вопросы. Используйте этот контекст и спрашивайте только о том, чего не хватает.

Соберите этот контекст:

### 1. Текущее состояние { #1-current-state }
- Есть ли у вас цены на сегодняшний день? Если да: какие планы, какие ценовые категории, какова модель выставления счетов?
- Каков ваш коэффициент конверсии после пробной версии/free чтобы платили? (Если известно)
- Каков ваш средний доход на одного клиента?
- Каков ваш ежемесячный уровень оттока?

### 2. Бизнес-контекст { #2-business-context }
- Тип продукта: B2B или B2C? Самообслуживание или помощь в продажах?
- Клиентские сегменты: кто ваши лучшие клиенты по сравнению со случайными пользователями?
- Конкуренты: с кем вас сравнивают клиенты и сколько это стоит?
- Структура затрат: во сколько вам обходится обслуживание одного клиента в месяц?

### 3. Цели { #3-goals }
- Вы разрабатываете, оптимизируете или планируете повышение цен?
- Какие-либо ограничения? (например, клиенты-дедушки, договорные ограничения, маржа партнеров по каналам сбыта)

## Как работает этот Скилл { #how-this-skill-works }

### Режим 1: Разработка ценообразования с нуля { #mode-1-design-pricing-from-scratch }
Начинать без модели ценообразования или полностью перестраиваться. Мы проработаем выбор показателей ценности, структуру уровней, исследование ценовых показателей и дизайн страницы с ценами.

### Режим 2: Оптимизация существующих цен { #mode-2-optimize-existing-pricing }
Ценообразование существует, но конверсия низкая, расширение незначительное или клиенты чувствуют, что цена завышена. Мы проведем аудит того, что там есть, проведем сравнительный анализ и определим конкретные улучшения.

### Способ 3: Спланируйте повышение цен { #mode-3-plan-a-price-increase }
Цены должны расти — из-за инфляции, повышения стоимости или изменения положения на рынке. Мы разработаем стратегию, которая увеличит доход, не сжигая клиентов.

## Три ценовые оси { #the-three-pricing-axes }

Каждое ценовое решение зависит от трех факторов. Сделайте все три правильно.

```
         ┌─────────────────┐
         │   PACKAGING     │  What's in each tier?
         │  (what you get) │
         └────────┬────────┘
                  │
         ┌────────┴────────┐
         │  VALUE METRIC   │  What do you charge for?
         │ (how it scales) │
         └────────┬────────┘
                  │
         ┌────────┴────────┐
         │  PRICE POINT    │  How much?
         │    (the number) │
         └─────────────────┘
```

Большинство команд сразу переходят к вопросу о цене. Это наоборот. Сначала зафиксируйте метрику, затем упаковку, затем проверьте номер.

## Выбор показателя значения { #value-metric-selection }

Ваш показатель ценности определяет, как ценообразование соотносится с ценностью для клиентов. Сделав неправильный выбор, вы либо оставляете деньги на столе, либо создаете трения, которые убивают рост.

### Общие показатели ценности для SaaS { #common-value-metrics-for-saas }

| Метрика | Лучше всего подходит для | Пример |
|--------|---------|---------|
| **На одно место / пользователя** | Инструменты для совместной работы, CRM | Salesforce, Понятие, Линейный |
| **За одно использование** | Инструменты API, инфраструктура, искусственный интеллект | Полоса, Twilio, OpenAI |
| **Для каждой функции** | Игры на платформе, дополнения | Домофон, точка доступа |
| **Фиксированная плата** | Неограниченные возможности, инструменты SMB | Базовый лагерь, Календарно базовый |
| **По каждому результату** | Высокая, измеримая рентабельность инвестиций | Инструменты, основанные на комиссионных |
| **Гибрид** | Сочетание вышеперечисленного | Самые зрелые SAAS |

### Как выбрать { #how-to-choose }

Ответьте на эти вопросы:

1. **Что заставляет клиента платить больше?** → Это ваш показатель ценности
2. ** Зависит ли показатель от их успеха?** → Если они растут, растете и вы
3. ** Легко ли это понять?** → Сложность убивает конверсию
4. ** Сложно ли играть? ** → Клиенты не должны иметь возможности обойти это

**Красные флаги:**
- "На одно место" в инструменте, где всю работу выполняет один опытный пользователь → количество мест не зависит от значения
- "Фиксированная плата", когда одни клиенты получают в 10 раз больше, чем другие → вы субсидируете активных пользователей
- "За каждый вызов API", когда количество вызовов сильно меняется от недели к неделе → непредсказуемые счета = отток

## Структура уровней "Хорошо-лучше-Наилучший" { #good-better-best-tier-structure }

Стандарт - это три яруса. Не из—за традиции - потому что она закрепляет восприятие.

### Принципы проектирования уровней { #tier-design-principles }

**Начальный уровень (хороший):**
- Охватывает сегмент, который будет оттоковываться при более высокой цене
- Ограничено — либо функциями, использованием, либо поддержкой
- НЕ бесплатно. Free - это отдельная стратегия (freemium), а не уровень.
- Должно покрывать ваши расходы по минимуму

**Средний уровень (лучше) — по умолчанию:**
- Именно здесь вы подталкиваете большинство клиентов
- Цена: в 2-3 раза выше начального уровня
- Особенности: все, что нужно растущей компании
- Вызовите это визуально, как рекомендовано

**Высший уровень (лучший):**
- Для ценных клиентов с корпоративными потребностями
- Это может быть "Свяжитесь с нами" или индивидуальная цена
- Разблокирует: единый вход, журналы аудита, соглашение об уровне обслуживания, выделенную поддержку, пользовательские контракты
- Если у вас есть корпоративные сделки на сумму более 1 тыс. долл. США в год, этот уровень существует для их учета

### Что входит в каждый уровень { #what-goes-in-each-tier }

| Категория объектов | Запись | Лучше | Лучший |
|----------------|-------|--------|------|
| Основной продукт | ✅ (ограничено) | ✅ (полный) | ✅ (полный) |
| Ограничения по использованию | Низкий | Средний | Высокий / неограниченный |
| Пользователи/seats | 1-3 | 5-неограниченное количество | Неограниченный |
| Интеграции | Базовый | Полный | Полный + пользовательский |
| Отчетность | Базовый | Продвинутый | Обычай |
| Поддержка | Электронная почта | Приоритет | Выделенный CSM |
| Функции администратора | — | — | Единый вход, журнал аудита, SCIM |
| Соглашение об уровне обслуживания | — | — | ✅ |

Видишь [ссылки/pricing-models.md](references/pricing-models.md) для модельных глубоких погружений и примеров SaaS.

## Ценообразование, основанное на ценности { #value-based-pricing }

Цена между следующей лучшей альтернативой и вашей воспринимаемой ценностью.

```
[Cost of doing nothing] ... [Next-best alternative] ... [YOUR PRICE] ... [Perceived value delivered]
```

**Шаг 1: Определите следующую наилучшую альтернативу**
- Что бы сделал клиент, если бы вашего продукта не существовало?
- Конкурент? Электронная таблица? Ручной процесс? Нанимать кого-то?
- Чего им это стоит?

**Шаг 2: Оцените полученную стоимость**
- Сэкономленное время × почасовая ставка человека, использующего его
- Генерируемый или защищаемый доход
- Цена ошибки/risk избегаемый
- Спросите своих лучших клиентов: "Что вы потеряете, если перестанете пользоваться нами завтра?"

**Шаг 3: Цена посередине**
- Приблизительная эвристика: цена составляет 10-20% от задокументированной стоимости поставленной продукции
- Не назначайте цену в размере 50% от стоимости — клиенты чувствуют, что переплачивают
- Не назначайте цену ниже следующей лучшей альтернативы - это сигнализирует о том, что вы не верите в свой собственный продукт

**Коэффициент преобразования в качестве сигнала:**
- >40% от платной пробной версии: вероятно, цена занижена — протестируйте повышение цены
- 15-30%: полезно для большинства SAAS
- <10%: цены могут быть высокими, или при переходе от пробной версии к платной возникают трения

## Методы исследования ценообразования { #pricing-research-methods }

### Измеритель ценовой чувствительности Ван Вестендорпа { #van-westendorp-price-sensitivity-meter }

Четыре вопроса, заданные текущим клиентам или целевому сегменту:

1. По какой цене этот продукт был бы настолько дешевым, что вы бы усомнились в его качестве?
2. По какой цене этот продукт был бы выгодной сделкой?
3. При какой цене этот продукт начнет казаться дорогим — все еще приемлемым?
4. По какой цене этот продукт был бы слишком дорогим, чтобы его рассматривать?

** Интерпретируйте результаты:** Постройте четыре кривые. Пересечение понятий "слишком дешево" и "слишком дорого" дает ваш приемлемый ценовой диапазон. Пересечение понятий "выгодный" и "дорогой" дает оптимальную цену.

** Когда использовать:** B2B SaaS, n≥30 респондентов, существующие клиенты или квалифицированные потенциальные клиенты.

### Анализ MaxDiff { #maxdiff-analysis }

Показывать респондентам наборы функций/prices и спросите, что они ценят больше всего, а что меньше всего. Статистический анализ показывает относительную ценность каждой функции — упаковка информирует больше, чем цена.

** Когда использовать: ** При принятии решения о том, какие функции поместить на какой уровень.

### Сравнительный анализ конкурентов { #competitor-benchmarking }

| Шаг | Что делать |
|------|-----------|
| 1 | Перечислите прямых конкурентов и альтернативы, которые рассматривают клиенты |
| 2 | Запишите их опубликованные расценки (названия планов, цены, показатели ценности). |
| 3 | Обратите внимание, что включено в каждую ценовую категорию |
| 4 | Определите, где в вашем продукте перевыполнение или недопоставка по сравнению с каждым другим |
| 5 | Цена относительно позиционирования: премия = на 20-40% выше рыночной, стоимость = на уровне или ниже |

** Не просто копируйте цены конкурентов ** — их цены отражают их структуру затрат и позиционирование, а не ваши.

## Стратегии повышения цен { #price-increase-strategies }

Повышение цен - один из способов получения максимальной рентабельности инвестиций, доступных SaaS-компаниям. Большинство ждет слишком долго.

### Выбор стратегии { #strategy-selection }

| Стратегия | Используйте, когда | Риск |
|---------|---------|------|
| **Только для новых клиентов** | Ожидается значительный откат | Низкий — не затрагивает существующую базу |
| **Дедушка + задержка** | Постоянная клиентская база, риск заключения контракта | Средний уровень — существующие клиенты чувствуют уважение |
| **Привязан к доставке ценности** | Понятные новые функции/improvement | Низкий уровень — оправданный |
| **Планируйте реструктуризацию** | Значительное изменение упаковки | Средней сложности для клиентов |
| **Равномерное увеличение** | Уверенный в ценности, цена явно ниже рыночной | Средне-высокий |

### Чек-лист для выполнения (Checklist Execution Execution) { #execution-checklist }

1. ** Количественная оценка перехода:** Рассчитайте новый MRR при 100%, 80%, 70% удержании существующих клиентов
2. ** Сегментация по рискам:** Годовые контракты, победители против недоброжелателей, учетные записи, подверженные риску на основе использования
3. ** Установите дату:** уведомление за 60-90 дней для существующих клиентов. минимум 30 дней.
4. **Сообщите причину:** Новые функции, растущие затраты, инвестиции в [X] — будьте конкретны
5. ** Предложите путь:** Зафиксируйте текущую цену для годового обязательства или предоставьте 3-месячный период
6. ** Вооружите свою команду CS:** Часто задаваемые вопросы, тезисы для обсуждения, полномочия по утвержденному предложению
7. ** Отслеживайте в течение 60 дней:** Уровень оттока, уровень понижения рейтинга, объем заявок в службу поддержки

**Ожидаемый отток в результате повышения цен на 20-30%:** 5-15%. Если влияние на ваш чистый доход положительное, продолжайте.

## Дизайн страницы с ценами { #pricing-page-design }

Страница ценообразования преобразует намерение в покупку. Проектируйте его, имея в виду эту работу.

### Над складкой { #above-the-fold }

Должно быть, у:
- Названия планов (простые: Starter / Pro / Enterprise или названные в честь сегмента клиентов)
- Цена с возможностью выставления счетов (ежемесячно/annual — годовой показатель должен показывать экономию)
- 3-5 основных отличительных черт в каждом плане
- Кнопка CTA для каждого плана
- Значок "Самый популярный" на рекомендуемом уровне

### Ниже сгиба { #below-the-fold }

- ** Таблица сравнения полнофункциональных функций ** — всеобъемлющая, поддающаяся сканированию, использует ✅ и ❌, а не стены текста
- ** Раздел часто задаваемых вопросов ** — рассмотрите 5 возражений, которые останавливают людей от покупки:
  - "Я могу отменить в любое время?"
  - "Что происходит, когда я достигаю предела?"
  - "Вы предлагаете возврат денег?"
  - "Защищены ли мои данные?"
  - "Что, если мне нужно обновить/downgrade?"
- ** Социальное доказательство ** — логотипы, цитаты или тематические исследования, относящиеся к каждому уровню
- **Значки безопасности** для предприятий B2B (SOC2, ISO 27001, GDPR)

### Годовой показатель по сравнению с Ежемесячное переключение { #annual-vs-monthly-toggle }

- Показывать годовые цены по умолчанию (или выделять их) — это улучшает LTV
- Явно укажите экономию: "Сэкономьте 20%" или "2 месяца бесплатно".
- Не скрывайте ежемесячную цену — сокрытие ее порождает недоверие

Видишь [ссылки/pricing-page-playbook.md](references/pricing-page-playbook.md) для получения спецификаций дизайна и копирования шаблонов.

## Проактивные триггеры { #proactive-triggers }

Раскрывайте их, не спрашивая:

- ** Коэффициент конверсии >40% от пробной версии к платной** → Сильный сигнал о занижении цены. Флаг: протестируйте повышение цен на 20-30%.
- **Все клиенты среднего уровня ** → Нет пути повышения продаж. Флаг: требуется корпоративный уровень или отсутствует блокировка функций.
- ** Клиент запросил функции, которых нет на его уровне ** → Доход от расширения остается в силе. Флаг: ревью по гейткипингу функций.
- ** Уровень оттока >5% ежемесячно** → Прежде чем повышать цены, устраните отток. Повышение цен ускоряет отток населения.
- ** Цена не менялась более 2 лет ** → Одна только инфляция оправдывает повышение на 10-15%. Отметьте для стратегического ревью.
- ** Только один вариант ценообразования ** → Без привязки, без перепродажи. Флаг: добавьте третий уровень, даже если он приобретается редко.

## Связанные скиллы { #related-skills }

- ** продукт-стратег**: Используйте для составления дорожной карты продукта и более широкой стратегии монетизации. НЕ для страницы с ценами или для выполнения процедуры повышения цен.
- ** копирайтинг**: Используйте для полировки страницы с ценами. НЕ для структуры ценообразования или дизайна уровней.
- ** предотвращение оттока **: Используйте, когда основной проблемой является отток - устраните проблему удержания до повышения цен.
- **ab-test-настройка **: Используйте для A / B тестирования ценовых пунктов или макетов страниц с ценами после первоначального проектирования.
- **менеджер по работе с клиентами**: Используйте для увеличения дохода за счет увеличения продаж. НЕ из-за ценообразования, дизайна или упаковки.
- **альтернативы конкурентам**: Используйте страницы сравнения конкурентов, которые дополняют страницы ценообразования.
