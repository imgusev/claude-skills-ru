# /cs: мощность-план — операции определение мощности + риск использования + последовательность найма { #cscapacity-plan--ops-capacity-sizing--utilization-risk--hiring-sequence }

Запустите `capacity-planner` скилл на основе этого ввода:

**$АРГУМЕНТЫ**

## Воркфлоу с тремя инструментами { #three-tool-workflow }

1. **`capacity_modeler.py`** — Математика Erlang-C / массового обслуживания: требуемый FTE при загрузке 70/80/90%, P (нарушение SLA) для каждого уровня загрузки, запас пропускной способности. Отраслевая настройка `--profile {support,cx,bizops,finance-ops,it-ops}`.

2. **`utilization_analyzer.py`** — Обнаружение красной зоны для каждого члена команды: >85% устойчиво = снижение производительности (закон Литтла), <40% = недостаточная загрузка или неправильные скиллы, отклонение >30% = несбалансированность. Вердикт: ЗДОРОВ/ ЗАЖАТ/ ПЕРЕГРУЖЕН/ НЕУРАВНОВЕШЕН.

3. **`hiring_sequencer.py`** — 12-месячный квартальный план найма с учетом кривой роста (50% продуктивных недель с 1 по N, 100% после) + выбытие + рост. Отображает точку "триггера диспетчера" (диапазон управления >7-8 микросхем).

## Жесткое правило { #hard-rule }

** Никогда не планируйте 100%-ную загрузку.** Райнерцен 2009: загрузка >80% в умственной работе снижает пропускную способность из-за очередей.

## Отличный от { #distinct-from }

- `c-level-advisor/vpe-advisor` — в частности, инженерная пропускная способность. Планировщик мощностей предназначен для оперативных групп, не являющихся англичанами.
- `c-level-advisor/chro-advisor` — стратегическое кадровое планирование. Планировщик мощностей - это тактический расчет размеров.
- `business-operations/skills/process-mapper` (брат или сестра) — находит узкое место. Планировщик производственных мощностей формирует команду вокруг себя.
- `project-management/*` — отслеживание доставки. Планировщик мощностей - это предварительное определение размера.
