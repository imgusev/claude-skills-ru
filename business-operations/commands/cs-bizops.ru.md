# /cs:bizops — Маршрутизатор бизнес-операций { #csbizops--business-operations-router }

Используйте `cs-bizops-orchestrator` агент + `business-operations-skills` скилл оркестратора для обработки этого запроса:

**$ARGUMENTS**

## Протокол маршрутизации { #routing-protocol }

1. Классифицируйте запрос по шести полосам BizOps:
   - **ПРОЦЕСС** — узкое место, время цикла, хэндофф, воркфлоу → `process-mapper`
   - **ПОСТАВЩИК** — Соглашение об уровне обслуживания, риски третьих лиц, аудит SaaS → `vendor-management`
   - **МОЩНОСТЬ** — численность персонала, загрузка, последовательность найма → `capacity-planner`
   - **СВЯЗЬ** — общий доступ, объявление об изменениях, внутренняя рассылка → `internal-comms`
   - **ЗНАНИЯ** — СОП, рансбук, онбординг doc → `knowledge-ops`
   - **ЗАКУПКИ** — провести аудит, рационализацию поставщиков → `procurement-optimizer`

2. Если показатель сигнала верхней полосы движения ≥ 2 попаданий по ключевому слову → вызовите этот вспомогательный скилл в раздвоенном контексте.

3. Если одиночный сигнал или ничья → задайте **один** уточняющий вопрос, назвав две верхние полосы движения-кандидата.

4. После запуска вспомогательного скилла верните дайджест из 200 слов в родительский контекст.

## Ожидаемые результаты { #output-expectations }

- Что было проанализировано
- Топ-3 результатов по степени тяжести (КРИТИЧЕСКИЙ/ВЫСОКИЙ/СРЕДНИЙ)
- Топ-3 следующих действий с названными владельцами
- Путь к артефактам, сохраненным в рабочем каталоге пользователя
- Предлагаемая цепочка (какой вспомогательный скилл использовать следующим, если таковой имеется)

## Анти-паттерны { #anti-patterns }

- ❌ Тщательное освоение нескольких вспомогательных скилл - выберите один, переварите, объедините в цепочку по запросу
- ❌ Автоматическое утверждение изменений в операции — по результатам поверхностного анализа человек принимает решение
