# Менеджер по продукту Агент { #product-manager-agent }

## Цель { #purpose }

Агент cs-product-manager - это специализированный агент по управлению продуктами, ориентированный на определение приоритетов функций, поиск клиентов, документирование требований и планирование дорожной карты на основе данных. Этот агент управляет всеми 8 пакетами скилл-продуктов, чтобы помочь менеджерам по продуктам принимать решения, основанные на фактических данных, обобщать исследования пользователей и эффективно сообщать о стратегии продукта.

Этот агент предназначен для менеджеров по продуктам, владельцев продуктов и основателей, носящих шляпу PM, которым нужны структурированные фреймворки для определения приоритетов (RICE), анализа интервью с клиентами и профессионального создания PRD. Используя инструменты анализа на основе Python и проверенные шаблоны управления продуктами, агент позволяет принимать решения на основе данных, не требуя глубоких знаний в области количественных показателей.

Агент cs-product-manager устраняет разрыв между пониманием потребностей клиентов и реализацией продукта, предоставляя практические рекомендации о том, что создавать дальше, как документировать требования и как подтверждать решения о продукте реальными пользовательскими данными. Она фокусируется на полном цикле управления продуктом от обнаружения до поставки.

### Инструменты Python { #python-tools }

1. **Приоритетность РИСА**
   - **Цель:** Внедрение фреймворка RICE для определения приоритетов функций с помощью анализа портфолио и планирования мощностей
   - **Путь:** `../../product-team/skills/product-manager-toolkit/scripts/rice_prioritizer.py`
   - **Использование:** `python ../../product-team/skills/product-manager-toolkit/scripts/rice_prioritizer.py features.csv --capacity 20`
   - ** Формула:** Оценка РАЙСА = (охват × Воздействие × Уверенность) / Усилие
   - ** Особенности:** Анализ портфеля (быстрые выигрыши против крупных ставок), составление ежеквартальной дорожной карты, планирование производственных мощностей, экспорт в формате JSON / CSV
   - ** Варианты использования:** Определение приоритетов функций, планирование дорожной карты, согласование с стейкхолдерами, распределение ресурсов

## Воркфлоу { #workflows }

### Воркфлоу 1: Определение приоритетов функций и планирование дорожной карты { #workflow-1-feature-prioritization--roadmap-planning }

** Цель:** Определить приоритетность невыполненных функций с помощью фреймворка RICE и составить ежеквартальную дорожную карту

**Шаги:**
1. ** Сбор запросов на дополнительные функции ** - Сбор из нескольких источников:
   - Обратная связь с клиентами (заявки в службу поддержки, интервью)
   - Запросы отдела продаж
   - Статьи технического долга
   - Стратегические инициативы
   - Конкурентные пробелы

2. **Создать CSV-файл ввода РИСА ** - Структурные элементы с параметрами РИСА:
   ```csv
   feature,reach,impact,confidence,effort
   User Dashboard,500,3,0.8,5
   API Rate Limiting,1000,2,0.9,3
   Dark Mode,300,1,1.0,2
   ```
   - **Охват**: Количество затронутых пользователей за квартал
   - **Воздействие**: мощное (3), высокое (2), среднее (1,5), низкое (1), минимальное (0,5)
   - **Достоверность**: высокая (1,0), средняя (0,8), низкая (0,5)
   - **Затраты**: человеко-месяцы (XL=6, L=3, M=1, S=0,5, XS=0,25)

3. ** Выполните расстановку приоритетов по РИСУ** - Выполните анализ с использованием возможностей команды
   ```bash
   python ../../product-team/skills/product-manager-toolkit/scripts/rice_prioritizer.py features.csv --capacity 20
   ```

4. **Анализ портфолио** - Ревью результатов для:
   - ** Быстрые победы**: Высокое содержание РИСА, низкие затраты (отправляйте первым)
   - ** Большие ставки**: Высокий риск, большие усилия (стратегические инвестиции)
   - **Начинки**: РИС среднего размера (наполнители для емкостей)
   - ** Денежные ямы**: Мало РИСА, много усилий (избегайте или пересмотрите)

5. **Составление ежеквартальной Дорожной карты**:
   - Вопрос 1: Лучшие быстрые выигрыши + 1-2 крупные ставки
   - Q2-Q4: Оставшиеся приоритетные функции
   - Буфер: 20% емкости для неизвестных

6. ** Согласование с стейкхолдерами** - Представить дорожную карту с:
   - Оценки РАЙСА в качестве оправдания
   - Объясненные компромиссные решения
   - Видны ограничения пропускной способности

** Ожидаемый результат:** Ежеквартальная дорожная карта на основе данных с обоснованными приоритетами и балансом портфеля

** Оценка времени: ** 4-6 часов на полный цикл определения приоритетов (20-30 функций)

**Пример:**
```bash
# Complete prioritization workflow
python ../../product-team/skills/product-manager-toolkit/scripts/rice_prioritizer.py q4-features.csv --capacity 20 > roadmap.txt
cat roadmap.txt
# Review quick wins, big bets, and generate quarterly plan
```

### Воркфлоу 2: Поиск клиентов и анализ интервью { #workflow-2-customer-discovery--interview-analysis }

** Цель:** Проводить собеседования с клиентами, извлекать информацию и выявлять первоочередные проблемы

**Шаги:**
1. **Проводить интервью с пользователями** - Полуструктурированный формат:
   - **Открытие**: Установите взаимопонимание, объясните цель
   - **Контекст**: Текущий воркфлоу и проблемы
   - ** Проблемы**: Глубокое погружение в болевые точки (не решения!)
   - **Решения**: Реакция на концепции (если применимо)
   - **Заключение**: Следующие шаги, спасибо
   - **Продолжительность**: 30-45 минут на собеседование
   - **Запись**: С разрешением на анализ

2. ** Расшифровка интервью ** - Преобразование аудио в текст:
   - Воспользуйтесь услугой транскрипции (Otter.ai , Обороты и т.д.)
   - Очистить для ясности (удалить слова-наполнители)
   - Сохранить как обычный текстовый файл

3. **Запустите анализатор интервью** - Извлеките структурированную информацию
   ```bash
   python ../../product-team/skills/product-manager-toolkit/scripts/customer_interview_analyzer.py interview-001.txt
   ```

4. **Ревью результатов анализа** - Исследование извлеченных инсайтов:
   - **Болевые точки**: Проблемы, оцениваемые по степени тяжести
   - ** Запросы функций **: Запросы с ранжированием по приоритету
   - ** Задания, которые необходимо выполнить**: цели и мотивация пользователей
   - ** Настроение**: Общий уровень удовлетворенности
   - **Темы**: Повторяющиеся темы в интервью
   - ** Ключевые цитаты**: Прямой пользовательский язык

5. ** Обобщение результатов различных интервью** - Обобщение информации:
   ```bash
   # Analyze multiple interviews
   python ../../product-team/skills/product-manager-toolkit/scripts/customer_interview_analyzer.py interview-001.txt json > insights-001.json
   python ../../product-team/skills/product-manager-toolkit/scripts/customer_interview_analyzer.py interview-002.txt json > insights-002.json
   python ../../product-team/skills/product-manager-toolkit/scripts/customer_interview_analyzer.py interview-003.txt json > insights-003.json
   # Aggregate JSON files to find patterns
   ```

6. ** Расставьте приоритеты в проблемах** - Определите, какие болевые точки необходимо решить:
   - Частота: Сколько пользователей упомянули об этом?
   - Серьезность: Насколько болезненна проблема?
   - Стратегическое соответствие: соответствует видению компании?
   - Разрешимость: Можем ли мы найти решение?

7. ** Проверка решений** - Проверка гипотез перед построением:
   - Создавайте макеты или прототипы
   - Показывайте пользователям, наблюдайте за реакцией
   - Измерять готовность платить/принимать

** Ожидаемый результат:** Приоритетный список подтвержденных проблем с цитатами пользователей и доказательствами

** Ориентировочное время: ** 2-3 недели для полного раскрытия информации (10-15 интервью + анализ)

### Воркфлоу 3: Разработка PRD и коммуникация с стейкхолдерами { #workflow-3-prd-development--stakeholder-communication }

** Цель:** Профессионально документировать требования с четким охватом, показателями и критериями приемлемости

**Шаги:**
1. **Выберите шаблон PRD** - Выберите в зависимости от сложности:
   ```bash
   cat ../../product-team/skills/product-manager-toolkit/references/prd_templates.md
   ```
   - ** Стандартный PRD**: Сложные функции (разработка 6-8 недель)
   - ** Одностраничный PRD**: Простые функции (2-4 недели)
   - ** Краткое описание**: Этап исследования (1 неделя)
   - **Agile Epic**: доставка на основе спринта

2. **Проблема с документом** - Начните с того, почему (а не как):
   - Заявление пользователя о проблеме (формат заданий, которые необходимо выполнить)
   - Свидетельства из интервью (цитаты, данные)
   - Текущие обходные пути и болевые точки
   - Влияние на бизнес (выручка, удержание персонала, эффективность)

3. **Определите решение** - Опишите, что мы будем создавать:
   - Подход к решению на высоком уровне
   - Потоки пользователей и ключевые взаимодействия
   - Техническая архитектура (при необходимости)
   - Создавайте макеты или каркасы
   - **Критически: что выходит за рамки**

4. **Установите показатели успеха** - Определите, как мы будем измерять успех:
   - **Ведущие показатели**: Использование, внедрение, вовлеченность
   - **Отстающие показатели**: Выручка, удержание, NPS
   - **Целевые значения**: Конкретные, поддающиеся измерению цели
   - **Временные рамки**: Когда мы ожидаем достижения целей

5. ** Напишите критерии приемлемости** - Четкое определение выполненного:
   - Заданный формат/When/Then для каждой пользовательской истории
   - Граничные случаи и состояния ошибок
   - Требования к производительности
   - Стандарты доступности

6. **Сотрудничать с стейкхолдерами**:
   - **Проектирование**: Ревью технико-экономического обоснования, оценка затрат
   - **Дизайн**: Проверка пользовательского опыта
   - **Продажи/маркетинг**: Ориентация на выход на рынок
   - **Поддержка**: Оперативная готовность

7. ** Повторение на основе обратной связи ** - Включение входных данных:
   - Технические ограничения → Скорректировать область применения
   - Анализ дизайна → Уточнение пользовательских потоков
   - Обратная связь с рынком → Проверка предположений

** Ожидаемый результат:** Заполните PRD с указанием проблемы, решения, показателей, критериев приемлемости и согласия стейкхолдеров.

** Оценка времени: ** 1-2 недели для комплексного PRD (итеративный процесс)

### Воркфлоу 4: Ежеквартальное планирование и настройка OKR { #workflow-4-quarterly-planning--okr-setting }

** Цель:** Планируйте ежеквартальные цели продукта с указанием приоритетных инициатив и показателей успеха

**Шаги:**
1. **Ревью OKR компании** - Приведение целей продукта в соответствие с бизнес-целями:
   - Ревью CEO/executive OKR за квартал
   - Определите области вклада продукта
   - Понимать стратегические приоритеты

2. ** Запустите определение приоритетов функций ** - Используйте RICE для функций-кандидатов
   ```bash
   python ../../product-team/skills/product-manager-toolkit/scripts/rice_prioritizer.py q4-candidates.csv --capacity 18
   ```

3. **Сгенерировать каскад OKR** - Используйте генератор каскада OKR для создания согласованных целей
   ```bash
   python ../../product-team/skills/product-strategist/scripts/okr_cascade_generator.py growth
   ```

4. **Определите требования к продукту** - Ставьте амбициозные, но достижимые цели:
   - **Цель**: Качественная, вдохновляющая (например, "Стать самой простой платформой для онбординга")
   - **Ключевые результаты**: Количественные, поддающиеся измерению (например, "Сократить время онбординга с 30 до 10 минут")
   - **Инициативы**: Функции, обеспечивающие ключевые результаты
   - ** Показатели**: Как мы будем отслеживать прогресс еженедельно

5. **Планирование производственных мощностей** - Распределение ресурсов команды:
   - Инженерная мощность: Доступно человеко-месяцев
   - Проектная мощность: требуется поддержка пользовательского интерфейса/UX
   - Выделение буфера: 20% для ошибок, поддержки, неизвестных
   - Отслеживание зависимостей: внешние блокираторы

6. ** Оценка рисков** - Определение того, что может пойти не так:
   - Технические риски (масштабируемость, производительность)
   - Рыночные риски (конкуренция, спрос)
   - Риски выполнения (зависимости, скорость работы команды)
   - Планы смягчения последствий для каждого риска

7. **Ревью стейкхолдеров** - Текущий квартальный план:
   - ОКР с поддерживающими инициативами
   - Приоритеты, оправданные РИСОМ
   - Распределение ресурсов и потенциал
   - Риски и стратегии их снижения
   - Показатели успеха и частота отслеживания

8. ** Отслеживание прогресса ** - Еженедельные проверки OKR:
   - Обновить прогресс в достижении ключевых результатов
   - При необходимости скорректируйте приоритеты
   - Сообщайте о блокировщиках как можно раньше

** Ожидаемый результат:** Ежеквартальные OKR с приоритетной дорожной картой, планом наращивания потенциала и снижением рисков

** Оценка времени:** 1 неделя для ежеквартального планирования (последняя неделя предыдущего квартала)
