## Воркфлоу внедрения СМК { #qms-implementation-workflow }

Внедрите систему менеджмента качества, соответствующую стандарту ISO 13485:2016, начиная с анализа пробелов и заканчивая сертификацией.

### Воркфлоу: Первоначальное внедрение СМК { #workflow-initial-qms-implementation }

1. Провести анализ несоответствий требованиям стандарта ISO 13485:2016
2. Документируйте текущее состояние по сравнению с требуемым состоянием для каждого предложения
3. Определите приоритетность пробелов с помощью:
   - Критичность регулирования
   - Риск для безопасности продукта
   - Потребности в ресурсах
4. Разработать дорожную карту внедрения с указанием основных этапов
5. Разработать руководство по качеству в соответствии с пунктом 4.2.2:
   - Сфера применения СМК с обоснованными исключениями
   - Взаимодействие процессов
   - Ссылки на процедуры
6. Создайте необходимые документированные процедуры — смотрите [Обязательные документированные процедуры](#quick-reference-mandatory-documented-procedures) для получения полного списка
7. Деплей-процессы с обучением
8. **Валидация:** Завершен анализ пробелов; Утверждено руководство по качеству; все необходимые процедуры задокументированы и обучены

> Используйте шаблон матрицы анализа пробелов в [qms-process-templates.md](references/qms-process-templates.md) документировать постатейно текущее состояние, пробелы, приоритеты и действия.

### Структура СМК { #qms-structure }

| Уровень | Тип документа | Пример |
|-------|---------------|---------|
| 1 | Руководство по качеству | QM-001 |
| 2 | Процедуры | СОП-02-001 |
| 3 | Инструкции по работе | WI-06-012 |
| 4 | Записи | Записи о тренировках |

## Воркфлоу для управления документооборотом { #document-control-workflow }

Установите и поддерживайте контроль документации в соответствии с пунктом 4.2.3 стандарта ISO 13485.

### Воркфлоу: Создание и утверждение документов { #workflow-document-creation-and-approval }

1. Определить необходимость в новом документе или доработке
2. Присвоение номера документу в соответствии с соглашением о нумерации:
   - Формат: `[TYPE]-[AREA]-[SEQUENCE]-[REV]`
   - Пример: `SOP-02-001-01`
3. Проект документа с использованием утвержденного шаблона
4. Маршрут для ревью к экспертам в данной области
5. Собирайте комментарии к ревью и отвечайте на них
6. Получите необходимые разрешения в зависимости от типа документа
7. Обновить основной список документов
8. ** Проверка:** Документ пронумерован правильно; все рецензенты подписаны; Основной список обновлен

### Соглашение о нумерации документов { #document-numbering-convention }

| Префикс | Тип документа | Уполномоченный орган по утверждению |

## Воркфлоу внутреннего аудита { #internal-audit-workflow }

Планируйте и проводите внутренние аудиты в соответствии с пунктом 8.2.4 стандарта ISO 13485.

### Воркфлоу: Ежегодная программа аудита { #workflow-annual-audit-program }

1. Определите процессы и области, требующие охвата аудитом
2. Оценка факторов риска для периодичности проведения аудита:
   - Выводы предыдущего аудита
   - Изменения в законодательстве
   - Изменения в процессе
   - Тенденции подачи жалоб
3. Назначить квалифицированных аудиторов (независимо от области, в которой проводится аудит)
4. Разработать график ежегодного аудита
5. Получить одобрение руководства
6. Сообщайте расписание владельцам процессов
7. Отслеживайте завершение и переносите сроки по мере необходимости
8. **Валидация:** Охвачены все процессы; аудиторы квалифицированы и независимы; утвержден график

> Используйте шаблон программы аудита в [qms-process-templates.md](references/qms-process-templates.md) планировать аудиты по пунктам и кварталам в таких процессах, как Контроль документации (4.2.3/4.2.4), ревью руководства (5.6), Контроль проектирования (7.3), производство (7.5) и CAPA (8.5.2/8.5.3).

### Воркфлоу: Выполнение индивидуального аудита { #workflow-individual-audit-execution }

1. Подготовьте план аудита с указанием объема, критериев и графика
2. Уведомить проверяемую организацию минимум за 1 неделю до этого
3. Процедуры ревью и результаты предыдущего аудита
4. Подготовьте чек-лист для аудита audit audit
5. Провести вступительное заседание
6. Собирать доказательства с помощью:
   - Ревью документов
   - Запись выборки
   - Наблюдение за процессом
   - Собеседования с персоналом
7. Классифицировать находки:
   - Основной ЧПУ: Отсутствие или поломка системы
   - Незначительный ЧПУ: единичный сбой или отклонение
   - Наблюдение: Риск возникновения в будущем НЗ
8. Провести заключительное заседание
9. Выдать отчет о аудите в течение 5 рабочих дней
10. **Проверка:** Рассмотрены все пункты чек-листа; выводы подтверждены доказательствами; отчет распространен

### Квалификационные требования к аудитору { #auditor-qualification-requirements }

| Критерий | Требование |
|-----------|-------------|
| Тренировка | Осведомленность об ISO 13485 + обучение аудиторов |
| Опыт | Минимум 1 аудит в качестве наблюдателя |
| Независимость | Не проводит аудит собственной рабочей области |
| Компетентность | Понимание процесса аудита |

### Руководство по поиску классификации { #finding-classification-guide }

| Классификация | Критерии | Время отклика |
|----------------|----------|---------------|
| Основной ЧПУ | Отсутствие системы, полный сбой, нарушение нормативных требований | 30 дней для CAPA |
| Незначительный ЧПУ | Единичный случай, частичное соответствие | 60 дней для CAPA |
| Наблюдение | Потенциальный риск, возможность улучшения | Отслеживать в следующем аудите |

## Воркфлоу проверки процесса { #process-validation-workflow }

Проверка специальных процессов в соответствии с пунктом 7.5.6 стандарта ISO 13485.

### Воркфлоу: Протокол проверки процесса { #workflow-process-validation-protocol }

1. Определите процессы, требующие проверки:
   - Выходные данные не могут быть проверены с помощью проверки
   - Недостатки проявляются только при использовании
   - Стерилизация, сварка, герметизация, программное обеспечение
2. Группа проверки формы с экспертами по предмету
3. Напишите протокол проверки, включающий:
   - Описание процесса и параметры
   - Оборудование и материалы
   - Критерии приемлемости
   - Статистический подход
4. Выполните IQ: проверьте правильность установки оборудования и задокументируйте технические характеристики
5. Выполните OQ: проверьте диапазоны параметров и проверьте управление технологическим процессом
6. Выполните PQ: запустите производственные условия и убедитесь, что выходные данные соответствуют требованиям
7. Напишите отчет о проверке с выводами
8. **Валидация:** IQ/OQ/PQ завершена; критерии приемлемости выполнены; отчет о валидации утвержден

### Требования к подтверждающей документации { #validation-documentation-requirements }

| Фаза | Содержание | Доказательства |
|-------|---------|----------|
| Протокол | Цели, методы, критерии | Утвержденный протокол |
| Коэффициент интеллекта | Проверка оборудования | Записи об установке |
| OQ | Проверка параметров | Результаты тестирования |
| PQ | Проверка работоспособности | Производственные данные |
| Отчет | Резюме, выводы | Подписи об утверждении |

### Триггеры повторной проверки { #revalidation-triggers }

| Триггер | Требуемые действия |
|---------|-----------------|
| Замена оборудования | Оценка воздействия, повторная проверка затронутых этапов |
| Изменение параметра | Минимальное значение OQ и PQ |
| Существенное изменение | Оценка воздействия, минимум PQ |
| Сбой процесса | Полная повторная проверка |
| Периодический | В соответствии с графиком проверки (обычно 3 года) |

### Примеры специальных процессов { #special-process-examples }

| Процесс | Стандарт валидации | Критические параметры |
|---------|--------------------|--------------------|
| Стерилизация EO | ISO 11135 | Температура, влажность, концентрация EO, время |
| Стерилизация паром | ISO 17665 | Температура, давление, время |
| Радиационная стерилизация | ISO 11137 | Доза, равномерность дозы |

## Воркфлоу по квалификации поставщика { #supplier-qualification-workflow }

Оценивать и утверждать поставщиков в соответствии с пунктом 7.4 стандарта ISO 13485.

### Воркфлоу: Новая квалификация поставщика { #workflow-new-supplier-qualification }

1. Определите категорию поставщика:
   - Категория A: Критическая (влияет на безопасность/эксплуатационные характеристики)
   - Категория B: Основная (влияет на качество)
   - Категория C: Незначительное (косвенное воздействие)
2. Запросить информацию о поставщике:
   - Сертификаты качества
   - Технические характеристики продукта
   - История качества
3. Оценивайте поставщика на основе:
   - Система качества (сертификация ISO)
   - Технические возможности
   - История качества
   - Финансовая стабильность
4. Для поставщиков категории А:
   - Проведение аудита на месте
   - Требуется соглашение о качестве
5. Рассчитать квалификационный балл
6. Принять решение об утверждении:
   - >80: Одобрено
   - 60-80: Условное одобрение
   - <60: Не одобрено
7. Добавить в список утвержденных поставщиков
8. **Проверка:** Критерии оценки оценены; квалификационные записи заполнены; поставщик отнесен к категории

### Критерии оценки поставщиков { #supplier-evaluation-criteria }

| Критерий | Вес | Подсчет очков |
|-----------|--------|---------|
| Система качества | 30% | ISO 13485=30, ISO 9001=20, Документировано=10, Отсутствует=0 |
| История качества | 25% | Процент брака: <1%=25, 1-3%=15, >3%=0 |
| Доставка | 20% | Вовремя: >95%=20, 90-95%=10, <90%=0 |
| Технические возможности | 15% | Превышает=15, соответствует=10, Предельное значение=5 |
| Финансовая стабильность | 10% | Сильный=10, Адекватный=5, Сомнительный=0 |

### Требования к категории поставщиков { #supplier-category-requirements }

| Категория | Квалификация | Мониторинг | Соглашение |
|----------|---------------|------------|-----------|
| A - Критический | Аудит на месте | Ежегодный ревью | Соглашение о качестве |
| Си - мажор | Анкета | Полугодовой ревью | Требования к качеству |
| До - минор | Оценка | Основанный на проблемах | Стандартные условия |

### Показатели эффективности работы поставщиков { #supplier-performance-metrics }

| Метрика | Цель | Расчет |
|--------|--------|-------------|
| Принимаемая ставка | >98% | (Принятые лоты / Общее количество лотов) × 100 |
| Своевременная доставка | >95% | (Время выполнения / Общее количество заказов) × 100 |
| Время отклика | <5 дней | Среднее количество дней, затрачиваемых на решение проблем |
| Документация | 100% | (Полные КОК / требуемые КОК) × 100 |

### Требования к хранению записей { #record-retention-requirements }

> **⚠️ СТАТУС — переход к QMSR (вступает в силу 2026-02-02): ** Окончательное правило Регламента системы менеджмента качества (QMSR) FDA (89 FR 7496) внесло поправки в 21 CFR, часть 820, чтобы ** включить ISO 13485:2016 путем ссылки ** и удалило устаревшую структуру подразделов QSR. Приведенные ниже номера разделов (820.30/.181/.184/.198) ** больше не существуют в CFR** — они сохраняются только в качестве привычного индекса. Действующими полномочиями по хранению записей являются **ISO 13485:2016 §4.2.5** (хранить "по крайней мере в течение срока службы медицинского устройства, определенного организацией, но не менее двух лет"), с дополнениями к записям в разделе "Сохранено" **21 CFR 820.35**. Ссылайтесь на положения стандарта ISO 13485, а не на номера 820.x, в текущей документации по соответствию.

| Тип записи | Минимальное удержание | Текущие полномочия в рамках QMSR (устаревший QSR показан для индекса) |
|-------------|-------------------|------------------|
| Основная запись устройства | Срок службы устройства + 2 года | ISO 13485 §4.2.3 (файл медицинского устройства)/§4.2.5 (устаревший QSR 820.181, исторический) |
| Запись истории устройства | Срок службы устройства + 2 года | ISO 13485 §4.2.5 + 21 CFR 820.35 (устаревший QSR 820.184, исторический) |
| Файл истории проектирования | Срок службы устройства + 2 года | ISO 13485 §7.3.10/§4.2.5 (устаревший QSR 820.30, исторический) |
| Записи о жалобах | Срок службы устройства + 2 года | ISO 13485 §8.2.2/§4.2.5 + 21 CFR 820.35(b) (устаревший QSR 820.198, исторический) |
| Записи о тренировках | Занятость + 3 года | Наилучшая практика |
| Записи аудита | 7 лет | Наилучшая практика |
| Записи CAPA | 7 лет | Наилучшая практика |
| Записи о калибровке | Срок службы оборудования + 2 года | Наилучшая практика |

> ** Дисциплина принятия решений:** чек—листы и инструменты этого скилла структурируют оценку соответствия СМК - они не подтверждают соответствие ISO 13485 / QMSR. Окончательные определения соответствия и решения о хранении записей принимаются вами и должны быть ревью и подписаны указанным QMR; направьте вопросы, относящиеся к нормативной классификации FDA, в Отдел регулирования и подтвердите текущий текст 21 CFR 820 / ISO 13485:2016 по адресу fda.gov прежде чем полагаться на какую-либо цитату здесь.
