## Стратегия регулирования Воркфлоу { #regulatory-strategy-workflow }

Разработайте стратегию регулирования, соответствующую бизнес-целям и характеристикам продукта.

### Воркфлоу: Новая стратегия регулирования продуктов { #workflow-new-product-regulatory-strategy }

1. Сбор информации о продукте:
   - Назначение и показания к применению
   - Классификация устройств (уровень риска)
   - Технологическая платформа
   - Целевые рынки и временные рамки
2. Определите применимые правила для каждого целевого рынка:
   - Управление по санитарному надзору за качеством пищевых продуктов и медикаментов (США): 21 CFR, часть 820, 510(k)/PMA/De Novo
   - ЕС: MDR 2017/745, требования нотифицированного органа
   - Другие рынки: Health Canada, PMDA, NMPA, TGA
3. Определить оптимальный путь регуляции:
   - Сравните типы заявок (510(k) против De Novo и PMA)
   - Оценка доступности основного устройства
   - Оценить требования к клиническим доказательствам
4. Разработайте график регулирования с указанием основных этапов
5. Оцените потребности в ресурсах и бюджет
6. Определение регулятивных рисков и стратегий их смягчения
7. Получить согласование и одобрение со стороны стейкхолдеров
8. **Подтверждение:** Стратегический документ утвержден; сроки приняты; ресурсы выделены

### Матрица выбора регуляторного пути { #regulatory-pathway-selection-matrix }

| Фактор | 510(k) | Заново | ПМА |
|--------|--------|---------|-----|
| Доступный предикат | Да | Нет | Н/Д |
| Уровень риска | Низкий-умеренный | Низкий-умеренный | Высокий |
| Клинические данные | Обычно не требуется | Может потребоваться | Требуемый |
| Время Ревью | 90 дней (MDUFA) | 150 дней | 180 дней |
| Плата за пользование | ~$22 тыс. (2024) | ~$135 тыс. | ~$440 тыс. |
| Лучше всего подходит для | Устройства "я тоже" | Новая система с низким уровнем риска | Рискованный, новый |

### Шаблон документа о стратегии регулирования { #regulatory-strategy-document-template }

```
REGULATORY STRATEGY

Product: [Name]   Version: [X.X]   Date: [Date]

1. PRODUCT OVERVIEW
   Intended use: [One-sentence statement of intended patient population, body site, and clinical purpose]
   Device classification: [Class I / II / III]
   Technology: [Brief description, e.g., "AI-powered wound-imaging software, SaMD"]

2. TARGET MARKETS & TIMELINE
   | Market | Pathway        | Priority | Target Date |
   |--------|----------------|----------|-------------|
   | USA    | 510(k) / PMA   | 1        | Q1 20XX     |
   | EU     | Class [X] MDR  | 2        | Q2 20XX     |

3. REGULATORY PATHWAY RATIONALE
   FDA: [510(k) / De Novo / PMA] — Predicate: [K-number or "none"]
   EU:  Class [X] via [Annex IX / X / XI] — NB: [Name or TBD]
   Rationale: [2–3 sentences on key factors driving pathway choice]

4. CLINICAL EVIDENCE STRATEGY
   Requirements: [Summarize what each market needs, e.g., "510(k): bench + usability; EU Class IIb: PMCF study"]
   Approach: [Literature review / Prospective study / Combination]

5. RISKS AND MITIGATION
   | Risk                         | Prob | Impact | Mitigation                        |
   |------------------------------|------|--------|-----------------------------------|
   | Predicate delisted by FDA    | Low  | High   | Identify secondary predicate now  |
   | NB audit backlog             | Med  | Med    | Engage NB 6 months before target  |

6. RESOURCE REQUIREMENTS
   Budget: $[Amount]   Personnel: [FTEs]   External: [Consultants / CRO]
```

## Воркфлоу подачи заявок в Управление по санитарному надзору за качеством пищевых продуктов и медикаментов { #fda-submission-workflow }

Подготовьте и отправьте нормативные заявки FDA.

### Воркфлоу: 510(k) отправок { #workflow-510k-submission }

1. Подтвердите пригодность пути 510(k):
   - Идентифицированное устройство предиката (обратите внимание на K-номер, например, K213456)
   - Существенный аргумент эквивалентности (SE), подтверждаемый предполагаемым использованием и технологическими характеристиками
   - Никакое новое предполагаемое использование или технология не связаны с триггером De Novo
2. Запланируйте и проведите встречу перед подачей заявки (Q-Sub), если это необходимо (см. [Предварительное решение](#pre-submission-meeting-decision))
3. Составьте чек-лист пакета документов для подачи заявки на участие в конкурсе.:
   - [ ] Сопроводительное письмо с названием устройства, кодом продукта и K-номером предиката
   - [ ] Раздел 1: Административная информация (заявитель, контактное лицо, тип 510(k))
   - [ ] Раздел 2: Описание устройства — включает фотографии, размеры, список материалов
   - [ ] Раздел 3: Назначение и показания к применению
   - [ ] Раздел 4: Сравнительная таблица существенной эквивалентности (см. пример ниже)
   - [ ] Раздел 5: Тестирование производительности — протоколы, цитируемые стандарты, результаты прохождения/неудачи
   - [ ] Раздел 6: Краткое описание биосовместимости (оценка риска по стандарту ISO 10993-1 при контакте с пациентом)
   - [ ] Раздел 7: Документация по программному обеспечению (уровень IEC 62304, кибербезопасность в соответствии с рекомендациями FDA, если применимо)
   - [ ] Раздел 8: Маркировка — окончательный проект IFU, этикетка устройства
   - [ ] Раздел 9: Резюме и заключение
4. Провести внутренний ревью и проверку качества в соответствии с чек-листом Управления по санитарному надзору за качеством пищевых продуктов и медикаментов (FDA).
5. Подготовьте электронную копию в соответствии с требованиями FDA к формату (PDF с закладками, титульная страница электронной копии)
6. Отправить через портал ESG FDA с оплатой пользовательского сбора
7. Следите за часами MDUFA и отвечайте на запросы AI / RTA в установленные сроки
8. ** Подтверждение:** Заявка принята; получена дата MDUFA; обновлена система отслеживания

#### Пример сравнения существенной эквивалентности { #substantial-equivalence-comparison-example }

| Характеристика | Предикат (K213456) | Предметное устройство | То же самое? | Примечания |
|----------------|---------------------|----------------|-------|-------|
| Использование по назначению | Измерение раны | Измерение раны | ✓ | Идентичный |
| Технология | 2D-камера | Анализ 2D + искусственный интеллект | ✗ | Новый TC; адрес ниже |
| Тип энергии | Обесточенный | Обесточенный | ✓ | |
| Контакт с пациентом | Нет | Нет | ✓ | |
| Заключение SE | Новый TC не поднимает новых вопросов безопасности/эффективности; стендовые данные демонстрируют эквивалентную точность (±2 мм против предиката ±3 мм). |

### Воркфлоу: Отправка PMA { #workflow-pma-submission }

1. Подтвердите путь PMA:
   - Устройство класса III или нет подходящего предиката
   - Определена стратегия сбора клинических данных
2. При необходимости завершите клиническое исследование IDE:
   - Одобрение IDE
   - Выполнение клинического протокола
   - Завершение отчета об исследовании
3. Провести совещание перед подачей заявки
4. Составьте чек-лист для подачи заявки на участие в PMA submission submission:
   - [ ] Том I: Административные вопросы, описание устройства, производство
   - [ ] Том II: Неклинические исследования (стендовые, на животных, биосовместимость)
   - [ ] Том III: Клинические исследования (протокол IDE, данные, статистический анализ)
   - [ ] Том IV: Маркировка
   - [ ] Том V: Информация о производстве, стерилизация
5. Подать оригинальную заявку на PMA
6. Устраните вопросы и недостатки FDA
7. Подготовьтесь к инспекции объекта FDA
8. **Валидация:** Утвержден PMA; получено письмо об утверждении; задокументированы требования после утверждения

|-----------|--------|---------|-----|

| Подчинение | День 0 | День 0 | День 0 |

### Распространенные недостатки FDA и их профилактика { #common-fda-deficiencies-and-prevention }

| Категория | Общие проблемы | Предотвращение |
|----------|---------------|------------|
| Существенная эквивалентность | Слабое сравнение предикатов; нет данных о производительности | Создайте таблицу SE со столбцом данных; приведите признанные стандарты |
| Тестирование производительности | Неполные протоколы; отсутствует обоснование наихудшего варианта | Следуйте стандартам, признанным FDA; документируйте обоснование наихудшего случая |
| Биосовместимость | Отсутствуют конечные точки; отсутствует оценка рисков по стандарту ISO 10993-1 | Заполните матрицу ISO 10993-1 перед тестированием |
| Программное обеспечение | Неадекватный анализ рисков; отсутствие спецификации материалов по кибербезопасности | Соответствие стандарту IEC 62304 + чек-лист руководства FDA по кибербезопасности |
| Маркировка | Противоречивые утверждения против IFU; стандарт отсутствующих символов | Сверьте этикетку с IFU; для обозначения приведите ISO 15223-1 |

## Воркфлоу-процесс подачи MDR в ЕС { #eu-mdr-submission-workflow }

Получите маркировку CE в соответствии с MDR ЕС 2017/745.

### Воркфлоу: Техническая документация по MDR { #workflow-mdr-technical-documentation }

1. Подтвердите классификацию устройства в соответствии с приложением VIII к MDR
2. Выберите маршрут оценки соответствия в зависимости от класса:
   - Класс I: Самопровозглашение
   - Класс IIa/IIb: Участие нотифицированного органа
   - Класс III: Полная оценка NB
3. Выберите и привлеките нотифицированный орган (для класса IIa+) — смотрите критерии отбора ниже
4. Составьте техническую документацию в соответствии с приложением II к чек-листу:
   - [ ] Приложение II §1: Описание устройства, предполагаемое назначение, UDI
   - [ ] Приложение II §2: Информация о проектировании и производстве (чертежи, спецификация, технологические процессы)
   - [ ] Приложение II §3: чек—лист GSPR - каждое требование сопоставлено с доказательствами (стандарт, отчет об испытаниях или обоснование).
   - [ ] Приложение II §4: Файл анализа выгод и рисков и управления рисками (ISO 14971)
   - [ ] Приложение II §5: Проверка и валидация продукции (протоколы испытаний)
   - [ ] Приложение II §6: План пострыночного надзора
   - [ ] Приложение XIV: Отчет о клинической оценке (CER) — литература, клинические данные, обоснование эквивалентности
5. Создание и документирование СМК в соответствии с ISO 13485
6. Подать заявление в Нотифицированный орган
7. Отвечайте на вопросы NB и координируйте аудит
8. **Подтверждение:** Выдан сертификат CE; Подписана декларация о соответствии; Завершена регистрация EUDAMED

#### Пример строки Чек-листа GSPR { #gspr-checklist-row-example }

| Ссылка на GSPR | Требование | Стандарт/ руководство | Подтверждающий документ | Статус |
|----------|-------------|---------------------|-------------------|--------|
| Приложение I §1 | Безопасный дизайн и производство | ISO 14971:2019 | Файл управления рисками версии 2.1 | Полный |
| Приложение I §11.1 | Устройства с функцией измерения ±точность | EN ISO 15223-1 | Отчет об испытаниях производительности PT-003 | Полный |
| Приложение I §17 | Кибербезопасность | MDCG 2019-16 | Оценка кибербезопасности CS-001 | В процессе разработки |

### Требования к клиническим доказательствам в разбивке по классам { #clinical-evidence-requirements-by-class }

| Класс | Клинические требования | Документация |
|-------|---------------------|---------------|
| Я | Клиническая оценка (CE) | Отчет CE |
| IIa | CE с акцентом на литературу | Отчет CE + план PMCF |
| IIb | CE с клиническими данными | Отчет CE + PMCF + клиническое исследование (некоторые) |
| III | CE с клиническим исследованием | Отчет CE + PMCF + клиническое исследование |

### Критерии отбора нотифицированного органа { #notified-body-selection-criteria }

- ** Область применения: ** Предназначено для вашей конкретной категории устройств
- **Вместимость:** Подтвержденная доступность в установленные сроки
- **Опыт:** Послужной список в области вашего типа технологии
- **География:** Близость для проведения аудита на месте
- **Стоимость:** Прозрачность структуры вознаграждения
- **Коммуникация:** Оперативность реагирования и обработка запросов

## Воркфлоу доступа к глобальному рынку { #global-market-access-workflow }

Координирует получение разрешений регулирующих органов на международных рынках.

### Воркфлоу: Стратегия представления на нескольких рынках { #workflow-multi-market-submission-strategy }

1. Определите целевые рынки на основе бизнес-приоритетов
2. Последовательные рынки для эффективного использования фактических данных:
   - Фаза 1: FDA + ЕС (референтные рынки)
   - Этап 2: Рынки признания (Канада, Австралия)
   - Фаза 3: Основные рынки (Япония, Китай)
   - Фаза 4: Развивающиеся рынки
3. Определите местные требования для каждого рынка:
   - Приемлемость клинических данных
   - Потребности местного агента/представителя
   - Требования к языку и маркировке
4. Разработать мастер-технический файл с планом локализации
5. Создание нормативно-правовой поддержки внутри страны
6. Выполнять параллельные или последовательные отправки
7. Отслеживание утверждений и координация запусков
8. ** Проверка:** Получены все разрешения целевого рынка; обновлена регистрационная база данных

### Матрица рыночных приоритетов { #market-priority-matrix }

| Рынок | Размер | Сложность | Признание | Приоритет |
|--------|------|------------|-------------|----------|
| США | Большой | Высокий | Н/Д | 1 |
| ЕС | Большой | Высокий | Н/Д | 1–2 |
| Канада | Средний | Средний | MDSAP | 2 |
| Австралия | Средний | Низкий | Принятый ЕС | 2 |
| Япония | Большой | Высокий | Местная клиническая | 3 |
| Китай | Большой | Очень высокий | Локальное тестирование | 3 |
| Бразилия | Средний | Высокий | Проверка GMP | 3–4 |

### Стратегия повышения эффективности документирования { #documentation-efficiency-strategy }

| Тип документа | Единый источник | Требуется локализация |
|---------------|---------------|----------------------|
| Ядро технического файла | Да | Адаптация формата |
| Управление рисками | Да | Нет |
| Клинические данные | Да | Промежуточная оценка |
| Сертификат СМК | Да (ISO 13485) | Аудит с учетом специфики рынка |
| Маркировка | Основная этикетка | Перевод, местные требования |
| МФУ | Основной контент | Перевод, местные символы |

## Нормативно-аналитический воркфлоу { #regulatory-intelligence-workflow }

Отслеживайте изменения в законодательстве, влияющие на ассортимент продукции, и реагируйте на них.

### Воркфлоу: Управление нормативными изменениями { #workflow-regulatory-change-management }

1. Осуществлять мониторинг регулирующих источников:
   - Федеральный реестр FDA, руководящие документы
   - Официальный журнал ЕС, руководство MDCG
   - Сообщения нотифицированного органа
   - Отраслевые ассоциации (AdvaMed, MedTech Europe)
2. Оценка соответствия ассортименту продукции
3. Оценить воздействие:
   - Сроки выполнения требований
   - Потребности в ресурсах
   - Необходимые изменения в продукте
4. Разработать план действий по соблюдению требований
5. Доведение информации до сведения затронутых стейкхолдеров
6. Внесите необходимые изменения
7. Статус соответствия документа
8. **Валидация:** Утвержден план действий по соблюдению требований; изменения внесены в соответствии с графиком
