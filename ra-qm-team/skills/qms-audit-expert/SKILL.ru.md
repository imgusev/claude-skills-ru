## Планирование воркфлоу-процесса аудита { #audit-planning-workflow }

Планируйте программу внутреннего аудита, основанную на оценке рисков:

1. Перечислите все процессы СМК, требующие аудита
2. Назначьте уровень риска для каждого процесса (высокий/средний/низкий)
3. Ревью к выводам и тенденциям предыдущего аудита
4. Определите частоту проведения аудита в зависимости от уровня риска
5. Назначить квалифицированных аудиторов (проверка независимости)
6. Составьте график ежегодного аудита
7. Сообщайте расписание владельцам процессов
8. **Валидация:** Все положения стандарта ISO 13485, охватываемые циклом

### Частота проведения аудита, основанного на оценке рисков { #risk-based-audit-frequency }

| Уровень риска | Частота | Критерии |
|------------|-----------|----------|
| Высокий | Ежеквартально | Контроль проектирования, CAPA, валидация производства |
| Средний | Полугодовой | Закупки, обучение, документооборот |
| Низкий | Ежегодный | Инфраструктура, ревью руководства (при условии стабильности) |

### Объем аудита по пунктам { #audit-scope-by-clause }

| Оговорка | Процесс | Приоритетные области |
|--------|---------|-------------|
| 4.2 | Контроль документооборота | Утверждение документов, распространение, контроль устаревания |
| 5.6 | Ревью руководства | Вводимые данные завершены, решения задокументированы, действия отслеживаются |
| 6.2 | Тренировка | Компетенция определена, записи заполнены, эффективность подтверждена |
| 7.3 | Контроль проектирования | Вводные данные, ревью, V&V, передача, изменения |
| 7.4 | Покупка | Оценка поставщика, входной контроль |
| 7.5 | Производство | Рабочие инструкции, валидация процесса, DHR |
| 7.6 | Калибровка | Список оборудования, статус калибровки, выход за пределы допуска |
| 8.2.2 | Внутренний аудит | Соблюдение графика, независимость аудитора |
| 8.3 | Изделие с ЧПУ | Идентификация, сегрегация, распоряжение |
| 8.5 | КАПА | Первопричина, внедрение, эффективность |

### Независимость аудитора { #auditor-independence }

Проверка независимости аудитора перед назначением:

- [ ] Аудитор не несет ответственности за область, подлежащую аудиту
- [ ] Отсутствие прямой отчетности перед проверяемым лицом
- [ ] Не участвовал в недавних мероприятиях в рамках аудита
- [ ] Документально подтвержденная квалификация для проведения аудита

## Выполнение аудита { #audit-execution }

Проводить систематический внутренний аудит:

1. Подготовить план аудита (объем, критерии, график)
2. Перед аудитом ревью соответствующую документацию
3. Провести вступительную встречу с проверяемым лицом
4. Сбор доказательств (записи, интервью, наблюдения)
5. Классифицировать результаты (основные/второстепенные/Наблюдения)
6. Провести заключительное совещание с предварительными выводами
7. Подготовьте отчет по аудиту в течение 5 рабочих дней
8. ** Проверка:** Охвачены все пункты сферы охвата, выводы подтверждены доказательствами

### Сбор доказательств { #evidence-collection }

| Способ | Использовать для | Документация |
|--------|---------|---------------|
| Ревью документов | Процедуры, записи | Номер документа, версия, дата |
| Интервью | Понимание процесса | Имя интервьюируемого, должность, краткое описание |
| Наблюдение | Реальная практика | Что, где, когда наблюдалось |
| Трассировка записи | Технологический процесс | Идентификаторы записей, даты, привязка |

### Вопросы аудита по пунктам { #audit-questions-by-clause }

**Контроль документооборота (4.2):**
- Покажите мне основной список документов
- Как вы контролируете устаревшие документы?
- Покажите мне доказательства одобрения изменений в документе

**Контроль проектирования (7.3):**
- Покажите мне файл истории проектирования для [продукт]
- Кто участвует в ревью дизайна?
- Покажите мне, как проектировать входные данные для отслеживания выходных данных

**CAPA (8,5):**
- Покажите мне журнал CAPA с открытыми элементами
- Как вы определяете первопричину?
- Покажите мне записи о проверке эффективности

Видишь `references/iso13485-audit-guide.md` для получения полных наборов вопросов.

### Поиск документации { #finding-documentation }

Документируйте каждое открытие с помощью:

```
Requirement: [Specific ISO 13485 clause or procedure]
Evidence: [What was observed, reviewed, or heard]
Gap: [How evidence fails to meet requirement]
```

**Пример:**
```
Requirement: ISO 13485:2016 Clause 7.6 requires calibration
at specified intervals.

Evidence: Calibration records for pH meter (EQ-042) show
last calibration 2024-01-15. Calibration interval is
12 months. Today is 2025-03-20.

Gap: Equipment is 2 months overdue for calibration,
representing a gap in calibration program execution.
```

## Управление несоответствиями { #nonconformity-management }

Классифицировать результаты аудита и управлять ими:

1. Оцените находку в соответствии с критериями классификации
2. Назначить степень серьезности (основная/второстепенная/Наблюдение)
3. Поиск документов с объективными доказательствами
4. Связаться с владельцем процесса
5. Инициировать CAPA для получения основных/второстепенных результатов
6. Путь к закрытию
7. Проверка эффективности при последующих действиях
8. ** Проверка:** Поиск закрыт только после вступления в силу CAPA

### Критерии классификации { #classification-criteria }

| Категория | Определение | Требуемый CAPA | Временная шкала |
|----------|------------|---------------|----------|
| Майор | Систематический сбой или отсутствие элемента | Да | 30 дней |
| Второстепенный | Изолированный сбой или частичная реализация | Рекомендуемый | 60 дней |
| Наблюдение | Возможность улучшения | Необязательный | По мере необходимости |

### Классификационное решение { #classification-decision }

```
Is required element absent or failed?
├── Yes → Systematic (multiple instances)? → MAJOR
│   └── No → Could affect product safety? → MAJOR
│       └── No → MINOR
└── No → Deviation from procedure?
    ├── Yes → Recurring? → MAJOR
    │   └── No → MINOR
    └── No → Improvement opportunity? → OBSERVATION
```

### Интеграция CAPA { #capa-integration }

| Определение степени серьезности | Глубина КАПЫ | Проверка |
|------------------|------------|--------------|
| Майор | Полный анализ первопричин (5-Почему, рыбья кость) | Следующий аудит или в течение 6 месяцев |
| Второстепенный | Непосредственное выявление причины | Следующий запланированный аудит |
| Наблюдение | Не требуется | Отмечено при следующем аудите |

Видишь `references/nonconformity-classification.md` для получения подробных указаний.

## Подготовка к внешнему аудиту { #external-audit-preparation }

Подготовка к аудиту органа по сертификации или регулирующих органов:

1. Завершите все запланированные внутренние аудиты
2. Убедитесь, что все выводы закрыты с помощью эффективного CAPA
3. Ревью документацию на предмет актуальности и точности
4. Провести ревью руководства с использованием аудита в качестве исходных данных
5. Подготовьте объект и персонал
6. Провести имитационный аудит (полный объем)
7. Ознакомьте персонал с протоколом аудита
8. **Валидация:** Фиктивные результаты аудита, рассмотренные до проведения внешнего аудита

### Чек-лист готовности к предварительному аудиту: { #pre-audit-readiness-checklist }

**Документация:**
- [ ] Текущий контроль качества вручную
- [ ] Процедуры отражают реальную практику
- [ ] Записи полные и доступные для извлечения
- [ ] Результаты предыдущего аудита закрыты

**Персонал:**
- [ ] Ключевой персонал, доступный во время аудита
- [ ] Эксперты по предмету определили
- [ ] Персонал проинформирован о протоколе аудита
- [ ] Назначены сопровождающие

**Объект:**
- [ ] Организованные рабочие зоны
- [ ] Документы на момент использования текущие
- [ ] Виден статус калибровки оборудования
- [ ] Несоответствующий продукт отделен

### Макет протокола аудита { #mock-audit-protocol }

1. Используйте внешнего аудитора или квалифицированного внутреннего аудитора
2. Охватить весь объем предстоящего внешнего аудита
3. Имитировать фактические условия аудита (сроки, формальности)
4. Документируйте выводы как для реального аудита
5. Рассмотрите все основные и второстепенные выводы до проведения внешнего аудита
6. Краткое руководство по состоянию готовности

# JSON output for integration
python scripts/audit_schedule_optimizer.py --processes processes.json --output json

Формирует график аудита, основанный на оценке рисков, с учетом:

**Выходные данные включают в себя:**
- График приоритетного аудита
- Ежеквартальное распределение
- Предупреждения о просроченном аудите
- Рекомендации по ресурсам

## Показатели программы аудита { #audit-program-metrics }

Отслеживать эффективность программы аудита:

| Метрика | Цель | Измерение |
|--------|--------|-------------|
| Соблюдение графика | >90% | Аудиты завершены в срок |
| Определение коэффициента закрытия | >95% | Выводы завершены к установленному сроку |
| Повторные выводы | <10% | Один и тот же вывод в ходе последовательных аудитов |
| Эффективность CAPA | >90% | Подтверждена эффективность при последующем наблюдении |
| Использование аудитора | 4 дня/месяц | Дней аудита на одного квалифицированного аудитора |
