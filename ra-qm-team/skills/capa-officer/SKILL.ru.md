## Воркфлоу расследования CAPA { #capa-investigation-workflow }

Проводить систематическое расследование CAPA от начала до закрытия:

1. Задокументируйте событие-триггер с объективными доказательствами
2. Оценить значимость и определить необходимость CAPA
3. Сформировать следственную группу с соответствующим опытом
4. Систематически собирайте данные и доказательства
5. Выберите и примените соответствующую методологию RCA
6. Определите первопричину (причины) с помощью подтверждающих доказательств
7. Разрабатывать корректирующие и предупреждающие действия
8. ** Проверка:** Первопричина объясняет все симптомы; если устранить проблему, она не повторится

### Определение необходимости CAPA { #capa-necessity-determination }

| Тип триггера | Требуемый CAPA | Критерии |
|--------------|---------------|----------|
| Жалоба клиента (безопасность) | Да | Любая жалоба, связанная с безопасностью пациента/пользователя |
| Жалоба клиента (качество) | Оценивать | В зависимости от тяжести и частоты |
| Заключение внутреннего аудита (основное) | Да | Систематический сбой или отсутствие элемента |
| Заключение внутреннего аудита (незначительное) | Рекомендуемый | Изолированный сбой или частичная реализация |
| Несоответствие (повторяющееся) | Да | Один и тот же тип ЧПУ встречается более 3 раз |
| Несоответствие (изолированное) | Оценивать | В зависимости от тяжести и риска |
| Заключение внешнего аудита | Да | Все основные и второстепенные находки |
| Анализ тенденций | Оценивать | На основе значимости тренда |

### Состав следственной группы { #investigation-team-composition }

| Серьезность CAPA | Требуемые члены команды |
|---------------|----------------------|
| Критический | Сотрудник CAPA, владелец процесса, менеджер по контролю качества, эксперт по предмету, представитель руководства |
| Майор | Сотрудник CAPA, владелец процесса, эксперт по предмету |
| Второстепенный | Сотрудник CAPA, владелец процесса |

- [ ] Описание проблемы с конкретными деталями (что, где, когда, кто, сколько)
- [ ] Хронология событий, приведших к выпуску
- [ ] Соответствующие записи и документация
- [ ] Записи интервью с привлеченным персоналом

## Анализ первопричин { #root-cause-analysis }

Выберите и примените соответствующую методологию RCA, основанную на характеристиках проблемы.

### Дерево решений о выборе метода RCA { #rca-method-selection-decision-tree }

```
Is the issue safety-critical or involves system reliability?
├── Yes → Use FAULT TREE ANALYSIS
└── No → Is human error the suspected primary cause?
    ├── Yes → Use HUMAN FACTORS ANALYSIS
    └── No → How many potential contributing factors?
        ├── 1-2 factors (linear causation) → Use 5 WHY ANALYSIS
        ├── 3-6 factors (complex, systemic) → Use FISHBONE DIAGRAM
        └── Unknown/proactive assessment → Use FMEA
```

### 5 Почему анализ { #5-why-analysis }

Используйте, когда: Проблемы с единственной причиной с линейной причинно-следственной связью, отклонения процесса с четкой точкой отказа.

**Шаблон:**

```
PROBLEM: [Clear, specific statement]

WHY 1: Why did [problem] occur?
BECAUSE: [First-level cause]
EVIDENCE: [Supporting data]

WHY 2: Why did [first-level cause] occur?
BECAUSE: [Second-level cause]
EVIDENCE: [Supporting data]

WHY 3: Why did [second-level cause] occur?
BECAUSE: [Third-level cause]
EVIDENCE: [Supporting data]

WHY 4: Why did [third-level cause] occur?
BECAUSE: [Fourth-level cause]
EVIDENCE: [Supporting data]

WHY 5: Why did [fourth-level cause] occur?
BECAUSE: [Root cause]
EVIDENCE: [Supporting data]
```

**Пример - Просроченная калибровка:**

```
PROBLEM: pH meter (EQ-042) found 2 months overdue for calibration

WHY 1: Why was calibration overdue?
BECAUSE: Equipment was not on calibration schedule
EVIDENCE: Calibration schedule reviewed, EQ-042 not listed

WHY 2: Why was it not on the schedule?
BECAUSE: Schedule not updated when equipment was purchased
EVIDENCE: Purchase date 2023-06-15, schedule dated 2023-01-01

WHY 3: Why was the schedule not updated?
BECAUSE: No process requires schedule update at equipment purchase
EVIDENCE: SOP-EQ-001 reviewed, no such requirement

WHY 4: Why is there no such requirement?
BECAUSE: Procedure written before equipment tracking was centralized
EVIDENCE: SOP last revised 2019, equipment system implemented 2021

WHY 5: Why has procedure not been updated?
BECAUSE: Periodic review did not assess compatibility with new systems
EVIDENCE: No review against new equipment system documented

ROOT CAUSE: Procedure review process does not assess compatibility
with organizational systems implemented after original procedure creation.
```

### Категории диаграмм рыбьей кости (6 м) { #fishbone-diagram-categories-6m }

| Категория | Приоритетные области | Типичные причины |
|----------|-------------|----------------|
| Человек (Люди) | Подготовка, компетентность, рабочая нагрузка | Пробелы в скиллах, усталость, общение |
| Машина (оборудование) | Калибровка, техническое обслуживание, возраст | Износ, неисправность, недостаточная производительность |
| Способ (процесс) | Процедуры, рабочие инструкции | Неясные шаги, отсутствующие элементы управления |
| Материал | Технические характеристики, поставщики, условия хранения | Несоответствие спецификации, деградация, загрязнение |
| Измерение | Калибровка, методы, интерпретация | Ошибка прибора, неправильный метод |
| Мать-природа | Температура, влажность, чистота | Экологические экскурсии |

Видишь `references/rca-methodologies.md` для получения полной информации о методе и шаблонах.

### Проверка первопричины { #root-cause-validation }

Прежде чем приступить к планированию действий, проверьте первопричину:

- [ ] Первопричина может быть подтверждена объективными доказательствами
- [ ] Если первопричина устранена, проблема не повторится
- [ ] Первопричина находится под контролем организации
- [ ] Первопричина объясняет все наблюдаемые симптомы
- [ ] Никакие другие существенные причины не остаются без внимания

## Планирование корректирующих действий { #corrective-action-planning }

Разработать эффективные действия по устранению выявленных коренных причин:

1. Определите немедленные меры по сдерживанию
2. Разработать корректирующие действия, направленные на устранение первопричины
3. Определить превентивные действия для аналогичных процессов
4. Распределите обязанности и ресурсы
5. Установите временную шкалу с контрольными точками
6. Определите критерии успеха и метод проверки
7. Документ в плане действий CAPA
8. ** Проверка:** Действия непосредственно направлены на устранение первопричины; критерии успеха поддаются измерению

### Типы действий { #action-types }

| Тип | Цель | Временная шкала | Пример |
|------|---------|----------|---------|
| Сдерживание | Остановить немедленное воздействие | 24-72 часа | Продукт, подвергшийся карантину |
| Исправление | Исправьте конкретное происшествие | 1-2 недели | Переработайте или замените поврежденные элементы |
| Корректирующий | Устраните первопричину | 30-90 дней | Пересмотреть процедуру, добавить элементы управления |
| Профилактический | Предотвращать в других областях | 60-120 дней | Распространить решение на аналогичные процессы |

```

```

### Показатели эффективности действий { #action-effectiveness-indicators }

| Индикатор | Цель | Красный флаг |
|-----------|--------|----------|
| Сфера действия | Полностью устраняет первопричину | Лечит только симптомы |
| Специфика | Поддающиеся измерению результаты | Расплывчатые обязательства |
| Временная шкала | Агрессивный, но достижимый | Нет сроков выполнения или нереалистично |
| Ресурсы | Выявленные и распределенные | Не указано |
| Устойчивость | Постоянное решение | Временное исправление |

## Проверка эффективности { #effectiveness-verification }

Проверьте, достигли ли корректирующие действия запланированных результатов:

1. Обеспечить достаточный период внедрения (минимум 30-90 дней)
2. Сбор данных после внедрения
3. Сравнение с базовым уровнем, предшествовавшим внедрению
4. Оценивайте по критериям успеха
5. Убедитесь в отсутствии повторений в течение периода проверки
6. Доказательства проверки документов
7. Определить эффективность CAPA
8. **Валидация:** Все критерии выполнены с объективными доказательствами; рецидивов не наблюдалось

### Рекомендации по срокам проверки { #verification-timeline-guidelines }

| Серьезность CAPA | Период ожидания | Окно проверки |
|---------------|-------------|---------------------|
| Критический | 30 дней | 30-90 дней после внедрения |
| Майор | 60 дней | 60-180 дней после внедрения |
| Второстепенный | 90 дней | 90-365 дней после внедрения |

### Методы проверки { #verification-methods }

| Способ | Используйте, когда | Требуемые доказательства |
|--------|----------|-------------------|
| Анализ тенденций в данных | Поддающиеся количественной оценке проблемы | Сравнение до/после, графики трендов |
| Аудит процесса | Проблемы с соблюдением процедур | Чек-лист для аудита, заметки об интервью |
| Ревью записи | Проблемы с документацией | Выборочные записи, уровень соответствия |
| Тестирование/инспекция | Проблемы с качеством продукции | Результаты тестирования, данные о прохождении/неудаче |
| Интервью/наблюдение | Вопросы обучения | Заметки об интервью, записи наблюдений |

### Определение эффективности { #effectiveness-determination }

```
Did recurrence occur during verification period?
├── Yes → CAPA INEFFECTIVE (re-investigate root cause)
└── No → Were all effectiveness criteria met?
    ├── Yes → CAPA EFFECTIVE (proceed to closure)
    └── No → Extent of gap?
        ├── Minor gap → Extend verification or accept with justification
        └── Significant gap → CAPA INEFFECTIVE (revise actions)
```

Видишь `references/effectiveness-verification-guide.md` для получения подробной информации о процедурах.

## Показатели CAPA и отчетность { #capa-metrics-and-reporting }

Контролируйте эффективность программы CAPA с помощью ключевых показателей.

### Ключевые показатели эффективности { #key-performance-indicators }

| Метрика | Цель | Расчет |
|--------|--------|-------------|
| Время цикла CAPA | в среднем <60 дней | (Дата закрытия - Дата открытия) / Количество CAPAs |
| Уровень просроченной задолженности | <10% | Просроченные CAPA / Общее количество открытых CAPA |
| Эффективность с первого раза | >90% | Вступает в силу при первой проверке / Полностью проверено |
| Частота повторения | <5% | Повторяющиеся проблемы / Общий объем закрытых ресурсов |
| Качество расследования | первопричина подтверждена на 100% | Подтверждены первопричины / Общие возможности |

### Категории анализа старения { #aging-analysis-categories }

| Возрастное ведро | Статус | Требуемые действия |
|------------|--------|-----------------|
| 0-30 дней | На верном пути | Следите за прогрессом |
| 31-60 дней | Монитор | Ревью на предмет задержек |
| 61-90 дней | Предупреждение | Эскалация до уровня руководства |
| >90 дней | Критический | Требуется вмешательство руководства |

### Руководство проводит ревью вводимых данных { #management-review-inputs }

Ежемесячный отчет о состоянии CAPA включает:
- Количество открытых CAPA по степени серьезности и статусу
- Просроченный список CAPA с владельцами
- Тенденции во времени цикла
- Тенденции в показателях эффективности
- Анализ источников (жалобы, аудиты, NCs)
- Рекомендации по улучшению

## Нормативные требования { #regulatory-requirements }

### ISO 13485:2016, пункт 8.5 { #iso-134852016-clause-85 }

| Подпункт | Требование | Основные виды деятельности |
|------------|-------------|----------------|
| 8.5.2 Корректирующие действия | Устраните причину несоответствия | Ревью NC, определение причины, оценка действий, внедрение, ревью эффективности |
| 8.5.3 Превентивные действия | Устраните потенциальное несоответствие | Анализ тенденций, определение причин, оценка действий, внедрение, ревью эффективности |

### Управление по санитарному надзору за качеством пищевых продуктов и медикаментов CAPA authority — ISO 13485 §8.5.2/8.5.3 в соответствии с QMSR (устаревший QSR 820.100, исторический) { #fda-capa-authority--iso-13485-852853-under-the-qmsr-legacy-qsr-820100-historical }

> **⚠️ СТАТУС — переход к QMSR (вступает в силу 2026-02-02): ** Окончательное правило Регламента системы менеджмента качества (QMSR) FDA (89 FR 7496) внесло поправки в 21 CFR, часть 820, чтобы ** включить ISO 13485:2016 путем ссылки ** и удалило устаревшую структуру подразделов QSR. Номер раздела CAPA **820.100 больше не существует в CFR** — он сохранен ниже только в качестве знакомого индекса. Действующими полномочиями FDA в отношении CAPA являются ** ISO 13485:2016 §8.5.2 (корректирующие действия) и §8.5.3 (превентивные действия)** (см. таблицу пунктов выше), с дополнениями по рассмотрению жалоб в сохраненном **21 CFR 820.35**. Приведите положения стандарта ISO 13485, а не 820.100, в текущей документации по соблюдению требований.

Элементы CAPA, требуемые в соответствии с ISO 13485 §8.5.2/§8.5.3 (устаревший QSR 820.100, исторический):
- Процедуры осуществления корректирующих и предупреждающих действий
- Анализ источников качественных данных (жалобы, NCS, аудиты, служебные записи)
- Расследование причин несоответствий
- Определение действий, необходимых для исправления и предотвращения повторения
- Действия по проверке эффективны и не оказывают негативного воздействия на устройство
- Предоставление соответствующей информации для ревью руководства

### Общие замечания FDA 483 { #common-fda-483-observations }
