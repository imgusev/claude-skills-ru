## Управление программой аудита { #audit-program-management }

### График аудита, основанный на оценке рисков { #risk-based-audit-schedule }

| Уровень риска | Частота проведения аудита | Примеры |
|------------|-----------------|----------|
| Критический | Ежеквартально | Привилегированный доступ, управление уязвимостями, ведение журнала |
| Высокий | Полугодовой | Контроль доступа, реагирование на инциденты, шифрование |
| Средний | Ежегодный | Политика, повышение осведомленности, физическая безопасность |
| Низкий | Ежегодный | Документация, инвентаризация активов |

### Планирование ежегодного аудита воркфлоу { #annual-audit-planning-workflow }

1. Ревью к выводам предыдущего аудита и результатам оценки рисков
2. Выявлять средства контроля высокого риска и недавние инциденты в области безопасности
3. Определите объем аудита на основе границ ISMS
4. Назначать аудиторов, обеспечивающих независимость от областей, в которых проводится аудит
5. Создайте расписание аудита с распределением ресурсов
6. Получить одобрение руководства на план аудита
7. **Валидация:** План аудита охватывает все средства контроля, указанные в приложении А, в рамках сертификационного цикла

### Требования к компетентности аудитора { #auditor-competency-requirements }

- Сертификация ведущего аудитора ISO 27001 (предпочтительно)
- Отсутствие оперативной ответственности за процессы, прошедшие аудит
- Понимание технических средств контроля безопасности
- Знание применимых нормативных актов (GDPR, HIPAA)

## Выполнение аудита { #audit-execution }

### Подготовка к предварительному аудиту { #pre-audit-preparation }

1. Ревью документации по ISMS (политики, SoA, оценка рисков)
2. Проанализируйте предыдущие отчеты по аудиту и открытые выводы
3. Подготовьте план аудита с расписанием собеседований
4. Уведомлять проверяемых о масштабах и сроках проведения аудита
5. Подготовьте чек-листы для контроля в области применения
6. **Валидация:** Вся документация получена и ревью проведена перед открытием совещания

### Этапы проведения аудита { #audit-conduct-steps }

1. **Вступительное заседание**
   - Подтвердите объем и цели аудита
   - Внедрить команду и методологию аудита
   - Согласовать каналы связи и логистику

2. **Сбор доказательств**
   - Опросите владельцев и операторов средств контроля
   - Ревью документацию и записи
   - Наблюдайте за процессами в процессе эксплуатации
   - Проверьте технические конфигурации

3. **Контрольная проверка**
   - Дизайн тестового контроля (учитывает ли он риск?)
   - Операция тестового контроля (работает ли она так, как задумано?)
   - Примеры транзакций и записей
   - Задокументируйте все собранные доказательства

4. **Заключительное заседание**
   - Представляем предварительные выводы
   - Прояснить любые фактические неточности
   - Договориться о поиске классификации
   - Подтвердите сроки корректирующих действий

5. **Валидация:** Все средства контроля в объеме, оцененном с использованием документированных доказательств

## Оценка контроля { #control-assessment }

### Подход к контрольному тестированию { #control-testing-approach }

1. Определить цель контроля в соответствии с ISO 27002
2. Определить метод тестирования (запрос, наблюдение, инспекция, повторное выполнение)
3. Определите размер выборки на основе численности населения и риска
4. Выполните тестирование и задокументируйте результаты
5. Оценка эффективности контроля
6. **Валидация:** Фактические данные подтверждают вывод о статусе контроля

Подробные процедуры технической проверки с помощью контроля, предусмотренного в приложении А, приведены в разделе [security-control-testing.md](references/security-control-testing.md).

## Поиск управления { #finding-management }

### Поиск классификации { #finding-classification }

| Серьезность | Определение | Время отклика |
|----------|------------|---------------|
| Основное несоответствие | Сбой в управлении, создающий значительный риск | 30 дней |
| Незначительное несоответствие | Изолированное отклонение с ограниченным воздействием | 90 дней |
| Наблюдение | Возможность улучшения | Следующий цикл аудита |

### Поиск шаблона документации { #finding-documentation-template }

```
Finding ID: ISMS-[YEAR]-[NUMBER]
Control Reference: A.X.X - [Control Name]
Severity: [Major/Minor/Observation]

Evidence:
- [Specific evidence observed]
- [Records reviewed]
- [Interview statements]

Risk Impact:
- [Potential consequences if not addressed]

Root Cause:
- [Why the nonconformity occurred]

Recommendation:
- [Specific corrective action steps]
```

### Корректирующие действия Воркфлоу { #corrective-action-workflow }

1. Проверяемый подтверждает факт обнаружения и серьезность
2. Анализ первопричины завершен в течение 10 дней
3. Представлен план корректирующих действий с установленными сроками
4. Действия, осуществляемые ответственными сторонами
5. Аудитор проверяет эффективность исправлений
6. Заключение закрыто с доказательствами разрешения
7. ** Проверка:** Устранена первопричина, предотвращено повторение

## Сертификационная поддержка { #certification-support }

### Этап 1 Подготовка к аудиту { #stage-1-audit-preparation }

Убедитесь в полноте документации:
- [ ] Заявление о сфере применения ISMS
- [ ] Политика информационной безопасности (подписана руководством)
- [ ] Заявление о применимости
- [ ] Методология и результаты оценки рисков
- [ ] План лечения рисков
- [ ] Результаты внутреннего аудита (за последние 12 месяцев)
- [ ] Протокол ревью руководства

### Этап 2 Подготовка к аудиту { #stage-2-audit-preparation }

Проверка эксплуатационной готовности:
- [ ] Рассмотрены все выводы этапа 1
- [ ] ISMS функционирует минимум 3 месяца
- [ ] Доказательства осуществления контроля
- [ ] Записи тренингов по повышению осведомленности о безопасности
- [ ] Доказательства реагирования на инцидент (если применимо)
- [ ] Доступ к документации для ревью

### Цикл надзорного аудита { #surveillance-audit-cycle }

| Период | Сосредоточься |
|--------|-------|
| Год 1, квартал 2 | Меры контроля высокого риска, последующее наблюдение за результатами 2-го этапа |
| Год 1, четвертый квартал | Постоянное совершенствование, контрольный образец |
| Год 2, второй квартал | Полное наблюдение |
| Год 2, четвертый квартал | Подготовка к повторной сертификации |

**Валидация:** Серьезных несоответствий при проведении надзорных аудитов не выявлено.
