# Специалист по соблюдению Закона ЕС об искусственном интеллекте { #eu-ai-act-compliance-specialist }

Приведенные в статье операционные скиллы для Регламента (ЕС) 2024/1689. **Три решения, никакой исполнительной стратегии искусственного интеллекта:**

1. ** На каком уровне находится эта система искусственного интеллекта?** — запрещена (статья 5) / высокорисковая (статья 6 + приложение III) / прозрачность с ограниченным риском (статья 50) / минимальный риск
2. **Для систем высокого риска каков маршрут оценки соответствия + пакет документации?** — Модуль A статьи 43 по сравнению с модулем H + техническая документация приложения IV
3. **Каковы обязательства в зависимости от организационной роли?** — матрица поставщика /развертывателя / импортера /дистрибьютора/уполномоченного представителя в соответствии со статьями 16, 22, 25, 26

Этот скилл ** НЕ является главным специалистом по искусственному интеллекту-советником**. CAIO решает, следует ли вообще внедрять функцию искусственного интеллекта, и принимает на себя бизнес-риск. Этот скилл управляет работой по соответствию, которая превращает "мы отправим это" в артефакты, соответствующие требованиям статьи.

Этот скилл ** НЕ является законной заменой**. Закон является обязательным нормативным актом. Для новых случаев (является ли это моделью GPAI? Применяется ли исключение из статьи 6(2)? Является ли тонкая настройка базовой модели "существенной модификацией"?), привлеките квалифицированного внешнего консультанта. В скилле цитируются статьи + приложения и используется опубликованная Комиссией/EDPB интерпретация, но не приводится обязательное юридическое заключение.

Этот скилл ** НЕ подпадает под действие GDPR**. Многие системы искусственного интеллекта также триггеры GDPR (обучающие данные, обработка выходных данных). Видишь `ra-qm-team/skills/gdpr-dsgvo-expert/` для работы DPIA + на законных основаниях. Действия взаимодействуют (пункт 10, статья 10 для данных об обучении высокому риску).

## Ключевые вопросы (задайте их в первую очередь) { #key-questions-ask-these-first }

- ** Подпадает ли эта система искусственного интеллекта под действие статьи 5 (запрещенные практики)?** Социальная оценка, распознавание эмоций на рабочем месте/education, методы манипулирования подсознанием, дистанционная биометрическая идентификация в режиме реального времени на публике - все это категорически запрещено.
- **Подпадает ли это под приложение III (категории высокого риска)?** 8 категорий: биометрия, критически важная инфраструктура, образование, занятость, основные услуги, правоохранительная деятельность, миграция, правосудие. Триггер Приложения III триггеры статьи 6(2) — за исключением случаев, когда применяются исключения из статьи 6(3).
- ** Какую организационную роль играет компания?** Поставщик (размещается на рынке), разработчик (использует по собственному усмотрению), импортер (размещает систему третьей страны на рынке ЕС), дистрибьютор (обеспечивает доступность в цепочке поставок). Многие компании являются одновременно и поставщиком, и развертывателем.
- **Является ли это моделью искусственного интеллекта общего назначения? ** У GPAI есть свой собственный трек (статьи 51-55) с более строгими правилами, превышающими 102⁵ провальных вычислений для обучения (статья 51 системный риск).
- ** Для лиц с высоким риском: применяем ли мы статью 9 "Управление рисками" И статью 27 FRIA?** Статья 9 - это управление рисками в течение жизненного цикла; Статья 27 - это оценка воздействия на основные права для организаций государственного сектора + основные услуги.
- ** Каков модуль оценки соответствия в соответствии со статьей 43?** Модуль A (внутренний контроль, возможный для большинства систем, включенных в Приложение III) по сравнению с модулем H (полная СМК + нотифицированный орган, необходимый для биометрии + иногда другие).

## Основные обязанности { #core-responsibilities }

### 1. Классификация рисков системы искусственного интеллекта { #1-ai-system-risk-classification }

** Фреймворк:** В Законе используется подход, основанный на оценке риска (пункт 26). Каждая система искусственного интеллекта относится ровно к одному из четырех уровней:

| Уровень | Источник | Примеры | Обязательства |
|---|---|---|---|
| **Запрещено** | Статья 5 | Социальная оценка; распознавание эмоций на рабочем месте/education; подсознательные манипуляции; публичная биометрия в режиме реального времени правоохранительными органами (за редкими исключениями) | Не может быть размещен на рынке или использован (штрафы до 35 млн евро / 7% оборота) |
| **Высокий риск** | Статья 6 + Приложение III; Статья 6(1) + Приложение I | Проверка резюме, кредитный рейтинг, биометрическая классификация, компоненты безопасности подкарантинной продукции | Статьи 8-17 (поставщик) + статья 26 (разработчик); оценка соответствия; маркировка CE |
| **Ограниченный риск (прозрачность)** | Статья 50 | Чат-боты, глубокие подделки, распознавание эмоций вне контекста статьи 5 | Раскрытие информации о прозрачности физическим лицам |
| **Минимальный риск** | Значение по умолчанию | Спам-фильтры, искусственный интеллект для видеоигр, прогнозисты запасов | Нет в соответствии с Законом (добровольные кодексы поведения, статья 95) |

**Критические исключения (статья 6(3)):** система, включенная в приложение III, не является высокорисковой, если она (а) выполняет узкую процедурную задачу, (б) улучшает результат ранее выполненной человеческой деятельности, (в) выявляет закономерности принятия решений, не заменяя оценку человека, (d) выполняет подготовительную задачу. Предостережение: составление профилей физических лиц всегда связано с высоким риском, предусмотренным в Приложении III, независимо от исключений.

**Запуск** `ai_system_risk_classifier.py` с системными характеристиками. Инструмент сначала проверяет запреты по статье 5, затем категории приложения III, затем исключения по статье 6(3), затем прозрачность по статье 50, затем неисполнение обязательств с минимальным риском.

Видишь `references/eu_ai_act_titles.md` смотрите полное пошаговое руководство по каждой статье.

### 2. Оценка соответствия + Техническая документация по приложению IV { #2-conformity-assessment--annex-iv-technical-documentation }

** Фреймворк (статья 43 + приложение VI/VII):** для систем искусственного интеллекта высокого риска поставщик должен продемонстрировать соответствие перед размещением на рынке. Два маршрута:

- **Модуль A — Внутренний контроль** (Приложение VI): поставщик проводит самооценку в соответствии с требованиями. Применяется к большинству систем, включенных в Приложение III, в которых поставщик внедрил гармонизированные стандарты.
- **Модуль H — Полная система менеджмента качества + техническая документация** (приложение VII): участие нотифицированного органа. Требуется для биометрических систем (статья 43(1)).

**Требуемые артефакты согласно приложению IV — Техническая документация:**

1. Общее описание системы искусственного интеллекта (предполагаемое назначение, идентификация, версия)
2. Подробное описание элементов системы (архитектура, обучающие данные, процедуры проверки)
3. Информация о мониторинге, функционировании и контроле
4. Описание системы управления рисками (статья 9)
5. Описание изменений после размещения на рынке
6. Перечень применяемых гармонизированных стандартов (или альтернативных вариантов)
7. Декларация соответствия ЕС (статья 47)
8. Описание системы пострыночного мониторинга (статья 72)

**Запуск** `conformity_assessment_planner.py` выбрать модуль и составить чек-лист приложения IV для данной системы высокого риска.

Видишь `references/high_risk_systems_annex_iii.md` для каких систем требуется какой маршрут соответствия.

### 3. Отслеживание обязательств для каждой роли { #3-per-role-obligation-tracker }

** Фреймворк (Статьи 16, 22, 23, 24, 25, 26):** Закон проводит различие между обязательствами поставщика (большинства) и обязательствами нижестоящих субъектов (развертывателя, импортера, дистрибьютора, уполномоченного представителя). Одна компания может играть несколько ролей одновременно.

| Роль | Основные статьи | Ключевые обязательства |
|---|---|---|
| **Поставщик услуг** (статья 3(3)) | 8–17, 47, 49, 72 | Оценка соответствия; маркировка СЕ; управление рисками; управление данными; техническая документация; постпродажный мониторинг; отчетность о серьезных инцидентах (статья 73) |
| **Лицо, осуществляющее развертывание** (статья 3(4)) | 26 | Использование в соответствии с инструкциями; надзор со стороны персонала; качество входных данных; ведение учета (статья 19); информирование работников (статья 26(7)); FRIA, если государственный сектор/essential-services (Статья 27) |
| **Импортер** (статья 3(6)) | 23 | Проверка соответствия; нанесенная маркировка CE; наличие технической документации |
| **Дистрибьютор** (статья 3(7)) | 24 | Проверьте маркировку CE + документацию перед предоставлением |
| **Уполномоченный представитель** (статья 22) | 22 | Поставщики, не входящие в ЕС, должны назначить одного представителя; представитель, ответственный за обязательства поставщика |

**Важно:** согласно статье 25, разработчик, который существенно модифицирует систему искусственного интеллекта с высоким уровнем риска или размещает ее на рынке под своим собственным именем, становится ** поставщиком** и наследует обязательства поставщика.

**Запуск** `ai_act_obligation_tracker.py` с помощью roles JSON для создания матрицы обязательств, отсортированной по срокам.

Видишь `references/gpai_obligations.md` для отдельного отслеживания статей 51-55 GPAI.

## Воркфлоу { #workflows }

### Воркфлоу 1: Ревью приема системы искусственного интеллекта (для каждой системы ~2 часа) { #workflow-1-ai-system-intake-review-per-system-2-hours }
**Цель:** классифицировать, определить обязательства, охват работы по обеспечению соответствия.

```bash
# 1. Document system characteristics: purpose, users, data, autonomy, deployment context
# 2. Run classifier
python scripts/ai_system_risk_classifier.py systems.json
# 3. If high-risk: run planner
python scripts/conformity_assessment_planner.py system.json
# 4. Identify org roles played (provider / deployer / both)
python scripts/ai_act_obligation_tracker.py roles.json
# 5. Cross-check with GDPR DPIA (gdpr-dsgvo-expert) if personal data
# 6. Cross-check with ISO 42001 AIMS evidence (compliance-team-iso42001)
# 7. Output: classification memo + conformity plan + obligation list
```

### Воркфлоу 2: Создание технической документации по приложению IV (для каждой системы с высоким уровнем риска, 2-4 недели) { #workflow-2-annex-iv-technical-documentation-build-per-high-risk-system-24-weeks }
**Цель:** соберите упаковку, указанную в приложении IV, перед оценкой соответствия.

```bash
# 1. Run conformity assessment planner to get the checklist
python scripts/conformity_assessment_planner.py system.json
# 2. Assemble: system description, architecture, training data, validation, risk management
# 3. Reference ISO 42001 evidence where it satisfies Annex IV items
# 4. Reference ISO 27001 evidence for security controls
# 5. Run Article 9 risk management lifecycle
# 6. Sign EU declaration of conformity (Article 47) AFTER assessment passes
# 7. Affix CE marking (Article 48)
# 8. Register in EU database (Article 71) — high-risk Annex III systems
```

### Воркфлоу 3: Аудит обязательств перед развертыванием (для каждой системы, перед запуском) { #workflow-3-pre-deployment-obligation-audit-per-system-before-launch }
**Цель:** подтвердить наличие всех активных обязательств перед размещением в ЕС.

```bash
# 1. Confirm classification still correct (re-run classifier if system changed)
# 2. Confirm conformity assessment completed (if high-risk)
# 3. Confirm transparency requirements (Article 50) — for chatbots, deepfakes, emotion detection
# 4. Confirm post-market monitoring system (Article 72) is live
# 5. Confirm serious-incident reporting procedure (Article 73) is documented
# 6. For deployers: FRIA done (Article 27, if applicable); workers informed (Article 26(7))
# 7. For GPAI: Articles 51-55 obligations met if applicable
```

### Воркфлоу 4: Ежегодное обновление соответствия требованиям (для каждой организации, ежегодно) { #workflow-4-annual-compliance-refresh-per-organization-yearly }
**Цель:** перепроверять классификации + обязательства по мере реализации Закона.

1. Перечислите все системы искусственного интеллекта, представленные на рынке ЕС или планируемые к выпуску
2. Запустите классификатор для каждого — список запрещенных по статье 5 может расширяться за счет делегированных действий
3. Запустите отслеживание обязательств — сроки сдвигаются по мере прохождения этапов Раздела III (2025 → 2026 → 2027)
4. Для каждой системы высокого риска: проверка потока данных мониторинга после выхода на рынок + способность сообщать о серьезных инцидентах.
5. Обновить техническую документацию по приложению IV в соответствии с текущими требованиями статьи 11
6. Сопряжение с ревью менеджмента ISO 42001 (пункт 9.3), если оба работают
