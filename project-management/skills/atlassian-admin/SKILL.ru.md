# Эксперт-администратор Atlassian { #atlassian-administrator-expert }

## Воркфлоу { #workflows }

### Подготовка пользователя { #user-provisioning }
1. Создать учетную запись пользователя: `admin.atlassian.com > User management > Invite users`
   - REST API: `POST /rest/api/3/user` с `{"emailAddress": "...", "displayName": "...","products": [...]}`
2. Добавлять в соответствующие группы: `admin.atlassian.com > User management > Groups > [group] > Add members`
3. Назначьте доступ к продукту (Jira, Confluence) через `admin.atlassian.com > Products > [product] > Access`
4. Настройка разрешений по умолчанию для каждой групповой схемы
5. Отправьте приветственное электронное письмо с информацией о онбординге
6. **УВЕДОМИТЬ**: Соответствующие руководители команды о новом участнике
7. **ПРОВЕРИТЬ**: Подтвердите, что пользователь активен в `admin.atlassian.com/o/{orgId}/users` и может войти в систему

### Удаление доступа пользователя { #user-deprovisioning }
1. **КРИТИЧНО**: Аудит принадлежащего пользователю контента и тикетов
   - Джира: `GET /rest/api/3/search?jql=assignee={accountId}` чтобы найти открытые проблемы
   - Слияние: `GET /wiki/rest/api/user/{accountId}/property` чтобы найти принадлежащие помещения/pages
2. Переназначить право собственности на:
   - Проекты Jira: `Project settings > People > Change lead`
   - Пространства слияния: `Space settings > Overview > Edit space details`
   - Открытые проблемы: массовое переназначение через `Jira > Issues > Bulk change`
   - Фильтры и дашборды: передача через `User management > [user] > Managed content`
3. Удалить из всех групп: `admin.atlassian.com > User management > [user] > Groups`
4. Отменить доступ к продукту
5. Деактивировать учетную запись: `admin.atlassian.com > User management > [user] > Deactivate`
   - REST API: `DELETE /rest/api/3/user?accountId={accountId}`
6. **ПОДТВЕРДИТЬ**: Подтвердить `GET /rest/api/3/user?accountId={accountId}` возвращает `"active": false`
7. Удаление документа из журнала аудита
8. ** ИСПОЛЬЗУЙТЕ **: Jira Expert для переназначения любых оставшихся проблем

### Управление группой { #group-management }
1. Создавайте группы: `admin.atlassian.com > User management > Groups > Create group`
   - REST API: `POST /rest/api/3/group` с `{"name": "..."}`
   - Структура по: командам (разработка, продукт, продажи), ролям (администраторы, пользователи, зрители), проектам (проект-альфа-команда)
2. Определите цель группы и критерии членства (документ в Confluence)
3. Назначьте разрешения по умолчанию для каждой группы
4. Добавляйте пользователей в соответствующие группы
5. **ПОДТВЕРДИТЬ**: Подтвердите участников группы с помощью `GET /rest/api/3/group/member?groupName={name}`
6. Регулярный ревью и очистка (ежеквартально)
7. **ИСПОЛЬЗУЙТЕ**: Эксперт по слиянию для документирования структуры группы

### Разработка схемы разрешений { #permission-scheme-design }
**Схемы разрешений Jira** (`Jira Settings > Issues > Permission Schemes`):
- ** Общедоступный проект**: Все пользователи могут просматривать, участники могут редактировать
- ** Командный проект**: Полный доступ членов команды, просмотр стейкхолдеров
- **Ограниченный проект**: Только указанные лица
- **Администратор проекта**: Только для администраторов

**Схемы разрешения слияния** (`Confluence Admin > Space permissions`):
- ** Публичное пространство**: Все пользователи просматривают, участники пространства редактируют
- **Командное пространство**: Доступ для конкретной команды
- **Личное пространство**: только для индивидуального пользователя
- **Ограниченное пространство**: Названные лица и группы

**Лучшие практики**:
- Используйте группы, а не индивидуальные разрешения
- Принцип наименьших привилегий
- Регулярные аудиты разрешений
- Обоснование разрешения на документирование

### Конфигурация единого входа { #sso-configuration }
1. Выберите поставщика удостоверений (Okta, Azure AD, Google)
2. Настройка параметров SAML: `admin.atlassian.com > Security > SAML single sign-on > Add SAML configuration`
   - Установите идентификатор объекта, URL ACS и сертификат X.509 из IdP
3. Протестируйте единый вход с учетной записью администратора (сохраняйте пароль для входа активным во время тестирования)
4. Тест с обычной учетной записью пользователя
5. Включить единый вход для организации
6. Принудительное выполнение единого входа: `admin.atlassian.com > Security > Authentication policies > Enforce SSO`
7. Настройте SCIM для автоматической подготовки: `admin.atlassian.com > User provisioning > [IdP] > Enable SCIM`
8. **ПРОВЕРКА**: Подтвердите успешное выполнение процесса единого входа и отображение журналов аудита `saml.login.success` события
9. Отслеживайте журналы единого входа: `admin.atlassian.com > Security > Audit log > filter: SSO`

### Управление приложениями на Маркетплейсе { #marketplace-app-management }
1. Оцените потребность в приложении и его безопасность: проверьте самооценку безопасности поставщика по адресу `marketplace.atlassian.com`
2. Ревью документацию поставщика по безопасности (отчеты о тестировании на проникновение, SOC 2)
3. Протестируйте приложение в среде песочницы
4. Приобретите или запросите пробную версию: `admin.atlassian.com > Billing > Manage subscriptions`
5. Установить приложение: `admin.atlassian.com > Products > [product] > Apps > Find new apps`
6. Настройка параметров приложения в соответствии с документацией поставщика
7. Обучать пользователей использованию приложения
8. ** ПОДТВЕРДИТЬ **: Подтвердите, что приложение появится в `GET /rest/plugins/1.0/` и проходит проверку работоспособности
9. Следите за производительностью и использованием приложений; ежегодно проводите ревью на предмет постоянной необходимости

### Оптимизация производительности системы { #system-performance-optimization }
**Джира** (`Jira Settings > System`):
- Архивируйте старые проекты: `Project settings > Archive project`
- Переиндексировать: `Jira Settings > System > Indexing > Full re-index`
- Очистите неиспользуемые воркфлоу и схемы: `Jira Settings > Issues > Workflows`
- Отслеживать очередь/thread подсчитывает: `Jira Settings > System > System info`

**Слияние** (`Confluence Admin > Configuration`):
- Архивировать неактивные пространства: `Space tools > Overview > Archive space`
- Удаление потерянных страниц: `Confluence Admin > Orphaned pages`
- Отслеживайте индекс и кэширование: `Confluence Admin > Cache management`

**Мониторинг частоты вращения**:
- Ежедневные проверки здоровья: `admin.atlassian.com > Products > [product] > Health`
- Еженедельные отчеты о проделанной работе
- Ежемесячное планирование производственных мощностей
- Ежеквартальные ревью по оптимизации

### Настройка интеграции { #integration-setup }
**Общие интеграции**:
- **Слабина**: `Jira Settings > Apps > Slack integration` — уведомления для Jira и Confluence
- **GitHub/Bitbucket**: `Jira Settings > Apps > DVCS accounts` — привязка коммитов к проблемам
- **Команды Microsoft**: `admin.atlassian.com > Apps > Microsoft Teams`
- ** Масштабирование **: Доступно через приложение Маркетплейс `zoom-for-jira`
- **Salesforce**: через приложение Маркетплейс `salesforce-connector`

**Этапы настройки**:
1. Ревью требования к интеграции и необходимые области OAuth
2. Настройте аутентификацию OAuth или API (храните токены в защищенном хранилище, а не в обычном тексте)
3. Поля карты и потоки данных
4. Тщательно протестируйте интеграцию с примерами данных
5. Конфигурация документа в рансбуке Confluence
6. Обучать пользователей функциям интеграции
7. **ПОДТВЕРДИТЬ**: Подтвердите доставку webhook с помощью `Jira Settings > System > WebHooks > [webhook] > Test`
8. Отслеживайте работоспособность интеграции с помощью дашбордов для конкретных приложений

## Глобальная конфигурация { #global-configuration }

### Глобальные настройки Jira (`Jira Settings > Issues`) { #jira-global-settings-jira-settings--issues }
**Типы проблем**: Создавайте типы проблем в масштабах организации и управляйте ими; определяйте схемы типов проблем; стандартизируйте все проекты
**Воркфлоу**: Создание глобальных шаблонов воркфлоу с помощью `Workflows > Add workflow`; управлять схемами воркфлоу
**Пользовательские поля**: Создавайте пользовательские поля в масштабах всей организации на `Custom fields > Add custom field`; управление конфигурациями полей и контекстом
**Схемы уведомлений**: Настройка правил уведомлений по умолчанию; создание пользовательских схем уведомлений; управление шаблонами электронной почты

### Глобальные настройки слияния (`Confluence Admin`) { #confluence-global-settings-confluence-admin }
**Чертежи и шаблоны**: Создавайте шаблоны для всей организации по адресу `Configuration > Global Templates and Blueprints`; управление доступностью схемы
**Темы и внешний вид **: Настройте фирменный стиль организации на `Configuration > Themes`; настройка логотипов и цветов
**Макросы**: Включить/disable макросы в `Configuration > Macro usage`; настройка разрешений для макросов

### Настройки безопасности (`admin.atlassian.com > Security`) { #security-settings-adminatlassiancom--security }
**Аутентификация**:
- Политика использования паролей: `Security > Authentication policies > Edit`
- Тайм-аут сеанса: `Security > Session duration`
- Управление токенами API: `Security > API token controls`

**Резидентство данных**: Настройка местоположения данных по адресу `admin.atlassian.com > Data residency > Pin products`

**Журналы аудита**: `admin.atlassian.com > Security > Audit log`
- Включить всестороннее ведение журнала; экспорт через `GET /admin/v1/orgs/{orgId}/audit-log`
- Сохранять в соответствии с политикой (минимум 7 лет для соблюдения SOC 2/GDPR)

## Управление и политика { #governance--policies }

### Управление доступом { #access-governance }
- Ежеквартальный ревью всего пользовательского доступа: `admin.atlassian.com > User management > Export users`
- Проверка ролей и разрешений пользователей; удаление неактивных пользователей
- Ограничьте число администраторов организации 2-3 лицами; ежемесячно проводите аудит действий администратора
- Требуется MFA для всех администраторов: `Security > Authentication policies > Require 2FA`

### Соглашения об именовании { #naming-conventions }
**Jira**: Ключи проекта из 3-4 заглавных букв (PROJ, WEB); регистр заголовка типов проблем; пользовательские поля с префиксом (см.: Сюжетные точки)
**Слияние**: В пробелах используется префикс команды/проекта (TEAM: Engineering); страницы описательные и согласованные; надписи в нижнем регистре, через дефис

### Управление изменениями { #change-management }
** Основные изменения**: Анонс за 2 недели; тестирование в изолированной среде; создание плана отката; выполнение во внепиковое время; ревью после внедрения
** Незначительные изменения**: Объявляйте за 48 часов; документируйте в журнале изменений; отслеживайте наличие проблем

## Аварийное восстановление { #disaster-recovery }

### Стратегия резервного копирования { #backup-strategy }
**Jira & Confluence**: Ежедневное автоматическое резервное копирование; еженедельная ручная проверка; 30-дневное хранение; удаленное хранилище
- Триггер ручного резервного копирования: `Jira Settings > System > Backup system` / `Confluence Admin > Backup and Restore`

**Тестирование восстановления**: Ежеквартальные тренировки по восстановлению; процедуры документирования; измерение RTO и RPO

### Реагирование на инцидент { #incident-response }
**Уровни серьезности**:
- **P1 (критический)**: Сбой системы — ответ через 15 минут
- **P2 (высокий)**: Основная функция не работает — ответ через 1 час
- **P3 (средний)**: Незначительная проблема — ответим через 4 часа
- **P4 (низкий)**: Повышение — ответ через 24 часа

**Шаги реагирования**:
1. Подтвердите и зарегистрируйте инцидент
2. Оценить воздействие и серьезность
3. Информировать о статусе стейкхолдеров
4. Исследуйте первопричину (проверьте `admin.atlassian.com > Products > [product] > Health` и страница статуса Atlassian)
5. Внедрить исправление
6. ** ПРОВЕРКА **: Подтвердите разрешение с помощью теста затронутого пользователя и проверки работоспособности
7. Вскрытие и извлеченные уроки

## Показатели и отчетность { #metrics--reporting }

**Работоспособность системы**: Активные пользователи (ежедневно/weekly/monthly), использование хранилища, ограничения скорости API, работоспособность интеграции, время отклика
- Экспорт через: `GET /admin/v1/orgs/{orgId}/users` для подсчета пользователей; дашборды аналитики для конкретного продукта

**Аналитика использования**: Наиболее активные проекты/spaces, тенденции создания контента, вовлеченность пользователей, шаблоны поиска
**Показатели соответствия требованиям**: Завершение ревью доступа пользователей, результаты аудита безопасности, неудачные попытки входа в систему, использование токена API

## Фреймворк принятия решений и протоколы Хэндоффа { #decision-framework--handoff-protocols }

**Эскалация поддержки Atlassian**: Сбой в работе системы, снижение производительности в масштабах организации, потеря данных/corruption, лицензия/billing проблемы, сложные миграции

**Делегировать полномочия экспертам по продуктам**:
- Эксперт Jira: Конфигурация для конкретного проекта
- Эксперт по слиянию: настройки для конкретного пространства
- Scrum Master: потребности командного воркфлоу
- Старший премьер-министр: вклад в стратегическое планирование

** Вовлекать команду безопасности**: инциденты безопасности, необычные схемы доступа, подготовка к аудиту соответствия требованиям, ревью безопасности новой интеграции

** Эксперту Jira**: Доступны новые глобальные воркфлоу, настраиваемые поля, схемы разрешений или возможности автоматизации
**ДЛЯ Confluence Expert**: Настроены новые глобальные шаблоны, схемы разрешения пространства, чертежи или макросы
** Старшему руководителю**: Аналитика использования, информация о планировании производственных мощностей, оптимизация затрат, статус соответствия требованиям безопасности
**ДЛЯ Scrum Master**: Предоставлен доступ к команде, параметры конфигурации доски, правила автоматизации, включена интеграция
** ИЗ всех ролей**: Запросы доступа пользователей, изменения разрешений, запросы на установку приложений, поддержка конфигурации, отчеты о инцидентах

## Интеграция Atlassian MCP — пределы области применения { #atlassian-mcp-integration--scope-limits }

**Операции администратора недоступны через удаленный MCP-сервер Atlassian** (входит в комплект поставки `.mcp.json`, серверный ключ `atlassian`). Канонический список инструментов (`project-management/references/atlassian-mcp-tools.md`) не содержит инструментов для пользователя/group управление, схемы разрешений, полевые/workflow конфигурация, единый вход, управление приложениями или организационные настройки. Никогда не придумывайте названия инструментов — каждый воркфлоу администратора в этом скилле проходит через `admin.atlassian.com` или остальные API, упомянутые встроенно выше.

** Какой вклад MCP МОЖЕТ внести в работу администратора ** (читай -в основном поддержка):
- `mcp__atlassian__lookupJiraAccountId` — разрешить пользователям `accountId` перед проведением депровизационных аудитов
- `mcp__atlassian__searchJiraIssuesUsingJql` — найдите открытые вопросы выпускника (`assignee = <accountId>`) для переназначения
- `mcp__atlassian__getVisibleJiraProjects` / `mcp__atlassian__getConfluenceSpaces` — исходные данные инвентаризации для ревью доступа
- `mcp__atlassian__atlassianUserInfo` / `mcp__atlassian__getAccessibleAtlassianResources` — подтвердите действующую личность и доступные сайты

**Точки интеграции**:
- Поддержите экспертов Jira /Confluence, выполнив изменения администратора пользовательского интерфейса / REST, которые они не могут выполнить с помощью MCP
- Обеспечить, чтобы старший премьер-министр имел представление о состоянии здоровья организации (экспорт из admin.atlassian.com )
- Включите Scrum Master с помощью team provisioning (консоль администратора)
