# Эксперт Atlassian Jira { #atlassian-jira-expert }

Опыт работы на уровне магистра в области настройки Jira, управления проектами, JQL, воркфлоу, автоматизации и отчетности. Занимается всеми техническими и эксплуатационными аспектами Jira.

## Быстрый запуск — Наиболее распространенные операции { #quick-start--most-common-operations }

Во всех примерах MCP в этом скилле используются настоящие инструменты Atlassian Remote MCP (camelCase, отображаемые как `mcp__atlassian__<toolName>`). Канонический список инструментов таков `project-management/references/atlassian-mcp-tools.md` — никогда не придумывайте названия инструментов; если какая-либо возможность там не указана, она недоступна через MCP.

**Создать проблему** (позвонить `getAccessibleAtlassianResources` один раз сначала получить `cloudId`):
```
mcp__atlassian__createJiraIssue (cloudId, projectKey="MYPROJ", issueTypeName="Story", summary="My new story")
```

**Запустите запрос JQL** (создайте JQL на естественном языке с помощью входящего в комплект скрипта, затем выполните):
```bash
python3 scripts/jql_query_builder.py "high priority bugs assigned to me"
# → emits validated JQL, e.g.: assignee = currentUser() AND type = Bug AND status != Done
```
```
mcp__atlassian__searchJiraIssuesUsingJql (cloudId, jql="project = MYPROJ AND status != Done AND dueDate < now()")
```

**Создать проект**: недоступно через MCP. Используйте веб-интерфейс Jira (`Projects > Create project`) или REST API (`POST /rest/api/3/project`).

Полную информацию об инструменте смотрите в разделе [Интеграция Atlassian MCP](#atlassian-mcp-integration). О функциях JQL смотрите в разделе [Ссылка на функции JQL](#jql-functions-reference). Шаблоны отчетов см. в разделе [Шаблоны отчетов](#reporting-templates).

## Воркфлоу { #workflows }

### Создание проекта { #project-creation }

> Создание проекта ** недоступно через MCP** — выполните шаги 2-6 в веб-интерфейсе Jira (`Projects > Create project`) или через REST API (`POST /rest/api/3/project`). После создания проверьте видимость с помощью `mcp__atlassian__getVisibleJiraProjects` и проверять типы проблем с помощью `mcp__atlassian__getJiraProjectIssueTypesMetadata`.

1. Определите тип проекта (Scrum, Канбан, отслеживание ошибок и т.д.).
2. Создайте проект с соответствующим шаблоном (web UI / REST)
3. Настройка параметров проекта:
   - Имя, ключ, описание
   - Руководитель проекта и правопреемник по умолчанию
   - Схема уведомления
   - Схема получения разрешений
4. Настройка типов проблем и воркфлоу
5. При необходимости настройте пользовательские поля
6. Создайте начальную доску/backlog вид
7. **ХЭНДОФФ**: Scrum-мастер для онбординга команды

### Проектирование воркфлоу { #workflow-design }

> Воркфлоу/scheme редактирование ** недоступно через MCP** — настройте в `Jira Settings > Issues > Workflows`. Используйте прилагаемый валидатор для перехвата анти-шаблонов перед деплою.

1. Отображение состояний процесса ("Сделать" → "В процессе" → "Готово")
2. Определите переходы и условия
3. Доработайте дизайн перед его созданием в Jira:
   ```bash
   python3 scripts/workflow_validator.py workflow.json --format json
   ```
   Входные данные: JSON-файл с описанием воркфлоу `states` и `transitions`. Используйте выходные данные: исправьте каждый обнаруженный анти-шаблон (тупиковые состояния, недоступные состояния, пропущенные переходы) в дизайне, прежде чем обращаться к Jira.
4. Добавьте валидаторы, постфункции и условия; настройте схему воркфлоу (веб-интерфейс)
5. **Проверка **: сначала деплою в тестовом проекте; убедитесь, что все переходы, условия и постфункции ведут себя ожидаемым образом, прежде чем связываться с производственными проектами
6. Связать воркфлоу с проектом
7. Протестируйте воркфлоу с примерами проблем — через MCP: `mcp__atlassian__getTransitionsForJiraIssue` в примере проблемы, чтобы подтвердить ожидаемую поверхность переходов, затем `mcp__atlassian__transitionJiraIssue` чтобы провести его по течению

### Построение запросов JQL { #jql-query-building }

** Начните со встроенного конструктора ** — его шаблон - сопоставляет естественный язык с проверенным JQL:
```bash
python3 scripts/jql_query_builder.py "high priority bugs assigned to me" --format json
python3 scripts/jql_query_builder.py --patterns   # list all supported query patterns
```
Потребляйте выходные данные: используйте `jql` поле из результата JSON (или сгенерированного блока JQL в текстовом режиме) и выполните его с помощью `mcp__atlassian__searchJiraIssuesUsingJql (cloudId, jql=<generated>)`. Если конструктор сообщает об отсутствии совпадения с шаблоном, составьте JQL вручную, используя ссылку ниже.

**Базовая структура**: `field operator value`

**Общие операторы**:
- `=, !=` : равные, не равные
- `~, !~` : содержит, не содержит
- `>, <, >=, <=` : сравнение
- `in, not in` : членство в списке
- `is empty, is not empty`
- `was, was in, was not`
- `changed`

**Мощные примеры JQL**:

Поиск просроченных проблем:
```jql
dueDate < now() AND status != Done
```

Проблемы с выгоранием при спринте:
```jql
sprint = 23 AND status changed TO "Done" DURING (startOfSprint(), endOfSprint())
```

Найдите устаревшие проблемы:
```jql
updated < -30d AND status != Done
```

Межпроектное эпическое отслеживание:
```jql
"Epic Link" = PROJ-123 ORDER BY rank
```

Расчет скорости:
```jql
sprint in closedSprints() AND resolution = Done
```

Потенциал команды:
```jql
assignee in (user1, user2) AND sprint in openSprints()
```

### Создание Дашбордов { #dashboard-creation }
1. Создайте новую дашборд (личную или общую)
2. Добавьте соответствующие гаджеты:
   - Результаты фильтрации (на основе JQL)
   - Выгорание в спринте
   - Диаграмма скорости
   - Создано против разрешенного
   - Круговая диаграмма (распределение статусов)
3. Расположите макет для удобства чтения
4. Настройка автоматического обновления
5. Поделитесь с соответствующими командами
6. **ХЭНДОФФ**: Старшему менеджеру по персоналу или Scrum-мастеру для использования

### Правила автоматизации { #automation-rules }
1. Определить триггер (проблема создана, поле изменено, запланировано)
2. Добавить условия (если применимо)
3. Определите действия:
   - Поле обновления
   - Отправить уведомление
   - Создать подзадачу
   - Проблема перехода
   - Оставить комментарий
4. Автоматизация тестирования с использованием выборочных данных
5. Включение и мониторинг

## Расширенные функции { #advanced-features }

### Настраиваемые поля { #custom-fields }
**Когда создавать**:
- Отслеживать данные, не указанные в стандартных полях
- Сбор информации, относящейся к конкретному процессу
- Включить расширенную отчетность

**Типы полей**: Текстовое, числовое, Дата, Выбор (одиночное/multi/cascading), Средство выбора пользователя

**Конфигурация**:
1. Создать пользовательское поле
2. Настроить контекст поля (который проецирует/issue типы)
3. Добавить на соответствующие экраны
4. При необходимости обновите шаблоны поиска

### Проблема связывания { #issue-linking }
**Типы ссылок**:
- Блокирует / заблокирован
- Относится к
- Дублирует / дублируется с помощью
- Клонирует / клонируется с помощью
- Отношения между эпосом и историей

**Лучшие практики**:
- Используйте Epic linking для группировки объектов
- Используйте блокирующие ссылки для отображения зависимостей
- Причины ссылки на документ в комментариях

### Разрешения и безопасность { #permissions--security }

**Схемы получения разрешений**:
- Просмотр проектов
- Создавать/редактировать/удалять проблемы
- Администрирование проектов
- Управление спринтами

**Уровни безопасности**:
- Определите видимость конфиденциальной проблемы
- Контролируйте доступ к конфиденциальным данным
- Аудит изменений в системе безопасности

### Массовые операции { #bulk-operations }
**Массовое изменение**:
1. Используйте JQL для поиска целевых проблем
2. Выберите операцию массового изменения
3. Выберите поля для обновления
4. **Проверка **: Предварительный просмотр всех изменений перед выполнением; убедитесь, что фильтр JQL соответствует только предполагаемым ошибкам — массовые правки трудно отменить
5. Выполнить и подтвердить
6. Отслеживание фоновой задачи

**Массовые переходы**:
- Перемещение нескольких проблем с помощью воркфлоу
- Полезно для очистки спринта
- Требуются соответствующие разрешения
- **Проверка **: Запустите фильтр JQL и ревью результатов небольшими партиями, прежде чем применять в масштабе

## Ссылка на функции JQL { #jql-functions-reference }

> ** Совет**: Сохраняйте часто используемые запросы в виде именованных фильтров вместо повторного запуска сложного JQL ad hoc. Видишь [Лучшие практики](#best-practices) для руководства по работе.

**Дата**: `startOfDay()`, `endOfDay()`, `startOfWeek()`, `endOfWeek()`, `startOfMonth()`, `endOfMonth()`, `startOfYear()`, `endOfYear()`

**Спринт**: `openSprints()`, `closedSprints()`, `futureSprints()`

**Пользователь**: `currentUser()`, `membersOf("group")`

**Продвинутый**: `issueHistory()`, `linkedIssues()`, `issuesWithFixVersions()`

## Шаблоны отчетов { #reporting-templates }

> ** Совет**: Эти фрагменты JQL можно сохранить как общие фильтры или подключить непосредственно к гаджетам Дашборд (см. [Создание Дашбордов](#dashboard-creation)).

| Отчет | JQL |
|---|---|
| Отчет о спринте | `project = PROJ AND sprint = 23` |
| Скорость команды | `assignee in (team) AND sprint in closedSprints() AND resolution = Done` |
| Тенденция к ошибкам | `type = Bug AND created >= -30d` |
| Анализ блокировщика | `priority = Blocker AND status != Done` |

## Фреймворк для принятия решений { #decision-framework }

**Когда эскалация до администратора Atlassian**:
- Нужна новая схема получения разрешений на проект
- Требуется настраиваемая схема воркфлоу для всей организации
- Предоставление или отмена предоставления услуг пользователем
- Вопросы о лицензии или выставлении счетов
- Изменения конфигурации в масштабах всей системы

**Когда следует сотрудничать со Scrum Master**:
- Конфигурация платы Спринта
- Представления о приоритизации невыполненных работ
- Фильтры для конкретной команды
- Потребности в отчетности по спринту

**Когда следует сотрудничать со старшим премьер-министром**:
- Отчетность на уровне портфеля
- Межпроектные дашборды
- Потребности руководителей в наглядности
- Зависимости от нескольких проектов

**ОТ Scrum Master**:

- Требования к фильтрации невыполненных работ

**К Scrum-мастеру**:
- Настроенные платы для спринта

## Лучшие практики { #best-practices }

**Качество данных**:
- Применяйте обязательные поля с помощью правил проверки полей
- Используйте согласованные соглашения об именовании ключей проблем для каждого типа проекта
- Запланируйте регулярную очистку устаревшего/orphaned проблемы

**Производительность**:
- Избегайте начальных подстановочных знаков в JQL (`~` на больших текстовых полях это дорого)
- Используйте сохраненные фильтры вместо повторного запуска сложного JQL ad hoc
- Ограничьте использование гаджетов дашборда, чтобы сократить время загрузки страницы
- Архивируйте завершенные проекты, а не удаляйте их, чтобы сохранить историю

**Управление**:
- Документальное обоснование пользовательских состояний и переходов воркфлоу
- Разрешение на управление версиями/workflow схемы перед внесением изменений
- Требуется ревью управления изменениями для обновления схемы в масштабах всей организации
- Запускайте аудит разрешений после изменения роли пользователя

## Интеграция Atlassian MCP { #atlassian-mcp-integration }

**Основной инструмент**: Удаленный MCP-сервер Atlassian (входит в комплект поставки `.mcp.json`, серверный ключ `atlassian`). Поверхность инструментов как `mcp__atlassian__<toolName>`. **Канонический список инструментов**: `project-management/references/atlassian-mcp-tools.md`. Никогда не придумывайте названия инструментов — если возможности нет в этом списке, перейдите к веб-интерфейсу /REST API.

**Ключевые операции с примерами вызовов** (получение `cloudId` один раз через `mcp__atlassian__getAccessibleAtlassianResources`):

Создайте проблему (сначала проверьте обязательные поля с помощью `getJiraIssueTypeMetaWithFields`):
```
mcp__atlassian__createJiraIssue (cloudId, projectKey="MYPROJ", issueTypeName="Story", summary="My new story")
```

Выполнить запрос JQL:
```
mcp__atlassian__searchJiraIssuesUsingJql (cloudId, jql="project = MYPROJ AND status != Done AND dueDate < now()")
```

Обновить поле проблемы:
```
mcp__atlassian__editJiraIssue (cloudId, issueIdOrKey="MYPROJ-42", fields=<payload — discover via tool schema>)
```

Переход проблемы (изменения статуса происходят посредством переходов, а не редактирования полей):
```
mcp__atlassian__getTransitionsForJiraIssue (cloudId, issueIdOrKey="MYPROJ-42")
mcp__atlassian__transitionJiraIssue (cloudId, issueIdOrKey="MYPROJ-42", transition=<id from previous call>)
```

Проблемы с комментариями / работой журнала / ссылками:
```
mcp__atlassian__addCommentToJiraIssue (cloudId, issueIdOrKey="MYPROJ-42", body="...")
mcp__atlassian__addWorklogToJiraIssue (cloudId, issueIdOrKey="MYPROJ-42", timeSpent=<discover via tool schema>)
mcp__atlassian__createIssueLink (cloudId, link type from mcp__atlassian__getIssueLinkTypes)
```

**Недоступно через MCP — вместо этого используйте веб-интерфейс или REST API:**
- Создать **проект** → Пользовательский интерфейс Jira `Projects > Create project` или `POST /rest/api/3/project`
- Создайте ** спринт** или настройте платы → Пользовательский интерфейс программного обеспечения Jira или `POST /rest/agile/1.0/sprint`
- Создавать/share a **фильтр** → Пользовательский интерфейс Jira `Filters > Save as` или `POST /rest/api/3/filter`
- Настраиваемые поля, экраны, воркфлоу/permission схемы → Пользовательский интерфейс администратора Jira

**Точки интеграции**:
- Извлекать показатели для отчетности старших руководителей
- Настройка плат для спринта для Scrum Master
- Создание страниц документации для Confluence Expert
- Поддержка создания шаблона для создателя шаблона
