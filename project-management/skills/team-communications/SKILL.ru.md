# Внутренняя связь { #internal-comms }

> Первоначально внесенный [максимальное кодирование](https://github.com/maximcoding) — усовершенствован и интегрирован командой claude-скиллы.

Создавайте отточенные внутренние коммуникации, загружая правильный справочный файл, собирая контекст и выводя данные в точном формате компании.

## Маршрутизация { #routing }

Определите тип связи по запросу пользователя, затем прочитайте соответствующий справочный файл, прежде чем что-либо записывать:

| Тип | Фразы-триггеры | Справочный файл |
|---|---|---|
| **Обновление 3P** | "3P", "проблемы с планами выполнения", "еженедельное обновление команды", "что мы отправили" | `references/3p-updates.md` |
| **Информационный бюллетень** | "информационный бюллетень", "новости компании", "еженедельно/monthly обзор", "общее резюме" | `references/company-newsletter.md` |
| **Часто задаваемые вопросы** | "Часто задаваемые вопросы", "распространенные вопросы", "о чем спрашивают люди", "путаница вокруг" | `references/faq-answers.md` |
| **Общие сведения** | что-нибудь внутреннее, что не соответствует описанному выше | `references/general-comms.md` |

Если тип неоднозначен, задайте один уточняющий вопрос — не гадайте.

## Воркфлоу { #workflow }

1. **Прочитайте справочный файл** для поиска подходящего типа. Точно следуйте его форматированию.
2. ** Собирайте исходные данные. ** Используйте доступные инструменты MCP (Slack, Gmail, Google Диск, календарь) для получения реальных данных. Если инструменты не подключены, попросите пользователя предоставить маркированные точки или исходный контекст.
3. ** Уточните область применения.** Подтвердите: название команды (для 3Ps), период времени, аудиторию и любые конкретные элементы, которые пользователь хочет включить или исключить.
4. **Черновик.** Точно следуйте ограничениям формата, тона и длины, указанным в справочном файле. Не изобретайте новый формат.
5. ** Представьте черновик** и спросите, нужно ли что-то добавить, удалить или изменить формулировку.

## Тон и стиль (применимо ко всем типам) { #tone--style-applies-to-all-types }

- Используйте "мы" — вы являетесь частью компании.
- Активный голос, настоящее время для обозначения прогресса, будущее время для обозначения планов.
- Лаконичный. Каждое предложение должно содержать информацию. Нарежьте наполнитель.
- Включайте показатели и ссылки везде, где это возможно.
- Профессиональный, но доступный — не корпоративный - язык.
- Ставьте на первое место самую важную информацию.

## Когда инструменты недоступны { #when-tools-are-unavailable }

Если пользователь не подключил Slack, Gmail, Диск или календарь, не останавливайтесь. Попросите их вставить или описать то, что они хотят охватить. Вы форматируете и повышаете резкость — это по-прежнему ценно. Укажите, какие инструменты улучшат будущие черновики, чтобы они могли подключить их позже.

## Анти-паттерны { #anti-patterns }

| Анти-паттерн | Почему это терпит неудачу | Лучший подход |
|---|---|---|
| Написание обновлений без предварительного прочтения справочного шаблона | Выходные данные не будут соответствовать формату компании — пользователь должен переформатировать | Всегда загружайте соответствующий справочный файл перед составлением проекта |
| Придумывание показателей или достижений | Внутренняя связь должна основываться на фактах — фальсификация разрушает доверие | Включайте только данные, предоставленные пользователем или извлеченные средствами MCP |
| Использование страдательного залога для обозначения достижений | "Функция была отправлена" скрывает, кто выполнил эту работу | "Команда X внедрила эту функцию" — активная голосовая поддержка команды |
| Написание стен из текста для обновления статуса | Руководство сканирует, но не считывает — ключевая информация скрывается | Начните с заголовка, затем укажите 3-5 основных пунктов |
| Отправка без подтверждения аудитории | Обновленная информация для команды читается иначе, чем общекорпоративный информационный бюллетень | Всегда подтверждайте: кто будет это читать? |
